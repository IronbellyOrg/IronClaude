# Release v5.0.0 - codegraph replaces codebase-memory and Serena

**Release Date**: 2026-11-02
**Version**: 5.0.0
**Type**: Major Release
**Impact**: Breaking. Several flags, a command and six core files are removed, two MCP servers are retired, and session memory moves to new files. An upgrade needs `superclaude install --force` and a restart of running Claude sessions. A plain `superclaude install` does not refresh existing files, and `superclaude update` refreshes them but never installs codegraph or retires the old MCP servers.

---

## Summary

IronClaude 5.0.0 replaces codebase-memory-mcp and Serena with codegraph, a code graph that is installed, registered and indexed by default and used by commands, skills and agents for symbol, caller and impact questions. Session memory moves from Serena to plain markdown files under `<project>/.superclaude/memory/`. Review loops change too: minor findings never fail a review, and every review loop stops after 2 fix cycles and escalates open blocking findings to the user. The version is major because of the removals listed under Breaking Changes. It covers 387 commits and 190 merged pull requests since the package version was set to 4.3.5 on 2026-06-04, which was never tagged.

---

## Changes by Category

### Added

- **codegraph installed by default (#323)**: `superclaude install` downloads the pinned codegraph `1.6.2` (Linux or macOS, x64 or arm64), checks its SHA-256, and registers it at user scope with seven narrow tools. A SessionStart hook indexes each clone and worktree on its first session. `SUPERCLAUDE_CODEGRAPH_AUTOINIT=0` turns the hook off.
- **codegraph in commands, skills and agents (#323)**: troubleshoot, reflect, validate-roadmap, brainstorm, cleanup-audit, auggie-review, task, tasklist and four agents use codegraph, with Grep/Read as the fallback. A shared guide, `~/.claude/CODEGRAPH.md`, holds the rules. `SUPERCLAUDE_CODEGRAPH_PRIMITIVES=off` switches this off.
- **`/sc:impact`**: lists the production and test dependents of named symbols or of a diff, with an advisory test list on `--tests`.
- **`/sc:graph`**: reports whether this worktree's code-graph index is ready; `/sc:graph init` indexes it by hand.
- **Routing guide**: `~/.claude/HOW-WE-WORK.md` says which command or skill to use for each kind of work. `/sc:recommend` and `/sc:help` read it.
- **`/sc:pr-submit` Codex support**: Codex review threads go through the same verify, fix, reply and resolve path as Augment's. Either reviewer may be absent.
- **ccsession**: tier rules by Coder username or role (`CCSESSION_TIER_RULES`), letter tier names (`tier1a`), one session name shared by ccsession, Claude Code (`/rename`) and Orca, names shared across a repo's worktrees, and `ccsession-orca` for Orca's Claude launches.
- **Issue body files**: `ISSUE-HANDOFF.md` and `ISSUE-BACKLOG.md` are installed to `~/.claude/`, with a CLAUDE.md rule to fill a copy and pass it to `gh issue create --body-file`.
- **LiteLLM MCP gateway entry**: `superclaude mcp --servers litellm` (opt-in).
- **Sprint and reflect CLI**: per-task handoff records, `--resume <task_id>` and `--task-parallelism` on `superclaude sprint run`; a bounded `--fix` loop on `superclaude reflect run`.

### Changed

- **Review severity and loop cap**: a finding is graded blocking or minor. Minor findings are recorded as notes, are not rechecked, and never fail a review or start a fix pass. Every review loop runs at most 2 fix cycles (3 reviews), then stops and escalates the open blocking findings to the user, instead of turning them into Open Questions. This covers the Pragmatic output style, the rf-qa agents, the QA and MDTM templates, the prd, tdd, task and task-builder skills, the prd CLI, `/sc:tasklist` and `/sc:cli-portify` (default 1 iteration). `/sc:implement` keeps its own severity model and drops its second in-place repair.
- **`/sc:pr-submit` defaults to `--monitor 3`**: it fixes confirmed review findings of Medium severity or higher and failing CI checks, and pushes the fixes without asking. Use `--monitor 2` to stop before pushing.
- **`/sc:pr-submit` target**: the PR repository comes from the `origin` remote first. It accepts `--pr <N>` to attach to an existing PR and checks that the checkout is the PR head before pushing.
- **`superclaude sprint run` and `rerun-tasks` auto-resume** an interrupted sprint when no `--start/--end` (or `--phase/--tasks`) is given. CI needs `--yes` or `CI=1`.
- **Remediation routing**: `/sc:troubleshoot --fix`, `/sc:reflect --remediate` and the auggie-review offer build a `/sc:workflow` plan for `/sc:implement`; the task-builder chain is used only with `--depth deep`.
- **`superclaude reflect run`** promotes by default (`--promote`).
- **`~/.claude/CLAUDE.md`** is shorter: it carries the routing block and drops the persona table and contributor sections.

### Removed

- **codebase-memory-mcp and Serena**: no longer installed or registered. The install's retire step removes user-scope registrations IronClaude can prove it wrote, and keeps anything else with the reason printed.
- **`superclaude mcp --uninstall` and `--yes`**; `serena` and `codebase-memory-mcp` are no longer `--servers` choices.
- **`/sc:reflect --onboard` and `--with-hierarchy`**.
- **`/ccsession-tag`**: use Claude Code's `/rename`.
- **`/sc:pr-submit --yes`**: it was accepted and never read.
- **Core files** `ORCHESTRATOR.md`, `COMMANDS.md`, `PERSONAS.md`, `MODES.md`, `FLAGS.md` and `MCP.md`, and the `/sc:README` command file. Copies already in `~/.claude/` are left in place.

### Fixed

- **ccsession shim stopped when its terminal closed (#341)**: the shared gateway shim ran inside the terminal that first started it, so closing that terminal cut every other session's replies until a later launch restarted it. It now starts outside the terminal and in its own session.
- **`/sc:pr-submit` could open a PR on the upstream parent**: it asked `gh repo view` first, which prefers an `upstream` remote.
- **ccsession `--model` window**: a model launched by name takes the same window as `/model`.
- **Sessions dropping out of Orca Web and the phone app**: ccsession sets the Orca tab title so the pane is still seen as Claude.

### Security

- No security fixes in this release.

## Migration Required

**Migration Steps:**

1. **Back up files you edited in `~/.claude/`.** The upgrade overwrites every shipped file, including an edited `~/.claude/CLAUDE.md` and `~/.claude/RULES.md`, and deletes and re-copies each shipped skill folder. For example: `cp ~/.claude/CLAUDE.md ~/.claude/CLAUDE.md.mine`.
2. **Upgrade the package and the installed files.** A plain `superclaude install` skips files that already exist, and `superclaude update` refreshes them but never installs codegraph or retires the old MCP registrations, so neither is enough for this release. Use `install --force`, which refreshes every shipped file and then installs and registers codegraph and retires the old registrations:

   ```bash
   pipx install --force git+https://github.com/IronbellyOrg/IronClaude
   superclaude install --force
   ```

   The codegraph step needs the `claude` CLI on `PATH` and network access to download codegraph. If it fails, the command exits 1 and names the failed step; fix the cause and run it again. From a clone, `./update.sh` runs the same `superclaude install --force` (plus `make sync-dev` and `superclaude doctor`) and needs `pipx` on `PATH`.
3. **Restart every running Claude session.** MCP servers and skills load at session start, and a running session can write a removed MCP registration back.
4. **Check the result:** `superclaude --version` prints `5.0.0`; `superclaude install --list` shows a codegraph block whose `User registration:` is not `absent` and whose last line reads `Ready for Serena retirement: yes`, plus one line per retired name; `superclaude doctor --verbose` passes and prints no `no codegraph registration` line (plain `superclaude doctor` passes even when codegraph is missing); `/sc:graph status` in a new session reports an index state. If you already upgraded with `superclaude update`, run `superclaude install --force` now.
5. **Move session memories you want to keep.** Copy files from `<project>/.serena/memories/` into `<project>/.superclaude/memory/`. For this release only, `/sc:load` still reads a `.serena/memories/<key>.md` file when the new file is absent.
6. **Keep Serena only if you want it:** register it as `serena-local`, a name the installer never removes. The exact command is in `CHANGELOG.md` under "Manual cleanup".
7. **Update scripts:** remove `--yes` from `/sc:pr-submit` calls and `--uninstall`/`--yes` from `superclaude mcp` calls. In CI, add `--yes` (or `CI=1`) to `superclaude sprint run`, or pass `--start 1` to keep the old start-from-phase-1 behaviour.
8. **Restart the ccsession shim to get the #341 fix.** A running shim keeps the old behaviour. When no session needs it: `pkill -f local-gateway-alias-proxy.py`; the next ccsession launch starts a new one.

## Breaking Changes

### Change 1: codebase-memory-mcp and Serena removed; session memory moves to files

**Impact**: Anyone who used Serena or codebase-memory tools, or Serena memories through `/sc:save`, `/sc:load` or `/sc:pm`.
**Migration**: Migration steps 2, 3, 5 and 6 above.
**Timeline**: Removed in 5.0.0. The `/sc:load` read-only fallback to `.serena/memories/` ends in the next release.

### Change 2: removed flags and command

**Impact**: Scripts and habits that pass `superclaude mcp --uninstall` or `--yes`, `superclaude mcp --servers serena`, `/sc:reflect --onboard` or `--with-hierarchy`, `/sc:pr-submit --yes`, or use `/ccsession-tag`.
**Migration**: Drop the flags; use `/rename` instead of `/ccsession-tag`.
**Timeline**: Removed in 5.0.0.

### Change 3: core files no longer shipped

**Impact**: Anything that reads `~/.claude/ORCHESTRATOR.md`, `COMMANDS.md`, `PERSONAS.md`, `MODES.md`, `FLAGS.md` or `MCP.md`. The shipped `CLAUDE.md` has not imported them since 2026-03-16.
**Migration**: Use `~/.claude/HOW-WE-WORK.md`. Old copies stay in `~/.claude/` until you delete them.
**Timeline**: Removed in 5.0.0.

### Change 4: review loops stop after 2 fix cycles

**Impact**: QA gates that used to keep fixing minor findings, or ran 3 or more fix cycles, now pass with notes or stop and escalate to the user after 2 fix cycles. `/sc:cli-portify` runs 1 convergence iteration by default.
**Migration**: None needed. Expect an escalation where a loop used to keep running.
**Timeline**: 5.0.0.

### Change 5: default behaviour changes

**Impact**: `/sc:pr-submit` with no `--monitor` now pushes review and CI fixes (level 3); `superclaude sprint run` with no range auto-resumes; `superclaude reflect run` promotes by default.
**Migration**: Pass `--monitor 2`, `--start 1` or `--no-promote` to keep the old behaviour.
**Timeline**: 5.0.0.

## Known Issues

- **`./update.sh` needs `pipx`**: on an image without it, the script stops at its first line (exit 127). Install pipx (for example `uv tool install pipx`) or use the two commands in migration step 2.
- **`/sc:cli-portify --max-convergence` has no effect**: the convergence engine always runs its default of 1 iteration, and a failure message still suggests raising the flag. Follow-up noted in #343.
- **Stale troubleshooting page**: `docs/reference/common-issues.md` still says to `pipx upgrade SuperClaude` (the upstream package). Follow migration step 2 instead.
- **`superclaude install --list` checks names only**, so it cannot show that an installed core file is out of date.
- **`superclaude update` does not complete this upgrade**: it never installs codegraph or retires the old MCP registrations, and plain `superclaude doctor` still passes afterwards. Use `superclaude install --force` (migration step 2).
- **`superclaude install --force` exits 1 when the codegraph step fails** (no network, `claude` CLI missing, or a platform other than Linux or macOS on x64 or arm64). The framework files are still refreshed; fix the cause and run it again.
- **`/sc:pr-submit` may record a clean Augment review as incomplete** when Augment posts "Review completed with 0 suggestions" (seen on #342). The run still ends clean when CI and the other reviewer pass.
- **Running ccsession shims keep the old behaviour** until restarted (migration step 8).
