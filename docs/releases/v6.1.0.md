# Release v6.1.0 - the task and documentation bundle is removed

**Release Date**: 2026-11-18
**Version**: 6.1.0
**Type**: Minor Release (the owner chose 6.1.0; the changelog rule counts a removed skill as breaking)
**Impact**: Breaking for anyone who typed `/task`, `/task-builder`, `/roadmap`, `/tdd`, `/prd`, `/readme`, `/tech-reference`, `/tech-research` or `/operational-guide`, or used `/sc:tdd` or `/sc:brainstorm --handoff task`. Upgrade with `pipx install --force git+https://github.com/IronbellyOrg/IronClaude@v6.1.0`, then `superclaude install --force`.

---

## Summary

IronClaude 6.1.0 removes the task-file (MDTM) route and the document skills that were built on it. Nine skills, one slash command and one eval suite are gone, and so are levels 4, 5 and 6 of the routing guide. Planned work has one route: `/sc:workflow` writes a checked plan and `/sc:implement` runs it. Every command that used to offer the task-file route (`/sc:reflect --remediate`, `/sc:troubleshoot --fix`, `/sc:brainstorm`, `/sc:recommend`, crash recovery and the issue chains) now offers the plan route at every depth.

Kept on purpose: `/sc:task`, `/sc:validate-tests` (with their skills `sc-task-protocol` and `sc-validate-tests-protocol`), the eval suite `task_classification_contract`, and all eight `rf-*` agents (`rf-analyst`, `rf-assembler`, `rf-qa`, `rf-qa-qualitative`, `rf-task-builder`, `rf-task-executor`, `rf-task-researcher`, `rf-team-lead`). What happens to the agents is Part C of the cleanup (issue 572) and is undecided.

The release also carries #641 (ccsession separates sessions an agent saved from sessions a person saved); see "ccsession" under Changed.

---

## Changes by Category

### Changed

- **Plan route at every depth.** `/sc:reflect --remediate` and `/sc:troubleshoot --fix` take the plan route whatever `--depth` says; `--depth deep` only sets the review depth, and alone still does not remediate.
- **Reflect wrapper.** `superclaude reflect run --fix` always applies a corrective plan with `/sc:implement <remediation_plan_path>` and ignores `remediation_task_path`. An old report that carries only that pointer ends as a terminal HALT.
- **Routing guide.** The scale is three levels (ask, small direct change, checked plan). The `task-file`, `research-first`, `full-spec` and technical-design-document routes are gone.
- **Crash recovery.** It still detects roadmap and task files from earlier releases, but says to copy the open items into a new list and run `/sc:implement <list>`.
- **Contract fields.** `remediation_task_path`, `handoff_memory_key`, `handoff_memory_written`, `handoff_payload_size_bytes`, `handoff_persist_failed` and troubleshoot's `task_file_path` stay in the schemas so older reports load; they are always null, false or 0.
- **ccsession (#641): human-saved and agent-saved sessions.** (1) The installer's Claude Code retention target goes from 365 to 90 days; it never lowers a value already set (a 365 stays 365) and never writes where managed settings decide. (2) Sessions an agent saved are hidden from `ccsession --list`, `--here` and the new-tab question; `ccsession --agents` shows them, and `ccsession --mark <name> agent|human` and `ccsession --classify [--apply]` set or infer the marker. (3) New `ccsession --prune [--apply] [--days N]` deletes agent-saved sessions older than 30 days (never fewer than 30); it is a dry run without `--apply` and never touches a session a person saved. The full entry is in `CHANGELOG.md` under `[6.1.0]`.

## What is removed and what to use instead

### Skills (9)

| Removed | Use instead |
|---|---|
| `task` (`/task`) | `/sc:implement <plan path>` for a plan; for an old task file, copy its open items into a new list and run `/sc:implement <list>`. |
| `task-builder` (`/task-builder`) | `/sc:workflow "<what to build>"` then `/sc:implement <printed plan path>`. |
| `roadmap` (`/roadmap`) | `/sc:workflow` then `/sc:implement`. |
| `prd`, `tdd`, `tech-research`, `tech-reference`, `operational-guide`, `readme` | None. `/sc:research`, `/sc:analyze` and `/sc:brainstorm` cover the research steps; write requirement and design documents by hand or with `/sc:design`. |

### Slash command (1)

| Removed | Use instead |
|---|---|
| `/sc:tdd` | `/sc:design` for a design document. |

### Options and routes removed from kept commands

| Command | Removed | Use instead |
|---|---|---|
| `/sc:brainstorm` | `--handoff task` (now a STOP) | `--handoff design` or `none`, then `/sc:workflow @<output>/merged-requirements.md` |
| `/sc:reflect --remediate` | the MDTM route at `--depth deep` and the `reflect/handoff-*.md` file | the plan route (`/sc:workflow`, then `/sc:implement`) |
| `/sc:troubleshoot --fix` | the MDTM route at `--depth deep` | the plan route |

### Eval suite (1)

`workflow_vs_task_builder`, with `scripts/eval_workflow_vs_task_builder.py` and its test. `uv run superclaude eval list` shows 15 suites and 59 evals.

### Agents

None removed, and none is retired by the installer in this release. All eight `rf-*` agents stay.

### Kept on purpose (nothing removed, nothing to change)

| Kept | Why |
|---|---|
| `/sc:task` and `sc-task-protocol` | The compliance-tier command; independent of the removed task-file route. |
| `/sc:validate-tests` and `sc-validate-tests-protocol` | They validate `/sc:task` tier classification. |
| Eval suite `task_classification_contract` | It tests `/sc:task`. |
| `rf-analyst`, `rf-assembler`, `rf-qa`, `rf-qa-qualitative`, `rf-task-builder`, `rf-task-executor`, `rf-task-researcher`, `rf-team-lead` | Part C of the cleanup (issue 572) decides their future; text that names them is unchanged. |
| The 52 installed document templates | Kept; two of them carry a one-line note that `/task`, `/task-builder` and `/roadmap` were removed. A follow-up reworks them. |

### Known leftovers (for issue 572)

- `src/superclaude/rules/contextual/context_embedding.md` and `src/superclaude/rules/prompts/agent_library.md` still name the old `/rf:taskbuilder` command, which no longer exists. They belong to the `rf-*` agent rules and are left for issue 572.
- The templates under `src/superclaude/templates/` (for example `skill_template.md`, `roadmap_template.md` and the `modularization-template-review` set) still describe the task-file flow.

## Migration Required

1. Back up files you edited under `~/.claude/` (the retire step keeps edited copies of removed skills, but back up anyway).
2. Upgrade the package and the installed files:

   ```bash
   pipx install --force git+https://github.com/IronbellyOrg/IronClaude@v6.1.0
   superclaude install --force
   ```

   From a clone: `git fetch origin --tags`, `git checkout v6.1.0`, then `./update.sh`.
3. Read the install output. The nine skills and `tdd.md` print as `Removed ...`. An edited copy prints `Kept ...` with the reason and the exact `rm` command; run it if you do not need your copy.
4. Restart running Claude Code sessions so the removed commands and skills disappear from them.
5. Check the result: `superclaude doctor`, `superclaude install --list` and `/sc:help`.
6. If you have task files from an earlier release, they stay on disk. To continue one, copy its unchecked items into a new list and run `/sc:implement <list>`; `/sc:implement` lists checked items too, so do not point it at the old file.
7. If a script used `superclaude reflect run --fix` with a report that holds only `remediation_task_path`, regenerate the report with `/sc:reflect --remediate`.
