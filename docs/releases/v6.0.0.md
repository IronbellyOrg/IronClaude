# Release v6.0.0 - the headless pipelines and twelve commands are removed

**Release Date**: 2026-11-18
**Version**: 6.0.0
**Type**: Major Release
**Impact**: Breaking. Six command-line groups, twelve slash commands and five skills are removed, and `/sc:workflow` and `/sc:brainstorm` lose their `tasklist` handoff. An upgrade needs `superclaude install --force` (or `superclaude update`) and a restart of running Claude sessions. The installer now removes the retired commands and skills itself, but only files it can prove it installed; an edited copy is kept and explained.

---

## Summary

IronClaude 6.0.0 removes what nobody uses any more. The command-line pipelines that start headless Claude sessions (`prd`, `cleanup-audit`, `cli-portify`, and the roadmap, tasklist and sprint family) are gone, together with twelve slash commands and five skills that went with them or had no users. Swarm and everything attached to it stay, as do `/sc:workflow`, `/sc:implement`, `/sc:task`, the interactive `prd` skill and the document skills. The installer gains a retire step, so an upgraded workspace no longer keeps dead commands such as `/sc:roadmap`. Eight small reported problems in help text, `doctor`, the PM wording and the `ic` launcher are fixed in the same release. The version is major because of the removals listed under Breaking Changes. The previous release, 5.0.0 (2026-11-02), is kept as a snapshot in the fork `ironbelly/IronClaudeV5`.

---

## Changes by Category

### Added

- **Retire step in `install` and `update` (#633)**: `superclaude install` (with or without `--force`), `superclaude update` and `./update.sh` end by removing, from `~/.claude/commands/sc/`, `~/.claude/skills/` and `~/.claude/agents/`, the commands, skills and agents this release no longer ships. A file is removed only when its content is byte-identical to the file an earlier release shipped (its sha256 at the `v5.0.0` tag); a skill folder only when every file in it matches and nothing else is in it. Anything else is kept, and one line says why and prints the exact `rm` command. A second run changes nothing, and the install exit code never changes.
- **`scripts/gen_retired_install_data.py`**: generates the removed names and file hashes from a previous release tag into `src/superclaude/cli/install_retired_data.py`. The release procedure says to regenerate it for each release.

### Changed

- **`/sc:workflow` and `/sc:brainstorm`**: the `tasklist` handoff choice is gone. `--handoff` is now `none|design|implement` for `/sc:workflow` and `none|design|task` for `/sc:brainstorm`.
- **`sc-crash-recovery`**: it no longer lists roadmap and sprint resume commands; its MDTM recovery names `/task`.
- **`ic` launcher**: only a model name that starts with a lowercase letter resolves through `~/.aienv`; anything else passes through as typed (see Fixed, #542).

### Removed

See "What is removed and what to use instead" below for the full list with replacements. In short: six command-line groups, twelve slash commands, five skills, no agents, and the supporting `superclaude.compression` module, `scripts/compress.py`, the roadmap and tasklist example templates, and the scripts and docs that only drove the removed pipelines.

### Fixed

- **#505**: `/sc:business-panel` has a `description:` header, so `/sc:help` shows a description for it.
- **#506 (cleanup half)**: the `/sc:cleanup` usage line lists `--preview`, which shows what would change and edits nothing. The `/sc:improve` half of the issue went away with the command.
- **#510**: `superclaude doctor` prints the missing-codegraph-registration line without `--verbose`. The check still passes in that case, as before.
- **#536**: the PM command, agent and protocol skill no longer say PM runs automatically at every session start or restores memory by itself; they say it runs when `/sc:pm` is invoked. No startup hook was added.
- **#545**: `superclaude recommend --help` shows `uv run superclaude recommend ...`, not the `python -m` form that cannot run.
- **#544**: `ic --help` works when the `AIENV` file contains a failing command. Normal launches stay strict.
- **#543**: `ic -p` (and `-H`, `-S`, `-O` and their long forms) with no value prints `ic: option <option> requires a value` and exits 2, not Bash's `$2: unbound variable`.
- **#542**: `ic -H HOME` no longer puts the home path in the model setting. Only a name that starts with a lowercase letter resolves through `~/.aienv`.

### Security

- No security fixes in this release.

## What is removed and what to use instead

### Slash commands (12)

| Removed | Use instead |
|---|---|
| `/sc:build` | None. Run your project's own build tool. |
| `/sc:cli-portify` | None. |
| `/sc:improve` | None as one command. `/sc:cleanup` for cleanup, `/sc:analyze` to find problems, `/sc:workflow` then `/sc:implement` to change code. |
| `/sc:index` | `/sc:document <target>` for documentation. |
| `/sc:index-repo` | `/sc:graph` and codegraph for a code index. Existing `PROJECT_INDEX.md` and `PROJECT_INDEX.json` files stay on disk. |

| `/sc:review-translation` | Moved to the snapshot fork `ironbelly/IronClaudeV5` (the command and its skill). |
| `/sc:roadmap` | The plain `roadmap` skill (`/roadmap`) for MDTM roadmaps; `/sc:workflow` then `/sc:implement` for ordinary implementation planning. |
| `/sc:spawn` | Orca (`orca worktree create --agent`) to start workers; `/sc:workflow` to plan a decomposition. |
| `/sc:tasklist` | `/sc:workflow` then `/sc:implement`. There is no Sprint-format bundle any more. |
| `/sc:validate-roadmap` | None. |

## Migration Required

1. Back up files you edited under `~/.claude/` (the retire step keeps edited copies of removed commands and skills, but back up anyway).
2. Upgrade the package and the installed files:

   ```bash
   pipx install --force git+https://github.com/IronbellyOrg/IronClaude@v6.0.0
   superclaude install --force
   ```

   From a clone: `git fetch origin --tags`, `git checkout v6.0.0`, then `./update.sh`.
3. Read the install output. Removed commands and skills print as `Removed ...`. An edited copy prints `Kept ...` with the reason and the exact `rm` command; run it if you do not need your copy.
4. Restart running Claude Code sessions so the removed commands and skills disappear from them.
5. Check the result: `superclaude doctor`, `superclaude install --list` and `/sc:help` (it lists only what exists).
6. If you used a removed command-line group in scripts or CI (`superclaude roadmap`, `tasklist`, `sprint`, `prd`, `cleanup-audit`, `cli-portify`), stay on `v5.0.0` or move to the replacement in the tables above.
7. If you set model aliases in `~/.aienv` with a name that starts with a capital letter (for example `export GLM=...`), rename them to start with a lowercase letter.

## Backward Compatibility

- Breaking: every removed command, skill and command-line group above, and the `tasklist` handoff choice.
- Breaking for `ic` users: an alias whose name starts with an uppercase letter no longer resolves; it is passed through as typed.
- Not changed: swarm and its skills, `/sc:workflow`, `/sc:implement`, `/sc:task`, `/sc:graph`, the interactive `prd` skill, `/sc:cleanup-audit` with its skill and agents, `reflect`, the eval harness, ccsession, and the shared runner `cli/pipeline`.
- Not removed from your machine automatically: a customized copy of a removed command or skill (kept, with the `rm` command printed); the markdown files under `<project>/.superclaude/memory/`; `PROJECT_INDEX.md` and `PROJECT_INDEX.json` files.

## Testing & Validation

### Automated Testing

Each pull request was checked by its author against the full suite (the command the CI `test` job runs), `make lint`, `ruff format --check`, `make verify-sync` and `git diff --check`, and merged only when every GitHub check was green and Augment and Codex had finished on the final commit with no open thread. The agents' full-suite runs, before and after each pull request, are in `.dev/releases/current/v6.0.0/RELEASE-READINESS.md`. The suite went from about 27,900 passing tests to about 22,650 because the tests of the removed code were removed with it (for example 4,112 for the roadmap family and 896 for cli-portify); 21 new tests cover the help-text fixes, 41 the `ic` launcher and 31 the retire step. One test, `tests/cli/test_install_keep.py::test_same_content_is_true_only_for_identical_readable_files`, failed in the agents' runs on `integration` before any 6.0.0 change and was not caused by any of them.

### Manual Validation

The retire step was checked by hand in a throwaway home: the `v5.0.0` files (45 commands, 39 skills, 45 agents) were laid down, then the real `superclaude install` ran: exit 0, 37 commands and 37 skills left, an edited `roadmap.md` and a skill folder with an extra file kept with their printed `rm` commands, a second run printed only those two kept lines. The go/no-go gate (G1 to G9) results for the release commit are recorded in `.dev/releases/current/v6.0.0/RELEASE-READINESS.md`.

## Breaking Changes

### Change 1: command-line groups removed

`superclaude prd`, `cleanup-audit`, `cli-portify`, `roadmap`, `tasklist` and `sprint` are gone, with every subcommand and flag. Scripts and CI jobs that call them stop working. Replacements are in the tables above.

### Change 2: twelve slash commands and five skills removed

The commands and skills listed above are removed from the package. The installer removes your installed copies on upgrade when they are unchanged.

### Change 3: `--handoff tasklist` removed

`/sc:workflow` and `/sc:brainstorm` no longer accept `tasklist` as a handoff.

### Change 4: `ic` alias resolution

Only a name that starts with a lowercase letter resolves through `~/.aienv`.

## Known Issues

- While a kept, customized copy of a removed command exists, `superclaude doctor` fails with `Missing command-required skill(s)` (for example `sc:roadmap-protocol`). That is intended: the command is dead. Run the `rm` command the installer printed.
- The root `commands/` folder of the repository holds older `sc-` copies of commands (spelled `/sc:sc:...`) that `make sync-dev` does not generate and that no test reads; each removal edited it for consistency, and it is not installed.
- `docs/getting-started/upgrading.md` still describes the 5.0.0 upgrade in its title and counts; the post-release documentation sync updates it.
- The eight issues fixed here (#505, #506, #510, #536, #542, #543, #544, #545) are closed when this release reaches `master`.
