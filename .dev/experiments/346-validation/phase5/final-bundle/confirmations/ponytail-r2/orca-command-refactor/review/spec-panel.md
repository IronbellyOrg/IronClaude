## 2. Requirements analysis (Wiegers, Adzic, Cockburn)
=== REQUIREMENTS ANALYSIS ===

**Wiegers (requirements quality).** WC-1 to WC-12 are well scoped and each row names an owner and evidence (`SPEC:57-70`). Three requirements are not verifiable as written:
- WC-4 says the report file is "known before dispatch" (`SPEC:62`) but defines its location only for a directory-valued output flag. For file-valued flags (`init-lite.md:32` "Report output path", default a `.md` file; `tdd.md:49` "Output path for the final TDD document") and for commands whose contract sits in a generated or nested folder (`SPEC:83`, `SPEC:92`), the coordinator cannot compute the path. Finding 2.
- WC-4's `status` vocabulary (`succeeded / partial / failed / blocked`, `SPEC:62`) reuses the field name that three existing contracts already fill with a different vocabulary (`success | partial | failed`): `sc-workflow-protocol/refs/return-contract.md:7`, `sc-brainstorm-protocol/SKILL.md:341` (adds `dry-run`), `sc-adversarial-protocol/SKILL.md:436`. "Keep their fields and add the missing ones" (`SPEC:62`) and the step-4 assertion `d['status'] in {'succeeded',...}` (`SPEC:183`) cannot both hold. Finding 1.
- WC-6 (`SPEC:64`) asks for "a fresh output directory" on re-run without saying who chooses it, while WC-4 fixes the directory in the brief. Finding 3.

**Adzic (specification by example).** The main path is exemplified by 7.2 and AC-2.2, which is good. Two examples expose gaps:
- Given a person types `/sc:troubleshoot "why does --unattended skip the prompt?"`, when the command looks for `--unattended`, then the spec does not say whether that counts. D1 claims the flag "cannot misfire on a person" (`SPEC:228`), but no token rule exists. Finding 5.
- Given the coordinator retries a failed Task with `worker-start --retry-of` and the same brief, when the retry writes `<dir>/return-contract.yaml`, then the first attempt's contract and report are overwritten, which WC-6 forbids. Finding 3.

**Cockburn (actors and goals).** Actors are clear: coordinator, worker session, command, person (`SPEC:55`, `SPEC:72-73`). The person sharing the worktree is missing: workers share the current worktree by default (`CAPS:115`), and the cleanup and improve rows apply source edits under `--unattended` (`SPEC:103,110`) although the routing guide makes an authorized checkpoint commit the precondition for those commands (`HOW-WE-WORK.md:170`, `:365`) and section 4 says workers make no commits (`SPEC:133`). Finding 7.

## 3. Architecture analysis (Fowler, Nygard, Newman, Hohpe)
=== ARCHITECTURE ANALYSIS ===

**Fowler (interfaces and boundaries).** The central decision (coordinator on top, commands as units, no Orca calls in commands) is sound and well evidenced: depth 1 (`CAPS:97-98`), `worker_done` bound to the dispatched pane (`CAPS:76,150`), standalone use outside Orca (`CAPS:147-149`). The coordinator-to-command interface has two unspecified edges:
- The switch is per command, but commands call other commands. Only tasklist to reflect (`SPEC:122`) and tdd to `/task` (`SPEC:90`) are covered. Brainstorm runs an adversarial step (`sc-brainstorm-protocol/SKILL.md:345` `adversarial_artifacts_dir`), workflow runs `/sc:reflect --mode pre` (`return-contract.md:16`), auggie-review offers a design-workflow-reflect chain (`auggie-review.md:53`), pr-submit calls troubleshoot (`sc-pr-submit-protocol/SKILL.md:194`, Wave 4). No rule says that `--unattended` passes down, where the nested report goes, or how a nested `blocked` reaches the parent's contract. Finding 6.
- The rollout makes the flag an interface before its behaviour exists: P1 makes every 3.1-3.2 command accept `--unattended` "as a no-op where a command has no gate" (`SPEC:159`) and AC-1.1 requires the section on all of them in P1 (`SPEC:195`), but gates and outward defaults are converted only in P2-P4 (`SPEC:160-162`). Finding 4.

**Nygard (failure modes).** The stall analysis in 1.4 (2) is correct and important: a command prompt after readiness is a silent stall, visible only as `agentWait` (`SPEC:44`; `CAPS:129`). Weak points:
- WC-10's 4-minute split (`SPEC:68`) covers poll waits but not a single Agent-tool call, which blocks the top-level session until the subagent returns. Tasklist fans out one reflect agent per phase in one parallel wave (`sc-tasklist-protocol/SKILL.md:1618`), so heartbeat gaps beyond 5 minutes are normal. Absence of heartbeats never authorizes stop or retry (`CAPS:125`), so the impact is limited. Finding 10.
- 7.2 step 2 passes when `agentWait` is "never non-null" (`SPEC:181`); an absent field means Orca never looked (`CAPS:129`), so a run with no observations passes. Finding 11.

**Newman (evolution and compatibility).** SA-1 to SA-6 are the right compatibility promises. Two things threaten them: renaming the existing `status` values to satisfy WC-4 changes standalone output (finding 1), and the AC-C5 / AC-0.3 additive-edit checks miss deleted bullet lines, so SA-4 and SA-5 are not enforced (finding 8). The spec also pins no base commit; current `origin/master` already ships a `WORKER-CONTRACT.md` and an Orca-calling skill (finding 12).

**Hohpe (messages and delivery).** Pull-only follow-ups (WC-12, `SPEC:70`), resume of `ask` by message ID (WC-3, `SPEC:61`) and exactly-once `worker_done` (WC-5, `SPEC:63`) match Orca's guarantees (`CAPS:60,66-67,73`). WC-3 assumes every answer can be passed back "as a flag" (`SPEC:61`); free-text clarifications (tdd's topic clarification, `SPEC:90`; recommend's clarifying question, `SPEC:115`) have no flag to carry them. Finding 15.

## 4. Adversarial analysis (Whittaker)
=== ADVERSARIAL ANALYSIS ===

- **A1, Sentinel Collision (CRITICAL).** I can break this specification by **sentinel collision**. The invariant at **WC-4 / 7.2 step 4** (`SPEC:62,183`) fails when **a command that already writes `return-contract.yaml` keeps its own `status` field**. Concrete attack: `/sc:workflow "<x>" --handoff none --unattended` completes; its contract says `status: success` (`return-contract.md:7`, `:27`). Step 4 asserts `status in {'succeeded','partial','failed','blocked'}` and fails. If the implementer instead renames `success` to `succeeded`, a person's standalone run now emits a different contract, breaking SA-1 (`SPEC:146`) for any caller that reads `status`. Same collision for brainstorm (`SKILL.md:341`) and adversarial (`SKILL.md:436`). Finding 1.
- **A2, Zero/Empty (MAJOR).** The invariant at **WC-4** fails when **`--unattended` is passed with no output flag, or with a file-valued one**. Concrete attack: `/sc:init-lite --unattended --output .dev/x/report.md` (`init-lite.md:32`: a file path). `<output-dir>/return-contract.yaml` is undefined: `report.md/return-contract.yaml` is not a valid path. With no output flag at all, the contract "written on every outcome" (`SPEC:62`) has no location. Finding 2.
- **A3, Sequence (MAJOR).** The invariant at **WC-6** (`SPEC:64`) fails when **steps repeat**: dispatch, fail, `worker-start --retry-of` with the brief unchanged (`SPEC:73` does not require a new directory). Before: `<dir>/return-contract.yaml` = attempt 1 `failed`, `<dir>/REPORT.md` = attempt 1 evidence. After: both overwritten by attempt 2. Finding 3.
- **A4, Sequence (MAJOR).** The invariant at **WC-2 / WC-9** fails when **phases execute in their stated order and a coordinator dispatches between P1 and P2**. After P1, `auggie-review.md` has an `## Unattended mode` section (AC-1.1, `SPEC:195`) but its posting default is still on (`auggie-review.md:51` "No confirmation prompt"); `/sc:auggie-review 123 --unattended` posts to GitHub. Finding 4.
- **A5, Sentinel Collision (MAJOR).** The invariant at **D1 (a)** "cannot misfire on a person" (`SPEC:228`) fails when **the flag text appears inside a person's quoted argument**. Concrete attack: `/sc:tdd "explain why --unattended disables prompts"`; a substring test (no token rule exists in the spec) turns prompts off for a person, breaking SA-1. Finding 5.
- **A6, Divergence (MAJOR).** The invariant at **WC-2** fails when **the command under `--unattended` invokes another `/sc:` command that was not passed the flag**. Concrete attack: `/sc:brainstorm "<x>" --unattended --output d/` runs its adversarial step (`sc-brainstorm-protocol/SKILL.md:345`); nothing forwards `--unattended`, so any nested gate parks the worker on a prompt (`agentWait` non-null), with no `worker_done`. Finding 6.
- **A7, Accumulation (MAJOR).** The invariant at **WC-11** (`SPEC:69`) fails when **two writers edit the same source file**: two `/sc:improve src/x/ --unattended` workers in the default shared worktree (`CAPS:115`), or one worker and the person. WC-11 covers only output paths; the edits interleave and, with no checkpoint commit (`HOW-WE-WORK.md:365` step 1), cannot be separated or undone. Finding 7.
- **A8, Sentinel Collision (MAJOR).** The invariant at **AC-C5 / AC-0.3** (`SPEC:176,193`) fails when **a deleted line starts with `-`**. Concrete attack: removing the bullet `- **Single-owner keys** ...` from `save.md` yields the diff line `-- **Single-owner keys** ...`; `grep -E '^-[^-]'` does not match it, so the check prints nothing and passes. Tested: of the inputs `-- bullet removed`, `---flag removed`, `-` and `- plain`, the pattern matched only `- plain` (count 1). Finding 8.
- **A9, Sequence (MAJOR).** The invariant at **AC-0.4** (`SPEC:194`) fails by construction: it requires 7.2 steps 1-3, and step 3 requires "its report path is the WC-4 contract path" (`SPEC:182`), which no command writes before P1 (`SPEC:79`). A literal P0 run fails, and the spec says such a failure "reopens section 1". Finding 9.
