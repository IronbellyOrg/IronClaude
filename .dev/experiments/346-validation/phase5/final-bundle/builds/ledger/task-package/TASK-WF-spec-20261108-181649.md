## Task 1: Create the ledger kernel core with init, find, close, status and verdict

Create `src/superclaude/skills/sc-review-ledger/scripts/review_ledger.py` (source.md section 2 "Parts", "Where the ledger lives", "Termination", and section 3 "Script CLI outline"; ledger file format in `.dev/brainstorms/346-ledger/merged-requirements.md` section 3 "Ledger file", CLI detail in its section 6). Before creating any file, write `./artifacts/untracked-before.txt` with the output of `git status --porcelain --untracked-files=all` (the files that existed before this plan; Task 12 uses it). This task builds the shared core and the review-1 path:

- Ledger folder `<doc dir>/<doc stem>.review-ledger/` by default, `--ledger <dir>` override; contents `ledger.json`, `snapshots/`, `diffs/`, `inputs/`, `.lock`.
- `ledger.json`: one UTF-8 JSON object, `schema: 1`, keys `schema`, `profile`, `doc`, `cap_reviews`, `round`, `fix_cycles`, `phase`, `seq`, `snapshots`, `decisions`, `ops`, `rows`, `body_sha256`; each row carries frozen fields (id, grade, rule, wrong_outcome, blocking, anchor, origin, scope, caused_by, finding text), a mutable `status` and its own `history`. `round` is the review number k (1 to 3) and always equals `1 + fix_cycles`; `fix_cycles` counts committed `begin` calls.
- Phases: `find` (after `init`), `revise` (after a `close` whose decision is CONTINUE), `verify` (after `begin`), `terminal` (after a `close` whose decision is PASS or ESCALATE), `swept` (after the sweep). Each subcommand names the phases it accepts; any other phase is `E-PHASE`.
- `body_sha256` is recomputed on every call before anything else; a mismatch refuses with `E-TAMPERED` (exit 3) and writes nothing.
- Every write: temp file, fsync, `os.replace`, under a nonblocking `fcntl.flock` on `.lock` (held lock: exit 4). Mutations take `--op` and `--expect-seq`; a stale sequence is exit 4; an identical request (same digest within phase and round) under a new op id returns the committed result and does not use a slot.
- `--input F` (for `find`, and later `answer`, `verify`, `sweep`): a path ending `.json` is read as the JSON input; a path ending `.md` is read as a report and the input is the single fenced block whose info string is `ledger-input` (zero or several such blocks: `E-SCHEMA`). The ingested JSON is copied to `inputs/`. This is how a review session that may write only its own report hands its rows to the ledger step (owner ruling M-F21).
- `PROFILES` dict with one row `spec-panel`: grades CRITICAL/MAJOR/MINOR, blocking predicate `grade == CRITICAL or rule in {FR-8, FR-9} or (grade == MAJOR and wrong_outcome non-empty)`, cap. Module constant `CAP_REVIEWS = 3`.
- `init --doc D --profile spec-panel [--archive-existing]`: creates the ledger and `snapshots/r1.md`, prints `review: 1 of 3`; refuses `E-EXISTS` when a ledger exists; `--archive-existing` renames the old folder first (never deletes).
- `find --input F`: rows with `grade`, `rule`, `wrong_outcome`, `anchor`, finding text; accepts an empty array; each anchor must occur exactly once in the snapshot (`E-ANCHOR`, `E-ANCHOR-AMBIGUOUS`); bad shape `E-SCHEMA`; second `find` `E-PHASE`; non-blocking rows stored `deferred`.
- `close --report R` (after a committed `find` or `verify` in this round, else `E-PHASE`): computes `loop_decision` with the source.md section 2 termination formula (`U`, `X`, `I`), appends the tail (the line `review: k of 3`, the rendered ledger, a Reviser brief listing only blocking row ids and restating the base Reviser contract: revise only text a blocking row names, add no rule, mechanism or section no blocking row calls for, cite the row id for each added paragraph or table, report the byte size before and after; then the decision line), stores the tail text and its digest. Last line: `verdict: FAIL` for CONTINUE; for a terminal decision at any k, a review-1 PASS or ESCALATE included, `loop: PASS (sweep pending)` or `loop: ESCALATE (sweep pending)` (owner decision: the sweep is never skipped). A terminal tail carries no Reviser brief.
- `status` (read-only counts) and `verdict` (read-only; exit 0 PASS, 10 CONTINUE, 11 ESCALATE, 12 PENDING whenever the loop is terminal and the sweep has not run).
- Output is one JSON object on stdout (`{ok, seq, phase, review, fix_cycles, counts, loop_decision, delivery_outcome, next_action}` or `{error, detail, next_action}`); exit codes 0 committed whatever the decision, 1 usage, 2 row-level input refused, 3 state refused, 4 lock or sequence conflict.

Create `tests/skills/test_review_ledger_script.py`, loading the script by path with `importlib.util.spec_from_file_location` as `tests/skills/test_workflow_archive.py` does (lines 22-28), and running the CLI through `subprocess` with `sys.executable` in `tmp_path`. - `begin --doc D [--revert-unclaimed]`: check order `E-TAMPERED`, then `E-CAP` (a fourth review, which is also a third fix cycle), then `E-TERMINAL`, then (Task 3) `E-REPORT-EDITED`. - `revert-unclaimed [--hunk k]` (reviser, phase `revise`): restores provisional hunk k, or every provisional hunk no stored answer claims, in the live document, preimage-checked; any other phase `E-PHASE`.

## Task 3: Add verify, the full loop to the cap and the report-tail check

Depends on: Task 2

Extend `src/superclaude/skills/sc-review-ledger/scripts/review_ledger.py` with `verify --input F` and the remaining loop rules (source.md section 2 step 3 second half, steps 4 and 5, the full status-transition table, the dispute rule, and `E-REPORT-EDITED`):

- `verify` (phase `verify`): every plan row answered once with `resolved`, `open`, `regressed` or `cannot-verify`, an evidence quote that must occur in the new snapshot, and `touched_ok` (`no` requires a child row); a missing answer is `E-INCOMPLETE`. `resolved` moves `fixed -> verified`; `resolved` on a row still `open` or `reopened` (no hunk touched it) is `E-NOT-CHANGED`. `open` moves `fixed -> open`, or `reopened` if ever verified (from history), and needs a reason or quote. `regressed` is allowed only on a row whose history holds `verified` and moves it to `reopened` (else `E-ILLEGAL`). `cannot-verify` leaves the status unchanged and counts in `X`. An untouched `verified` row cannot be reopened (`E-NOT-CHANGED`); any change to a frozen field is `E-FROZEN`; a deferred row cannot change (`E-ILLEGAL`). New rows: anchored inside a hunk (either diff side) become `scope=in`, `origin=changed`, `caused_by` = the rows that claimed the hunk, and can block; anchored outside the hunks become `scope=outside`, `deferred`, never block. A dispute is a flag on a claim; an unruled dispute at the cap counts as open.
- `begin` refuses an edited report tail (`E-REPORT-EDITED`) by comparing the stored tail digest with the report's last lines. Recovery: in phase `revise`, `close --report R` on a report that no longer ends with its stored tail re-appends the stored tail text unchanged (no new decision, recorded in history); on a report that still ends with it, `close` is `E-PHASE`.
- Review 3's decision can only be PASS or ESCALATE.
