## Suggested resolution per UNADDRESSED HIGH item
- **INV-001**: Use the coordinator's existing saved copy (SP:261) as the baseline, and put the receipt data inside the disposition file, so the reviser writes no `.fixcheck/` file.
- **INV-002**: Make the review-N `fixbudget` block list every still-open prior blocking id with its class, not only the findings new to this review.
- **INV-005**: When the checker sees a hard-gate finding graded minor, have it reclassify the finding as class M and record a warning, instead of exiting with an input error.
- **INV-006**: Write one exit-code table used by every actor. Rewrite B's reviser actions and `enforce` triggers in terms of C's codes, and assign each action to the reviser or the reviewer, never the coordinator.
- **INV-007**: Add one rule: any fail-closed stop before review 3 escalates to the user with the open blocking findings and the named input error.
- **INV-012**: Fix the cycle-cap revert order (lowest class first, then smallest gross) and record each cut finding as escalated with its need.
- **INV-023**: Exempt the condition words of an FR-8/FR-9 gap fill from the condition counter, up to the guard rows the finding names, and keep those rows within the finding's budget.
- **INV-026**: Withdraw the claim that the mechanism alone makes review 3 reach 3 or fewer. Pre-register within-budget parents with blocking children as a measured column (B's `attacks:`), and state the convergence claim only as conditional on it.
- **INV-027**: Add guard-introducing words (`where`, `only when`, `unless`, `if`) to the condition counter, and count each new guard against the finding's budget.
- **INV-028**: Pre-register a cut-down success-rate check in the replay harness, and report the review-3 count split into carried and new findings before the bar is applied.
