## 6. Official install page on `main` now describes v7 preview, not v6 (topics b, c, f-for-option-F)

**Sources:** https://docs.bmad-method.org/start/install-bmad/ and https://github.com/bmad-code-org/BMAD-METHOD/blob/main/docs/start/install-bmad.md (official docs; reliability: HIGH; text below is the fetch helper's extraction with quotes, so quoted strings are as extracted by it, not re-read raw: MEDIUM-HIGH).
**Relevance:** HIGH. **Relation to codebase findings:** EXTENDS and partly CONTRADICTS the assumption inside option F and option A that "the documented install flow" is the v6 `npx bmad-method install` flow.

What the pages say (both pages agree):

- The default docs now cover the **v7 preview alpha**, with a warning about breaking changes. **v6.12** is described as the stable alternative: "`npx bmad-method install`", with the sentence "The rest of this page does not apply to v6.12." Readers on v6 are sent to "the V6.12 branch's source and documentation" (https://github.com/bmad-code-org/BMAD-METHOD/tree/V6.12).
- v6.12 requirements: Node.js 20.12+, Python 3.10+, and `uv`.
- v7 install is a different mechanism: "`npx skills add bmad-code-org/BMAD-METHOD --skill '*'`" (all skills; it "asks which coding tools to install to"), or the same command without `--skill '*'` for an interactive pick; then, in the coding tool, ask the installed `bmad` skill to execute "`bmad setup`" (creates the project's shared runtime and module scripts), and verify with "`bmad status`". A marketplace route (`/plugin marketplace add bmad-code-org/bmad-plugins`; `codex plugin marketplace add bmad-code-org/bmad-plugins`) is marked "Not v7-ready yet".
- v7 locations named: `_bmad/` (shared configuration, runtime, module-support scripts), `_bmad/scripts/` (Python scripts used by skills), `_bmad/custom/` (retained across setup refreshes), `_bmad-output` (generated documents).
- The v7 page acknowledges global scope in one sentence: "Keep project and global installation scopes consistent." It gives no scope flags and no user-level destination path. Both fetches report: no separate user-level or global installation procedure is provided.
- Headless: "None are documented" on the v7 page ("Even the all-skills command asks which coding tools to install to"). Empty or new directory: no explicit guidance on the v7 page.
- Install-on-demand: the helper reports that a security discussion on the page says some skills request missing-skill installation with `npx skills add`, but "does not describe automatic installation".

What this means for our question:

1. v7 upstream design is "skills first, project runtime second": skills are installed by a separate tool (the Skills CLI), possibly at global scope, and a first-use step `bmad setup` creates the project's `_bmad/`. That is structurally the pattern our option B/D (stub or hook that creates project files on first use) imitates, but it is a v7-preview mechanism: it is NOT in 6.9.0 and the page says it is alpha with breaking changes. The page text I received does not say what happens when a v7 skill runs in a project where `bmad setup` was never run (see section 8).
2. v6.12 remains the stable line and has the same project-level `npx bmad-method install` flow and the same `bmad-method` package (latest published `6.12.4`).
3. Because the main-branch docs are v7-preview, a reader who follows "the documented install flow" on the website gets the v7 flow. The documented flow for our 6.9.0 pin lives at the `v6.9.0` tag (section 7). The npm tarballs for 6.9.0 and 6.12.4 contain no `docs/` directory (observed by `ls` of both extracted packages).
