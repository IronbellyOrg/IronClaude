Where the variants agree: the core decision-table cells. Every variant blocks the implement skills only at `worktree` before approval, blocks commit, push and `/sc:pr-submit` below `full --submit`, never lets approval unlock them, blocks merge and protected pushes at every level, allows ordinary Edit/Write and local subagents, and blocks scheduling tools. The fight is about the edges: what happens when state is missing or broken (X-001 to X-003, C-015), how subagents are recognised when U1 fails (C-002, X-004), and how wide the Bash and tamper nets are (C-004, C-008 to C-010, X-006 to X-008).

Per-variant pattern:

- Variant 1 is the most complete and the strictest on failure (marker always governs, traps to exit 2, remote and repo checks, MCP coverage). Its main cost is size and an asserted answer to U7: O-5 says "An `orca agent launch` session has no Task or Dispatch ID, so it is an ordinary session", which `WORKER-CONTRACT.md` section 1 supports only if no preamble is sent, and that is still UNVERIFIED.
- Variant 2 is the smallest and closes the tamper route best (two-part store name, escaped-slash tokens, settings and hooks tokens), but it lets a lost or stale nonce leave a session ungoverned (X-001), allows `git pull` (X-008), drops UserPromptExpansion, and does not cover MCP, Monitor or Workflow.
- Variant 3 has the most concrete test cases and the best speed regression guard, but carries three state-mechanics errors that break acceptance criteria: its always-on cwd fallback governs a person's own subagents (X-004, AC-4), it does not stop settings edits that switch the hook off (X-006, AC-5), and it allows `git push origin HEAD` from `master` and `--all`/`--mirror` at submit (X-007, AC-6). It is also the only variant that fails open on missing `jq` and on bad input in a governed session (X-002, C-015).

Repository and verified-fact checks: three variant claims contradict the repository (X-009 git hooks location; X-010 `_FRESHNESS_SCRIPTS` location in V1 and V3, the unregistered `manual` marker under `--strict-markers` in V3, `session-init.sh` as a state example in V3). Two variant claims misread a VERIFIED fact: V3's use of V8 to justify fail-open (X-002) and V3's use of V4 to rule out the fallback false positive (X-004); V3's settings claim is contradicted by V11 (X-006).

One further shared gap did not fit the assumption cap: all three assume every git call contains the word `git` (or a path ending `/git`) in the command text. None protects the shell startup files the Bash tool is initialised from, so an alias or function defined in `~/.bashrc` could hide `git` from every scanner (whether a mid-session edit takes effect is UNVERIFIED). V1 and V2 list git aliases; no variant lists shell aliases.
