TERMINAL DASHBOARD CONCEPTS
===========================
Design sketches, not a running application. All data is SYNTHETIC.
Ten complete compositions: five chat snapshots and five live-terminal concepts.
These are parent-authored visual refinements of the saved brainstorm proposals,
not an adversarially approved merge. Orca remains the orchestration authority.
Plain ASCII is intentional. No actual ANSI escapes or cursor controls are used.

SHARED DEMO SCENE
-----------------
At 15:00 UTC: 24 observed workers, each in one display bucket:
16 active (A), 4 waiting (W), 3 reported complete (D), 1 unavailable (?).
Reported complete is not verified or merge-ready. Requests and blockers overlap
these buckets and must not be added to worker counts.
Three observed human requests: schema choice 42m, API target 18m, review 7m.
Two reported blockers: schema choice and a CI queue. Schema choice affects two
waiting workers; API target one; review one. CI queue affects an active worker.
Local host covered; expected-host inventory unknown. Inbox is partial.
The oldest request shown is the oldest OBSERVED, not necessarily the true oldest.
Demo operator owns all three requests. Billing, API and UI workers requested them.
Evidence identifiers DEMO-M1/M2/M3 are illustrative, not live links.
No cost, tokens, completion percentage, delivery ETA or performance claims.

INTERACTIVE TERMINAL CONCEPTS
============================
All key hints below describe proposed behavior, not working controls.
Observe-only first. Opening or reading never consumes Orca's inbox.
If added later, reply/acknowledge/resolve remain separate explicit operations.
Selection follows stable identity, never a changing row number.
Pause freezes the view, not workers; show frame age and queued updates.
Input stays ASCII; optional ANSI color must never be the only status signal.

INTERACTION CONTRACT FOR ALL FIVE
---------------------------------
- Filter by run, host, worktree, state, owner, age and observed attention.
  Always display active filters and distinguish filtered-out from unobserved.
- Header counts use the declared scope; selected-pane counts name their filter.
- Refresh cadence is a future implementation choice, not established here.
- Freeze leaves collection running only if the future collector supports it;
  otherwise disclose a collection gap instead of inventing queued updates.
- No action keys send anything in these sketches. Later actions need a target,
  fresh authority check and explicit confirmation. Transport acceptance does
  not prove an answer was read or that a decision was resolved.
- Human-seen state must not acknowledge or consume coordinator deliveries.
- Older hidden messages and unavailable hosts can contain further requests.

VISUAL COMPARISON
-----------------
S1: quiet reading. S2: compact overview. S3: cause and effect.
S4: communication clarity. S5: repeated-update readability.
I1: balanced triage. I2: ambient instruments. I3: time-focused investigation.
I4: conversation-heavy work. I5: broad worker-state overview.
Provisional starting pair: S2 + I1. This is a visual recommendation, not approval.
Use I2 when the desired character is a dense instrument panel, I4 when reading
and responding dominates. None requires adopting another orchestration product.
