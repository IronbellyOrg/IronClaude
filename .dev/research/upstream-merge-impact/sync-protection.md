[CODE-VERIFIED] **Actual protection boundary:** command/agent sources are copied into root `commands/` and `agents/`, not into the fork's canonical `src/superclaude/` or installed skill tree. The script hashes existing files under its protected list (fork documentation, `.claude-plugin/`, `.github/`, `scripts/`, `tests/`, backups, core and modes); it rejects modifications/deletions found immediately after `_sync_content`. Evidence: `scripts/sync_from_framework.py:443-480,490-522,584-639,719-766`. The declarative mappings are descriptive: `_sync_content` hardcodes those two source/destination pairs rather than iterating `SYNC_MAPPINGS` (`scripts/sync_from_framework.py:719-766`).

[CODE-VERIFIED] **Important limit, not a reason to strip protection in isolation:** the hash check precedes manifest generation and MCP merging. It does not prevent the later intended manifest write, and checks only pre-existing snapshot files, not additions under protected directories. The external workflow separately checks five selected root files. Evidence: `scripts/sync_from_framework.py:503-522,593-603,618-626,768-817`; `.github/workflows/pull-sync-framework.yml:56-78`. Removing only these checks while retaining the importer would weaken an active safety boundary and is not recommended.

[CODE-VERIFIED] **Severity: important, persistent namespace corruption.** The header rewrite accepts any slash plus word and prepends `sc:` without recognizing an existing `sc:` namespace (`scripts/sync_from_framework.py:70-102`). The current generated analysis command actually has `# /sc:sc:sc:analyze` and `/sc:sc:analyze` examples (`commands/sc-analyze.md:10,20`), rather than the canonical command's single namespace. This is a concrete cost of continuing the old transformation pipeline; repairing imported copies is a separate decision in the automated-sync-copies unit, not a source edit made by this investigation.

[CODE-VERIFIED] **Severity: minor, validation is not semantic validation.** `_validate_sync` counts prefixed Markdown files and checks whether the manifest exists, logging warnings rather than validating command references or rejecting duplicate namespaces (`scripts/sync_from_framework.py:822-843`). Therefore the current validation does not establish that copied prompts are usable.

### Recommendation and reversal prerequisites

**Verdict: revert this importer feature as a scoped cleanup, not by indiscriminate historical rollback.** Its only identified direct consumer is the scheduled/manual workflow, while continued namespace rewriting already produces malformed command names. The recommendation is to stop the importer before deciding whether to keep or repair imported copies; it is not a recommendation to remove the fork's canonical package, skills or independent CI safeguards.

1. **First retire the producer:** after explicit approval, remove/disable the workflow's scheduled/manual entry point together with its standalone importer. Until then the producer can write upstream copies back into root directories and delete prefixed files absent from upstream (`.github/workflows/pull-sync-framework.yml:3-6`; `scripts/sync_from_framework.py:199-246`). Do not remove protection checks alone.
2. **Then resolve references/cursor:** update the workflow overview and decide whether the now-inert cursor should remain as provenance. The complete tracked direct-reference set is preserved at `.dev/research/upstream-merge-impact/sync-protection-git-evidence.txt:974-1001`. Validate references again at execution time, because other work can add consumers.
3. **Only then consider namespace-copy changes:** the automated-sync-copies unit determines whether its root command/agent outputs and manifest should stay, be repaired, or be removed. This unit's two-file payload did not add those assets, so their rollback is not a prerequisite to retiring its producer.
4. **Preserve unrelated fork work:** do not reverse the broad later formatting/CI commits just to get rid of their edits to these two files. In particular leave the independent swarm advisory guard intact; its actual watched paths are `.github/workflows/boundary-guard.yml:25-33`.
5. **One history carrier only:** if the user chooses a historical reversal rather than scoped removal, use either the upstream payload or the importing merge's first-parent mainline, not both. Resolve the current file removals deliberately and review the later fork PR-flow loss. No such action was performed here.
