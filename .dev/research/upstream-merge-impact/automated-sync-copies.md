### Current consumers and distribution boundaries

1. [CODE-VERIFIED] **Positive root-plugin consumer contract, not dead files.** `.claude-plugin/plugin.json:1-12` identifies a repository-root plugin named `sc`. `CHANGELOG.md:11` explicitly distinguishes the repository-root plugin that can currently be installed from the future build under `plugins/superclaude`; the latter lacks its required manifest metadata. The fork's own command documentation says plugin commands come from the plugin root's `commands/<name>.md`, with the namespace supplied by `${CLAUDE_PLUGIN_ROOT}/.claude-plugin/plugin.json` (`src/superclaude/commands/help.md:25-28`). These are sufficient to reject a claim that root command/agent trees are definitely unused. [UNVERIFIED] Actual current external installations, platform loader execution and usage counts were not inspected.

2. [CODE-VERIFIED] **Marketplace check.** Direct Read of `.claude-plugin/marketplace.json` returned missing. `git ls-files '.claude-plugin/*' '*marketplace*' 'plugin.json'` returned only `.claude-plugin/plugin.json`; no tracked repository-root marketplace registration or root `plugin.json` was found. This does not negate direct plugin loading by root path or an external marketplace pointing at this repo. Negative evidence and search scope are recorded here; absence of an in-repo marketplace is NOT proof of no deployments.

3. [CODE-VERIFIED] **Package and CLI install are separate.** `src/superclaude/cli/install_commands.py:96-126` selects package commands, with `plugins/superclaude/commands` as fallback; `src/superclaude/cli/install_agents.py:89-108` selects package agents. `pyproject.toml:78-97` includes `src/` and `plugins/` in distributions, not the root namespace copies. Normal command/agent installation therefore does not need these bot-created root files. The root manifest and root assets have no Python import dependency.

4. [CODE-VERIFIED] **Plugin build does not consume the root copies, but is not a drop-in replacement today.** `scripts/build_superclaude_plugin.py:15-23` reads `plugins/superclaude/manifest/metadata.json`; that file is absent by direct Read, agreeing with `CHANGELOG.md:11`. It copies the separate plugin source assets (`scripts/build_superclaude_plugin.py:74-90`); the Makefile publishes those built directories to another plugin repository (`Makefile:65-86`). Reverting root plugin assets and saying 'use the existing build instead' would leave a verified missing-input blocker and still require migration of consumers. No build was run.

5. [CODE-VERIFIED] **Active writer and cursor dependency.** The scheduled workflow compares upstream HEAD with `docs/.framework-sync-commit`, runs `scripts/sync_from_framework.py` in the checkout, records the new cursor, stages root commands/agents/manifest, and proposes `sync/framework` via a pull request (`.github/workflows/pull-sync-framework.yml:21-54`, `.github/workflows/pull-sync-framework.yml:80-118`). The script maps upstream `src/superclaude/commands` and `agents` to root `commands` and `agents` with `sc-` filename prefixes (`scripts/sync_from_framework.py:719-758`). Its directory synchronizer writes upstream bodies and removes destination-prefixed files not present in the upstream source (`scripts/sync_from_framework.py:200-248`). A root-asset removal without changing this writer is not durable; a cursor-only reversal encourages another comparison/import attempt.

6. [CODE-VERIFIED] **Generic tools are possible consumers, not evidence of widespread use.** `src/superclaude/cli/cli_portify/resolution.py:78-85` falls back to a supplied project's root `commands`/`agents`; explicit existing Markdown paths are accepted (`src/superclaude/cli/cli_portify/resolution.py:89-105`). Its discovered references were the synthetic directory-tree tests, not a proven production caller; tests construct their own trees (`tests/cli_portify/test_resolution.py:30-79`). The old cleanup script reads `project_root/commands`, but its root detector requires a root `plugin.json`, which is absent here (`src/superclaude/scripts/clean_command_names.py:23-42`, `src/superclaude/scripts/clean_command_names.py:128-145`). Do not promote either into a verified live deployment dependency.

7. [CODE-VERIFIED] **Scoped consumer search result.** Git-tracked searches outside root `commands`, root `agents`, `.dev`, `.claude`, and generated indexes found no literal `commands/sc-` or `agents/sc-` consumers. The cursor has explicit workflow readers; a `sc-backend-architect` match is only the transformer's explanatory example. Complete query text and results are in `.dev/research/upstream-merge-impact/automated-sync-evidence.json` under `searches`; this negative search does not cover generic glob loaders or external repositories, so it cannot justify wholesale root deletion.

### Later fork work and overwrite consequences

[CODE-VERIFIED] **The fork did build on the imported root assets.** The root-asset history contains fork-owned formatting commit `89df2c11` (2026-05-22), reflection upgrade `80fd3520` (2026-06-04), command retirement `3ae238b1` (2026-09-30), and obsolete MCP-reference removal `046a03ab` (2026-10-03). Evidence: `.dev/research/upstream-merge-impact/automated-sync-history.txt:1-9`. These are actual later changes to the imported paths, not just later timestamps on unrelated code.

[CODE-VERIFIED] **An observed fork regression, not a theoretical dependency.** `80fd3520` replaced the root reflection copy with tiered pre/post modes, evidence-validation gates and corrected namespace spelling (`.dev/research/upstream-merge-impact/automated-sync-fork-reflect.txt:18-62`). July sync `ff5f73ad` removes those exact fork instructions and returns the root copy to Serena-only legacy behavior (`.dev/research/upstream-merge-impact/automated-sync-patches.txt:10870-11024`). The current root remains old (`commands/sc-reflect.md:18-45`) while the canonical fork command specifies tiered audit modes, preconditions and output guards (`src/superclaude/commands/reflect.md:13-35`). This is the narrow semantic overwrite worth reversing; it does not show that the canonical fork protocol was itself deleted.

[CODE-VERIFIED] **Known retired content must stay retired.** The fork explicitly removed `commands/sc-estimate.md`, `commands/sc-sc.md` and `commands/sc-select-tool.md` in `3ae238b1`, along with their canonical equivalents and removed-MCP references. The root deletion is visible in `.dev/research/upstream-merge-impact/automated-sync-fork-removal.txt:26-41` and the full saved patch; complete current absence is recorded in the changed-path appendix. Reversing broad historical command edits must not accidentally restore those retired commands merely to resolve conflicts.

[CODE-VERIFIED] **Namespace transformation defect exists independently of the copied content's usefulness.** Current root commands spell headings such as `/sc:sc:sc:implement` and usage `/sc:sc:implement` (`commands/sc-implement.md:10-23`) instead of the fork's canonical `/sc:implement` (`src/superclaude/commands/implement.md:9-18`). The writer first adds a prefix to the header, then transforms slash references again; neither pattern excludes already-prefixed `sc:` references (`scripts/sync_from_framework.py:70-102`). This explains repeated prefixes at the source-text level. [UNVERIFIED] Whether a particular platform loader accepts a different frontmatter name or exposes a filename-based command was not executed; do not mistake the prompt's spelling for a verified runtime registration.

[CODE-VERIFIED] **Later fork distribution work did not consolidate these trees.** The current normal installer/build paths remain separate from the root surface (`src/superclaude/cli/install_commands.py:96-126`, `scripts/build_superclaude_plugin.py:15-18`, `scripts/build_superclaude_plugin.py:74-85`), and the current changelog expressly acknowledges the old root plugin (`CHANGELOG.md:11`). Thus a whole first-sync reversal would remove a documented distribution path even though it would not remove the wheel's installed commands.
