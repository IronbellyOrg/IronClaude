[CODE-VERIFIED] `10844490` contains two unsafe conditions visible in source. If a backup copy fails, `|| true` hides it and execution proceeds to `rm -rf`; this establishes a potential unbacked deletion path, **not an observed deletion incident** (`scripts/uninstall_legacy.sh:37-43`). Separately, the script enables `set -e`, initializes `FOUND_COUNT=0`, and uses unguarded post-increment after the first successful removal. In Bash, an arithmetic command whose old value is zero returns nonzero, so that first increment can terminate the script after the removal and before later cleanup/settings processing (`scripts/uninstall_legacy.sh:7,52-57`). This is a static shell-semantics finding; the destructive script was not executed.

[CODE-CONTRADICTED] Treating `ab0bb0f5` as deletion of entirely identical duplicates would be false.
