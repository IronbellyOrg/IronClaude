## 1. Executive Verdict — Theatre vs. Net Value

The blunt finding: **for the registry miss class, the review stack was almost pure theatre.** Five review surfaces ran across this episode. Four of them (`sc:troubleshoot`, `task-builder`, `sc:reflect-PRE`, `sc:reflect-POST`) caught **zero** of the misses they should have caught before runtime. Only `adversarial` registered any pre-runtime catch — and that single catch (F-A) was actually delivered by the **human PR reviewer downstream of the adversarial pass**, not by the debate itself. Every M-series miss (M1–M6) was discovered by **runtime crash**, never by review.

**Aggregate:** across the five steps, **16 should-have-caught obligations, 1 actual pre-runtime catch (6.25%).** Theatre ratio of the stack as a whole ≈ **0.94**.

### The important nuance — "theatre" ≠ "did nothing"

`sc:reflect-POST` and the troubleshoot self-review were **not lazy**. The POST ensemble was a 3-model heterogeneous run with cross-class convergence 0.83 that genuinely caught an orphaned-field Drift (F1) and a real BLOCKER (#A) elsewhere. The problem is **orthogonality**: every rigorous thing it found was off-axis from the whack-a-mole defects, because it was structurally pointed at the wrong target — a *representation* of the change rather than the *executed bytes*. The value delivered was real but **never intersected the miss class.** That is the precise definition of theatre that matters here: motion that cannot, by construction, touch the defect.

**Net value verdict:** the stack produced real intra-fix defect catches (Drift, BLOCKER #A, F-A's substring regression via the human tail) but **net-zero value against the six registry misses that actually broke the pipeline.** The misses were 100% runtime-discovered. The review stack, as configured, was incapable of catching them — not unlucky, incapable.

## 3. The Systemic Causes (3)

### SC-1 — Oracle-by-abstraction: no review stage executes against the real artifact bytes / live call-graph
Covers **M1, M3, M4, M5.** Every correctness oracle was built from a *representation* of the input, not the executed artifact, and no stage forced the fix to run against the actual bytes/path that triggered the failure before certifying. M1's gates scored a driving spec that omitted the invariant; M3's convergence gate scored an analyst-asserted phase set instead of a real `re.finditer` trace; M4 verified an unused symbol while the runtime ran a re-implementation no test instantiated; M5's tests parametrized over the regex's own three branches rather than the producer's real output. Each oracle was a faithful test of a model the author already held — it could only **ratify, never falsify.** Structurally confirmed by the absence of any "run fix against the real file / trace the production call-graph" step and by green tests visually indistinguishable from real runtime coverage.

### SC-2 — Serial fail-fast ordering hides every downstream gate until the upstream wall falls — manufacturing the whack-a-mole
Covers **M2, M5.** The PRD pipeline is a serial chain of halt-on-hard-failure gates: at runtime only the FIRST reproducing fault is observable; all downstream gates are unreachable on real input until each upstream wall is removed. M1's crash at scope-discovery crashlooped every run before control reached build-task-file, so M2 could not fire until M1 was fixed; one `_check_verdict_field` gates four stages but M4's prior halt blocked three of them, so M5 was runtime-exercised on only 1 of 4. Each fix didn't regress the system — it **advanced the runtime frontier** to the next shadowed gate. This compounds SC-1: the only non-abstraction oracle (runtime) is itself withheld stage-by-stage. There is no gate-isolation, mocked-upstream harness, or "continue and collect all verdicts" mode.

### SC-3 — No cross-cutting-dimension oracle: every gate's attention unit is the single artifact-vs-its-own-claim, never the sibling / primitive / scope differential
Covers **M1, F-A, F-B.** Each stage scopes attention to one artifact judged against its own stated purpose; no gate's reference set spans the orthogonal dimensions where this defect class lives — the sibling-pipeline differential (M1), the implementation primitive's lexical domain (F-A: does `sig in heading` admit superstrings?), or the commit-scope containment boundary (F-B). Reviewers held the competence but aimed it one altitude too high/narrow: F-A's reviewers doubted the OLD heuristic yet never put the NEW matcher's string domain on trial; F-B's pipeline took the aggregate `gh pr diff` as atomic and never decomposed per-commit-scope. M1's invariant had **no enforceable home** — it lives only as inline prose in three sibling files; there is no shared `forbidden_flags` registry. Because the catching inquiry is never *in* the ordering, the defect is invisible regardless of reviewer skill; F-A/F-B were caught only by an out-of-pipeline human reading the literal diff.

## 4. Merged GENERALIZED Remediation Strategy (issue-agnostic)

Three remediations, one per systemic cause. All deliberately name **no** PRD/flag/matcher specifics in their principle/mechanism — episode detail is confined to coverage demonstration.

### R-1 → SC-1: Live-Artifact Oracle Gate with Negative-Witness Admission
**Principle.** A certification stage may pass a change only when its oracle satisfies three properties at once: **(a) independent provenance** — expected behavior derived from a source *other than* the party/spec that produced the change (an independent downstream consumer's real output, a captured golden trace, a reference implementation, or a second un-briefed reviewer), never the author's own restatement or the changed code's own branch list; **(b) territory-not-map execution** — exercised against the real executed artifact (actual bytes, actual path, code actually reached from the production entrypoint), with the tested symbol independently re-derived from that entrypoint, failing closed when the change/tests bind to an unreachable or shadow re-implemented symbol; **(c) demonstrated falsifiability** — shown capable of failing by reproducing the defect against reality with the fix *absent* before being accepted with the fix present.

**Mechanism.** A terminal gate placed after candidate selection and before the pass verdict, refusing green unless it records four mechanically-checkable items: (1) **entrypoint re-derivation** — re-derive the reached path by static call-graph or dynamic instrumentation from the production entrypoint; a change/test bound to an unreached or shadow-re-implemented symbol fails closed; (2) **negative witness** — a recorded execution where the oracle runs against real captured input through the production entrypoint with the fix reverted and shows FAIL (supplied by revert-and-rerun / mutation automation); absence marks the suite UNSIGNED and blocks merge; (3) **positive witness** — identical harness, fix applied, shows PASS; (4) **oracle-provenance check** — reject any oracle whose expected output was authored or mechanically derived from the change's own source, and reject author-asserted (non-hash-pinned) inputs. Emit a binary `did_execute_real_path` flag; cannot certify while 0. Genuinely uncapturable inputs (nondeterministic / environment-coupled / destructive / sensitive) route through an **explicit, logged, audited exemption** — never a silent bypass.

**Generality.** Converges three independently-evolved practices: TDD red-green (a test never observed to fail proves nothing = negative witness); positive-and-negative assay controls in wet-lab/clinical diagnostics (a negative result is uninterpretable unless a known-positive control fires); chaos engineering / fault-injection (a redundancy claim isn't accepted until failure is injected live and recovery observed = territory-not-map). Transfers to a web-service incident review (regression test asserts a mocked handler while prod routes through omitted middleware) and a compiler fix (validated against the author's mental grammar instead of the real crashing corpus). **Covers M1, M3, M4, M5.**

**Cost.** Highest of the three: stands up call-graph/coverage tracing + a revert-and-rerun harness + an independent oracle producer, runs the oracle ≥2× per sign-off. Residual modes: (i) some defects have no cheaply-capturable real input → audited-exemption fidelity is only as good as its capture; (ii) entrypoint re-derivation defeated by dynamic dispatch/reflection → fail-closed blocks legitimate fixes and tempts operators to disable the gate; (iii) the exemption path *is* the bypass surface and must be logged/audited. Mitigate by scoping the full gate to certified-critical paths.

### R-2 → SC-2: Observe/Enforce Split with an Unshadowing Acceptance Contract
**Principle.** When the only ground-truth oracle is an ordered abort-on-first-failure chain, it emits one verdict per run and hides every downstream stage until all upstream stages are green. Two remedies: **(production of truth)** separate OBSERVE from ENFORCE — a stage failure must be *recordable without aborting traversal*, so one pass yields a complete verdict for every stage against realistic-shaped state while strict mode still aborts at the first hard failure; **(acceptance of a fix)** repairing an early-exit stage *advances the observability frontier* — sign-off therefore requires positive evidence that every stage the fix newly unblocked was actually executed against representative (not happy-path) input. The acceptance question is "what did my stage stop hiding, and has that been exercised."

**Mechanism.** Engine: an execution flag (shadow / continue-on-failure) splitting the `if outcome==fail: break` loop into (a) a per-stage evaluator that always runs and returns `{stage_id, pass/fail, reason, evidence, fidelity}` and (b) a policy layer that aborts on first hard-fail in enforce mode but appends-and-continues in shadow mode. Downstream stages run against a best-effort upstream state — canonically by **mocking the upstream to a VALID success output** (carry-forward last-known-good or recorded fixture), not by letting a failing upstream emit garbage; each synthesized verdict is tagged `shadowed` (degraded) vs `fully-reached` (ground truth). A troubleshoot run runs shadow mode FIRST as a discovery oracle to enumerate ALL currently-failing stages in one pass and dispatches fixes as a single batch — collapsing the serial whack-a-mole. Contract: **Gate 1 Frontier Delta** (which stages became reachable after the change); **Gate 2 Unshadow Exercise** (every delta stage must record an explicit pass/fail on representative input; any still-never-reached stage is `shadowed-verdict-unknown` and BLOCKS sign-off); **Gate 3 Anti-Whack-a-Mole Ledger** (record N expected newly-surfaced stages and list each verdict).

**Generality.** Compilers (GCC/Clang error recovery reports all diagnostics in one compile; fixing a lexer bug first exposes the parser); test runners (full pass/fail matrix → batch fix); request middleware chains (fixing auth is the only thing that lets requests reach schema validation); JSON-Schema collect-all-errors validators. **Covers M2, M5.**

**Cost.** Orchestration refactor so each evaluator is side-effect-free enough to run out of strict order; carry-forward/valid-success-mock path for upstream artifacts. Fidelity risk: synthesized upstream state can diverge → mitigated by mocking to a *valid* success output and mandatory `shadowed`/`fully-reached` tagging. Runtime/token cost rises (no short-circuit). Two policies (enforce vs shadow) must stay behaviorally consistent.

### R-3 → SC-3: Differential Oracle Gate (mandatory cross-reference wave before sign-off)
**Principle.** A pipeline whose every attention unit is "does this artifact satisfy its own stated purpose?" is structurally blind to violations that exist ONLY as a disagreement between a unit and a reference set its author does not control. No decision may be signed off on self-relative evidence alone: before sign-off, construct at least one explicit COHORT (≥2 units an invariant says should agree along a named dimension) and make the unit of attention the **differential** between members. "No inconsistency across the cohort" is non-derivable from "each member is internally fine."

**Mechanism.** A Differential-Oracle wave ordered before final sign-off, parameterized by three reusable cohort generators emitting machine-checkable status (consistent / divergence-found / no-cohort-constructible): **(1) Peer-Set/Consistency** — enumerate siblings of the unit (parallel modules / command paths / config consumers), diff each shared decision token across the set, flag any member diverging without recorded justification; expected-agreement relations live in a flat invariant registry (`{dimension → members expected to agree}`) run as ONE predicate across ALL peers including unchanged ones. **(2) Domain/Adversarial-Input** — for any predicate/matcher gating flow, mechanically enumerate adversarial neighbors of its decision boundary (superstrings, substrings, prefix/suffix-extended, case/decoration/look-alike variants of every literal token) and require each an explicit admit/reject classification. **(3) Containment** — compute the actual affected-element set and diff against the change's self-declared scope, flagging every element in one set but not the other. Two-tier enforcement: cheap high-precision differentials (Consistency, Containment) fail mechanically on any unjustified divergence (a missing differential artifact is itself a mechanical fail); the noisier boundary-neighbor enumeration is advisory. `no-cohort-constructible` is a first-class status that nudges registration, fighting registry staleness.

**Generality.** IaC fleet config (per-host schema passes while one host's flag drifted → peer-set differential); linters/parsers/access-control (`admin` blocklist silently admits `administrator` → domain differential); DB schema migration across services (new column correct while sibling consumers expect the old → consistency differential); release automation (a rider squashed into a refactor → containment differential = conventional-commit scope discipline). **Covers M1, F-A, F-B.**

**Cost.** Moderate, front-loaded: a flat invariant/cohort registry + three generator routines + a CI predicate-across-peers assertion; per-run bounded compute proportional to cohort/token-set size (~one extra wave). False-positive control is structural (mechanical fail only on the high-precision tier; boundary-neighbor advisory). Residual: registry staleness/ossification → mitigated by `no-cohort-constructible` and per-dimension scoping.

**Merge rationale.** R-3 is a merge of two converging remediations: it keeps the stronger SKELETON (differential as the literal attention unit, concrete generators, machine-checkable status enum, graduated enforcement, `no-cohort-constructible` status) and grafts in two hardening properties — "evidence against a reference set the author does not control" (rules out self-authored pseudo-differentials) and "a missing differential artifact is a mechanical fail" + "run the invariant as ONE predicate across ALL peers including the unchanged one" (closes the exact M1 hole).

## 5. The `sc:troubleshoot` Refactor + Would-Have-Caught Matrix

### What the prior refactor already had — and its residual blind spot
The prior refactor's gates all evaluate the **BASELINE code** and the verdict the pipeline emits — Wave 4.5 oracle (R-1), Wave 2.5 shadow sweep (R-2), Wave 4.6 differential (R-3). None of them ever (a) applies the candidate fix in shadow and re-sweeps siblings, (b) lints the remediation diff's own new code, or (c) audits the actual commit graph for scope creep. That is exactly the residual class **M3 / F-A / F-B** fall into: they are **PATCH-RELATIVE, not baseline-relative**, and invisible to any forward pass over un-patched code.

## 7. Bottom Line — Would the refactored pipeline have caught ALL of M1–Mn in one shot at `ac80f176`?

**Honest answer: yes for static coverage, with one load-bearing caveat — not all in a single *purely static* shot.**

The refactored pipeline achieves 100% registry coverage, but **it does not get there by static analysis alone.** Three of the eight misses are caught only by waves that **execute or simulate** rather than read:

- **M2 and M5** require the **shadow sweep actually driving the chain past the upstream wall** (R-2 / Wave 2.5). They are defects in *downstream* gates that a serial fail-fast chain structurally hides. No amount of reading baseline code surfaces them — you have to *run the chain in continue-on-failure mode against realistic input.* That is a runtime/exercise mechanism wearing a wave's clothing.
- **M3** is caught only by **applying the candidate patch in shadow and re-sweeping** (R-1's negative-witness discipline extended into SC-4 / Wave 4.7). Unmasking is, by definition, a property that exists *only after the fix is applied.* A forward static read of the un-patched code cannot see a false-positive that the fix itself creates.
- **M4** is caught only because Wave 4.5 **re-derives the live call-graph from the production entrypoint** and discovers the runtime runs a *different* evaluator than the one the fix touched. This is borderline-static (a call-graph trace can be static), but the certifying confidence comes from the *negative-and-positive witness pair* — i.e., from running the oracle against reality twice.

So: **would a single one-shot run of the refactored pipeline at `ac80f176` have caught all of M1–M6 + F-A + F-B? Yes** — because the pipeline's design *is* "run shadow-discovery first, enumerate all failing stages, batch the fixes, then re-sweep the patch." That single orchestrated pass collapses the serial whack-a-mole into one discovery-plus-certification cycle. The replay confirms it (100%, round 2). What it would **not** have done is catch them by *inspection* — every catch that mattered (M2, M3, M4, M5) routes through a stage that **executes against the real artifact, the real chain, or the patched chain.**

### What is irreducibly un-catchable by static troubleshooting alone

The episode's own data is the proof: **100% of the registry misses were runtime-discovered, 0% were caught by any reading-based review surface** (§1). The systemic causes name the reason directly — SC-1 (oracle-by-abstraction) and SC-2 (serial fail-fast hides the runtime oracle stage-by-stage) are both statements that *the only oracle that ever fired was execution.* Specifically un-catchable without a runtime/exercise mechanism:

1. **Map-vs-territory divergence (SC-1, M4).** When a fix and its tests bind to a symbol that *looks* live but isn't on the executed path, no static read of either side reveals the gap — both are internally consistent. Only re-deriving the path from the real entrypoint *and running the oracle against reality* (negative + positive witness) falsifies it.
2. **Shadowed downstream faults (SC-2, M2, M5).** A defect in gate N is invisible until gates 1..N-1 are green. Static reading of gate N's code won't tell you its *input at runtime* will be the real decorated verdict bytes that its regex rejects. Only driving the chain (shadow/continue-on-failure) against realistic captured input exercises it.
3. **Unmasking / second-order false-positives (M3).** A property that exists *only after* the candidate fix is applied cannot be present in the artifact a static pass reads. It requires applying the patch (in shadow) and re-running — an exercise step by construction.

The refactor's answer to all three is correct in kind: it does not pretend static inspection can find these. It **builds the runtime/exercise mechanism into the gate** — shadow-sweep discovery, live-call-graph re-derivation, negative-witness reproduction, and patched-shadow re-sweep. The irreducible truth is that **a troubleshooting pipeline that only reads code and specs will catch ~0% of this miss class no matter how many reviewer agents it fans out** — the value comes entirely from the stages that *execute against the real bytes and the real (and patched) call-graph.* The refactored `sc:troubleshoot` works because it stopped being a review pipeline and became an *exercise* pipeline at the points where it matters.
