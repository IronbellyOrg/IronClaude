# E2 opening case (advocate)

I argue E2 is third-best. It is not a strong pick, and I say so below.

## 1. Mechanism
E2 plugs in before the ab5 panel. Code in the coordinator extracts passages and builds a candidate pool of related pairs: explicit references, shared ids, paths, numbers and rare words (`p15/e2/extract.py`, `candidates.py`). Jev then labels each pair with two Noul questions, `same_behavior` and `incompatible`, plus a `context_sufficient` companion. Code ranks the pairs and renders at most 12 pairs in at most 1,200 tokens, as `section N "title" lines a-b` plus a code-written reason (`PLAN-E2` sections 2 and 4.2). The four panel reviewers (R1.t1b, R1.t2, R1.t3-1, R1.t3-2) read this as an UNVERIFIED reading-priority file. They still review the whole document. A missing or invalid answer gives document-order hints, so the fallback is the existing path.

It touches only the first-review input. The merge, ADJ, the clean VF, the revise step and the scoped re-reviews are unchanged, so it is cap-neutral.

## 2. Evidence
- **The target is real.** The ledger's main finding is that cross-section defects survive. D06-D12 (contract path vs WC-4, AC-0.4 step 3 needing P0 before the contract exists) are relations between distant passages. D09 and D10 are fixed in 0 of 6 specs in every arm except ab1 (2/6). D08 is fixed in at most 3 of 6 (`p17/score/perdefect.md`).
- **Static ranking misses chains.** Stage 0 measured H = 3 of 16 defect cases. These are pairs in the pool but outside static top-12: s0-21 and s0-23 (seeded reference chains) and s0-22 (real D16 relation, static rank 73). Static coverage was 2/16 (`p15/e2/offline/stage0-results.md`).
- **The other four integrations have all failed a gate.** E1 is NO-GO-OFFLINE (`p15/e1/results.json`). E4 is blocked behind E1. E3's automation was 0.179, under the 0.20 minimum (`p15/e3/results.json`). E5 has no headroom. E2 is the only one whose Stage 0 passed on headroom. Its block is the pool-miss count (11 > 2), not a negative Jev result (`p15/e2/results.json`).

## 3. Complementarity
- It reinforces the panel and lint by a different route. Panel diversity varies who reads. Lint catches mechanical issues. E2 directs where to read for non-lexical relations. Lint and the AC sweep already cover lexical and acceptance-criteria cases, so those pairs are duplicates and E2 should add nothing there.
- It duplicates the panel to a large degree: four reviewers already raise the "never found" themes. This is the main redundancy.
- Pairing with E3: E3 would cut verification of findings E2 helped surface, but E3 is NO-GO.
- Pairing with E1: E1 would check fixes. E1 and E2 act on opposite ends, so they do not overlap, but E1 is NO-GO.
- E2 does not touch the revise step, which is where fixes are lost.

## 4. Cost
- Tokens: 12 pairs x about 100 tokens is at most 1,200 input tokens per reviewer. For four reviewers that is 4.8k input tokens, against a panel of roughly 340k, or 1.4%. Output tokens, which is how loop tokens are measured, rise by at most a few hundred per reviewer. Reviewers may also write somewhat longer reports.
- Savings: none claimed.
- Jev: a pool of 150 pairs x 3 questions is about 450 calls x about 600 tokens = 270k tokens x $0.042/M = $0.011 per run. Cost is negligible. Calls are made by harness code.

## 5. Strongest case against
1. **No Jev ranking has been measured.** Stage 0 made zero Jev calls. Jev is only the label step. Whether Jev beats static ranking is untested, and Stage 1 (+8/160 over static) is blocked.
2. **Candidate coverage is the real limit.** Only 5/16 evidence pairs reach the pool (admitted-before-cap misses 9). Ranking cannot fix this. The one prefilter revision did not clear it (`p15/e2/PREFILTER-REVISION.md`). Pool misses hurt every router equally, so a better ranker alone gives little.
3. **The old context.** The gate measured the single-reviewer loop. The four-reviewer panel plausibly shrinks headroom, so H = 3 may not hold in ab5. It also needs an owner decision to amend the rule before it can proceed.
4. **Wrong lever.** The ledger says reviewers raise defects and revise fails to fix them. E2 improves raising, not fixing.
5. **Measurability.** Residual blocking has sd about 2 at n = 6, so a roughly 1-defect effect is invisible.

I concede points 1 to 4 weaken E2. It stays in contention only because it is cheap, additive and the least gate-negative of the five. If a panel of three has other integrations with positive evidence, E2 should lose to them.

## 6. Falsifiable prediction
Compared with the ab5 control, ab6 with E2 would show:
- Residual blocking of 20: about 0.5 to 1.5 lower, not statistically detectable (the ledger detects about 3).
- Fixed of 44: +0 to +1.
- Loop output tokens: within +2% of ab5. Input tokens +4.8k per run.
- A secondary signal is needed: first-review raise counts of the cross-section defects D07-D12 and D14-D17 from `p17/findings.jsonl`. These should rise by at least 1 defect-instance per run, while the count of defects raised by every arm is unchanged.

E2 is wrong if resid_blk is not lower than ab5, if the cross-section raise counts are flat, or if output tokens grow by more than 5%.
