## 1. Mechanism
E1 plugs into one point: the scoped re-review (R2/R3) after each revise step (V1/V2). Harness code builds, per prior blocking finding, a packet: before/after hashes, the cited obligation, mapped diff hunks, verbatim-still-present flags, up to 3 dependency passages (`p15/plans/PLAN-E1E4-fix-closure.md` 2.1). Code rejects no-ops first (OPEN, no call). Jev then answers separate Noul questions: defect still present, obligation still required, contradicts each dependency, context sufficient. Its only possible action is AUTO_CLOSE, and only when all are decisive; everything else goes to the conventional checker or re-reviewer. Output is a `checks-<n>.md` (closed / open / recheck) given to R2/R3. Jev never writes PASS or keeps a finding open; the 3-review / 2-fix cap is unchanged. Panel, merge, ADJ, lint and clean VF are untouched.

## 2. Evidence it addresses a real failure
- Ledger main finding: reviewers raise, revise leaves them. Baseline fixes 2.8/44 and leaves 17.3/20 blocking yet passed 6/6; PN1 still leaves 10.0 (`p17/LEDGER-RESULTS.md`). So the re-review passes work it should not.
- Persistent defects fit E1's target: D01/D02/D04 (scope claims partly narrowed), D06-D08 (path rule patched in one place), D11/D12 (`p17/score/perdefect.md`: fixed in 0-3 of 6 specs in most arms). Partial-branch and moved-defect fixes are what E1 refuses to close.
- The E1 plan's own estimate (not a ledger count): about 4 of 9 baseline first-audit blockers were "found, then survived".
- Smoke (`p15/e1/results.json`, 40 real Jev calls): all 20 deleted-obligation, moved-defect, partial-branch, contradictory-addition and later-regression cases went to FALLBACK, 0 false closures. All 8 correct fixes (C1/C4) auto-closed. Injected self-justifying text never auto-closed. Jev agreed with the conventional checker on 97% of closing decisions; 10/10 perturbation groups kept the closing decision.

## 3. Complementarity
E1 is the only candidate acting after the reviser, where the measured loss is; E2/E3 act before it. The 4-reviewer panel raises more findings, so more is lost at fix/closure in ab5 than in ab4, which raises E1's value. No duplication with lint (pre-review, mechanical) or clean VF (pre-revise finding verification). E3 overlaps only in goal (checker savings) at a different stage. E4 is E1 extended, not independent.

## 4. Cost
Jev: ~16 packets/run (2 revisions x ~8 eligible findings) x ~1.3k tokens = ~21k x $0.042/M = $0.001 (smoke: 44,886 tokens, $0.0019 for 34 packets). Worker tokens: a conventional checker on fallback packets is ~15k per revision (plan s9), about +30k on ab5's ~408k (+7%) if a new step; Jev removed 35.6% of checker output offline (11,049 to 7,113 per 34 packets), so net ~+20k (+5%). Roughly neutral, not a saver.

All were C7 coupled blockers (one hunk fixes finding A, breaks B) with 0 dependencies in the packet. Jev gave defect-present 0.03-0.17, obligation 0.98 and context_sufficient 0.91-0.95, so its own guard did not fire. The gate was measured on packets, so it applies fully to ab5, and the panel yields more coupled findings. I do not say the gate was wrong.
