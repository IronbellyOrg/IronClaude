## 1. Mechanism and insertion
Code reuses the PN2 table parser (`p16/ab4/reqlint.py`) to extract section-7 checks: 25 table rows plus 7 live-check steps, so 32 in the original. Lint stays the control. Each lint-clean check goes to Jev with its pass-condition cell and the cells it cites. Jev answers one Choice: {can pass, cannot pass, cannot discriminate, insufficient}. Anything but "can pass" becomes one UNVERIFIED line in `lint-N.md`, the file the four panel reviewers already receive (R2/R3 get it re-run on changed rows only). Merge, ADJ, VF, revise and caps are untouched. Jev error or "insufficient" means no line, which is the ab5 path.

## 3. Fully loaded cost
- N = 32 judgments, no prefilter, so no prefilter misses enter m1. About 650 tokens per packet is 21k a pass. With re-runs on up to 10 changed rows twice and 3 questions each, that is ~100k tokens, $0.004 per run.
- Fallback is "no hint", so fallback_unit_cost = 0.
- Consume: ~500 hint tokens read by 4 reviewers (+2k input), 3-5 extra findings (+1.5-2.5k output), a longer revise (+1-2k).
- Net ab5 loop tokens: +3 to +5k (~+1% of ~408k). Savings are 0, so A2 must win on quality_value.
- Evaluation, charged once: 274 unique check rows across the 70 final specs. Blind relabelling is ~7 Opus agents (~200k tokens). Jev replay is ~800 calls (~$0.03).

## 6. Cheap offline test
1. Extract the 274 unique check rows from the 70 final specs plus the 7 steps.
2. Run the charged controls: lint with all checks, the two regexes, and execution of the shell and grep rows in a scratch repo.
3. Blind independent labellers, held out by spec family, label each row {passable, cannot pass, cannot discriminate, insufficient}. The ledger only seeds; Jev is never truth.
4. Build joint counts: control-only catches, Jev-only catches, and Jev false flags on passable rows.

**Kill rule:** Jev catches fewer than 3 of the 12 tail defects that controls miss, or flags a blocking-eligible "cannot pass" on a row labelled passable. A2 is dropped at zero live cost.
