## 1. Mechanism
After ADJ and the clean VF, before V1, code extracts obligation rows (37 section-3 rows, 12 WC rules) and criteria (25 AC rows, 7 live-check steps). A prefilter pairs them by command name, AC/WC id, phase or quantifier. Jev labels each pair {supported, partial, unsupported, contradicts-or-defers, insufficient}. Code shows at most 12 non-supported pairs as UNVERIFIED hints in the V1 brief. After V1 it re-runs on the revised spec and passes still-flagged pairs to the V2 brief and the R2/R3 scoped re-reviews. "supported" is never shown. Any Jev error or `insufficient` gives no hint (identical to ab5). Jev emits no finding, closure or PASS.

## 5. Strongest argument against, and my answer
**Against.** Reviewers already raise D01, D03 and D11; the loss is at the reviser, which A1 does not change; the effect is undetectable; and against a same-packet conventional judge Jev wins only on price.

**Answer.**
1. Part of the target is never raised (D38-D40, D44, D28): a recall gap the panel leaves.
2. Detectability is conceded: PN1 sd on T1 blocking is 1.94, so a detectable shift is about 2.8 x 1.94 x 0.58 = 3.1 of a 3.83 mean. Live ab6 is a no-regression check; headroom is settled offline.
3. The seam is non-controlling: no closure or hidden-blocker risk.
4. A conventional-judge arm stays in. If it matches A1, Jev has no claim.

**Prefilter risk.** My prototype recalls 17 of 28 command-AC pairs named in the T1 defect texts (61%). D13, D14, D26 and D44 name no command-AC pair, because the obligation is a WC rule, so WC x AC pairing (300 raw) is required. Phase-matching drops cross-phase defects such as D01.
