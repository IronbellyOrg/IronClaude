# Task: reconcile 20 per-cluster defect lists into ONE canonical defect ledger

Context: A real spec (`/tmp/claude-0/-home-user-IronClaude/a6884237-9a8e-5417-a03f-8e5a29d7c57f/scratchpad/p17/in/spec-original.md`, line numbers in the lists refer to it) was reviewed by many agents in many experiment runs. Twenty validator agents each took one slice of the findings, merged them into defects and verified them against the spec. Their outputs overlap across slices (the same real defect appears in several chunks under different wording). Your job is to produce one deduplicated, independently checkable ledger.

Input: `/tmp/claude-0/-home-user-IronClaude/a6884237-9a8e-5417-a03f-8e5a29d7c57f/scratchpad/p17/recon-input.json` — list of entries from all chunks (`local_id` cNN-dK for defects, cNN-xK for extras noticed during validation), with kind (original / introduced / not-a-defect / unverifiable), severity, title, quote, original_lines, what_goes_wrong, is_fixed_when, deletion_note, n_gids (how many review findings support it).

Rules:
1. Read the original spec fully first. Re-verify anything you are not sure of by grep/reading; do not trust an entry blindly, but do not redo all work.
2. Build canonical ORIGINAL defects (kind original, plus extras that are real). Merge entries describing the same underlying flaw. Two entries are the same defect if one fix of the spec text would resolve both. If one entry bundles several flaws that a spec revision could fix independently (e.g. "the contract path breaks for file-valued --output" and "the contract path breaks for workflow's generated id"), SPLIT it into separate defects, each with its own `is_fixed_when`. Aim for defects that a reader checking one revised spec can answer "fixed properly / still present / obligation deleted / worse" for without ambiguity. Expect roughly 25–45 canonical defects; do not force a number.
3. For each canonical defect: `id` (D01…), `title`, `severity` (blocking = the spec as written cannot be implemented/pass its own acceptance checks, or an unsafe outcome; medium = real flaw that does not by itself block; minor = cosmetic/low risk — use the strictest level the evidence supports, and note disagreement among sources), `spec_lines`, `quote` (verbatim from spec), `what_goes_wrong`, `is_fixed_when` (concrete test a reader can apply to a revised spec), `deletion_ok` (true if removing/narrowing the obligation consistently also counts as a proper fix, false if deletion just hides it; add one sentence), `sources` (list of every input local_id merged in), `support` (sum of n_gids of sources, counting each source once).
4. INTRODUCED defects (kind introduced): dedupe into `introduced_patterns` — each a short, reusable description of a flaw that a revision can add (e.g. "parent-directory contract rule lets parallel workers overwrite each other") with `id` (I01…), `title`, `how_to_recognise` (what to look for in a revised spec), `severity`, `sources`.
5. not-a-defect and unverifiable entries go to `rejected` with the reason (keep their local_id, one line why). Unverifiable ones that are plausibly real but could not be confirmed go to `unverifiable` instead, with what would confirm them.
6. Every input local_id must appear exactly once in `sources` of a canonical defect, an introduced pattern, `rejected` or `unverifiable`. If an input fits two canonical defects after splitting, list it in both.
7. Also record `coverage_notes`: any area of the spec you think is under-reviewed (parts with no defects at all) — skim the spec for obvious flaws the lists missed and list them under `new_candidates` with quote + why (clearly marked unvalidated by any run; the score will treat them separately).

Output: write valid JSON to `/tmp/claude-0/-home-user-IronClaude/a6884237-9a8e-5417-a03f-8e5a29d7c57f/scratchpad/p17/ledger.json` with keys `defects`, `introduced_patterns`, `rejected`, `unverifiable`, `new_candidates`, `coverage_notes`. Validate with `python3 -c "import json;json.load(open(...))"` and check rule 6 with a script. Work only inside the p17 directory; do not modify other files. Final reply: DONE + path + counts (canonical defects by severity), nothing else.
