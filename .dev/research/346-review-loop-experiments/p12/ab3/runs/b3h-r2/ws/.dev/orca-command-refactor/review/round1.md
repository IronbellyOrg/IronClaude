### Pipeline Dimensional Analysis (triggered)

Trigger: §1.3 describes N worker Tasks whose reports feed one adversarial worker (SPEC:39). INV-A:42 describes cleanup-audit batching (files divided by batch size), which is a fan-out with a count rule.

1. Detection (Fowler): coordinator Tasks → N worker reports (contracts) → one fan-in worker.
2. Quantity annotation: N Tasks in and N contracts out; the fan-in worker consumes K usable reports, where K ≤ N. A failed or blocked Task keeps its dependents blocked (CAPS:90).
3. Downstream tracing: the spec does not say which Task IDs the fan-in worker depends on, or whether it gets failed reports.
4. Consistency check: if the dependency list has N entries but only K are usable, the consumer's count differs from the producers' count. The spec states no rule (M-11).

Severity note: FR-19 would classify this mismatch as CRITICAL if the spec made the fan-in normative. Here §1.3 is a rejected-alternative example, not a stated requirement, so under the FIRST-REVIEW rule I grade it Medium (M-11), and the recommendation is to state the rule.
