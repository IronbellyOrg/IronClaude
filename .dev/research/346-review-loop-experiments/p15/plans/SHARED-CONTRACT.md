### J1.2 Request builder (`jevlib/questions.py`)

```python
def noul(instructions: str, true: str, false: str) -> dict          # {"type":"noul","instructions":..,"criteria":{"true":..,"false":..}}
def choice(instructions: str, options: dict[str, str]) -> dict      # {"type":"choice","instructions":..,"criteria":{name: description}}
def build_request(state: dict, questions: dict[str, dict], model: str = MODEL) -> dict
def canonical_bytes(req: dict) -> bytes   # json.dumps(req, sort_keys=True, separators=(",", ":"), ensure_ascii=False, allow_nan=False).encode("utf-8")
def request_sha256(req: dict) -> str
```

`build_request` raises `BuildError` when: a question name fails `QNAME_RE`; a type is not `noul`/`choice` (Score and Box are not used in p15); a Choice has <2 or >255 options or a positional option name (`^(a|b|c|d|option_?\d+|choice_?\d+|left|right|\d+)$`, case-insensitive); any instructions/criteria string is empty; state is not a dict; state or criteria nest deeper than 64; any number is not finite (`allow_nan=False`); a Noul's `true`/`false` criteria are missing. State is a JSON object with descriptive keys (never serialized JSON in a string). Question wording lives ONLY in each experiment's `questions.py` (J7).

### J1.3 Strict response validator (`jevlib/validate.py`)

```python
class Invalid(Exception): code: str; detail: str
def validate_response(req: dict, status: int, raw: bytes) -> dict
# returns {"model": str, "answers": {name: {"type": "noul", "p": float} | {"type": "choice", "choice": str, "probs": {opt: float}, "confidence": float}},
#          "usage": {"input_tokens": int, "output_tokens": int}}
```

All-or-nothing: one failed check invalidates the whole response (no partially decoded answer set ever clears or confirms anything). Codes, checked in this order: `http_<status>` (status != 200), `not_json`, `not_object`, `model_mismatch` (returned `model` != `MODEL`; alias drift), `answers_missing`, `keys_mismatch` (set of answer names != set of question names), `type_mismatch` (answer `type` != question `type`), `unknown_type` (an answer type other than noul/choice: never warned-and-omitted, the call is invalid), `noul_bad` (`noul` missing, not a number, not finite, outside [0,1]), `choice_bad` (`choice` not one of the question's option names), `prob_keys_mismatch` (probability keys != option names), `prob_bad` (non-number, non-finite, outside [0,1]), `prob_sum` (|sum-1| > `PROB_SUM_TOL`), `choice_not_argmax` (choice's probability < max probability - 1e-9), `confidence_bad` (missing, non-finite, outside [0,1]), `usage_missing`, `usage_bad` (non-int or negative). Booleans are not numbers. Extra top-level keys are ignored; extra answer keys fail `keys_mismatch`.

### J1.5 Retry and deadline policy (`jevlib/client.py`)

| Outcome of an attempt | Action |
|---|---|
| 200 + valid | done, `status="ok"` |
| 200 + invalid (J1.3) | no retry; `status="invalid"`, `error=<code>` |
| 429, 529, 500, 502, 503, 504, `TransportTimeout`, `TransportError` | retry once after `max(BACKOFF_S, min(Retry-After, RETRY_AFTER_CAP_S))` if the logical deadline allows; else/after the retry `status="unavailable"`, `error="http_429"` / `"timeout"` / ... |
| 400 with body containing `max_tokens_exceeded` | no retry; `status="refused"`, `error="oversize_server"` |
| 400, 413, 415, 422 (other) | no retry; `status="invalid"`, `error="http_<n>"` (a builder bug: the replay script prints it as an ERROR) |
| 401, 403 | no retry; raise `KeyRejected` (configuration error: replay scripts stop with exit 3; live `advance.py` prints `MANUAL <run> <step> jev key rejected` and does NOT fall back) |

A failed call is never an answer: every `status != "ok"` routes to the plan's conventional fallback (or keeps the finding open). Missing usage is not zero.

### J1.6 Client (`jevlib/client.py`)

```python
@dataclass
class Result:
    status: str                  # "ok" | "invalid" | "unavailable" | "refused"
    error: str | None            # validator / transport / refusal code
    answers: dict | None         # validated answers (J1.3) when status == "ok"
    usage: dict | None
    model: str | None
    attempts: int
    latency_ms: int
    logical_call_id: str         # f"{experiment}:{phase}:{case_id}:{qset_version}:{n}"
    request_sha256: str

class KeyMissing(Exception): ...   # JEV_API_KEY unset while live=True: a hard error, never a fallback
class KeyRejected(Exception): ...

class JevClient:
    def __init__(self, *, experiment: str, phase: str, budget: "Budget", journal: "Journal",
                 transport=None, live: bool = False, cache: "ResponseCache | None" = None,
                 allowed_classes: set[str] = ALLOWED_DATA_CLASSES, clock=time.monotonic, sleep=time.sleep): ...
    def ask(self, state: dict, questions: dict, *, case_id: str, qset_version: str,
            data_classes: set[str], purpose: str) -> Result: ...
```

`ask` does, in this order: (1) `build_request`; (2) privacy guard (J3): refuse `status="refused"`, `error="privacy"`; (3) size check: estimated tokens of `canonical_bytes` / `SIZE_BYTES_PER_TOKEN` over `LIMIT_REQUEST_TOKENS`, or state + any single question over `LIMIT_QUESTION_TOKENS` -> `refused`/`oversize` (no call, no truncation); (4) budget draw (J4) -> `refused`/`budget_exhausted`; (5) cache lookup when `cache` is set and `phase != "live"`; (6) `live=False` -> `refused`/`dry_run` (the request is still journalled: this is the pre-flight manifest); (7) key from `os.environ[KEY_ENV]`, else `KeyMissing`; (8) attempts per J1.5; (9) validate; (10) settle the budget with `usage.input_tokens` (usage missing: settle at the reserved estimate and mark `usage_missing`); (11) journal every attempt and the final result (J5); (12) return. `transport` defaults to `UrllibTransport()` only when `live=True`; with `live=False` and no transport, no network object is created.

`ResponseCache(dir)`: key = `request_sha256` (covers model, state and every question's wording, so any wording/model change invalidates); stores only validated `status="ok"` results; never used when `phase == "live"` (constructor or `ask` raises if both). Used to re-run an offline analysis without paying again.

## J2. API key handling (binding)

- The key lives ONLY in the env var `JEV_API_KEY`, loaded by the coordinator from `$SP/.jev.env`, and ONLY inside the single shell command that runs a Jev-calling script:
  `bash -c 'set -a; . "$SP/.jev.env"; set +a; cd <dir> && uv run --no-project python <script> ...'`
  Never `export` it into a persistent shell, never echo or print the environment, never pass it on a command line, never write it to any file (repo, clone, journal, telemetry, results, test fixture, log, prompt, sandbox).
- Implementer agents (Sonnet, in the clones) never have the key and never call the live API; they build and test against `MockTransport` and dry runs.   `advance.py` of a Jev arm with `JEV_API_KEY` unset prints `MANUAL <run> <Jstep> JEV_API_KEY not set (use drive-jev.sh)` and does nothing for that step (it never falls back because of a missing key; a missing key would silently turn a Jev arm into a conventional arm).

## J4. Jev budget: pre-flight reservations (D6-compatible)

`jevlib/budget.py`:

```python
class BudgetExhausted(Exception): ...
class Budget:
    def __init__(self, path: Path, *, ceiling_usd: float, ceiling_input_tokens: int): ...   # ledger JSON, fcntl-locked
    def reserve_phase(self, phase: str, est_input_tokens: int) -> None   # raises BudgetExhausted if spent + open reservations + est > ceiling
    def draw(self, phase: str, est_tokens: int) -> str                 # per-call draw against the phase reservation; returns a draw id
    def settle(self, draw_id: str, actual_input_tokens: int | None)    # None (usage missing) -> charged at the estimate
    def release_phase(self, phase: str) -> None                         # returns the unused part of a finished phase reservation
    def state(self) -> dict                                             # {"ceiling_usd", "spent_usd", "spent_tokens", "reserved": {...}}
```

USD = input tokens x 0.042 / 1e6. Ledgers: `$JEV/budget/<experiment>.json`. Ceilings (stored in each `decision.toml` `[jev]`, raised only by the owner): offline replay ceiling $5 and 30,000,000 input tokens per experiment, whichever binds first; live ceiling $1 per experiment.

- **Offline:** `replay.py` first builds every request of the phase with `live=False` (dry run), sums the reservation estimate (`RESERVE_BYTES_PER_TOKEN`) x 1.2, and calls `reserve_phase` BEFORE the first paid call. If it does not fit, the replay refuses to start, writes `BLOCKED-BUDGET` with the estimate into its offline results, and makes no call. A started phase therefore never runs out (calls draw from the reservation); if a draw does fail anyway (estimate error), the case is recorded `refused/budget_exhausted` and counted as a non-automated fallback, never skipped silently.
- **Live:** `harness.py build` reserves the live phase (estimated J calls per run x runs x 2). If the reservation fails, `build` refuses (experiment BLOCKED before any run starts). If a draw fails mid-run (estimate error), that J step returns `refused/budget_exhausted`, the conventional path runs for it, and the run continues (D6: no run is ever killed, truncated or skipped because of cost). The report's original per-run Jev sublimits (60 HTTP attempts, 5M tokens, $1, 10 s) and every "exceeding any cap escalates" rule are removed; only the retry policy (J1.5) and these reservations remain.

## J7. Question sets, truth tables, thresholds (skill-derived; every plan)

- One module per experiment, `<exp>/questions.py`, holds ALL question wording, option names/criteria and a `QSET_VERSION = "<exp>-qN"` string; it is the only file with question text. Changing any wording bumps `QSET_VERSION` and invalidates caches (J1.6).
- One question = one judgment (no "or"/"and" joining two conditions; one question per item, e.g. per dependency passage); state carries facts code already knows (hashes, "this sentence no longer appears verbatim", "all quotes found verbatim at lines ..."); state holds only fields the questions need; descriptive keys; questions refer to state by backticked paths.
- Nouls are used for yes/no judgments, with `true`/`false` criteria written as concrete situations and phrased so true means yes. The report's three-option Choices with an `uncertain`/`insufficient` option are realized as (a) a Noul per statement and (b) a companion Noul for the null case ("does the state contain what is needed"), with the 0.3-0.7 band of each Noul as its own truth-table row. This follows the skill ("companion Noul usually works better than a none-of-the-above option", "a Noul near 0.5 means the state does not settle the question"). Choices are used only where options are mutually exclusive (E5 relation), always with a companion Noul.
- Decisions live in code as an explicit truth table (`<exp>/policy.py`, pure functions, every combination of answer bands has an outcome, unit-tested exhaustively over bands). Jev never decides an action; it supplies judgments.
- `confidence` is never a gate. Probabilities are never multiplied or combined arithmetically across questions; each enters the table through its own threshold. Thresholds are data in `decision.toml` `[thresholds]`; the starting values are the skill's 0.7/0.3; calibrated values are fitted on the calibration split only and frozen in `<exp>/offline/calibration-freeze.json` (sha256 recorded in `decision.toml` before any held-out call).
- Yellow flags are review criteria for the implementer's own work (criteria naming a test item, a clause added per failing case, thresholds fitted to cases, tests asserting an exact probability, code quietly overriding answers): none may appear; each plan's READY report states that it checked.

## J8. Offline datasets and labeling protocol (E1, E2, E3, E5 probe)

- **Case files.** `<exp>/offline/cases/<split>/<case_id>.json` with `{"case_id", "group", "family", "category", "variant", "split", "data_classes", "source": {"kind": "synthetic|public|s1|stage2", "paths": [...], "url": null}, "packet": {...exact state material...}, "author_intent": {...}}`. `author_intent` is the author's expectation, NEVER truth, never shown to labelers or Jev.
- **Leakage control.** `group` = original scenario/document family; all paraphrases, reorders, distractor and adversarial variants of one base case share its group; splits are assigned per group BEFORE variants are generated (`split_groups(groups, seed, sizes)` in `p15common/datasets.py`, seeded, written to `<exp>/offline/splits.json` with sha256). Real S1/Stage 2 cases are grouped by run (or by catalog cluster where noted). Novel-defect categories listed in a plan are held-out only.
- **Independent labels.** Labels never come from Jev, from the case author, or from any worker that saw `author_intent` or a model output. Protocol, executed as offline worker steps (J9) the coordinator launches:
  1. L1 = fresh `sonnet` worker, L2 = fresh `haiku` worker (model diversity against correlated blindness); each labels every case of a batch (10 cases per batch by default) blind, from a sandbox holding only the batch's label packets (the full evidence a labeler needs: e.g. the full before/after documents for E1, the full candidate for E3) and the plan's labeling rubric. Output: `labels.jsonl` lines `{"case_id", "field": value, ..., "evidence": "<quote(s)>", "confidence": "high|low"}`.
  2. `p15common/labels.py: agreement(l1, l2, fields) -> {"field": {"raw": x, "kappa": k, "n": n}}` (Cohen's kappa per field).
  3. Every case where L1 != L2 on any decision field, and every case either labeler marked `low`, goes to ADJ = fresh `sonnet` worker (not L1's instance) with both labels, both evidence quotes and the label packet; ADJ writes the final label with a one-sentence reason. Cases still unresolved (ADJ answers `undecidable`) are excluded from accuracy denominators and listed.
  4. Disputes are explicit: `<exp>/offline/labels/disputes.jsonl` (case, L1, L2, ADJ, reason); `truth.jsonl` = agreed labels + ADJ labels; `agreement.json`; after truth is final, `author_mismatch.jsonl` lists cases where truth differs from `author_intent` (reported, truth stands).
  5. Report raw agreement and kappa per field; kappa < 0.4 on a decision field is a validity warning in the results (not a stop).
- **Conventional comparator on identical packets.** Where a plan replays a conventional checker/verifier/router, a fresh worker of the plan's conventional model gets exactly the packets Jev got (same fields, same decomposition), answers the same judgments as `yes|no|uncertain` per question, and the SAME truth table maps them to actions (yes = 1.0, no = 0.0, uncertain = 0.5). Its cost is its deduplicated output tokens (J10.3), apportioned per packet equally within its batch.

## J9. Offline worker driver (`<exp>/offline/offline_advance.py`)

Same pattern as `$SP/p12/ab2/advance.py`: a ledger `offline/workers.json` of steps `{"id": "L1-b03", "kind": "label|adjudicate|convcheck|router|verifier", "model": "sonnet|haiku", "prompt": <abs path>, "out": <abs path>, "status": "pending|launched|done|lost", "relaunch": 0}`; prompts written by `prep_offline.py`; each prompt uses the p11 `WRAP` text (sandbox `<exp>/offline/sb/<id>/`, no `CMDPART`) and ends with `DONE <path>`. `offline_advance.py` prints `LAUNCH <abs prompt path> model=<m>`, `RUNNING n`, `MANUAL ...`, `ALL DONE`; at most `MAX_CONCURRENT` (6, env `AB_MAX` may lower it) at once; finished = output exists and transcript has DONE (J10.3 scan with root pattern `p15/<exp>/offline`); missing output -> relaunch once, then `lost`. Offline worker tokens are reported (measurement/labeling cost), never part of a loop A figure.

### J10.2 Frozen audit (identical everywhere, TWICE per final spec)

`AUD` (sandbox `runs/<run>/aud`) and `AUD2` (`runs/<run>/aud2`): fresh overlay copy + the run's final spec + frozen command (assert sha) + frozen rules (assert sha) + p11 `WRAP`/`CMDPART`/AUD brief; model `sonnet` in both strata (`advance.py` asserts it); prepared and launched together. Never given hints, checks, confirmations, Jev output or any test-arm insertion. `BLK` = mean of `len(blocking_findings(audit.md))` (0 for PASS) over both audits of every completed run (`score_themes.blocking_findings`).

### J10.3 Tokens (D2; binding)

Worker output tokens = sum over unique `message.id` of max `usage.output_tokens` in the worker's transcript (transcript belongs to `(run, step)` when its first user message is `Read <abs PROMPT path> and follow it exactly...`). Loop A = all loop worker steps (R*, V*, VF*, CK*, ROUTER, any adjudication inside the loop), excluding AUD/AUD2 and post-hoc measurement workers. `R_LOOP = A / 100,424` decides cost; `R_B = (A + AUD tokens) / 169,468` is printed beside it and never decides. Jev usage is reported separately (`jev_input_tokens`, `jev_usd`) and never added to A or B. Planner token totals are forecasts, never limits.

### J10.4 D6 in tooling

No file in a p15 experiment reads running token or dollar totals to stop, abort, truncate or skip a step, run, wave or experiment. Cost enters only the post-hoc verdict. Loop caps that are not cost caps (3 reviews / 2 fix cycles, relaunch-once, `lost`) stay. Jev budget exhaustion is a fallback trigger (J4), never a stop.
