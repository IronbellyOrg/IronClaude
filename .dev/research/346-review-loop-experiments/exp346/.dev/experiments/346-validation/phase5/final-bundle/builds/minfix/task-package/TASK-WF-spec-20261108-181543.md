## Task 1: Create `fixcheck.py` with constants, input parsing, `hash` and `snapshot`

Create `src/superclaude/skills/sc-fixcheck/scripts/fixcheck.py` (source.md sections 2.1 step 0 to step 2 item 1, 2.3 exit codes, 3.3) and `tests/skills/test_sc_fixcheck.py`.

- Constants exactly as source.md section 3.3: `BUDGETS` keyed `C`, `M`, `m` with the section 2.3 table values (gross, net, add-only, entries, heading, id, table row, normative, universal, condition, check recipe), `CYCLE_GROSS_WORDS=600`, `CYCLE_GROSS_BYTES=6144`, a raw-size limit of 6144 bytes, `MAX_OVERRIDES=1`, `EXIT={OK:0, POLICY:1, USAGE:2, INPUT:3, HASH:4, WRITE:5, INTERNAL:70}`.
- `main` with argparse subcommands `hash --file`, `snapshot --spec --report`, `check --baseline --revised --report [--ledger] [--enforce]` (the `check` scoring body is Task 2, `--enforce` is Task 3; until then `check` may exit 70). Argparse errors exit 2; any uncaught exception exits 70.
- `read_text`: missing, unreadable or empty file exits 3.
- `hash`: prints the sha256 hex of the file bytes.
- `parse_fixbudget`: reads the fenced `fixbudget` block (`review: N of 3`, `reviewed_sha256`, `refs`, `# id | severity | grade | budget` rows, `override-reason:` lines). Exit 3 on no block, a malformed row, a second override, an override without `override-reason`, an override on a minor row, `override` combined with `gap:<n>`, or a Reviser-brief id that is not a blocking id. A `CRITICAL`, `MAJOR/FR-8` or `MAJOR/FR-9` row graded minor is not an error: it gets budget 0 and is recorded as `GRADE-CONFLICT <id>`.
- `parse_ledger`: reads the fenced `fixledger` block of the disposition file: first line `report: <file name>`, `## L<n>` entries with `finding`, `op` (delete|narrow|replace|add), `old` or `anchor`, `new`, `considered` (required for add), optional `depends: L<n>`, and a `## deferred` list of `<id>: escalated: <need>`. A malformed block exits 3.
- `find_ledger`: without `--ledger`, scans the report's directory for files whose `fixledger` block starts `report: <report file name>`; zero or more than one match exits 3.
- `snapshot`: exits 4 (`STALE-BASE`) when the spec's sha256 differs from the report's `reviewed_sha256`; otherwise writes only `<report dir>/.fixcheck/base-<N>.md` (N from `review: N of 3`) via temp file and rename; a write failure exits 5.

## Task 2: Implement diffing, attribution, scoring and the `check` report

Depends on: Task 1

Extend `src/superclaude/skills/sc-fixcheck/scripts/fixcheck.py` and `tests/skills/test_sc_fixcheck.py` with source.md sections 2.2, 2.3 (budget and cycle cap), 2.1 step 2 item 5 (plain `check` writes nothing) and step 3 (re-review lookup), and the 3.3 report format.

- `units`, `words`: normalise line endings, whitespace, table padding and emphasis; split into line, sentence and table-cell units; `path:line` citations, pipes and heading marks are not words; bytes count raw added text.
- `diff_hunks`: `difflib.SequenceMatcher(autojunk=False)` on units; a word-level matcher inside each hunk counts added and deleted words; identical moved units count zero. A hunk spanning units claimed by more than one ledger entry is split per entry (each entry's `old`/`anchor` unit range). A pure-deletion hunk is printed with the revised line it sits before (source.md section 7 item 10, proposed v1 rule).
- `attribute`: a hunk belongs to the entry whose `old` quote it contains (or whose `anchor` precedes it) and whose `new` words start it; derive the real op and fail a mislabelled one; a hunk matching no entry is unattributed, with reason `quote not in baseline` when its entry quotes text absent from the baseline. Quote-match rule (M-F9): `old` and `anchor` are compared after normalisation (whitespace, emphasis, curly quotes); the quote must occur exactly once in the normalised baseline, and a quote shorter than its whole unit must be at least 40 characters; any other quote counts as `quote not in baseline`.
- Word counts (M-F7): per finding, `gross` = words added in its attributed hunks; `net` = gross minus words deleted in those hunks; `add-only` = words added in its hunks whose derived op is `add` (pure insertion). A `delete` hunk adds no words, so a deletion of any size never counts toward the per-finding gross or the 600-word cycle cap.
- Baseline hash (M-F6): `check` (plain or `--enforce`) exits 4 when the sha256 of `--baseline` differs from the report's `reviewed_sha256`, before any scoring.
- `element_counts` and `score`: per finding, gross, net and add-only words, entries, new headings, new ids (an id counts only if absent from the baseline; a `(F3)` tag is a new id), new table rows, normative words (MUST SHALL must never always shall), universal words (only every exactly none total closed), condition words (if unless when whenever where except otherwise), check recipes (fenced blocks; backtick spans holding `grep`, `git `, `diff`, `find `, `uv `, a pipe or `$(`; bare `--flags` do not count). `override` doubles gross, net, add-only and entries; `gap:<n>` sets the condition limit to n; `delete` entries are free of the gross cap. An entry with no attributed hunk is `reverted` and counts toward no per-finding total. A blocking id with neither an entry nor a `## deferred` line is `unanswered` and is not an exit-1 reason. Any hunk charged to a minor id is `MINOR-EDIT`.
- `cycle_checks`: 600 gross added words, 6,144 gross added bytes, and revised size minus baseline size at most 6,144 bytes.
- `render_report`: the source.md section 3.3 layout: `FIXCHECK cycle=... exit=...` header, summary line, one line per hunk `h<k> L<n>|unattributed <finding id> revised:<first>-<last> +<added>/-<deleted>`, one line per finding with status, `unattributed:`, `escalated:`, `result:`, final `FIXCHECK exit=<n>`; attribution reasons print before size reasons.
- Owner decision (Constraints): add one line `carried-open: n=<k> <id>(<status>) ...` listing every id of the report's `fixbudget` block whose severity starts with `CRITICAL` or `MAJOR` and whose status is `escalated`, `reverted`, `unanswered`, `OVER`, or graded minor (including `GRADE-CONFLICT`), sorted by id; `n=0` with no ids when none.
- Plain `check` prints to stdout only and writes no file; exit 1 when any policy reason exists, else 0.

Acceptance criteria:
- `tests/skills/test_sc_fixcheck.py` passes with one test each (source.md section 3.4) for: clean in-budget fix exits 0; 81 added words on a MAJOR fix exits 1 with `gross`; net 51 at gross 60 exits 1; a one-word minor edit exits 1 with `MINOR-EDIT`; a new heading, a new id, a second table row, a second MUST and a second condition word each exit 1 with their own reason; an unattributed hunk, a quote not in the baseline and a mislabelled op each exit 1; an unanswered blocking id is reported `unanswered` and leaves the exit code 0 on otherwise clean input; a raw size growth above 6,144 bytes from whitespace only exits 1; per-hunk lines exist, carry the right `L<n>` and revised line range, and two runs print identical output; edits to two neighbouring sentences by two entries are credited to both entries; moved text counts zero words; a `path:line` token adds zero words and a `(F3)` tag fails with `id`; `check` without `--ledger` uses the lookup of Task 1.
- A test shows `carried-open:` lists an escalated MAJOR, an unanswered CRITICAL and a MAJOR graded minor, and omits a minor-severity id and a CRITICAL fixed within budget.
- A test confirms plain `check` leaves the directory listing and every input file's bytes unchanged.
- Tests (M-F6, M-F7, M-F9): `check` on a baseline whose hash does not match the report's `reviewed_sha256` exits 4; a MAJOR finding whose `delete` entry removes more than 80 words, with no other change, exits 0; a 20-character `old` quote that is only part of its unit is reported `quote not in baseline` and exits 1.
