# Round 2, Advocate 3 (QA): rebuttals

Variant 3's claim on the merge was never the decision rules; both other advocates now run Variant 1's failure posture through a merged script. My claim is and remains the proof layer: literal payloads, harmlessness proven first, a speed guard that survives CI noise, and a named case for every merged rule. Round 2 adds one thing: I went back to the repository and checked the two commands `/sc:pr-submit` actually runs at submit level. Both checks matter, one against Advocate 1's LL-REPO and one in favour of the merged push rule.

## 1. Response to criticisms

Every criticism aimed at Variant 3, from Round 1 and both Round 2 rebuttals, with my answer. The four false claims the diff analysis found (X-004, X-006, X-007, X-002) lead.

1. **X-004, my always-on cwd fallback governed a person's own subagents (A1, A2, diff).** Conceded in Round 1 and not withdrawn. My V4 reading was wrong: V4 says subagent payloads carry `agent_id`, and a subagent of an unbound human session in the same worktree carries `agent_id` with an unbound `session_id`, which is exactly my rule 2's match. The merged design keeps the fallback off, requiring `agent_id`, decided by OB-H1.
2. **X-006, my rules let a settings edit switch the hook off (A1, A2, diff).** Conceded in Round 1. An Edit of `~/.claude/settings.json` hit only my store-path check, and `disableAllHooks` (V11) then kills the hook. Fix adopted: `.claude/settings`, `.claude/hooks` and `disableAllHooks` tokens on decoded commands and on Edit/Write/NotebookEdit path fields, governed sessions only.
3. **X-007, my push rule allowed `git push origin HEAD` from `master`, `--all` and `--mirror` at submit (A1, A2, diff).** Conceded in Round 1. Word-matching after `push` cannot see where HEAD points. The merged destination rule (Advocate 1's N-2 with Advocate 2's edits) fixes it with no subprocess; I verified it against the framework's real push command (new evidence NE-2).
4. **X-002, I failed open in a governed session and misread V8 (A1, A2, diff).** Conceded in Round 1. V8 says a crashed hook does not block; it says nothing about a script choosing exit 2 on its own `command -v jq` check. A governance hook that exits 0 when it cannot judge is silent non-enforcement. Merged rule: governed calls block when `jq` is missing, the claim script refuses to launch without it.
5. **X-005, my tamper rule contradicted my own "ordinary sessions never blocked" and T-ISO-1 (A1, A2).** Conceded in Round 1. Tamper scope is governed-only, and T-ISO-1's wording says "gated payloads", excluding the state rule.
6. **X-009 and X-010, my repository facts were wrong: git hooks location, `manual` marker, `session-init.sh`, the Makefile list (A1, A2).** Conceded in Round 1 after checking. Re-verified this round: `_FRESHNESS_SCRIPTS` is defined at `src/superclaude/cli/install_hooks.py:42` and imported at `Makefile:309`; `pyproject.toml:114` sets `--strict-markers` and the marker list at lines 117 to 148 has no `manual`. Observed checks become `pytest.skip` placeholders or a registered marker, not `@pytest.mark.manual`.
7. **My blanket `claude`/`orca` word block hit read-only calls (A1, A2).** Conceded. Subcommand lists (`orca agent|terminal|dispatch|worker-start|task-create|worktree create|rm|send|launch`) and a `claude` flag list without `-r` block the escapes without breaking `orca worktree current` or `grep claude -rn docs/`.
8. **I had no remote-isolation rule (A1).** Conceded. `isolation: remote` is ESCAPE at every level; Advocate 2's E5 confirms the key and value from this session's tool definitions, so the rule is writable today, with OB-H1 confirming the payload.
9. **I hard-coded `IronbellyOrg/IronClaude` in a hook installed into every user's `~/.claude/hooks` (A2).** Conceded. New evidence NE-1 below shows even record-based name equality is wrong; the merged rule is Advocate 2's: require an explicit `--repo` or `-R` word at submit, compare no name.
10. **My binding needed cwd equality, adding a silent fail-open path (A2 R1 weakness 5, R2 row 13).** Partly rebutted, partly fixed. Steelman of A2: the nonce is single-use 32-hex, a pasted template never matches, and with a degraded bind behind it a failed check frees nobody; and exact equality breaks a launch from a subdirectory. My fix keeps the check but changes the failure: marker plus record plus cwd prefix-match (resolved paths, `record` or `record/...`) binds normally; marker plus record plus mismatch binds degraded `worktree` WITHOUT consuming the record; marker plus no record binds degraded. No path leaves the launched agent ungoverned, a subdirectory launch degrades instead of escaping, and a pasted marker in a stranger directory can no longer steal the real level before the real session binds (it gets degraded, the record survives for the right session). Cost: one `realpath`-style resolution and two extra test cases. This answers A2's row-13 rebuttal: the check no longer protects "only against a copied marker landing elsewhere first"; it also stops a level upgrade landing in the wrong session, and it can never free anyone.
11. **My bind was write-then-delete, not atomic (A2).** Conceded; the merged `mv` is atomic and the nonce is single-use.
12. **My wrapper list was a sub-parser after I cited the #357 ceilings (A2).** Conceded. The merged scanner is the character sweep plus basename compare plus the full option-skip list; Advocate 2's live `git -c alias.ci=commit ci` test is exactly the kind of evidence my persona should have produced.
13. **My approval rewrote the governing JSON (A2, C-006).** Conceded. `touch sessions/<sid>.ok` only at `worktree`, prompts with `agent_id` ignored.
14. **My PreToolUse matcher `*` spawned the script on every Read (A1 R1 row 8), and my V10 justification was wrong.** Conceded, and sharper than A1 put it: V10 is about `if` patterns narrowing Bash command content, not about tool-name matchers. `hooks.json` line 87 already gates `block-bare-python.sh` with an exact `Bash` matcher, so tool-name matching is proven; I over-generalised V10. The merged matcher is anchored per Advocate 2's E1.
15. **`gh pr ready` has zero use in `src/superclaude` (A2 R2).** Fact conceded; I re-ran the grep, zero matches. Position adjusted: it moves from my NEVER row to the submit class, blocked below `full --submit`, allowed at submit. No acceptance criterion makes it never-allowed; marking a draft ready is publishing, which is what submit governs.
16. **Advocate 1's R2 row 12 rebuts my R1 criticism that LL-BROKEN bricks a governed session.** I accept the rebuttal: with the merged matcher keeping Read, Grep and Glob out of the hook, a fail-closed block needs no `tool_name` read, and reads still work. My criticism applied to the no-matcher version only.

## 3. New evidence

- **NE-1 (checked).** `sc-pr-submit-protocol/SKILL.md:274` creates the PR with `gh pr create --repo "$REPO" --base <base> --head <head> ...`, where `REPO` is resolved by command substitution in the same line. So no word in the command equals a record's repo value: Advocate 1's LL-REPO name equality would block the framework's own PR creation at the only level meant to allow it. Advocate 2's rule (require an explicit `--repo` or `-R` word, compare nothing) passes it. This settles the C-010 mechanism against name matching, mine included.
- **NE-2 (checked).** The only submit-level push in the framework is `git push origin <target_sha>:<target_branch>` with "never an upstream parent remote, never the repo's default/protected branch, never a force push" (SKILL.md:282). The merged destination rule (origin first, at least one refspec, destination after the last `:` with `refs/heads/` stripped, not `master`/`main`/`HEAD`/`@`, no `--all`/`--mirror`/`+`) admits exactly this command and blocks the whole X-007 family. The rule is compatible with the framework's real workflow, not just with the issue text.
- **NE-3 (checked).** The Tier 1 conflict sync runs `git -c merge.conflictStyle=zdiff3 -c rerere.enabled=false merge --no-commit --no-ff <base_sha>` (`refs/conflict-mechanical.md:76`). Two QA consequences: it confirms Advocate 1's N-3 (every merge rule blocks pr-submit's own sync at `full --submit`, so O-10 is real and OB-H3 needs a conflicting PR); and it is a ready regression payload for the option-skip rule, because a scanner that forgets to skip `-c` values reads `merge.conflictStyle=zdiff3` and misses the merge. It is now T-WR-prsubmit-merge.
- **NE-4 (checked).** `hooks.json:110` is an unanchored regex matcher (`mcp__auggie__.*|...`) and lines 77 and 87 are exact lists, so both matcher styles have prior art, but no anchored `^(...)$` form exists in the repo; whether the harness honours in-pattern anchors is UNVERIFIED. OB-H1 should log one `TaskCreate` payload to prove the anchored matcher excludes it (Advocate 2's E1 hazard).
- **NE-5 (checked).** `Wave 6` commits with `git commit --only -- <paths>` (SKILL.md:282), which is a COMMIT-class payload with option words before paths; added to the wrapper corpus so the subcommand read is not confused by `--only`.
- **UNVERIFIED:** whether `--receive-pack` and `--exec` on push can redirect the destination (taken from Advocate 1, not re-checked); real MCP tool names on any host.
