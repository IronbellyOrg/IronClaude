# Protocol for the two planning agents (set by the coordinator, ORCH-IronClaude)

Folder: /home/coder/workspaces/IronClaude/.dev/brainstorms/20261122-release-pipeline-bmad-ironclaude/ (agent1/, agent2/, shared/). Both agents write only inside this folder. The owner's text is OWNER-INSTRUCTIONS.md in the same folder.

Agents: `bmad-planner` (agent 1, BMAD side) and `ic-planner` (agent 2, IronClaude side). You can message each other with SendMessage using those names; messages arrive at your next tool round. If SendMessage does not work for you, say so in shared/LOG.md and talk through numbered files in shared/messages/ (NN-from-<name>.md), checking the folder before each new step. Every position, question and answer must also exist as a file so the owner can read it later.

## Hard limits (both agents)
1. No GitHub writes of any kind: no issue, comment, label, sub-issue, project or pull request. Read-only `gh` calls are allowed and must pass `--repo IronbellyOrg/IronClaude`. Never touch SuperClaude-Org. The deliverables are DRAFTS on disk; the coordinator files them after the owner reviews the consensus.
2. No git commit, push, stage, branch or worktree creation. No edits outside this folder. Never read or print credentials or tokens. Python only through `uv run`. No em dashes in files you write.
3. Do not start a worker session, do not call `orca` write commands. Reading Orca state is fine.
4. You may invoke skills and commands as the owner's text says (/bmad-help and the BMAD skills for agent 1; /sc:recommend, /sc:brainstorm, /sc:adversarial, /sc:workflow, /sc:implement protocol reading, spec-panel for agent 2). Read what they say and follow them, but for anything they would do outside this folder (write code, open issues, commit) STOP at the draft stage and write the intended action into your file instead. If a skill spawns agents of its own and you cannot, say so in LOG.md and do that part inline.
5. Be honest about what is verified and what is not. Mark UNVERIFIED anything you did not read in a file or command output. Do not invent BMAD commands or IronClaude flags: read the skill files first.

## Rounds
- Round 0 (solo, in parallel): each agent does its own part of the owner's text and writes it down (agent 1: agent1/RELEASE-PLAN.md; agent 2: agent2/IRONCLAUDE-SIDE.md). Each ends with a numbered list of "Questions for the other agent" and "What I need from the other agent".
- Round 1: swap by message and file; each answers the other's questions in writing (shared/messages/).
- Round 2: debate the open points one by one. Required topics, taken from the owner's text: (a) at which step a BMAD user story is handed to IronClaude, and the hand-off contract (what is in the story, who accepts it); (b) who writes the spec or PRD: BMAD only (then IronClaude runs spec-panel on it), or both (then /sc:brainstorm for an IronClaude design plus /sc:adversarial to merge the two); recommend one default and say when to switch; (c) how progress flows back into the BMAD plan and the GitHub epics and sub-issues as IronClaude sessions finish tasklists; (d) how the coordinator (Orca orchestration plus IronClaude's coordinator rules and the issue pipeline) drives BMAD work versus IronClaude work, in one worktree or several, one session or several, sequential or parallel; (e) that GitHub issues are created and updated throughout so progress is visible; (f) how the pipeline treats the owner's rule that BMAD owns the higher-level planning and IronClaude owns implementation planning, execution and rapid iteration; (g) what is reusable: the agents, skills, templates and commands to build, and which of them already exist.
- Round 3: write shared/CONSENSUS.md together. It must state, for each topic (a) to (g): the decision, the owner of each step, the division of labour, the deliverables BMAD planning must produce, the open disagreements (if any) and each agent's reason. Both agents sign at the bottom ("agent 1 agrees" / "agent 2 agrees", with the date) only when they truly agree. At most 3 rounds of debate. If consensus is not reached on a topic after Round 3, write the two positions side by side under "No consensus" and report it to the coordinator; do not fake agreement.
- Final: agent 1 writes shared/PIPELINE-PROPOSAL.md (the reusable pipeline: steps, agents, skills, templates, commands, who runs what, where each file lives) from CONSENSUS.md; agent 2 reviews it against IronClaude's real rules and adds corrections as a dated section.
