# Round 2 Rebuttal: Advocate A (architect)

New evidence (read-only, today): `orca worktree list --repo path:<main> --json` returns rows for `/tmp/ironclaude-p0live/fix-scratch` and `merge-scratch`, which `git worktree list` marks `prunable` (directory gone), both `isArchived: false`. Stale rows are live.

## O1. Matched path missing on disk
Decision: warn `W-WORKTREE-STALE` and create nothing; print the row path, its branch and the remedy (`git worktree prune` then `orca worktree rm`, or recreate by hand). Do not create fresh: the old branch may hold unpushed commits, git still registers it as checked out, and a new marker row would make the next claim ambiguous. Confidence 75%.

## O2. `worktree.json` record
Decision: include it as a second key. Store the absolute path only (not the branch, which fixes C's own `issue-<N>-2` bug). Use it when the list call fails (daemon down: reuse if the path exists and `git -C <path> rev-parse --git-common-dir` equals main's) and when the marker is empty (match the record path against list rows). Write it only after a confirmed create or reuse; never copy it into the worktree. Confidence 65%.

## O3. Copy rule
Decision: per file, never `cp -r`. Missing: copy. Identical: skip. Differing: rename the existing file to `<name>.prev-<UTC timestamp>`, then copy, and name it in the warning. Every `<D>` file is regenerated by the claim, so the fresh copy wins (C) and user edits survive (B). Files not in `<D>` are untouched. Confidence 70%.

## O4. Name
Decision: `--name issue-<N>`, no `--branch`, no slug. The name is not fully irrelevant: the path fallback needs a basename starting `issue-<N>`, which both `issue-<N>` and hand-made `issue-<N>-<slug>` satisfy. Confidence 70%.

## O5. Marker reliability
`--comment` filling `comment` is UNVERIFIED (all rows show `""`). Order: marker contains `sc:issue <R>#<N>`, then record path, then basename `^issue-<N>(-|$)`; drop archived rows; classify missing-path rows as stale (O1) before counting. A fake-orca case must return an empty `comment` after create and still reuse on re-run. The manual run verifies: `comment` equals the marker; path basename equals `--name`; branch is `<prefix>/issue-<N>`; no `linkedIssue`/`linkedPR`; a second claim reports `reused` with one row; `projectId` recorded as observed. Confidence 75% the design works without the marker.

## O6. New defects
1. Filter order: "several matches" must count after dropping archived rows, but stale matches must still block create. Test one live plus one stale match.
2. Self-copy: `<D>` is relative to the current checkout. A re-claim run inside the issue worktree makes source equal destination; the script must compare real paths and skip, or every file gets a `.prev` churn.
3. Sufficiency: only with the O1 stop and O3 rule does the claim end with a usable worktree or one named warning plus a remedy, never a silent duplicate.
