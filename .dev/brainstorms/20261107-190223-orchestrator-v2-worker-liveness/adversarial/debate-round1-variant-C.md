# Round 1 — Variant C Advocate

## Steelman of Opposing Variants

### Variant A
A's strongest contribution is its separation of evidence, verdict and action, backed by three independent process/interaction/progress axes and an explicit positive/absence/unknown proof classification (A, “Root cause, stated architecturally”, “Design principle: three orthogonal axes, one derived state”, “Observation record”). Its inexpensive fleet observations trigger targeted costly probes instead of repeatedly pouring every worker's screen into the coordinator's context (“Cost tiers”, “The sweep”). Its person-prompt precedence and never-on-silence safeguards are strong, and its single parameter table is easier to operate than C's scattered deadlines. Its practical v1 proposal supplies a status-carried application acknowledgement, concise handoffs and a lineage-wide restart budget without first building a service (“Protocol”, “Rules”, “Restart budget”). The honest architectural argument for A is that clear boundaries plus a small manual procedure can fix today's failures while retaining an extensible v2 core.

### Variant B
B most clearly distinguishes the cause of a worker's failure from the cause of late detection (“Mapping of the 8 Observed Cases”, “What the root causes have in common”). Its arrival/change matrix explains why both fresh heartbeats and fresh transcript entries can coexist with no useful progress (“The arrival vs change matrix”). It respects whole-FIFO delivery semantics, includes every known wake type and requires processing every message before transport acknowledgement (“Mechanism (verified)”). It offers an immediately usable status-body read-ack, a payload-free fallback, handoffs even on failure, explicit unreachable versus exited states, and a resume note that yields to implement freezes (“What the worker sends”, “States”, “Resume-note format”, “Requirements”). The strongest case for B is that diagnosing the observation mistake and giving the coordinator an executable procedure matters more immediately than a large new schema.

Old acks and completion claims cannot advance the replacement. C also admits that a local epoch cannot fence an unrelated remote writer; remote fencing remains UNVERIFIED. This is stronger integrity discipline without inventing an Orca field.
3. **Reading and executing are separate transitions.** C, “Reply Read-Acknowledgement Protocol” (FR-015–018), distinguishes enqueue, read confirmation, continuation and resolution; persists input disposition; and blocks blind replay after an ambiguous invocation. Seed line 67 explicitly denies sender-side read receipts. C's digest/dedup checks are useful even if its heartbeat ack carrier is replaced by A/B's status carrier.

7. **Operational failure is visible instead of healthy.** C, “Detection Rules and Time Bounds” and “Risks, False Positives and Edge Cases”, gives degraded coverage, monotonic incident ages, an independent watchdog requirement, payload limits and staged rollout. These are proposed release conditions, not demonstrated timings. They cover failure of the supervisor itself, which otherwise invalidates every worker deadline.
8. **Boundary discipline is explicit.** C, “Worker-Side Rules” and “Contract Changes: v1 Now vs v2 (#423)”, puts local checkpoints in commands but all lifecycle sends at top level; its WC-7 clarification requires actual Skill invocation. This preserves contract lines 44 and 58–61, including legitimate fan-out gaps, and does not add Orca calls to commands. ## Critiques of Variants A and B
### Variant A

- **Wake completeness is weakened rather than met.** “Wake set versus read set” and FR-016 exclude heartbeat. A heartbeat-only batch containing a near-limit or pending-ack indication will wait until timeout rather than waking immediately. This does not discard a message—A correctly describes whole-FIFO returns—but it fails the literal all-worker-types wait criterion. A replay containing only heartbeat traffic falsifies compliance without needing a live run.
- **The v2 proof amendment crosses the authority boundary.** “WC rules amended (proposed wording)” treats twice-confirmed context exhaustion as positive stall proof. That is not one of the documented proof classes. A replay with thrash text and a flat revision, but no exit or completed final-turn proof, would authorize a replacement under A v2 and not under the current baseline. Labeling the amendment v2 does not itself authorize changing Orca's recovery rule. A's v1 person-go path must likewise be an explicit person-directed exception, not represented as ordinary WC-6 compliance.
- **Ack timeout does not establish safe input ownership.** “Protocol” sends a terminal copy after a fixed timeout, including the ask path, without requiring that ask has released foreground input. “Nudge text” admits busy-input queueing is UNVERIFIED; the later R2 risk mitigation requires idle probing, so A is internally safer than its broad harmless-template claim suggests. Make the same safe-input guard mandatory for answer copies. A mock terminal still owned by ask is the falsifying case.
- **Incidental writes can hide context exhaustion.** “Per-state rules” makes no worktree writes since step start part of its context confirmation. A worker could write a partial result and then thrash; a shared writer could also keep modifying files. Current explicit thrash evidence must not be vetoed by filesystem activity. Replay those writes alongside the error and check whether A still classifies the incident.
- **New report directories do not make replay idempotent.** “Risks, False Positives and Edge Cases”, R13, relies on fresh report directories and old read-only handoffs to prevent repeated side effects. That does not establish whether a command already changed source files before crashing. A crash after an effect but before its handoff exposes the gap; C's uncertain-effect reconciliation is needed.

### Variant B

- **Interrupting is not a harmless nudge.** “Response per state”, S6, sends an interrupt before requesting a handoff and then uses the resulting turn end without worker_done for restart proof. A screen classifier false positive therefore permits interruption of useful work. Even if the resulting completed final turn literally meets Orca's documented proof form, the pre-proof intervention is not justified by the harmless-nudge constraint. A mid-write false-S6 replay is a concrete counterexample. B's ordinary S3/C-7 route is not inherently proof manufacture: it can be valid if an independently verified completed final turn already exists; failed nudges alone add no proof.
- **Person-only prompts lose the safety precedence.** “Precedence when evidence conflicts” puts context-exhausted above person-prompt and finished-unreported above both. Feed a current permission prompt plus old thrash text: S6 wins and reaches the interrupt rung. A's person-first precedence and C's independent no-typing gate are safer. The prompt must block actuation regardless of the displayed state.
- **Contract existence does not prove completion.** “States”, S9, uses contract-file existence; “Precedence when evidence conflicts” says that file means work is done whatever the screen shows. WC-4 requires blocked and failed contracts too, and an intermediate command may finish while its chain continues. B's later “Per-state rules” checks status and remaining Command lines, which is better, but does not repair the overbroad S9 definition. A blocked-contract/pending-ask fixture must remain blocked, not acquire a completion nudge.
- **Bounds and acceptance disagree.** “Acceptance criteria”, AC-1, allows case-1 detection at 20 minutes although “Per-state rules” and the seed target say 15. Separately, FR-010's adaptive silence window can exceed its default ten minutes, so the default 15-minute idle bound is not universal. Label initial classification separately from confirmation/restart eligibility and test both against explicit maxima.
- **Typing into ask is not repaired by dedup.** “Timeouts and escalation”, A3, includes S5, and risk R8 says ack/idempotency makes the copy harmless. Dedup works only once the intended worker parses the copy; it cannot stop a foreground process from receiving unintended text. C's input-ownership guard addresses the earlier failure boundary.
- **Activity may silence observation too long.** Proposed WC-10 wording in “Proposed wording (v1)” says not to probe a worker before its declared window ends, up to 45 minutes. A permission prompt or thrash error can appear during a legitimately declared operation. Keep the unconditional observation sweep; only intrusive nudges may be deferred.

All three preserve WC-7 top-level lifecycle ownership and the command-side no-Orca boundary on paper; I found no basis to accuse A or B of putting lifecycle sends inside commands. None supplies a sender-side read receipt or mistakes the wake filter for a returned-message filter in its explicit protocol description. Terminal safety, projection freshness and final-turn durability remain UNVERIFIED runtime properties, not facts proved by these documents.

## Concessions
1. **A/B have the better ack carrier.** Their status-message acknowledgement avoids coupling read confirmation to heartbeat cadence. C's immediate heartbeat ack is explicitly conditional on negotiated preamble support; it cannot be claimed for current workers. Retain C's immutable identity/digest/disposition and replay rules, but carry them using A/B's existing status convention after ask returns. Actual preamble compatibility is still UNVERIFIED.
2. **C overstates its v1 timing presentation.** Its one-minute closing-status bound depends on the v2 drain; v1 only has the five-minute bounded-wait procedure. Its 2/5/10 read-ack schedule can bound observation/escalation, not prove a busy worker can acknowledge within ten minutes. A legal long tool call is not noncompliance. A/B's status convention improves opportunities, but neither carrier can force execution during an accepted fan-out gap.
3. **C needs a deterministic action policy.** Its partial state order does not resolve simultaneous person-prompt, context error and completion claim. A's person-first ordering is better for a display/action selector; preserve all concurrent facts and independently prohibit input on any person/ask-owned prompt. B's distinct exited/unreachable states reduce dangerous ambiguity more than C's combined label.
4. **A makes cost and configuration easier to reason about.** Its tiered probes and single timing table are preferable to C's broad inventory and scattered numbers. C's 100-ms incremental inventory, one-minute drain, six-minute classifications and independent watchdog are requirements, not measured capability. Even a five-minute sweep-completion budget alone does not establish a six-minute per-worker detection bound; queueing/probe scheduling need their own proof. No variant budgets cumulative coordinator context adequately.
5. **B's manual handoff is the better v1 minimum.** A short session-written note, listed in artifacts and written on failure, requires less conversion than C's command-owned atomic JSON checkpoints with retained digests. Use B's v1 note and implement-freeze caveat now, then C's schema where an approved command integration warrants it. Ordinary brief-chain continuation belongs to the session; command-local stage continuation is a different responsibility.
6. **A/B's broader same-cause rule improves C.** C singles out same-checkpoint context thrash. A requires changed plans and person approval for recurring cause generally; B names multiple cause classes. Combine that broader rule with C's lineage counters and uncertain-effect stop gate; the numerical restart limits remain conservative policy choices, not empirically optimal values.
7. **C does not fully satisfy unconditional terminal-copy wording.** Its safe fallback can report instead of typing. That is the right safety trade, but it is a qualification of the seed success criterion, not proof of full compliance. Likewise its no-background-lifecycle rule and blocker yield wording must keep existing preamble behavior and WC-3 blocking semantics intact.
8. **Some diff accusations need narrowing.** X-020 is an ambiguity, not proof of a WC-3 violation: C FR-016 explicitly forbids heartbeat while ask is blocking, although FR-008 leaves blocked_ask emission timing unclear. X-003's ordinary B idle path can use a genuine existing final-turn proof; the unjustified interrupt-based path is the objection. X-009 is primarily a misleading v1/bounded-escalation claim, not evidence that C restarts on missing ack.
