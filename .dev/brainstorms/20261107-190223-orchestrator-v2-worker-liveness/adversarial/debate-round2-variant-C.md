### A's seven criticisms of C

1. **A-C1: “C sends its ack on a heartbeat, which contradicts :7 and WC-3.” — PARTIAL.** Concede the carrier problem: C FR-016, “Reply Read-Acknowledgement Protocol”, requires negotiated immediate-heartbeat permission that current preamble support does not establish. Replace it with A/B's top-level `status` acknowledgement, authoritative body line and optional structured payload. Rebut an actual heartbeat-in-ask instruction: that same paragraph explicitly says “after the worker's blocking ask returns” and “No heartbeat is required or sent while ask is still blocking.” It is conditional unsupported integration, not an instruction to violate WC-3. Current preamble compatibility remains UNVERIFIED; no preamble change is needed merely to propose the status-body convention.
2. **A-C2: “C's v1 ack bounds have no v1 mechanism ... Every answer would be reported as unread.” — PARTIAL.** Concede misleading timing and v1 delivery claims. C's v1 table only promises confirmation at a legal checkpoint, whereas FR-017 publishes 2/5/10-minute escalation. Rebut “every” and “unread”: FR-017 preserves `answer_enqueued/read_unknown`, and FR-016 has an explicit unsupported fallback. Neither proves that reading did not occur. Status improves the carrier, not the ability to send during a blocking call. Keep enqueue age for visibility; re-derive state before action, mark accepted tool/fan-out gaps as deferred/read-unknown rather than worker fault, and never restart on an ack timeout. This follows WC-10 and the Heartbeats bullet, including `check --wait`.
3. **A-C3: “blocked_ask ... safe only if sent strictly before ask starts.” — CONCEDE.** C FR-008's enum leaves emission timing ambiguous despite FR-016's prohibition. Remove `blocked_ask` from transmitted heartbeat modes; represent pending question identity as a separate supervisor fact learned from the question and legal pre/post-wait observations. No heartbeat or status send is required inside a blocking ask. WC-3 and the Heartbeats bullet remain unchanged.
4. **A-C4: “C lets context exhaustion end by itself ... limit useful resumed work to a new checkpoint revision.” — PARTIAL.** Concede that “Worker State Model” has an insufficiently precise clearing predicate. Rebut the reading that any activity clears it: FR-011, “Detection Rules and Time Bounds”, already requires post-incident evidence that addresses the actual error, and “Risks” explicitly says timestamp growth and unchanged revisions cannot erase an incident. Adopt an explicit latch: a new semantic revision tied to a verified completed unit and fresh checkpoint evidence after confirmation, with no still-current contradictory error; otherwise retain the incident. Changed counters, bytes or mtimes alone are insufficient. Recovery without replacement remains legitimate; historical incident evidence is never deleted.
5. **A-C5: “C's v1 case-4 bound relies on v2 machinery.” — CONCEDE.** C “Mapping of the 8 Observed Cases” and FR-027 test 4 apply the one-minute FR-010 drain without phase labels; “Contract Changes: v1 Now vs v2” places that drain in v2. Correct the v1 commitment to one bounded five-minute wait cycle, conditional on a responsive coordinator. A one-minute drain is an optional measured v2 profile, not current functionality or a mandatory default.
6. **A-C6: “C's 6-minute idle bound has no scheduler in v1.” — CONCEDE.** FR-010's extra confirmation scheduling is v2 machinery, not text a coordinator can reliably execute while blocked for five minutes. Use the at-most-15-minute design target in v1 and the default v2 profile; qualify exact-state detection on probe availability. Even v2's five-minute sweep-completion budget does not prove onset-to-classification in six minutes: queue delay and confirmation/probe capacity must fit too. The six-minute profile stays optional and UNVERIFIED until measured.
7. **A-C7: “C's bounds cost more than the target needs.” — CONCEDE.** C NFR-003/FR-010 and its UNVERIFIED fleet budget do not justify mandatory one-minute drains, broad inventory and extra probes for a 15-minute target. Make A's cost tiers, five-minute due sweep and bounded changed-worker summaries the default; use B's scoped contract-path metadata. In v2, periodic draining and durable bookkeeping belong in a non-LLM supervisor, with the LLM receiving bounded incident/change summaries rather than every empty drain. This is proposed architecture, not a verified running component. Tighter profiles require a measured benefit and capacity/context budget.

Accept B's simple session-written handoff for v1; structured command integration is opt-in v2.

## Updated Assessment

The strongest design is a merge, not C unchanged: **A's evidence axes and cheap tiered observations; B's small status-body acknowledgement, occurrence/detection analysis and v1 handoff; C's recovery integrity and fail-closed v2 ledger.** Labels in the position table select design content, not an implementation or a measured winner.

New movement this round is specific: tighten the exhaustion-clearing predicate; accept the combined sweep trigger and capability-scoped transcript preference; merge the response-ladder presentation and cause-investigation treatment; explicitly add lineage-level intervention accounting. I withdraw compulsory broad inventory and tight default scheduling, although C already picked A's cost tiers and B's scoped metadata in Round 1. Likewise, status-body acknowledgements and session-owned brief continuity were already Round 1 concessions, not new discoveries or new pick changes.

The minimal v1 proposal uses all nine known wake types, whole-batch handling, a bounded five-minute wait/due sweep, targeted observations, status-body read confirmation at legal execution opportunities, manual lineage budgets and session-written handoffs even on failure. Default detection is a design target of at most 15 minutes with available evidence; unavailable observations produce bounded unknown/degraded reporting instead of false exact-state claims. Unreachable coverage is reported by ten minutes. Neither target is a live measurement.

V2 adds machine-owned durable ingress before transport acknowledgement, bounded state summaries, timers, incident/action identities and reconciliation of ambiguous external effects. Local transactions do not atomically commit remote actions. A local epoch cannot fence a competing remote writer. Automatic typing requires tested prompt-bound safety; automatic replacement requires positive proof, ownership, reconciliation, confirmed stop and old-Task settlement, plus a supported resume input and no uncertain effects or frozen-plan bypass. A new report directory is not source-edit idempotency.

Keep C's staged observation → tested safe intervention → proof-gated replacement rollout. Do not turn a detection target into an automatic-recovery deadline. Keep unsupported harness capabilities explicit; a transcript-free harness must still report safely rather than invent proof. Numeric restart policies, cross-boot time recovery, final-turn boundaries, prompt binding, transport/redelivery and actual multi-hour fleet/context cost remain UNVERIFIED.

## New Evidence

These are new cross-checks or deductions in this round, not new runtime observations. Source paths are relative to this file unless the Contract/seed aliases above are used. No external prior-art claims were independently re-fetched.

1. **Two unchanged reads do not prove final-turn completion.** B R2 “Responses to Criticisms”, A-B1, rewrites the proof as a final agent turn read twice a sweep apart. The seed “Enrichment Context / What Orca already provides” requires a transcript whose final agent turn sent no completion; C FR-019 and “Open questions” explicitly require a durable completed-turn boundary. Two byte-identical tails are also possible during accepted blocking work (Contract WC-10); therefore repetition can corroborate freshness/flatness but cannot supply the missing completion premise. **Deduction:** keep `proof=none` unless the adapter establishes completed finality and current assignment. Actual finality API/event semantics are UNVERIFIED. This narrows X-003/C-044 without claiming B intentionally removed the word “final”.
2. **C's persisted monotonic due times need a boot boundary.** C NFR-004 says to persist original due times and use coordinator monotonic time. A monotonic clock's persisted numeric value alone does not identify the clock domain after reboot; copying it to another host is likewise insufficient. **Proposed correction:** record clock-domain/boot identity and retain durable incident age evidence; on domain change, conservatively reconcile and sweep immediately, without resetting budgets or trusting source UTC as elapsed authority. This is a design deduction, not an inspected clock implementation. Existing recovery support is UNVERIFIED. C-045 gains an explicit cross-boot gate.
3. **C has its own per-attempt intervention reset.** C FR-020 says “no more than two nudges per attempt”, while replacement creates a new attempt; its lineage cap explicitly covers replacements, not total nudges. A R2 “Updated Assessment” correctly asks for caps surviving new Task IDs, but it would overstate C to say C already provides every lineage-level intervention cap. **Proposed resolution:** persist both incident limits and a lineage aggregate; inherit already-consumed counts across replacements, never reset them on a fresh Task ID. A conservative initial ceiling is two automatic nudges across the lineage, with no reset merely from counters/mtime. The exact new ceiling is policy, UNVERIFIED as optimal, and not yet accepted by A/B. C-018 changes to merge rather than claiming C alone solved it.
4. **Fresh contract is necessary evidence, not proof that an answer was acted upon.** B R2 C-B3 adds “contract newer than any answer”. Contract WC-3 permits the blocked contract to remain during answer parsing and eligible re-invocation, then be replaced whole. C FR-015 distinguishes reading from continuation and completion. **Deduction:** bind the resulting contract/checkpoint to the current attempt and command/input generation, and inspect outcome/remaining work; file mtime ordering alone does not prove input consumption. Concrete generation recording is a proposed v2 convention, UNVERIFIED; v1 uses explicit session disposition and report inspection. This preserves B's legitimate failed/blocked completion mapping while preventing a timestamp-only completion verdict.
5. **Probe budget is not an end-to-end latency proof.** C FR-010/NFR-004 permit a sweep every five minutes and a sweep finishing within five minutes; a just-missed failure can therefore wait nearly ten minutes for a late-in-sweep observation, before confirmation/queue time. C's six-minute claim needs a stronger per-attempt scheduling bound, not merely the stated full-sweep budget. **Deduction:** publish onset, first observation, confirmation and reporting budgets separately; adopt the 15-minute default and keep the tighter profile gated by measured worst-case queue/probe scheduling. No such capacity test ran here.

Existing but still decisive gates are C NFR-005/006/010 and “Risks”: persisted ingestion before delivery ack; reconcile, do not blindly resend after ambiguity; no automatic typing across an unclosed probe-to-submit race; no distributed fencing claim from a local lock. A/B's R2 acceptance strengthens the merged design but does not verify any of those runtime surfaces.
