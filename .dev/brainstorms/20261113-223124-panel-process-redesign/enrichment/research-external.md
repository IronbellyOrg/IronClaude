# External research: process-level levers for weak-model document review

Date: 2026-11-13. All queries were generic. Source status marked: OPENED = page fetched; UNVERIFIED = seen in search snippet only.

## 0. Honest framing

No source found tests the exact setup (small fast model, plan/spec review, defect classes: universal-quantifier claims, unsatisfiable criteria, grep-vs-text mismatch, produced-but-not-consumed values, missing tasks, stale duplicates). The evidence below is adjacent: LLM code review, LLM requirements QA, LLM document-inconsistency detection, and the human inspection literature. Treat effect sizes as direction-setting, not predictions. Most vendor numbers are UNVERIFIED marketing.

## 1. Prompt and process interventions (with weaker models)

### 1.1 Narrow, specific instructions beat "find all errors" (focused single-question passes)
- SEI/CMU blog on adjudicating static-analysis alerts (OPENED, https://www.sei.cmu.edu/blog/evaluating-static-analysis-alerts-with-llms): authors report LLMs "perform much better when given specific instructions, such as asking the model to resolve a particular issue on a line of code rather than prompting an LLM to find all errors in a codebase". Their pipeline gives the model one alert + the relevant function + adjudication instructions, JSON answer true/false/uncertain. When the model was allowed to ask for missing definitions and was then given them, it adjudicated correctly. Anecdotal (single example, no effect size), GPT-4 era, but it is the clearest statement of the "one question per pass" principle and of a deterministic tool producing the question.
- G-Research (OPENED, https://www.gresearch.com/news/building-a-code-review-tool-the-llm-patterns-that-actually-work): single pass gave "eight findings, two or three false positives". They added a second call that filters findings; "splitting recall and precision into separate prompts ... Two simple passes outperform one complex prompt". Per-rule regression tests (one rule, one synthetic diff, expected findings). Practitioner report, no controlled numbers. Cost: one extra call on findings only (small input).
- Claim-decomposition prompting in fact checking (HiSS, split claim into subclaims, verify each) is reported as better than plain CoT in a review article (https://arxiv.org/html/2508.03860v2, UNVERIFIED snippet only). Different domain; same shape as "extract claims, then check each".
- Policy-compliance paper (https://link.springer.com/article/10.1007/s10994-026-07038-6, snippet only, UNVERIFIED): staged prompt (read, canonicalize, resolve scope, locate evidence, evaluate, decide) and policies written as atomic requirements with explicit scope were judged more consistently; the model showed fuzzy-versus-strict-boolean errors. Direction: atomic checks plus explicit scope help.

### 1.2 Multi-pass and ensembles (self-aggregation)
- Multi-Review / SWR-Bench (OPENED, https://arxiv.org/html/2509.01494v2): run the same review N times, aggregate with one extra LLM call. Gemini-2.5-Flash Self-Agg n=10: F1 21.91% (+43.67% relative), recall 30.44% (+118.83% relative). Self-Agg n=5 Flash (F1 20.48%) beat single-pass Gemini-2.5-Pro (19.38%) at lower API cost ($3.68e-3 vs $5.86e-3). Qwen 7B n=10: F1 +26.13% relative (to 14.67%); 32B +19.25%. Gains plateau after n=5; cost keeps scaling. Absolute F1 stays low (about 15-24%), so this is a recall lever, not a precision one. Cost: N review calls (parallelizable) + 1 aggregation call.
- Cursor BugBot pattern: 8 parallel passes with randomized file order, majority vote, then validator pass (via https://zylos.ai/research/2026-03-01-multi-model-ai-code-review-convergence, UNVERIFIED secondary source; vendor numbers 52% to 70% resolution rate are marketing).
- MultiVer (https://arxiv.org/html/2602.17875v1, snippet only, UNVERIFIED): union voting over specialist agents gave 82.7% recall but 85.0% false-positive rate on one benchmark; weighted voting 37.7% recall / 35.3% FPR. Shows the recall-precision dial is set by the aggregation rule.
- Self-consistency (majority vote) reduces variance not bias (https://zeroentropy.dev/concepts/self-consistency, secondary). For small models on hard problems it can backfire: majority vote lowered per-problem accuracy on 56.6% (Qwen2.5-7B) and 65.7% (Llama-3-8B) of GPQA problems (https://arxiv.org/html/2608.11403v1, snippet only, UNVERIFIED; pre-registered per the snippet). Implication: for "did the model notice X" tasks use union or lens-diversity, not majority vote; use voting only to filter noise after union.

### 1.3 One lens per pass and reading techniques (the strongest older evidence)
- Scenario/defect-based reading in human inspections (Porter, Votta, Basili): scenario readers beat ad hoc and checklist readers by about 35%; scenarios focused reviewers on a defect class without hurting other classes; "checklist reading was no more effective than ad hoc reading" (OPENED snippet of https://www.cs.umd.edu/~mvz/handouts/emp_pbr.pdf, quote taken from the paper's related-work text). Reading technique explained R2=0.44 of detection rate vs 0.22 for the document (same source).
- Perspective-based reading vs checklist for UML design docs: PBR teams found about 41% more unique defects than CBR (https://www.sciencedirect.com/science/article/abs/pii/S0164121200000522, snippet, UNVERIFIED beyond abstract). A later replication with 59 students found PBR 69% vs CBR 70% individually and CBR better for virtual teams (https://www.computer.org/csdl/proceedings-article/isese/2002/17960148/12OmNyQphby, snippet): mixed, so the effect is not universal.
- Review-time cost of PBR: "average review time ... can increase by up to 30%" (academia.edu key-takeaways blurb, https://www.academia.edu/20223362, UNVERIFIED, AI-generated summary).
- Transfer to LLMs: the human finding is that a generic checklist adds little, while procedures that tell the reader how to examine the document for one defect class help. This matches "class-keyed procedures" (each class gets a concrete detection recipe) rather than "class-keyed lists of things to be careful about". I found no controlled LLM replication of scenario-vs-checklist (gap).

### 1.4 Tool-augmented review versus reading only
- Agent-based repository access vs static context (CBSoft 2026 workshop paper, snippet, UNVERIFIED beyond abstract, https://cbsoft.sbc.org.br/2026/data/papers/workshops/Beyond%20More%20Context%20Evaluating%20Static%20and%20Agent-Based%20Repository%20Context%20in%20LLM-Based%20Code%20Review.pdf): 144 PRs, merge-decision task; neither static concatenation nor agent tool access beat the benchmark-provided context; repository-aware strategies increased latency; agent access gave inspectable tool-call logs.
- Retrieval for review (MDPI Applied Sciences 16(4):1875, snippet): RAG raised relevance for larger models (+17.9% at k=3) but small models such as a 3.8B model "suffered context collapse, where too much context reduced accuracy" (https://www.mdpi.com/2076-3417/16/4/1875, UNVERIFIED beyond abstract). Direction: dumping context hurts small models.
- Vendor blog (Meerkat, https://comparethemarketcareers.com/blog/comparing-context-retrieval-approaches-for-ai-code-review, snippet, UNVERIFIED, vendor): AST-based tool retrieval beat vector RAG for symbol questions; extra noisy context can hurt; more tool calls (3.27 vs 1.23) came with more issues found.
- Atlas survey (https://laoujin.github.io/Atlas/research/2026-06-09-ai-assisted-code-review-in-2026-landscape-tools-evidence-and-limits/agentic-code-review-workflows, snippet, UNVERIFIED): vendor bug-catch claims 44-82% vs the only large peer-reviewed test (1,000 PRs) putting the best system at F1 about 19%, most techniques under 10% precision.
- Net: evidence that giving a weak model free-roaming tools helps is weak or mixed. The better-supported shape is the tool (grep, script) running deterministically and the model judging a small, specific result (see 1.5).

### 1.5 Deterministic pre-pass feeding the model
- Hybrid static analysis + LLM for false-alarm triage (OPENED snippets, https://arxiv.org/abs/2601.02627 is NOT this; the study is https://arxiv.org/abs/2601.18844, Tencent, 433 alarms): basic prompt accuracy 0.40-0.55 with precision about 0.26-0.29; hybrid methods (LLM4SA, LLM4PFA) reached accuracy 0.93-0.94 and eliminated 94-98% of false positives with high recall; cost 2.1-109.5 seconds and $0.0011-$0.12 per alarm. Caveat: here the static tool generates candidates and the LLM triages them; it is the reverse of "LLM finds, tool verifies" but supports "tool narrows, model judges a localized question" with large effect sizes.
- Requirements smell detection with simple rules (Femmer et al., OPENED abstract, https://arxiv.org/abs/1611.08847): rule-based detector averaged precision 59% at recall 82% across industrial cases; "some smells were not clearly distinguishable"; positioned as a supplement to reviews. Direction: cheap lexical/structural extraction has high recall, mediocre precision, so it should feed a model or human filter.
- Document inconsistency (https://arxiv.org/html/2601.02627v1, OPENED partial): "redact-and-retry" (find evidence spans, redact them, ask again over the reduced text) is guaranteed not to lower evidence hit rate versus direct prompting by construction, and the authors report it improves evidence hit/recall on ContraDoc with GPT-4o, LLaMA 90B and 70B ("weak") (exact deltas not read; UNVERIFIED). Cost: extra calls per round, but each round sees a shorter text.
- No source tested "extract claims, quantifiers, commands, cross-references with a script, then ask the model one question per item" end to end. This is the main gap and the main opportunity; it is an extrapolation from SEI and Tencent above.

### 1.6 Structured output with evidence fields
- Retrieve-then-verify (PMC13628037, snippet, UNVERIFIED): judge returns JSON with verdict, a verbatim quotation from the retrieved text, and a one-sentence rationale; more retrieved passages (k=1,3,5) reduced hallucination rates monotonically. Medical domain; supports "force a quote".
- Citation-enforced prompting in RAG across six open 8B-35B models (MDPI Applied Sciences 16(6):3013, snippet, UNVERIFIED): a "StrictCitations" prompt gave the strongest protection against unfaithful output. 
- Zylos note (secondary): per-finding confidence and pass_number fields let aggregation treat single-pass findings as noise candidates (UNVERIFIED).
- Document-inconsistency work defines findings as evidence spans plus a description (Kensho FIND, OPENED, https://kensho.com/news/can-llms-be-trusted-to-automatically-detect-inconsistencies-within-documents): best model found 64% of inserted inconsistencies (GPT-5), 61% Gemini 2.5 Pro, 76% for a newer model; performance falls with document length; models also found real inconsistencies the authors missed. ContraDoc (https://aclanthology.org/2024.naacl-long.362.pdf, snippet): models "predict No for most documents", near-random binary accuracy about 50% in 2023-era models. Direction: weak models under-report cross-location inconsistency unless the check is made local (spans) and explicit.

## 2. Requirements-engineering evidence that the defect classes are general

- ISO/IEC/IEEE 29148:2018 clause 5 (via https://www.modernrequirements.com/blogs/iso-29148-explained, OPENED, secondary summary): 9 characteristics for a single requirement: necessary, appropriate (implementation-free), unambiguous, complete, singular, feasible, verifiable, correct, conforming. 5 for a requirement set: complete, consistent, feasible, comprehensible, able to be validated. Mapping to our classes: unsatisfiable criterion = feasible/verifiable; no stopping rule = verifiable/complete; universal claim checked against whole set = consistent/correct; missing task a dependent needs = complete (set); stale duplicated claim = consistent (set), singular; value consumed but never produced = complete/consistent (set) and traceability.
- Requirements smells (Femmer, Mendez Fernandez, Wagner, Eder, https://arxiv.org/abs/1611.08847, OPENED abstract): the paper defines smells derived from ISO 29148; the abstract does not list them. The catalogue as I recall it (UNVERIFIED, not opened): subjective language, ambiguous adverbs and adjectives, loopholes, open-ended non-verifiable terms, superlatives, comparatives, negations, vague pronouns, incomplete references. The "open-ended, non-verifiable term" smell is the nearest published relative of "criterion with no stopping rule". Quantifier handling: Berry and colleagues' ambiguity handbook lists lexical, syntactic, semantic and pragmatic ambiguity (cited in https://www.ipr.mdu.se/pdf_publications/7221.pdf, snippet); Anton's regulatory-requirements taxonomy gives ambiguity, vagueness, incompleteness, referential ambiguity (https://www.cc.gatech.edu/~aianton/assets/2014_re14_ambiguity.pdf, snippet). I did not find a source that names "universal quantifier unchecked against the corpus" as a smell; scope/quantifier ambiguity sits under semantic ambiguity (inference).
- Nocuous vs innocuous: ambiguity that readers actually interpret differently is the harmful kind (Chantree et al. 2006, via https://nlp4re.github.io/2020/reqeval.html and arXiv 2608.21298 snippets). Important for false-positive control: smells are indicators, not defects.
- Ambiguity that "makes sense to each reviewer but means something different to each" is invisible to reviewers who all say it is fine (Wiegers, https://medium.com/analysts-corner/six-tips-for-writing-unambiguous-requirements-70bad5422427, snippet): a reason to make reviewers produce an explicit interpretation rather than a yes/no.
- LLMs and requirement quality: LLM ISO-29148 assessment with explanation and rewrite was judged useful by engineers (Lubos et al. 2024, described in https://arxiv.org/html/2608.21298v1, snippet). Ambiguity classification gained 20.2% average with 10 in-context demonstrations vs zero-shot, explanations rated 3.84/5 (https://www.ipr.mdu.se/pdf_publications/7221.pdf, snippet). LLMs reliably assessed user-story semantic quality "when equipped with clear evaluation criteria (complete codebook)" (IEEE TSE 2026 abstract, https://www.computer.org/csdl/journal/ts/2026/05/11430705/2eNCptC1zPy, snippet). INVEST evaluation (Testable is one criterion): GPT-5.1 correlation with experts rho 0.53-0.65, more conservative than experts (https://sol.sbc.org.br/index.php/cibse/article/view/42437, abstract). Direction: a codebook with definitions beats a bare label list.
- Smell effect on downstream LLM work: more smells in requirements lowered binary tracing accuracy significantly but not line-level F1 (https://fb-swt.gi.de/fileadmin/FB/SWT/Softwaretechnik-Trends/Verzeichnis/Band_45_Heft_1/Requirements_Smells_Traceability.pdf, snippet): defects in documents also hurt automated consumers.
- Natural-language defects in task descriptions (ACL Findings EMNLP 2026, https://aclanthology.org/2026.findings-emnlp.1908.pdf, snippet): a small locally deployed classifier (SpecValidator) outperformed frontier LLMs at flagging under-specified descriptions; flagged items had near-zero Pass@1. Direction: a narrow trained or rule-shaped detector can beat a general large model on one defect class (UNVERIFIED beyond snippet).

## 3. Cost evidence and latency tricks

- Multi-Review: N parallel calls plus 1 aggregator; plateau at n=5-10; cheap model x5 beat expensive model x1 on both F1 and cost (OPENED). Wall-clock cost depends on parallelism; the paper reports API cost, not seconds.
- Static-plus-LLM triage: 2.1-109.5 s and $0.0011-$0.12 per alarm (arxiv 2601.18844, OPENED snippet).
- Multi-turn decomposed prompting for test generation: best fault detection but +187% compute cost (https://www.sciencedirect.com/science/article/pii/S0164121226000683, snippet, UNVERIFIED): sequential decomposition is the expensive form; parallel independent lenses cost tokens but not latency.
- Iterative refinement/second-pass revision often adds little: a modernization study found no benefit from iterative refinement over a good single prompt (https://www.mdpi.com/2073-431x/15/3/148, snippet); another thread warns revision gains may be re-solving, not error correction (https://openreview.net/forum?id=4WUqIrSACL, snippet). Lesson: spend the extra calls on distinct lenses and verification of specific claims, not on "review again".
- Latency tricks documented or implied: (a) run lenses as parallel independent calls so elapsed time is about max(lens) + aggregator, not the sum (Multi-Review, BugBot pattern); (b) put the cheap filter (script) first and send only candidates to the model (Tencent/SEI); (c) verification calls take findings only, not the full document (G-Research); (d) prompt caching of the shared document prefix across lens calls (general technique, mentioned in a video summary, UNVERIFIED); (e) early stopping when first runs agree (same). Using idle time of fast models for extra lenses is my inference from (a); no source measures it.
- Budget arithmetic for a +35% limit: a map pass over the full document is the main cost; if lenses run in parallel on the same document the wall-clock add is roughly one aggregation/verification call plus the slowest lens minus the baseline pass it replaces. Sequential multi-pass will almost certainly exceed +35% (inference).

## 4. Cautions

- Checklists alone: human literature shows checklist reading no better than ad hoc (Porter/Votta/Basili, OPENED snippet above); checklists "contain too many questions" and give no concrete how-to (SciDirect PBR paper, snippet).
- Over-flagging and the recall-precision dial: Datadog (https://www.datadoghq.com/blog/using-llms-to-filter-out-false-positives, snippet): prompts tuned to catch true positives misclassified more false positives; tuned to filter, they missed real issues. Tencent basic-prompt precision 0.26-0.29 means about 3 of 4 flags were wrong (OPENED snippet). Benchmarks: CodeRabbit recall 49.2% / precision 24.8%; Graphite recall 7.5% / precision 66.7% (https://entelligence.ai/code-review-benchmark-2026, vendor benchmark, UNVERIFIED). Femmer smells precision 59%.
- Mitigations seen: separate verification pass on findings (G-Research); severity-weighted acceptance (MUST rules 100% recall, overall precision above 85%); count agreement across passes to demote singletons (Multi-Review, BugBot); nocuous-vs-innocuous triage in RE.
- Small-model-specific: context collapse when too much retrieved context is added (MDPI, snippet); majority vote can backfire on hard items (arXiv 2608.11403, snippet); small LLM smell detection F1 only 0.20-0.67 (https://leopoldomt.github.io/assets/pdf/2026-ease.pdf, snippet, 8B-30B models).
- Anchoring and contamination from another model's output:
  - Peer-exposure experiments (https://arxiv.org/html/2606.00820v1, OPENED partial): stance-only exposure to peer answers raised flip rates by about 10 percentage points over self-reflection (46.85% vs 36.98% on MMLU-Pro); strict conformity about 29-34% across four datasets; "even vacuous reasoning leads 20-39% of resistant agents to adopt wrong answers"; mitigations reduced peer adoption but without correctness information did not improve accuracy because they also blocked beneficial corrections. Control design: three-source decomposition (self-reflection only vs stance-only vs full reasoning).
  - Debate vs independent vote (https://arxiv.org/html/2610.35930v1, snippet, UNVERIFIED): against an equal-compute vote of independent agents debate gained about 1 point, unanimous wrong answers became more frequent, and three debating agents approximated about one independent opinion. Control: equal-compute independent-voting baseline.
  - Conformity benchmark (BENCHFORM, https://www.alphaxiv.org/abs/2501.13381, snippet): conformity found across 11 LLMs; grows with rounds and majority size.
  - Self-preference bias: judges favor outputs familiar to them (lower perplexity) (https://arxiv.org/html/2410.21819v1, OPENED snippet) and recognise their own outputs (https://arxiv.org/html/2404.13076v1, snippet); mitigation by cross-family judges or ensembles. Anchoring in LLMs is common, not removed by CoT or "ignore previous" prompts, partly reduced by reasoning (https://arxiv.org/html/2505.15392v2 and Springer 10.1007/s42001-025-00435-2, snippets).
  - Design implication (inference): show a second reviewer only a task list of specific claims to verify (what/where), not the first reviewer's verdict or confidence; keep first-pass lens reviews mutually blind; give verifiers the evidence text, not the prior conclusion; randomize item order.
- Human anchoring analog: reviewers anchor to their initial scores even when later shown contrary evidence (RCT, https://pmc.ncbi.nlm.nih.gov/articles/PMC11573134, snippet).
- Structure of Multi-Review aggregation also carries an echo risk: agreement across same-model runs shares the model's bias (self-consistency, "variance not bias").
- Evidence quality warning: several items above are snippet-only; vendor claims (BugBot, CodeAnt "60% fewer false positives", Entelligence benchmark) are marketing.
