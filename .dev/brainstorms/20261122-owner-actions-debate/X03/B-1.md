## 3 Revised proposal (the unified proposal I would sign)
**CODEOWNERS** (`.github/CODEOWNERS`, `@ironbelly` on every line): `/.github/CODEOWNERS`, `/docs/designs/`, `/src/superclaude/core/WORKER-CONTRACT.md`, plus two temporary lines `/src/superclaude/cli/issue_watch/` and `/src/superclaude/skills/sc-issue-protocol/` (held draft PRs 686 and 690; removed by PR when each is merged or closed).
**Ruleset 1 `gate-master`** (branch master): Enforcement Disabled at creation. Restrict deletions on; Block force pushes on; Require a pull request on, approvals 0, dismiss stale approvals on, require review from code owners on, last-push approval off, thread resolution off. Bypass: Repository admin role, mode "For pull requests only", nobody else. Merge methods unrestricted. No required checks.
**Ruleset 2 `guard-integration`** (branch integration): Active on day 0; only Restrict deletions and Block force pushes. A merge of master into integration is a fast-forward-safe addition, so Clay's sync still works.
**Order and who:**
1. Owner in chat: "Go on X03 as in the final proposal: sole code owner @ironbelly on the five paths; gate-master created disabled, then switched on by me; guard-integration on; integration PR gate on at the step 7 trigger; no agent uses admin bypass or switches a ruleset off unless I type it for that one PR." Agents on the shared login: opening PRs is unchanged; a gated PR they author merges only through the bypass on the owner's typed go; `/sc:pr-submit` never merges (no `pr merge` under its skill, A and I both read none), so no change except the owner re-approves after its fix pushes.
