**What.** Three parts, all reversible: (1) a CODEOWNERS file on master by pull request; (2) ruleset `gate-master` on master with the D16 settings; (3) ruleset `history-integration` on integration with only two rules, no deleting and no force push. **CODEOWNERS** (`.github/CODEOWNERS`, sole owner `@ironbelly`, one owner per line): `/.github/CODEOWNERS`, `/docs/designs/`, `/src/superclaude/core/WORKER-CONTRACT.md`, plus two temporary lines, `/src/superclaude/cli/issue_watch/` and `/src/superclaude/skills/sc-issue-protocol/` (they cover held draft PRs 686 and 690; they come out when both are merged or closed).
**`gate-master`** (branch ruleset; enforcement Disabled at creation, then Active): target `refs/heads/master` only. Bypass: Repository admin role, mode "For pull requests only". ON: restrict deletions; block force pushes; require a pull request with required approvals 0, dismiss stale approvals ON, require review from code owners ON. OFF: approval of the latest push, conversation resolution, required status checks (later decision), linear history, signed commits, restrict creations and updates. All three merge methods stay allowed.
**`history-integration`:** target `refs/heads/integration`; no bypass list needed; ON: restrict deletions, block force pushes; nothing else. Clay's direct pushes and merges there continue.
