## 3 Revised proposal (the unified proposal I would sign)
**Parts, all reversible.** (1) `.github/CODEOWNERS` on master by pull request. (2) Ruleset `gate-master`. (3) Ruleset `guard-integration`, thin on day 0, gated at day 14.
**CODEOWNERS** (sole owner `@ironbelly`, one path per line): `/.github/CODEOWNERS`, `/docs/designs/`, `/src/superclaude/core/WORKER-CONTRACT.md`, and two temporary lines `/src/superclaude/cli/issue_watch/` and `/src/superclaude/skills/sc-issue-protocol/` (they cover held draft PRs 686 and 690; removed by PR when both are merged or closed).
**`gate-master`** (branch ruleset, target master only, Enforcement Disabled at creation). On: restrict deletions; block force pushes; require a pull request with approvals 0, dismiss stale approvals, require review from code owners. Off: approval of the latest push, conversation resolution, required checks, linear history, signed commits. All merge methods allowed. Bypass: Repository admin role, "pull requests only", nobody else.
**`guard-integration`** (target integration, Active on day 0): restrict deletions and block force pushes only. At day 14 (or earlier if Clay agrees) add the pull-request rule (approvals 0, code-owner review, same bypass), after CODEOWNERS exists on integration and its errors check is clean. The owner may postpone in chat.
