## 3 Alternatives rejected
- Blanket `superclaude install --force` on every host: wipes local edits, runs the network codegraph phase (exit 1 on failure), may retire skills still in use (RK-27, FR-66), overwrites ~/.claude/CLAUDE.md; no diff, no way back.
- Do nothing, rely on the claim refusal: covers claims only; a window guard still lacks the rule PR 682 removed (INSTALL-TEST line 13) for every other use, and the contract stays stale.
- Wait for a new Coder pin: reaches template hosts only, which are not the affected ones.
- Fix the installer to read the stamp or hash: right long-term (INSTALL-TEST line 81 shows a stamp bump alone does nothing), but it is a code change needing review (guard changes need an independent review). Not a blocker; offer as a follow-up issue only.
- Track to master instead of one pin: a moving target breaks "verify by hash"; Coder tested only 2ea5245 at the uv boundary (Coder commit 4eae24b message).

## 4 Implications, benefits, risks, costs
- Benefit: closes the one hole where guard rule 1 and the worker contract are stale on a host that runs agents; one build everywhere; each host leaves a before and after hash.
- Risk 1: the maintainers' hosts are unknown. Mitigation: ask both by name; silence means "assume affected"; nobody launches workers there until a clean fingerprint arrives.

- Risk 5: running sessions keep the old hooks until restarted (retire note in `install_retired_files.py`). Do it when no Orca worker is running on that host.
