## 3 Revised proposal (the unified one I would sign)
**Definition.** "The owner" for typed answers is the person behind GitHub account `ironbelly`, identified by numeric id, in two tiers.
- Tier 1, chat-only answers (grant rows, `--apply`, cleanup approval, design go): text the owner types in the live chat of a session a person opened by hand. Never: a `worker-start` worker, a script- or watcher-started session, `orca terminal send`, a mailbox message, issue or PR text. Recorded word for word with date by the receiving session. The spec says it narrows and cannot prove who typed (D06 item 9). Needs no account; do now.
- Tier 2, merges and the `Approved` label: needs (a) the Tier 1 chat go and (b) an approving GitHub review by the `ironbelly` id on that exact head sha, newer than the gate output. Needs the second login.

**Second login.** Worth it. Set up before OA-18, OA-19, OA-20 or any merge automation goes live; not needed to build S14 (SPEC.md:674: neither verb exists yet).
1. Owner chat: "OA-6: the owner means ironbelly only; create a separate agent account. Record it." Agent records words, date, recorder; `git add .dev/tasks`, no commit.
2. Owner (account creation, 2FA and admin are owner-only) reads GitHub's machine-account terms, creates the agent account with 2FA, invites it as outside collaborator with Write on IronClaude only (IronbellyOrg/Coder only if the owner wants agents filing there).
3. Owner sets the OA-5 ruleset with the D16 settings, after CODEOWNERS is merged and Clay accepts the roles, plus the approvals decision of section 2 point 3.
4. Agent reads both ids (`gh api users/<login> --jq .id`) and writes `owner_login`, `agent_login`; in the watcher config `owner_account_id` and `approval_excluded_ids` = agent id, approvers file = `ironbelly` id (origin/master `cycle.py` lines 65 and 262-306, `cli.py` lines 215-224). Builds the migration list of open issues assigned to `ironbelly` (they read as `assigned_other` until reassigned).
5. Owner switches ONE host: signs `ironbelly` out of `gh`, replaces the Coder `github` secret with the agent credential, revokes every old `ironbelly` token. Admin work moves to the owner's browser. After the owner says go, tests on throwaway PRs: `gh api user --jq .login` prints the agent; permission is `write`; an unapproved agent PR cannot merge on a gated and an ungated path (per decision a); `gh pr merge --admin` and a push to master are refused; both review bots answer; claim assigns the agent and writes issue type, Complexity and Approved; the watcher sees an agent-assigned issue.
6. Owner says "Cut over"; agent records it with ruleset id and credential expiry. Only now may `answer-check` pass a merge go, and only with the `ironbelly` approval on the head sha. Other hosts switch one by one with the first two tests.
7. Rollback: owner says OA-6 is unnamed again; merges typed by hand. Break-glass is the owner's browser or own laptop, never `ironbelly` logged into a host.

**Effects.** `/sc:pr-submit`: unchanged (`--repo IronbellyOrg/IronClaude`; it never merges, per A's grep, which I did not contradict); PR author becomes the agent; its pushes dismiss stale approvals, so the owner approves after the last round. Workers: same agent login; can push branches, open PRs, comment; cannot approve as the owner or use admin bypass. Coordinator: merges only after the chat go plus the id-matched approval; before cutover it asks the owner to merge by hand.

**Cost (estimates; basis D16's about 20 min chat and 15 to 30 min ruleset, plus ordinary account setup).** Owner about 1 to 1.5 h one time, about 1 min per merge, about 15 min per credential renewal if a token is used. Agent about 3 to 4 h (id refusal and keys 1 to 2 h inside S14, tests 1 h, ledger, config, migration 1 h). Extra host about 0.25 h. Ruleset time belongs to OA-5.

**Risks.** Surviving `ironbelly` credential in either route (revoke; live-id refusal; `--admin` test). Owner logs back in under pressure (break-glass rule; refusal makes it visible). Review bots silent on a new account read as clean (test first, SEC-04 hold). Credential expiry stops all agents (fails safe). Chat-only answers keep a residual risk. With approvals at 0, ungated merges stay open to a worker calling `gh`.
