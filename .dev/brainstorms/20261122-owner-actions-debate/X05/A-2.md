## 3 Revised proposal (the one I would sign)
**Definition.** "The owner" is the person behind GitHub account `ironbelly`, identified by numeric id.
- Tier 1 (now, no account needed): chat-only answers count only as text the owner types in a session the owner opened by hand. Workers started by `worker-start`, script or watcher sessions, `orca terminal send`, mailbox text, issue or PR text and anything with a launch marker never count. The receiving session records the quoted words, date, scope and recorder (SEC-08) and runs `git add .dev/tasks` (no commit). It narrows; it cannot prove who typed.
- Tier 2 (merges, `Approved`): the chat go plus an approving GitHub review by the `ironbelly` id on the exact head sha. Needs the second login.

**Second login: worth it, done at the cutover, not before S14 is built.** S14 builds the id parameter and the refusal without it. The login exists before any of: merge automation, coordinator autostart (OA-18), real-repo watcher switch-on (OA-19), worker binding flip (OA-20). Each of those stays its own owner decision with its own default; the cutover is a precondition for all four. If the owner declines, those four stay off and every merge is typed by hand.

**Order and who does what.**
1. Owner in chat: "OA-6: the owner means ironbelly only; chat answers count only from a session I opened. Create a separate agent account. Record it." An agent records it (interim ledger, SEC-14).
2. Owner (account creation, 2FA and admin are owner-only): reads GitHub's machine-account terms (UNVERIFIED what they say), creates the agent account (name is the owner's pick; `IB-AIReviewer` is an existing read-role org member of unknown purpose, reuse only if the owner says so), turns on 2FA, invites it as outside collaborator with Write on IronClaude (Coder only if wanted).
3. OA-5 ruleset by the owner with the D16 settings (master and integration, pull request required, code owner review, dismiss stale approvals, bypass for Admin only), after the CODEOWNERS PR merges and Clay accepts the roles. D16 sets 0 approvals because the owner has no other approver for own PRs; with agent-authored PRs the owner is a real approver and may raise it to 1 later as a separate decision.
4. Agent reads both ids (`gh api users/<login> --jq .id`) and writes `owner_login`, `agent_login`, `owner_account_id` (agent id), `approval_excluded_ids` (agent id), approvers file (`ironbelly` id), plus a list of open issues assigned to `ironbelly`. Those read as `assigned_other` to the watcher until reassigned (`predicates.py`, checked in A-1).
5. Owner switches ONE host: signs `ironbelly` out of `gh`, replaces the Coder `github` secret with the agent token typed in the owner's own terminal, revokes every old `ironbelly` token. Fine-grained versus classic token: I prefer fine-grained and limited to IronClaude, but it is not a condition; if the project-field write fails, use classic.
6. Owner says go; then throwaway tests: login prints the agent in a fresh shell and in an Orca session; collaborator permission is `write`; an unapproved agent PR cannot merge; `gh pr merge --admin` and a push to master are refused; Augment and Codex both review an agent-authored PR (a silent reviewer reads as clean, so test first, SEC-04 hold); claim assigns the agent and writes issue type, the Complexity field and the `Approved` field; a watcher dry run sees an agent-assigned issue; a pr-submit dry PR.
7. Owner says "Cut over"; agent records it with the ruleset id and token expiry date. Other hosts follow one by one with the first two tests. Rollback: owner says OA-6 is unnamed again; merges typed by hand. Break-glass is the owner's browser or own laptop, never `ironbelly` back on the host.

**Effects.** `/sc:pr-submit`: same command and `--repo IronbellyOrg/IronClaude`; it never merges; PR author, replies and resolves become the agent; fix pushes dismiss stale approvals, so the owner approves after the last round. Workers: same host login as the coordinator; can push branches, open PRs and comment; cannot merge, bypass or approve as owner (SEC-13 stays "narrows"). Coordinator: merges only after the chat go plus the id-matched approval; holds no owner credential; before cutover it asks the owner to merge by hand. Residual: chat-only answers still leave no GitHub trace.

**Cost (estimates).** Owner: Tier 1 about 0.25 h; second login about 1 to 1.5 h one-time; about 0.25 h per extra host; about 1 min per merge; about 15 min per token renewal (expiry assumed 90 days). Agent: Tier 1 about 1 h; second login about 3 to 4 h (id parameter and refusal inside S14 1 to 2 h, tests 1 h, ledger, config and migration list 1 h). Ruleset time is OA-5's.

**Risks and fixes.** Old `ironbelly` credential left in either route (revoke, `--admin` test, id refusal). Owner logs back in under pressure (break-glass rule; the refusal makes it visible). Bots silent on the new account (test first). Token expiry stops all agents (expiry date in the ledger; fails safe). Outside-collaborator permission may lack org-level field writes (UNVERIFIED; the step 6 test decides; the owner then picks a wider role or does those writes by hand).
