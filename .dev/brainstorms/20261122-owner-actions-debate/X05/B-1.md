## 3 Revised proposal (unified, standalone)
**Definition.** For typed answers, "the owner" is the person behind GitHub account `ironbelly`, in two tiers.
- Tier 1, chat-only answers (grant rows, `--apply`, cleanup approval, design go). Counts only as text the owner types in the live chat of a Claude Code session a person opened by hand in an Orca terminal (main checkout, or the coordinator the person opened). Never counts: a `worker-start` worker, a script- or watcher-started session, `orca terminal send`, a mailbox message, issue or PR text, anything with a `[sc-launch:v1:...]` marker. Recorded word for word with date by the receiving session. The spec says it narrows and cannot prove who typed. Needs no account and is done now.
- Tier 2, merges and the `Approved` label. A typed go counts only with (a) the Tier 1 chat go, recorded with the SEC-08 checks, and (b) an approving GitHub review by the `ironbelly` id on that exact head sha, newer than the gate output. This needs the second login.

**Second login.** Worth it, set up at the trigger (before any of the four go-lives, not before S14 is built).
1. Owner creates one free GitHub account for agents (name is the owner's pick; `IB-AIReviewer` reused only if the owner says so, its purpose is unknown), two-factor on, checks GitHub's machine-account terms (UNVERIFIED), invites it as outside collaborator with Write on IronClaude. Owner-only: account creation and admin.
2. Agent records the decision, the login, and the ids (`gh api users/<login> --jq .id`), and writes keys `owner_login`, `agent_login`, `owner_account_id` (agent id, watcher meaning), `approval_excluded_ids`.
3. Owner switches this host: signs `ironbelly` out of `gh`, replaces the Coder `github` secret with the agent token (the owner types it in the owner's own terminal), revokes every old `ironbelly` token in GitHub. One host first, tests, then other hosts. Admin work (ruleset, approvals) is done in the owner's browser, never by logging `ironbelly` back in here.
4. OA-5 ruleset as D16 recommends, after CODEOWNERS is merged and Clay accepts the roles. D16 sets 0 approvals because no non-author approver exists for the owner's own PRs (D16 VERDICT.md:61); with agent-authored PRs the owner is a real approver, so the owner may raise it to 1 later (separate decision).
5. Tests (they write to GitHub, owner says go first): agent PR cannot merge unapproved; `gh pr merge --admin` and a push to master are refused; Augment and Codex both review an agent-authored PR; claim assigns the agent login and writes the project fields; watcher sees an agent-assigned issue.
6. Owner says "Cut over"; agent records it. `answer-check` and the merge verb refuse, with a reason, whenever the host login id equals the owner id (failing test).
7. Rollback: owner says OA-6 is unnamed again; merges typed by hand. Never log `ironbelly` into a host.

**Sentences the owner says.** Now: "OA-6, chat answers: my answer is only what I type in a session I opened myself; workers, script-started sessions, relays and GitHub text never count. Record it." Later: "Create a separate agent GitHub account; for merges 'the owner' means ironbelly's approval on GitHub plus my chat go." After tests: "The agent account is <login>. Cut over."

**Effects.** `/sc:pr-submit`: unchanged command and `--repo`; PR author becomes the agent; its fix pushes dismiss stale approvals, so the owner approves after the last round. Workers: same unix user, same agent login; can push branches, open PRs and comment (SEC-13 residual), cannot merge, bypass or approve as owner. Coordinator: merges only after chat go plus `ironbelly` approval on the head. Watcher: issues assigned to `ironbelly` read as `assigned_other` (predicates.py:172-182, from B-0, not reopened) until reassigned; a migration list is needed.

**Costs (estimates; basis D16's 20 min chat and 15 to 30 min ruleset, plus ordinary account setup).** Tier 1: about 0.25 h owner, 1 h agent. Second login: owner 1 h; agent 3 to 4 h (refusal and key 1 to 2 h inside S14, tests 1 h, ledger, config and assignment migration 1 h); about 0.25 h per extra host; about 1 min per merge for the click; token renewal about 15 min per expiry.

**Risks.** Surviving `ironbelly` credential in either route (fix: revoke, tests, id refusal). Owner logs back in during an emergency (break-glass rule: browser or own laptop; the refusal makes it visible). Reviewer bots silent on a new account, read as clean (test first, SEC-04 hold). Token expiry stops all agents (fails safe). Chat-only answers keep a residual risk.
