## 3 Revised proposal (the unified one I would sign)
**Definition.** "The owner" is the person behind GitHub account `ironbelly`, identified by numeric id.
- Tier 1 (chat-only answers: grant rows, `--apply`, cleanup approval, design go). Counts only as text the owner types in the live chat of a session the owner opened by hand. Never a `worker-start` worker, a script or watcher session, `orca terminal send`, mailbox text, issue or PR text. The receiving session records the quoted words, date, scope and recorder (SEC-08) and runs `git add .dev/tasks` (no commit). Spec text only: it narrows and cannot prove who typed (SEC-18, D06 item 9). Needs no account. Do now.
- Tier 2 (merges and the `Approved` label): the Tier 1 chat go plus an approving GitHub review by the `ironbelly` id on that exact head sha, newer than the gate output. Needs the second login. Only then may `answer-check` pass a merge go.

**Second login: worth it, as one cutover, not before S14 is built.** S14 builds the owner-id parameter and the code refusal (host login id equals owner id: `answer-check` and the merge verb refuse with a reason, failing test first). The login exists before merge automation, OA-18, OA-19 and OA-20 go live. If the owner declines, those stay off and every merge is typed by hand.

**Steps.**
1. Owner in chat: "OA-6: the owner means ironbelly only; chat answers count only from a session I opened. Create a separate agent account. Record it." An agent records it.
2. Owner (account creation, 2FA, admin are owner-only): reads GitHub's machine-account terms, creates the agent account (name is the owner's pick), turns on 2FA, invites it as outside collaborator with Write on IronClaude. Coder only if the owner wants it.
3. Owner sets the OA-5 ruleset (D16 settings) after the CODEOWNERS PR merges and Clay accepts the roles, and decides the approvals count (section 4, choice 1).
4. Agent reads both ids and writes `owner_login`, `agent_login`; watcher keys `owner_account_id` and `approval_excluded_ids` = agent id; approvers file = `ironbelly` id (a mismatch stops the watcher, so it fails safe); plus a list of open issues assigned to `ironbelly`, which read as `assigned_other` until reassigned.
5. Owner switches ONE host: signs `ironbelly` out of `gh`, replaces the Coder `github` secret with the agent credential typed in the owner's own terminal, revokes every old `ironbelly` token. Owner says go. Throwaway tests: login prints the agent in a fresh shell and in an Orca session; permission is `write`; an unapproved agent PR cannot merge on a gated and an ungated path (per the approvals choice); `gh pr merge --admin` and a push to master are refused; Augment and Codex both review an agent-authored PR (a silent reviewer reads as clean, so test first); claim writes assignee, issue type, Complexity and `Approved`; a watcher dry run sees an agent-assigned issue; a pr-submit dry PR.
6. Owner says "Cut over". Agent records it with the ruleset id and the credential expiry date. Other hosts follow one at a time with the first two tests.
7. Rollback: the owner says OA-6 is unnamed again; merges are typed by hand. Break-glass is the owner's browser or own laptop, never `ironbelly` logged into a host.

**Effects.** `/sc:pr-submit`: same command and `--repo IronbellyOrg/IronClaude`; it never merges; PR author, replies and resolves become the agent; fix pushes dismiss stale approvals, so approval comes after the last round. Workers: the same agent login; can push branches, open PRs, comment; cannot approve as the owner or use admin bypass. Coordinator: merges only after the chat go plus the id-matched approval; before cutover it asks the owner to merge by hand.

**Cost (estimates).** Owner about 1 to 1.5 h once, about 0.25 h per extra host, about 1 min per merge, about 15 min per credential renewal if the credential expires. Agent about 3 to 4 h (id refusal and keys 1 to 2 h inside S14, tests 1 h, ledger, config and migration list 1 h). Ruleset time is OA-5's.

**Risks and fixes.** Old `ironbelly` credential left in either route (revoke; `--admin` test; live-id refusal). Owner logs back in under pressure (break-glass rule; refusal makes it visible). Bots silent on the new account (test first). Credential expiry stops all agents (expiry in the ledger; fails safe). Write role may lack org-level field writes (UNVERIFIED; step 5 test decides). Chat-only answers still leave no GitHub trace.
