## 2 Why this is best
- "Every repo off" is NOT what master does. `dispatch.py:415-427` generates a config for each Orca repo and runs `first_run`; `first_run.py:153` (`_enable`) writes `enabled: true` when the six checks pass; `first_run.py:195` creates the trigger label. `git grep auto_enable origin/master -- src docs/designs tests` printed nothing; `defaults.py:32-41` has no such key. Only the plan (SPEC.md:118, :582) has it.
- Today the hole is shut by accident: no `Coordinator` worktree exists (`ls /home/coder/workspaces/worktrees/*/Coordinator` fails; Coder 516 is open), so the `config` check fails. When 516 and 515 land, any repo with a Project (IronClaude, a public repo, is one: Project "Ironclaude - Development") can switch itself on. The 515 answer "the entry on its own starts nothing" is true only until then.
- A hand-set `enabled: false` is sticky: `first_run` runs only for a freshly generated config (`dispatch.py:425-427`), and `_enabled` skips the repo (`dispatch.py:428-436`).
- `run-all --dry-run` alone cannot show issue decisions: it generates nothing and starts no child (`dispatch.py:416-420`, `:446-448`). Decision lines come from `once --dry-run`, so the shadow needs part (b).
- The launch account (ironbelly, shared by the owner and all agents) is dropped from generated approvers (`generate.py:243-245`). Keeping that exclusion is what stops an agent approving its own issue.
- Ship gate closed: `launch.py:48` `GOVERNED_LEVELS_ALLOWED = False`, so only Pipeline None launches. Code cap is 6 launches a day per repo (`cycle.py:36`); there is no in-flight cap on master (`git grep max_in_flight` empty), so "one issue" is procedure.
- Sandbox facts (gh reads): PRIVATE; `projectsV2` empty; issue 1 open, assigned to clayphi; collaborators ironbelly and clayphi are admins; org issue field `Approved` exists with option Yes. Host: `crontab` not found; `~/.config/superclaude/issue-watch.json` has `enabled: false`.
- There is no global off: `git grep DISABLED` shows only the per-repo store check (`cycle.py:742`, `:1156`, `record.py:283`). The Coder 515 text re-creates the cron line at every boot, so removing the line by hand does not last.

## 3 Alternatives rejected
- Plan default as written (install 515 now, trust "every repo off"): false on master, see section 2.
- IronClaude as first throwaway: public, real issues get a new label, strangers can comment; fails the risk-first test. It gets its own later go.

- 24-hour `run-all --dry-run` as the only evidence, or a 6-hour shadow: shows no decisions; too short to cross a cron tick count and a day boundary.
- One class-level go for later repos: the plan's own rule is a go per enable (SPEC.md:501, :565).
