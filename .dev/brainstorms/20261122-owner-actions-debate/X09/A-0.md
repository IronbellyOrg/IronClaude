# X09 (OA-19) Switching the issue watcher on, repo by repo. Agent A, round 0, lens: pragmatic

Terms. "Watcher" = the poll that finds issues assigned to the launch login and starts a claim. "Sweep" = one `run-all` pass over every Orca repository. "first_run" = the six per-repo setup checks. "Ship gate" = `GOVERNED_LEVELS_ALLOWED = False`, so only Pipeline None launches. "Shadow run" = dry runs that read GitHub and write only local state.

## 1 Proposal
First throwaway repo: `IronbellyOrg/orchestrator-sandbox` (private). Not IronClaude (public, the real repo) and not Coder (real infrastructure).
Sequence, each step reversible, each behind its own chat go:
1. Agent, read only: confirm entry criteria (section 5). Nothing is written.
2. Go 1 (owner, chat): "Go: set up orchestrator-sandbox only for the watcher test: Project, trigger label, two decoy issues, a Coordinator worktree. Nothing else." Agent then does exactly those writes, hand-writes the sandbox config with `enabled: false` (docs/designs/issue-watcher-setup.md sections 2-5), runs `check-config`, `init-state`, the lock test and restart test (sections 8.2-8.5).
3. Shadow run, 24 hours: `superclaude issue-watch once --dry-run --config <sandbox>` every 5 minutes under `flock -n` and `env -i HOME PATH=/usr/bin:/bin` (cron-like), plus one `run-all --dry-run` at start and end. The doc lets you pick the scheduler (setup doc line 197), so no crontab is needed.
4. X-001 check (claim agent and standing coordinator share one worktree), recorded at four points.
5. Kill-switch drill: touch `DISABLED`, next cycle must say `disabled`, remove it.
6. Go 2 (owner, chat): "Go: enable the watcher on orchestrator-sandbox for issue 1 only." Agent sets `enabled: true`, labels, assigns and approves issue 1 in the documented order (setup doc section 6), and touches `DISABLED` the moment the first `launched` line appears. Cap of 1 is by procedure: only one eligible issue exists.
7. Agent reads the claim: one assignment and comments, no worker, at most one new session. It writes the go/no-go record. S17 ends there.
Switch off, in order of speed: `touch ~/.local/state/superclaude/issue-watch/<repo>/DISABLED` (stops before any GitHub call, setup doc line 301); `"enabled": false` in that repo's config; remove the cron line (only holds until next boot once Coder 515 is built, because the template recreates it). Owner says: "Stop the watcher." Agent touches DISABLED in every state dir and sets `enabled: false`.
Owner does NOT say "turn auto_enable on" here. That is a separate later go after Coder 515 and 516 are built.

## 2 Why this is best (evidence, read 2026-11-22 on origin/master 2ea524514)
- The self-enable path has no brake in code. `git grep auto_enable origin/master` over src, docs, tests returns nothing. `first_run.py:152-153` rewrites `enabled: true` on a pass and `first_run.py:195` calls `ensure_trigger_label`, a GitHub write, in every repo. `run-all` calls `first_run` for each newly generated config (`dispatch.py:421-427`). The plan says the key ships false (SPEC.md:213, :582) but the key is not built.
- Today only an accident keeps repos off: `worktree_invalid` while no `Coordinator` worktree exists (`cycle.py:396-400`; `ls /home/coder/workspaces/worktrees/*` showed none). Coder 516 would remove that brake.
- `run-all` has no repo filter (options at `cli.py:432-469`), so a real sweep cannot be limited to one repo. Hence the one-repo test uses the documented hand config and `once`.
- `run-all --dry-run` with no configs only lists `would_generate` (`dispatch.py:416-420`), so "it wrote nothing" is trivially true; a per-repo `once --dry-run` is the shadow run that applies the rules (setup doc lines 187-214).
- Sandbox facts (gh reads): private; 1 open issue "Add a subtract function to calc.py"; no Project; maintainers `ironbelly`, `clayphi`. Private means outsiders cannot file issues, the cheapest protection there is.
- Host: `crontab: command not found` (Coder 515 not built; its answer of 2026-11-21 keeps the build on hold until the owner says go).
- Ship gate closed (`launch.py:48`, `cycle.py:1032`): only level none launches, so the worst real effect is a claim: assignment plus comments.

## 3 Alternatives rejected
- IronClaude first: public, anyone can file issues, claim comments are public. Last, not first.
- Wait for Coder 515 and 516 before any test (SPEC.md:501 lists them as S17 preconditions): rejected for the throwaway only. A hand-made worktree and a loop give the same evidence now. They stay mandatory before the auto_enable go.
- Dry runs only, forever: a dry run never calls Orca (setup doc line 187), so the launch path stays unproved.
- 24-hour `run-all --dry-run` alone as the shadow run: see section 2, near zero information.
- A brand new repo: extra Orca registration and approvers for no gain.
- Per-repo go for every repo permanently: contradicts the owner's "nothing manual" end state (OAG3 verdict, C-001).

## 4 Implications, benefits, risks, costs
Benefits: proves claim, kill switch and cron-like environment on a repo where failure is harmless; produces the first real capture to replace `_assumed_shape` fixtures.
Costs (all estimates; basis: setup doc has about 12 owner commands, the SPEC 13.2 X-001 test has 4 observation points): setup 1.5 h, shadow run 0.5 h attention (24 h wall clock), X-001 1 h, first claim and record 1 h. About 4 h attention, a little over 1 day elapsed. GitHub calls: 2 per idle cycle, 24 an hour, 0.48 percent of the limit (setup doc line 565).
Risks:
- Shared login: the owner and agents are both `ironbelly`, which is also an approver, so an agent could approve its own issue (`warning: approver_is_launch_account`, `first_run.py:187-190`). Acceptable in the sandbox; the Approved step there should be done by `clayphi` or by the owner in the web page. Must be fixed or accepted in chat before IronClaude.
- The launch guard reads command text only and master is unprotected (SPEC.md RK-2, INV-025). On a public repo a worker could push; the sandbox limits the blast radius.
- Public repo later: issue text becomes agent input (prompt injection); gates are exact assignee, trigger label, approver id and `edited_after_approval`; maintainers are also approvers (`generate.py:117-126`). Public label and comment writes are visible to all.
- No global kill file exists in `run-all` (grep of `dispatch.py`, `cli.py` found no `DISABLED`); the switch is per repo. A cheap global off by config alone is `allowed_owners` set to an owner that matches nothing (`repos.py` filter; UNVERIFIED by run). Optional small code change: global `DISABLED` check in `run_sweep` (estimate 1-2 h, basis: one guard plus one test).
- Owner note on Coder 515/516 (2026-11-21) says configs should start `enabled: true`; code starts false (`generate.py:252`). Recommendation: keep false until the one flip, which still ends at the owner's true.
- `claim_by`, `max_in_flight` are not built (SPEC.md:61); real caps today are 1 launch per cycle and 6 per day per repo (`cycle.py:36`).
