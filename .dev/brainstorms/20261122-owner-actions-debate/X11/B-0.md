## 4 Implications, benefits, risks, costs
Benefits: six removals settled; install gate is mechanical (backup) not memory; the two real questions get asked once.
Risks: (1) A host install before the backup deletes unchanged copies of the 650 and 656 skills; recovery then needs `git show v6.0.0:<path>` from the tag. (2) The backup folder gets forgotten and becomes clutter. (3) Holding 650 and 656 leaves rf-team-lead.md and the launch-level guard text pointing at removed skills; agents may follow them. (4) Hash proof means a host edited copy is kept, and the install prints "Kept ..." lines that an agent must not "fix".
Costs (estimates, basis: reading 8 PR bodies and ~20 greps took me about 1 hour): owner 5 to 10 minutes to answer two questions; agent 30 minutes to record, 15 to 20 minutes per host for the check and backup (host count UNVERIFIED); a follow-up issue plus PR for a per-name opt-out about 3 to 5 hours.
If a removal is wrong later: the repo can restore a file from tag v5.0.0, v6.0.0 or v6.1.0; the installer never touches a name the current release ships (install_retired_files.py docstring), so re-shipping a skill needs no extra step beyond regenerating retire data.
