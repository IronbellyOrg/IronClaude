## 3. Alternatives rejected

- Confirm all eight now without asking: cheapest, but it would bless 632, 650 and 656 for an owner who built a task package three days ago. A wrong "confirm" is cheap to undo only if the host check still runs, so it would still need the check.
- Revert 632, 650 and/or 656: D14 already rejected a revert. Cost is high (PR 650 alone touched 68 files; 632 deleted dozens of docs and tests) and re-adds code Clay chose to retire.
- Review each PR line by line: PRs of 68 to several hundred files, most deleted. The reviews that matter (bots, Clay, tests green) already ran. The owner's real question is "do I still use it", not "is the diff right".
- Keep "not confirmed" forever with the per-host diff only: safe, but leaves every host install blocked with no owner action that ends it.

## 4. Implications, benefits, risks, costs

- Benefit: host installs unblock for the five low-risk items today; the owner answers one question, not eight.
- Benefit: the plan's FR-66 gets corrected to name the retire step as the real hazard.
- Risk if a removal is wrong: the next install or update deletes the pristine installed copy on that host, silently apart from one printed line. Edited copies are kept. Recovery: the files exist at tags v5.0.0 and v6.0.0 (`git show v6.0.0:<path>`), and the backup in step 3 above. Restoring one skill is about 0.1 hour (est, copy of one folder); reverting a whole PR 632 or 650 is about 3 to 8 hours (est, basis: 68-file PR 650 and the larger 632, plus merge conflicts with later work).
- Risk of the sentence: owner confirms from habit and loses a workflow. Mitigated by the one named question and the backup.
- Cost: owner about 5 minutes (est). Agent: recording about 0.5 hour (est); per-host read-only list about 0.25 hour per host (est, one listing and eight hash comparisons; host count UNVERIFIED).
- Not fixed by this item: a stale `/task` mention at `src/superclaude/commands/issue.md:101`. A follow-up, not blocking.
