## 1. Proposal
The two consents are two different hazards, so I answer them separately, per repository.

**A. Typed wake line** (a script typing a line into an existing Claude session with `orca terminal send`): NO for every repository, with no "idle sessions only" exception. A coordinator learns of work from the wake file it reads when each `check --wait` returns (at most every 5 minutes, FR-28) and from the Orca mailbox if live test U5 passes. The last-resort alert marks the Orca workspace unread (D10 item 1), which types nothing. The typed path is not built. If the owner ever says yes, it becomes its own stage behind a hard code switch flipped by a reviewed commit, the same pattern as `GOVERNED_LEVELS_ALLOWED = False` (FR-23).

**B. `coordinator_autostart`** (a script starts the `COORD-<RepoName>` session): false for every repo today; an absent key means false (FR-27). Turn it on one repo at a time, in this order:
1. A throwaway repo the owner names in chat (stage S17). Candidate: IronbellyOrg/orchestrator-sandbox (private; its description says it was made for the issue 655 end-to-end tests, "owner deletes"; whether Orca has it registered is UNVERIFIED).
2. IronbellyOrg/IronClaude: after S17 passes and 14 clean days on the throwaway (14 is my proposal, no source gives a number).
3. IronbellyOrg/Coder (where issue 516 is built): after IronClaude has run clean for the same period.
4. IronOrca (a fork of an outside project), Ironbrain, Ironeye: stay false; no question is put until the owner wants the watcher there. IronOrca is last because gh defaults pull requests to a fork's parent (the trap in the project CLAUDE.md).

Conditions that must ALL hold before the owner is asked about a repo (each is checked by an agent and shown in chat):

The owner has confirmed the new WORKER-CONTRACT wording in chat (OA-7): line 70 today says the coordinator is "an Orca coordinator session the person opened"; the drafted amendment adds "started at depth 0 by the owner's installed watcher under a standing authorization recorded in chat" (D06 item 7).

## 2. Why this is best (evidence)
- The plan already defaults both off: SPEC.md:581 (OA-18), DECISIONS.md:1266 and :1358. My proposal keeps those answers and changes only what is built (the typed path is not built) and which conditions gate a later yes.
- A typed line cannot be told from a person's typing. D06 VERDICT.md:22 says the same terminal accepts `orca terminal send` and a script knows the head sha, so a script-typed text cannot be told from a person's go (risk INV-003); VERDICT.md:86 lists "whether the harness marks text sent with `orca terminal send` differently" as unchecked. If the poll ever types into the coordinator terminal, that terminal stops being a person-only channel, and every merge go and push go is typed there. Refusing the typed wake keeps the residual spoofing risk from growing. This is my main reason.
- What Claude Code does with text typed during a tool call is unchecked: `src/superclaude/core/WORKER-CONTRACT.md:200` on master ("UNVERIFIED ... this is why typed text goes only to a positively idle prompt"). Even the contract's own typing rules veto typing into a busy or unknown session (same file :138).
- The typed line is only a nudge: D10 VERDICT.md:15 ("Losing either costs latency, never a wake"), :16 (idle only) and :21 (item 8: start route waits on the U25 tag spike). Losing it costs at most about one 5-minute pull cycle (FR-28; cron entry `*/5` in docs/designs/issue-watcher-zero-setup-coder-handoff.md section 2).
- Nothing typed exists on master to disable: `git ls-tree` of src/superclaude/cli/issue_watch on origin/master lists no wake module, and `git grep 'terminal send'` there returns nothing; `coordinator_autostart` appears nowhere in master src. So "no" costs no rework on master; the typed path lives only in draft PR 686 (SPEC.md:204, :495).
- Autostart needs the conditions because the authority model is the stricter one: SPEC.md:229 (FR-27) and :627 (E-2: "D06 is the stricter authority rule; D10's start is transport"); D06 VERDICT.md:19 (item 6: depth 0 only, authorization "self-attested", INV-010) and :20 (item 7: the contract amendment is "none in force"); :88 (depth 0 for a script start: "not run").
- The contract on master still says the coordinator is one "the person opened" (WORKER-CONTRACT.md:71), so a script start today would contradict the contract: that is C1.
- Restart has a known hole: FOLLOW-UPS.md:16 (F5) says FR-34 restarts a coordinator without the consent FR-27 requires. Coder 516's own owner decision 2 ("a stopped coordinator session is started again at the next check") has no cap, while FR-34 caps at 3 (SPEC.md:236).

## 3. Alternatives rejected
- **Plan default as written ("both paths built behind the flag and tested", DECISIONS.md:1266).** Rejected in part: a built but switched-off typing path is a standing capability on a shared login that every later reviewer must re-check. Not building it is smaller and fails safer. Cost of being wrong: building it later (about 6 hours, estimate).
- **Typed line only into idle or just-started sessions (D10 item 3).** Rejected: for a just-started session `orca agent launch --prompt` already delivers the first prompt without typing; for a person-opened idle session the person is at the screen or the unread mark reaches them. The carve-out buys little and needs the unproven idle test.
- **Turn autostart on now for IronClaude, as Coder 516 decision 5 ("nothing manual") reads.** Rejected: U3 and U25 have not run, the contract wording is not amended, 516 is on hold, and the watcher is `enabled: false`. The owner's goal (no per-user setup) is kept; only the order changes.
- **One global switch for all repos.** Rejected: repos differ (public with two maintainers, private, a fork of an outside project). A wrong start in one must not be switched on by an answer about another.
- **Autostart permanently false, as OA-7's default says ("can never be true").** Rejected as a final answer: every workspace would need a person to open a coordinator by hand, the manual step the owner removed on 2026-11-18, and a forgotten coordinator leaves approved issues unworked (`coordinator_absent`). Fine as the default until the conditions hold.
- **Typed ccsession start as fallback when U25 fails (D10 item 8).** Rejected: it types a command into a fresh terminal on a shared login with no proof of the tag the lookup keys on; a duplicate start is the known failure (D10 VERDICT.md:21).
- **A listener or listening daemon in the coordinator.** Out already: owner decision on Coder 477.

## 4. Implications, benefits, risks, costs
**Benefits.** The coordinator terminal stays a person-only channel for every go (merge, push, close). No new code that types. Autostart reaches zero-setup one proven repo at a time, with a stated stop rule. Both answers are reversible by one chat sentence.
**Risks that remain.**
- Autostart is self-attested: the script writes the prompt that claims the owner's authority (INV-010). The conditions narrow it; they cannot make it verified.
- A script-started coordinator runs on the shared `ironbelly` login (OA-6): whatever it can do, the owner can. Whether to start it with `CCSESSION_PERMISSIONS=default` (commit 843df6ac4 on master adds that mode) instead of the permission bypass is open: default mode may stall on a prompt nobody sees. UNVERIFIED.
- Restart loops spend money and can duplicate sessions if the process list is unreadable (D10 :21); cap 3 and "unknown means start nothing" cover it only once built and tested.
- Latency: without a typed nudge an idle person-opened coordinator may sit up to about 5 to 10 minutes before reading a wake, and not at all if it is not in `check --wait`. Mitigation: the unread mark, and the person's own look at the dashboard.
- Mailbox (U5) may fail from outside an Orca Run; then the file pull is the only channel (SPEC.md section 13.2, Transport gate row). That is acceptable by design (D10 item 2).
**Costs (all hours are my estimates, basis in brackets).**
- Live checks U3, U25, `tui-idle` meaning, U5: about 3 hours together [four short probes, one throwaway repo; no data].
- Autostart key, conditional restart (F5), `coordinator_absent` handling and tests: about 4 hours [about four requirements, FR-27, FR-34, FR-17, FR-20, at the size of comparable watcher tests].
- Contract amendment review (lines 70 and 245, already drafted): about 1 hour owner and agent time [short text, two lines].
- Owner time: about 2 minutes per sentence, 3 sentences now or later.
- If the owner later wants the typed path: about 6 hours plus U25 and the busy-send check U40 [shared terminal helper with a parity test, FR-18].
