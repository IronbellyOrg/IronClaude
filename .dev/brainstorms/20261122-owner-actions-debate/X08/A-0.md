## 1 Proposal
Split the one item into three questions, answer each by the smallest step, and keep everything reversible.
1. Typed wake line into an idle session a person opened: NO, for every repo, with no review date. Build no code for it now (a "typed_wake" key, absent means false, is the only thing kept).
2. Autostart (a script, not the owner, starts the project coordinator session): FALSE for every repo today. Switch it on one repo at a time, only when the conditions in section 5 hold.
3. The first prompt of a script-started session is passed as a launch argument (orca agent launch or orca worktree create with --prompt), never typed in afterwards. So autostart needs no typing at all.
Order of repos to switch autostart on (each needs its own chat sentence):

 b. IronbellyOrg/IronClaude (public), only after Coder issue 516 provisions a COORD-IronClaude session. Until then the hand-opened session ORCH-IronClaude is the duty holder and nothing restarts it (SPEC:236).
 c. Every other repo (Coder, the chiba repos, and so on): stays false until the owner names it.
Sentence the owner says in chat NOW (one message, covers all repos):
 "OA-18 for every repo: coordinator_autostart stays false, and no typed wake line into an idle session. Record it."
Sentence the owner says LATER, once per repo, when its conditions hold:
 "Turn on coordinator_autostart for IronbellyOrg/<repo>: a script may start COORD-<repo> at depth 0 with the issue-pipeline duties I recorded on 2026-11-18, and nothing else."
What an agent then does: (now) records the quote with date in the decisions record, sets no key (absent already means false, SPEC:229), and tells the code builders to skip the typed-line path. (later) records that quote, writes "coordinator_autostart": true into that one repo's JSON file under the watcher config directory, makes the launch prompt cite the recorded quote and say it is self-attested (D06 item 6), runs the live checks of section 5 if not yet done, and reports the first start. To undo: owner says "turn off", agent sets false; the running session is left for the owner to close.

## 2 Why this is best
- The plan default already is both off; file pull and mailbox only (DEC:1358; OA-TRIAGE.md:35). My step records it once so nobody keeps asking, and does not widen anything.
- Nothing needs the typed line. The coordinator reads the wake folder at every wait return, at most every 5 minutes (SPEC:230); the wake file is durable and is the guarantee, the typed line is only a nudge (D10 items 2 and 3, D10:15-16; D10:76 "not the transport and not the guarantee").
- The typed line is the only channel with unproven preconditions: idle meaning "tui-idle", screen-tail check and the tag spike (D10:26, D10:84; SPEC:668). D10 gave the whole item 75 percent confidence and says it drops if the owner rules any typed line unacceptable (D10:79), leaving file and mailbox: a cheap fallback already designed.
- Typing is the same capability as forging a go. The same terminal accepts "orca terminal send", and the plan admits answer-check cannot tell a person from a script (D06 item 9, D06:22). A typing channel into a session where the owner types approvals widens that hole for no gain. A wake line holds ids only (SEC-16, SPEC:305), which limits injection but not forged approvals.
- Autostart has no code, no key and no live proof today: origin/master has no "coordinator_autostart" (git grep, empty) and I found no orca_term or waker file in the master tree (D10:85 says they are on master; UNVERIFIED either way, I did not find them). FR-27 itself requires the depth-0 live test (U3) and the contract amendments (WC:70, WC:245) first (SPEC:229).

The owner's 2026-11-18 answers there (restart yes, duties granted by launch prompt) are intent, not the per-repo recorded consent D06 item 6 needs. - Launch prompts can be passed as arguments: issue 516 says orca worktree create takes --agent and --prompt, checked with --help. So no typing is needed to start a session (still UNVERIFIED for depth 0, which is U3).

## 4 Implications, benefits, risks, costs (hours are my estimates)
Benefits: one minute of owner time closes the item; no new capability is opened; nothing blocks other work, because the wake file, the ack and the coordinator's own pull are unaffected; the owner's later per-repo yes is one sentence.
Implications: while autostart is false and no coordinator is running, the poll reports "coordinator_absent" (SPEC:229) and wakes pile up in the wake folder until a person opens the session. For a lone owner on one box that is a visible, harmless delay. On fresh workspaces with no person it means the pipeline idles until Coder 516 plus autostart are on (accepted trade).
Risks if autostart is later on: a script starts a session with write duties under a self-attested prompt (D06 item 6; the script writes the prompt). Bounds already in the plan: duties list only what the owner recorded, never merge or close; restart at most 3 times, stored counter; an unreadable process table starts nothing (SPEC:207, 236); one session per repo name (COORD-<repo>). A crash loop costs model tokens until the cap of 3 stops it. Reversal is one config line.
Risks of typing (why not): text can land in a half-written draft, a permission prompt or a busy session; a script that can type can also type an approval word. Both are avoided by not enabling it.
Costs (estimates, basis in brackets):
- Owner now: about 1 minute (one chat message). Per repo later: about 1 minute.
- Agent now: about 0.25 h (record the quote, brief the builders; no code).
- Typed-line work avoided: about 3 to 5 h build plus 2 h tests (basis: D10 says the poll's wake code copies about 100 lines of terminal-helper code, plus tests for the 4 preconditions; UNVERIFIED).
- Before the first autostart yes: depth-0 start live test about 1 h (one throwaway launch and capture); autostart code and tests about 4 to 6 h but already inside the planned stages S14 to S16, so not new cost (basis: FR-27, FR-34 sizes; UNVERIFIED).
- Tag spike (the naming check) about 1 h; needed for the COORD- name, not for typing.
