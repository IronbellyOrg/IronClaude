# X04 (Orca auth token printed in a debate transcript). Agent B, round 0. Lens: risk-first.

## 1 Proposal
Verify first, rotate only if still needed, never delete transcripts, and stop the habit with a ban plus a hook.
1. The coordinating session (not a debate agent) runs ONE command that never prints the token. It compares a one-way fingerprint (first 10 characters of a SHA-256 hash) of today's token with the fingerprint of the exposed one, `5220dd2a31` (computed by me from the transcript without printing the value):
   `t=$(jq -er .authToken /home/coder/.config/orca/orca-runtime.json) && [ ${#t} -eq 48 ] || { echo ERROR; exit 1; }; [ "$(printf %s "$t" | sha256sum | cut -c1-10)" = 5220dd2a31 ] && echo SAME || echo DIFFERENT; unset t`
   Fail-safe: a missing `jq` or a wrong-length value prints ERROR, never a false DIFFERENT. `jq` being installed is UNVERIFIED. Shell tracing must be off.
2. DIFFERENT: stop. The token was already replaced by the 2026-11-21 02:08 restart. SAME: the owner picks a moment with no worker running, quits and restarts Orca, then step 1 is repeated and must say DIFFERENT. ERROR: fix the command, do not guess.
3. Re-run the names-only scan (below) over `~/.claude/file-history`, `~/.claude/history.jsonl` and the Orca journal `~/.config/orca/agent-session-journal.db`; report file names only.
4. No transcript is edited or deleted. 5. The rule below goes into the shared rules file and every workflow brief, and a hook enforces it.
Rule text: "Never open, search inside, print or copy a file that holds a secret: `/home/coder/.config/orca/orca-runtime.json`, anything named token, key, secret, credentials or `.env`, and the transcript folders under `~/.claude/projects`. `stat` and `ls -l` are allowed. Do not try to hide the value with a filter; do not read it at all. If you need a fact from such a file, ask the coordinator. If a command prints a secret by mistake, stop, name only the file to the coordinator, and never repeat the value."
Hook (mechanical backstop): a PreToolUse hook on Read, Grep and Bash that refuses a path or command text matching `orca-runtime.json`, and a `permissions.deny` entry `Read(/home/coder/.config/orca/**)` in `~/.claude/settings.json`.
Owner says in chat: "X04 approved. Compare the Orca token fingerprint and tell me SAME or DIFFERENT. If SAME, restart Orca at the time I name. Do not edit any transcript. Add the credential-file rule and hook." An agent then records the words, runs step 1 and reports one word, and opens the rule PR with `/sc:pr-submit --monitor 3`.

## 2 Why this is best (evidence)
- The record: `DECISIONS.md:1176-1178` (debate agent printed the token; the value is in no brainstorm file), `DECISIONS.md:1298` (owner action), `debates/D02/VERDICT.md:63`, `STATE.md:27`, `spec/SPEC.md:545` ("not rotated"). The cause, `debates/D02/adversarial/adversarial/debate-transcript.md:361`: "my redaction pattern did not match". So the agent meant to hide it and a filter failed. A rule saying "redact" would fail the same way; it must say "do not read".
- The token is made fresh at each Orca start. In `/opt/Orca/resources/app.asar` (grep) the runtime class has `authToken=(0,Y.randomBytes)(24).toString("hex")`, a 48-character value. Searching for a reload path (`this.authToken =`) found none (minified code, so UNVERIFIED).
- Timing: `stat` of `orca-runtime.json` = 2026-11-21 02:08:41 UTC, mode 600, 366 bytes; `ps` shows the Orca processes started 02:08:39 to 02:08:41. The exposed transcript was last written 2026-11-20 04:18:20. So at least one restart sits between. Likely rotated; not proven, hence step 1.
- What the token allows: the Orca command line sends it with every request (`/opt/Orca/resources/app.asar.unpacked/out/cli/runtime/transport.js:138`) over a local socket (`.../cli/runtime/metadata.js:16`). Anyone holding it AND able to reach the socket can run any Orca control call: terminals, worktrees, agent sessions, typed input into sessions. Socket folders are `drwx------ coder` (`/tmp/orca-ab-973b597026fe08cf`). Orca also listens on `127.0.0.1:6768` (`/proc/net/tcp`, state listening); whether that port accepts this token is UNVERIFIED.
- Scan, names only, nothing printed: `grep -rlE 'authToken[^A-Za-z0-9]{1,6}[A-Za-z0-9_.-]{20,}'` over `~/.claude/projects` found 4 files. Three (Ironeye, Ironbrain, Coder issue 473 claim, dated 2026-11-07 to 11-09) hold 29, 31 and 34 character letters-only-plus-symbol values, not 48 hex characters: probably code text, UNVERIFIED. The parent session file did not match.
- Who could read it: `getent passwd` lists one login user, `coder` (uid 1000); `/home/coder` is `drwx------`, transcripts are `-rw-------`. So only `coder` and root. But every agent here runs as `coder` and can search those folders (my scan did), and the text was also part of that subagent's model context sent to the model service (retention UNVERIFIED).
- No guard exists today: `~/.claude/settings.json` has no `deny` list (grep found none); `src/superclaude/core/RULES.md` Safety Rules (line 221 of origin/master) say nothing about secrets.

## 3 Alternatives I rejected
- Restart Orca now without checking: interrupts every running agent session and the coordinator for a possibly useless change; the Orca guide (`~/.claude/skills/orca-cli/SKILL.md:44-45`) also says not to restart Orca casually.
- Do nothing because it is local: cheap, but rotation is unproven; a few minutes of checking beats an unknown live control token.
- Purge the transcript or the folder: transcripts are the debate evidence, the session folder holds 615 saved tool results, and editing a session file risks breaking resume. A replaced token makes the old text worthless.
- Edit the one file with `sed -i`: only a fallback if the token is SAME and cannot be restarted. Otherwise it alters a record for no gain.
- Prompt rule alone: the incident was a failed filter, not ignorance; a mistaken command is not stopped by words. Hence the hook.
- Delete or hand-edit `orca-runtime.json` to force rotation: Orca owns that file; what the Orca command line does without it is UNVERIFIED.

## 4 Implications, benefits, risks, costs
Benefits: a yes or no on rotation; no loss of evidence; the next agent mistake is blocked by a tool refusal, not by memory. Risks: (a) the check reads the token inside one command, so run it only by the coordinator with no output but one word; (b) a hook can block legitimate `stat` use if too broad, so match on read-style tools and the file name only, and test it; (c) restart (if SAME) drops running sessions, and a resumed coordinator needs to be re-bound and its screen checked (memory notes `orca-coordinator-rebind-after-resume`, `orca-worker-resume-verify-screen`); (d) the three older name-only hits stay unexplained until someone classifies them without printing; (e) the model-service copy cannot be recalled.
Costs (all estimates): step 1 about 0.1 h (one command plus reporting); scan of other places about 0.2 h; restart plus re-check about 0.5 h, up to 1 h with session recovery (basis: re-attaching the coordinator and checking its screen); rule text in `src/superclaude/core/RULES.md`, the debate brief template and `make sync-dev` about 0.5 h; hook plus a test plus one PR monitor round about 2 h (basis: a small script, one test, one review cycle). Total about 1 h if DIFFERENT and the rule only; about 4 h with the hook and a restart.
