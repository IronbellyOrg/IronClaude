## 3 Revised proposal (the one I would sign)
1. **Entries now:** `issue.comment` and `issue.status.move` (Status to In review only, only from allowed Statuses, never Done). These are exactly what FR-83 (SPEC line 243) needs. **Later:** `issue.body.append_plan_sections` (S15c). **Never granted:** `issue.assign` (the claim session assigns; no coordinator code needs it), `pr.merge`, `issue.close` (SEC-06 refuses both as grant names), `issue.hold` (Q03 removed it). One per-PR go bound to the head sha covers merge and that PR's issue close (OD-10).
2. **Scope:** one `owner/repo` per grant, adopted issues only, no wildcards, never global. A repository added later starts empty. Order: the S17 throwaway repository (name not set, OA-19, UNVERIFIED), then `IronbellyOrg/IronClaude` after that run passes.
3. **Expiry:** stored end date, default 90 days, longest 90. After it the write refuses and says "expired on <date>". The owner may name a shorter date.
4. **Owner sentence, in chat:** `Grant issue.comment and issue.status.move on <owner/repo> for adopted issues, 90 days.` The tool refuses "all" or "everything".
5. **Recording:** only a session the owner opened and types in, never a worker or a script-started coordinator (who counts is OA-6, still unnamed). It says "Received" once. From S14, `repos grant` writes grant id, date, repo, entries, end date, the owner's quoted words and the recorder into `<config dir>/issue-watch.d/<name>-grants.json` beside the approvers file (path shape from B; UNVERIFIED against master). That path joins the SEC-10 protected set (verb refusal plus Write/Edit hook). The owner writes no file.
6. **Reading:** every write re-reads the file, no cache. Missing, unreadable, malformed, unknown entry, wrong repo, past end date, repo not enabled, or issue not adopted means no grant. Each use is logged with the grant id in `grants-use.jsonl` (SPEC line 176, SEC-07).
7. **Revoke:** `Revoke <entry> on <repo>` or `Revoke all on <repo>`. Newest line per repo and entry wins; a revoke wins a tie; it bites at the next write; it needs no accepted-record check because it only narrows. An agent may suspend an entry at once after a wrong write if it says so in chat; only the owner turns it back on. No revoke verb exists in the plan (SPEC grep), so S13 adds `repos revoke`.
8. **Completion rule:** a succeeded run needs both entries; a failed, blocked or partial run needs only `issue.comment`. If that comment is refused, the local escalation must show the failure so it is not hidden.
9. **Refusal (printed before any `gh` call, no issue text echoed):** `Refused: no standing permission "<entry>" for <repo> (none recorded, expired on <date>, or revoked). Nothing was written to issue <N>. To allow it the owner says in chat: "Grant <entry> on <repo> for adopted issues, 90 days." A local escalation was recorded.`
10. **Spec edits (about 1.5 hours, estimate, about eight table rows):** SEC-07 (two entries now, body later, the rules above); SPEC line 243 last sentence (per-outcome rule); SEC-10 (grants file path, not a config key); the "three versus four" wording in OD-11, X-1, OA-11 and R-4 (SPEC lines 107, 580, 598, 602); `WORKER-CONTRACT.md` lines 302-303 ("that issue's grant row") with the owner's chat approval (OA-7). Land before S14 so tests pin expiry and the file.

**Benefits:** the coordinator posts the result and moves the issue to In review with no owner round trip; every permission has a user, an end date, a use log and a one-line off switch; a typo cannot stop the poll; merge, close, hold and assign stay out.
**Risks (narrowed, none closed):** the login `ironbelly` is shared, so only our verbs check grants and any shell with the login can run `gh` directly (SEC-13, SEC-18, D15); any session on this host can claim the owner said it (SEC-09); on a public repository comments and Status moves are world-readable and appear as the owner, a comment can be deleted and a Status moved back, but a body edit's history survives a revoke; before S14 nothing refuses a write; if the owner forgets to renew, the writes refuse safely and say "expired".
**Costs (estimates, not measured):** owner about 1 minute per sentence; agent recording about 15 minutes per grant; spec and contract edits about 1.5 hours; build 5 to 7 hours over S14 (grants-file loader 1 hour, `repos revoke` 1 to 2 hours, about eight small tests 2 to 3 hours, adopted-issue check 1 hour, contract review 0.5 hour), or 8 to 12 hours if the whole feature is counted.
**Order:** (1) owner confirms the chat-grant reading (OA-7) and the two entries; (2) spec edits land; (3) S13 and S14 built; (4) OA-19 names the throwaway repository and the owner says the sentence; (5) after that run passes, the same sentence for `IronbellyOrg/IronClaude`; (6) body entry when S15c lands and one plan section has been read.
