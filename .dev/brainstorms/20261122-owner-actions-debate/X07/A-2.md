## 3 Revised proposal (the one I would sign)
**Entries.** Two now: `issue.comment` and `issue.status.move` (Status to In review only, only from allowed Statuses, never Done). Later: `issue.body.append_plan_sections` when S15c lands. Never: `issue.assign` (the claim session assigns; no coordinator code needs it), `pr.merge`, `issue.close`, `issue.hold` (SPEC SEC-06 refuses the first two as grant names; Q03 removed hold). One per-PR go on the head sha covers merge and that PR's issue close (OD-10).
**Scope.** One `owner/repo` per grant, adopted issues only. A repo added later starts empty. Order: the S17 throwaway repo (not yet named, UNVERIFIED), then `IronbellyOrg/IronClaude` after the throwaway run passes. The adopted-issue check is my and B's proposal; UNVERIFIED that S14 enforces it today.
**Expiry.** Stored end date, default 90 days, refuse beyond 180, owner may name a shorter date.
**Owner sentence (chat):** `Grant issue.comment and issue.status.move on <owner/repo> for adopted issues, 90 days.` The tool refuses "all" or "everything" in a grant.
**Recording.** Only a session the owner opened and types in (never a worker or a script-started coordinator; SEC-08 and OA-6 govern who that is). It says "Received" once. Before the verb: one decision line in the interim ledger (SEC-14), "not an active grant". From S14: `repos grant` writes id, date, repo, entries, end date, the owner's quoted words and the recorder into `<config dir>/<name>-grants.json`, beside the approvers file. That path joins the SEC-10 protected set (verb refusal plus Write/Edit hook). The owner writes no file.
**Reading.** Every write re-reads the file, no cache. Missing, unreadable, malformed, unknown entry, wrong repo, past end date, repo not enabled, or issue not adopted means no grant. Each use is logged in `grants-use.jsonl` with the grant id (SPEC line 176, SEC-07).
**Revoke.** `Revoke issue.comment on <repo>` or `Revoke all on <repo>`. Newest line per repo and entry wins; a revoke wins a tie; it bites at the next write. A revoke needs no accepted-record check (it only narrows). An agent may suspend an entry after a wrong write if it says so in chat; only the owner turns it back on. No revoke verb exists in the plan (neither of us found one), so S13 adds `repos revoke`.
**Refusal (printed before any `gh` call, no issue text echoed):** `Refused: no standing permission "<entry>" for <repo> (none recorded, expired on <date>, or revoked). Nothing was written to issue <N>. To allow it the owner says in chat: "Grant <entry> on <repo> for adopted issues, 90 days." A local escalation was recorded.` For a failed run whose comment is refused, the escalation must show the failure so it is not hidden.
**Spec edits.** SEC-07 (two entries now, body later, rules above); SPEC line 243 last sentence (per-outcome rule); SEC-10 (grants-file path, not a config key); the "three versus four" wording in OD-11, X-1 and OA-11 (SPEC lines 107, 580, 602); `WORKER-CONTRACT.md` lines 302-303 ("that issue's grant row") in the FR-84 amendment with the owner's chat approval (OA-7).

**Benefits.** The coordinator posts the result and moves the issue to In review with no owner round trip. Every permission has a user, an end date and a use log. A typo cannot stop the poll. Merge, close, hold and assign stay out.
**Risks (each narrows, none closes).** The login `ironbelly` is shared: only our verbs check grants, and any shell with the login can run `gh` directly (SEC-13, SEC-18, D15). Public repo: comments and Status moves are world-readable and appear as the owner; a comment can be deleted, a Status moved back; edit history of a body write survives revoke. Before S14 nothing refuses a write (search above). Any session on this host can claim the owner said it (SEC-09). Expiry chore: one sentence per repo per 90 days; if forgotten, the writes refuse safely and say "expired".
**Costs (estimates, not measured; I did not read Clay's parser).** Owner: about 1 minute per sentence. Agent recording: about 15 minutes per grant. Spec and contract edits: about 1.5 hours (basis: about eight table rows plus the two contract lines). Build over what S14 already has: grants-file loader with expiry 1 hour; `repos revoke` 1 to 2 hours; tests for expiry, wildcard, revoke tie, malformed file and failed-run rule 2 to 3 hours (about eight small tests); adopted-issue check 1 hour; contract review 0.5 hour. About 6 to 8 hours extra build and review.
**Order.** (1) Owner confirms the chat-grant reading (OA-7) and the two entries. (2) Spec edits land before S14 so tests pin expiry and the file. (3) S13 and S14 built. (4) OA-19 names the throwaway repo; owner says the sentence. (5) After that run passes, the same sentence for `IronbellyOrg/IronClaude`. (6) Body entry when S15c lands.
