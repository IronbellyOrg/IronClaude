## 3 Revised proposal (the one I would sign)
1. **Entries on day one:** `issue.comment` and `issue.status.move`. Later: `issue.body.append_plan_sections`, at S15c, own sentence. Never grantable: `issue.assign`, `pr.merge`, `issue.close`, `issue.hold` (SEC-06 already refuses the first two as names, Q03 removed hold). Merge and that PR's issue close ride on one per-PR go bound to the head sha (OD-10).
2. **Scope:** one `owner/repo` per grant on this host, adopted issues only, no wildcard, never global. A repository added later starts empty.
3. **Expiry:** end date always stored. Default 90 days; cap 90 (see section 4); the tool refuses a longer date and "forever". After it the write refuses and says "expired on <date>".
4. **Owner sentence (one chat sentence):** `Grant issue.comment and issue.status.move on <owner/repo> for adopted issues, <N> days.` The tool refuses "all" or "everything".
5. **Recording:** only a session the owner opened and types in; never a worker, never a script-started coordinator (OA-6 still unnamed). It says "Received" once. Before S14: one decision line in the interim ledger (SEC-14) marked "not enforced by code, not an active grant"; no real-repository sentence yet. From S14: `repos grant` writes grant id, date, repo, entries, end date, the owner's quoted words and the recorder to the grants file. The owner writes no file.
6. **Reading:** missing, unreadable, malformed, unknown entry, wrong repo, past end date, repo not enabled, or issue not adopted means no grant. Each use is logged with the grant id (SEC-07). The adopted-issue check is a build item; I found no such check on master (UNVERIFIED that S14 includes it).
7. **Revoke:** `Revoke <entry> on <repo>` or `Revoke all on <repo>`. Newest line wins; a revoke wins a tie; it bites at the next write and needs no accepted-record check because it only narrows. An agent may suspend an entry at once after a wrong write if it says so in chat; only the owner re-enables it. S13 adds `repos revoke` (no revoke verb in the plan).
8. **Completion rule:** a succeeded run needs both entries; a failed, blocked or partial run needs only `issue.comment`. If that comment is refused, the local escalation must show the failure.
9. **Refusal (printed before any `gh` call, no issue text echoed):** `Refused: no standing permission "<entry>" for <owner/repo> (none recorded, expired on <date>, or revoked). Nothing was written to issue <N>. To allow it the owner says in chat: "Grant <entry> on <owner/repo> for adopted issues, <N> days." A local escalation was recorded.`
10. **Spec edits (about 1.5 hours, estimate: about eight table rows plus two contract lines):** SEC-07 and OA-11 to two entries now and one later (fix the three-versus-four wording at lines 107, 580, 602); SPEC line 243 last sentence to the per-outcome rule; one home for the grants file and SEC-10 protecting that path; `WORKER-CONTRACT.md` lines 302-303 reworded with the owner's chat approval (OA-7). Land before S14.

**Benefits:** the coordinator posts the result and moves to In review with no owner round trip; each permission has a user, an end date, a log line and a one-line off switch. **Risks (narrowed, not closed):** the login `ironbelly` is shared, so any session can claim the owner said it (SEC-09) and any shell can run `gh` directly (SEC-13, SEC-18, D15); comments and Status moves on a public repository are world-readable and show as the owner, and edit history survives a revoke; before S14 nothing refuses; a forgotten renewal makes the coordinator refuse (safe, visible). **Costs (estimates):** owner about 1 minute per sentence; recording about 15 minutes; build 6 to 8 hours over S14 (or 8 to 12 counted whole); spec edits 1.5 hours; contract review 0.5 hour.

## 4 Residual disagreement
No dispute on design. Two owner choices remain:
- **Longest allowed grant:** 90 days (my pick) or 180 days (A's). With 90, a forgotten grant on a public repository ends sooner and the owner renews about twice as often; with 180, fewer sentences but a longer window for a wrong or stolen claim.
- **Throwaway repository length:** 30 days (my pick: it forces one real renewal before the real repository depends on it) or the same 90 days (A's: less owner work, renewal tested only with a fake clock). With 30, one extra sentence; with 90, the human renewal step is first tried on the real repository.
