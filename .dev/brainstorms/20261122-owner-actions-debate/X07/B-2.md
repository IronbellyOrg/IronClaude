## 3 Revised proposal (the one I would sign)
1. **Entries:** two on day one, `issue.comment` and `issue.status.move` (Status to In review only, from allowed Statuses only, never Done). Later, one more: `issue.body.append_plan_sections`, only when S15c gives it a user and a checking verb. Never granted: `issue.assign` (the claim session assigns), `pr.merge`, `issue.close`, `issue.hold`. Merge and that PR's issue close ride on one per-PR go bound to the head sha (OD-10).
2. **Scope:** one `owner/repo` per grant, per host, adopted issues only, no wildcards, never global. A repository added later starts empty. Order: throwaway repository (name unset, OA-19), then `IronbellyOrg/IronClaude` after that run passes.
3. **Expiry:** end date always stored. 30 days throwaway, 90 days real, 90 maximum. After it the write refuses and says "expired on <date>".
4. **Owner sentence (one chat sentence):** `Grant issue.comment and issue.status.move on <owner/repo> for adopted issues, <30|90> days.` The tool refuses "all" or "everything" in a grant.
5. **Recording:** only a session the owner opened and types in; never a worker, never a script-started coordinator (leans on OA-6, still unnamed). It says "Received" once. Before S14: one ledger line (SEC-14), headed "decision only, not enforced by code, not an active grant", and no real-repository sentence. From S14: `repos grant` writes grant id, date, repo, entries, end date, the owner's quoted words and the recorder into `<config dir>/issue-watch.d/<name>-grants.json`, beside the approvers file, under the SEC-10 verb refusal and Write/Edit hook. The owner writes no file.
6. **Reading:** every write re-reads the file, no cache. Missing, unreadable, malformed, unknown entry, wrong repo, past end date, repo not enabled, or issue not adopted means no grant. Each use is logged with the grant id (SEC-07).
7. **Revoke:** `Revoke <entry> on <repo>` or `Revoke all on <repo>`. Newest line wins and a revoke wins a tie; it bites at the next write and needs no accepted-record check (it only narrows). An agent may suspend an entry at once after a wrong write if it says so in chat; only the owner re-enables it. S13 adds `repos revoke`.
8. **Completion rule:** a succeeded run needs both entries; a failed, blocked or partial run needs only `issue.comment`. If that comment is refused, the local escalation must show the failure so it is not hidden.
9. **Refusal (printed before any `gh` call, no issue text echoed, SEC-16):** `Refused: no standing permission "<entry>" for <owner/repo> (none recorded, expired on <date>, or revoked). Nothing was written to issue <N>. To allow it the owner says in chat: "Grant <entry> on <owner/repo> for adopted issues, <30|90> days." A local escalation was recorded.`
10. **Spec edits (about 1.5 hours, estimate, about eight table rows):** SEC-07 and OA-11 wording to two entries now plus one later (the plan says three in some rows and four in others); FR-83 last sentence to the per-outcome rule; one home for the grants file; WORKER-CONTRACT lines 302-303 ("that issue's grant row") reworded with the owner's chat approval (OA-7). Land before S14 so tests pin expiry and the file.

**Benefits:** the coordinator posts a result and moves to In review with no owner round trip; each permission has a user, an end date, a log entry and a one-line off switch; a typo cannot stop the poll. **Risks (narrowed, not closed):** the login `ironbelly` is shared, so any session can claim the owner said it (SEC-09) and a coordinator shell can run `gh` directly as the admin login; comments and Status moves on a public repository are world-readable and appear as the owner, and edit history survives a revoke; before S14 nothing refuses; an expired grant makes the coordinator refuse (safe but visible). **Costs (estimates):** owner about 1 minute per sentence; recording about 15 minutes; build 5 to 7 hours over S14 (A's basis) up to 8 to 12 hours if counted whole (my basis); spec edits 1.5 hours; contract review 0.5 hour.
