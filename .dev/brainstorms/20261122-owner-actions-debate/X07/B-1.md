## 2 Still rejected (with the evidence I checked)
1. **"No expiry by default" (A).** A fears results stop quietly. That is answered without dropping expiry: a refusal is a local escalation the owner sees, and the grant verb prints the end date. I keep an end date because the login is shared and the repository is public, so a permission nobody remembers should end by itself. The plan's no-clock choice for the merge go (OA-13a) is a per-PR go, a different thing. I move from 30 to a 90 day default and a 180 day maximum. These numbers are my judgment, not measured.
2. **Grants as a key in the per-repo config (A, SPEC SEC-10).** On master the loader lists its allowed keys (`_TOP_KEYS`, `cycle.py:59-70`, no `grants`) and `cycle.py:223-226` turns any unknown key into `config_invalid`. The plan is also split: SPEC line 176 puts `grants` under the state folder, line 299 puts it in the per-repo config, and DECISIONS line 244 asks for "the grants file" outside the orchestrator's write reach. I hold the separate file: `<config dir>/issue-watch.d/<name>-grants.json`, beside the approvers file, under the same SEC-10 verb refusal and Write/Edit hook.
3. **Completion needs both entries even for a failed run (SPEC line 243 last sentence).** The same row says failed, blocked or partial runs get a comment only. A refusal on the status entry would then hide a failure. A did not address this; I keep it: failed outcomes need only `issue.comment`, succeeded needs both.

## 3 Revised proposal (the one I would sign)
1. **Entries:** two, `issue.comment` and `issue.status.move` (Status to In review only, only from the allowed Statuses, never Done). Not granted: `issue.assign`, `issue.body.append_plan_sections` (until S15c), `pr.merge`, `issue.close`, `issue.hold`.
2. **Scope:** one `owner/repo` per grant, per host, adopted issues only. Order: the S17 throwaway repository (name UNVERIFIED, OA-19), then `IronbellyOrg/IronClaude` after the throwaway pass.
3. **Expiry:** an end date is always stored. Default 90 days, maximum 180 days, no "forever". After it the writes refuse and name "expired".
4. **Owner sentence:** `Grant issue.comment and issue.status.move on <owner/repo> for adopted issues, 90 days.` The tool refuses "all" or "everything" in a grant.
5. **Recording:** only a session the owner opened and types in (never a worker or a script-started coordinator; this leans on OA-6, still unnamed). It says "Received" once. Before the verb exists, it appends a decision line to the ledger (SEC-14). From S14 `repos grant` stores grant id, date, repo, entries, end date, the owner's quoted words and the recorder in the grants file.
6. **Reading:** each write re-reads the file with no cache. Missing, unreadable, malformed, unknown entry, wrong repo, past end date, repo not enabled, or issue not adopted means no grant. Each use is logged with the grant id (SEC-07).
7. **Revoke:** `Revoke issue.comment on <repo>` or `Revoke all on <repo>` (revoke may say "all"). A revoke line wins a tie and bites at the next write. An agent may suspend an entry after a wrong write if it says so in chat; only the owner re-enables it.
8. **Refusal:** `Refused: no standing permission "<entry>" for <repo> (none recorded, expired on <date>, or revoked). Nothing was written to issue <N>. To allow it the owner says in chat: "Grant <entry> on <repo> for adopted issues, 90 days." A local escalation was recorded.`
9. **Spec edits:** SEC-07 to two entries plus the rules above; SPEC line 243 to the per-outcome rule; WORKER-CONTRACT lines 302-303 ("that issue's grant row") reworded in the FR-84 amendment, with the owner's chat approval (OA-7).

**Benefits:** the coordinator can post a result and move to In review with no owner round trip; every permission has a user, an end date and a log entry; a typo cannot stop the poll. **Risks (narrowed, not closed):** any session on this host can claim the owner said it (SEC-09); before S14 nothing refuses; the coordinator's own shell can run `gh` as the shared admin login regardless; public text stays in edit history after revoke; the expiry chore means one sentence per repo per 90 days. **Costs (estimates):** about 1 hour spec edits, 8 to 12 hours build at S14 (about 10 tests and 150 lines; I did not measure Clay's parser), 1 to 2 hours revoke verb, 1 hour adopted-issue check, 0.5 hour contract review; owner about 1 minute per sentence.
