## 3 Alternatives rejected
- **Record as a rule breach (B.3 "Yes").** No rule existed; public blame text; Clay is the only other active maintainer (`IB-JonathanB` has authored and reviewed nothing, `VERDICT.md:36`); D16 itself says an unaccepted rule turns the ruleset into "a dispute at the merge button" (`VERDICT.md:69`, A-003). Highest risk to the one thing X03 needs, Clay's acceptance.
- **Accept with no record and no interim rule (B.3 "No" as written).** Fails safe the wrong way: leaves the 66-minute pattern unanswered and sets PR 700 as a precedent that a reviewer reading the plan could quote.
- **Revert or hold PR 700.** Re-removes code that PRs 701, 705, 707 and others now build on; high regression risk for no gain.
- **A public comment on PR 700 or an issue naming it.** Permanent, searchable, blames by name, and it is a GitHub write the owner has not authorised.
- **A written apology demand or a probation period for Clay.** Not in D16, adds an unmeasured cost, and no source shows it changes behaviour.
