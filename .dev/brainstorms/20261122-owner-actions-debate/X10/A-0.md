# X10 (OA-20) Flip WORKER_BINDING_PROVEN: Agent A, round 0, Pragmatic lens

Terms. "The guard" is the hook script `launch-level-guard.sh` that blocks a bound session's commit, push, merge and implement calls. "W" is guard level `worktree` (plan only until released). "Binding" means the guard is attached to a coordinator-started worker, through a `pending/<nonce>` record plus a `[sc-launch:v1:<nonce>]` marker in the worker's first prompt. "Claim route" is a session launched by `/sc:issue --claim`. "Worker route" is a session the coordinator starts with `worker-start`. All facts below were read on origin/master after `git fetch origin` on 2026-11-22 unless marked UNVERIFIED.

## 3 Alternatives rejected
- Flip now on the claim-route evidence: the constant and the worker route are unbuilt and unobserved (RK-1 High).
- Re-run all twelve 442 observations first: most already PASS; the rest do not bear on level W.
- Require the ruleset (OA-5) before the probe: the probe runs on a disposable issue and writes nothing to master. I require it before the first REAL issue instead (section 5), where it buys protection.
- Owner chat sentence flips it with no pull request: the plan wants a reviewed commit (D05 item 3, SPEC.md:583), and the commit is one line.
- A config key or environment variable as the switch: rejected by the design text cited above; an agent could set it without review.
- Run one real issue unbound with the owner's OK (repeat the G1 exception): D05 item 1 says the guard is required, staged, not exempted.
- Make a second human (Clay) a required reviewer: the owner is the only admin and merges; agents and owner share the login, so a second reviewer is a quality check, not a security boundary. I offer Clay as an optional reader of the probe record.

## 4 Implications, benefits, risks, costs
Benefits: RK-1 is retired early by a real run instead of at the end of S17; the flip is one reviewed line with a failing-test speed bump; real issues stay off until the evidence exists; rollback is one commit setting the constant back to False.
Risks (state them in the PR body; the proof is "honest drift at level W", not a security boundary):
- The guard is text-only. A script run (`bash ./push.sh`), a push to `integration` or another default branch, a new session id, and tools outside the hook matcher pass (INV-034, INV-019, INV-003 in `debates/D05/VERDICT.md:22`). A worker script pushing a feature branch is recorded as not stopped (INV-025, SPEC.md:706).
- The launch account is also an approver: agents and owner share the login `ironbelly`, which is admin. Binding cannot stop a worker that uses that login. Only a server ruleset on master and integration (OA-5, SPEC.md:579; "admin bypass for PRs only", effect UNVERIFIED until the ruleset throwaway test FR-77) or a separate agent login (OA-6) can.
- The proof ages: a new Claude Code, guard or Orca version can change hook behaviour. Mitigation: P7 records versions and hashes; rerun P1 to P4 (about 1 hour, estimate) when they change.
- The 60 second consume time and the hook 5 second limit behaviour are unobserved (D05 Unverified list).
- The coupling test checks a text file; it slows a careless flip, it does not stop a determined one.
Costs (estimates, basis: the 2026-11-21 OB-H2 observation took about 1 hour 04 minutes wall time, 02:32 to 03:36 UTC, per the issue 691 comment; the worker route has more steps): probe 2 to 3 hours agent time; record and flip PR with `/sc:pr-submit --monitor 3` about 1.5 hours; optional docs PR for the 2026-11-21 results about 1 hour; owner time: two chat sentences, one summary read (about 10 minutes), one merge go. Disposable issues 712 to 715 already exist (OPEN), so no new GitHub writes besides comments and a throwaway pull request.
