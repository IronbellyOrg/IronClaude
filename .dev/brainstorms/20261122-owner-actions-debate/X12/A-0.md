## 2. Why this is best
- The plan already asks for this: FR-70 (SPEC.md 327) "own worktree or keep `max_in_flight` 1; real rollout stays off until the X-001 live check ... is recorded and the owner picks the route". RK-7 (line 651) is High, with the controls "real rollout off; cap 1; OA-23".
- The defect is real in code: `launch_argv` puts every claim agent in one worktree; debate D07 item 8 (`debates/D07/VERDICT.md` line 22) and probe finding INV-004 (HIGH) say it breaks "one worktree holds one live agent".
- `claim_by` exists only in the spec (git grep on origin/master finds no `claim_by`); S17 excludes `claim_by: coordinator` (SPEC.md line 503). Today the poll route is the only route there is, so the check decides whether it needs a fix, not which of two built routes to use.
- Running first beats waiting: Coder 516 is OPEN with no work started (`gh issue view 516 --repo IronbellyOrg/Coder`), so an amended 516 costs a wording change, not rework.
- The check is mostly reads: its only writes are the claim's own (assign, two comments) on a throwaway issue.

## 3. Alternatives rejected
- Build a separate claim worktree now, without a check: a 516 change and a config key on a guess. The check costs about an hour and may show no change is needed.
- Choose `claim_by: coordinator` now: unbuilt, needs the coordinator build (S14), and the plan defers it (line 503). It also makes every claim depend on a live coordinator.
- Run X-001 only inside S17: S17 waits for S14 to S16 and Coder 515 and 516, so a bad result would land after 516 is built. I keep a one-claim re-check in S17 on the real 516 worktree, because my stand-in may differ from it.
- Use the 24-hour dry run as the check: a dry run launches nothing (SPEC.md line 501), so it cannot show a lingering terminal.
- A one-time manual `orca agent launch` of the same argv: skips the poll's real path, so it could miss launch-time and record-keeping effects.

## 4. Implications, benefits, risks and costs
- Benefit: OA-23 is answered from a record, 516 is fixed before it is built, and the S17 pass list gets its X-001 line early.
- Cost (estimates, basis: the step list above; nothing measured): stand-in worktree and two throwaway issues 30 min; two claims plus four observation points about 60 min of wall clock (15 min of it is the P3 wait, twice); writing the record 20 min; drafting the 516 text 20 min. About 2 to 2.5 hours of agent time. Owner time: two chat sentences. Each claim uses model tokens (amount UNVERIFIED).
- Risk: two samples prove little and cover cap 1 only; raising the cap needs its own check (SPEC.md line 503). Mitigation: the rule takes the worse of the two claims.
- Risk: GitHub writes on a throwaway issue under the shared login `ironbelly`, so owner and agent cannot be told apart there. Mitigation: the owner's two chat sentences are copied into the record.
- Risk: a hand-made `Coordinator` may differ from what Coder 516 builds. Mitigation: the S17 re-check.
- Risk: Clay's hold on 516. Mitigation: this proposal only drafts 516 text; it posts nothing without the owner's go, and the owner or an agent tells Clay.
- Risk: the throwaway repo may not exist; creating one is a GitHub write that needs the owner's chat OK (OA-19 and the S17 throwaway-repo step, not decided here).
