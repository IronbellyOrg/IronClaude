## Remaining Disagreements

All are amendments to V1's text, not rival designs. None changes a resolution type.

1. **INV-002, nonzero exits after the first call (vs V1R3:23).** V1 treats every nonzero exit as `unavailable` and stops all Orca reads. I keep that rule for the first call only and add `call_failed` for later calls without the `runtime_unavailable` token. If the owner prefers V1's simpler rule, the only cost is completeness: one failed row turns the rest of the sweep disk-only. Safety is the same under both.
2. **INV-003, "complete" against "scanned" (vs V1R3:24).** Without my wording, the truncated page that V1 itself introduces at V1R3:31 lets an unjoined transcript become idle or Historical. I consider this a correctness gap in V1's text, not a style choice.
3. **INV-001, reasoning only.** Same requirement text plus one sentence for "binding found, then Orca lost". I disagree only with V1's use of INV-004 as a reason, because INV-004 applies with `--run` too.
4. **INV-008, the status template.** I propose `--untracked-files=normal` in the one status call. V1 names the config hole as a limitation instead. The override behaviour is UNVERIFIED here; the owner or the real-git control test decides.
5. **INV-017, citation only.** V1's binary rule stands. The record should say it deliberately departs from orca-cli SKILL.md:27 for safety, not that the skill says "never bare `orca`".
6. **V3R2:16 still prefers exit 0 for an outage without `--run`.** V2 no longer holds that position (V2R2:81 is superseded by this file). If V3 keeps it in Round 3, the owner decides; only the exit code for that one case differs, and the INV-002 predicate is the same either way.
