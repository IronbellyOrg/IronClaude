The owner should restore `agent-work-report` from the archive branch in a later owner-reviewed pull request, as two commits: first a byte-identical restore the owner can check with one diff, then the amendments the plan already requires (person-neutral config and a safe local page server). ## 5. Costs and risks of restoring, and how to contain each

**R1. The page server serves the whole state folder, and a security finding was open at merge.** `page.py:308` `ensure_server()` starts `python -m http.server 8765 --bind 127.0.0.1 --directory <state_dir>`; `page.py:326` shows the `--directory` argument is the state folder, not one file. The tech reference (line 799) lists what is in it: "`settings.json` with ClickUp user and DM channel ids, `action-log.jsonl`, run folders". The Codex security review of PR 684 (comment `4637549094`, P2, rated Medium in the summary and the only one of its five advisory findings not marked Resolved) says the server "accepts the rebound `Host` and exposes all of `.dev/coordinator/`, not just `report.html`" and advises "Validate Host, require an unguessable token, and serve only the generated page." Binding to 127.0.0.1 stops the local network but not DNS rebinding or another local account, as that finding says. Also, the page "loads Google Fonts" (tech reference line 799). *Containment:* this is a must-fix in the restore PR (commit 2), not a later item. Serve a scratch folder that holds only the generated `report.html`, reject any `Host` other than `127.0.0.1:<port>`, and add a test that a request for `settings.json` and for a directory listing fails. Either self-host the font or drop it. The owner should not accept commit 2 without that test.

**R2. Person-specific values ship to every install.** `config.json:2` is `"person": "clayphi"`, `:3` `"person_name": "Clay"`, the orgs are `IronbellyOrg` and `IronbellyGroup`, the time zone is America/Chicago. 36 lines of `SKILL.md` mention Clay (`grep -c -i clay`), and its description starts "gather all of Clay's open work". `superclaude install` copies skills to `~/.claude/skills/`, so another user's session would be offered a skill whose description matches "what's on my plate" and whose config reports Clay's work. `SKILL.md:36` calls the config "Code, not a file Clay edits". *Containment:* FR-46 in commit 2: a per-user config in the user's own config folder, no person, ClickUp id or org list in shipped files, neutral description, and the test that issue 718 D3 already names ("a test shows no `"person"` or ClickUp ids in shipped config").

The daily run has side effects the sweep and observer rules forbid on those surfaces.** ClickUp DM, typed text in an Orca terminal, an Orca tab, a model-run git commit (tech reference line 799, items 1 to 6).
