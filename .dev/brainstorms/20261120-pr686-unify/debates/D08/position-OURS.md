# D08 position paper: OURS (the owner's line): one word, "coordinator"

Topic: naming and identity of the primitive (session role, command, and how issues 339, 423, 444 and Clay's design nest). Status: stub, filled below.

Written as the strongest honest case for the owner's line. Evidence paths: "master" = /home/coder/.cache/ic-snap-20261120/master (origin/master 61ac2c2e6); "ZS-REQ" = /home/coder/workspaces/worktrees/IronClaude/claim-handoff-planb/.dev/releases/backlog/issue-watcher-zero-setup/requirements.md; "D:nnn" = docs/designs/orchestrator.md on master.

## Claim

The session role has one name: **coordinator**. The command and skill that put a session into that role are `/sc:coordinator` and `sc-coordinator-protocol` (the command does not exist yet, so nothing has to be renamed). The word "orchestrator" is kept only where another party owns it: Orca's own layer name (`orca orchestration`, the `orchestration` skill) and the titles of issues 339 (the owner's epic asking for one session that manages all sessions), 423 (Orchestrator v2, a knowledge layer) and 444 (evaluate a sub-orchestrator mode). Those titles are left alone and a glossary says "orchestrator in an issue title means the coordinator role or the program around it". Clay's per-repo issue-polling session is a coordinator of a particular kind (script-woken, with grants), not a new kind of thing.

## Mechanism

One genus noun lets every installed rule that already says "coordinator" apply or be narrowed by name, instead of two nouns that leave the rules silent about the second. `WORKER-CONTRACT.md` section 4 binds "the coordinator"; a script-started coordinator is added to that section as a named case (which is what Clay's own addition ADD1, D:135, already does when it writes "standing-grant coordinator"). Qualifiers carry the differences, not new nouns: "project coordinator" (one per project, session `COORD-<RepoName>`), "sub-coordinator" (issue 444's `--sub`, evaluation only), and "report session" for Clay's daily report session, which stops being called a coordinator.

## What it costs

- A rename inside Clay's merged design text and open code: the design file has 759 uses of "orchestrator" and PR 686 adds about 640 occurrences (1816 against 1179 in src and tests, counted over the two snapshots); most are prose or local variable names. The persistent identifiers are listed in fact 8. These are mechanical edits on a PR that is unmerged and a design doc whose disposition D14 decides.
- Issue titles 339, 423 and 444 keep "orchestrator" until the owner renames them (no GitHub write is allowed here). A glossary line in the spec and in `HOW-WE-WORK.md` covers the gap.
- Clay's report session is called `coordinator` in a live tag and two automations (D:714); keeping the genus word for the role means that session needs a different name ("report session"), or the tag stays and specs never call it a coordinator.

## What it risks

- Reading "everywhere" too widely: R10 sits in a row about the watcher worktree name, and the primary issue text was not read. If the owner meant only the branch, worktree and session name, the command name is still open. Even then the fact 5 and fact 2 arguments carry the command name without any owner decision.
- A single noun can hide the authority difference between a person-opened coordinator and a script-started one. The mitigation is named qualifiers in `WORKER-CONTRACT.md` section 4, not a second noun.

## What it gets right

- One word is already used by the platform, the installed contract, the routing guide, the sweep, the owner's decisions and Clay's own spec lineage.
- It removes a collision with 63 installed files rather than adding to it.
- It costs almost nothing today because the command and skill are not built.
- It gives issues 339, 423 and 444 a place in one family without rewriting any of them (see the nesting table in the verdict).
