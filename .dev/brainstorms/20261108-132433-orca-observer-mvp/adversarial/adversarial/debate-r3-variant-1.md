# Round 3 Final Arguments: Variant 1 (opus:architect, A Signal Bridge)

## Final Position

**The human selection of the visual direction must be restored as owner decision 1 and as a hard gate before production integration.** The issue's acceptance criterion ("A human selects the visual direction before production integration", issue #409, restated in `../seed-brief.md` line 69 as "the issue requires a human selection before production integration") is a requirement on *who* decides, not on *what* is decided. Three advocates agreeing, or two of three, cannot satisfy it, however good their reasons. All three variants had it as decision 1 (`variant-1-opus-architect.md` line 207, `variant-2-opus-analyzer.md` line 193, `variant-3-haiku-backend.md` line 127). It dropped out of the Round 2 S-008 list, and my own Round 2 S-008 stance (`debate-r2-variant-1.md` line 123) signed off on that list without noticing. That was my error.

What the debate did produce is a **recommendation** to the owner, not a decision. C-001 should be worded as follows in the merged plan:

> **Default screen: RECOMMENDATION, pending owner decision 1 (visual direction).** Advocates recommend (2 of 3): A's worker ledger with the `COUNTS (source-reported)` strip and B's one-line question-source gap notice as the default while no question row can be interpreted. From the first release whose QUESTION-OBSERVATION gate passes, B's attention ledger becomes the default and A's ledger is one key away as the fleet view. C's decision desk is a later view behind the QUESTION-LINK gate. Dissent (V3): once links verify, C's desk may be the better complete composition. The owner may choose this sequence, a single direction (A, B or C), or a different post-link default. The choice is recorded before production integration (gate DIRECTION-SELECTED). Advocate agreement is not a substitute for it.

Architecture argument for why this costs nothing: S-010's seams (`SourceResult`, a pure `View(snapshot, width)`, one atomically published view) mean the direction is a choice of view module and a default key binding. The adapter, model, retention, sanitizer and tests do not depend on it. So the gate can sit late (before production integration) without blocking R0 engineering. It must not be skipped either.

The rest of my position stands as in the Round 2 consensus (`convergence-r2.md` lines 83-133), with these final changes:
- **INV-020 (HIGH, ADDRESSED) is carried into the merge text.** `check --all --run <runId> --json` is a *candidate* R2 verb, not a settled one (`convergence-r2.md` line 96 states it as settled; that sentence is reworded). The QUESTION-OBSERVATION gate must show, from recorded samples: (a) whether `--run` actually narrows `--all` (the help says `--all` returns "every message for the handle", `../seed-brief.md` line 38), using a sample with at least two Runs; (b) which handle receives human-addressed messages; (c) a measured message rate set against the rotation period, so that rate times period stays under 100 rows. All three are UNVERIFIED today.

**Why that is not enough.** The walkthrough is listed only as a tie-breaker for V3's post-link dissent, not as a required, recorded selection. Nothing in the release table gates production integration on it. A plan that leaves it out can pass every engineering gate and ship a default screen no human picked. INV-019 is right, and its HIGH rating is right: the issue's own acceptance criterion would fail at review.

5. **Optional, the owner's call:** a second confirmation at the QUESTION-LINK gate for the post-link default (B or C) only. That is the one sub-choice where evidence that does not exist yet (explicit-link rows) changes what the options mean.

## Response to MEDIUM Invariants

The 14 UNADDRESSED MEDIUM rows from `invariant-probe.md`, one line each. "Accept fix" means the fix goes into the merged plan as written here.

- **INV-002, accept fix.** A value whose own-clock timestamp moves backward is never silently dropped. The row shows `conflict (time went back)`, detail keeps both readings with their `liveness.source` and `resource.recoveryAttemptCount`, and only a strictly newer value on the same clock and source replaces silently. Test: a fixture where the timestamp goes backward with a changed `liveness.source` renders the conflict.
- **INV-003, accept fix.** Pin a short required set against the redacted golden sample: top-level `result`, `result.workers` (array), and `result.page.total` and `result.page.hasMore`. Only these make a cycle `FAILED (shape)`, which keeps the last-good ledger marked STALE. `result.counts`, `result.scope.source`, `result.warnings` and every `projection.*` field are optional four-state facts. A missing count renders `unavailable`, never `0`. Test: drop each optional field in turn; the ledger still renders and no `0` appears for the dropped field.
- **INV-004, accept fix (the most important MEDIUM row).** Three layers, all before `subprocess` is reached, which is called with an argv list and no shell:
  1. Every flag token must exactly equal a flag in that release's template (allow by exact match, not "not in the forbidden set"). An alias, abbreviation or unknown option therefore fails closed whether or not Orca's parser expands abbreviations (UNVERIFIED). The forbidden set (`--ack`, `--wait`, `--retry-request`, plain `check`) stays as a second, never-shrinking check, and it matches by prefix as well as by whole token.
  2. Values taken from Orca output are format-checked. `runId` must match `^[A-Za-z0-9][A-Za-z0-9._:-]{0,127}$`, so it cannot start with `-` and cannot contain whitespace or control characters. This regex is PROPOSED: tighten it to the format seen in the golden sample, which is UNVERIFIED. `nextCursor` is opaque, so it gets `^[A-Za-z0-9._:=+/-]{1,1024}$`, no whitespace or control characters, plus the existing repeat/missing guard.
  3. Values are bound to their flag in one token: `--run=<runId>` and `--cursor=<value>`, if Orca's parser accepts the `--opt=value` form (UNVERIFIED: check it with one recorded call per flag at the R1 gate). If it does not, a value that starts with `-` is rejected: for a cursor, fall back to the pages already read plus `PARTIAL`; for a runId, mark the source `FAILED (unsafe value)`, with the sanitized value shown in detail. An end-of-options `--` does not help here, because these are option values, not positional arguments; whether Orca supports `--` at all is also UNVERIFIED, so the design does not rely on it.

  Test: a fake runner that fails the test if it is reached, fed runIds `--ack`, `-a`, `--wai`, `x --ack`, `x\n--ack` and `--run=y`, and a cursor starting with `--`: zero subprocess calls, and the expected source state for each.
- **INV-005, accept fix.** The strip shows T from the last page read, labelled `reported T (page k)`. If `page.total` changed during the traversal it shows `reported T1-T2 (changed during read)`. A finished traversal (`hasMore=false`) with n not equal to T shows `collected n / reported T (mismatch)`. A page with `workers=[]` while `total > 0` ends the traversal as `PARTIAL (empty page k)`. Each case is a fixture test.
- **INV-007, accept as risk, with disclosure.** No filter that keeps active rows ahead of released ones is verified in today's help. Add an UNVERIFIED item: "does `worker-list` offer a state or active filter?", checked against `--help` at the R1 gate; adopt it only if it is listed and recorded. Until then the PARTIAL line reads `oldest rows not read; long-running active workers may be among them`. This is the recency bias the issue describes, made visible rather than solved.
- **INV-009, accept fix.** The rotation set is every Run with at least one non-historical row in the latest worker read, plus every Run that holds a retained open question. Historical-only Runs are left out, with a disclosed count. Runs that may sit beyond the page cap are covered by the PARTIAL line, `Runs beyond page cap not read`. An empty rotation set renders `message source not read this cycle (no Run in rotation)`, never an empty list under a verified source.
- **INV-013, accept fix.** The strip rule is stated per width range, not per breakpoint: the strip is present at every width of 80 columns or more. Tests run at 80, 81, 115, 116, 117, 143, 144, 159, 160 and 200, which include the built 144 branch. Under 80 columns the screen shows `terminal too narrow (min 80)` above the strip, and the strip's denominators still print.
- **INV-014, accept fix.** The strip has a priority order: `collected n / reported T`, `PARTIAL` and scope are never truncated. At narrow widths the strip wraps to a second line before anything is cut, and `>` applies only to the lower-priority tokens (source age, the `unavailable (no source)` token). In the 44-row height contract the strip is one of the minimum rows and is never dropped.
- **INV-015, accept fix.** My own `View(snapshot, width)` feeding "Live screen | text export" (`variant-1-opus-architect.md` line 103) caused this. The fix: one view model, two renderers. `render(view, W)` is width-bound and uses `>`; T23 and T24's `cell_len <= W` applies only to it. `export(view)` is a record form (`key: value`, one field per line, full IDs and values, wrapped rather than truncated), and has its own test that every ID in the fixture appears whole.
- **INV-016, accept fix.** Restore NO_COLOR to the consensus as my T14 has it (`variant-1-opus-architect.md` line 192): any non-empty value, including `yes`, disables colour; unset or empty allows it. Add a harness run with a colour system enabled, in two parts: with NO_COLOR set, no colour segments appear; and the plain text of the coloured render equals the plain text of the NO_COLOR render, so no meaning is carried by colour alone. `color_system=None` alone cannot catch either failure.
- **INV-017, accept fix.** The exposure unit must match the read unit. Bodies of terminals that are not opted in are dropped at parse time in the adapter. They are never held in the model and never written to `--once` export; only metadata stays (ID, type, time). If the message rows carry no field that names the terminal (UNVERIFIED), the opt-in becomes per Run, and the opt-in prompt says so plainly.
- **INV-021, accept fix.** Two runtime rules. (a) The default view is picked once at start-up from the runtime state of the question source: if it has not succeeded in this process, start on A with the gap notice, even in a release whose gate passed. The view never switches automatically mid-session, because that would move the human's place. (b) The B ledger header reads `read k of N Runs since start; oldest among Runs read` until every Run in the rotation set has been read once. If the question source fails at runtime (shape drift, exposure not granted, every Run in backoff), the ledger title shows `question source FAILED` or `STALE` and keeps the retained rows.
- **INV-022, accept fix.** A defined procedure per admitted verb, recorded as a gate sample. Before and after one call of the verb under test: (1) `check --peek` unread message IDs for the same scope (verified non-consuming), and (2) `worker-list` lease, liveness and `observedAt` values for the dispatches in scope. The verb passes when the after-reading equals the before-reading, apart from new arrivals identified by ID. Help text alone never passes the check.
- **INV-023, accept fix.** Restore a cycle budget equal to the interval (15 s). The per-call timeout times the calls in a cycle must fit inside it; if it does not, fewer pages are read and PARTIAL is shown. The source reads STALE after 3 intervals (45 s) with no successful `worker-list`, counted on a monotonic clock. Ages are computed on the monotonic clock; wall-clock time is used only to print `HH:MM`. An overrun cycle is shown as `cycle overran (Ns)`, and the next cycle starts immediately after it, under the single-flight rule.

ADDRESSED MEDIUM rows, for the record: INV-008 stands (`unknown (no question source)`). INV-025 is closed with `unknown (retention exceeded)` (see Final Position).
