## Proposed rulings for UNADDRESSED HIGH and MEDIUM findings

| ID | Proposed ruling (at most 40 words) |
|---|---|
| INV-001 | The Orca probe, prompt build and worktree origin check all run before the `pending` write. Once `pending` is written, the only outcomes are `launched`, `unknown` or `abandoned`, and `failed` never follows a `pending` write. |
| INV-002 | A non-zero Orca exit after the spawn, including a definite error body, is `unknown` with the slot consumed. A's C-011 phrase "definite Orca error gives retryable `failed`" is withdrawn. |
| INV-003 | `--retry-launch` runs only on `unknown` with an operationId, after the C-009 re-read and the origin check pass. It runs at most once per cycle and three times in total, never increments `launches`, and gives `abandoned` when exhausted. |
| INV-004 | `unknown` with an operationId becomes `abandoned` (`retry_exhausted`) when its retries run out and `claimed` when an own marker appears. The lease never drives a transition. |
| INV-005 | `once --dry-run` takes the lock, performs every read, and reports each transition and launch it would make. It leaves the store, backoff and rate-limit times byte-identical and never calls Orca. |
| INV-006 | A cycle with several outcomes exits with the first applicable code in the order 6, 5, 3, 4, 7, 2. Only exit 0 refreshes `last_completed_cycle_age_seconds`. |
| INV-008 | An issue is eligible only when the latest approval `labeled` event postdates the latest trigger `labeled` event. A trigger re-added after approval needs a fresh approval. |
| INV-009 | Event and comment pages are read until a page returns fewer than 100 items. A repeated event ID, or a full page at the call cap, makes the read incomplete. The latest event is the one with the highest event ID. |
| INV-010 | Before launch, the approving actor's current repository role is verified as triage or higher (endpoint access UNVERIFIED). Otherwise the issue is skipped as `approver_not_current`, and the call counts toward the 35-call cap. |
| INV-011 | The origin check compares a lowercased `owner/repo` parsed the same way as `origin_repo.py`, never the raw URL. It runs again immediately before every Orca spawn and every `--retry-launch`. |
| INV-012 | `once` checks `DISABLED` again immediately before each `pending` write and each `--retry-launch`. If the file is present, it starts nothing further, records the cycle and exits 0. |
| INV-014 | Discovery adds `--assignee <own login>`, so the 100-result limit counts only issues assigned to the own login. The C-004 exact-assignee-set check still runs locally. |
| INV-015 | The store keeps `last_examined_at` per issue, set for every examined candidate including `budget_exhausted` and `revalidation_failed` skips. Candidates run oldest first, and `max_candidates` becomes 5 to fit the 33-call remainder. |
| INV-016 | The day cap counts every entry whose `pending` write time falls within the last 24 h, in any state. A launch is refused when that count is already 6, and `--retry-launch` adds nothing to the count. |
| INV-017 | Each `gh` and probe call times out at the lesser of its configured value and the time left before the 240 s deadline. A launch already started is never cut short, and its record is written before exit. |
| INV-018 | Project membership means exactly one item in the configured Project node ID whose Status option is Backlog, read over all `projectItems` pages. Other Projects are ignored. No matching item, or several, skips the issue as `project_mismatch`. |
| INV-019 | `once` exits 2 before any `gh` call when the approver file is missing, empty or unsafe, so a misconfigured watcher never reports a healthy cycle. |
| INV-021 | A claim marker is `claimed` evidence only when its comment was created or last edited after the current approval event. An older marker leaves the issue eligible. |
| INV-024 | `init-state` records `created_at`, and `once` treats an approval event older than it as not approved. A store re-created after loss never re-dispatches earlier approvals; the owner re-applies the label to re-arm an issue. |
| INV-026 | An issue is eligible only if its body and every comment were created or last edited before the approval event, read over all pages (GraphQL `lastEditedAt`, UNVERIFIED). Otherwise the issue is skipped as `edited_after_approval`. |
| INV-027 | No verb deletes or replaces `<state_dir>/lock`. The lock is taken on a file that `init-state` creates, and `check-config` rejects a state directory that is not on a local filesystem. |
