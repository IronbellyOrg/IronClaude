# Invariant Probe Results
## Round 2.5 — Fault-Finder Analysis

Reconstructed consensus used for this probe (from consensus-round2.txt and the round-2 vote tables and resolutions): `/sc:git` = command plus `sc-git-protocol` skill with refs and a mirrored read-only skill script (S-008, S-009); operations status (bare default), add, commit (`--message` or `--smart-commit`), branch list/create/switch, cleanup as a route to `/sc:worktrees` only, submodule status/update/commit-pointer; no push, pull, merge or `--interactive` (C-001, C-002, X-002, X-003). Between-task commits only with a person-typed `--commit-tasks`, checked once per run, recorded as a `run` line in `commits.md` after Wave 0 step 6, revocable, refused for other origins (X-001, A-003). Boundary after the `complete` line (or after the whole batch) and before the next Q0, plus R0 reconcile and L0 before FINAL (C-005). Sidecar `commits.md` with `prepared` before `git add` and a terminal line after; boundary key and trailers; Q0 and reviewed-tree pins kept until the terminal line; a boundary pin; no ledger grammar change (S-011, C-010, C-011, X-004). Person's edits kept out by per-path `foreign-change` against the Q0 pin plus equality with the last reviewed tree, `git commit --only`, `--literal-pathspecs` (C-008, C-021). Hooks never bypassed; `pre_tree` comparison; pinned plan/source hash re-check; no automatic retry (C-009, X-007). Commit set = `files=` union plus the run's own package directory, all `.dev/tasks` staged (X-005). Submodules: one level, fast-forward-only update, pointer commit needs a clean module and remote-tracking containment, never recursive, never fetch (C-015, X-012, X-013, X-014). Protected set = master, main, integration plus `origin/HEAD` when it resolves (C-017).
