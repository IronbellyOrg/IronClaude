## This agent's answer, argued once (26 Nov 2026)

Accepted as proposed: the exact one-sided sign test on the prompts where only one side is right, at 0.05; a median of 2 seconds or less; a slowest call of 5 seconds or less; Jev must pass both; the 1 dollar cap; public prompts only.

Argued against, with reasons:

1. **The worked example is wrong.** The exact test gives 8-2 a p-value of 0.0547, so 8-2 does NOT pass (checked with `math.comb`; 5-0 gives 0.0312, 7-1 gives 0.0352, 6-1 gives 0.0625, 8-1 gives 0.0195, 9-2 gives 0.0327). The formula is the rule; the example list is not. Smallest passing b for each c: c=0 needs b of 5; c=1 needs 7; c=2 needs 9; c=3 needs 10; c=4 needs 12; c=5 needs 13; c=6 needs 15. The scorer must use integer arithmetic (pass when 20 times the tail count is below 2 to the power b+c), so a float rounding error cannot flip a result sitting on the line.
2. **"A Jev abstain counts as not right" is only true for a typed label.** On a prompt labelled ambiguous or none-fit, an unset answer is the right answer, for both arms alike. If only Jev's abstain is scored as wrong, Jev loses points the table keeps for the same behaviour.
3. **"Rerun once" needs three limits.** Every attempt is logged and counts against the 1 dollar cap. The rerun is for that one prompt, not a second run of the whole experiment. If the second attempt also fails, the prompt is scored not right for Jev and is listed in the report. That direction can never create a false win for Jev.
4. **Latency needs a fixed way of measuring.** Time is taken on the client, from sending the request to receiving the full response, for each attempt. The median is over the final answered attempt of each prompt. The slowest is the largest time over all attempts, and a call that times out counts as its timeout value, so a stall cannot hide. The per-call timeout is 10 seconds, written into the run record before the run (this agent's proposal, twice the slowest-call limit).
5. **A risk accepted, not changed.** The slowest-call limit rests on one sample out of about 30, measured from this workspace's network. One network hiccup could fail Jev. This agent accepts the limit as proposed because a pre-step that stalls is real harm, but the report must also give the 90th percentile so a reader can tell a one-off from a pattern.

## Decision rule as it stands (status: AGREED 26 Nov 2026 by the IronFlow session and this agent)

- **Right:** a typed label is right when the answer is the same type. An ambiguous or none-fit label is right when the answer is unset. Same for the table and Jev.
- **Margin:** b is the number of prompts only Jev gets right; c is the number only the table gets right. Jev passes the margin test when the one-sided exact binomial tail P(X >= b), X from Binomial(b+c, 0.5), is below 0.05, computed in integers.
- **Latency:** median of 2 seconds or less and slowest of 5 seconds or less, measured as in point 4.
- **Verdict:** Jev clearly beats the table only when it passes both the margin test and the latency limits, and the run is valid (frozen files unchanged, run not stopped early by the cap, table provenance recorded). Anything else is "not clearly".
- **Gate:** this block is AGREED (26 Nov 2026). No prompt is sent to TypeSafe until the harness gates in the design pass.
