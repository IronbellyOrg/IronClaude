# Rendering rules

One view model, three views over it (A Signal Bridge, B Attention Ledger, C Decision Desk), a detail inspector and a text export, in two data modes: `fixture` (the package's synthetic fixtures) and `live` (`worker-list` only).

- **R0** renders A, B and C at 160, 116 and 80 columns, each marked "synthetic fixture, not live evidence", with realistically degraded versions beside them (input to DIRECTION-SELECTED).
- **R1 onward** builds the owner-selected view. Recorded owner decision 1: R1 = A's worker ledger + COUNTS strip + B's one-line question-source gap notice; B after QUESTION-OBSERVATION with A's ledger one key away; C only behind QUESTION-LINK. The B screen below is the post-QUESTION-OBSERVATION view, and its degraded form is used for the owner's R0 comparison.
- **Start-up rule (INV-021):** the view is picked once at start-up from the runtime state of the question source. If the question source has not succeeded in this process, the observer starts on A with the gap notice, even in a release whose gate passed. The view never switches automatically mid-session.
- **Prototype (X-001):** the design-package prototype is a visual reference only; no production import. Its 116-column collapse claim does not match the built prototype, so width rules come from the Round 2 consensus (A's width matrix, B's x/width coordinates, C's 44-row height contract). The sources name these three artifacts but do not define their contents; only the values copied below are specified, the rest is UNVERIFIED and an open question (`SPEC.md`).

## Geometry and height

- At 116 columns or more B draws the full frame with `right = width - 43`. From 80 to 115 it uses the single-column narrow layout. Under 80 every view shows `terminal too narrow (min 80)` above the COUNTS strip, and the strip's denominators and the question-source gap notice still print.
- Height follows C's 44-row height contract (drop order, minimum rows). Coverage, scope, `PARTIAL` and the question-source gap notice are minimum content, kept ahead of every optional panel; if height cannot hold them a too-small diagnostic shows instead, and it still carries the gap notice. No per-panel scrolling, no multi-pane focus.

## Common to every width

- **Header line 1:** `ORCA OBSERVER  mode=fixture|live  scope=<result.scope.source or "scope unknown">  as of <local time of last good poll>`. Fixture mode always reads `SYNTHETIC FIXTURE <variant>, not Orca data`. With R2 questions on there is no rotation set, so no `read k of N Runs since start` is shown for messages; the question panel states `one Run only: <runId>` (below). CONTRADICTION (for worker reads): the source's adapter scope-honesty rule (`adapter-contract.md`), T45 and the risks table put this token in every header; which applies is an open question (`SPEC.md`).
- **Header line 2, freshness strip (from A):** one cell per source: `worker-list OK 4s` / `STALE 52s` / `FAILED (exit 2) 1m` / `NOT POLLED`. A second cell `messages UNVERIFIED (not read)` stays unless R2 questions are on (QUESTION-OBSERVATION passed and `--questions` given), when it reads `coordinator questions: one Run, last read <age> ago`. The strip is collection freshness; evidence freshness (`evidence.lastObservedAt`) is shown per row as a plain age, never merged into the source cell. When `result.warnings[]` is non-empty the strip adds `source warnings: n (inspector)`, and the inspector lists the sanitized warnings.
- **Before the first successful poll:** the header reads `as of never`, the COUNTS strip reads `collected unknown / reported unknown`, and the ledger area reads `no successful worker-list read yet`; never an empty fleet or `0`.
- **COUNTS strip (source-reported), every width of 80 or more:** numbers and denominators only, no bars, no health name. Tokens: `collected n / reported T`, `PARTIAL` when it applies, the scope, `source counts: active a / reclaimable r / retained t / released l` (from `result.counts`, never summed with page-derived counts), `SETTLED unavailable (no source)`, `FROZEN unavailable (no source)`, `cost unavailable`. `collected n / reported T`, `PARTIAL` and scope are never truncated. At narrow widths the strip wraps to a second line before anything is cut; `>` applies only to lower-priority tokens (source age, the `unavailable (no source)` tokens). It is a minimum row and is never dropped.
- **Keys (inspection and local filtering only):** Up/Down or `j`/`k` move, `Enter` opens detail, `Esc` returns, `/` local text filter, `h` show/hide historical rows, `m` mark a look, `e` write an export, `q` quit. No `r` key: refresh runs on the fixed 15 s cycle. No key maps to an Orca call.
- **Footer:** the key list plus `shown x/y | collected n / reported T`.
- **Historical rows:** rows with historical `terminalState` (only the values `released` and `retained`; that they mean historical is UNVERIFIED, `unverified-register.md`) are hidden by default. A row whose `terminalState` is absent or any other value is shown with its raw value (absent reads `unknown`), never hidden and never counted active. Hiding shows a visible `k historical hidden (h)`; `h` shows them; the toggle never changes source counts; historical evidence explicitly linked to a shown item is never hidden. They are never deleted from the snapshot.
- **Selection** is anchored to identity, never a row index. Worker rows: source namespace + `dispatchId`. Questions (after QUESTION-OBSERVATION): a verified source-scoped question identity, never a worker `dispatchId`. A reordering refresh keeps the cursor on the same identity; if it disappears the cursor stays on `selected <id> no longer in source window` until the user moves, never jumping to another worker.
- **Truncation:** list cells truncate by display-cell width with a visible `>`. Non-UTF-8 terminals use `--ascii`, which replaces box drawing with `+-|`.
- **Detail inspector (Enter):** every field untruncated, wrapped by cells: `dispatchId`, `taskId`, `runId`, `resource.worktreeId`, `resource.ownerDispatchId`, `resource.originDispatchId`, `projection.host.id`, `projection.workspace.id`, and `projection.stage.{worker,dispatch,activity,detail}` (sanitized, labelled `worker-reported`; the only place `stage` renders). Absent reads `unknown (absent in source)`.

## Worker ledger (A; the R1 view)

- One row per worker from `worker-list`, in source order: `dispatchId`, run (labelled "run", never "orchestrator"), `workerState`, `dispatchStatus`, `terminalState`, `projection.outcome` (raw), `projection.nextAction.kind`, `liveness.verdict (liveness.source)`, evidence age. There is no `stage` column at any width; `stage` is in the inspector.
- **`projection.nextAction.kind` is verbatim.** Absent or blank reads `unknown`. Never classified, executed, ranked as an action list or called a question. May be used as a labelled local filter.
- Above the ledger, at every width, the gap notice: `Human questions: source UNVERIFIED, 0 rows interpreted, not "no questions"`. Exact strings by place: this gap notice above the ledger (every view); B's live question-panel block `Question rows: source UNVERIFIED. 0 rows interpreted. This is not "no questions".`; anywhere else the question area reads the shared core `source UNVERIFIED, 0 rows interpreted, not "no questions"`.
- At 116 columns: `<kind> <dispatchId> <liveness.verdict> <age>`, with `stage` moved into the inspector. At 80 columns: `kind`, a dispatch ID cell-truncated with `>`, and an age.

## Attention Ledger (B)

- **160 columns.**
  - Left `COORDINATOR QUESTIONS` (x=1, width 114; fixture and live R2 title; the earlier title `OPEN HUMAN QUESTIONS` is retired because Orca has no human recipient field). Fixture: one block per question (`NN MIN`, the question, `requester requests / owner`, `Affected: id, id`), oldest first. Live before QUESTION-OBSERVATION, or with questions off: `Question rows: source UNVERIFIED. 0 rows interpreted. This is not "no questions".` After the gate, with `--questions`, the title carries `bounded best effort; coverage unknown; at most 100 rows per read, not 100 questions; bursts over 100 rows between reads may be lost`.
  - Left lower (live only): the worker ledger with verbatim `nextAction.kind`, titled `worker-reported, not questions`; it replaces the base's separate "next actions" proxy panel.
  - Right top `SEEN IS NOT RESOLVED` (x=117, width 42): big count of observed open questions; sub-line `closed by evidence: unavailable` (R2 lists questions without individual selection or marking, so there is no `marked looked` split for questions; `m` marks worker rows only and never changes the question count). Live with no question source: `unknown (no question source)`, never 0.
  - Right lower `RETAIN CONTEXT` (design reference; not built in R2, where only the one-Run panel below is shown): seven retained attributes (original question, original age, acting owner, requesting orchestrator, affected stable IDs, source coverage, explicit closure evidence), each with its availability live, e.g. `original question: UNVERIFIED source`, `acting owner: resource.ownerDispatchId (worker-list)`, `explicit closure evidence: unavailable (no source)`.
- **On start (live, R2):** question retention is in memory for this process only, so the question panel shows `retention reset at HH:MM; questions observed before this start are not retained`.
- **Coordinator questions panel (R2, one Run only; PROPOSED layout; updated 2026-11-12 with the owner's decisions).** One stacked block at every width of 80 columns or more; the two-column layout above is design reference / R3 (QUESTION-LINK), not built in R2. Lines, in this order up to the state line (the order after it is PROPOSED):
  - Title `COORDINATOR QUESTIONS`; line `one Run only: <runId>`.
  - The first state line, always: `question read: OK 3s` | `question read: STALE 50s` | `question read: FAILED (consumer-fenced) 3s` | `question read: FAILED (no-active-terminal) 3s` | `question read pending`. `STALE <age>` after 45 s without a good question read on the monotonic clock, with retained questions kept.
  - Under FAILED or STALE: `list as of HH:MM:SS (last good read)`. For the two fence codes also the sentence `this terminal does not hold the named Run; the observer never binds to a Run` and then `start the observer in the terminal that holds <runId>` (the observer's inference from the error code, marked inferred, not an Orca message).
  - The counts line `seen, not resolved: <n> | closed by evidence: unavailable (no source)`. A window of exactly 100 rows: `seen, not resolved: 100+ (window full) | closed by evidence: unavailable (no source)`. Retention exceeded: `seen, not resolved: unknown (retention exceeded) (retained 1000)`. The word "seen, not resolved" is the SEEN IS NOT RESOLVED wording; "observed open" is retired.
  - The standing caveat `no read marker in source: answered questions stay listed`.
  - The disclosure, verbatim: `bounded best effort; coverage unknown; at most 100 rows per read, not 100 questions; bursts over 100 rows between reads may be lost`.
  - One line per question, oldest first: `<age>  [no longer in source window]  <subject>  reason unknown`. The bracket part appears only when the question left the read window. Only the subject is ever clipped, so the state word is never cut. No verified reason field exists, so `reason unknown`; the body is never shown. Lines are listed, not selectable; `m` marks worker rows only.
  - When the list is cut to fit the screen the oldest stay (oldest first) and the screen says so: `questions shown 7 of 20 (oldest first; 13 newer not shown; e exports all)`. The worker ledger keeps `workers shown 2 of 4`. On a short terminal the questions win over the worker ledger: the ledger is squeezed first.
  - Empty good read: `no observed questions in this source window; not proof none exist`, never `no questions`. If retained rows exist and the latest read returned none: `latest read returned 0 questions; the rows below are older`.
  - `window full: older questions may be missing` when a read returned exactly 100 rows. `retention reset at HH:MM; questions observed before this start are not retained`.
  - Header freshness cell: `coordinator questions OK 0s (one Run <runId>)` / `STALE 50s` / `FAILED (consumer-fenced)` / `not read yet`.
  - On a screen too short for the panel (also the too-narrow or too-small diagnostic line) the panel is one line: `coordinator questions: seen, not resolved <count text>; <state>; one Run only: <runId>; best effort, coverage unknown`. The count text is never a bare number: an empty read says `0 (source window only; not proof none exist)`, a full window `100+ (window full)`.
  - The gap notice stays while the question source has not read; the panel replaces it once the source has read or failed.

  There is no rotation, no `revisit ~Ns` token and no empty-rotation-set line. Other places in this file that still say `observed open: n` (the 100-row cap and Question area bullets) are superseded for the R2 panel by this paragraph; they are left as written until the spec owner re-words them.
- **116 columns.** Same structure with `right = 73`; question panel 70 wide; right column stays 42; ledger in its 116-column line form.
- **80 columns.** Single column: header, freshness strip, COUNTS strip, `SEEN IS NOT RESOLVED n`, question lines (fixture) or the UNVERIFIED notice (live), then the ledger in its 80-column form. The invariant lines stay: "Questions stay until explicit resolution." and "No reply observed is not delivery failure." RETAIN CONTEXT is reachable only through the inspector.

## Changes since last look

The first observation in a process is the baseline; a restart discloses that a new baseline was taken. `m` records an observer-local mark in memory for this process only. Every row added, removed or changed in `stage` (which `projection.stage.*` subfield is an open question), `nextAction.kind` or `liveness.verdict` since the mark shows `*` and counts in `changed since HH:MM (k)`. Rows on pages not read this cycle read `not reobserved`, not "unchanged". Marking never changes the open count.

## Unknown, stale, partial

- **Four states per fact:** `known`, `unknown` (source omitted it), `unavailable` (no verified source exists), `stale` (not read successfully within 3 intervals). An aggregate with unknown members is `n+? (k unknown)`. Unknown is never zero or false.
- **Absent field:** literal `unknown`, muted (plain under NO_COLOR); never `0`, `false`, `-` or blank. A source-given value that is itself the text `unknown` or `UNKNOWN` renders quoted (`"unknown"`), so it is never confused with an absent field.
- **Separate facts:** `workerState`, `dispatchStatus`, `terminalState`, `projection.outcome` are separate raw values. Report status, acceptance, tests and human approval read `unavailable (no source)`. `terminalState=released` is never "done". Help text: "a completed Task can still own a live terminal".
- **Stale:** STALE after 3 intervals (45 s at 15 s) with no successful poll, on a local monotonic clock; wall-clock time only prints `HH:MM`. The cell reads `STALE <age>`; values keep their last reading with `as of HH:MM:SS`. Source loss never closes a question, changes the open count or turns a value into `failed`. A failed poll shows `FAILED (<exit code or timeout>) <age>` with sanitized stderr in the inspector.
- **Collection vs evidence freshness:** source STALE depends on poll success only; a worker's evidence age is a plain age, with no per-row STALE until Orca's timestamp cadence is measured.
- **Partial pages:** if `page.hasMore` is still true at the call cap: `PARTIAL: collected n of reported T (newest first; oldest rows not read; long-running active workers may be among them)`. Derived counts state denominators, e.g. `nextAction present: 17 of 300 collected (reported 412)`. T comes from the last page read: `reported T (page k)`. `page.total` changing mid-traversal: `reported T1-T2 (changed during read)`. Finished traversal with n not T: `collected n / reported T (mismatch)`. `workers=[]` with T above 0 ends as `PARTIAL (empty page k)`.
- **Filtered vs global:** a filter always shows `filter <expr>: k of n collected` beside the unfiltered `source counts: ...`; source counts are a different scope (terminal accounting) and never summed into "workers".
- **Overflow:** `x/y shown`; `+N more` counts only rows not shown, never the selected visible row.
- **100-row cap:** (a) `worker-list` returns at most 100 rows per page and the observer follows `nextCursor` up to the call cap. (b) If the R2 message template (`check --all --types question --run <runId> --json`) is admitted at QUESTION-OBSERVATION, the question panel title reads `at most 100 rows per read, not 100 questions; older history not available`; a retained question that leaves the window stays open with `no longer in source window (last seen HH:MM)`; exactly 100 rows read shows `window full: older questions may be missing`.
- **Question area:** before QUESTION-OBSERVATION `source UNVERIFIED, 0 rows interpreted, not "no questions"`, no number; no count is ever derived from `result.count`. After the gate, with R2 questions on: `seen, not resolved: n` (unique Run plus `message.id`; no total is ever taken from `result.count`) and the Coordinator questions panel above; there is one Run, so no rotation and no per-scope `revisit` token.
- **Seen is not resolved:** the big count is observed open questions, or `unknown (no question source)`. `m` marks worker rows only and never changes the question count (questions are listed, not individually selectable, in R2). `closed by evidence` reads `unavailable` until a closure source exists. No key, timer or source loss lowers the open count; only explicit closure evidence, not available in the MVP. No verified source records explicit closure today, so every retained question renders `open, closure source unavailable`; it is never shown as resolved and never quietly dropped.
- **Empty states (T33):** with no message source the question area carries the gap-notice wording above, never `no questions` (the source's T9 and empty-state rule also use `0 rows interpreted (contract UNVERIFIED)`; this spec uses the source's Change 28 question-area wording everywhere for one consistent string); `worker-list returned 0 workers in scope=bound` names the scope; fixture `empty` renders `no observed items in this source window; not proof none exist`.
- **Cost and tokens:** `cost unavailable`, never `$0`; no progress bar from tokens or activity.
- **SETTLED and POLICY FROZEN (T34):** live both read `unavailable (no source)`; in fixture mode a frozen item keeps a `FROZEN` marker no other state overrides.

## Deliberately left out

| Left out | Why |
|---|---|
| Any operational control (approve, retry, terminate, spawn, merge, rebase, delete-worktree, worker instruction, reply) | No write path into Orca; the design package's mock-up action buttons are not built. |
| Plain `check`, `--ack`, `--wait`, `--retry-request` | Plain `check` and `--ack` consume a delivery; `--wait` is a listener on the bound Run's FIFO. Forbidden set never shrinks (`adapter-contract.md`). |
| Parsing `check --peek/--all` or `inbox --json` rows before QUESTION-OBSERVATION | Row fields UNVERIFIED; `check --all --types question --run <runId> --json` is the one candidate verb, behind the gate (status: not passed). |
| Live question age, requester, owner | They exist only in message rows; `lastObservedAt` is an observation time, not a question open time. |
| C's affected-session ledger before QUESTION-LINK | Needs authoritative question-to-dispatch-to-worktree joins; cross-host joins not established. |
| Fleet SIGNALS bars | No verified mapping from `workerState`/`outcome` to "settled"; the COUNTS strip is shown instead. |
| Deleting historical rows | Hidden behind `h` with the count always shown; never deleted from the snapshot. |
| `r` refresh key | Would add a second polling path; `m` takes its place. |
| `--include-remote` | No verified cross-host ownership join; off until R4. |
| Persisted "last look" | No agreed retention or location; session memory only. |
| Complete message history, cost/usage, admission, revision-pinned verification, durable replay, deep links | Not established; never presented as available. |
| Windows keyboard input | The stdlib reader is POSIX-only; on Windows `--once` prints a text export. |
| Mouse, themes, blinking, animation | Out of scope; no blinking is a constraint. |

## A and C strengths (input to the owner's selection)

- **A is stronger on day-one live data:** every A panel except the request panel fills from `worker-list` today, and A answers "is the fleet alive?" at a glance. Weakness: a single request slot (`_request` in `signal_bridge`) repeats the recency bias #409 complains about; its 116- and 80-column builds drop SIGNALS; the prototype does not match the brief's collapse claim (X-001).
- **C is stronger once a question is chosen:** answers "who is affected, and what is the evidence?" and ships the most honest overflow line, `x/y other questions shown`, which B copies. Weakness: needs both unverified contracts at once, and defaults to `requests[0]`, so the first question depends on UNVERIFIED source order. Hence C only behind QUESTION-LINK.
- **Dissent (V3):** once explicit-link rows exist, C should be the post-link composition. Two of three advocates recommend B as the post-link default. Not settled; the optional owner re-confirm at QUESTION-LINK exists for this choice.
- **B's own weakness:** if the message contract never verifies, B's headline panel stays empty and the product is A with different labels; then A is the better MVP.
