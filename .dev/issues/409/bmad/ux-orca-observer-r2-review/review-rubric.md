# Spine Pair Review — Orca Observer (R2 coordinator questions)

Reviewed: `DESIGN.md` and `EXPERIENCE.md` in this folder (copies of the 2026-11-08 spines, status draft). Reviewed against the release 2 design: `spec-orca-observer/rendering-rules.md` (Attention Ledger (B), Unknown/stale/partial), `release-gates.md`, `adapter-contract.md`, `src/superclaude/cli/observe/view.py` (`_questions_panel`, literals at :52-69), `render.py` (`_panel_lines` :297, `screen_lines` :318), `tests/observe/test_render.py` :412-610, and real renders in `/tmp/r2render/out.txt` plus a second run of `/tmp/r2render/render2.py` (pure STALE, long subject with left-window, 100 rows at h=16, fenced at h=14, NO_COLOR). Nothing was changed. Findings tagged **[R2]** concern the new panel or its screen fit. Spine line numbers are those of the copies in this folder.

## Overall verdict

The pair is still a sound, well-cited R1 contract (tokens complete, section order correct, required sections present), but it is NOT a usable R2 contract. Everything about questions (release table row B, screens 5-6, B geometry and shrink order, the SEEN IS NOT RESOLVED / RETAIN CONTEXT components, the `m` and Enter behaviour, UJ-5, the glossary) still describes the retired two-column "OPEN HUMAN QUESTIONS" Attention Ledger with rotation, a view switch and selectable questions. The built panel (single stacked block, one named Run, listed not selectable) has no Key Flow, no component row, no state row and no shrink rule in either spine. The panel itself also has screen-fit defects the spines should settle: its status suffix is clipped on long subjects, its collapsed one-line summary drops the 100-row caveat, hidden (newest) questions cannot be reached on screen, and the ledger gets one row fewer than its own budget promises. Run an Update on the question parts before any story work on R2.

Open decisions for a human are marked **Open question**.

## 1. Flow coverage — broken

Checked: every PRD journey (UJ-1 to UJ-5, prd.md:65-69) has a Key Flow with protagonist, numbered steps, climax and failure path; then whether R2-relevant flows exist and use the new design.

### Findings
- **[critical]** **[R2]** UJ-5 "Find the oldest question (B, then C; gated)" describes the retired design (EXPERIENCE.md:479-490). Step 2 opens `OPEN HUMAN QUESTIONS` with `SEEN IS NOT RESOLVED`; step 3 selects a question and presses `Enter` for an inspector with RETAIN CONTEXT; step 4 presses `m` to move it to `marked looked`; the failure path says the observer opens on the R1 ledger with the gap notice and stays there for the session (INV-021). Move the select/inspect/affected-session steps to an R3 flow under QUESTION-LINK.
- **[high]** **[R2]** No Key Flow for a coordinator question arriving and being read. The most important event for the supervisor is "a new question appeared". The 15 s cycle adds a line and raises `observed open: n`, but nothing marks it as new: the `changed since` / `*` machinery covers worker rows only (EXPERIENCE.md:355; rendering-rules.md:49). In a long list the new question is the newest, and the window keeps the oldest (`7/20 shown`, render.py:215 `lines[:keep]`), so it can be off screen. *Fix:* add a flow "A coordinator question arrives" with climax, plus the failure path "the list is longer than the screen". **Open question:** does the owner want a new-question cue (a count `k new since HH:MM`, or newest-first when cut)? The spec says oldest first.
- **[high]** **[R2]** No flow for the question source failing or being fenced. The panel has real, distinct paths: `FAILED (consumer-fenced)` and `FAILED (no-active-terminal)` with the sentence `this terminal does not hold the named Run; the observer never binds to a Run` (view.py:60); `STALE <age>` with retained questions; a question that left the window; the process restart (`retention reset at HH:MM`). None appears as a flow or failure path. The supervisor's recovery action (run the observer in the terminal that holds the Run) is only in adapter-contract.md:61. *Fix:* add failure paths to the arrival flow, each ending in the exact on-screen words and the one action the supervisor can take outside the observer.
- **[medium]** **[R2]** UJ-1 steps 3 and 5 (EXPERIENCE.md:437, :439) and its failure path assume the `messages UNVERIFIED (not read)` cell and the gap notice. With questions on the strip reads `coordinator questions: one Run, last read 0s ago` and the gap notice is replaced by the panel once the source is OK or FAILED (render.py:364, view.py:673). *Fix:* add a "questions on" variant to UJ-1 step 3/5, or state that UJ-1 is the questions-off path.

R2 can show the oldest question but cannot inspect it (no selection, no inspector, evidence links are R3). Does R2 satisfy UJ-5 in part, and should the spine say so? A human decides; the spine must not claim inspection in R2.
- **[low]** **[R2]** The R0 owner-review walkthrough (EXPERIENCE.md:492-498) steps through "B" fixtures. The fixture B is two-column with blocks (`NN MIN`, `requester requests / owner`, `Affected:`; rendering-rules.md:38), while live R2 is a stacked panel with one line per question. Two different B shapes now exist. *Fix:* say which one the R2 contract is (the live panel) and that the fixture is a design reference.

## 4. State coverage — thin

### Findings
- **[high]** **[R2]** State vocabulary and view-level tables contain no question-panel rows. Add the exact strings: `question read pending`; `STALE <age>`; `FAILED (consumer-fenced)` / `FAILED (no-active-terminal)` plus `this terminal does not hold the named Run; the observer never binds to a Run`; `observed open: unknown (no question read yet)`; `no observed questions in this source window; not proof none exist`; `window full: older questions may be missing`; `<subject>  reason unknown  no longer in source window`; `retention reset at HH:MM; questions observed before this start are not retained`; `x/y shown`. - **[high]** **[R2]** The collapsed summary hides the honesty disclosure. When the panel does not fit, it becomes `coordinator questions: observed open 100; read OK; one Run only: run_14cfcbd8edf2` (116x16 render; `observed open 20` at 160x14). - **[high]** **[R2]** A long subject hides the status suffix. Question lines are `age  subject  reason unknown  [no longer in source window]`, clipped at the end (render.py:309 `clip`). At 116 the suffix reads `no lo>`; at 80 columns the whole suffix and `reason unknown` are cut (`... should wait f>`), so the one flag that says "this question may be gone" is invisible. *Fix:* clip the subject, not the tail: put the flag in a fixed prefix or reserve the suffix cells. - **[high]** **[R2]** Questions beyond the window cannot be reached on screen, and the hidden ones are the newest (`lines[:keep]`, view.py:215). With no selection and no scroll there is no key to see the rest; only `e` exports all questions (export.py:106-118). `Enter detail` in the footer does nothing on a question. *Fix:* **Open question** for the owner: add a scroll key for the panel, or show newest-first when cut, or at minimum make the cut line say `7/20 shown, oldest first; 13 newer not shown (e exports all)`. The spine must state the chosen rule in Interaction Primitives and Focus.
- **[medium]** **[R2]** FAILED always wins over STALE. After a fence, the panel stays `FAILED (consumer-fenced) 50s` and never becomes STALE although 45 s has passed with retained questions (the `stale view` render). The age on FAILED is time since the last good read, not since the failure (view.py:574-592), and a first-read failure has no age. Spec rendering-rules.md:43 lists STALE after 45 s; EXPERIENCE.md:283 has the combined PROPOSED form `STALE <age>, last poll FAILED (<reason>)` for worker-list only. *Fix:* use the same combined form for questions, or state the precedence and the age meaning.
- **[medium]** **[R2]** Height budget. (a) The spine's 44-row budget (EXPERIENCE.md:144-157), minimum-12-row rule and shrink order (:159-163) have no panel rows. The panel base is 6-8 rows (title, run, disclosure x1-2, counts, retention, plus state lines) before any question. (b) The code promises "at least 3 ledger rows stay" (render.py:371-373) but the `x/y shown` line is not budgeted: at 116x24 and 80x24 with 20 questions the ledger shows `2/4 shown +2 more`, and at 116x40 with 100 rows it also shows 2 of 4. (c) The panel takes 17 of 24 rows while the worker ledger, the R1 core, gets 2. *Fix:* budget the cut line; add the panel to the shrink order. **Open question:** which block wins when height is short, the ledger or the questions? A human decides.
- **[medium]** **[R2]** The panel replaces the gap notice after a FAILED first read (`replaces_gap = qstate in ("OK","FAILED")`, view.py:673; the `no-active-terminal first read` render has no `source UNVERIFIED` line). EXPERIENCE.md:58, :233 and :383 say the gap notice stays "until QUESTION-OBSERVATION passes and the question source has succeeded in this process". The panel's FAILED line plus `observed open: unknown (no question read yet)` is honest, so the spine is the part that should change. *Fix:* restate the rule: the gap notice stays until the source has been read or has failed; PENDING keeps both.
- **[medium]** **[R2]** `observed open: 100` with `window full` printed 20 lines below it (116x40 render, after `22/100 shown`). The count reads as exact, not as "100 or more". Spec says `observed open: n` (rendering-rules.md:62). *Fix:* **Open question** (spec wording): `observed open: 100+ (window full)`, or place `window full` on the counts line.
- **[medium]** **[R2]** Per-question closure text. rendering-rules.md:63 says every retained question renders `open, closure source unavailable`. The built lines carry neither; only the counts line says `closed by evidence: unavailable (no source)`. The spec is also inconsistent: :43 says `no longer in source window`, :61(b) says `no longer in source window (last seen HH:MM)`; the build follows :43. *Fix:* the spine should adopt one string for each; **Open question** for the spec owner.
- **[low]** **[R2]** In `tests/observe/test_render.py` :412-610 I found no screen-level test for a pure STALE panel, for `no-active-terminal`, or for the collapsed summary at 14-16 rows. These states render correctly in my runs, but nothing pins them.
