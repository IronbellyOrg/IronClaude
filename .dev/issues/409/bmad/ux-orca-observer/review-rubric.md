# Spine Pair Review — Orca Observer

## Overall verdict
The spine pair is a usable contract: every YAML token resolves, every colour is hex, every UJ has a protagonist, numbered steps, a climax and a failure path, and the binding owner decisions (R1 scope, later B/C, read-only, PROPOSED numbers, open questions) are applied consistently. Five real defects remain. UJ-1's timeout failure path contradicts T5. The shrink rule drops the never-dropped gap notice. The T50 fixture label is missing. FR-16's per-cycle snapshot is reduced to an on-demand export. The ledger has no column that can satisfy T20's 'each naming it' worktree rule. Visual-reference hygiene is thin: imports/ is empty, the design-package source path does not resolve from the repo, and no spines-win-on-conflict line exists.

## 1. Flow coverage — adequate
UJ-1..UJ-5 and the DIRECTION-SELECTED review task from extract-prd.json (prd.md:65-69, 463) and the FR-1..FR-18 / NFR-1..14 list, against EXPERIENCE.md Key Flows. Each was checked for protagonist, numbered steps, climax and failure path. Failure paths were spot-checked against prd.md:181 and acceptance-tests.md:12 (T5).
### Findings
- **high** (blocking) The UJ-1 failure path says that when 'the poll times out three times in a row' the freshness cell turns to `STALE 52s` and 'Nothing becomes failed'. The sources say a timed-out call shows `FAILED (timeout)` (prd.md:181, T5 in acceptance-tests.md:12). 'Never turned into failed' in rendering-rules.md:53 is about values, not the source cell. The spine also never says which word wins when a source is both failed and past 45 s with no success. (EXPERIENCE.md § Key Flows > UJ-1 Fleet glance (R1) failure path; § State Patterns > State vocabulary (stale / failed rows)). *Fix:* Rewrite the failure path so each timeout shows `FAILED (timeout) <age>` and values keep `as of HH:MM:SS`. Add one precedence rule for the freshness cell when FAILED and STALE both apply. If the sources do not decide it, mark the rule PROPOSED or carry it as an open question.
- **medium** (blocking) FR-16 (prd.md:86, 235) requires a versioned JSON snapshot written by `export(view)` on each R1 cycle (snapshot-export-schema.md 'Envelope (one per cycle)'; SPEC.md CAP-10). The spine instead attaches the JSON snapshot only to the `e` key and `--once`, and never mentions a per-cycle write. A consumer following the spine would never write the snapshot on its own. (EXPERIENCE.md § Information Architecture > Screen inventory row 4; § Key Flows > UJ-4 Export step 2). *Fix:* Separate the record export (`e` / `--once`, T27/T48) from the per-cycle snapshot (FR-16). State where and when the snapshot is written, or carry its destination with UX-OQ-4.
- **medium** The R0 owner-review flow leaves out the walkthrough task that the source makes the core of the review: 'find the oldest question and inspect its evidence' (prd.md:463, release-gates.md:9). The climax jumps straight to recording a direction. (EXPERIENCE.md § Key Flows > R0 owner review). *Fix:* Add a step where the reviewer performs the walkthrough task on each direction's fixture render before recording the selection.
- **low** The R2/R3 labels that FR-17/FR-18 require are missing from the B/C flow and screens: 'bounded best effort; coverage unknown; at most 100 rows per read, not 100 questions' (rendering-rules.md:37) and 'affected scope unknown' (FR-18). (EXPERIENCE.md § Key Flows > UJ-5; § Information Architecture rows 5 and 7). *Fix:* Add the two labels to the UJ-5 steps and failure path. They are later-release requirements, so a one-line mention is enough.

Give the status line a partialColor and a warnColor. Name the colour of the under-80 notice and the vanished-selection row.

## 3. Component coverage — adequate
Every component name in the DESIGN.md YAML and Components table, and every component in EXPERIENCE.md Component Patterns, IA and State Patterns. Each was checked for a visual row and a behaviour row.
### Findings
- **medium** `{components.status-line}` has a DESIGN row but no EXPERIENCE Component Patterns entry. Its behaviour is spread across the IA, State Patterns and Export: it holds the partial sentence, cycle overrun, new baseline, export result and filter count. There is no rule for which item wins when several apply on one line. (EXPERIENCE.md § Component Patterns (missing 'Status line'); DESIGN.md § Components 'Status line'). *Fix:* Add a Status line pattern with its content list, priority order when items compete, and the fold-into-footer rule from the shrink order.
- **medium** `fixture-state-marks` (settledColor, frozenColor) is defined in the YAML but has no row in DESIGN.md § Components and no behaviour rule in EXPERIENCE.md. The fixture FROZEN marker 'no other state overrides' (rendering-rules.md:63) is not specified anywhere in the spines. (DESIGN.md frontmatter components.fixture-state-marks; § Components; EXPERIENCE.md § Component Patterns). *Fix:* Add a Components row and a behaviour line: fixture-only, the FROZEN marker overrides other states, and live mode shows `unavailable (no source)`.
- **low** The names drift between the files. EXPERIENCE calls the gutter component 'Row gutter', while DESIGN uses 'Selected row' and 'Change mark'. EXPERIENCE has an 'Export' pattern with no DESIGN row. The filter prompt in the footer has no visual spec. The B/C components (OPEN HUMAN QUESTIONS panel, SEEN IS NOT RESOLVED, RETAIN CONTEXT, question inspector, Decision Desk) have no rows, even though R0 renders B and C. (DESIGN.md § Components; EXPERIENCE.md § Component Patterns). *Fix:* Use one component name in both files. Add one line saying that B/C component specs are deferred and that R0 renders them from the design-package exports.

## 4. State coverage — adequate
IA screens 0-8, with R1 screens 1-4 checked in depth. Screen 1 states: loading, empty, partial, stale, failed, binary missing, overrun, filter, historical, changes, fixture, under-80, too-small. Screen 2 states: absent field, stderr, vanished worker. Screens 3 and 4: success, failure, `--once`. Screen 0: navigation and variants.
### Findings
- **medium** (blocking) This is a contradiction about which rows are never dropped. 'Rows that never drop' lists header, freshness, COUNTS, the gap notice and the footer, and the gap-notice pattern says it shows 'in every view and at every width'. DESIGN's diagnostic shows 'the rows that are never dropped'. Shrink-order step 4 says the too-small diagnostic 'keeps the header, freshness, COUNTS and footer lines', which leaves out the gap notice. (EXPERIENCE.md § Responsive & Platform > PROPOSED shrink order step 4). *Fix:* Add the gap notice to step 4, or say 'keeps every never-dropped row'.
- **medium** (blocking) T20 / prd.md:148 require two sessions that share a `worktreeId` to show as two rows, 'each naming it', and a session with no worktree to show `worktree unknown`. The ledger columns at every width (rendering-rules.md:29, mirrored in the Width bands table) contain no worktree field. The spine repeats 'A missing worktree reads `worktree unknown`' without saying where. As written, the ledger cannot satisfy T20. (EXPERIENCE.md § Component Patterns > Ledger; § Responsive & Platform > Width bands). *Fix:* Say where the worktree is named (for example, in the inspector only, with T20 checked there), or raise the column-list versus T20 tension as a new UX-OQ.
- **medium** The discovery probe has no state. The probe is a one-time `skills list --json` check that validates the binary before the first cycle (prd.md glossary, NFR-9). The spine covers 'binary missing' but not 'binary found, probe failed', for example the wrong `orca` (github.com/orca-cli/orca). (EXPERIENCE.md § State Patterns > View-level states (R1)). *Fix:* Add a probe-failed row with the freshness-cell wording, or mark the wording PROPOSED.
- **medium** Three states are underspecified. (1) In the UJ-3 failure path the inspector 'keeps its last values' after the worker leaves the source window, with no notice on the inspector, so it shows values that are no longer current without saying so. (2) The inspector says nothing about STALE or FAILED source state or `as of`. (3) `--once` has no failure state (poll failure or write failure with no status line, exit code). (EXPERIENCE.md § Key Flows > UJ-3 failure path; UJ-4 failure path; § Component Patterns > Inspector). *Fix:* Add an inspector notice line, for example `no longer in source window, values as of HH:MM:SS` (PROPOSED). Specify the `--once` failure output and exit code, or mark it PROPOSED.
- **medium** Fixture gallery (screen 0) is the first deliverable, but its interaction is unspecified. Its keys are not in the keyboard table, and it is not said how the reviewer steps through A/B/C x 160/116/80 x variants (27-case matrix, FR-1), or whether the gallery is an interactive screen or a set of byte-identical text renders (T6). (EXPERIENCE.md § Information Architecture row 0; § Interaction Primitives > Keyboard model). *Fix:* Add a gallery column or a short section: how a frame is chosen (keys or files), and the frame label.
