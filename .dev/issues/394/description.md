# Description given to /sc:issue --create

Hook that mechanically enforces the launch level of agents started by /sc:issue --claim --pipeline. Background: a claim now creates an Orca worktree and launches Claude Code behind the ccsession shim, with permission prompts off, to run the issue's next steps. Level worktree (the default) must stop at an approved plan. Level full also implements. Option --submit also commits, pushes and runs /sc:pr-submit. Nothing ever merges. Problem: today the stop is only an instruction in a prompt file, so a launched agent can still run /sc:implement, /task, git commit, git push or /sc:pr-submit. Goal: a hook that blocks those actions unless the level allows them, with maximum effect and minimum edge cases and unwanted behaviour. Requirements: act only in sessions launched by a claim and leave ordinary sessions untouched; read the level from state the agent cannot edit; cover Bash, Skill and Task tool calls and subagents; let a human approve by typing the command or replying approved; fail closed on missing or unreadable state; never allow a merge or a push to master or main at any level; explain every block in plain words; be testable. Edge cases to design for: slash commands typed by a human versus issued by the agent, nested subagents, tampering with the state file, worktree identity after a rename, re-claims, shell wrappers around git, and hook speed. Follow-on to the /sc:issue --pipeline feature; its spec is in .dev/brainstorms/20261105-024132-issue-claim-orca-worktree-flag/ (launch-levels-addendum.md, FR-28 to FR-31).
