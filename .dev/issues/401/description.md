# Description given to /sc:issue --create

run_with_timeout in src/superclaude/cli/cli_portify/executor.py (line ~211) does not stop a hung step at its limit. It uses 'with ThreadPoolExecutor', whose exit waits for the worker thread, so TimeoutError is raised only after the function finishes. Measured: a 0.1s limit raised after 3.0s. SC-001 (validate_and_configure <= 30s) and SC-002 (discover_components <= 60s) are therefore not enforced for a hung step. The tests in tests/cli_portify/test_executor.py::TestRunWithTimeout only check the exception type, not elapsed time, so they did not catch it. Python threads cannot be killed, so a fix needs a design choice (for example a daemon thread with shutdown(wait=False), or running the step in a subprocess). Found while shortening slow CI tests on branch ci/parallel-python310-tests.
