## Convergence Gate Outcome

**CONVERGENCE BLOCKED** on invariant grounds. The following HIGH + UNADDRESSED findings must be resolved before merge:

1. **INV-001** — Redis pub/sub denylist semantics under Sentinel failover (breaks ≤60s revocation claim).
2. **INV-002** — Encrypted-column inventory does not enumerate V2-added tables (consents, email-change, mfa_secrets).
3. **INV-005** — No guard binding all V2-added PII-bearing tables to D1.2 encryption invariant.
4. **INV-009** — ≤60s revocation arithmetic is unverified (pub/sub delay + local cache TTL + clock skew not enumerated).
5. **INV-010** — 13-week duration claim does not survive V1-ordering merge; corrected schedule unstated.
6. **INV-021** — pgcrypto on `email` column breaks all email-lookup queries (login, reset, dedup, change) → NFR-001 violation.
7. **INV-022** — ≤60s revocation sufficiency depends on unstated local-cache TTL and Sentinel pub/sub behavior.
8. **INV-023** — pgcrypto key residency claim is technically false; DEK transits app memory and pg wire.
9. **INV-024** — Plaintext-PII window enumeration: no negative test guarantees D1.2 binding across all M2/M3/M4/M6 write paths.

## Notes for Merge Refactoring Plan

- **Patch INV-021 + INV-023 together** by introducing a documented "PII access pattern" deliverable in M1 that (a) adds a deterministic `email_lookup_hash` (HMAC-SHA256 with separate KMS key) sidecar column for equality lookups, and (b) clarifies that pgcrypto DEK is unwrapped per-request via KMS GenerateDataKey and held only in request-scoped memory (or moves to a server-side key extension like `pg_tde` / Vault Transit). Without this, NFR-001 and the encryption sufficiency claim both fail.
- **Patch INV-001 + INV-009 + INV-022** by replacing the pub/sub denylist with a TTL-bounded Redis SET (`denylist:<jti>`) checked on every request, with explicit budgets: Redis check ≤5ms + per-pod local cache TTL ≤30s + clock-skew tolerance ≤5s → total ≤40s ≤ 60s claim. Document Sentinel failover behavior (reconnect window ≤10s) and add a chaos sub-test in D7.4 that kills the Redis primary during an active revocation.
- **Patch INV-002 + INV-005 + INV-024** by adding to D1.2 a "PII Encryption Inventory" artifact enumerating every column across every table (including V2-added `user_consents`, `email_change_pending`, `mfa_secrets`) that stores PII, with a CI test that greps the DB for plaintext-email regex post-integration-test-suite and fails the build on any hit.
- **Patch INV-010** by either (a) restating the schedule under the V1-ordering merge (likely 15 weeks, M2 sequential before M3), or (b) explicitly noting M2 (core auth) and M3 (OAuth) can parallelize after M1 foundation, recovering ~2 weeks.
- **Patch INV-004 + INV-019** by adding a single-writer queue (e.g., a Postgres advisory lock on `audit_events` insert, or a dedicated audit-writer worker) so the hash chain has a serialized append point. Document the DBA-only repair runbook for cron-detected corruption.
