# State Variable Registry — Troubleshoot Pipeline Hardening (Pipeline Hardening Closure mode)

> Correctness cluster artifact (Nygard lead / Fowler / Crispin / Whittaker), `/sc:spec-panel --focus correctness`.
> Target: `troubleshoot-pipeline-hardening-spec.md` §6–§10 + `EFFICACY-REPORT-MERGED.md` §9–§10 + Appendix A.
> Method: every mutable variable the hardened protocol introduces is cataloged. The **ASSUMED** flag (Wiegers correctness shift) fires whenever the spec does not state an initial value, a valid range/enum, or an invariant. **Each ASSUMED gap auto-promotes to a Functional Requirement** in the spec (column "→ FR").

## Legend

- **Type**: declared or implied data type.
- **Initial Value**: STATED if the spec gives one; `ASSUMED` if not.
- **Invariant**: the correctness rule that must always hold; `ASSUMED` if the spec leaves it unstated.
- **→ FR**: whether the registry row should generate a Functional Requirement to close a Wiegers gap.

## Summary for the spec

- **Total mutable variables cataloged: 15** (SV-1 … SV-15).
- **Variables with ASSUMED initial value / range / invariant (→ each becomes an FR): 11** — SV-1, SV-2, SV-7, SV-8, SV-9, SV-10, SV-11, SV-12, SV-13, SV-14, SV-15. (SV-3–SV-6 have an OK `null` initial but carry ASSUMED existence/completeness invariants, also → FR.)
- **Highest-severity ASSUMED rows (CRITICAL, drive adversarial findings):**
  - **SV-8 `known_escapes_caught`** — no anti-inflation invariant; an agent can assert `[E1..E5]` with zero evidence (Accumulation attack F-A1).
  - **SV-13 `h4_status`** — fail-closed default unspecified; does it start FAIL-until-proven or PASS-until-broken? (Zero/Empty attack F-N1).
  - **SV-15 `waiver_status`** — the one-way `partial` latch is the single anti-theatre control (§10) yet is not bound to a variable, so nothing mechanically forbids a downstream re-green (Sequence attack F-S1).
- **Recommended FR text seed:** "FR-SV: Every Pipeline Hardening Closure state variable MUST declare an initial value, a valid range/enum (including the unevaluated/`pending` state), and a written invariant. `known_escapes_caught` entries MUST be evidence-earned (no assertion-only membership). `waiver_status` MUST be a monotonic one-way latch to `partial`."
