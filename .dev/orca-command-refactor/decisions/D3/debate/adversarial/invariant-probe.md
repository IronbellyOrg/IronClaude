## Emerging consensus

All three Round 2 rebuttals converge on one recommendation (R2-V1, R2-V2, R2-V3 "Overall recommendation"):

1. **(a) is D3's answer and the default.** The coordinator, or the person, runs `/sc:pr-submit --monitor 3` from the change's worktree once the workers finish. No Phase 4 change to pr-submit.
2. **(c) is adopted by one D3 sentence as the parallel route.** Only when the person asks for one agent tab per named PR and accepts no completion tracking; authority from `HWW:215` and `HWW:221`; the coordinator launches one person-owned tab per PR with `agent launch`, records the person's instruction beside each worktree id and handle, then stops (`[CLI] 29`, `[G] 39`); a lost launch reply is retried only with `--retry-launch` (`[CLI] 65`); enabled only after a smoke test shows a Claude tab, on the person's actual chat-or-terminal setting, runs `/sc:pr-submit` from `--prompt`.
3. **(b) is deferred, not rejected.** The "attended" objection is withdrawn (X-001 to V2: `PRS:43-45`, `PRS:83-84`, `CAPS:161`), but (b) runs only under D4 (a) (`HWW:223`, `D4c:3`), its HALT route is one hop slower (WC-3 at `SPEC:67`), and it alone carries build cost and unverified runtime (`SPEC:276`, `SPEC:393-394`).
4. **Spec fix whatever D3 decides:** drop "`ask` or `escalation`" from the `SPEC:137` row to match WC-3 (`SPEC:67`).

Agreed per-point facts underneath it: monitor 3 pushes without asking in every option (`CLAUDE.md:50`), so the safety difference is visibility and who authorized the start (C-002); operator HALTs end the run with `terminal_halted` in every option (`PRS:268`, `PRS:274`; C-003); `--resume <run-log>` recovers every option the same way (A-005, C-010); (a) and (c) "need no D4 answer" (C-008, C-004); (a) holds the coordinator for "roughly four waits, about 40 minutes" at defaults (R2-V1 #2, C-005); (a) must run from each PR's head checkout, accepted as "friction" (A-006, R2-V1 #16).

**HIGH UNADDRESSED (block convergence per the protocol):** INV-006, INV-012, INV-017, INV-023.

- INV-006: the (a) sentence lacks the "requested and authorized" guard that `HWW:221` and `HWW:215` require.
- INV-012: nothing ensures one live monitor per PR; two monitors in one worktree can publish each other's unvalidated edits.
- INV-017: (a) and (c) depend on D4 through the pre-PR commit and branch push, which pr-submit does not perform.
- INV-023: the consensus alone does not give working PR monitoring; seven of ten enumerated gates are not shown to pass for at least one route.

Each can be closed by wording in the D3 sentence rather than a change of option: name the authorization trigger for (a); state the pre-PR steps (commit, rebase onto `origin/<base>`, push with approval) and who performs them under each D4 answer; require one PR per worktree and no second monitor on a PR that already has one; and define the (c) smoke test as an acceptance check with a safe target.
