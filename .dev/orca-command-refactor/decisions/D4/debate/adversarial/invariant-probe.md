## Emerging consensus

All three advocates converge on option **(c′)**, with (b) as its default and fallback (R2-V1:79, R2-V2:90, R2-V3:88). The spec's D4 recommendation (`SPEC:348`) changes from (a) to (c).

- **Worker commits.** There are none unless all of these hold: (1) the brief quotes the user's instruction naming a commit for that Task; (2) the coordinator has placed the worker in its own worktree and branch under `.dev/worktrees/` (`CLAUDE.md:297-299`, `CAPS:115`); (3) V3 adds a P0 check that proves `worker-start` accepts that worktree (`SPEC:236`, UNVERIFIED). V2 lists it as a spec edit (R2-V2:104), and V1 does not mention it.
- **How the worker commits.** The worker session makes one plain-git commit (`HWW:324`) after the command has exited with `worker_status: succeeded`. It never commits after `partial` or `blocked`, and never inside a command, so implement makes no commits until #326 K3. It stages the Task's own files plus that worktree's `.dev/tasks` (`CLAUDE.md:37`). It never commits on the default branch, never pushes, and lists each SHA in the contract's `artifacts`.
- **Command commit steps.** Every command's own commit step stays off under `--unattended`: post-release's commit, task's EXEMPT `commit` and the TFEP report commit (R2-V3:37, R2-V3:95). V1 and V2 do not restate this.
- **Outward actions.** Everything that leaves the machine stays with the coordinator: push, merge, PR, GitHub comment or progress post, real-target install, VM and paid run. The coordinator confirms with the person at the moment of action unless the instruction is in its own live conversation (`PRL:351`). PRs go only through `/sc:pr-submit` (`CLAUDE.md:50`), and auggie-review summaries are posted from the worker's `REVIEW.md` (`AUG:319`).
- **Spec edits.**
  - Apply EVAL F0, F1 (reworded to one end-of-Task commit), F2 (with an added clause for commit-authorized workers), F3 and F4.
  - Remove `README.md:31` from WC-9 and from the `/sc:git` row.
  - Make AC-4.2's "`git log -1` unchanged" conditional and add "`git log origin/<branch>` unchanged".
- **Conceded residuals.**
  - The provenance gap remains for commits (C-007 conceded to V2).
  - Commits are per Orca Task, not per implement task, until K3.
  - The person must decide what to do with each unmerged branch (F3).
  - The inline auggie-review comments have no deferred posting path.
  - Option (a) stays available as a later, additive loosening.
