## Emerging consensus

All three advocates converge on **option (c) as corrected in R1-V3:16-21, with the Round 2 amendments** (R2-V1:76, R2-V2:86, R2-V3:79-91). Option (b) is withdrawn by its own advocate (R2-V2:86).

The agreed design:
1. Commands switch to unattended mode only on the standalone `--unattended` token outside quoted arguments (option (a)'s command side, `SPEC:55`). Commands read no environment and no conversation.
2. From P1 onward, the worker session runs one check when it loads each top-level command, before the command's first step. It refuses with `worker_done --outcome failed` and runs nothing in three cases:
   - the flag is missing although the command has an `## Unattended mode` section;
   - the flag is present although the command has no such section;
   - the command is one of the six coordinator-only commands (`SPEC:150-160`).
3. The guard is keyed to the `## Unattended mode` section, which AC-1.1 already ties to the phase table (`SPEC:257`). So it is inert in P0 and never refuses `/sc:load`.
4. The guard sentence travels in the brief template and in `WORKER-CONTRACT.md`. `SPEC:79` is amended to "where the command accepts it at this phase". `SPEC:330` and item 13 (`SPEC:395`) record that `ORCA_TERMINAL_HANDLE` marks any live Orca terminal (`CAPS:149`, `CAPS:151`).
5. Three checks: a static assertion in `test_worker_contract.py`; AC-1.2 plus one P1 flag-omitted run; the discriminating P2 bare-topic tdd run. If the guard misfires, deleting its sentence returns exactly option (a).
