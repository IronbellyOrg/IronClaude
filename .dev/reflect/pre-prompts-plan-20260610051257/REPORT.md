# Reflect — UC-1 Pre-Execution Plan Review

- **Mode**: pre · **Target**: the two generated prompts (reflectWrapper wrapper-alignment + ReflectInTaskLists tasklist-alignment)
- **Objective (spec)**: O1 — every task-builder tasklist ends with a bash `superclaude reflect run --depth deep` gate; O2 — every sc:tasklist phase ends with the same; mechanism = bash wrapper (top-level subprocess, preserves Tier-2); behavior = `--depth deep`, **auto-fix/auto-apply**, **promote-by-default**.
- **Grounding**: 5/5 load-bearing technical claims independently GROUNDED (file:line below). Author-side analysis acknowledged — I wrote the plan, so the independent verification is the anti-self-confirmation control.

## Verdict

**The plan's *placement* design (O1+O2 gate sites) is sound and achievable. The plan's *behavior* design (auto-fix + promote-by-default) is NOT achievable as written — it contradicts reflect's core boundary and creates an unbounded recursion.** Two CRITICAL issues must be resolved in the brainstorms or the objective will fail / cause harm. Coverage of O1/O2 mechanics is otherwise good.

## CRITICAL findings

### C-1 — "Auto-fix" contradicts reflect's design AND creates unbounded recursion
- **Grounded**: reflect explicitly forbids auto-execution — `sc-reflect-protocol/SKILL.md` Will-Not: *"Auto-execute a Tier 3 remediation task — task-builder produces a file, the user runs `/task`"* + *"Auto-commit after Tier 3"*; Waves 0-6 are *"read-only … never modify the work-unit tree."* So the wrapper calling `/sc:reflect` **cannot** make reflect auto-fix — reflect won't. `--remediate` only *authors* a remediation task.
- **Therefore** auto-fix requires a NEW execution layer outside reflect: wrapper → reflect (audit) → author remediation task → **run `/task` on it** → re-run reflect. But that remediation tasklist is generated by task-builder, which (per **O1**) emits its own terminal `superclaude reflect run` gate → wrapper → reflect → remediation → wrapper → **unbounded recursion** (reviewer confirmed C4).
- **Required before build**: (a) a **recursion-breaker** — remediation tasklists the wrapper auto-executes must be exempt from emitting/running the O1 gate (e.g., a `REFLECT_WRAPPER_ACTIVE` env guard or a `no-post-gate` marker); (b) a **bounded fix-loop** (apply → re-verify → max-N iterations → halt-on-non-converge). The prompts treat auto-fix as one brainstorm bullet; it is the **central design problem** and must be elevated.

### C-2 — Auto-fix + promote-by-default deletes the human-decision discipline
- reflect routes ambiguous / unfixable findings to **Grounding Gaps → `needs_human_decision: true`**, and the whole project leans on `feedback_human_decision_items_must_halt`. "Literally auto-fix + promote by default" would **auto-apply and promote work with unresolved human-decision items**.
- **Required**: a hard carve-out — auto-fix ONLY mechanically-unambiguous deviation classes; anything in Grounding Gaps / `needs_human_decision` / `regression` still **HALTS** (does not auto-promote). This preserves "auto-fix by default" for the safe majority while refusing to silently ship a wrong human-decision call. Recommend confirming this boundary with the operator explicitly.

## HIGH findings (will fail O2 or break at runtime)

### H-3 — O2 per-phase BASE is unsupported by the wrapper
`config.py:_resolve_base` resolves a **single task-level** base (`start_commit` else `merge-base`); **no per-phase awareness** (reviewer GROUNDED C2). A per-PHASE gate (O2) needs each phase's own base. **Gap**: the wrapper invocation contract must add `--base <ref>` (or a per-phase `start_commit` frontmatter key) so phase-N's gate audits only phase-N's work. The prompts say "define per-phase BASE" but don't flag that the wrapper currently *can't* do it.

### H-4 — "Promote by default" is undefined for an sc:tasklist phase
Only two promotion adapters exist: `task` (`.dev/tasks/to-do/TASK-*`) and `sprint-release` (reviewer GROUNDED C3). **There is no per-phase adapter** — an sc:tasklist phase isn't a promotable work-unit folder. So "promote by default" has **no defined semantics for O2**. **Required**: either define a per-phase promotion adapter, or scope promotion to tasklist/release level only and have per-phase gates auto-fix-but-not-promote.

### H-5 — Cost: forcing `--depth deep` everywhere = Tier-2 on every phase + every tasklist
`--depth deep` ALWAYS escalates to Tier 2 (~35-70k Claude tokens, 8-15 min, ~52 turns) (reviewer GROUNDED C5). A 5-phase sc:tasklist = **5 deep Tier-2 runs + the terminal tasklist gate** ≈ 200-400k tokens / 45-90 min, even for trivial phases. This **reintroduces the one-size-fits-all over-spend** the (now-dropped) dial's `auto` mode was designed to avoid — just inverted (always-heavy vs always-manual). The user chose "always deep"; surface the cost so it's an eyes-open choice, and consider keeping the dial's *proportionality idea* (auto-depth per phase) even while dropping its over-built *form*.

### H-6 — Sequencing/install dependency is load-bearing, not just noted
Every emitted gate calls `superclaude reflect run`. That command must be **merged to master AND `pipx install --force`'d** in the environment where generated tasklists execute (`reference_superclaude_install_vector`). If the generators (O1/O2) ship before the wrapper is installed, **every generated tasklist breaks at its terminal gate** ("no such command"). The two efforts must land wrapper-first, install-verified, then generators.

## MEDIUM (process)

- **M-7 — The 2-worktree / 2-prompt split risks re-creating the split-brain.** The wrapper's invocation+generator contract is the single coupling point; two *independent* brainstorms in two worktrees is exactly the divergence that produced the reflectWrapper-vs-ReflectInTaskLists mismatch in the first place. The contract should be **one source of truth** consumed by both, not re-derived twice.
- **M-8 — Brainstorm vs build.** The objective is already converged (this whole session). Two more open `/sc:brainstorm`s risk **re-litigating settled decisions** (the dial, auto-fix). A single consolidated spec (the convergence) + one coordinated tasklist may be cleaner than two fresh brainstorms.
- **M-9 — rf-qa is a third surface.** Rewiring the emitted gate form means `rf-qa.md`'s POST-item validation (which asserts the self-run/HALT form on master) must also change. The prompts name 2 SKILLs; it's really 3 files.
- **M-10 — Idempotency / re-run.** Auto-fix + promote moves the work-unit to `done`; re-running the gate against a moved folder breaks. Needs idempotent re-run semantics.

## Process validation

The **direction** is right (converge on one wrapper engine + two gate sites). The **vehicle** (two independent brainstorm prompts across two worktrees) is the weakest part — it under-weights the deepest design problem (auto-fix/recursion, C-1) by burying it as a bullet, and it risks re-forking the contract (M-7/M-8).

## Recommended revision (improvements/alternatives)

1. **Resolve C-1/C-2 as decisions BEFORE the brainstorms**, not inside them: (a) recursion-breaker exemption for wrapper-spawned remediation; (b) bounded fix-loop; (c) auto-fix scoped to safe deviation classes, HALT on `needs_human_decision`/`regression`. These are the load-bearing design choices; settle them with the operator first.
2. **Collapse to one spec + one tasklist.** Author a single convergence spec (objective + the C-1/C-2/H-3/H-4 decisions + the wrapper contract) once; drive both the wrapper change and the two-generator rewire from it. Keeps the contract single-source (fixes M-7/M-8).
3. **Sequence explicitly**: wrapper (merged + pipx-installed + the per-phase `--base` + the promotion-scope decision) → THEN generators emit gates → THEN verify end-to-end on a real tasklist + a real multi-phase run.
4. **Make the cost choice explicit** (H-5): confirm "deep everywhere" with the cost on the table, or re-admit per-phase auto-depth (the dial's valid core).
5. If keeping two prompts: **add the C-1/C-2/H-3/H-4/H-6 items as explicit required-decisions** in each prompt (not optional brainstorm bullets), and make Prompt 1 emit the contract as a written artifact Prompt 2 *reads* (not re-derives).

## Bottom line
O1/O2 *placement* will be achieved by the plan. O1/O2 *behavior* (auto-fix + promote-by-default) will **not** be — as written it fights reflect's design and recurses. Elevate auto-fix to the central, decided-up-front design problem; unify the contract into one spec; sequence wrapper-before-generators with install verification.
