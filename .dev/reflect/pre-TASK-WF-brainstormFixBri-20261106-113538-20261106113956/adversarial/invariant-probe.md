## Notes

### Note 1 — mixed path bases (INV-001)

In managed packages (refs/managed-workspace.md), `./artifacts/...` and `./source.md` are relative to the package, while delivery paths like `src/superclaude/...` are relative to the repo. The consensus example mixes both bases in one command. Measured:

- cwd = repo root: `sed: can't read ./source.md`, so the extraction is empty and `grep -cF -- "" src/superclaude/skills/sc-brainstorm-protocol/SKILL.md` prints 461. The AC fails on a correct edit.
- cwd = package directory: `grep: src/superclaude/...: No such file or directory`, rc=2.

Minimal fix: use one base. For example, run from the repo root with `P=.dev/tasks/to-do/TASK-WF-brainstormFixBri-20261106-113538` and `sed -n '231s/.../\1/p' "$P/source.md"`, or state "run from the package directory" and prefix targets with `$(git rev-parse --show-toplevel)/`. Also see INV-014 for the archive move.

### Note 2 — line-number anchoring (INV-002)

Lines 219 (1210 characters, 2 double quotes), 223 (450 characters) and 231-233 (the Task 1/2/3 applied texts) are correct today. The PLAN pin keeps them stable during a run. The risk is outside a run: regeneration or a pre-start edit. Two cheap guards: (a) anchor the sed address on text instead of a line number (for example `/^.*Task 1 AC/`), or (b) add a self-check AC per extraction: the result is non-empty, and `grep -cxF -- "$X" <plan>` = 1, which proves the extraction equals the plan's fenced line.

### Note 3 — backtick in the Task 2 regex (INV-003)

The extracted text itself is safe: command substitution output is not re-parsed. The problem is only the markdown rendering of the AC line that contains the sed program. Use `.grep` in place of `` `grep `` (verified: 261 characters, plan `-cxF` = 1), or put the AC in a fenced block instead of an inline code span.
