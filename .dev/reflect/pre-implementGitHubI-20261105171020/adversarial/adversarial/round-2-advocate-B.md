## 3. New evidence not in earlier rounds

All verified by reading in this round.

- **NB-1. An env file can poison nested launches with a bad value, which no card or round had stated.** The `case` at `ccsession:124` reads only the shell value; `~/.claude/ccsession.env` is sourced later (`:847-849`) into the same shell, before the six `exec` lines (`:1799-1868`). So an `export CCSESSION_PERMISSIONS=typo` in the env file leaves the *current* launch on default flags (PLAN:23's claim holds) but exports the bad value into the exec'd Claude, and a nested `ccsession` then exits 2. Consequences: PLAN:23's "not settable from that file" is true only for the current launch; A's Round 2 N5 (default via export reaching nested launches) is the same mechanism in the benign direction; the U-005 test should pin the `default` case and the corrected plan's Constraints sentence should state the file's nested-launch reach.
- **NB-2. A third unisolated `--help` site, which A's Round 2 listed as unchecked.** `tests/cli/test_update_command.py:198-208` runs the installed `ccsession --help` with `env={**os.environ, ...}` and `check=True`. Under a bad exported value it raises CalledProcessError; under a valid `default` it passes (its assert is the substring `"ccsession --help"`). This completes the A-007 site list (with `test_install_ccsession.py:51-67` and `:224-238`); the two `install.sh` sites correctly come off it (A's N1).
- **NB-3. `ccsession-orca` never sources the env file** (grep for `ccsession.env` and `CCSESSION_ENV_FILE` in `ccsession-orca`: no match). Independently confirms A's Round 2 response 2: one env-file test through `ccsession` covers the direct and the orca print-mode path.
- **NB-4. The tier `--settings` payload carries no permission content.** `models.py:707-712` (re-read) returns only `{"modelSettings": {key: {"autoCompactWindow": ...}}}`. This closes the "not re-read" gap A's Round 2 left open on A-002.
- **NB-5 (verification of A's N1/N4, not new facts of my own).** `install.sh:63` (`--migrate-names 2>/dev/null || true`), `install_ccsession.py:104-113` (`check=False`, captured), `session-name.sh:196-212` (`--sync-name` ungated on `OWNER`, all three calls swallowed) — all re-read and as A stated.
