## CF-05 verdict

As written, the A/B edge set (4b on 4a, 5, 7; 8 on 4b) cannot be executed. It leaves Task 5's "Depends on: Task 4" (P:106) unchanged, which either creates the cycle 4b → 5 → 4b or, read as 4a, leaves Task 9 (P:171) without a path to 4b. Task 9's `__init__` imports `conflict_resume_plan` and `crash_resume_plan` (S:744), which 4b defines (P:92), so a dependency-order scheduler may run Task 9 first, and that import failure would break every `tests/pr_submit` gate (INV-001, INV-002).

C's edge set (5 on 4b; 4b on 4a, 7; 8 on 4b) is acyclic, with the topological order 1, 2, 6, 3, 7, 4a, 4b, 5, 8, 9, … 20, and it is complete for imports (INV-004). However, `/sc:implement` runs in document order and ignores Depends-on (IMPL:77, IMPL:97). C's edges therefore hold only if Task 7 (P:137) is moved above Task 5 (P:104), a move nobody proposed. That move also makes Task 5 depend on Task 7, which is stricter than spec step 4 (S:1419; see INV-005, INV-014).

The set that is acyclic, complete for imports and consistent with document order without moving any existing task is C's own fallback (R2-C line 20). It takes the A/B set and adds two edges, "Task 5 depends on: Task 4a" and "Task 9 depends on: Task 4b", and places the 4b heading between Task 7 and Task 8. The resulting order, 1, 2, 3, 4a, 5, 6, 7, 4b, 8, 9, … 20, is the plan's own document order with 4b inserted, and every edge points backward in it. Recommended CF-05 resolution: adopt that amended set, and record 4b's document position in the fix, because that position is the only part of the consensus that affects execution under `/sc:implement`.
