# Pre-registration addendum, frozen hold-out comparison (written 2026-11-16, before any hold-out run)

Context for a reader with no history: Recipe Ledger (RL) asks cheap reviewer models to run eight written recipes and write a ledger before reviewing a plan. An exploratory 81-run check on the three study packages (never frozen; `results/derivation-3x/SUMMARY-9reps.md`, `SUMMARY.md`, `scores-table.json`) found RL at 2.00 of 14 defects per replicate against 0.67 for the control (Z0) and 0.56 for a plain checklist (K), at 1.46 to 1.60 times Z0's run time on two packages. This file fixes, before the first hold-out run, how the confirming comparison is run and read. Background and open questions: `../../OPEN-DECISIONS-20261115.md`.

1. **Documents:** HO-1 to HO-4 (four plans from `.dev/tasks/done` that are not the three study packages), chosen from the generality investigation (H5, H2, H4, H3). None was used to design the recipes. Ground truth is written by a fresh session that has not read the recipes, cards, extractors or derivation results, and is committed and hashed after the freeze tag and before the first run.
2. **Arms:** Z0 (control: harness fixes and brief edits, no redesign), K (Z0 plus the plain-words checklist), RL. Z0-raw is not run (it only measures the harness share).
3. **Panel and runs:** ember panel only (`muse-ember-1.0` + 2x `gpt-6-luna`), 5 replicates per arm per document = 60 panel runs, block-randomised (one block per replicate), one panel at a time through `20261114-collab-process/with-slot.sh`. The sandbox is rebuilt before a run when the previous run left files behind (`bin/run-schedule.sh`).
4. **Judging:** blind Opus judge only for scoring; a second judge scores a 15% sample (REQ-43). No other use of Opus.
5. **Format reading:** the owner-approved small allowances stay on. The compliance gate (ledger missing at most 10%) is decided on the LENIENT reading. The STRICT reading is reported next to it for every arm; if the strict reading fails and the lenient passes, the result is reported as "passes only with allowances".
6. **Gates D1 to D7** are those in `config/prereg.json`, unchanged. D1 (per-document median elapsed at most 1.35 x Z0 in the same block) is a per-document rule: the derivation set showed RL failing it on two of three packages, so a fail here is expected to be reported as such, not explained away.
7. **Primary metric:** share of hold-out items that are consistent (reached in at least 3 of 5 runs), per arm; secondary: found fraction per run, wrong blockers, real blocking finds, tokens, time.
8. **Not used for adoption:** the derivation set and its p-values (chosen after seeing data). A pass here means D2 to D7 hold on four documents; the power note of the requirements (about 36 to 40 items, low power) applies: a pass is evidence, not proof.
9. **Invalid runs:** a run is invalid when a reviewer was killed with no output, the model was not the one labelled, or a tracked file of the sandbox changed. Invalid runs are listed, rerun once with the same seed and block, and reported either way.
10. **Pre-registered limits of this study:** one panel (ember); documents are all plans, so nothing is said about specs or documentation targets; the ground-truth author is a model session chosen by the owner.
