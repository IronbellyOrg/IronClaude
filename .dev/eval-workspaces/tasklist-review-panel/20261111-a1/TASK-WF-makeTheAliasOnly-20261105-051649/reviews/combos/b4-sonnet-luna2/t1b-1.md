## Findings

**F1 (Medium, missing requirement): the launcher spec exports all three variables with no access check.**
- An implementer who follows the Task 9 text as written builds three exports that run whenever tier mode is on, and that is wrong for a limited owner.
- `models.py` already has per-owner tier rules (`CCSESSION_TIER_RULES` and `CCSESSION_ACCESS`).
- An owner limited to tier2 and tier3 would get `opus` mapped to `claude-gw-tier1a`, a tier they cannot use. Subagents with `model: opus` would then fail.
- The source states the exports without a condition, so this is a missing restriction and not a stated text that does harm.
- The Task 6 page and its "Known consequences" list also never mention limited owners.
- The repo's `.dev/issues/384/launcher-access-aware.md` shows the owner later asked for exactly this gate.

**F2 (Medium, missing requirement): the scratch-copy instruction does not say to repoint the harness paths.**
- An implementer who follows Task 9 as written copies the harness into `./artifacts/t9-scratch/` and gets a collection error.
- The module sets `REPO_ROOT = Path(__file__).resolve().parents[2]`, `SKILL_DIR` from it, and then runs `import models`.
- From `.dev/tasks/<pkg>/artifacts/t9-scratch/` those paths are wrong. The result is a ModuleNotFoundError, which the same acceptance criterion forbids.
- The criterion can still pass once the implementer sets `REPO_ROOT` by hand. The text never says to do that.

**F3 (Medium, contradiction): "Edit under src/ only" contradicts most tasks.**
- Read literally, the constraint forbids every task that edits or creates files in tests/, docs/, plugins/ and .dev/.
- The next sentence of the constraint authorizes plugins/ edits, and its first clause is about `.claude/` copies, so the intent is clear.
- This is a wording fix: say "do not edit `.claude/`".

**F4 (minor): the issue-worker pin order is ambiguous.**
- The constraint lists the files as t1, t2, t3. Task 1 lists the values as tier3, tier2, tier1a.
- Pairing them by position gives t1 = tier3, which is wrong (t1 is tier1a).
- That would make the test that must pass on the unchanged tree fail.
- Name the pairs explicitly.

**F5 (minor): Task 8 does not declare Tasks 2 to 4.**
- Its final check needs them done, but its dependency chain is 7, 6, 5, 1.
- This only matters if tasks run out of document order.

**F6 (minor): some cited line numbers will go stale.**
- The test-file lines for the fake claude (330-341 and 359) carry no "re-verify" mark. In the supplied checkout they sit near 399-411 and 429.
- D12 cites `commands.py` line numbers in its source note. Task 2 lengthens the comment above `_DEFAULT_MODEL` and does not tell the implementer to refresh them.

**F7 (minor): installed skill text points at a repo-only page.**
- chains.md and tiers.md are installed to `~/.claude/` and run in other projects.
- The new `docs/reference/model-aliases.md` pointer will be dead there.
- The project's path rule covers only `src/superclaude/` paths, so this is a note and not a violation.
