## Findings

### F1 (MAJOR, graded Medium, not blocking): the tier-text allow-list omits `src/superclaude/cli/review/data/`

An implementer who follows the stated text as written builds a tier-text test with only three file paths, `sc-issue-protocol/` and `ccsession-tag/` allowed. That test is wrong in this checkout. `review-tiers.default.json` and `review-panel.live7.json` under `src/superclaude/cli/review/data/` contain `claude-gw-tier1a[1m]` and similar ids. The test scans `cli` with no file-type limit, so it would fail. No task fixes it, and the constraints forbid editing those files.

- The "remaining tests pass" criterion in Task 1 would then fail.
- The "passes in full" criterion in Task 8 would fail.
- It is Medium because the guess is whether those files exist at the base commit. They look like #346 review-panel data, whose docs mention a list supplied on 2026-11-11.
- The test file already in this checkout allow-lists that directory.

### F2 (MINOR): the pinned values are listed in reverse order from the files

The files are named t1, t2, t3. The values follow as tier3, tier2, tier1a. Read in order, that maps t1 to tier3, but the correct mapping is t1 to tier1a, t2 to tier2, t3 to tier3. The frontmatter test would then fail on the unchanged tree, so the implementer has to check the files. Say the mapping once.

### F3 (MINOR): the `sk-` grep also matches ordinary words

`grep -nE "sk-|token=" docs/reference/model-aliases.md` returns nothing only if the page has no word ending in `sk-` such as "task-", "risk-" or "disk-". It also does not match uppercase `TOKEN=`. Anchor the pattern, for example `\bsk-[A-Za-z0-9]`.

### F4 (MINOR): "exactly as in the mapping table" can read as a table, not `NAME=value` text

The Task 6 criterion says the exports are "spelled exactly as in the mapping table". The Task 1 test needs the contiguous strings `ANTHROPIC_DEFAULT_OPUS_MODEL=claude-gw-tier1a` and the sonnet and haiku equivalents. A three-column table would not contain those strings, so the test fails until the page is fixed. Name the `NAME=value` form in Task 6.

### F5 (Medium): the T9 scratch copy leaves out what the harness depends on

The harness depends on `REPO_ROOT = Path(__file__).resolve().parents[2]` and on the module-level autouse fixture `_isolated`. Both are in `tests/unit/test_ccsession_tiers.py`.

- A scratch module under `./artifacts/t9-scratch/` that copies only "the harness and the test" resolves the launcher path wrongly and loses the isolation fixture.
- The run can then fail with `FileNotFoundError` or leak the real environment, instead of the `AssertionError` that the T9 criterion checks.
- Tell the implementer to copy the fixture and set `REPO_ROOT` to the checkout.

### F6 (MINOR): the `--models` removal covers only the chains file

`source.md` says the workaround is in `chains.md` "and templates". Task 3 and its test cover only `refs/chains.md`. There is no step that searches `templates/next-steps.md` or the design record for other `--models opus,sonnet` sites. In this checkout there are none in `src`; design record `docs/designs/sc-issue-command.md` still has them at lines 248 and 464, which Task 3 handles with the superseded note.
