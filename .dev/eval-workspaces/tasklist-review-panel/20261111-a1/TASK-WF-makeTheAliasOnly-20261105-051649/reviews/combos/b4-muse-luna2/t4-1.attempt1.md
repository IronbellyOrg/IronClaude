### CRITICAL, blocking: launcher exports can bypass tier access restrictions

Task 9 requires the launcher to export all three model variables whenever tier mode is on, without conditioning those exports on which tiers the workspace owner may use.

An implementer who follows the stated text as written builds unconditional tier-alias exports in tier mode, and that is wrong because an owner restricted from tier1a or tier1b could select those tiers through the exported model aliases. The tier system has owner-specific allowed tiers, and its existing tests expect aliases for unavailable tiers to remain inherited rather than being set. See `src/superclaude/skills/ccsession-tag/models.py:589-623` and `tests/unit/test_ccsession_tiers.py:3309-3339`.

**Recommendation:** Specify that each alias variable is set only when its mapped tier is available to that owner; preserve the inherited value otherwise.
