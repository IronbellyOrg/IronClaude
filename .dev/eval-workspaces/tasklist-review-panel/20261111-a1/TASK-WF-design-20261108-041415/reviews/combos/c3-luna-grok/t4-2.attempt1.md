## Findings

**F1, blocking.** An implementer who follows the stated text as written builds a create flow whose only writes to the new issue are `gh issue create --type` and one Complexity POST, and that flow is wrong because the goal and Task 2 also require applying the mode label and posting the pushback comment.

The constraint says the skill writes exactly two things to a created issue besides the issue itself, and it names only the issue type and the Complexity POST. The goal says the same run applies the `bug` or `enhancement` label. Task 2's Wave 5 sequence includes that label and the pushback comment, and it keeps `E-POST-FAILED` as the comment's failure. Those texts cannot all be true of one implementation. Following the constraint drops the label and the comment. Following Task 2 breaks the "exactly two" rule.

**F2, Medium (not blocking).** An implementer who follows the stated text as written builds a field read-back that looks for the posted option name, and that check is wrong because GitHub's GET returns the option id in `value` and the name on `single_select_option.name`. This needs the worse reading: the plan never says which field to compare, so a careful implementer might still compare the option name. It is a requirement the plan does not state, not a comparison the plan states incorrectly.

GitHub's docs (issue field values, read 2026-11-11): POST `value` for a single-select field is the option name, and it must match an existing option. GET `value` is a string, number, or integer, and the name is `single_select_option.name`. Task 1 shows the POST body with `"value":"<option name>"` and then a read-back of the same resource, with no comparison rule. The natural check treats a numeric `value` as "the option name is absent" and always prints `not set: field Complexity ...: not applied after create` after a successful POST. The live `refs/labels.md` already warns about this. Task 1's rewrite list does not. Task 7 says not to change tests except old label wording, and the current file's read-back test requires those warning sentences. A rewrite that drops them fails `tests/skills/test_issue_protocol.py`, which Task 12 requires to pass.
