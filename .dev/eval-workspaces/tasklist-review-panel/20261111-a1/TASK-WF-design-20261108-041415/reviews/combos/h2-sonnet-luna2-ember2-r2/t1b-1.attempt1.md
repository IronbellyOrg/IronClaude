## Follow-up candidates (Medium and minor, none fail the review)

**Medium**

1. **F1: one existing test file breaks and no task fixes it.**
   - `tests/skills/test_worker_contract.py` keeps the exact text of the `gh api` and write lines in `create.md`, `SKILL.md` and `issue-worker-t3.md` as keys. It has a test that fails on an unclassified line and one that fails on a stale key (`test_every_write_verb_hit_is_classified` and `test_classification_table_has_no_stale_entries`).
   - Tasks 1, 2, 3 and 5 rewrite those lines and add a `gh api -X POST` line, and no task touches that file. Task 12 runs only `test_issue_protocol.py`.
   - An implementer who follows the plan as written leaves two tests red in the full suite. No stated criterion catches it, so I graded it Medium.
2. **F2: a failed pushback comment hides the `not set` lines.**
   - The plan prints every `not set` line last, after the pushback comment, and keeps `E-POST-FAILED` as a STOP.
   - If that comment fails, the run stops. The issue exists but its missing type or field is never listed, and on a STOP the three new return keys are `null`.
   - The plan never says whether the lines print on that STOP.
3. **F3: the scanner for `orgs/` paths has no stated pattern.**
   - Task 2 requires the prose "no other `orgs/` path is allowed". Task 8 requires that every `orgs/` path found by regex equals `orgs/<owner of R>/issue-fields` (or the `<owner>` spelling).
   - A plain `orgs/\S+` pattern would flag that required sentence. It would also cut the spaced spelling at `<owner`.
   - The self-check test the plan asks for would not catch either problem.
4. **F4: the "reverting a task turns a test red" criterion fails for Task 3.**
   - None of the six listed new tests asserts text that only Task 3 adds to `SKILL.md`. The only test that does is the updated return-contract test from Task 7, which is not a new test.
   - Test 2 says the `orgs/` path "appears only in" three files, which is a subset check and does not require `SKILL.md` to hold it.
5. **F5: the read-back of the Complexity value has no comparison rule.**
   - The plan says to read back with `gh api repos/<R>/issues/<N>/issue-field-values` and flag "not applied" when the value is absent. It does not say how to match a single-select value.
   - GitHub's response includes a nested `single_select_option` object with an id and a name. The docs page I fetched does not say whether `value` is the id or the name.
   - An implementer comparing `value` to `Medium` could print a false "not applied after create" on every create. The live `labels.md` has a section on this that the plan lacks.
6. **F6: one Task 10 criterion cannot be met literally.**
   - It says every `gh api` path in `docs/designs/sc-issue-command.md` spells `repos/<R>/...` except the `orgs/` read.
   - Line 157 of that file has `gh api user -q .login`, which is claim-mode text that stays unchanged.
   - The skill's own rule allows `user`, so I read this as a loose wording, not a real blocker.

**Minor notes**
