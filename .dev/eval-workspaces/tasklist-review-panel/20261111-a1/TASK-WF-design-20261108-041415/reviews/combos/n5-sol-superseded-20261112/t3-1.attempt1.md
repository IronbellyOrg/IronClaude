**F1 (Medium, not blocking).** Constraints bullet 6 says the skill "writes exactly two things to a created issue besides the issue itself: the issue type ... and the Complexity field value", while the Goal, Task 1, Task 2, Task 3, Task 6 and Task 9 all apply a mode label to the created issue as well (via `gh issue create --label`). The sentence undercounts: `--label` is a create flag exactly as `--type` is, so a strict count gives three things. Grading check fails for blocking: to produce harm the implementer must pick the worse reading (drop the label step) over a dozen explicit task statements that apply it, which is a guess between allowed readings. The live tree applies the label, as every task requires.

**F2 (minor).** Task 12 writes `./artifacts/owner-manual-check.md` and `./artifacts/t12-checks.log` "in this package" while Constraints bullet 1 says "Edit only under `src/superclaude/`, `tests/`, `docs/` and `plugins/...`". The repo's own rule stages `.dev/tasks/<pkg>/artifacts/` and treats it as part of the package machinery, so "edit" plainly means repo source; resolvable with no wrong outcome.

The full rule sits one row below (`--type`) and in `refs/labels.md` and design section 11, so behavior is inferrable; a doc simplification only. Same wording lands in `commands/issue.md:41`, both user-guide files and design line 77.

**F4 (minor).** Constraints bullet 4 bans any brace placeholder "for owner and repo" in "no file", while Task 10's touched design doc keeps the anti-example string `{owner}/{repo}` (design line 334, quoting the forbidden form, "never `{owner}/{repo}`").
