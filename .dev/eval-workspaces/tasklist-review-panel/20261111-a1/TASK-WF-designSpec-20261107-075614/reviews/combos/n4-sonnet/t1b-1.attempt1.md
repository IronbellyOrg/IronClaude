## Findings

No finding passes the grading check for blocking. For each one, the sentence "An implementer who follows the stated text as written builds X, and X is wrong because Y" needs a guess about which of two readings the implementer picks, or the finding is a requirement the plan never states.

**F1 (Medium, graded down from MAJOR): Wave 0 bullet text and its test.** Task 9 says the bullet "carries no L3 or `draft` condition", but also that "at L3 with `--merge-guard off`" the line is printed. Read literally, a test that fails on any L3 mention fails the required bullet. The checkout shows the intended reading: the test checks the resume-load part, not the print clause. The plan should say which part carries the no-gate rule.

**F2 (Medium, graded down from MAJOR): CI-fix trigger.** Task 8 makes the trigger "a verified finding of Medium severity or higher routed to a fix" and applies it to "review-fix cycles and CI-fix cycles". A failing CI check is not a graded finding. An implementer may never engage on a CI-only fix, or may engage on any CI fix. The plan never says which. The checkout's Wave 8 bullet resolves this by requiring a routed verified finding.

**F3 (Medium): write-verb classification scope narrower than the constraint.** The Constraints bullet covers `gh pr`, `gh api` and any git write verb. `WRITE_VERB_RE` also matches `git add`, `commit`, `push`, `merge`, `stash`, `update-ref` and `worktree add|remove`. Tasks 7, 8 and 12 each say to classify lines matching only `gh pr` or `gh api`. A ref or command line that names `git push` would be missed by the task text. The test run in each task would catch it, so the harm is a failed run, not silent breakage.

**F4 (minor): exit code for `not_open` is not given.** Task 7 asserts exit codes 0, 1, 2 and 127, and asserts that `--to ready` on a merged PR prints `ok:false` with `error:"not_open"`. It never says which exit code goes with `not_open`. Neither `source.md` section 4.4 nor Task 7 maps it to 1. The test author has to pick.

**F5 (minor): nothing owns the PR-body gate statement.** Task 1 records that "the PR body states the gate plainly" and that the PR-opening run passes `--merge-guard off`. No later task writes or checks either. They are release-time actions outside the file changes, but the plan lists them as decisions it carries.
