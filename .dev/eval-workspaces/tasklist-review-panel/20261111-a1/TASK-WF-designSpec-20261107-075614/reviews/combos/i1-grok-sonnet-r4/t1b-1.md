## Findings

Each Medium finding failed the blocking grading sentence. In each case the implementer must pick a reading, and the repo or the same candidate shows the better one.

**F1 (MAJOR, not blocking): the script's repo-scope scan contradicts its own required resolution line** (Wiegers, Crispin)
Task 7 asks for a static scan that every `gh` line carries `--repo` or a `repos/` path. It also requires the script to pass the `_RESOLUTION_SCRIPTS` tests. Those tests need a `REPO=` or `[ -n` line containing `gh repo view --json nameWithOwner`, which carries neither. The script's `command -v gh` line also mentions `gh`. The plan's own Task 8 points to the existing `_repo_scoped` helper, which exempts that idiom, so a sensible implementer reuses it. The text does not say so.

**F2 (MAJOR, not blocking): the Wave 0 bullet is told to have no L3 condition and also to say "at L3"** (Adzic)
Task 9 requires a bullet that "carries no L3 or `draft` condition". The same task requires it to say that at L3 with `--merge-guard off` the line is printed and "no draft call is made". Its test is described as rejecting "`L3 only` or `draft` gate wording". The implementer must guess whether "condition" means a gate on loading the ref or any mention of L3 or the word "draft".

**F3 (MAJOR, not blocking): the Task 12 grep check cannot show the heading the task names** (Crispin)
The task names the section "Merge guard". The check says `grep -n "merge-guard"` shows "the section heading". A heading with a space and a capital M is not matched. It passes only if the heading also contains the flag text, and the task does not say so.

**F4 (MAJOR, not blocking): "byte-identical" is checked against a start-text constant** (Wiegers)
Task 10 asserts the S5a and Wave 6 pre-push sentences are byte-identical. It compares them with constants taken from "the literal start text" recorded in Task 1. A start-text constant only proves the prefix, so an edit later in either sentence would pass.

**F5 (MAJOR, not blocking): nothing says what happens after release holds on a draft PR** (Nygard)
Task 8 says release happens before reply, resolve and the re-trigger, with one retry. The decision table can also return `HOLD` after a completed push, for example when the PR head read still shows the old commit. The text does not say whether the run then replies, resolves and re-triggers anyway. That would post re-triggers on a PR that G5 says reviewers may skip.

**F6 (MINOR): "one single place" for minting the cycle id is unclear** (Fowler)
Task 1 wants one place. Task 10 has the Wave 3 bullet mint it, and the Wave 8 bullet engages with kind `ci`. The reading that works is one minting rule covering both kinds, but the text does not state it.

**F7 (MINOR): the scenario tests prove their own driver, not the protocol** (Whittaker)
Task 11 builds a test driver that applies the decisions, then asserts on what the driver did. Examples are "no push after `pr_not_open`" and "release before re-trigger". The ordering in `SKILL.md` and the ref is covered only by the wording tests of Tasks 8 to 10.

**F8 (MINOR): the force-push constraint names a narrower scope than the test applies** (Crispin)
The constraint covers only "a new `SKILL.md` line". `test_skill_forbids_force_push` scans every `.md` and `.sh` file under the skill directory, including the new ref and script.

**F9 (MINOR): two boundary cases are left out of Task 3 and Task 4** (Whittaker, Nygard)
The `fix_cycle_id` check names `n == 0` only, while the source says `n < 1`. A check that tests only zero would accept `-1` and produce `fix--1`. The `classify_toggles` boundary is shown only with `failed_mutations`. The case of exactly `run_toggles + unsettled + failed_mutations` plus one is not named.

**F10 (MINOR): a Task 13 check expects `git status` to list ignored files** (Crispin)
`git status --short` never lists gitignored `.claude/` mirrors.

**F11 (MINOR): already-draft PRs halt when the timeline is unreadable** (Nygard)
In the `engage_decision` table, row 8 (timeline unreadable, halt) comes before row 10 (already draft, skip). So an already-draft PR with a failed timeline call halts with `draft_guard_unavailable` even though nothing would be guarded. This is safe but forces `--merge-guard off`.
