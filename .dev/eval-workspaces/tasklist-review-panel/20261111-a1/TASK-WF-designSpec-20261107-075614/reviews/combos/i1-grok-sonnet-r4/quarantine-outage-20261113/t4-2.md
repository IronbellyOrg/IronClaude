### F1. The engage table and unreadable-timeline acceptance criterion require different outcomes

**Severity: MAJOR. Blocking. Category: contradiction.**  
Perspectives: requirements, reliability and testing.

Task 4 requires all eleven incorporated engage rows, in order. Task 8 requires an unreadable timeline at engage to halt before any edit.

Consider an enabled guard in `RELEASED`, with baseline 0 and two counted transitions. A successful, complete read returns only one transition:

1. The classifier returns `unreadable`, as Task 4 expressly requires.
2. Incorporated engage row 8 does not match: the read is complete and its count is present.
3. Row 9 does not match: the classifier returned `unreadable`, not `foreign`.
4. Row 11 returns `ENGAGE`.

**An implementer who follows the stated text as written builds an engage function that proceeds on this short timeline, and that function is wrong because Task 8 requires that same unreadable-timeline input to halt before any edit.**

This is an acceptance-criterion contradiction, not an inferred missing restriction. The existing `test_only_a_failed_or_incomplete_read_halts_at_engage` confirms that this distinction is real in the checkout.

**Required correction:** Make Task 4's incorporated table and Task 8's halt criterion agree on complete-but-short timelines. State the selected behavior once and test that exact case.

### F2. An already-held guard retains an earlier cycle's publication proof

**Severity: MAJOR. Blocking. Category: safety.**  
Perspectives: architecture, integration and adversarial sequence analysis.

Task 4 adopts engage row 7, which returns `NOOP(already_held)` whenever the guard is held. Task 3 checks publication using the guard's stored cycle id. Tasks 8 and 10 mint a new id for the next fixing cycle, but the incorporated row does nothing to transfer the held record to that id.

Concrete sequence:

1. The first fixing cycle pushes commit A. Its release read is unavailable, so the PR remains held.
2. A later fixing cycle starts and receives a new cycle id. Engage returns `NOOP` because the guard is already held.
3. That later cycle applies local edits, then crashes before starting its push.
4. On resume, there is no dangling push. The stored guard still names the first cycle, whose completed push makes `published=True`.
5. The first cycle's target A still matches the PR head. The resume release check can therefore mark the PR ready while the later cycle's fixes remain unpublished.

**An implementer who follows the stated text as written builds a guard that can release a later fixing cycle using an earlier cycle's completed push, and that guard is wrong because the goal requires publication of the cycle whose fixes are currently protected.**

The existing `test_a_held_guard_follows_the_next_cycle` addresses precisely this boundary. Its rebinding behavior is absent from the incorporated eleven-row contract.

**Required correction:** Replace the unconditional already-held outcome for a different cycle with a durable transfer of the held record to the current cycle, preserving ownership and counters. Test a crash after later-cycle edits but before its push, with an earlier completed push still in the log.

### F3. Historical failed calls leave allowance that can hide a person's draft changes

**Severity: MAJOR. Blocking. Category: safety.**  
Perspectives: event accounting, reliability and adversarial accumulation analysis.

Task 3 requires the incorporated fold effect table. Failed mutations increment `failed_mutations`; confirmed changes increment `run_toggles`; confirmed unchanged results add no toggle. The table leaves historical failure allowance available after successful retries. Task 4 accepts observed transitions up to the counted transitions plus that allowance.

Concrete sequence under those fold rows:

1. Two completed cycles each have a failed ready attempt that changes nothing, followed by a successful retry.
2. A third cycle engages. The run has made five actual transitions, and the fold still has two failed-mutation allowances.
3. A person marks the held PR ready and then draft again. Observed transitions become seven; the PR is draft.
4. Seven equals five counted transitions plus two allowances. The classifier returns `ok`, not `foreign`.
5. After publication, the guard can mark ready a PR that the person deliberately returned to draft.

**An implementer who follows the stated text as written builds a classifier that accepts this person's ready-then-draft round trip as historical failure allowance, and that classifier is wrong because the specified foreign-toggle behavior must disable the guard rather than undo the person's draft decision.**

The checkout's `test_a_resolved_failure_no_longer_widens_the_count_for_a_persons_toggles` verifies the necessary distinction. The candidate also explicitly requires no added toggle for unchanged confirmations, so correcting landed failed calls must distinguish the current call's `changed` result from accounting for an earlier call.

**Required correction:** Specify how confirmation resolves earlier failed attempts for the same cycle and direction. Remove resolved uncertainty, account for a failed call that actually landed, and test the two-cycle failure accumulation followed by a person's round trip.
