## Findings

**F1 (blocking). Draft timing contradicts itself.** The Goal says the PR turns draft "as soon as" a Medium-or-higher finding is routed to a fix. The owner decision fixes engage "at the end of Wave 3", and Tasks 8 and 10 repeat that.
An implementer who follows the Goal as written engages at the moment of routing, and that is wrong because the owner decision fixes engage at the end of Wave 3. In practice the window is small, since no edit lands before the end of Wave 3, but the two timings cannot both be built.

**Medium, follow-up:**
- **F2. Wave 0 bullet wording.** The bullet must "carry no L3 or draft condition", yet it must also say "at L3 with `--merge-guard off`" and "no draft call is made". The acceptance test "fails when it names an L3 or draft condition" and "passes on the real file", which must contain the L3 clause. An implementer must guess which tokens the test forbids.
- **F3. Toggle count has no baseline.** Task 4 paraphrases the foreign-toggle rule as "observed transitions", without the baseline subtraction the source defines (observed = transitions minus baseline). No acceptance case uses a non-zero baseline. An absolute count passes every listed test, then reports a PR with earlier toggles as `user_override` and leaves it draft.
- **F4. OR read as AND.** The `guard_status` acceptance reads "mode `OFF` and ordinal below 3". The source and Task 3's body mean OR. Under the AND reading, mode off at ordinal 3 with no record reports `released`, not `off`.
- **F5. No engage trigger for CI-fix cycles.** The Wave 8 bullet says a CI-fix cycle engages but gives no trigger. The only trigger stated is a Medium-or-higher verified finding, and CI failures are not findings.
- **F6. Classification scope is narrower than the constraint.** Constraint 22 requires entries for git write verbs. Tasks 7, 8, 10 and 12 classify only `gh pr` and `gh api` lines. The ref may contain git lines, so an unclassified git write line would fail the classification test.
- **F9. No base commit named.** Task 1 records the base state "before any code edit", but names no base commit. This checkout already has the feature code, so a record taken here is not a base record.

**Minor:**
- **F7.** The clear command is spelled two ways: `gh pr ready <N> --repo "$REPO"` (Task 8) and `gh pr ready <N> --repo <REPO>` (Task 13). Task 12 asks for "the exact clear command" without choosing one.
- **F8.** Task 13's acceptance lists gitignored `.claude/` mirrors among what `git status --short` shows. Gitignored paths never appear there.
