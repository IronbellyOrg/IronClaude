**F1 (Medium, label MAJOR): the Task 12 grep check can miss the section heading it names.**
- Task 12 asks for a section called "Merge guard", and its criterion says `grep -n "merge-guard"` shows the section heading.
- A heading written "Merge guard" does not contain the hyphenated string, so the grep would not show it.
- Why not blocking: the implementer can title the heading "Merge guard (`--merge-guard`)", which the text allows.

**F2 (Medium, label MAJOR): the Task 9 Wave 0 bullet wording and its test criterion pull in different directions.**
- The bullet must say that "at L3 with `--merge-guard off`" the unprotected line is printed.
- The criterion says the test fails when the bullet "names an L3 or `draft` condition".
- The body of Task 9 narrows this to "no `L3 only` or `draft` gate wording", which can pass.
- Why not blocking: the intent is that the resume-loading part has no L3 gate. An implementer who writes the test from the broader criterion text would reject the mandated sentence.

**F3 (minor): the byte-identical checks in Task 10 only have the start text to compare against.**
- Task 10 asserts the S5a re-trigger sentence and the Wave 6 pre-push sentence are "byte-identical".
- Task 1 records only their "literal start text".
- A constant holding only the start of a sentence cannot prove the whole sentence is unchanged.
- The existing exact-text pins already cover the full sentences, so the risk is small.

**F4 (Medium, label MAJOR): where a CI-fix cycle id is minted is not stated.**
- Task 8 says the cycle id is minted "in the single place named by Task 1 O1".
- Task 10 puts the minting in the Wave 3 bullet.

- The push triad and `rereview_requested` of a CI cycle need that id to match.
- Why not blocking: the requirement is missing, not contradicted. Task 1 O1 is meant to settle it, and the implementer can reuse the same mint point.

**F5 (minor): Task 13 requires staging that its steps never perform.**

- None of the Task 13 steps runs `git add .dev/tasks`.
- This matches the repo rule that `.dev/tasks/` is always staged, but the step is missing from the task body.
