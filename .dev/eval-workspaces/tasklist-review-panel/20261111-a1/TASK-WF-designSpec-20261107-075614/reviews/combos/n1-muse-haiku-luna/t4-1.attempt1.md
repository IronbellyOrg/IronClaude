An implementer who compares the raw count marks a human toggle made before the run as `foreign` and disables the guard for that run. The text never says what the `requested` event stores to make the delta possible.
- **M4 (ordinals 0 to 2 may read GitHub).** Constraint 25 says ordinals 0 to 2 change "only by one report line", and the scenario list says they "make no call". Task 8 loads Resume "at every ordinal", and `resume_decision` takes a live `read` as input. The text does not say whether a read happens below ordinal 3, so an implementer can make a GitHub read at ordinal 2 on `--resume`.

Under the rules, the protocol cannot be built from this text alone.

The row-level acceptance tests therefore cannot be checked from the candidate. I did not treat this as "incomplete", because the candidate itself is readable and hashed.
