**F1 (Medium). The Wave 0 bullet test can be read as forbidding the very sentence the bullet must contain.** Task 9 requires the bullet to carry the literal line for the `off` case at L3, and its acceptance criterion says the test fails "when it names an L3 or `draft` condition". Grading check: an implementer who follows the stated text as written builds a test that rejects any L3 mention in the bullet, and that test is wrong because the bullet is also required to contain the L3 `off` sentence. This needs the guess that the implementer checks the whole bullet rather than only the loading clause, so it is Medium. The fix is one clause: say the gate check applies to the loading sentence, with the `off` sentence excluded.

**F2 (Medium). `resume_decision` is given no inputs for the `release_decision` call its row 4 must make.** Task 4 fixes the resume signature as `(mode, ordinal, guard, read, pending, dangling_branch, published)`, while `release_decision` also requires `cycle_id`, `applied_edits` and `target_sha`; the fold fields listed in Task 3 include `cycle_id` but no `target_sha`. Grading check: an implementer who follows the stated text as written builds a resume function that cannot supply a head proof, and releases or holds on a guessed `target_sha` instead of the held cycle's recorded one. This needs the guess that the implementer does not add optional parameters the text does not forbid, so it is Medium. The fix is to name the extra inputs, or state that the protocol layer, not the pure function, supplies them.

**F3 (Medium). The artifact location and the final staging check do not quite meet.** Task 1 creates `./artifacts/pre-build-gate.md` "in this package", Task 13 writes `./artifacts/final-checks.md`, and Task 13's acceptance criterion allows changes only under `src/superclaude/`, `tests/`, `docs/user-guide/`, `.dev/` and `.claude/` mirrors, plus requiring `.dev/tasks` to be staged even though no task body gives the staging step. Grading check: an implementer who follows the stated text as written writes the artifacts at the repository root, and the final `git status --short` check then fails on a path its own task created. This needs the guess that `./artifacts` resolves to the repository root rather than the package folder under `.dev/tasks/`, so it is Medium. The fix is to write the package-relative path in full in Tasks 1 and 13.

**F4 (Medium). The Wave 8 bullet and its test omit the engage trigger that the Wave 3 test pins.** Task 8 makes engage conditional on a verified Medium-or-higher finding routed to a fix, and Task 10's Wave 3 test fails if that trigger phrase is deleted; the Wave 8 bullet text and its test assert only the `ci` kind and the release order, with no trigger. This needs the guess that the reader follows the bullet summary instead of the ref it loads, so it is Medium. The fix is to repeat the trigger phrase in the Wave 8 bullet and assert it like the Wave 3 test does.

**F5 (Minor).
