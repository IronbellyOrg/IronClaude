### follow-up candidates

**F1, Medium (label MAJOR, not blocking). Resume can mark the pull request ready without proving the head.** Task 4 lists `resume_decision` inputs as mode, ordinal, guard, read, pending, dangling branch, and published. Row 4 re-enters release with `push_completed` true. Task 11 requires that a normal completed push, with no dangling window, releases. Release itself returns ready immediately when this cycle's edit count is zero, and only afterwards checks that the head matches. Nothing in the resume inputs carries that edit count or the target commit. A zero count on this path marks the pull request ready even if the head moved. The release rows already say a real push must match the head. The resume signature needs those two values, and a missing target must hold, not release.

**F2, Medium (label MAJOR, not blocking). The new script's repo check fights the required fallback.** Task 7 says every `gh` call carries `--repo "$REPO"` or a `repos/${REPO}/` path, and the new test asserts that of every `gh` line. The same task says the script follows `retrigger-review.sh` and must pass the `_RESOLUTION_SCRIPTS` tests. Those tests require a `gh repo view --json nameWithOwner` line that runs only after the origin remote fails, which is when the repo name is still empty. The existing scope check allows that one line. The new wording does not. Use that existing check, and do not put `--repo` on the discovery line.

**F3, Medium (label MAJOR, not blocking). The Wave 0 acceptance line rejects the bullet it requires.** The bullet must say `at L3 with --merge-guard off` and `no draft call is made`, and it must apply at every ordinal. The acceptance line says the test fails when the bullet names an L3 or draft condition. The task's own test sentence is narrower: it fails on `L3 only` or draft-gate wording. Write the test to the narrower sentence, or the required bullet cannot pass.

**F4, Medium (label MAJOR, not blocking). A ready request that never landed is specified as held without the earlier phase.** Task 3 says any `not_applied` settle restores the phase from before the request, and a first draft request then `not_applied` erases the record. It also says a ready request followed by `not_applied` gives phase `HELD`. That is true only after a held phase already exists. State that earlier held record in the test, or the case contradicts the erase rule.
