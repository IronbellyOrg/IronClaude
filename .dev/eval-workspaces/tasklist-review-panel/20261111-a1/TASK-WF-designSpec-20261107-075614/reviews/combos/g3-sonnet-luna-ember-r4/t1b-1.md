## Findings

All findings are Medium or minor, so none is blocking. Each one needs a reader guess or concerns a requirement the plan never states. I did not write the blocking sentence for any of them, because none holds without a further assumption.

**F1 (Medium, missing-requirement). Engage-failure halt message dropped.**
- `source.md` section 5 says the message names `--merge-guard off` and prints the clear command.
- Task 8 and its phrase checks keep only the `terminal_halted` reason `draft_guard_unavailable`.
- An implementer following Task 8 builds a halt with no way out. This matters because the `gh pr ready --undo` plan-support gate (G1) is still OPEN.

**F2 (Medium, other). The type of `guard` is never stated.**
- Task 5 asserts `state["draft_guard"]["phase"] == "held"`, which needs a dict.
- Tasks 3 and 4 use attribute access (`guard.phase`, `guard.owned_draft`), which suggests a dataclass like `GuardRead`.
- An implementer who builds a frozen dataclass fails the Task 5 check. Stating "dict" once in Task 3 fixes it.

**F3 (Medium, other). Wave 0 bullet wording conflicts with its own test.**
- Task 9 requires the bullet to say "at L3 with `--merge-guard off`", to say "no draft call is made", and to carry "no L3 or `draft` condition".
- The test "fails when it names an L3 or `draft` condition".
- A literal substring check fails the required text. The intended reading is "the load is not gated".
- The test should be pinned to gating phrases such as `L3 only` and `only with draft`.

**F4 (Medium, other). The CI-fix cycle id has no stated mint site.**
- Task 1 and Task 8 want one single place that mints the id, "at the end of Wave 3".
- A CI-fix cycle starts in Wave 8, after that point.
- The Task 10 Wave 8 bullet says "engages with kind `ci`" but not where `ci-<n>` is minted.
- If it is minted separately from the push triad's id, `held_cycle_published` stays false and the PR stays draft after a good CI push.

**F5 (Medium, other). A held earlier cycle can be released by a later zero-edit cycle.**
- Task 4 requires `release_decision` to return `RELEASE(no_edits)` for `applied_edits=0` when the guard record holds an earlier fixing cycle.
- The tables test `applied_edits` before the publication check.
- If a resumed run continues with an unpublished earlier fix still held, a later zero-edit cycle makes the PR ready while the earlier fix is local only.
- This needs the "continue after an unpublished cycle" path, which the plan neither shows nor forbids.

**F6 (minor, missing-requirement). The `--read` output has no stated conversion to `GuardRead`.**
- `autoMergeRequest` is an object or null from `gh`, while `GuardRead.auto_merge_armed` is a bool.
- The field names also differ (`isDraft` vs `is_draft`, `headRefOid` vs `head_sha`).
- Neither Task 3 nor Task 7 says who converts, or that the script emits a bool.

**F7 (minor, missing-requirement). The exit code for `error:"not_open"` is unstated.**
- The Task 7 exit-code list covers 0, 1, 2 and 127, but not `not_open`.

**F8 (minor, other). "Exact event order" in the Task 11 trace.**
- A real cycle also writes `push_decision` and `push_initiated` between `fix_applied` and `push_completed`.
- The check should say "in this order as a subsequence".

**F9 (minor, other). "Every `gh` line" in Task 7's static scan.**
- Read literally, this also catches `command -v gh` and the `die "gh CLI not found"` line.
- Limit the scan to `gh pr`, `gh api` and `gh repo` command lines.
