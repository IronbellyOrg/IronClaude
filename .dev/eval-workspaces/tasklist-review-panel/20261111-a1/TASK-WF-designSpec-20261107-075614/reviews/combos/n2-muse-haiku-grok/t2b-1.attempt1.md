## Follow-up candidates

### F1 (Medium): Resume row 4 has no stated input for the head proof or the edit count

Grading check: An implementer who follows the stated text as written builds a `resume_decision` with exactly the listed parameters, and that function is wrong because re-entering `release_decision` needs `applied_edits` and `target_sha`, which are not among them and are not supplied by the `guard` fold fields listed in Task 3 either. This needs a guess to be harmful: the implementer could add optional parameters fed from the push record (the reading the shipped code in `src/superclaude/pr_submit/merge_guard.py` in fact took), could pass `target_sha=None` and so never release on resume, or could pass the live head as its own target and so release without any head proof. Because the worse outcomes depend on that choice, this is Medium, not blocking. The fix is one clause in Task 4 and one in the Resume part of Task 8 naming where `target_sha` and the edit count come from on resume.

### F2 (Medium): The Wave 0 bullet is told both to carry no L3 or draft condition and to state the L3 `off` behaviour

Grading check: An implementer who follows the stated text as written builds a Wave 0 bullet that states the behaviour at L3 with `--merge-guard off`, and that bullet is wrong because the Task 9 acceptance criteria say the Wave 0 test fails when the bullet names an L3 or `draft` condition. This also needs a guess: the task body that specifies the test itself narrows the check to the phrases `L3 only` and `draft` gate wording, so an implementer who builds the test from that narrower sentence gets a passing pair. The acceptance bullet and the test-specification sentence should be made to say the same thing.

### F3 (minor): Byte-identical is asserted from literal start text only

Task 1 records the literal start text of the S5a sentence and of the Wave 6 pre-push sentence, and Task 10 then asks for those sentences to be asserted byte-identical by comparing the live text with string constants. A start-text constant proves a prefix, not the whole sentence, so a change after the recorded prefix would pass. An implementer can still recover the full pinned sentences from the existing pins found under O3, which is why this is a note rather than a defect.

### F4 (minor): The final task requires a staged `.dev/tasks` but lists no staging step

Task 13 enumerates the final commands (`make sync-dev`, `make verify-sync`, `make lint`, format check, full suite, the two sync test files) and then writes `./artifacts/final-checks.md`, while its acceptance criteria require `.dev/tasks` to be staged with `git add .dev/tasks`. If the executing protocol does not stage the package itself, the last acceptance check fails on a step no task performs. One line in Task 13 closes it.
