## Blocking findings

### F1. Resume cannot release a landed or normally completed push, because no head proof reaches `release_decision`

An implementer who follows the stated text as written builds `resume_decision(*, mode, ordinal, guard, read, pending, dangling_branch, published)` with no `target_sha` and no per-cycle `applied_edits` argument, and that is wrong because its row 4 must re-enter `release_decision`, which can release only when the live head equals `target_sha` (and must not release through the zero-edit row for a cycle that did push). With no target SHA supplied, the re-entered call has nothing to prove the head against, so the crash cases the plan itself requires to release, a dangling push that landed and a push that completed normally before the crash, hold the PR as a draft instead. Passing the live head as its own target would instead release on a moved head, which the plan's moved-head case forbids. Task 8's Resume section and Task 9's Wave 0 bullet also never say where the held cycle's `target_sha` comes from (its push record) or that resume passes it, and the folded guard fields listed in Task 3 do not carry it. The repository's implemented `resume_decision` confirms the missing inputs: it accepts `target_sha`, `applied_edits` and `cycle_id`, defaults `target_sha` to `None`, and with no target the head proof cannot succeed and the guard holds.
