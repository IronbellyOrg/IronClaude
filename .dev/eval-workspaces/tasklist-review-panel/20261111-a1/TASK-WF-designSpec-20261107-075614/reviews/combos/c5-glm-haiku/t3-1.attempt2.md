## Findings

=== CORRECTNESS / ADVERSARIAL ANALYSIS (Whittaker, Nygard) ===

**F1 (MAJOR, graded Medium, non-blocking).** Whittaker zero/empty attack on the timeline classifier. Grading sentence: "An implementer who follows the stated text as written builds a `classify_toggles` that classes a timeline as `unreadable` for 'short' with no defined threshold, and this is wrong because a young PR whose genuine timeline has few events can be classed unreadable (exit held, PR left draft) or a truncated one classed `ok`, depending on a floor the plan never gives." Blocking would require no guess about the implementer's choice; here the harm depends on which threshold they pick, so Medium. Recommendation (Wiegers): define "short" by an observable property (for example: fewer transitions than the run itself caused) or defer the literal rule text to source.md section 4.1 verbatim. Priority: High for follow-up.

**F2 (MINOR).** The `run_toggles` increment rule is never stated as a rule; it is only implied by AC phrases ("adds no toggle", "`foreign` when observed transitions exceed `run_toggles + unsettled + failed_mutations`", the `ok` test at "observed equals `run_toggles + failed_mutations`"). An implementer who restates section 4.2 faithfully is fine; one working from the plan alone must derive the counter semantics from test expectations. Note only.

**F3 (MINOR).** Whittaker sequence attack: `resume_decision` precedence is stated only as "row 2 wins over row 3". A log holding both an unsettled request and a dangling `push_initiated` has no stated row-2-vs-row-4 precedence. In the stated wave order the settle always precedes the push (settle is appended right after the draft mutation, push is Wave 6), so the combination appears unreachable; if it ever occurs the behavior is undefined. Note only.
