### F1. A failed attempt to make the pull request a draft can never be retried

Grading check: An implementer who follows the stated text as written builds a fold that records a failed draft attempt as `RELEASE_PENDING` with `owned_draft` left false, and an engage decision that then returns `HOLD(ownership_unproven)` for that state, and that is wrong because the next engage will not turn the pull request into a draft.

Task 3 requires every row of the design's effect table. That table sets a failed draft settle to `RELEASE_PENDING` and does not set `owned_draft`. The confirmed-draft rows are the ones that set `owned_draft` true, so after this failure it stays false. Task 4 requires all 11 engage rows, first match wins. Row 6 of that table is: phase `RELEASE_PENDING` and not `owned_draft` returns `HOLD(ownership_unproven)`. Rows 1 to 5 do not match a later engage at monitor level 3 with the guard on, a readable open pull request, and this folded state. Row 11, the row that would draft the pull request, is never reached.

The same phase is also what a failed "mark ready" uses. For that case, holding is right: do not mark the pull request ready when this run has not proved it owns the draft. For a failed draft attempt the pull request is still ready, and holding means this run will not try to draft it again. Resume does not repair it: the failure was settled, so nothing is pending, and resume row 9 is a no-op. The goal in the plan's opening paragraph is that the pull request is turned into a draft once a verified Medium-or-higher finding is routed to a fix. After one failed draft call, that stop is permanent for the rest of the log.

The first failure itself still halts before edits, as Task 8 says. The break is the next engage on that same log, including a resume.
