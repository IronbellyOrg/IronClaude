## Findings

1. **F1 (MAJOR, not blocking). A later cycle never rebinds a held guard.**
   - An implementer who follows the stated text as written builds `engage_decision` row 7 (`HELD` gives `NOOP(already_held)`) and `held_cycle_published` keyed to `guard.cycle_id`. That is wrong in one case: a cycle that ended `held` (for example an unreadable timeline, after which the run keeps pushing) is followed by a second cycle with a new id such as `fix-2`.
   - The guard keeps the old cycle id, so after a crash following the second cycle's `push_completed`, `published` is computed against the wrong cycle.
   - Resume then either does not release, or compares the head with the wrong `target_sha`. The PR stays draft even though both pushes landed. The outcome is safe but defeats the stated goal.
   - The live implementation had to add a `REBIND` action (`cycle_rebound`) for this. The plan's `GuardAction` list lacks it. I grade this Medium because it is a requirement the document never states and it needs a held cycle plus a crash.

2. **F2 (MAJOR, not blocking). The Wave 0 bullet is both "no L3 or `draft` condition" and "at L3 with `--merge-guard off`".**
   - Task 9 says the bullet "carries no L3 or `draft` condition". It also says the same bullet states that "at L3 with `--merge-guard off`" the line is printed and "no draft call is made". Its test must fail when the bullet "names an L3 or `draft` condition".
   - Reading A, which is the intended one: only the condition for loading the ref is forbidden. Reading B: the words `L3` and `draft` may not appear in the bullet at all, so the required `off` sentence fails its own test.
   - The text allows both readings. Medium.

3. **F3 (MAJOR, not blocking). No source is stated for `target_sha` when resume re-enters the release step.**
   - `resume_decision` has no `target_sha` parameter. Row 4 "re-enters `release_decision` with `push_completed=True`", and `release_decision` row 8 compares the head with `target_sha`.
   - For a normal `push_completed` there is no dangling window, so `resolve_crash_window` does not run. Neither Task 4 nor the Resume section of Task 8 says where `target_sha` comes from.
   - An implementer can pass the wrong cycle's sha, and the release holds (see F1). The live ref had to add "from its push record". Medium, missing requirement.

4. **F4 (MAJOR, not blocking). A static check, "every `gh` line carries `--repo` or a `repos/` path", cannot pass as literally worded.**
   - The `_RESOLUTION_SCRIPTS` tests, which the same task requires the script to pass, need a script line starting `REPO=` or `[ -n` that contains `gh repo view --json nameWithOwner`. That line has neither `--repo` nor `repos/`. A `command -v gh` line fails the same way.
   - Task 7 never names that fallback line. An implementer who writes the scan literally fails on the required line. One who reuses `_repo_scoped` from `test_static_grep.py` passes, because that helper exempts the `gh repo view` idiom.
   - The text allows both readings. Medium.

5. **F5 (MINOR). The cycle-id "single place" conflicts with the CI-fix wording.**
   - Task 8 puts the mint in "the single place named by Task 1 O1" and lists CI-fix cycles under "Engage at the end of Wave 3".
   - Task 10 has the Wave 8 bullet say a CI-fix cycle "engages with kind `ci`" at Wave 8.
   - Whether a CI-fix cycle goes back through the end of Wave 3 is not stated, so there may be two mint sites. Task 1's O1 should settle this, but the plan text does not.

6. **F6 (MINOR). Classification steps name only `gh pr` and `gh api` lines.**
   - The Task 8, 9, 10 and 12 classification steps cover `gh pr` and `gh api` lines only. The constraint and `WRITE_VERB_RE` also cover `git add|commit|push|merge|stash|update-ref|worktree add|remove`.
   - A ref or `SKILL.md` line that says "git push" or "git commit" would be an unclassified hit. The per-task test run catches it, so this is a wording gap.

7. **F7 (MINOR). `auto_merge_armed` is produced but never consumed.**
   - `engage_decision` puts `auto_merge_armed` in `notes`, but no task text says what the SKILL does with it.
   - Gate G4 (disarming auto-merge) is a release gate, so this is acceptable for now. A line in the Engage section would close it.
