**F1 (MAJOR, Medium, not blocking, category: contradiction) - Wiegers/Whittaker, priority Medium.**
Task 9 mandates a Wave 0 bullet that "carries no L3 or `draft` condition" yet must state "at L3 with `--merge-guard off` ... no draft call is made", while its acceptance criterion demands a test that "fails when it names an L3 or `draft` condition".
Grading check: an implementer who follows the stated text as written builds a compliant bullet containing "at L3" and the word "draft", and a test that fails whenever the bullet names an L3 or draft condition, and that test fails on the mandated bullet content. The sentence holds only under the strict reading; the same task's "gate wording" phrasing and the "passes on the real file" clause allow the narrower reading (forbid only gating phrases like `L3 only` or `--merge-guard draft`), and pytest iteration forces convergence, so this is a two-readings ambiguity, not a blocking contradiction.

**F2 (MAJOR, Medium, not blocking, category: missing-requirement) - Whittaker, priority Medium.**
Task 3 states the ids must never collide with `CONFLICT_CYCLE_PREFIXES` (which are `sync-` and `conflict-`), but mandates `ValueError` only for kind `sync` and `n == 0`; kind `conflict` (or any future kind string starting a banned prefix) is accepted and mints a colliding id.
Grading check: an implementer who follows the stated text as written builds `fix_cycle_id` rejecting only `sync` and `0`, and that function is wrong because `fix_cycle_id("conflict", 1)` returns `conflict-1`, colliding with the conflict-cycle namespace. The harm needs a caller passing kind `conflict`, which no stated text does, so it is a missing restriction, graded Medium.

**F3 (MINOR, note, category: other) - Nygard, priority Low.**
Task 7 defines exit codes 0/1/2/127 but leaves the exit code for the `not_open` and `verify_failed` outcomes unspecified (1 is defined only for "a failing `gh`"). Implementer picks one; tests assert the JSON, not the code.
