## Findings

**F1 (Medium, not blocking): the Task 7 static scan, read literally, flags a line the same task requires.**
- Task 7 requires `test_set_draft_state.py` to assert "every `gh` line carries `--repo` or a `repos/` path".
- The same task requires the script to pass the `_RESOLUTION_SCRIPTS` tests. Those tests look up a `gh repo view --json nameWithOwner` fallback line in the script, and that line has neither `--repo` nor `repos/`.
- The shared predicate `_repo_scoped` in `tests/pr_submit/test_static_grep.py` accepts that line explicitly, so the contradiction goes away if the scan reuses `_repo_scoped`.
- An implementer who writes the scan from the stated words builds one that fails on the required fallback line. They then have to guess whether to exempt it or drop the line. That guess is why this is Medium, not blocking.

**F2 (Medium, not blocking): Task 9 says the Wave 0 bullet has no L3 condition and also requires an L3 sentence in it.**
- Task 9 says the bullet "carries no L3 or `draft` condition", and the test "fails when it names an L3 or `draft` condition".
- The same bullet must state that "at L3 with `--merge-guard off`" the notice is printed once.
- A reading that makes both true exists: only the load-the-ref part is unconditional, and the `off` notice may carry its L3 condition. A test written from the acceptance wording instead rejects the required sentence. The implementer has to choose between the two readings.

**F3 (minor): Task 10's byte-identical check uses only the "literal start text".**
- The acceptance criterion says the S5a re-trigger sentence and the Wave 6 pre-push sentence are asserted byte-identical by comparing against constants, which are the "literal start text".
- A start-text comparison cannot catch an edit made later inside the same sentence, so the "never inside the pinned sentences" rule is not fully enforced.

**F4 (minor): "exact event order" in the Task 11 acceptance trace is ambiguous.**
- A real push cycle also appends `push_decision` and `push_initiated` between `fix_applied` and `push_completed`.
- A whole-list equality on the seven named events fails with a real triad. The test needs to be a filtered subsequence check, and the text does not say so.

**F5 (minor): Task 3 says the module "imports only" four names.**
- Other modules in `pr_submit` start with `from __future__ import annotations`. A literal "only" check would reject it. The statement should say "no other package imports".
