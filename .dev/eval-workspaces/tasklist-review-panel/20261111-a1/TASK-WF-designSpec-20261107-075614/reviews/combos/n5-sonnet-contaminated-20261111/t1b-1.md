No finding passes the grading check for blocking. Each needs a guess about which of two allowed readings an implementer picks, or concerns a requirement the plan leaves unstated.

**F1 (Medium, not blocking): "every `gh` line" in Task 7 cannot be read literally.**
- An implementer who follows the stated text as written scans every line of `set-draft-state.sh` that contains `gh` for `--repo` or a `repos/` path.
- That scan is wrong because the required origin-URL fallback line (`gh repo view --json nameWithOwner ...`) and `command -v gh` carry neither.
- The same task requires the script to pass the `_RESOLUTION_SCRIPTS` tests, which demand that fallback line.
- The existing `_repo_scoped` predicate exempts the fallback idiom. Task 8 says to reuse that predicate, but Task 7 does not.
- Under the sensible reading (gh command lines, with the resolution idiom exempt) it passes, so I graded it Medium.

**F2 (Medium, not blocking): the Task 9 Wave 0 bullet is told to carry no L3 condition and also to say "at L3 with `--merge-guard off`".**
- Read literally, the planned test "fails when it names an L3 or `draft` condition" would fail on the required off sentence.
- Only the loading must be unconditional; the print is L3-only. The text does not say that.

**F3 (Medium, not blocking): the CI-fix engage trigger is unstated.**
- Task 8's Engage section applies "only when at least one verified finding of Medium severity or higher is routed to a fix" to CI-fix cycles too.
- Task 10's Wave 8 bullet engages a CI-fix cycle unconditionally. A CI failure is not a verified review finding, so a CI-fix cycle never engages under the first reading.
- The plan never says which reading is meant, so an implementer could build either. The test only checks that the Wave 8 sentence exists.

**F4 (minor):** the last acceptance criterion says `git status --short` lists gitignored `.claude/` mirrors. Ignored files never appear there. Harmless, but not checkable as written.

**F5 (minor):** `fold_draft_guard` is specified to return `None` "when no guard record exists". The case list also makes it return `None` after a lone draft request settled `not_applied`, which leaves guard records in the log. The explicit case wins, but the sentence is loose.
