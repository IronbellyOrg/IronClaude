## Findings and grading

**F1 (Medium, missing-requirement).** Grading check: "An implementer who follows the stated text as written builds `fix_cycle_id` that rejects only kind `sync` and `n == 0`, and this is wrong because `CONFLICT_CYCLE_PREFIXES` is `("sync-", "conflict-")`, so `fix_cycle_id("conflict", 1)` would mint `conflict-1`, which `is_conflict_cycle` classifies as a conflict cycle while the guard treats it as its own." The sentence needs the guess that the implementer tests only the kinds the criterion lists rather than honoring the prose constraint for both prefixes, so it is Medium, not blocking. The implemented module and the plan's own constraint both point the right way; the gap is only in the criterion's coverage.

**F2 (Medium, missing-requirement).** Grading check: "An implementer who follows the stated text as written builds Tasks 3, 4, 8 and 11 exactly as the plan states them, and this is wrong because..." does not complete: nothing in the repo contradicts the row counts. The real weakness is that Task 1 verifies pins by reading code but never records the `./source.md` section 4.1/4.2/5/7 tables, so plan-vs-source drift in the row counts or the twelve test names would be invisible until implementation. That is a requirement the document never states, so Medium.

**F3 (minor).** Task 2's criterion "no remaining claim that the enum has 43 members" is judgment-based: `models.py` keeps the historical comment "the 42nd-43rd", which contains `43` but is not a size claim. The natural reading passes; noted for the implementer.

**F4 (minor).** Task 13's `git status --short` criterion lists "gitignored `.claude/` mirrors" among the changes it shows; git status does not list ignored paths, so that clause can never fire as written. The staging assertions around it are the real check and are correct.

**F5 (minor).** Task 9 requires the Wave 0 bullet to contain no `draft` condition while the same bullet must name `draft_guard_requested`/`draft_guard_settled`; only the "gate wording" reading (no `--merge-guard draft`-mode gate) is coherent. The implemented test resolves it this way.

**F6 (minor).** Task 11's parenthetical "pytest would collect it twice" is inaccurate as a mechanism (importing an already-collected module does not double-collect); the no-test-import rule it justifies is still the safe practice.

No finding passes the blocking test: no two stated texts contradict each other, no stated text causes data loss or crosses a security/safety boundary (the plan's own regime keeps every mutation behind repo-scoped calls and fake-gh tests), and every acceptance criterion I could execute against the repo passes as written.
