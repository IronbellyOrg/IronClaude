## Blocking finding

**The resume API cannot prove that a published push reached its recorded target.**

An implementer who follows the stated text as written builds a resume decision that may mark a PR ready without verifying the head against the push’s recorded `target_sha`, and that is wrong because a push for the held cycle is not proof that the PR head equals that push’s target. Task 4 gives `resume_decision` only `mode`, `ordinal`, `guard`, `read`, `pending`, `dangling_branch`, and `published`; the folded guard has no `target_sha`, and the read’s head is only the observed value. Yet the row 4 acceptance criterion requires resume to re-enter `release_decision` with `push_completed=True`, while release is allowed only when `read.head_sha == target_sha`. The scenario acceptance criterion also requires a normal completed push to release before the re-trigger. Without passing the recorded target SHA into resume, the implementation cannot verify that requirement; using the current read head as the target would make the check circular and could release after the head moved.
