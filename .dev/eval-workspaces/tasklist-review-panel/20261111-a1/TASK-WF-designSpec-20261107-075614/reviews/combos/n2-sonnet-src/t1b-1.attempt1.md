## Follow-up candidates (Medium and minor, none blocking)

1. **Medium, Task 9: the Wave 0 bullet is told to carry no L3 or `draft` condition, but its required content names both.**
   - The task says the bullet "carries no L3 or `draft` condition".
   - The same task requires it to say "at L3 with `--merge-guard off` ... no draft call is made".
   - The acceptance criterion says the Wave 0 test "fails ... when it names an L3 or `draft` condition".
   - An implementer who reads the criterion literally writes a test that rejects the required `off` sentence. The text allows a narrow reading: ban only gating phrases such as "L3 only" or "only at L3 with draft". The plan never says which reading to use.
   - Grade: Medium. The failing outcome needs the implementer to pick the worse reading.
   - Fix when convenient: state that the test rejects an L3 or `draft` condition on the resume-load clause only, and that the `off` sentence is exempt.
2. **Medium, Task 4 and Task 11: "once per cycle id" has no row or test in the pure decision table.**
   - The 11 engage rows return `NOOP` for `HELD`, but a `RELEASED` guard with the same `cycle_id` falls through to `ENGAGE` (row 11).
   - The only "once per cycle" assertions are in prose (Task 10) and in the name of a scenario test (Task 11). Task 4's acceptance criteria do not cover a repeat engage after release.
   - A second engage call for a cycle that was already released would re-draft the PR.
   - Grade: Medium. It is a requirement the document never states, not a stated text that does harm.
   - Fix when convenient: add one Task 4 test, or one row, for "same cycle id already released".
3. **Minor, Task 7: the exit code for `error:"not_open"` is not pinned.**
   - The criterion lists exit 1 for "a failing `gh`", and `source.md` also gives exit 1 for a failed verification.
   - A refusal because the PR is not open is neither case, so the script and its test may disagree on 0 versus 1.
