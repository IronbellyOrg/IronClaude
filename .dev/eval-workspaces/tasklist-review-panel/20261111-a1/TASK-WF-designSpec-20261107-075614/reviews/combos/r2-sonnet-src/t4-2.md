## Findings

### F1. Blocking. A published fix cannot be proved and released with the inputs the plan gives resume.

An implementer who follows the stated text as written builds `resume_decision` with only mode, ordinal, guard, read, pending, dangling branch and published, then re-enters `release_decision` with `push_completed=True` after a normal completed push, and that call cannot return release for a fixing cycle: the edit count is not zero, and the function has no target commit to compare with the live head. The scenario acceptance criterion that this path releases therefore cannot pass.

Task 4 closes the signature at `pending`, `dangling_branch` and `published`. The folded guard record it may read has no target commit either (phase, cycle id, baseline, toggle counters, owned draft, disabled cause). Task 4 also says release has nine rows and that a head different from the target commit holds. The only release that does not need the target commit is a zero-edit cycle. Task 11 treats that as a separate case, and a completed push is not that case: a zero-edit cycle is specified not to push. So a faithful re-entry holds, and `test_guard_crash_boundaries_and_push_recovery_abc` cannot pass.

The two escapes are both contrary to the same text. Passing an edit count of zero releases without checking the head, which Task 4 says must hold when the head differs. Copying the live head into the target makes every head match, so the pull request is marked ready even when the fix commit is not the head. The code on disk already widened this function with the edit count, the target commit and the cycle id. That widening is not in the plan.

This is a sequence attack on resume after push. The invariant "ready again only when this cycle's fix is confirmed on the pull request head" fails when published is true, the cycle had edits, and the target commit is not an input. Before: pull request draft, push recorded. After a faithful resume: still draft, criterion fails. After either escape: pull request ready without a head proof.
