**F1, Medium, missing requirement.**
- Task 4 gives `resume_decision` the arguments `mode, ordinal, guard, read, pending, dangling_branch, published` and says row 4 "re-enters `release_decision` with `push_completed=True`".
- `release_decision` also needs `cycle_id`, `applied_edits` and `target_sha`. The guard record holds no `target_sha`, and the candidate never says what row 4 returns.
- An implementer who follows the text builds a row 4 that cannot prove the head equals `target_sha`, or that guesses `applied_edits`. A guessed 0 would release through the zero-edit path with no head check. The text allows either reading, so this is Medium.
- The existing implementation had to add `applied_edits`, `target_sha` and `cycle_id` to this function.

**F2, Medium, missing requirement.**
- Engage row 7 returns `NOOP(already_held)` when a guard is already `HELD`, and the fold keeps one `cycle_id`.
- Take a cycle that stays held (validation failed, or the timeline was unreadable) while the run goes on to the next cycle. The next cycle's push is tagged `fix-2`, but `held_cycle_published` compares against the guard's old id.
- If the run crashes after that push, resume sees "not published", does nothing, and the PR stays draft with a `held` report. This fails safe but breaks the stated rule that a normally completed push releases.
- The text never says the guard follows a new cycle id. The existing implementation added a `REBIND` action for this.

**F3, Medium, contradiction between two checks.**
- Task 7 asks for a static scan that "every `gh` line carries `--repo` or a `repos/` path".
- It also requires the script to pass the `_RESOLUTION_SCRIPTS` tests. Those tests need a `gh repo view --json nameWithOwner` fallback line with no `--repo`, and the model script has `command -v gh`.
- Read literally, the scan fails on lines the same task requires. The existing `_repo_scoped` helper exempts the `gh repo view` idiom, and Task 8 points to that helper. So this is Medium: an implementer who reuses it passes.

**F4, minor.** Task 7's exit-code list does not say what `error:"not_open"` returns. The list covers success, a failing `gh`, usage errors and a missing dependency, but `not_open` is none of these.
