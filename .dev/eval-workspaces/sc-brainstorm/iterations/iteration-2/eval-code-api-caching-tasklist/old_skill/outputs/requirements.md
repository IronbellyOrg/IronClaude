## Phase 2 — Multi-Persona Analysis

### Architect

Build the cache as a coherency-aware layer. Structured keys, explicit invalidation events. The middleware is a thin shell over a coherency model. Important to design for the invalidation correctness up front — that's where stale-data incidents come from.

### Refactorer

Build a thin middleware over the existing Redis client. Reuse the SETNX lock primitive in `src/api/shared/locks.py` for stampede protection. Migrate the pricing LRU as the first real test. Don't over-engineer.

### Performance

Stampede protection is mandatory v1. Without it, a popular cached key expiring under load causes an upstream storm. Use the existing SETNX primitive. Also: outcome counter must distinguish hit/miss/bypass/degraded/stampede-waited.

### Backend

Cache lives between auth (so user tier is known) and rate limit (so cache hits don't consume rate budget). Pricing LRU migration should preserve function signatures.

### QA

Test invalidation under concurrent write/read. Test stampede. Test Redis-down chaos. Test pricing-migration parity.

## Phase 4 — Specification

### Functional Requirements

1. **FR-1**: Add a request-cache middleware enabled per route.
2. **FR-2**: Use a structured cache key including route, version, user tier, and params hash.
3. **FR-3**: Configure TTLs per data class (catalog/pricing/flags).
4. **FR-4**: Invalidate cached entries on relevant writes.
5. **FR-5**: Include stampede protection via SETNX.
6. **FR-6**: Migrate the per-instance LRU in `pricing.py` to use the shared cache.
7. **FR-7**: Emit cache outcome metrics (hit/miss/bypass/degraded).

### Non-Functional Requirements

1. **NFR-1**: p99 cache-hit latency ≤ 5ms.
2. **NFR-2**: Hit rate ≥ 70% sustained.
3. **NFR-3**: Graceful degradation if Redis is unavailable.

### Acceptance Criteria

- **AC-1**: A cached endpoint shows ≥50% p99 latency reduction on hit.
- **AC-2**: Stampede test (1000 concurrent first-callers) produces ≤2 upstream calls.
- **AC-3**: Redis kill mid-load → 100% requests succeed.
- **AC-4**: Canary at 10% traffic shows ≥40% upstream-spend reduction on cached routes.

### Open Questions for User

2. Should `X-Cache` response headers be exposed to clients?
3. Background-job access to the cache — in v1 or v1.1?
