# Requirements: Improve Onboarding Workflow for New Contributors

> Generated by `/sc:brainstorm "improve onboarding workflow for new contributors" --strategy agile --depth normal`
> Protocol: v1 (monolithic, in-context personas)

## Intro

The project wants more new contributors to stick around past their first PR. This brainstorm covers documentation, review process, and engagement levers.

---

## Phase 1 — Socratic Exploration

**Q1. Who is a "new contributor" here?**
A: Mostly external OSS first-time contributors. ~20-30 first-PRs/month.

**Q2. What's the current state?**
A: README is huge (2,400 lines), CONTRIBUTING.md is 14 months stale, "good first issue" is half-mislabeled, reviewer assignment is ad-hoc and review wait is around 2 weeks.

**Q3. What are the goals?**
A: Time-to-first-merged-PR median under 7 days (from ~21). Second-PR-within-60-days rate up to ~40% from ~25%.

**Q4. Any constraints?**
A: 4 maintainers, no new tooling to operate, no CLA, GitHub-only path must exist.

**Q5. Deadline?**
A: Soft — about 10 weeks until a conference talk.

**Q6. Has anything been tried before?**
A: A hackathon day 9 months ago (no lift) and a Notion dev-env page (8 page views, broken).

---

## Phase 2 — Multi-Persona Analysis

### Scribe

The 2,400-line README is too much. Split it into a small entry point, a "start here" walkthrough, and a real CONTRIBUTING.md. Existing content moves to `docs/` instead of being deleted. Write a 1-page reviewer rubric covering tone, must-fix vs should-fix, and a two-comment rule for first PRs. Audit `good first issue` against a written definition (≤30 LOC, no architecture, has acceptance criterion); publish the definition in CONTRIBUTING.md for ongoing triage.

### PM

The bottleneck isn't docs — it's review latency. 21-day median time-to-merge means contributors disengage before the docs even matter. Establish a First-PR Shepherd rotation: weekly, one maintainer is accountable for triage within 24h and decision within 7 days. Publish the SLA in CONTRIBUTING.md. Add a scorecard for visibility, not performance management.

### Mentor

Both of the above improve PR #1; neither addresses PR #2. Add a "second issue" handoff template — the shepherd posts a templated comment on every merged first PR with two suggested follow-up issues. Costs about 2 minutes per PR. Shift the primary technical Q&A surface from Discord to GitHub Discussions (searchable, no third-party account). Add tone-calibration examples to the rubric.

### Architect / Reviewer

The three proposals don't compete — they layer. Documentation handles the first 30 minutes. The shepherd rotation handles the first 7 days. The second-issue handoff handles the first 60 days. Sequence: stand up shepherd in weeks 1-2 (fastest signal), write docs spine in weeks 3-8, deploy handoff template in week 4 (once shepherd rotation is running).

---

## Phase 3 — Validation

All three interventions are feasible inside the 4-maintainer / 1-day-per-week budget. The conference deadline at week 10 is realistic for shepherd + docs + handoff. Measurement is the soft spot — second-PR-rate needs ≥60 days of lookback, so AC2 measures the cohort from weeks 1-4.

---

## Phase 4 — Specification

### Functional Requirements

- Three-tier documentation spine: README ≤200 lines, START_HERE.md (new), CONTRIBUTING.md rewritten.
- First-PR Shepherd weekly rotation among the 4 maintainers with 24h response / 7-day decision SLA.
- Review rubric at `docs/reviews/first-pr-rubric.md` with tone examples and the two-comment rule.
- Second-issue handoff template posted on every merged first PR by the shepherd.
- One-time `good first issue` audit with written definition in CONTRIBUTING.md.
- Shift primary Q&A from Discord to GitHub Discussions.
- Publish the SLA externally in CONTRIBUTING.md.

### Non-Functional Requirements

- Maintainer effort ≤ 1 day/week sustained.
- Measurable signal by week 10 for the conference talk.
- Zero broken external links during README relocation.

### Acceptance Criteria

- Time-to-first-merged-PR median ≤ 7 days over weeks 5-10.
- Second-PR-within-60-days rate ≥ 35% on weeks-1-4 cohort.
- Shepherd SLA hit rate ≥ 80% over weeks 3-10.
- Documentation spine shipped (README ≤200 lines, START_HERE.md exists, CONTRIBUTING.md rewritten).
- `good first issue` mislabel rate ≤ 10%.
- Top-5 recurring Discord questions answered in docs or routed to Discussions.

### Risks

- Shepherd rotation burnout.
- Metric gaming (fast harsh declines hurting second-PR rate).
- Spine rewrite stalling on the START_HERE.md mental-model diagram.
- External link breakage during README relocation.
