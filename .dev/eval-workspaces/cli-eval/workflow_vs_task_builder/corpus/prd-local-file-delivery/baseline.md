# Remove the PRD pipeline's `--file` local-path misuse (session-token crash fix)

## Task Overview

This task implements the bug-fix design spec `.dev/specs/prd-local-file-delivery-fix.md` (§5, **hardened Option B**) as a small, surgical change to the PRD CLI pipeline. The PRD pipeline is the only pipeline that passes the `claude` CLI's `--file` flag, and it passes **local filesystem paths** to it. `--file` is a **cloud download mechanism** (`file_id:relative_path`) that requires `CLAUDE_CODE_SESSION_ACCESS_TOKEN`; in a headless run (no session token) the `claude` subprocess exits 1 in ~0.3 s with `Error: Session token required for file downloads. CLAUDE_CODE_SESSION_ACCESS_TOKEN must be set.`, crashlooping the pipeline at `scope-discovery`. Sibling pipelines (roadmap / tasklist / validate) deliberately pass **no** `--file` and deliver all content inline (FR-003/FR-023).

The fix is two-fold: (1) **remove both `--file` emissions** from `src/superclaude/cli/prd/process.py` (the refs >50KB branch and the unconditional `--spec` branch), the now-empty `_build_file_args` method, its `extra_args` wiring, and the three dead module constants; (2) **upgrade `_authoritative_specs_block`** in `src/superclaude/cli/prd/prompts.py` to embed each spec's CONTENT inline via the existing `_read_file` (50KB cap + `_TRUNCATION_MARKER`) behind a **mandatory `Path(p).is_file()` guard** that falls back to a path-only line for missing/stale paths. Then invert/replace the `--file` tests, add content/truncation/missing-path/empty-input tests, and verify deterministically with a grep guard + `uv run pytest` + `make sync-dev && make verify-sync`.

Every edit is **surgical**: remove the `--file` plumbing exactly per the research-verified anchors, change only the non-empty body of `_authoritative_specs_block` (signature and call sites unchanged), and preserve the empty-input contract (`return ""` for `None`/`[]`) so no-spec prompts stay byte-identical. The dominant verification is the grep guard (`grep -rn '"--file"' src/superclaude/cli/prd/` → 0) + the `tests/cli/prd/` pytest subset + `make verify-sync` — encoded as concrete command items. QA gating is **FINAL_ONLY** (lite intensity): one final validation gate.

## Key Objectives

The following objectives MUST be achieved by this task:

1. **Zero `--file` in the PRD pipeline:** both `--file` emissions in `process.py` are removed, `_build_file_args` and its `extra_args` wiring are gone, the three dead constants are deleted (after a grep confirms zero external references), and `grep -rn '"--file"' src/superclaude/cli/prd/` returns 0 matches.
2. **Hardened inline spec delivery (Option B):** `_authoritative_specs_block` embeds each EXISTING spec's content via `_read_file` under a per-spec header, and falls back to a path-only line for any non-existent path via the mandatory `Path(p).is_file()` guard — never raising `FileNotFoundError`. The empty-input contract (`""` for `None`/`[]`) and the substrings `AUTHORITATIVE SPECIFICATIONS` and `MUST Read each one IN FULL` are preserved.
3. **Tests green:** the inverted `TestSpecFileAttach` asserts NO `--file`; new tests confirm content-inline + truncation + missing-path-no-raise + empty-input parity; `uv run pytest tests/cli/prd/ -q` is GREEN.
4. **Drift guard clean:** `make sync-dev && make verify-sync` exit clean (a no-op for a cli-only change, but must stay clean), and the change is confined to `src/superclaude/cli/prd/{process.py,prompts.py}` + `tests/cli/prd/`.
