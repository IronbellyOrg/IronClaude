2. **FR-16 release retry is untested and unbounded (MAJOR).** Spec section 7 (source.md:315) names a test for "one retry, already_in_state counts as confirmed, release_pending". Plan Task 8 states "one retry" in prose only (plan:124). Task 8's phrase checks (plan:129) omit it. Task 11 lists the test name (plan:168) but no case body (plan:166). `settled(ready, failed)` returns `RELEASE_PENDING` (source.md:205), and `release_decision` accepts that phase (source.md:147-157). No decision row therefore enforces the one-retry bound.

3. **Crash boundaries are narrower than the spec (MINOR).** Spec section 7 (source.md:318) requires crash before and after each request and settle. Task 11 covers only the crash between request and settle (plan:166), plus the branch and publish cases (plan:171).

5. **Classification scope is narrower than the constraint (MINOR).** Plan line 22 and spec 4.7 (source.md:255) cover git write verbs as well as `gh pr` and `gh api`. The per-task wording (plan:108, 124, 182) covers only `gh`. Task 8 allows `git` command lines in the ref (plan:124). The base `WRITE_VERB_RE` (`artifacts/base-e8db2fe6/tests/skills/test_worker_contract.py:1098-1100`) matches `git add|commit|push|merge|stash|update-ref|worktree`.
