## Orchestrator resolution of INV-009 (added after the probe; the fault-finder's rows above are unchanged)

INV-009 asked whether the pr-submit loop starts another fix or CI cycle after a push that did not complete. Read with `git show e8db2fe6:src/superclaude/skills/sc-pr-submit-protocol/SKILL.md` (the spec's base commit; reviewers had no shell, so this is orchestrator-verified and not a plan or spec citation): the Wave 6 text halts with `terminal_halted` for a failed fix commit (`fix_commit_failed`), a moved PR head (`pr_head_mismatch`) and a wrong push range (`push_range_mismatch`), each "with nothing pushed"; the exit table lists "Crash mid-push" as `--resume` three-way recovery, "no double push, no re-fix". No found text starts a second cycle after a push that did not land. The falsifying condition is not met by the base protocol; residual: the exact text for a plain push command failure in a fix cycle was not located. INV-009 is therefore treated as resolved with moderate confidence, HIGH UNADDRESSED count 0, and C-004 is lowered to MINOR.
