### anti-patterns
Look for: god functions (> 100 lines), god classes (> 20 methods), god modules (>800 LOC), feature envy, primitive obsession, shotgun surgery (one change forces many distant edits), inappropriate intimacy, lazy class, speculative generality, refused bequest, message chains, middle-man classes. Cross-reference: are these patterns recurring across the 10 subpackages (sprint/roadmap/prd/pipeline/etc.) given they share a near-identical commands/executor/models/gates skeleton? Is there evidence of shotgun surgery or copy-paste between subpackages?

### architecture
Look for: layering violations (executor reaching into models internals, commands.py containing business logic instead of just CLI wiring), business logic in transport/presentation layers, missing abstractions (the same try/except + log + return pattern repeated across executors), god-objects, circular imports (especially between models.py and executor.py within a subpackage), leaky abstractions, modules with too many responsibilities. Cross-reference: how do the 10 subpackages diverge in their shared skeleton — and is the divergence intentional or accidental drift? Is there a base class / mixin / common runner that should exist but doesn't?

### quality
Look for: off-by-one errors, null-deref / unwrap-on-None, untyped function boundaries (functions with no type hints despite being a public API), dead code, unused variables/imports, swallowed exceptions, broad `except Exception:` clauses that hide bugs, copy-pasted code blocks, magic numbers, misleading names, comments that contradict code, subprocess.run with shell=True or unvalidated argv, path traversal via Path concatenation, unsafe yaml.load / pickle / eval usage, mutable default arguments.
