## Brittleness drivers identified

- **No fixability invariant at finding-emission time:** `_make_finding` in `structural_checkers.py:261-291` constructs every HIGH without verifying the finding is reachable by an additive roadmap edit fitting inside the 30% diff guard. When this implicit contract is violated — by D-family ID-schema drift today, by something else next release — the convergence loop cannot distinguish "agent failed" from "fix is structurally unreachable." Each new release surfaces a new failure shape until that emission-time invariant is made explicit. (F-A12-01, F-A12-02, F-A12-03)
- **Binary pass predicate with no MANUAL_TRIAGE escape:** `convergence.py:539 active_highs == 0` is strictly binary. S6 was deferred from the `roadmap-spec-fidelity-fix` backlog as "safety net, not required if top-3 converge" — but the present failure shape is exactly what S6 was for. Until a third state ("active_highs of class X = unfixable, halt with explicit reason") exists, the loop is structurally guaranteed to opaque-halt on any new unfixable-finding class. (F-A12-02, F-A12-03)
- **Halt message field names embed cause attribution:** The convergence halt formatter at `convergence.py:653-668` emits `TurnLedger: available=X, consumed=Y` as part of the failure message, which leads operators to misread structural defects as budget exhaustion and reach for `--allow-regeneration` BACKUP-WORKAROUND escape valves that don't address the underlying issue. (F-A12-02)
- **Asymmetric extractor/comparator design pattern, generalized:** The D-family ID failure (F-A12-01) and the PR #86 mechanism-signature failure (F-A12-06) are the same shape at different abstraction layers. Until a project convention requires "every comparator that accepts tokens from a lenient extractor MUST canonicalize both sides before comparison," analogous failures will recur in function-signature, param-type, and dispatch-family comparisons. (F-A12-01, F-A12-06, F-A12-07)
- **No schema-enforcement meta-test between SKILL.md contracts and fixture YAMLs:** When sc-reflect's eval fixtures drifted from §14.5.6 (F-A12-09), only a Phase 7 qualitative review caught it — a meta-test that grep-asserts every `gate_evaluation:` key in `.dev/eval-workspaces/*/cases/promotion/*.yaml` against the §14.5.6 field-list could have caught it at build time. (F-A12-09)
- **Architectural gate sharing across pipelines (sprint reuses roadmap):** Sharing `ANTI_INSTINCT_GATE` between roadmap and sprint creates a vacuous-pass surface in the sprint pipeline that cannot be detected without per-pipeline gate definitions. Extension Path B (new third hook for acceptance criteria) has been the documented cleanest fix across multiple research outputs. (F-A12-13)
- **Forked-repo branch convention drift from upstream CLAUDE.md:** Task authors copy step text citing CLAUDE.md branch conventions (`integration` exists) without verifying against actual fork state. Mechanical gates (git) detect at runtime; no static check catches it pre-execution. (F-A12-08)
- **Stubs left in shipped code paths consume budget without doing work:** `_format_wiring_failure()` debits remediation budget and runs recheck without actually invoking a remediation subprocess (F-A12-14). This pattern (build the orchestration, leave the primitive stubbed) is the same shape as Pattern 1 — "harden everything around the broken primitive without touching the primitive itself." (F-A12-14)
- **Roadmap output format dictates downstream parser yield, not the input richness:** TDD+PRD inputs produce 4.1× more input lines than spec-only, but the LLM consolidates into 3 delivery-milestone phases instead of 5 technical-layer phases because the generate prompt does NOT enforce a minimum phase count or table-row decomposition. Tasklist generators that parse table-row granularity will see fewer items even when the input is denser. (F-A12-12)
