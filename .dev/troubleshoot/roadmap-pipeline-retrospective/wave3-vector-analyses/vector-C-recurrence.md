### Q1 — Recurrence Gap Analysis (Rows #1-#10)

For each top-10 row in the Recurrence Matrix (master:§Recurrence Matrix), the gap that allowed recurrence is named, then categorised as (a) incomplete test coverage, (b) missing eval-corpus case, (c) wrong abstraction level, or (d) silent feature creep.

**Row #1 — Spec-fidelity LLM-only / phantom-ID gate (~12 fix attempts, 8 partitions).** Every redesign — LLM-only → 5-vote consensus → structural checkers → convergence engine → DeviationRegistry → canonicalising comparator — closed the *previous* failure shape by adding machinery *around* the comparator (master:§Top-3 #1). `(A12:F-A12-03)` names this the "multi-release harden-orchestration-around-broken-comparator" anti-pattern. **Gap: (c) wrong abstraction level.** The remediation target was always the orchestration loop (TurnLedger, monotonic-progress, regression detection) when the broken primitive was the `phantom_ids = roadmap_ids - spec_ids` asymmetric set difference. Compounded by **(b) missing eval-corpus case**: there is no corpus of `spec ID shape → roadmap ID shape` pairs (D1 vs D01, FR-S10-02 hyphen-collapse) replayed against the comparator on every PR. `tests/roadmap/test_structural_checkers.py` exercises individual checkers but no test enumerates *adversarial ID-shape pairs* that a lenient extractor produces against a strict comparator. INFERENTIAL.

**Row #2 — "Written but not wired" (~8 attempts, 6 partitions).** `TurnLedger` + `ShadowGateMetrics` + `DeferredRemediationLog` ship complete with tests in v3.1 while `execute_sprint()` never calls `execute_phase_tasks()` `(A2b:F-A2b-003)`; `_resolve_wiring_mode()` defined but never read `(A3:F-A3-13)`; `build_certify_step()` at `executor.py:1899` unreferenced `(A11:F-A11-011)`; `_format_wiring_failure()` returns a prompt string but invokes no subprocess `(A12:F-A12-14)`. **Gap: (a) incomplete test coverage.** Tests verified the object existed and behaved when invoked, never that the production caller invokes it. `tests/roadmap/test_executor.py::TestBuildSteps::test_step_ids_in_order` asserts step IDs are present in `_build_steps()` output, but no test asserts every defined `build_*_step()` symbol in `executor.py` appears in *some* dispatch path. The whole "Tasklist→Code" link is missing as a *test surface*, not just as a runtime gate (master:§Flaw 1). Compound **(d) silent feature creep**: each release adds a builder + a hook + a config flag without a sibling test that imports the production entry point and asserts the new symbol is reachable from it.

**Row #3 — Wiring-verification gate scans wrong directory / empty target, silent PASS (~5 attempts).** Same bug at `(A2b:F-A2b-002)`, `(A4:F-A4-004)`, `(A6:F-A6-010)`, `(A9:F-A9-010)`. Fixed eventually with `files_analyzed > 0` guard at `executor.py:1019-1022`. **Gap: (a) incomplete test coverage + (c) wrong abstraction level.** The original tests asserted "gate runs on directory X and emits report" — they never asserted "if `len(scanned_files) == 0`, gate MUST NOT emit PASS." The abstraction-level error is treating "PASS" as a value the gate self-reports rather than a derived property of `(files_analyzed > 0 AND zero findings)`. Master:§Pipeline Heat Map confirms `_format_wiring_failure()` "debits budget without invoking remediation subprocess" — same anti-pattern persists in adjacent code.

**Row #4 — Roadmap fabricates / renumbers FR/NFR/SC/D-### IDs (~7 attempts).** v2.22 invented FR-001..FR-032 `(A1b:F-A1b-004)`; Goal-1a/NFR-001 fabricated `(A3:F-A3-16)`; SC-009b/FR-008 `(A5:F-A5-009)`; D01..D54 `(A12:F-A12-01)`. **Gap: (b) missing eval-corpus case + (c) wrong abstraction level.** No corpus of specs with known ID-sets gets replayed against the roadmap generator with a post-condition `assert roadmap_ids ⊆ spec_ids ∪ accepted_deviations`. The abstraction error is enforcing this in the *validator* (downstream) rather than the *generator* prompt (upstream) — master:§Flaw 2 calls this the generator/validator asymmetry. Tests like `test_structural_checkers.py` validate that the comparator runs; none replay a fixture-spec through generate-merge and check ID-set containment end-to-end.

**Row #5 — Phase restructure / module-layout deviation between architect and spec (~5 attempts).** v2.22 4 spec phases → 7 roadmap phases `(A1b:F-A1b-004)`; v2.24.1 7→5 consolidation dropping `config.py` `(A7:F-A7-07)`. **Gap: (c) wrong abstraction level + (d) silent feature creep.** Architects optimise execution units; spec optimises logical decomposition — these are different abstractions and the pipeline never declared which dominates. Each release adds a new manual-override deviation row instead of pinning a phase-count invariant or a `phase_count_drift ≤ N` policy. INFERENTIAL — the master report does not cite an existing pin-test, but `test_executor.py` shows step-count assertions (`assert len(steps) == 12`), demonstrating the *shape* of the missing test exists for steps but not for phases.

**Row #6 — Anti-instinct regex false positives on legitimate vocabulary (~4 attempts).** `\bStrategy\b` matched "Testing Strategy" / "Migration Strategy" headings `(A11:F-A11-002)`; `Scaffold` as imperative table-cell verb `(A2a:F-A2a-003)`; `\bhardcoded\b` on `bcryptjs cost factor (12)` `(A11:F-A11-003)`. **Gap: (b) missing eval-corpus case + (a) incomplete test coverage.** `tests/roadmap/test_obligation_scanner.py` has fixtures for *true positive* paths (MULTI_MILESTONE_ROADMAP, CLI_PORTIFY_REGRESSION, EXEMPT_ROADMAP) but no adversarial *false-positive corpus* of "Testing Strategy" headings, descriptive nouns ("scaffolding", "stub"), parenthetical labels ("hardcoded threshold (12)"), code-block contents — exactly the shapes that recurred. Each fix narrowed the regex one collision at a time, no test pinned the prior collisions against regression. Compound **(d) silent feature creep**: each release adds a narrower regex (`(?=\S*\d)` lookahead, `DISPATCH` over-capture fix `(A12:F-A12-04)`) instead of changing the abstraction to lex-with-context.

**Row #7 — Convergence-threshold drift / advisory-not-enforcing (~3 attempts).** `_convergence_score_valid()` only checks float ∈ [0.0, 1.0]; v2.13/v2.20 shipped at 0.72 below documented 0.85 `(A9:F-A9-007)`; sibling skills used 0.7/0.5 vs 0.6/0.5 `(A10:F-A10-003)`. **Gap: (c) wrong abstraction level.** Thresholds are *constants* duplicated across three sites (skill prose, CLI gate, executor parser) with no single registry — master:§Flaw 5 names this. The test gap is structural: there is no `tests/roadmap/test_threshold_registry.py` asserting that every gate's documented threshold matches the runtime constant. Master:§Pipeline Heat Map score row confirms: "convergence threshold drift across sibling skills."

**Row #8 — `_cross_refs_resolve` known-broken stub (2 attempts).** Returns `True` unconditionally with `# Don't fail on this — it's too fragile for now` comment shipped to production `(A9:F-A9-005)`, still in BACKLOG as C-108 `(A11:F-A11-031)`. **Gap: (d) silent feature creep + (a) incomplete test coverage.** A stub was authored, a comment was added, the project moved on — no test was written that *exercises* the cross-ref path and asserts it catches a real cross-ref drift. The test gap is institutional: the stub is detectable by `grep "return True  # .*fragile"` but no CI lint blocks merge.

**Row #9 — Retry without input mutation (3 attempts).** v2.24-cli-portify halt with 2 identical-output retries `(A1b:F-A1b-006)`; TUIBBS D-family flatline 58→54→54 over 3 runs `(A12:F-A12-02)`. **Gap: (c) wrong abstraction level.** Retry was modelled on *transient* failures (rate limits, timeouts) not on *deterministic-input* failures (master:§Flaw 4). The fix abstraction would be a *retry mutator* contract: `retry(input) -> mutated_input` that asserts input ≠ output before re-running. Test gap follows: `tests/roadmap/test_convergence.py` (57k bytes, the largest test file) exercises convergence success paths, not the "identical-input → identical-output → infinite loop" property.

**Row #10 — Generator/validator asymmetry (~4 attempts).** This is the *meta* recurrence: every fix adds a downstream validator, none constrains the generator. Pipeline step count: v4=9 → v2.22=11 → v5=13 → current=14 (master:§Executive Summary). **Gap: (c) wrong abstraction level — universally.** The pipeline has no architectural principle "for every new failure class, prefer generator constraint over validator addition." Test gap: there is no count or ratio test asserting that "generator-side constraints (tool-write templates, schema-pinned prompts) MUST grow ≥1:1 with validator additions." This is the deepest abstraction error in the project.

**Category roll-up across rows #1-#10:** (c) wrong abstraction level appears in 8/10 rows; (a) incomplete test coverage in 6/10; (b) missing eval-corpus case in 4/10; (d) silent feature creep in 4/10. The dominant gap is wrong-abstraction — recurrences are not "this regex needs another tweak," they are "this whole class of fix is on the wrong side of the producer/consumer boundary."

### Q2 — Test/Eval Discipline Thesis

The Fix → Recurrence → Fix pattern reveals a project that **tests for closure of the specific incident, not for the existence of the failure class**. Five concrete examples:

1. **Anti-instinct regex over-tightening.** The v2-A obligation scanner shipped as pure-regex by *deliberate design contract* `(A2b:F-A2b-001)` — "zero LLM calls" elevated to a spec property. Each subsequent false-positive (`Strategy` headings, `hardcoded` config descriptors, `DISPATCH` over-capture) added a narrower regex; no test enforces *the set of historically known collisions* against regression. `tests/roadmap/test_obligation_scanner.py` is 32k bytes but its fixtures (`MULTI_MILESTONE_ROADMAP`, `EXEMPT_ROADMAP`, `CLI_PORTIFY_REGRESSION`) demonstrate true-positive paths — there is no `KNOWN_FALSE_POSITIVE_CORPUS` symbol. Each Fix → Recurrence cycle (`(A11:F-A11-002)` → `(A12:F-A12-04)`) is local closure, not class closure.

2. **Frontmatter parser duplication.** `_check_frontmatter()` did byte-0 `lstrip().startswith("---")` `(A2a:F-A2a-001)`; `_parse_frontmatter` did re.MULTILINE `(A11:F-A11-010)`. Two parsers shipped, they disagree on identical input. No test asserts "for any frontmatter blob, parser A's verdict == parser B's verdict." `(A11:F-A11-010)` documents this as still-live. Discipline gap: parser-consistency invariants are not gated.

3. **Wiring-verification wrong-directory bug (3 releases of recurrence).** `(A2b:F-A2b-002)` → `(A4:F-A4-004)` recurred in v2.24.5, unified-audit-gating-v1.2.1, and v3.0 before the `files_analyzed > 0` guard landed. No regression test was committed at each fix that asserted "gate refuses to PASS on empty target." Each fix re-discovered the same defect because no test held the prior fix.

4. **`_cross_refs_resolve()` shipped as `return True` with a fragility comment for releases.** No CI lint blocks merging stubs with "too fragile for now" annotations. The project tolerates known-broken code shipping to production with prose disclaimers — `(A9:F-A9-005)` and `(A11:F-A11-031)` confirm this is institutional, not incidental.

5. **`build_certify_step()` defined at `executor.py:1899` but never invoked, across multiple releases.** `(A11:F-A11-011)`, `(A10:F-A10-019)`. A test exists that exercises the builder; no test asserts the symbol is *reachable from `_build_steps()`*. The discipline gap is the absence of a "reachability invariant" test on the executor's dispatch graph.

**Thesis:** The project's test discipline is *unit-rich and integration-poor where integration most matters* — at the producer/consumer seams where each Fix → Recurrence cycle plays out. Wave 1 retrospectives consistently find tests passing on the same day production gap-analysis identifies CRITICAL bugs (master:§Flaw 1 evidence chain: "v3.1 ValidationReport CLEAN — 0 findings same day gap analysis found 3 CRITICAL bugs"). The cure is not more tests of the same shape; it is a different class of test — *recurrence regression*, *reachability invariants*, *adversarial corpus replay*, and *contract conformance gates* — that the project does not currently author.

### Q3 — Missing Machinery

Each recurrence row needs a specific test/eval/audit lane that does not exist today. Six concrete proposals, each tied to a row:

1. **Recurrence-regression corpus for anti-instinct false positives.** Path: `tests/roadmap/fixtures/anti_instinct_known_false_positives/`. Contents: every fixture-marker from `(A11:F-A11-002)` ("Testing Strategy" heading), `(A11:F-A11-003)` ("bcryptjs cost factor (12)"), `(A12:F-A12-04)` (DISPATCH over-capture), `(A2a:F-A2a-003)` (scaffolding-as-noun). Driver: `pytest tests/roadmap/test_anti_instinct_recurrence.py::test_no_historical_false_positive_regresses`. Runs on every PR touching `src/superclaude/cli/roadmap/obligation_scanner.py`. Adds new entries on every accepted-deviation declaration. INFERENTIAL on naming; the structural pattern is borrowed from `test_obligation_scanner.py::CLI_PORTIFY_REGRESSION`.

2. **Dispatch-graph reachability invariant.** A `tests/roadmap/test_dispatch_reachability.py` that imports `src/superclaude/cli/roadmap/executor.py`, parses the AST, enumerates every `def build_*_step(` function, and asserts each symbol appears in *some* dispatch path reachable from `_build_steps()`. Would have caught `build_certify_step()` dead code at `executor.py:1899` immediately on definition. Generalises to `tests/sprint/test_dispatch_reachability.py` for `execute_sprint()` calling `execute_phase_tasks()`.

3. **Spec↔Roadmap ID-set containment property test.** `tests/roadmap/test_id_registry_invariant.py` consuming a fixture spec with known ID set `{D1, D3, D5, FR-001, NFR-002, SC-003}`, running generate-merge, and asserting `roadmap_id_set ⊆ spec_id_set ∪ accepted_deviation_ids`. Replayed on every PR touching `generate_prompts.py`, `merge_prompts.py`, or `structural_checkers.py`. Would have caught v2.22 FR-001..FR-032 fabrication and D01..D54 schema drift.

4. **Wiring-gate empty-target post-condition test.** `tests/roadmap/test_wiring_gate_invariants.py::test_pass_requires_nonempty_scan`. Asserts `gate(target=empty_dir).status != PASS` for all 4 wiring-gate variants. Would have caught the `(A2b:F-A2b-002)` → `(A4:F-A4-004)` 3-release recurrence immediately and is a 6-line test.

5. **Parser-consistency conformance for every frontmatter parser pair.** `tests/roadmap/test_parser_consistency.py` enumerates every frontmatter parser symbol in the codebase (`_check_frontmatter`, `_parse_frontmatter`, …), feeds 50+ blobs (preamble, blank-prefix, MULTILINE, trailing-newline, no-frontmatter, broken-fence), and asserts pairwise verdicts agree. Would have surfaced `(A11:F-A11-010)`'s "still live" status as a failing test.

6. **Retry-with-mutation contract test.** `tests/roadmap/test_retry_contract.py::test_retry_mutates_input`. Asserts that for every retry call, `input_before_retry != input_after_retry` OR the retry is annotated `transient_failure_only=True`. Would have caught the v2.24-cli-portify futile-by-construction halt at the design-review stage. Pairs with a CI grep for stub `return True  # .*fragile` (catches `_cross_refs_resolve` class).

**Cross-cutting observation:** None of the six machineries above currently exist in `tests/roadmap/` (verified by grep — no recurrence/regression/reachability test files, and no `KNOWN_FALSE_POSITIVE` symbol in `test_obligation_scanner.py`). The project has 50+ test files in `tests/roadmap/` aggregating ~960k bytes, yet the *class* of test that would close the top recurrences is absent. This is the deepest evidence for Q2's thesis.

### Q4 — Brittleness-Elimination Contract

Any future fix to the roadmap pipeline must satisfy all 10 items below to be considered durable. Each is testable as written. This block is to be embedded verbatim in the Wave 4 BUILD-REQUEST.

1. **Recurrence regression fixture.** The fix MUST add ≥1 named fixture to a recurrence corpus that exercises the *specific failure shape* being closed. Fixture path: `tests/roadmap/fixtures/recurrence/<failure-class>/<incident-id>.md` (or equivalent typed format). Test: `pytest tests/roadmap/test_recurrence_regression.py::test_<failure_class>` MUST FAIL on the pre-fix codebase and PASS post-fix.

2. **Dispatch-reachability invariant.** If the fix adds a new builder, runner, gate, or hook symbol, a test MUST assert the symbol is reachable from a production entry point (`_build_steps()`, `execute_sprint()`, `run_portify()`, `execute_pipeline()`). Mechanism: AST walk + dispatch-graph trace. Failure mode targeted: master:§Flaw 1 "written but not wired."

3. **Producer-side constraint preferred over validator addition.** If the fix would otherwise add a downstream validator/gate/check, the PR description MUST contain a "Generator-Constraint Considered" section explaining why a tool-write template / structured-output schema / prompt-pinned invariant on the generator side was insufficient. CI lint blocks merge if section absent on PRs touching `gates.py`, `structural_checkers.py`, or `*_validator.py`. Failure mode: master:§Flaw 2 generator/validator asymmetry.

4. **No silent PASS on empty / wrong-target inputs.** Every gate that consumes a directory, file list, or token set MUST assert `len(input) > 0` before emitting PASS. Test: `tests/roadmap/test_gate_empty_target.py` enumerates every gate symbol and asserts `gate(empty_input).status != PASS`. Failure mode: master:§Recurrence #3 wiring-verification silent PASS.

5. **No `return True` stubs with fragility comments.** A CI lint MUST block merge of any source file containing the pattern `return True\s*(#|""").*fragile|too.*hard|for.*now` in production code paths (`src/superclaude/cli/`). Existing instances flagged for active remediation, not grandfathered. Failure mode: master:§Recurrence #8 `_cross_refs_resolve` perpetual stub.

6. **Frontmatter / parser consistency invariant.** If the fix adds, modifies, or touches a frontmatter parser, a pairwise-consistency test MUST assert all other extant frontmatter parsers in the codebase agree with the new one across the 50+ blob conformance corpus. Mechanism: `tests/roadmap/test_parser_consistency.py`. Failure mode: master:§Recurrence #13 dual-parser disagreement.

7. **Retry-mutates-input contract.** Any code path adding or modifying a retry/loop/convergence step MUST assert `input_state_n != input_state_n+1` between attempts, OR carry a `retry_reason: transient_failure_only` annotation. Test surface: `test_retry_contract.py::test_no_identical_input_retry`. Failure mode: master:§Recurrence #9.

8. **Threshold registry conformance.** Every numeric threshold (severity cutoff, convergence score, retry budget, max_runs) MUST be defined in `src/superclaude/cli/roadmap/thresholds.py` (or equivalent SoT module) and read by skill prose, CLI prompts, and gate code through importable symbols — never as duplicated literals. Test: `tests/roadmap/test_threshold_registry.py` asserts no numeric threshold appears in >1 source location. Failure mode: master:§Recurrence #7 + master:§Flaw 5.

9. **Spec↔Roadmap ID-set containment.** If the fix touches generate / merge / extract / spec-fidelity, a property test on a fixture spec with declared ID set MUST assert `roadmap_id_set ⊆ spec_id_set ∪ accepted_deviation_ids` after full generate-merge. Failure mode: master:§Recurrence #4 fabricated IDs.

10. **Adversarial false-positive corpus for any regex/keyword gate.** If the fix uses a regex or keyword check on LLM-generated prose, the fix MUST add ≥3 known-false-positive fixtures from documented historical recurrences (sourced from `master-report.md` Recurrence Matrix or partition reports). Test: `pytest tests/roadmap/test_<gate>_recurrence.py`. Failure mode: master:§Recurrence #6 anti-instinct vocabulary collisions.

**Pass criterion:** A fix is durable when items 1, 2, and 4 are MUST-MET for the specific failure class being closed, items 5, 6, 7, 8 are MUST-MET if the touched code matches their trigger conditions, and items 3, 9, 10 are MUST-MET when the failure class is in scope. CI gates 1, 2, 4, 5 are pipeline-blocking; 3, 6-10 are PR-review-blocking with explicit override-with-reason allowed.

### Q5 — Coverage Map

Quadrants: **covered/uncovered** × **tested-passes/tested-fails**. *Covered* = a test/eval/audit exists; *Tested-passes* = the test green-lights current production; *Tested-fails* = the test catches the failure class. **Source:** `tests/roadmap/` directory listing (50+ files), `tests/sc-roadmap/`, `tests/pipeline/`, `.dev/evals/` corpus, and Wave 1 retrospective citations.

| Quadrant | Brittleness drivers in this quadrant | Evidence |
|---|---|---|
| **Covered + Tested-fails (DESIRED)** | • Anti-instinct true-positive paths (CLI_PORTIFY_REGRESSION fixture in `test_obligation_scanner.py:84-98`) catches scaffold-as-noun regressions • Structural checkers property tests `test_structural_checkers_properties.py` enforce some invariants • Cosmetic remediator C1-C13 transforms each have a class-test in `test_cosmetic_remediator.py` (32k bytes) | Multiple test files in `tests/roadmap/` directly tied to identified failure shapes |

**Coverage-map summary:** The project's existing test suite occupies the **Covered + Tested-passes** quadrant disproportionately (~50 files, ~960k bytes); the **Covered + Tested-fails** quadrant is real but narrow (cosmetic remediator + obligation-scanner true-positive paths + structural-checker properties); the **Uncovered + Tested-fails** quadrant is the highest-leverage missing machinery — the six tests proposed in Q3 plus the five distinct contract types in Q4 occupy this space; the **Uncovered + Tested-passes** quadrant is where the recurrences come from. The retrospective's structural verdict (master:§Architectural-flaw Thesis "REWRITE") is consistent with this map: substrate-level brittleness lives in the quadrant where production passes silently and no test exists to dispute it.
