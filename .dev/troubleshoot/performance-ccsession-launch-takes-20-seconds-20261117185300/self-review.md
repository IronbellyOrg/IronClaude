## Findings

**F1 (blocking): the Stage 1 caches and combined values are lost in subshells.** Read: I:1599, 1610-1611, 1616-1617, 1480-1483. `session_transcript`, `get_btime`, `get_mtime` and `format_epoch` are all called inside `$(...)`; a variable set in a `$(...)` subshell is gone when it returns. So "build one `ls -t` index in memory on the first miss" rebuilds the index on every miss; a once-only `date --version` probe done inside `format_epoch` runs for every call; a combined `stat -c '%W %Y'` cannot hand two values back through `$(...)`. Consequence: the 2.03 s session_transcript saving and the date-probe saving do not happen; each miss would sort about 1741 paths instead of globbing, likely no faster than today. Correction: build the index and the date probe in the parent shell before the row loop; call the transcript lookup, the combined stat and the date formatting without `$(...)`, returning values through named globals (`printf -v` or plain assignment); add a spawn-count test that fails if the index is built more than once. (Parent check, 2026-11-17T19:22Z: grep of the installed script confirms `jsonl=$(session_transcript "$uuid")` at I:1599, `start_ts=$(get_btime "$jsonl")` at 1610, `last_ts=$(get_mtime "$jsonl")` at 1611, `start_str=$(format_epoch ...)` at 1616, `last_str=$(format_epoch ...)` at 1617.)

**F2 (non-blocking): the `ls -t` index has no `|| true`, and it is one big argument list.** Read: I:132 (`set -e`), 1482. `idx=$(ls -t "$PROJECTS_DIR"/*/*.jsonl 2>/dev/null)` exits non-zero with no transcripts or an unmatched glob and aborts the script under `set -e`; the proposal states `|| true` only for the `read`. One `ls` over every transcript is a single exec whose argument size grows with the store (macOS limit not verified); if the exec fails, `2>/dev/null` hides it and every row reads "(transcript missing)". Correction: `idx=$(...) || true`; if the index is empty or `ls` failed, fall back to the per-uuid glob; add an empty-store fixture.

**F3 (non-blocking): the cost of the bash lookup is unmeasured.** Read: I:1599. Scanning about 1741 index lines in a bash loop for each of 477 uuids is about 830,000 iterations; the 2.03 s saving assumes that costs about nothing; no gate covers it. Correction: specify an O(n) parameter-expansion lookup (for example `pre=${idx%%"/$uuid.jsonl"*}`, then the text after the last newline) and add a measurement gate.

**F4 (non-blocking): a failed redirect leaves the previous row's uuid.** Read: I:1591 (`local topic uuid ...`), 1594 (`uuid=$(head -n 1 "$topic_file")`). If `read ... < "$topic_file"` fails (for example an unreadable file), `uuid` keeps the previous iteration's value (the original `$(head)` gave empty). `|| true` is correct under `set -e` but does not fix this. Correction: `uuid=""` before the `read`; add a chmod-000 topic file fixture; a file with no trailing newline is fine.
