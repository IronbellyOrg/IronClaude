Standing rules for every replacement (they go into the shared guide, section 4):

1. **Read before cite or edit.** A codegraph answer locates code; it is not a citation. Re-`Read` the `file:line` range before quoting it, and always before `Edit` (the PostToolUse `Read` hook records reads for the edit freshness gate, `src/superclaude/hooks/hooks.json:47-59`). `codegraph_node` in file mode is allowed only with `symbolsOnly:true` (an outline); file mode with code would be a Read substitute that the freshness gate never sees (`BS` D-10; access decision §7).
2. **Fail open to the Phase 1 floor.** codegraph missing, unlisted, index missing, foreign or stale → use the step's Phase 1 floor (Grep/Glob/Read, `P1 §4.1` G2) and record one `graph:*` token (section 4) in the skill's existing `degraded` / `degraded_components` list. No codegraph step stops a run; `/sc:impact` returns `status: partial` with Grep-based results instead (section 3).
3. **Empty is not absence.** Files over 1 MB, ignored files, dependency dirs and Markdown are not indexed (`EVAL §4`, §5.4), and callers are call edges only. No "no callers", "no dependents" or "no tests" conclusion may come from a graph result (`BS` FR-07).
4. **Agents get exact names and the run's state.** A read-only agent lists exact `mcp__codegraph__codegraph_<tool>` names (never `mcp__codegraph__*`) and only for spawn modes that passed the T0 smoke matrix; its brief carries `index_state`, `checked_at`, `worktree_root` and the `projectPath` to pass on every call, and it calls codegraph only when `index_state: fresh` (access decision §4). Subagents do not see the MCP server instructions (`EVAL §3`), so the brief also points to the shared guide.
5. **No `explore`, no mutating CLI verb in a skill or agent.** No primitive names `codegraph_explore`, `codegraph explore` or `codegraph context`; no allowlist says `Bash(codegraph *)`. Indexing follows Phase 2's model (`P2 §3.1-3.2`, D21): the session-start hook is the default indexer of every new checkout; the main session may run `codegraph init --yes` as Phase 2's `core/CLAUDE.md` block says; among primitives only the user-typed `/sc:graph init` runs `init` (the manual path: nested worktree needing `-i`, hook switched off, failed or interrupted init). No skill or agent invokes `init`, `index`, `sync` or any other mutating verb (P3-D1, P3-D9, P3-D17).
6. **Both tool-list branches.** Primitive text is the same whichever value Phase 2 shipped (section 0 G3). At run time the readiness check reads the session's tool list: lookup tools listed → `access: mcp`; only `codegraph_status` listed (status-only branch) → token `graph:unlisted`, then orchestrators whose `allowed-tools` cover the read verbs use the CLI transport (`codegraph query|node|callers|callees|impact`, flags as captured in T0 E-2) and every other primitive, including closed-roster agents, uses the Phase 1 floor (or artifacts the orchestrator passes in the brief) (`decisions/P3-access-model/adversarial/P3-access-model-merged.md` §9.1 failure branch). A later Phase 2 follow-up that flips the constant back to seven tools needs no Phase 3 edit.
7. **Guard every CLI `status`.** Run CLI `codegraph status` only when `pgrep -f 'codegraph\.js (init|index)'` prints nothing; when it prints a line, skip `status`, set `index_state: stale` with token `graph:stale` (graph rows are leads only) and, in `/sc:graph`, `next_action: wait_for_sync`. Reason: `status` during an init can empty the index (`decisions/P2-indexing-sync/probe-results.md` rows 4, 6). MCP `codegraph_status` needs no guard (row 8).
8. **CLI binary.** A primitive calls the CLI as bare `codegraph` (that is what its exact `Bash(codegraph <verb> …)` allowlist entries match). `codegraph --version` failing or not equal to the guide's pin means CLI access is `none` (`graph:absent` or `graph:version_mismatch`); MCP access is unaffected. Phase 2's pointer `~/.codegraph/.superclaude-bin` (`P2 §2.2`) is used by the hook and the main-session guidance, not by primitives.
9. **Tier above the floor.** Where Phase 1 left a floor (ledger action `floor`), the codegraph step is inserted before it and the floor text stays unchanged below it; a row never says "skip" where the floor exists (`P1 §4` decision, G6).

### 2.1 Key findings that change the plan

1. **Graph answers locate, they do not cite.** Caller rows give the caller's definition line (`main.py:46`, not the call at `:255`, `EVAL §5.5`), and empty results never prove absence (no text search, no string or dynamic references, `EVAL §6.1`) (`BS §1`, FR-06, FR-07). Adopted as standing rules 1 and 3 (section 1.1) and in the guide (section 4).
2. **Test callers swamp production callers.** For one symbol, 18 of 20 shown caller rows were tests (`EVAL §5.5`). A 1:1 swap of `find_referencing_symbols` → `codegraph_callers` can inflate reflect's "HIGH if more than 5 referencing call sites" rule (`src/superclaude/skills/sc-reflect-protocol/SKILL.md:347`) (`BS` I-05). Adopted: reflect logs production and test counts separately and keeps today's severity rule until shadow evidence says otherwise (task T8).
3. **`codegraph_explore` is a token risk.** One call returned 24,913 characters and two unrelated functions, against a ~3K-token troubleshoot Wave 1 budget (`BS` I-03, D-01). Adopted: no primitive uses `explore` as a default step (decision P3-D9).
4. **Freshness without a daemon is unmeasured** (`BS` INV-001, HIGH, open). The watcher runs only while an MCP client is connected (`EVAL §4`, §5.7). Adopted: experiment E-1 becomes task T0 (section 5); until it passes, any graph number that would change a severity, gate or verdict is advisory only.
5. **The CLI has mutating verbs beside read verbs** (`install` edits Claude config, `EVAL §2`). Adopted: no `Bash(codegraph *)` allowlist anywhere; one pattern per read subcommand; a grep test forbids invocation forms (`Bash(codegraph <mutating verb>`) of `init|index|sync|uninit|unlock|upgrade|install|uninstall|telemetry on|off` in every command, skill and agent except `init` inside the one user-typed command (`BS` FR-04, FR-23; narrowed to invocation forms by review finding X-3, because `core/` prose legitimately names these verbs).
6. **Per-worktree init: superseded by Phase 2.** The brainstorm found no owner for per-worktree init (`EVAL §4`; `BS` B2) and dropped a SessionStart hook (`BS` D-03). Phase 2 later chose, by `/sc:adversarial` plus sandbox probes, a SessionStart hook that starts `init --yes` detached with a sub-second return (`P2 §3.2`, D21; `decisions/P2-indexing-sync/`), which answers the brainstorm's objection (1 s hook timeout, foreground 4.5 s / 1 GB init). Phase 3 adopts it: the hook is the default indexer; `/sc:graph init` is the manual path (section 3.2); no other primitive runs `init` (P3-D17).

## 4. Shared-guidance placement

**Decision (P3-D2): one core doc, `src/superclaude/core/CODEGRAPH.md`, installed to `~/.claude/CODEGRAPH.md`.** Every primitive points to it by the installed path and never repeats its rules beyond one line.

Why a core doc:

- `superclaude install` already copies every `*.md` in `src/superclaude/core/` to `~/.claude/` (`src/superclaude/cli/install_core.py:51-71`), so no new install code is needed; only the reporting list `KNOWN_CORE_FILES` (`install_core.py:13-24`) and the pinned file list in `tests/unit/test_cli_install.py` (`"core"` entry) gain the name.
- Upstream's own guidance block, written by `codegraph install` into `~/.claude/CLAUDE.md`, is erased by the next `superclaude install --force` (`EVAL §2`, "Interaction with IronClaude"), and Phase 2 does not run `codegraph install` at all (`EVAL §7`). IronClaude must own the text.
- Subagents do not see the MCP server's `initialize` instructions (`EVAL §3`); a file every agent can `Read` fills that gap without loading it into every main session.
- It is NOT `@`-imported into `CLAUDE.md` (same rule as `HOW-WE-WORK.md`, repo `CLAUDE.md` "Key Documentation Files"), so it costs no context until a primitive needs it. The `core/CLAUDE.md` MCP table row (section 1.2 row 1) names the path, so a main session can find it.

Rejected placements: a ref inside a new skill (for example `~/.claude/skills/sc-impact-protocol/refs/…`) would tie generic guidance to one command and break if that skill is not installed; `src/superclaude/mcp/MCP_Codegraph.md` is package data that is not installed (`~/.claude/mcp/` does not exist, `SER §4.1`).

**Lookup line every primitive uses (installed-path rule, repo `CLAUDE.md` "Never Hardcode `src/superclaude/` Paths"):**

```text
Codegraph usage rules: read `~/.claude/CODEGRAPH.md` (in a dev checkout without an install, the labelled fallback is `src/superclaude/core/CODEGRAPH.md`).
```

`make sync-dev` does not copy core docs to `.claude/` (`Makefile:109-121` syncs skills, agents, commands, hooks, templates), so there is no project `.claude/` copy to name; the in-checkout fallback is the "clearly labelled in-checkout fallback listed AFTER the global path" the repo rule allows. The plugin mirror gets a byte copy at `plugins/superclaude/core/CODEGRAPH.md` (that folder already mirrors other core docs: `BUSINESS_*`, `PRINCIPLES.md`, `RESEARCH_CONFIG.md`, `RULES.md`), pinned by a parity test.

**Contents of `CODEGRAPH.md` (at most 120 lines; one section each):**

1. *What it is*: a read-only code graph of the current worktree, one SQLite index per worktree in `.codegraph/` (`EVAL §1`, §4).
2. *Readiness check, once per run*: detect MCP from whether `mcp__codegraph__codegraph_status` is in the tool list (never from the kind of run); call it, or CLI `codegraph status` only when MCP is absent and `pgrep -f 'codegraph\.js (init|index)'` prints nothing (a running init → `stale`, standing rule 7). Switches: `SUPERCLAUDE_CODEGRAPH_PRIMITIVES=off` (primitives only, token `graph:disabled`) and `SUPERCLAUDE_CODEGRAPH_AUTOINIT=0` (hook only).
3. *Degraded tokens* (closed list; consumers invent none): `graph:absent`, `graph:unlisted`, `graph:disabled` (user set `SUPERCLAUDE_CODEGRAPH_PRIMITIVES=off`; it switches off codegraph use in primitives only, while `SUPERCLAUDE_CODEGRAPH_AUTOINIT=0` switches off only Phase 2's session-start index hook; the guide names both), `graph:not_initialized`, `graph:foreign_index`, `graph:stale`, `graph:version_mismatch`, `graph:provenance_unproven`, `graph:empty`, `graph:ambiguous`, `graph:truncated`, `graph:parse_failed`, `graph:unresolved`, `graph:telemetry_on` (14 tokens; `BS` FR-02; access decision §8). 4. *Tool table*: section 1.1's job → tool rows, condensed to the seven MCP tools (`node`, `search`, `callers`, `callees`, `impact`, `files`, `status`; only `status` in the status-only branch) and the allowed CLI verbs (`--version`, guarded `status` when no MCP, `telemetry status`, `query <name> --json`, `affected … --json --quiet`, `init` in `/sc:graph` only, plus `node`, `callers`, `callees`, `impact` as the status-only-branch transport in orchestrators that allow them, flags from T0 E-2). `explore` is blocked by the server list and named only in this guide's "never" section.
