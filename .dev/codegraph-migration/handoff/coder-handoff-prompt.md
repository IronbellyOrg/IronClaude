# Coder handoff prompt: retire codebase-memory and Serena, install and sync codegraph

You are working in the **IronbellyOrg/Coder** repository (Coder workspace templates; the live template is `templates/VSCode-AIDev02/`, written `T/` below). Your job is the Coder side of IronClaude issue https://github.com/IronbellyOrg/IronClaude/issues/323: replace the code-intelligence MCP servers in Coder workspaces.

## Goal

1. **Existing workspaces**, when they update to the new template/image, end up with codebase-memory-mcp and Serena **removed** (binaries, bundle installs, registrations, markers, aliases) and **codegraph installed, registered and indexing** the user's projects.
2. **New workspaces** get codegraph baked into the image (preferred) or installed at startup, with no codebase-memory-mcp and no Serena.
3. **New worktrees and projects** (clone, `git worktree add`, Orca worktree creation, seed repos) get a codegraph index without the user doing anything, and stay in sync.

## What IronClaude does (do not duplicate it)

IronClaude (`superclaude install`, run by Coder's `ironclaude` catalogue slug) will, after its Phase 1 + Phase 2 release:
- **remove** the user-scope `codebase-memory-mcp` registration (including Coder's `/usr/local/bin/codebase-memory-mcp` entry), and, **only when codegraph is ready in the same run**, every user-scope Serena launcher entry (matched by `start-mcp-server` in its args under any name except `serena-local`, stdio, `env`/`headers` absent or `{}`; this includes the `serena-agent==1.7.0` one your bundle writes). If codegraph is not ready it keeps the current-pin Serena entry. It also stops shipping Serena and Codebase Memory text in `~/.claude`;
- **install codegraph v1.6.2** as a required phase: reuse a `codegraph` on PATH whose `codegraph --version` prints exactly `1.6.2` (no network), otherwise download the pinned release tarball and verify its SHA-256 (needs network);
- **register** it at user scope with `claude mcp add-json codegraph '{"type":"stdio","command":"<absolute realpath of the codegraph it chose>","args":["serve","--mcp"],"alwaysLoad":true,"env":{"CODEGRAPH_TELEMETRY":"0","CODEGRAPH_NO_UPDATE_CHECK":"1","CODEGRAPH_MCP_TOOLS":"node,search,callers,callees,impact,files,status"}}' --scope user`. `CODEGRAPH_MCP_TOOLS` lists the seven tools IronClaude's primitives use and hides `codegraph_explore` (upstream lists only explore by default). Its value comes from the constant `MCP_TOOLS` in IronClaude `src/superclaude/cli/install_codegraph.py` at the pinned SHA: IronClaude's task T2 may set it to `status` if a schema-cost check fails, so read it from that file (with `VERSION` and `SHA256`) in tests and in any registration Coder writes, instead of hard-coding the JSON. An entry without the key is "owned but stale" to IronClaude and gets replaced.

IronClaude also ships a SessionStart hook that, on a Claude session's start in a git checkout with no `.codegraph/codegraph.db`, runs `codegraph init --yes` once in the background. It never touches an existing database, so an index you build is left alone.

IronClaude does **not** remove root-owned binaries, Coder's `uv tool` install of Serena, Coder's bundle markers, the bundle's re-registration loop, shell aliases, or user data (`~/.serena`, project `.serena/`, caches). Those are yours. Its codegraph usage rule goes into the core `~/.claude/CLAUDE.md`, which Coder's `ironclaude` slug restores to the user's own copy after install. So Coder must carry that rule in its seed `T/workspace_defaults/CLAUDE.md` and in existing workspaces' `~/.claude/CLAUDE.md`, and **re-sync it on every IronClaude pin bump**: copy the lines from `<!-- SUPERCLAUDE_CODEGRAPH_BEGIN -->` to `<!-- SUPERCLAUDE_CODEGRAPH_END -->` (inclusive) out of IronClaude's `src/superclaude/core/CLAUDE.md` at the pinned SHA (the source of truth), replace the same marked lines in each target, and append them when no marker is present. Do not "append once": IronClaude's later releases (its Phase 3) change the block, and only the marker re-sync carries those changes to Coder users (the text at planning time is in the context file §2.3). Full contract and removal table: see "Context file" below.

- Do **not** use upstream `install.sh` (no checksum check) or `codegraph install` (edits Claude config and adds a prompt hook IronClaude does not want). Telemetry is on by default: set `CODEGRAPH_TELEMETRY=0` and `CODEGRAPH_NO_UPDATE_CHECK=1` in the image env. The MCP tool list is set only in the registration env (`CODEGRAPH_MCP_TOOLS`, above), not in the image env.
- Indexing: `codegraph init --yes [path]` per checkout (index in `<checkout>/.codegraph/`; its own `.gitignore` does not hide the folder from `git status`, so ignore `.codegraph/` globally; re-running on an indexed checkout is a fast no-op; refuses `$HOME` or `/` without `--force`; about 1 GB peak memory on large repos). While an MCP client is connected a per-project daemon watches files and keeps the index fresh. `codegraph sync --quiet` exists for hooks but fails with a lock error while that daemon runs. Each git worktree needs its own `init`. An interrupted `init` is repaired by the MCP daemon on its next connection. **Never run `codegraph status` or `codegraph index` while an `init` runs on the same checkout: the init fails and the index can be left empty.** Detect a running build with `pgrep -f 'codegraph\.js (init|index)'`.
