# Option B: use Claude Code native auto-memory as the store
/sc:save and pm-agent write memory files into Claude Code's own per-project memory directory (~/.claude/projects/<slug>/memory/ with MEMORY.md index and frontmatter types); /sc:load reads them. No SuperClaude-owned storage format.
Pros: shared across worktrees of the same repo slug, loaded into context automatically by Claude Code each session, no new folder. Cons: Claude Code specific (breaks the plugin/other-harness use of the primitives), path and format owned by Anthropic and can change, the slug differs per worktree path so cross-worktree sharing is not guaranteed, instructions must be conditional on the harness feature being enabled, harder to test in CI (the directory is outside the repo), writes outside the project folder.
