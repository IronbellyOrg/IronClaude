# Option C: drop MCP-style memory entirely
Delete /sc:save and /sc:load, the pm-agent memory lifecycle (list/read/write at session start/end), and MODE_Task_Management's write_memory hierarchy. Cross-session continuity relies on existing mechanisms: git, `.dev/tasks/` packages and progress.md ledgers, TodoWrite, `docs/memory/` files that pm-agent already documents, ccsession tagging, and Claude Code resume.
Pros: smallest surface, removes a feature that HOW-WE-WORK.md already says is "not a way to resume work"; no new storage to design; no gap to fill in Phase 3. Cons: loses an advertised user-facing capability (two slash commands, routing rows, ~12 doc pages, routing-table tests assert their text); sc-reflect calibration memory and sc-roadmap persistence have no home; users who rely on /sc:save get a breaking removal; pm-agent "session start restore context" has nothing to restore.
