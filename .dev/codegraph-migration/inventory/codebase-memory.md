## 0. Findings that change the plan

1. **Small blast radius, no skill/agent/command dependency.** 300 hits in 12 tracked files: 3 source files, 4 test files, 3 docs, README.md and 1 CI workflow. Zero hits in `plugins/`, in any `.claude/` mirror, in `.claude/settings.json`, `Makefile`, `pyproject.toml`, `.mcp.json`, or any skill, command, agent, hook or core doc. Removal is installer, CLI, tests, docs and CI only (1.1, 1.3).
2. **Only `superclaude install` provisions it.** `main.py:254-262` is the single call site. `superclaude update` (`main.py:352-431`) and `superclaude doctor` (`doctor.py`, no MCP content) never touch it. `./update.sh` reaches it through its line 8, `superclaude install --force` (`update.sh:8`).
3. **Deleting the code removes the only automated cleanup, and that cleanup already refuses this workspace.** Removal is gated on a private receipt (`install_codebase_memory.py:297-304`). This workspace has no receipt: the binary is the Coder-baked `/usr/local/bin/codebase-memory-mcp`. Observed: `superclaude mcp --uninstall --servers codebase-memory-mcp --dry-run` exits 1 with "External/custom PATH entries found ... no automatic removal" (section 3.1). So the existing code cannot clean a Coder workspace today; existing workspaces need new cleanup (Decision D6).
4. **Two test hazards if the removal is done naively.**
   - `tests/cli/test_update_command.py:31-76` is an *autouse* fixture that patches the codebase-memory modules for **every** test in that file, including the ccsession tests. It must change in the same step as `main.py`, or those tests fail on `AttributeError`, or worse, reach the real installer.
   - `tests/cli/test_install_codebase_memory.py` cannot simply be deleted: its `mcp_cli` block (lines 834-1380) holds about 16 tests of generic `superclaude mcp` behavior for non-cbm servers (Tavily and Auggie prompts, scopes, gateway preflight, menu). Deleting the file whole silently drops that coverage (1.4).
5. **Live environment is minimal.** Only three installed things plus running processes: the root-owned binary, one user-scope registration, and a small cache. No companion skills, agents, hooks, instructions, updater, receipt or PATH line exist (section 3.1). Of these, IronClaude can own only the registration.
6. **Shared files with the Serena workstream (W2).** `install_mcp.py` (registry `55-61`, prerequisites `561-570`), the registry tests (`11-80`) and the same three docs also carry Serena. Edits to those files must be sequenced with W2's removal order.
