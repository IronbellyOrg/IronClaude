Decisions for approval

Use the full official setup requested.

The upstream script installs the executable and companion skills, agents, instructions and hooks for detected clients. Do not silently substitute binary-only installation. Uninstall is likewise account-wide; it is not just a Claude Code registration toggle.

  • Default provisioning: normal superclaude install ensures a runnable executable and exact user-scoped MCP registration. Failure makes the overall install exit nonzero.
  • Scope: the new full lifecycle supports user scope on Linux/macOS amd64 and arm64. Reject project/local scope before effects. Other servers retain their current scopes.
  • Ownership: upstream owns native acquisition, activation and companion assets. Reuse the existing Claude CLI registration flow when registration needs repair.
  • Retention: never reset or delete graph indexes. Preserve independently managed installations.
  • Update boundary: framework update remains unchanged and does not resurrect an explicitly removed native tool.

The upstream bootstrap and latest release both move independently. This is download-on-missing, not a version-pinning or automatic-upgrade policy.

Installation contract

The requested upstream installation method is:

curl -fsSL https://raw.githubusercontent.com/DeusData/codebase-memory-mcp/main/install.sh | bash

Inside the Python CLI, download the complete script to a private temporary directory and execute it with Bash using argv-based subprocesses. This preserves the upstream behavior without executing a partial transfer or passing a pipeline through the existing token-quoting helper.

  1. Validate platform, user scope and Claude CLI. Native-only selection must not require Node, npm, Docker or an API key.
  2. Check the canonical executable, then usable PATH installations. Reuse a working installation rather than downloading on every run.
  3. When acquisition is needed, disclose the upstream URL and account-wide companion setup. Require curl/Bash, HTTPS-only redirects and a successful nonempty download. Use bounded download/install timeouts and terminate/reap the installer tree on timeout.
  4. Run the full upstream setup without --skip-config. Preserve its output, checksum checks and activation behavior. Do not add privilege escalation or another shell-profile editor.
  5. Verify the absolute executable with --version. Do not depend on a fresh shell having the install directory on PATH.
  6. Ensure exact name codebase-memory-mcp, user scope, stdio transport, absolute command and empty arguments. A matching entry in another scope is not success. Preserve and restore a stale user entry if replacement fails.

Add this phase after existing user setup and include it in the existing aggregated failure status. Keep successful framework work on failure. --list stays read-only; --force does not force a native upgrade; --target still controls slash-command destination only.

Print acquisition, executable verification and registration results separately. Registration success is not proof of indexing or a live MCP handshake.

Menu and CLI surface

The current MCP command is flat and offers installation only. Keep that structure and existing invocations; add these proposed flags rather than introducing subcommands:

superclaude mcp --servers codebase-memory-mcp
superclaude mcp --uninstall --servers codebase-memory-mcp
superclaude mcp --uninstall --servers codebase-memory-mcp --yes
superclaude mcp --uninstall --servers codebase-memory-mcp --dry-run

--uninstall and --yes/-y are new. The confirmation bypass applies only to the selected native lifecycle, never to index deletion or unrelated prompts.

No explicit servers

  • Uninstall Codebase Memory MCP.
  • Cancel.

Existing install menu

  • Keep gateway-first choices.
  • Add the native tool to registry-driven entries and install-all.
  • Process gateway-plus-native selections instead of dropping the native selection.

Noninteractive use requires an explicit selection. Removal requires confirmation or --yes. Dry-run prints a plan without prompts, network downloads, upstream lifecycle processes or mutations. With no selection, dry-run prints choices and exits. Reject incompatible list/mutation options before effects.

Uninstallation contract

Account-wide removal requires explicit consent.

The native uninstaller affects integrations across detected clients and may stop its active sessions. It has no client-scoped removal flag. Show this before confirmation; default to No.

  1. Accept only Codebase Memory for this new uninstall mode and only user scope. Reject unsupported or mixed removal selections before mutations.
  2. Resolve the canonical upstream install. If only an external/custom installation is found, report its path and stop; do not guess ownership or run an unrelated uninstaller.
  3. After consent, invoke the canonical binary with uninstall -y --dir=<canonical-install-directory>. Never pass --delete-indexes or reset flags. Passing -y prevents a separate interactive index-deletion prompt.
  4. Let upstream handle activation and owned integrations. Verify executable and exact user registration removal; use the existing Claude CLI only to clean a surviving exact user entry. Do not remove project entries or unrelated registrations.
  5. Preserve/report the adjacent updater script. Report any other installation still present on PATH.

Complete absence is an idempotent success. Missing binary with a surviving registration permits confirmed registration-only cleanup, explicitly reported as partial-install cleanup, not audited removal of companion assets. Query errors fail closed. Nonzero exit or timeout reports possible partial removal; do not claim rollback or run a blind deletion pass.

Acceptance and release gate

  • Fresh install acquires once; repeat install is a no-op; missing registration repairs without download.
  • Native selection works without Node/npm; existing npm-server behavior remains intact.
  • List and all dry-run paths remain mutation-free and prompt-free.
  • Download failure, empty script, timeout, native failure, failed executable verification and failed registration return accurate nonzero results.
  • Scope conflicts never remove the wrong entry. Paths with spaces remain single argv tokens. Failed registration replacement restores the old entry or reports restoration failure.
  • Uninstall decline changes nothing. Confirmed removal passes no index-deletion flags and reports leftover/partial states accurately.

Automated tests must mock the network and subprocesses and isolate HOME. Before release, separately authorize one live smoke test in a disposable user environment: inspect companion-file preservation, verify real registration, repeat setup, then remove while retaining index sentinels.

Block release if the released upstream installer overwrites unrelated framework or user assets. Mocked tests and inspection of moving main cannot establish release-asset merge safety.
