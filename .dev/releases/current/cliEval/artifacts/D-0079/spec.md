**Roadmap row:** R-079 (TEST-008)

**Test module:** `tests/cli/eval/test_exit_codes.py`
**Producers under test:**

- `src/superclaude/cli/eval/commands.py::HARD_FAIL_EXIT_CODE` (= 2)

## 1. Goal

Pin the four exit codes named in design-spec §4 at the **process
boundary** that operators, CI jobs, and downstream pipelines actually
read (subprocess `returncode`). The library boundary already has its
own pins — `REPORTER_CONTRACT_VIOLATION_EXIT_CODE` is held by the
T04.17 / D-0078 contract suite; `EXIT_INTERRUPTED` is held by the
T03.07 / D-0050 signal-handler suite — but neither of those verifies
that the constant actually flows out through `sys.exit` and into the
shell. This test module closes that gap, so a future refactor that
drops the constant on the way to `sys.exit` (or maps it to the wrong
exit branch) fails loudly here rather than silently in CI summary
parsers.

## 2. Test matrix

The four pytest cases in `tests/cli/eval/test_exit_codes.py`
correspond one-to-one with the TEST-008 scenarios named in the phase-4
tasklist:

| # | Scenario | Test function | Pins |
|---|---|---|---|
| 1 | **Clean run** | `test_exit_code_0_clean_run` | `superclaude eval run --suite real --no-pty --output-dir <tmp>` exits `0`. Every E1-E15 spec is tagged `no_pty: skip` (DOC-OQ3 / D-0077), so `--no-pty` short-circuits the whole suite into SKIPPED outcomes — no failures, no breaches, exit `0`. | 2 | **Failing run** | `test_exit_code_1_failing_run` | A synthetic single-eval suite whose `expect:` block is wired to fail is run via `superclaude eval run`; the orchestrator completes cleanly with one FAIL outcome, so the dispatcher exits `1` per design-spec §4. Skipped until T04.10 wires `_run_one_spec`. |
| 3 | **Harness contract error** | `test_exit_code_2_harness_error` | Two independent flag-validation gates (`--timeout-mult 0` and `--max-disk-mb -1`) each surface `eval run: --<flag> ...` on stderr and exit `2`. Both gates run BEFORE the run-loop closure, so this test runs today and is the canonical pin for the operator-visible exit-`2` contract. The test also pins `HARD_FAIL_EXIT_CODE == 2` at the library boundary so a constant rename cannot drift the contract silently. |
| 4 | **Interrupted run** | `test_exit_code_3_interrupted_run` | `subprocess.Popen` spawns the run, gives the orchestrator 2 s to install signal handlers, then delivers `SIGINT`. ## 3. subprocess invocation

`_run_eval(...)` invokes the **console-script** at
`<venv>/bin/superclaude`, not `python -m superclaude`. The package
deliberately ships without a `__main__.py`; the console-script
generated by hatchling is the canonical operator surface and matches
how CI / docs tell users to invoke the harness. The helper resolves
the binary off `sys.executable`'s parent so the test stays correct in
any venv layout (CI, `make dev`, ephemeral worktrees) and skips
gracefully if no console-script is installed on the host.

## 4. Forward-dependency policy (T04.10 deferral)

The 0 / 1 / 3 paths all flow through the run-loop closure whose
helpers (`_new_run_id`, `_run_one_spec`, `_compute_run_stats`,
`RUN_CLEAN_EXIT_CODE`, `RUN_FAILURES_EXIT_CODE`,
`RUN_INTERRUPTED_EXIT_CODE`) are T04.10 deliverables. While those
helpers are absent the closure raises `NameError` before reaching the
exit-code branch under test. Mirroring the
`test_no_pty_exclusion.py` pattern (T04.16), each affected test calls
`_skip_unless_t0410_landed()`, which returns the missing names and
issues `pytest.skip(...)` with a self-clearing diagnostic.

The exit-code-2 test **always runs**. Flag validation at
`commands.py:1398` (`--timeout-mult`) and `:1405` (`--max-disk-mb`)
sits BEFORE the run-id helper, so the `HARD_FAIL_EXIT_CODE` path is
exercised today regardless of T04.10 status.

When T04.10 lands the skipped tests auto-clear and the suite then pins
all four exit codes end-to-end at the process boundary.

## 5. Exit code 2 mapping (Scenario 3 detail)

Design-spec §4 maps the four eval-run exit codes as follows:

| Code | Constant(s) | Meaning |
|---|---|---|
| 0 | `RUN_CLEAN_EXIT_CODE` | All evals satisfied their `expects:` blocks; no FAIL / ERRORED / TIMEOUT / XPASS. |
| 1 | `RUN_FAILURES_EXIT_CODE` | At least one eval failed; orchestrator finished cleanly. |
| **2** | `HARD_FAIL_EXIT_CODE`, `SCRATCH_ROOT_VIOLATION_EXIT_CODE`, `SUITE_NOT_FOUND_EXIT_CODE`, `SUITE_LOADER_ERROR_EXIT_CODE`, `EVAL_NOT_FOUND_EXIT_CODE`, `COVERAGE_GATE_FAILED_EXIT_CODE`, `DISK_BUDGET_EXCEEDED_EXIT_CODE`, `RUN_BODY_DEFERRED_EXIT_CODE`, `REPORTER_CONTRACT_VIOLATION_EXIT_CODE` | **Harness contract error — operator-supplied flag invalid, scratch-root violation, suite missing, capability gate breach, Reporter contract violation, or run-body deferred.** All these constants resolve to `2` and represent "the harness rejected the run before / during dispatch." |
| 3 | `RUN_INTERRUPTED_EXIT_CODE`, `signal_handler.EXIT_INTERRUPTED` | Operator interrupted the run (SIGINT/SIGTERM cooperative cancellation). |

The T04.17 / D-0078 Reporter contract suite pins
`REPORTER_CONTRACT_VIOLATION_EXIT_CODE == 2` + the exception type at
the **library boundary**. This test module pins
`HARD_FAIL_EXIT_CODE == 2` and the process-level `returncode == 2`
contract at the **CLI boundary**. Together they prove the constant
both holds and flows.
