## Transferability Tag Legend

- **TRANSFERABLE** — feature can attach to a `/task` extension point with little
  or no shape change; semantics survive intact.
- **ADAPTABLE** — feature is conceptually portable but requires re-shaping
  (different invocation model, missing dependency, or boundary conflict) before
  it can land on `/task`.
- **NON-TRANSFERABLE** — feature is structurally tied to the `/sc:task`
  command-and-skill model and has no coherent attach point on the `/task` F1
  loop, or it would violate `/task`'s prohibited-actions / F4 mutation rules.
- **DUPLICATE-OF-EXISTING** — `/task` already provides equivalent capability;
  donor row contributes no new feature. Deeper duplicate confirmation happens
  in T01.03 — first-pass marks here are *candidates* for that confirmation.

All four tags appear in this catalog.
