# Sprint rerun-tasks v4.3.0 — granular per-task rerun for sprint pipeline

## Task Overview

This task implements the v4.3.0 release of `superclaude sprint rerun-tasks`, a new CLI subcommand under the existing `sprint` Click group that re-executes only the named failed tasks within a single phase, then merges the rerun results back into the canonical results directory and tasklist. The operational pain it solves was demonstrated by the MultiModelSwarm Phase 7 case: when 2 of 21 tasks failed due to transient API outage, the current sprint pipeline forced a full-phase rerun via `--start N --end N`, wasting tokens on the 19 already-PASS tasks. The new verb lets operators surgically re-run only `--phase 7 --tasks T07.11,T07.12` and merge results back atomically.

The implementation lands in `src/superclaude/cli/sprint/`, mirroring the canonical patterns established in `checkpoints.py`. Two new modules are created: `recovery.py` (~250 LOC) hosts the `RecoveryBundle` dataclass, `RecoveryStatus` enum, `Nominator` protocol, generic `merge_recovery_bundle()` engine, lock-file helpers, SHA256 helpers, and shared audit-log writer; `rerun_tasks.py` (~280 LOC) hosts the orchestration verb (`extract_phase_subset`, `walk_dependencies`, `build_sub_index`, `flip_target_checkboxes`, `run_rerun_tasks`, transcript-fallback discovery). Four existing modules are edited additively: `commands.py` (~90 LOC for the Click block), `models.py` (~70 LOC for `FAIL_TERMINAL` rename + `FAIL_RECOVERABLE` add + `PhaseResult.task_results`/`recovery_history` + JSON ser/de), `executor.py` (~40 LOC for `phase-N-result.json` write + classification heuristic), and `checkpoints.py` (~30 LOC for the optional `RecoveryBundle` return wrapper, forward-compat for v4.4.0).

The verb pre-positions for v4.4.0 SprintRunReflect integration via the `--from-reflect-report` flag (resolved by a `ReflectReportNominator` implementation of the shared `Nominator` protocol), and pre-positions for the eventual v4.4.0/v5.0.0 `sprint repair` umbrella verb. Defenses against the 7 known failure modes (SHA256 mid-flight-edit detection, retry-cap-3, `.failed-<ts>` forensic rename, stash-and-restore for partial deliverables, concurrent-recovery lock file, bundle-dir collision auto-suffix, abort auto-restore) are mandatory per TDD §T8.

## Key Objectives

The following objectives MUST be achieved by this task:

1. **Data model foundation:** Add `FAIL_RECOVERABLE = "fail_recoverable"` to `TaskStatus` enum and rename `FAIL` → `FAIL_TERMINAL` keeping serialized value `"fail"` for wire back-compat (per `research/06-gate-resolutions.md` Resolution 1); add `task_results: list[TaskResult]` and `recovery_history: list[RecoveryBundleRef]` fields to `PhaseResult`; widen `is_failure` predicate to include both terminal and recoverable variants (per Resolution 2); add `to_dict()`/`from_dict()` JSON helpers on `TaskResult`.
2. **Recovery abstraction:** Create `src/superclaude/cli/sprint/recovery.py` (~250 LOC) containing `RecoveryBundle` dataclass, `RecoveryStatus` enum, `Nominator` protocol with `ManualNominator` and `ReflectReportNominator` implementations, `merge_recovery_bundle()` 7-step engine, `write_recovery_audit_log()`, `compute_tasklist_sha256()`, `acquire_recovery_lock()`/`release_recovery_lock()`, and `retry_count_for_task()`.
3. **Rerun engine:** Create `src/superclaude/cli/sprint/rerun_tasks.py` (~280 LOC) containing `extract_phase_subset()` with regex slice + round-trip parser validation, `build_rerun_bundle_dir()` with auto-suffix `-1..-9`, `build_sub_index()`, `walk_dependencies()` with `--include-transitive`/`--ignore-deps`, `discover_failed_tasks_from_transcripts()` legacy fallback, `flip_target_checkboxes()`/`restore_checkboxes_on_abort()`/`finalize_checkboxes_on_success()`, `stash_and_restore_deliverables()`, `select_default_recoverable_tasks()`, and `run_rerun_tasks()` orchestration entrypoint.
4. **CLI surface:** Add `@sprint_group.command("rerun-tasks")` Click block (~90 LOC) to `commands.py` exposing 12 flags (`--phase`, `--tasks`, `--from-reflect-report`, `--merge-back/--no-merge-back`, `--dry-run`, `--include-transitive`, `--ignore-deps`, `--force-merge`, `--allow-loop`, `--no-verify-checkpoints`, `--bundle-dir`, `--restore`) with Click mutex enforcement, plus the post-merge auto-invoke of `verify-checkpoints --recover --phase N --quiet`.

6. **Logging wiring:** Edit `logging_.py` to add `write_phase_rerun_complete()` (and sibling start/per-task events) emitting `phase_rerun_start`, `task_rerun_complete`, `phase_rerun_complete` JSONL events.
7. **Checkpoints forward-compat:** Edit `checkpoints.py` to optionally wrap `recover_missing_checkpoints()` return into a `RecoveryBundle` (~30 LOC) for v4.4.0 unified recovery surface.
8. **Test coverage:** Create 4 new test files (`test_recovery.py`, `test_rerun_tasks.py`, `test_rerun_tasks_e2e.py`, `test_rerun_tasks_failure_modes.py`) and edit 5 existing test files (`test_cli_contract.py`, `test_models.py`, `test_executor.py`, `test_checkpoints.py`, `test_backward_compat_regression.py`) for a total of ~42 tests; AC1-AC8 each map to ≥1 specific pytest test per `research/04-test-patterns.md` §6.
