# Issue watcher: zero-setup rollout (requirements for a future sprint)

Status: backlog. Requirements are still being collected; each new need is added as a row below when it is found, and each built or tested piece is logged under "Built and tested".
Started: 2026-11-18. Owner: IronbellyOrg maintainers.
Tracker: GitHub issue 450 (roll out the issue watcher). Existing design: `docs/designs/issue-watcher.md`. Existing owner runbook: `docs/designs/issue-watcher-setup.md`.

## Goal

The issue watcher starts by itself in every workspace and needs no setup by the person using it. Everything it needs is either saved centrally in the Coder template or read automatically when a project is added to Orca.

## Findings that shaped the rows (verified 2026-11-18)

- `superclaude issue-watch check-config` failed with `config_invalid` at the start: no configuration file, no state directory, no approvers file.
- The watcher reads one configuration file with one `project_id`, one `worktree` and one approvers file (`src/superclaude/cli/issue_watch/cycle.py`, `load_config`).
- The workspace's GitHub login has the `project` permission. `gh api user` returns the account number (ironbelly is 7361222). `gh project list --owner IronbellyOrg --format json` lists the Projects. The Project a repo's issues sit on is found per repo with the GraphQL query `repository(owner, name){ projectsV2(first:10){ nodes{ id number title } } }`; for `IronbellyOrg/IronClaude` it returns "Ironclaude - Development", number 2, id `PVT_kwDODPJUp84Bo16j`.
- Maintainers come from `gh api "repos/<owner>/<repo>/collaborators?permission=maintain"`. For `IronbellyOrg/IronClaude` that is clayphi (193966884) and IB-JonathanB (254764696); ironbelly (7361222) is admin.
- Orca has `orca repo add` and `orca repo list` but no event that fires when a project is added. `orca repo list` today shows IronClaude, Coder, IronOrca, Ironeye, Ironbrain and one temporary test repo.
- This host has no `crontab` command. PID 1 is the Coder agent (`coder`), not systemd, and `systemctl --user is-system-running` prints `offline`, so systemd timers are not available. `orca automations create` exists (cron triggers, `--precheck`), but it starts an agent session with a prompt on each run.
