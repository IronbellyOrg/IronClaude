## Findings Table

| F1 | **G0-1 corpus is likely infeasible on a fork.** The plan requires ≥20 PRs + ≥10 merges for High-confidence graduation (§7, §13). This repo is a fork of SuperClaude-Org/SuperClaude_Framework; most PRs live upstream, not on IronbellyOrg/IronClaude. The "synthetic-backfill plan" is mentioned as a fallback but is never specified — no procedure exists for generating synthetic PRs that exercise entity diffs, merge conflicts, or risk triage with statistical validity. Use-case reports cite 30 merge commits and 152 Python commits, but these are *commits*, not PRs. Without a defined backfill method, the graduation gate cannot close. | **High** | §2 G0-1, §7, §13 | The entire eval's confidence label is capped at Low until this is resolved, making every KEEP/kill verdict non-actionable. |
| F2 | **Blind adjudication assumes a panel that does not exist.** §7 calls for "hide tool source from judge; dedupe findings; require evidence citation" — classic blind review. The framework has one developer. The person who runs the shadow eval is the same person who labels findings. No mechanism is provided for achieving blinding solo (e.g., automated output anonymizer, randomized naming, delayed adjudication). Without blinding, the judge's knowledge of which tool produced which finding introduces confirmation bias that invalidates the "falsifiable" claim. | **High** | §7 Judging Protocol | Every precision/recall number is contaminated if the judge knows the source. The plan's core claim of falsifiability is undermined. |
| F3 | **100% true-conflict preservation is unmeasurable for Markdown.** Weave's S2 gate demands "zero semantic-corruption divergences outside fallback envelope — one corruption = automatic KILL" (§8.3). But the repo is ~92% Markdown; weave falls back to line-merge for `.md` with no tree-sitter parser. Detecting semantic corruption on Markdown SKILL.md files requires human inspection of every merged artifact or a behavioral test suite that covers spec prose — neither exists. The Python test suite (449 files) only covers Python behavior. The "envelope" itself is undefined. | **High** | §5 MC metric, §8.3 weave S2, §12 risk register | The kill gate cannot be enforced because corruption cannot be reliably detected on the dominant file type. The gate is either trivially passed (only Python tested) or trivially failed (human can't inspect all merges). |
| F4 | **Token-reduction baseline vs Auggie is underspecified.** The sem S2 gate requires "≥30% token reduction vs Auggie" (§8.1), and §13 says "both raw diff and Auggie measured." But the harness does not specify how to isolate Auggie's token contribution from the rest of the review prompt. Auggie retrieval is one pass inside a multi-wave protocol; the prompt also contains the diff, skill instructions, and model context. Without a token-metering method that attributes tokens to Auggie specifically vs the surrounding prompt, the 30% delta is unmeasurable. The plan says "pin fixed provider in shadow" for inspect but not for sem. | **Medium** | §5 CP metric, §8.1 sem S2, §13 | The headline value metric for sem — the tool that gates the entire chain — cannot be measured as written. |

G0-1 allows synthetic backfill but does not specify what confidence label applies to synthetic data. If the repo has 12 real PRs (between the tiers), what confidence applies? The plan provides no interpolation, leaving a gap where verdicts have no defined confidence label. | **Medium** | §7, §2 G0-1 | Ambiguous confidence in the most likely scenario (partial native corpus + partial synthetic), leaving the gate decision without a defined standard. |
