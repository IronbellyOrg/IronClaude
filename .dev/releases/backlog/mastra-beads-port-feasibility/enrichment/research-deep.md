**Capabilities:**

- Dependency-aware DAG of work items with cycle detection (`bd dep cycles`), ready-work computation (`bd ready` = unblocked + priority-sorted), and impact/tree visualization (`bd dep tree`, `bd graph`).
- Agent-native machine interface: every key command supports `--json`; atomic claim (`bd update --claim`) for race-free multi-agent work dispatch; `bd prime`/`bd remember` give agents persistent cross-session memory — directly addresses the 'agent goldfish memory' problem.
- Hash-based collision-resistant IDs purpose-built for concurrent multi-agent / multi-branch writes.
- Multi-writer concurrency via Dolt server mode + gates; cross-repo dependencies via `external:` refs; built for swarms of agents working in parallel.
- Version-controlled SQL database (Dolt) underneath: real SQL queries for dependency analysis, branch/merge/commit history of the issue graph itself, Dolt-native replication (push/pull/remote).
- Coordination primitives beyond a plain tracker: gates (human/timer/GitHub-PR async coordination), formulas (repeatable workflow templates), molecules (work graphs), GitHub Issues two-way sync.
- Rich ecosystem of community web UIs/TUIs and an emerging MCP surface (beads-mcp, BeadHub's 16 MCP tools).

**Gaps:**

- NOT a markdown task-of-record. Storage is a Dolt SQL database; JSONL is export-only and lossy (no branches/history/working-set). If you want human-reviewable diffable markdown as the source of truth, Beads is the wrong layer — that is exactly Backlog.md's job. This is the crux of the overlap question (see fit_for_port).
- Multi-tenancy / RBAC: NONE at the Beads layer. 'Multi-writer' (Dolt server mode) is concurrency, not tenancy. There is no per-user auth, no role-based permissions, no tenant isolation. A company-wide multi-tenant deployment must impose tenancy ABOVE Beads (in Mastra's server.auth/RBAC + per-tenant DB/prefix scoping). Beads gives you one shared graph per Dolt database; tenant isolation = separate databases/prefixes managed by the orchestration layer.
- Operational stability risk on the current Dolt-only line: orphaned `dolt sql-server` processes, embedded-mode panics, and migration-induced pull failures are open issues as of mid-2026. Running Dolt server mode for multi-writer adds an external stateful service to operate (ports, daemons, backups) — non-trivial ops surface vs an embedded SQLite file.
- Architectural churn: rapid, sometimes-breaking releases; a notable contributor forked to freeze the old architecture. Betting the company's work-of-record on a target moving this fast is a strategic risk; version-pinning + an abstraction seam is mandatory.
- First-party MCP server maturity is UNVERIFIED — beads-mcp exists on PyPI but the most stable, documented agent interface remains the bd `--json` CLI, not MCP. Do not assume a production-grade official MCP server.
- No native UI for human PMs that is first-party/supported — all web UIs are community projects of varying maintenance (some flagged stale in COMMUNITY_TOOLS.md).
