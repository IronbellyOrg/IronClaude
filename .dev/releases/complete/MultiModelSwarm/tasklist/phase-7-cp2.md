1. **FR-004 `swarm attach` subcommand (R-123, T07.07)** — `src/superclaude/cli/swarm/commands.py:2414` (`attach_cmd(job_id)`, decorated `@click.command("attach")` at line 2412) re-attaches an operator's terminal to a detached swarm tmux session named via `tmux.session_name(job_id)`. The subcommand validates `job_id` through `tmux.session_name(...)` (rejects spaces, colons, dots, tabs, newlines — same boundary the launcher applies), exits with the Click usage code if `tmux.is_tmux_available()` is False, exits zero gracefully when the session has already terminated (`has_session(job_id)` False — covers the "I killed it; let me check" race), calls `tmux.attach(job_id)` when the session is live, and propagates the tmux client's non-zero return code. Two race classes are surfaced explicitly: session-missing race (sentinel disappears between `has_session` and `attach`) and tmux-unavailable race (binary removed mid-call).
2. **FR-005 `swarm kill` subcommand (R-124, T07.08)** — `src/superclaude/cli/swarm/commands.py:2616` (`kill_cmd(job_id, output_dir)`, decorated `@click.command("kill")` at line 2600) terminates a detached swarm tmux session by `job_id` and writes the terminal-state marker pair: (a) `<output_dir>/.swarm-state.json` flipped to a `killed` terminal state via `_write_killed_terminal_state` (line 2565); (b) `<output_dir>/done.json` sentinel emitted via `_emit_killed_done_sentinel` (line 2525) with `terminal_status: "killed"` — the only legal terminal status outside the `ResultStatus` enum (`"killed"` is bypassed past the `DoneSentinel.__post_init__` dataclass validation that T07.13 introduces). Behaviors: idempotent (second invocation is a no-op), graceful when tmux is unavailable, graceful when the session is already gone, creates the output dir when missing, rejects `output_dir` that is a file, uses `os.replace` for the sentinel atomic write.
3. **FR-006 `swarm scaffold --lens <name>` subcommand (R-125, T07.09)** — `src/superclaude/cli/swarm/commands.py:2805` (`scaffold_cmd(lens_name, output_path)`, decorated `@click.command("scaffold")` at line 2776) emits a starter JobSpec JSON document for one of the seven bundled lenses (`bare-review`, `refactor-find`, `edge-case-hunt`, `spec-completeness`, `feasibility-probe`, `troubleshoot-hypothesis`, `doc-completeness`). The emitted JSON: (a) round-trips through the DM-001 JobSpec schema (`test_scaffold_output_validates_via_schema` parametrized over all 7 lenses); (b) round-trips through `swarm validate --stdin` (`test_scaffold_output_validates_via_swarm_validate`); (c) carries the lens injection-guard substring (verified by `test_scaffold_stdout_carries_injection_guard_substring`); (d) is pure JSON on stdout (no shell-script noise — `test_scaffold_stdout_is_pure_json`); (e) writes atomically via tmp+os.replace when `--output` is provided. Custom / unknown lenses are rejected at the boundary.
4. **FR-013 `docs/swarm/monitoring-patterns.md` operator documentation (R-126, T07.10)** — `docs/swarm/monitoring-patterns.md` (179 LOC, 23 headings) documents three operator-grade observability patterns with paste-ready commands runnable against the `--transport stub` fixture: **Pattern 1** — `Bash run_in_background + until [ -f done.json ]` (atomic-sentinel polling, depends on the T07.13 done sentinel); **Pattern 2** — `Monitor` JSONL tail (live-tail the `execution-log.jsonl` stream, surfaces `worker_complete` events with slot + elapsed_ms, uses the `--tail == --jsonl --follow` shorthand built into `swarm logs`); **Pattern 3** — `swarm status --watch` (phase-transition polling at 2-second intervals, exits at terminal; exit-code matrix: 0 success / 1 partial-or-failed / 2 usage error). Each pattern has its own "When this pattern fits" section so operators can pick the right tool for the failure mode they're hunting.
5. **FR-014 `swarm run --detached` flag wiring (R-127, T07.11)** — `src/superclaude/cli/swarm/commands.py:1060` declares the `--detached` Click option on `@click.command("run")` (line 955) wired through `run_cmd` (line 1078). When `--detached` is set, the resolved JobSpec (with CLI overrides applied) is staged to `<output_dir>/.swarm-detached-spec.json` (DETACHED_SPEC_SNAPSHOT_FILENAME) and the child tmux process re-invokes `swarm run` against the snapshot — the inline executor never runs in the parent. The detached path is implemented by `_launch_detached_run(spec_dict, input_mode)` at line 799, which (a) lazily imports `swarm_tmux` to keep the inline path free of the tmux module's `subprocess` surface; (b) fails closed with the Click usage code when `tmux.is_tmux_available()` is False (no silent fallback to inline — operators who passed `--detached` get a clear error); (c) validates `job_id` through `session_name(...)`; (d) requires a resolvable `output.dir`; (e) stages the spec atomically; (f) launches via `tmux.launch_detached(...)` and exits with the launcher's return code. `--detached` is mutually exclusive with `--resume` (line 1154) because resume orchestrates its own pipeline inline.
