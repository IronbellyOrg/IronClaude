## 3. Category Legend

| Category | Definition | Default handling |
|---|---|---|
| EXACT_DUPLICATE | Same work appears in multiple tasklists with no meaningful unique scope. | Merge into one canonical item. |
| PARTIAL_OVERLAP | Similar work appears in multiple tasklists but scope, sequencing, or verification differs. | Merge, split, or clarify boundary. |
| DEPENDENCY | One task produces an artifact, decision, or precondition consumed by another task. | Reorder or add explicit dependency. |
| CONFLICT | Tasks prescribe incompatible behavior, sequencing, source of truth, file ownership, verification, or gating. | Needs resolution before execution. |
| UNDERMINES | One task weakens, bypasses, or invalidates another task's safety/acceptance criteria. | Usually discard/replace weaker item or require human decision. |
| DISCARD_CANDIDATE | A task is likely obsolete, unsafe, duplicative with no unique value, or undermines stronger work. | Discard only with high confidence or explicit human decision. |
| DISTINCT | No meaningful overlap or conflict. | Keep as separate work. |
| TRANSITIVE_CONFLICT | Third-tasklist append pass: new task interacts with an existing matrix recommendation in a way that changes/invalidates it. | Append revision note; do not overwrite old row. |
