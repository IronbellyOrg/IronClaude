### F2. Click group definition style (CODE-VERIFIED)

Two group-definition shapes exist:
- `reflect` (`reflect/commands.py:53-54`): `@click.group("reflect")` then `def reflect_group():` with a docstring that has an `Examples:` block (lines 63-67). Subcommands: `@reflect_group.command("contract-status")` (line 82) and bare `@reflect_group.command()` for `run` (line 221). Heavy imports are inside the command body (`reflect/commands.py:105-112`, `:362-363`): "Heavy imports (config/runner) are lazy inside the command body (house convention)" (docstring lines 5-6).
- `swarm` (`swarm/__init__.py:97-111`): `_SWARM_CONTEXT_SETTINGS: dict[str, object] = {"help_option_names": ["-h", "--help"], "max_content_width": 100}` and `@click.group("swarm", context_settings=_SWARM_CONTEXT_SETTINGS)`; subcommands are `@click.command("validate")` functions in `swarm/commands.py` added with `swarm_group.add_command(x, name="...")` (`swarm/__init__.py:175-182`).
- Smaller groups (`sprint/__init__.py:1-5`, `roadmap/__init__.py:1-10`, `prd/__init__.py`) define the group in `commands.py` and re-export it from `__init__.py` with `__all__`.

For `issue_watch` the design fixes: group `issue_watch_group` in `cli.py` and "six verbs" (`docs/designs/issue-watcher.md:176`, `:759`). The table at lines 112-119 has six rows but five distinct command names: `once`, `status`, `check-config`, `init-state`, `reset` (two rows: `reset <N> --forfeit-guarantee` and `reset --rate-limit`). Line 120 says `reset` with both `<N>` and `--rate-limit`, or with neither, is a usage error (exit 2), so it is ONE Click command `reset` with an optional argument `N` and two flags that validates its own combination (Click cannot register two commands under one name). The builder should create five `@issue_watch_group.command(...)` functions and say so in the item, so a reviewer does not look for a sixth.

Every verb takes `--config <path>` default `~/.config/superclaude/issue-watch.json` (design 4.1 line 110). Click idiom: `@click.option("--config", "config_path", type=click.Path(path_type=Path), default=...)`; `type=click.Path(path_type=Path)` is used at `recommend/commands.py:61,81,168`, and `click.Path(exists=True, dir_okay=False, resolve_path=True)` at `reflect/commands.py:222-225`. Do not use `exists=True` on `--config`: the design wants a missing config to be exit 2 `config_invalid` produced by `cycle.load_config`, not Click's own exit 2 usage text (both exit 2, but the audit/`check-config` message differs). click is 8.5.1 in `uv.lock:108-109`; the floor is `"click>=8.0.0"` (`pyproject.toml:36`), so `click.Path(path_type=...)` (added in click 8.0) is within the floor. `reflect run` is declared with bare `@reflect_group.command()` (line 221), the command name coming from the function name `run`; verb names with hyphens (`check-config`, `init-state`) need the explicit form `@issue_watch_group.command("check-config")` as in `reflect/commands.py:82` (`@reflect_group.command("contract-status")`).

- Exit-code constants are defined next to the code that owns them, not in a registry: `eval/exit_codes.py:21-24` (`SUCCESS: int = 0`, `FAILURES = 1`, `USAGE_ERROR = 2`, `INTERRUPTED = 3`), `reflect/models.py:26-52` (`Verdict(str, Enum)` with an `exit_code` property mapping; docstring says "the load-bearing fail-closed contract"). - Reflect's fail-closed pattern also wraps the runner in `try/except Exception` that writes a sidecar then re-raises (`reflect/commands.py:442-469`): for `issue_watch`, the design's `once` has no such wrapper and the Store crash points C1 to C5 use `SystemExit` raised by a `CrashingStore` in tests (design section 12 line 779); `cli.py` must not catch `SystemExit`/`BaseException` around `run_cycle`.
- Stdout/stderr: human messages via `click.echo(...)`; errors with `err=True` (`reflect/commands.py:76-78,391,478-482`). Emoji output appears in install/doctor commands (`main.py:92-171`, `:494-509`) but not in pipeline commands (`reflect`, `swarm`): the design needs deterministic, machine-readable output for `status --json`; use `click.echo(json.dumps(...))`.
