### Current command contract

[CODE-VERIFIED] This is the friendly front door for people who want to **use swarm**, request multi-model review, need help selecting a lens, or cannot act on technical swarm documentation. A goal and target are required eventually, but the wizard collects missing inputs itself. The target must exist and meet the 50 non-whitespace-byte floor. The command delegates to the actual skill name `sc:swarm-wizard-protocol`; it does not implement the workflow itself. (`/config/workspace/IronClaude/.dev/worktrees/RecommendUpdate/src/superclaude/commands/swarm-wizard.md:13-33,57-78`.)

[CODE-VERIFIED] Verified wizard options are `--goal`, `--target`, `--output`, `--real`, `--detached`, `--advanced` and `--yes`. Defaults are guided questioning, stub-first operation and a fresh generated output directory. `--real` expresses intent, not authorization to skip consent. `--yes` minimizes questions, not safety gates. CLI options such as `--lens`, `--reviewers`, `--transport`, `--tui` and `--resume` are not wizard options. (`/config/workspace/IronClaude/.dev/worktrees/RecommendUpdate/src/superclaude/commands/swarm-wizard.md:45-55,80-90`.)

[CODE-VERIFIED] Running the wizard writes run artifacts, but its purpose is analysis rather than source-code implementation. The protocol requires a successful stub dry-run, explains that stub findings are placeholders, then requires satisfied proxy prerequisites and explicit consent for real execution. Outputs include worker outcomes, merged findings, contract location and a recommended next command. Failed/partial runs can lead to a CLI resume offer; the wizard has no public `--resume` flag. [CODE-VERIFIED] **MUST, proposed policy:** Expand the existing guide's `multi-model-review` intent and section 3.6 explanation to cover running swarm, guided multi-model review and help choosing swarm settings. Explicit swarm-use intent should win over generic review/explanation phrasing; merely mentioning swarm implementation should not. ### Acceptance/regression scenarios

[CODE-VERIFIED] Proposed scenarios derived from the contracts:

1. “Help me run swarm on this file; which lens?” selects the wizard.
2. “Review this spec using several model families” preserves swarm intent rather than selecting only spec-panel.
3. “Explain the swarm target loader” remains an explanation request.
4. Bare “review this spec” does not automatically select swarm.
5. Supplied goal/target survive; no CLI-only options are attached to the wizard.
6. `--yes --real` never implies permission to skip dry-run or consent.
7. Plugin-only missing wizard remains clearly marked unavailable.
8. A matched wizard request bypasses a seeded generic review cache entry.

Existing routing tests pin text, guide ordering, flags and availability gates, but do not establish these semantic outcomes.
