### Current command contract

[CODE-VERIFIED] `/sc:implement` accepts one existing spec, PRD, tasklist, informal document, or inline prompt. File aliases are `--spec`, `--prd`, and `--tasklist`; `--resume` is optional because matching-ledger resume is implicit. `--ledger` is constrained, and `--skip-final-review` prevents managed archiving. The command activates `sc:implement-protocol`; it does not itself contain the executor. Bare invocation has no source and stops. (C:15-83)

[CODE-VERIFIED] The protocol supports enumerable markdown tasks and whole-document fallback for informal text. It explicitly warns, rather than stops or splits, at twenty tasks. Sequential execution is the default; parallel execution requires source-marked independence and sets of at most three. Therefore neither a short-session ceiling nor a small-task-count ceiling is a documented executor limit. This is a verified contract, not measured capacity. (P:63-101)

[CODE-VERIFIED] The executor changes product files and writes progress. Per-task acceptance compliance is the verdict; lint, typechecks, and tests are recorded extras unless required by the acceptance criteria. Small first-pass reviews may occur inline, so recommendations must not promise an independent subagent for every task. Managed FINAL is always independent. The command neither auto-commits nor opens PRs nor releases. (P:99-157; C:119-134)

[CODE-VERIFIED] Resume preserves the original task baseline and consults the ledger. Managed package detection precedes ordinary source resolution, including stale pre-archive paths. QA failure and infrastructure failure have different stops: `E-HALT-QA` versus `E-RESUME-NEEDED`. Clear informed user acceptance can be recorded automatically, but `--force` is not an escape hatch. (P:24-65, 105-132)

### Comparison with recommendation surfaces

[CODE-VERIFIED] The central mismatch is policy, not command discovery. The guide’s `simple-plan` row limits workflow/implement to “a few files” and “one or two sessions.” Its `task-file` row promotes “many files,” “more than one session,” or “must not drift” to MDTM. Its `feature-existing` row defaults even clear existing-system features to task-builder/task. Meanwhile implement explicitly supports resume, acceptance-based review, and larger enumerable lists. These facts do not establish unlimited capacity, but they undermine those automatic escalation proxies. (G:305-307; P:63-101, 123-132)

[CODE-VERIFIED] Recommendation cannot correct that mismatch merely by ranking implement more highly: a matched guide row decides the answer, bypasses cache and semantic ranking, and cannot be replaced with a lighter command in Phase 1. The guide must change together with recommendation wording. (R:58-60, 148-157)

[CODE-VERIFIED] The same old boundary appears in three fallback surfaces: recommendation Phase 1, its native-versus-delegation reference, and the cold-path runbook. The classifier also equates generic tasklist generation from a spec/report with task-builder/task. Fixing only the main guide would leave fallback behavior inconsistent. (R:155-157; H:38-39; Q:58-59, 78-79, 160-166)

[CODE-VERIFIED] Existing resume guidance already names both executors, and the guide expressly states that workflow packages belong to implement, not task. Preserve that behavior rather than rebuilding or converting an interrupted package. (G:213-216, 324)

### Acceptance/regression scenarios

[UNVERIFIED] Add these recommendation checks alongside T’s existing structural assertions:

1. Clear work across twelve files and several sessions defaults to workflow/implement unless additional extreme-workload requirements justify MDTM.
2. An existing approved workflow plan executes directly; resume does not regenerate it.
3. Explicit MDTM execution remains `/task`; an explicit implement invocation is not silently rerouted.
4. QA failure never produces `--force`; managed archive never receives routine `--skip-final-review`.
5. A review-only request remains review-only, not implementation.
6. Guide-matched, no-guide, and cold-path recommendations agree on the revised boundary.
