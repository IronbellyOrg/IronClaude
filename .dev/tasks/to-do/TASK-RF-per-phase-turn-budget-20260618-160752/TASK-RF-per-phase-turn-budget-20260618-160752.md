# Implement the Per-Phase Turn-Budget Model for the Sprint Runner (R-1..R-10, TM-0..TM-14)

## Task Overview

`run_sprint` (in `src/superclaude/cli/sprint/executor.py`) currently builds **one** `TurnLedger` before the phase loop, sized `initial_budget = config.max_turns * len(config.active_phases)` (`executor.py:1777-1780`), and shares that single pool across every phase. Because `--max-turns` is documented as **"Max agent turns per phase"** (`commands.py:92`), the global pool diverges from the documented unit: a heavy early phase drains turns later phases need, the per-task budget gate `try_launch()` returns False, later tasks are recorded `SKIPPED`, and the phase is mapped to `PhaseStatus.ERROR`. Empirically a `max_turns=100 × 3 phases = 300`-turn pool errored at phases 5/6 after 309 cumulative turns.

This task refactors the budget model so **each phase constructs a fresh `TurnLedger` sized `max_turns × len(tasks)`** at the tasks-resolution point, making per-phase independence structural (a new object every phase, no in-place reset, no cross-phase carryover). The single observable telemetry that the per-phase reset would silently regress — the sprint-cumulative wiring counters persisted in `gate-kpi-report.md` — is preserved by a **read-only sprint-level wiring accumulator** (OQ-1 Position A) constructed pre-loop and passed to `build_kpi_report` instead of the last phase's ledger. The `TurnLedger` model itself is **unchanged** (no new method); the legacy non-task subprocess **execution log** is **byte-equivalent unchanged** (only its wiring-hook ledger input is the deliberate, documented refinement). The change is pinned by a 15-item test matrix (TM-0..TM-14) anchored by the mandatory TM-0 regression test.

**This task implements the FINAL spec at `.dev/brainstorms/20260618-per-phase-turn-budget/merged-requirements-FINAL.md` (spec_version 3.0). Every `file:line` anchor below is from that spec and was re-verified live in this worktree on 2026-06-18; nevertheless YOU MUST re-`Read` each anchor at edit time, because anchors can drift between build and execution.** This task was design-only at build time and is executed by a FUTURE `/task` session on branch `perPhaseturnBudget`.

## Key Objectives

The following objectives MUST be achieved by this task:

1. **Remove the global pre-loop pool (R-1):** Delete the single `TurnLedger(initial_budget=config.max_turns * len(config.active_phases), ...)` construction at `executor.py:1777-1780` while leaving its pre-loop neighbors (`shadow_metrics`, `remediation_log`, `SprintGatePolicy`, `all_gate_results`) in place.
2. **Construct a fresh per-phase ledger (R-2, R-3, R-8):** Build `ledger = TurnLedger(initial_budget=config.max_turns * (len(tasks) if tasks else 1), ...)` at `executor.py:1838-1839`, after the python/skip `continue` guards, binding both the task branch and the legacy branch, with a construction-site comment stating the K-2 sequential-phase invariant.
3. **Preserve sprint-cumulative wiring KPI telemetry (R-10 / OQ-1 Position A):** Construct a read-only sprint-level wiring accumulator pre-loop next to `shadow_metrics`, add each phase's wiring fields into it after both wiring hooks, and pass the **accumulator** (not the last-phase ledger) to `build_kpi_report` at `executor.py:2417` — with zero coupling of the budget across phases.
4. **Keep the model and legacy execution log unchanged (R-5, R-6, R-7):** No code change to the gate or to `TurnLedger`; the legacy subprocess execution log stays byte-equivalent; only comments/log-strings/docstrings and the legacy wiring-hook ledger input change (the latter deliberately, documented, pinned by TM-13).
