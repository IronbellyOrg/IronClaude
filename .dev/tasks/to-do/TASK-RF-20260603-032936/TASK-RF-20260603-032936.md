# Implement sc-recommend lookup-cache layer (Haiku hot/cold dispatch + --eval pipeline + plugin eval gate)

## Task Overview

This task implements the sc-recommend lookup-cache feature — the round-3-converged design from a `/sc:brainstorm` + `/sc:adversarial` pass, authoritatively specified in `.dev/brainstorms/sc-recommend-lookup-cache/merged-requirements.md`. The current `sc-recommend` skill re-runs a full Phase-0 surface enumeration, a mandatory auggie semantic ranking, and a per-candidate source Read on EVERY `/sc:recommend` invocation, costing ~91K tokens. Research established that auggie ranking is ~46% (~42K) and the per-candidate Read is ~20% (~18K) of that cost — together ~two-thirds. A lazily-populated YAML lookup cache amortizes this across sessions: for the 60-70% of hot-path delegation-prompt requests that repeat, a `model: haiku` subagent classifies the request against the inlined cache table and emits the cached refined prompt, dropping the hot path to ~5-10K tokens. Cache misses fall through to a condensed cold-path runbook (still Haiku-driven) which writes the result back so the next identical request is a hit.

The feature also adds (R3) a per-row `best_model` recommendation populated by an opt-in `--eval <mode>` pipeline that spawns parallel subagents across `[opus, sonnet, haiku]`, grades their deliverables against assertions, aggregates per-model pass-rate/tokens/duration, and selects a best model via deterministic tier rules (quality/speed/cost/balanced). A separate plugin lookup table + 4-phase eval-gated adoption lifecycle (with a HARD-BLOCK precondition self-check) supports the `--plugin` ecosystem-search mode.

This is a code-modifying task spanning Python (a new `src/superclaude/cli/recommend/` module mirroring `cli/tasklist/`), skill prose (condensing and extending `src/superclaude/skills/sc-recommend/`), the `/sc:recommend` command, `.gitignore`, CLI registration, and tests. It contains ONE hard-halt human-decision item — the Python-vs-skill-prose boundary (Option H vs Option P vs Option Hybrid) — placed early, which BLOCKS the dispatch-wiring and `--eval` implementation phases until a human resolves it, because those phases cannot be written coherently without knowing which layer owns dispatch logic. Two soft-PENDING Open Questions (OQ3 best_model advisory-vs-prescriptive; the eval-reuse `.dev`-port-vs-cliEval conflict) are documented at the bottom of this file and do NOT gate implementation.

## Key Objectives

The following objectives MUST be achieved by this task:

1. **Boundary-independent foundation:** Create the `src/superclaude/cli/recommend/` module skeleton, the YAML cache reader/writer (atomic write, surface_hash reset), the telemetry JSONL appender, and the `.gitignore` tracked-cache exception — all of which are independent of the Python-vs-skill boundary decision.
2. **Human-decision gate (HARD-HALT):** Surface the Python-vs-skill-prose boundary as a `⚪ Blocked` halt item presenting Option H / Option P / Option Hybrid, blocking the dispatch and eval phases until the operator chooses.
3. **Classifier + condensed cold-path runbook:** Author the closed-enum Haiku classifier prompt and the ~50-line condensed cold-path runbook that preserves the Phase-0 gate, R1-R4, native-first default, graceful degradation, and the return contract.
4. **Hot/cold dispatch wiring:** Wire the hot-path lookup + cold-path write-back into `sc-recommend/SKILL.md` and the `/sc:recommend` command (`--eval` flag, expanded `allowed-tools`), per the boundary decision (blocked-by Objective 2).
5. **--eval pipeline + plugin eval gate:** Port the `.dev`-style grader/aggregator, implement the deterministic best_model tier selection, and the plugin precondition + adoption gate (blocked-by Objective 2).
