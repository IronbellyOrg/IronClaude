## 3. Target State

### 3.1 Desired behavior

A watcher selects GitHub issues that are tagged (trigger label), human-approved, in a GitHub Project and in Backlog status, and causes exactly the right developer's Coder workspace to start one new session that runs `/sc:issue --claim <N>`. The issue must also be meant for the polling workspace's `gh` login, so that workspaces do not race for the same issue. The watcher's job ends when the claim session has been started: the claim assigns the issue, optionally assigns the ClickUp task, runs the accuracy check and summary, posts two marked comments and stops at `next-steps.md` (file 01 sections 1 to 3). Everything after the claim (brainstorm, design, workflow, implement) stays manual.

The shape below is the flow the owner's decided option A implies. It is drawn from the research files (file 01 sections 3, 9 and 12; file 02 section 3.3; web-01 section 14.3; web-02 sections A and J); the routing rule and the exact selection query are still design choices (see 3.4 and Section 4).

```
 GitHub (IronbellyOrg/IronClaude)                Coder workspace of developer D
 ---------------------------------               ------------------------------------------------
 issue: trigger label                            poller = plain process (not a Claude session,
        + approval label by a human                      not a worker run), runs every 5 minutes
        + in a Project, Status = Backlog         as D's own `gh` login
        + meant for D's login                    1. read candidates (reads only; no title/body)
                                                 2. check approver, check intended owner
        <------------- gh reads -----------      3. write dispatch record BEFORE launch
                                                 4. build prompt = "/sc:issue --claim " + str(int(N))
                                                 5. orca agent launch --agent claude
                                                      --worktree path:<checkout> --surface terminal
                                                      --prompt <prompt>        (argv list, no shell)
                                                              |
                                                              v
                                                 ordinary top-level Claude session in the checkout
                                                 /sc:issue --claim N  -> assign @me, ClickUp (optional),
                                                 accuracy check, summary, 2 marked comments, STOP
                                                 (next-steps.md is for a person to run)
```
