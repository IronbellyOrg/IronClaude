# Fix the three `ic` launcher bugs (#542, #543, #544)

Source: ./source.md
Goal: `src/superclaude/scripts/ic` prints help even when the `AIENV` file fails (#544), prints a clear message when an option that needs a value gets none (#543), and resolves a model value through a variable only when that variable is a lowercase-initial alias name (#542). Each fix has a test in `tests/cli/test_ic_launcher.py` that fails on the old script and passes on the new one.

## Constraints

- Scope is the three issues and nothing more. Do not change the preset format, slot handling, the `--no-yolo` flag, the stderr slot summary, or how unknown flags are forwarded.
- Edit only `src/superclaude/scripts/ic`, the new test file `tests/cli/test_ic_launcher.py`, and the comment in `src/superclaude/cli/sprint/aienv.py` named in Task 4. The script has no mirror under `.claude/` or `plugins/superclaude/` (`make sync-dev` does not copy it), so there is nothing to sync for it.
- The usage block in the script header (file lines 2 to 11) must stay byte-identical: `--help` prints file lines 2 to 15 with the leading `# ` removed.
- Do not edit historical records (`docs/testing/v5.0.0/`, `docs/releases/`, `docs/designs/`, past `CHANGELOG.md` entries) and do not add a `CHANGELOG.md` entry.
- Existing behaviour that must not change: a valid preset applies all its slots; an unknown preset exits 2 with its message; arguments after `--` go to `claude`; unknown flags go to `claude`; a missing or failing `AIENV` file on a normal launch keeps the current strict behaviour (a failing file stops `ic` before `claude` starts).
- One commit per issue, in task order: Task 1 for #544, Task 2 for #543, Task 3 plus Task 4 for #542.

## Phase 1: Help works without the environment file (#544)

## Task 1: Handle `--help` and `-h` before sourcing `AIENV`, and create the test file

In `src/superclaude/scripts/ic`, add a pre-scan of the arguments before the `AIENV` block (currently file lines 25 to 31, with `set -euo pipefail` at line 23). The pre-scan walks the arguments with the same rules as the main parse loop: `-p`, `--preset`, `-H`, `--haiku`, `-S`, `--sonnet`, `-O`, `--opus` take a value and the value is skipped; `--` stops the scan; `-h` or `--help` prints file lines 2 to 15 with the leading `# ` removed (the same `sed` pipeline the current handler uses) and exits 0. Advance the index with `i=$((i + 1))`, not `((i++))`, because the script runs under `set -e`. Remove the `-h|--help` case from the main loop (current lines 80 to 82), since the pre-scan is now the only help handler. Keep the `AIENV` block itself unchanged.

Create `tests/cli/test_ic_launcher.py`, following the style of the other `tests/cli/` files. It runs the real script with `bash <path>` where the path comes from `importlib.resources.files("superclaude.scripts").joinpath("ic")` (the same lookup `tests/unit/test_cli_install.py` uses). Each run gets a temporary directory that holds a stub `claude` executable (a shell script that prints the three `ANTHROPIC_DEFAULT_*_MODEL` values and its own arguments, one per line, to stdout) placed first on `PATH`, a temporary `HOME`, and `AIENV` pointing at a file the test writes. The environment passed to the subprocess is built from scratch (no inherited `ANTHROPIC_*` variables). Write the helper once and reuse it in Tasks 2 and 3.

Tests for this task, each named for the behaviour:
- `--help` and `-h` with an `AIENV` file that contains the single line `false` exit 0 and print the usage text (it contains `ic <alias-or-model>`); this test fails on the old script (exit 1, no usage).
- `--help` with an `AIENV` file path that does not exist exits 0 and prints the usage text without the "not found" warning.
- A normal launch (no `--help`) with the failing `AIENV` file exits non-zero and the stub `claude` does not run (strictness is kept).
- `-- --help` forwards `--help` to the stub `claude` (the pre-scan stops at `--`).
- `-p --help` still treats `--help` as the preset name: exit 2 and the unknown-preset message.

Acceptance criteria:
- Running `bash src/superclaude/scripts/ic --help` with `AIENV` set to a file containing `false` exits 0 and prints the usage block; on the unmodified script the same command exits 1.
- `src/superclaude/scripts/ic` file lines 2 to 11 are byte-identical to before, and `ic --help` output starts with the same first line as before.
- `grep -n 'help' src/superclaude/scripts/ic` shows one handler (the pre-scan) and no `-h|--help` case in the main loop.
- `uv run pytest tests/cli/test_ic_launcher.py -v` passes after the script change; the same file run before the script change (tests written first, script still unmodified) shows the failing-before test from the first bullet failing, and that output is saved as evidence.
- Callers and dependents: `src/superclaude/cli/ic.py` (runs `bash <script> "$@"`) and `tests/unit/test_cli_install.py` (checks the file is packaged) are unaffected and their tests still pass.

## Phase 2: Missing option values give a clear message (#543)

## Task 2: Check that `-p`, `-H`, `-S`, `-O` (and long forms) have a value

Depends on: Task 1

In `src/superclaude/scripts/ic`, add one shared check at the top of the main parse loop, before the existing `case`: when `$1` is one of `-p`, `--preset`, `-H`, `--haiku`, `-S`, `--sonnet`, `-O`, `--opus` and fewer than two arguments remain, print `ic: option $1 requires a value` to stderr and exit 2 (exit 2 matches the script's other usage errors, such as the unknown-preset path). The check must run before `apply_preset "$2"` and the three `resolve "$2"` calls so none of them reads an unset `$2` under `set -u`. Do not change the `case` arms.

Add tests to `tests/cli/test_ic_launcher.py`: for each of the eight option spellings given with no value, the run exits 2, stderr contains `requires a value` and the option as typed, stderr does not contain `unbound variable`, and the stub `claude` did not run. Also a guard test: `-p <name>` with a defined `IC_PRESET_<name>` in `AIENV` still applies every slot of the preset.

Acceptance criteria:
- `bash src/superclaude/scripts/ic -p` exits 2 and prints `ic: option -p requires a value`; on the unmodified script it exits 1 with `$2: unbound variable`. The same holds for `--preset`, `-H`, `--haiku`, `-S`, `--sonnet`, `-O`, `--opus`.
- The test for each spelling fails on the old script and passes on the new one; the preset guard test passes on both.
- A value that is present (`-p coding`, `-H kimi`) behaves exactly as before.

## Phase 3: Alias lookup is limited to alias names (#542)

## Task 3: Restrict `resolve` to lowercase-initial alias names and correct the header comment

Depends on: Task 2

In `src/superclaude/scripts/ic`, change the identifier test in `resolve` (current file line 41) from `^[a-zA-Z_][a-zA-Z0-9_]*$` to `^[a-z][a-zA-Z0-9_]*$`: only a name that starts with a lowercase letter can be an alias. Aliases in the header example are `kimi` and `qwen`, while the variables that must not resolve (`HOME`, `PATH`, `USER`, `SHELL`, `LITELLM_API_KEY`, `ANTHROPIC_*`) start with an uppercase letter or an underscore. The literal pass-through for every other value stays. `resolve` is the single place all callers go through: the three preset slots in `apply_preset`, `-H`, `-S`, `-O` and the first bare positional, so one change covers all of them. Rewrite the stale resolution comment in the header (file lines 13 and 14, which names `$IC_ALIASES`, a variable the code never reads) and the comment block above `resolve` so they state the real rule: a value that is a lowercase-initial variable name defined in the `AIENV` file resolves to that variable's value; any other value is passed through unchanged. Keep the header the same number of lines so that `--help` still prints lines 2 to 15 and the usage block (lines 2 to 11) is not touched.

Add tests to `tests/cli/test_ic_launcher.py`, using an `AIENV` file that defines `export kimi=kimi-k2.6`:
- `-H HOME`, `-S HOME`, `-O HOME`, the bare positional `HOME`, and a preset `opus=HOME` leave the slot set to the literal `HOME`, not the temporary home path; the same for `PATH`; these fail on the old script.
- `-H kimi`, `-S kimi`, `-O kimi`, bare `kimi` and a preset `haiku=kimi` set the slot to `kimi-k2.6`.
- `-H qwen3.6-plus` (literal id) and `-H nosuchalias` (lowercase name with no variable) pass through unchanged.

Acceptance criteria:
- With `HOME` set to a temporary folder, `ic --no-yolo -H HOME` gives the stub `claude` `ANTHROPIC_DEFAULT_HAIKU_MODEL=HOME`; on the unmodified script it gives the folder path.
- A lowercase alias from `AIENV` (`kimi`) still resolves in all five places that call `resolve`.
- `sed -n '2,15p' src/superclaude/scripts/ic` still ends the help text on a comment line and shows the corrected resolution sentence; the old `$IC_ALIASES` wording is gone from the file.
- Callers and dependents: `apply_preset` (three `resolve` calls) and the main loop (four calls) are the only users; `src/superclaude/cli/sprint/aienv.py` only mentions the script in comments (Task 4).
