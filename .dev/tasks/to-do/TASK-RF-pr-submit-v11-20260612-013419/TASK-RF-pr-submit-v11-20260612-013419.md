# Implement pr_submit V1.1 — Post-Push Re-Trigger + Oversized-PR Auggie Fallback + Strict-Once Clamp

## Task Overview

This task extends the already-shipped `pr_submit` V1.0 implementation to the V1.1 design addendum. V1.0's remediation loop is broken: it assumed that pushing a remediation commit triggers an Augment re-review, but the `augmentcode[bot]` only reviews on PR-open or an explicit `auggie review` PR comment — pushes do NOT auto-trigger a review (verified memory `reference_augment_review_triggers`). V1.0's optimistic post-resolve `round_counter += 1` at `fsm.py:793` therefore papers over a loop that never really advances. V1.1 fixes this with three behaviors: **R1 (FR-8)** posts one `auggie review` comment after each push and polls for the attributed re-review; **R2 (FR-9)** detects an "abnormally large" decline and falls back to an in-session `/sc:auggie-review` review; **R3 (FR-10)** clamps the budget to 1 and guarantees `/sc:auggie-review` is invoked at most once per PR.

The work spans three surfaces on a strict dependency DAG: (1) the deterministic core `src/superclaude/pr_submit/{models,classifier,detection,run_log,fsm}.py` (`models.py` FIRST — it defines the new enum members and states the other modules import-resolve against); (2) the skill package `src/superclaude/skills/sc-pr-submit-protocol/{SKILL.md,refs/*,scripts/*}` (2 MOD refs + 1 MOD state-machine.md + 2 NEW refs + 1 NEW script); and (3) the test suite `tests/pr_submit/` (2 NEW modules + 5 EXTENDED + 7 NEW fixtures). The single highest-risk edit is relocating the INV-001 increment from `fsm.py:793` to the real attributed re-review WITHOUT breaking INV-001's verbatim guarantees (the S5→S2 edge, the `>=` gate, monotonicity, and `max_rounds=N ⇒ N pushes`). The whole feature is test-driven through the deterministic core's injected `RunConfig` seams — no real `gh`/`git` runs in tests, and NFR-6 core purity (zero `gh`/`git` tokens in the core) is preserved and statically asserted.

> **INV-R1 (re-trigger boundedness).** A re-trigger comment is emitted at most once per
> completed push cycle, on the `RESOLVING → S5a_RETRIGGER_REVIEW` edge, and only when
> `applied_edits > 0`. `rereview_request_count` is monotonic and
> `rereview_request_count <= max_rounds`. The re-trigger does **not** itself increment
> `round_counter`; INV-001's edge and gate are unchanged.

> **INV-R2 (auggie strict-once + total-push bound).** `/sc:auggie-review` is invoked **at

> `effective_max_rounds := min(effective_max_rounds, 1)` — a one-way, monotone
> non-increasing clamp recorded once. The fallback sub-loop (`fallback_round_counter`,
> cap 1, no loop-back, no auggie re-invoke) guarantees termination structurally, not merely

> verbatim; the two counters are **independent** and neither can re-open the other's loop.
