# Observe the real actor-isolation lifecycle cases and report a binary B-CTX result

Source: ./source.md
Goal: Produce observed evidence, or an explicit unsupported result that names the missing interface, for every actor and lifecycle case that the blocked B-CTX gate (Task 1 of package TASK-WF-implementDocsDes-20261106-210206) left unobserved, measured against the identity integration that PR #414 merged, and end with one report carrying a binary B-CTX result. Nothing is enforced and no production file changes.

## Constraints

- The authoritative design is docs/designs/sc-issue-launch-level-hook.md, section 19 (19.1 for the required cases and 19.7 for the merged job-identity contract). The gap list is the six findings F2.1 to F2.6 in review-2.md of the blocked package, at artifacts/retries/T1/ inside package TASK-WF-implementDocsDes-20261106-210206 (a package in the to-do folder of .dev/tasks/). The identity helper under test is src/superclaude/hooks/scripts/launch-job-identity.sh; the earlier real-CLI observation helper is tests/hooks/fixtures/launch_level/live_probe.py. Read all of them; edit none of them.
- Do not modify, move or re-run package TASK-WF-implementDocsDes-20261106-210206, and do not modify the done package TASK-WF-authorizedNarrow-20261106-214325. Their files are read-only inputs.
- This plan observes and reports only. It adds no production hook, no registration, no installer change, no change under src/, plugins/ or tests/, and it never configures a real repository's hooks. Git experiments run only in disposable local repositories and disposable local bare repositories created under a temporary directory. No push to a real origin or any protected branch of a real remote. No interaction with the SuperClaude upstream repository.
- Real Claude runs use a throwaway HOME and CLAUDE_CONFIG_DIR, an explicit --settings file and --setting-sources "", exactly like tests/hooks/fixtures/launch_level/live_probe.py. Never edit the user's real Claude settings. Each real Claude run is capped with --max-budget-usd 0.25 and a bounded timeout, and the whole plan makes at most twelve real Claude runs, counting every start of Claude including a refused launch and allowing no retries. Run budget: the preflight one, Task 2 four, Task 3 four and Task 4 three (its shapes share governed sessions as separate commands, grouped so that no shape runs after a call that stays blocked in the same session), twelve in all. Keep CLAUDECODE and existing auth variables intact: a nested-session refusal or missing authentication is recorded as unavailable and is never worked around.
- A case counts as observed only when a real Claude, Orca or Git process produced it in this plan's runs. Cases built from controlled processes or edited fixture state are labelled controlled and are never reported as real harness behavior. A case that cannot be driven is recorded as unavailable with the exact missing interface named. Never fabricate payload logs, and never write an unsupported or unobserved case as passed.
- Redact credentials, environment values, command text and process arguments from every artifact: keep identities, field names, hashes, selector results, exit codes and counts only.
- Use UV for Python (uv run --no-project python -I ...). Evidence belongs under ./artifacts/ in this package. No commit, push or issue comment is authorized. Stage .dev/tasks, including package evidence, throughout execution. Do not change this plan once implementation starts.

## Phase 1: Safe observation harness

## Task 1: Build the observation runner with a preflight and an exit-status ledger

Write ./artifacts/observe/observe.py, a stdlib Python runner started with uv run --no-project python -I, that all later tasks use. It creates its disposable HOME, disposable fixture repository and temporary directory, runs one named case at a time with a timeout, and appends one JSON line per run to ./artifacts/run-status.jsonl with the case id, a redacted command label, start and end time, exit code or signal, a real_claude flag (true when the run started Claude, a refused launch included), for a real_claude run the sha256 of the real Claude settings file read immediately before the run and again immediately after it, the process-tree depth from the Claude process to the command when the case measures it, and a result of observed, controlled, unavailable or blocked. Every Bash command that a real Claude run executes also writes its selector line to a file in the run group's temporary directory, and the runner copies that redacted line, with the run id and a sha256, into the case artifact: the model's own report of a result is never evidence. Model its isolated HOME, settings file and redaction on tests/hooks/fixtures/launch_level/live_probe.py and read the exit and cleanup handling of its probe function, but do not copy two of its behaviours: live_probe creates its HOME inside a per-call temporary directory, and its cleanup SIGTERMs every recorded supervisor after each run, which would kill the old child that Tasks 3 and 4 need alive. Instead the runner keeps one named run group: the disposable HOME (config folder and launch-level store), fixture repository and temporary directory are created once per group, reused by every run that depends on them, and removed only by an explicit teardown command after the last dependent run. A case may mark its jobs as surviving; per-case cleanup never signals a surviving job or its supervisor, and the teardown stops them and records each stop. Before each dependent run the runner checks that the launch-level store and the governed session record still exist and records the check. A case may also name one process to end with one named signal once a named ready file appears in the run group's temporary directory: the runner then signals that process id only, through its own child handle and never a process group, and only while the process id, start ticks and boot identity still match what was recorded; it records the signal, the target and the wait, and the case timeout stays only a backstop recorded as blocked. The runner refuses to start a thirteenth real Claude run. Runs that Task 3 resumes or forks keep session persistence on inside the throwaway HOME (a recorded session id and no --no-session-persistence, which live_probe sets on every run). The teardown, and a case timeout, also sweep /proc for processes whose working directory is under the fixture repository or the group's temporary directory and stop each by process id only while its start ticks still match, logging every stop in ./artifacts/phase2-cleanup.log, because each supervisor calls setsid and sits outside Claude's process group; a case-timeout sweep skips every registered surviving job and its supervisor and stops only processes started by the timed-out case, so a timeout never destroys the jobs that later runs depend on. At the start the runner records checksums of the real Claude settings file, of the diff of src/, plugins/ and tests/, and of the blocked package, in ./artifacts/baseline.json. Add a preflight command that writes ./artifacts/preflight.json recording the Claude version, whether a nested Claude launch is refused, whether authentication is available in the throwaway HOME, whether a persisted session's transcript is found in the throwaway HOME, the tool names the installed Claude offers in print mode, whether UV, Bash, git and /proc are present, and the host boot identity; the Claude-dependent fields come from at most one real Claude run, counted in the budget. When the preflight reports a refused nested launch or missing authentication, Tasks 2, 3 and 4 record every real-Claude case as unavailable with that redacted refusal result and spend no run.

Acceptance criteria:
- ./artifacts/observe/observe.py exists, runs a preflight with uv run --no-project python -I, and writes ./artifacts/preflight.json whose every field is an observed value or the word unavailable; the preflight exit status is recorded in ./artifacts/run-status.jsonl.
- A runner self-check in ./artifacts/observe-selfcheck.log shows that a secret-looking environment value and a command argument placed in a test run never appear in run-status.jsonl or preflight.json, that a timeout kills the whole process group and is recorded as blocked, and that the disposable HOME and temporary directory are removed by the explicit teardown and not before: a second run in the same group still finds the launch-level store and the governed session record written by the first run, a job marked as surviving is still alive after its case ends and after a later case in the same group times out and is swept, and the teardown stops it and logs the stop. A signal aimed at one named controlled process after its ready file appears ends only that process while an unrelated controlled process in the same group stays alive, and the signal is refused when the recorded start ticks no longer match.
- The runner touches nothing outside its temporary directory and ./artifacts/: git status for src/, plugins/ and tests/ is empty after the self-check, and the user's real Claude settings file has the same checksum before and after, every real_claude entry in ./artifacts/run-status.jsonl records equal before-run and after-run settings checksums, and ./artifacts/baseline.json holds the baseline checksums that Task 8 compares against.

## Phase 2: Real harness lifecycle observations

## Task 2: Observe a governed and an ordinary session in the same worktree, a nested subagent and Monitor

Depends on: Task 1

Use the runner of Task 1 to start two real Claude --print sessions in the same disposable fixture repository, one whose session id has a private governed level record in the throwaway HOME's launch-level store (created as live_probe.py does for its governed variant) with the Bash adapter registered through --settings, and one ordinary session with no record. In each, the prompt asks for exactly one Bash command that runs the helper's identify action of src/superclaude/hooks/scripts/launch-job-identity.sh and prints the result together with the count of parent hops from the command's shell up to the Claude process (recorded as the depth in the ledger). Then run a governed session whose prompt asks a subagent to run the same Bash command, and a governed session that tries the Monitor tool. live_probe offers Claude only the Bash tool, so the subagent run also offers the tool that starts a subagent and the Monitor run also offers the Monitor tool, named from the preflight's tool list; a case is recorded unavailable for a missing tool only when the preflight shows the tool is not offered in print mode or after a run that actually offered it. Record the selector result of every command and the raw event types only, not the text.

Acceptance criteria:
- ./artifacts/same-worktree.json records, for the governed and the ordinary session run against the same worktree, the session id each reported and the selector status (governed with the governed session's own id, and ordinary), with the ordinary result produced while the governed session's record still existed; when the preflight reports a refused nested launch or missing authentication the file instead records both sessions unavailable with the redacted refusal result and its ledger line, and no run is spent.
- ./artifacts/subagent-and-monitor.json records, for the nested subagent case and the Monitor case, either the observed selector status and session id, or the result unavailable with the missing interface named (for example the tool not offered in print mode, or a refused nested launch); neither is reported as passed without an observed selector line.
- Every run of this task has an exit status line in ./artifacts/run-status.jsonl, and a log ./artifacts/phase2-cleanup.log shows no leftover Claude, supervisor or fixture process after the task.

## Task 3: Observe resume, fork and clear against an old live governed child

Depends on: Task 2

Using the runner of Task 1, observe the three lifecycle events that the blocked gate called unproven. All runs of this task share one run group of Task 1, so the throwaway HOME and its launch-level store persist from the initial run through resume, fork and /clear; the group is torn down only after the last of them. First start a governed real Claude session whose Bash command starts one ordinary background child (a bounded sleep with its output redirected away, not through setsid, nohup or run_in_background), runs the identify action on it, and writes the selector line, the child's process id, start ticks and boot identity to a ready file in the run group's temporary directory. The adapter's supervisor waits for ordinary background descendants, so this governed call is not expected to return while the child lives and the first Claude process is not expected to exit by itself; record whether the call returned and for how many seconds it was held, and record a return while the child lived as an observed contradiction. Mark the job as surviving (no runner cleanup). When the ready file appears, the runner sends SIGKILL to the first Claude process's own process id only, never a process group, the supervisor or the child, and records the signal, the target and the time. If the first Claude process ends any other way before the ready file appears (the Bash tool's own timeout, the case timeout, or a returned call), record that end and the child's state as observed and do not treat it as the planned kill. After the kill and before any resume, read the child's process id, start ticks and boot identity from /proc and compare them with the ready file (a mismatch is recorded as unobserved with the reason "child identity changed" and never as a selector status), read the supervisor's process id and start ticks, and record whether each is alive; survival of the kill is not assumed. If the child or supervisor is gone, record resume, fork and the decisive case as unavailable with the reason "job did not survive the first Claude process ending" and start no substitute child. If the killed session cannot be resumed, record resume and fork as unavailable and name the refusal. Background scheduling with run_in_background is a separate unobserved case (section 19.7 of docs/designs/sc-issue-launch-level-hook.md) and is observed in Task 4, not here. If the child is alive, resume the same session id in a new Claude process (claude --resume) and run the identify action in the resumed process, and run a fork (claude --fork-session) the same way. For /clear, attempt a pty-driven interactive Claude session in the throwaway HOME, send /clear, then run one governed Bash command; if an interactive session cannot be driven within the budget, record /clear as unavailable and name the missing interface. In every case record the session id carried by the hook event of the resume, fork and /clear runs (the id the adapter selects on) next to the old child's origin session id. The pty /clear session is the one run that reuses a single Claude process for a new ordinary session; a resume or fork starts a new process and cannot test that form, so if the pty session cannot be driven the reused-process form is recorded unavailable with the interface named. In every case record whether the old child and the new work report the same or different session identities, and whether a new ordinary session started in a reused process is selected as ordinary. Task 3 uses at most four real Claude runs (initial, resume, fork, /clear) and no retries.

Acceptance criteria:
- ./artifacts/resume-fork-clear.json has one entry each for resume, fork and /clear. Each entry holds the old child's selector status and origin session id, the new process's selector status and session id, the old child's process id and start ticks read before and after the new process started (proving it was the same live child), a check that the launch-level store and governed session record still existed before the run, and a result of observed or unavailable; an unavailable entry names the missing interface. The first-call entry also holds whether the call returned and the seconds it was held, the ready-file sighting, the end action (signal name and that the target was the first Claude process only), the child's and the supervisor's process ids and start ticks before the kill and again after the kill and before the resume, and the label "job did not survive the first Claude process ending" when that applies.
- The decisive case is answered from observation or marked unavailable with its interface: an old governed background child stays alive while a new ordinary session starts, and the two report different identities (child governed with the old origin, new session ordinary), or the entry states exactly what could not be observed.
- No entry is written as observed without a selector line captured in ./artifacts/run-status.jsonl-linked output, and every started child and every surviving supervisor is accounted for as stopped in ./artifacts/phase2-cleanup.log.

## Task 4: Observe background and detached jobs under the governed Bash adapter

Depends on: Task 2

Using the runner of Task 1 in a governed real Claude session, observe four job shapes through the adapter's rewritten Bash call: an ordinary run_in_background Bash command, a foreground command that starts a descendant and exits so the descendant is reparented, a deliberate setsid daemonized child, and a command whose supervisor is killed while a child lives. Use the run group of Task 1 so the throwaway HOME and launch-level store persist across these runs. For each, run the identify action of src/superclaude/hooks/scripts/launch-job-identity.sh against the descendant's process id and record the status and origin session id. The adapter's supervisor waits for ordinary background descendants, so in the foreground-reparent shape the first governed call does not return while its descendant lives, and a later Bash call would find the descendant already dead and report unknown for the wrong reason. For that shape, run identify against the descendant inside the same governed command before it exits, and record how long the call waited as an observed fact. For the other shapes a later Bash tool call may also be used; it is a governed call too, because every Bash tool call inside a governed session is rewritten by the adapter, so call it "a second Bash tool call" (not "ordinary") and record that call's own selector status and session id next to the descendant's. Record the documented escapes (setsid, supervisor kill) as observed escapes, not as failures of the harness. Task 4 uses at most three real Claude runs; when the preflight reports a refused nested launch or missing authentication, every shape is recorded unavailable with the redacted refusal result and no run is spent.

Acceptance criteria:
- ./artifacts/background-jobs.json records, for each of the four shapes, the selector status and origin session id reported for the descendant (for the foreground-reparent shape, taken inside the same governed command, with the observed wait time), the selector status and session id of the second Bash tool call where one was made, or unavailable with the missing interface named when the harness did not run the case.
- The setsid and killed-supervisor entries state the status actually observed (for example ordinary or unknown) and say that these are documented limits of the merged design (section 19.7 of docs/designs/sc-issue-launch-level-hook.md), with no claim that they are protected.
- Exit statuses of all runs are in ./artifacts/run-status.jsonl and ./artifacts/phase2-cleanup.log shows every descendant stopped.

## Task 6: Observe same-worktree human pushes against governed pushes in a disposable bare repository

## Phase 4: Binary result and report

## Task 8: Write the B-CTX report with a binary result

Depends on: Task 3, Task 4, Task 6, Task 7

Write ./artifacts/b-ctx-report.md. It lists every case that section 19.1 of docs/designs/sc-issue-launch-level-hook.md requires (main Claude, subagent and nested tool calls, background Bash and Monitor descendants, same-worktree human terminal, ordinary Claude session, detached or reparented jobs, process exit and PID reuse, resume into a new process, /clear and fork, release with a live old background child, the launch wrapper, the Git and hook process trees, the auto-mode variants, and the decisive simultaneous distinction between an old governed background child and a new ordinary session) with the artifact that holds its evidence, the result observed, controlled or unavailable, and for unavailable the missing interface. Map each of the gap findings F2.1 to F2.6 of the blocked review to the case or artifact that closes it, or state that it stays open. End with one binary line B-CTX: PASS or B-CTX: FAIL and, for FAIL, the contract-gap and evidence-gap lists that the acceptance criteria define. Finish with a cleanup record.

Acceptance criteria:
- ./artifacts/b-ctx-report.md has one row for every case named above, each linking to an artifact of this package and carrying observed, controlled or unavailable; no row is empty and no unavailable row lacks a named interface. A row that rests on a real run references the runner-captured selector-output record by run id, never the model's own report of a result. The launch wrapper, Git and hook process tree, auto-mode and decisive-distinction rows are each observed or unavailable with the missing interface named.
- Every one of the findings F2.1 to F2.6 has a line stating closed by (artifact), open (why), or superseded or not applicable (citation), and a closed claim names its evidence class and is backed by a result of the same case; a finding about resume, /clear, Monitor or a nested subagent is never closed by a controlled result. Superseded or not applicable is allowed only for a point that the merged selector settles by cited code (for example boot identity, compared at helper:234) or for a finding that describes only the historical controller-ancestry probe, never for a finding about an unobserved lifecycle case.
- The report counts the real Claude runs from ./artifacts/run-status.jsonl (real_claude true, refused launches included) and the count is at most twelve.
- The report ends with exactly one result line B-CTX: PASS or B-CTX: FAIL. PASS appears only if every required case is observed (not controlled and not unavailable) and its observed selector status shows the required separation (governed work governed with its own origin session id, human and ordinary actors ordinary); an observed documented escape (setsid child, killed supervisor, Monitor without an adapter) shows no separation and never counts toward PASS. Because Task 5 can label release, PID reuse and boot identity only controlled, B-CTX: FAIL is the expected result of this plan and the report says so. Directly under the FAIL line the report gives two lists: contract gaps, the observed cases whose status broke the separation, each with the missing binding, reset or child-lifetime contract and the smallest integration that would supply it; and evidence gaps, the controlled or unavailable cases, each with the real-observation interface that would make it observed. A FAIL with an empty contract-gap list is reported as "contract not yet shown", never as a missing identity contract. The report states that the result does not waive the blocked package's gate.
- The cleanup record shows no leftover process or temporary directory from the plan's runs, the checksum of the real Claude settings file is unchanged before and after every real Claude run (the before-run and after-run checksums in every real_claude entry of ./artifacts/run-status.jsonl are equal, not only the start and end of the group), and the git status and diff checksums of src/, plugins/, tests/ and the blocked package equal the baselines in ./artifacts/baseline.json, with the package's own files staged under .dev/tasks.
