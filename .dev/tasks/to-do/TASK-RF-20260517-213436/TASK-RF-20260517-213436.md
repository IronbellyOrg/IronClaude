# hook-sync-and-matcher-fix — Makefile verify-sync hook coverage, matcher widening, cross-consistency, and pytest scenarios

## Task Overview

This task implements the 3-part `hook-sync-and-matcher-fix` release in IronClaude, ordered per release-spec §10: **Part 2 first** (user-impact bug fix: widen the auggie-flag-clear PostToolUse matcher to include the `mcp__auggie-mcp__` prefix actually used by the auggie-mcp MCP server installed in this project — without this fix, the v2.1 sticky never clears after `mcp__auggie-mcp__ask_question` calls and downstream gates fire false positives); **Part 1 next** (extend `make verify-sync` with a new `=== Hooks ===` section that runs forward `src → .claude` and reverse `.claude → src` checks over `src/superclaude/hooks/scripts/*.sh` with a `session-init.sh` case-skip on the reverse loop, plus a new `=== Installer Registration ===` section that asserts every `src/superclaude/hooks/scripts/*.sh` is a member of `_FRESHNESS_SCRIPTS` in `install_hooks.py`); **Part 3 last** (add `=== Hooks Cross-Consistency ===` section asserting the matcher in `hooks.json:60` and the case body in `auggie-flag-clear.sh:22` agree on auggie prefixes modulo regex `.*` vs glob `*` normalization, implemented with `jq` for matcher extraction and `grep -oE`/`sed -E` for case-body extraction); then create `tests/cli/test_verify_sync_hooks.py` (~140 LOC) with 7 pytest scenarios V1-V7 per release-spec §9, using `subprocess.run(["make", "verify-sync"], cwd=REPO_ROOT, ...)` with try/finally context managers that mutate real repo files (NOT tmp_path — the editable install resolves `from superclaude.cli.install_hooks import _FRESHNESS_SCRIPTS` to the outer repo regardless of tmp_path cwd) and module-level `pytestmark` skipping when `jq` or `make` is absent.

Bundling all three parts into a single PR is correct because Part 1's verify-sync coverage catches Part 2 regressions and Part 3 structurally prevents the lockstep-drift risk Part 2's two-file Option 1 patch carries. After landing, two expected orphan failures will surface that the maintainer handles outside this task (`.claude/hooks/auggie-bash-gate.sh` has no `src/` counterpart; `reject-workspace-writes.sh` is on disk in both but absent from `_FRESHNESS_SCRIPTS`) — both are documented as Open Questions, not auto-fixed.
