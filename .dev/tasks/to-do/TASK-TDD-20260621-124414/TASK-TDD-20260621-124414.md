# Create Heavyweight TDD for sc:reflect Deterministic Runtime-Surface Sweep (FR-DRS)

## Task Overview

This task produces a Heavyweight Technical Design Document (TDD) for the **sc:reflect Deterministic Runtime-Surface Sweep (FR-DRS)** — a new pure-Python, LLM-free module `src/superclaude/cli/reflect/runtime_surface.py` plus its integration into the reflect CLI product path, the eval harness, and the demotion of the corresponding SKILL.md prose. The driving spec (PRD-equivalent) lives at `.dev/reflect-hardening/issue-3-deterministic-runtime-surface-sweep/spec.md`.

The motivation: an FR-RSR prose-only implementation cannot deliver the structured-output guarantee. A 3×before/3×after eval proved the LLM emits ad-hoc field names on quiet reachability paths and writes the `runtime-surface-ledger.yaml` in only 1/9 runs. FR-DRS removes the LLM from the structured-emission path — deterministic Python computes the `runtime-surface-ledger.yaml` plus the six `runtime_surface_*` contract scalars — keeping the LLM only for narration/verdict in REPORT.md. This TDD is the engineering specification the implementer builds against.

The task follows the full TDD research-and-assembly pipeline as a Template-02 complex task: Preparation → Deep Investigation (parallel codebase research) → Completeness Verification (research-gate QA) → Web Research → Synthesis (+ synthesis-gate QA) → Assembly & Validation (rf-assembler → report-validation lens QA → source-fidelity gate) → Present & Complete (anti-orphaning post-completion). Every research, synthesis, and validation step is a self-contained checklist item with the full embedded agent prompt.
