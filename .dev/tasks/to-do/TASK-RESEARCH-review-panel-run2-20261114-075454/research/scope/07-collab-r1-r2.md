# PART A: R1 move-radar

## A1. Idea (R1/DESIGN.md)

- A1.1 Title/scope: "Redesign 1: Move Radar (F3): implementation and test design"; build spec for family F3, slot 3, arm A6, plus isolated baseline arm A1 on three panels (el2 ember+2xluna, sl2 sonnet+2xluna, hl2 haiku+2xluna). (R1/DESIGN.md:1, :7, :244-252)
- A1.2 Core idea: a PostToolUse hook per reviewer session watches that reviewer's tool calls (telemetry), at fixed tool-call checkpoints (searcher after calls 6 and 10, readers after 8 and 12) injects at most K catalogue "moves" (fixed text of at most 300 chars, ids M1..M10) that name a review action nobody on the panel has done yet. No findings, anchors, paths or counts are ever shared between reviewers; only move ids / fixed texts. Independent first pass kept (no injection before call 6/8). (R1/DESIGN.md:116-122, :163-168, :204-216)
- A1.3 Two roles: **searcher** (one non-luna reviewer; gets observable search moves M1,M2,M7,M4, booked to cost C) and **reader** (two lunas; get reading moves M3,M5,M6,M9,M8,M10 as timed static prompts, booked to P); every reviewer may get the "source.md has not been opened yet" check. (R1/DESIGN.md:244, :170)
- A1.4 Explicitly NOT built: no `panel-post` helper, no peer tagger, no Stop hook, no fallback ladder, no scheduler across the five redesigns. (R1/DESIGN.md:30)
- A1.5 "Nothing here is implemented yet" at DESIGN time (R1/DESIGN.md:7); implementation exists at the tip (tools/, tests/ listed above) and is reported in IMPLEMENTATION.md (see A9).

## A2. Mechanism: data flow and contract fields

- **One package end to end** (R1/DESIGN.md:102-112): preflight (pins, sandbox, index, values) -> T0 ms -> FINISH_MS/GUARD_MS/HANG_MS from values -> 3 reviewers launched concurrently, each with own `--settings` JSON when `PANEL_COLLAB=1` -> hook appends telemetry per tool call and may inject at checkpoints -> after each reviewer: H2 normalise, at most one re-ask, normalise again -> `collab_summary.py pre` (audits, quarantine), `superclaude review merge`, anonymise, `collab_summary.py post`, judge (unchanged `judge-one.sh`) -> after 3 packages `results.py` + `cleanup-sessions.sh`. "No reviewer ever waits for a peer"; `late` is always 0 (:112).
- **`panel-msg/1` F3 subset** (R1/DESIGN.md:116-134): keys `v,id,run,from,to,t,kind,move`; `from` always `radar`, `kind` always `move`; `id`=`m-<rid>-<2-digit call no>`; source.md check = same line without `move` key (Adaptation A-4); "finish now" is not a board message, logged as `{"ev":"finish"}` in metrics. Validator `msg-validate.sh` rejects: `too_long` (>600 bytes), `not_json`, `bad_key:<k>` (claim, verdict, blocking, severity, category, note, anchor, items, n all forbidden), `bad_field`, `bad_move`, `leak` (text must equal catalogue text + observable suffix for observable move to searcher only). Hook passes rendered text next to the line so leak lookup checks what the model receives; post-run re-validation is a HARD failure -> `QUARANTINED`.
- **Classifier** (`tools/radar-classify.jq`, R-31) (R1/DESIGN.md:138-153): signatures M1 (recursive grep/rg under `tests/` naming candidate path/key), M2 (grep -l/-c/-L, find, `| wc -l`, Grep output_mode files_with_matches/count), M4 (pattern equals a criterion_grep from the candidate), M7 (recursive search from repo root or naming a root file), SRC_OPENED, UNNAMED_TEST. Never emits M3,M5,M6,M8,M9,M10 (reading moves unobservable). Runs live at checkpoints, post hoc in `collab_summary.py`, and post hoc over collab-0 `--output-format json` transcripts so the baseline gets the same coverage counters.
- **Per-package index** (`tools/radar-index.sh` -> `index/<pkg>.json`): `paths`, `keys`, `task_of_path`, `tasks`, `criterion_greps`, `root_files`; derived from candidate only, "no ground truth" (R1/DESIGN.md:52). Tasks parsed from `^## Task (\d+):` headings (:52).
- **Hook** (`tools/radar-hook.sh`) (R1/DESIGN.md:155-172): 10 ordered steps under `flock`; fail-open on any error (exit 0, nothing printed, `hook_error` logged); subagent calls (`agent_id` non-null) logged `sub:true`, never counted; finish signal at `now >= FINISH_MS` injects `finish_text` once, nothing after; guard at `GUARD_MS` skips; **seal (fail closed)**: copy `transcript_path` to `snap/<rid>.jsonl` + sha256 before first delivery, `failed` state means nothing is ever delivered to that rid; item choice then 'task hint' written to metrics only (R-32); output must be the JSON `hookSpecificOutput.additionalContext` form ("plain stdout is not shown to the model for PostToolUse", :168).
- **Item choice and order** (R1/DESIGN.md:174-180): order = role list rotated left by `int(sha256(rid)[0:8],16) mod len`; searcher list `[M1,M2,M7,M4]`, reader `[M3,M5,M6,M9,M8,M10]`; worked rotation offsets t4-1->0, t3-1->4, t2b-1->1, t1b-1->2, t2-1->0 (:176) -> two lunas never get the same move at the same checkpoint. source.md check first if own tele has no SRC_OPENED. Peer telemetry used only as a yes/no per move id (panel-wide coverage). No message ever states coverage.
- **Timing values** (`tools/values.py`) (R1/DESIGN.md:182-191): `finish_offset = 1.35*B_f - turn_p90[crit] - T_report_p90[crit]`; `k = max(0,min(2,floor((0.35*B_f - 2 - turn_p90 - T_report_p90)/(2*turn_p90))))` (R-42); `guard_offset = min(1.35*B_f - G, finish_offset)` G=47 s EL2; `hang_offset = 1.5*B_f` (R-43). ## C7. Future-use-case exposure (what these designs would expose or lock in)

- E-1 Baseline dependency: all timing rules (`k`, `finish_at`, `guard`, `hang`) need per-package baseline elapsed `B_f` and `turn_p90` from prior isolated runs (Spike 4). A live PR-review or spec-review panel has no baseline for a new input; the rule set would need static per-model budgets or a calibration table. (R1/DESIGN.md:186-191; R2/DESIGN.md:372-378)
- E-2 Hook dependency: collaboration needs per-session PostToolUse hooks with JSON `additionalContext` on every model; S0 confirmed it for ember, luna, sonnet, haiku (R1) and ember, luna (R2). Any non-`claude -p` backend (API-only models, other CLIs, rf-qa subagents via the Agent tool) cannot be hooked this way. Agent-tool subagents are not covered by either design.
- E-3 Plan/tasklist-specific moves: M3, M5, M6, M8, M9, M10 mention acceptance criteria, tasks, mapping rules and source document; M1, M2, M4, M7 are repository-search moves and the only ones classifiable from tool calls. A code-review (PR diff) or rf-qa catalogue would need a new catalogue and new classifier signatures; `radar-index.sh` assumes `## Task N:` headings.
- E-4 Ground-truth coupling: calibration (`judge-one.sh`, `score.json`, `blocking_in_implement`, `found_14`) is tied to 3 packages with 14 + 2 ground-truth items; E1's calibration (blind calibration in sc:reflect) is a different mechanism. The designs produce no reusable calibrated confidence.
- E-5 Merge non-idempotence: `ledger.merge_round` refuses a second round-1 merge (R2 review-1 B-5; `ledger.py:117` verified here) so any run-recording/resume feature must be merge-aware.
- E-6 Findings contract drift: both designs fix on `findings-v1` and `superclaude review merge` as at the E2 tip; the E1 branch has additional `findings_v2.py` (adds `lens`, `channel`, `reflect_category`, `citations`, `deviation_class`, `self_confidence`, `coverage_rows`), `panel.py` profile validation, `cluster*`, `manifest*`, `card_convert.py`, `verify_cmd.py` and `data/review-panel.reflect-*.json` (git diff stat: tip lacks 2,787 lines present on this branch under `src/superclaude/cli/review`). R1/R2 are unaware; the `origin` field and the move/fact boards must be re-expressed on v2 if adopted.
- E-7 Cost: R2 adds a whole extra model session (sweeper) and shows +38% (EL2) and +47% (HL2) output tokens on single smoke rows; R1 adds no session (provisional collab-1 14,912 tokens vs collab-0 21,127 on one pair, n=1, not comparable).
- E-8 Gateway coupling: gateway aliases `claude-gw-tier*[1m]`, model misrouting, user-level hooks that fire in every reviewer session (R1 K-11) are confounds to the product runtime; `[claude-code:unrecognized_model]` for `claude-gw-tier2[1m]` appeared on a side call in the R1 design session (session.err).
- E-9 Security surface: R2 `cmd` field and `panel-post` give a model-authored shell string that is later displayed to other models; mitigations are allowlist + length cap only (R2 K-8).
- E-10 Sandbox: `/tmp/evalsb-collab-r{1,2}` and `/tmp/collab-r2/` scratch; session files under `~/.claude/projects` accumulate; H3 sandbox lacks project `.claude/{agents,commands,skills}` (R2 K-4), so skills resolve from `~/.claude`.
- E-11 Statistical power: both designs state n=12 per arm cannot detect the central gains (R1 K-4, R2 K-10); a shared core cannot claim quality gains from either package.
