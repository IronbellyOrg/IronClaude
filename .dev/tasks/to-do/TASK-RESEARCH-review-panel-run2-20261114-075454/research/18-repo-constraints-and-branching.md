## Summary

The repository has one source tree (`src/superclaude/`) whose `skills`, `agents`, `commands`, `hooks` and `templates` are mirrored into a gitignored `.claude/` by `make sync-dev`, checked by `make verify-sync` and `make lint-architecture` in CI, and kept out of commits by a pre-commit hook; the `plugins/superclaude/` copy is hand-kept and only partly pinned. The central design constraints are: new skill directories need a `SKILL.md` (otherwise `verify-sync` fails and `sync-dev` cannot fix it), a `sc-<x>-protocol` skill needs a paired `commands/<x>.md`, contract-constant names are reserved under `cli/`, reflect `SKILL.md` and its 1.8.0 contract blocks and verdict matrix (36 tests) are pinned, and review-rule wording is scanned across tracked files. The installed-path rule (no `src/superclaude/...` in installed primitives) has no global scanner (148 lines of legitimate hits exist), only per-file pins and a manual grep. The git ref rule was proven in both orders on git 2.47.3: `feat/review-panel` and `feat/review-panel/x` cannot coexist (`fatal: cannot lock ref ... exists; cannot create ...`), so a plan must use dash-separated siblings or names where none is a prefix of another. A shared core already has a home in `src/superclaude/cli/review/` (25 tracked files, optional-module registration), independent of `cli/reflect/` at HEAD.
