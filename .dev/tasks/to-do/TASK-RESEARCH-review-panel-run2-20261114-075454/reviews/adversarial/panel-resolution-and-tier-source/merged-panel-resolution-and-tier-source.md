Which models a tier holds, and in what order, is decided in the Coder env slots that `ccsession-models.json` names (`tiers.<tier>.models_env`) and that `MODEL-TIERS.md` describes. The packaged `review-tiers.default.json` is the reviewed copy `panel resolve` reads, held in step with those by a test (item 2 of section 2); it alone holds what those sources cannot carry: the model-id attributes `classes` and `names`, the per-environment `available`, `stand_ins` and `launch` data, the `review-tiers/1` shape and its frozen goldens. The test derives the ordered ids of every packaged tier from the `MODEL-TIERS.md` table and compares them, and the counts with the ccsession slot lists, in full and for every packaged tier. Distinctness stays soft by default in the resolver and the CLI, because availability differs by environment and the shipped tests pin that; a consumer that wants strict passes `--strict-distinct`, as reflect already does. The CLI resolves the non-fixed slots scarcest tier first (the sort key of that order is open, item 4a), which removes the gateway repeats without a default flip, and it writes `requested_slots` and `distinct_models` into every resolution, so a shortfall is visible to the quorum rule instead of being skipped silently. `muse-ember-1.0` enters in the order the owner repo requires (the Coder slot first) and, in this repo, as one change over the files listed in the ember bullet of section 2, not as a data edit of one file and not in a second copy.
