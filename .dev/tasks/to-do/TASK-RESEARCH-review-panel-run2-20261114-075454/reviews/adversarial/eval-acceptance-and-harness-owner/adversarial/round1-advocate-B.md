## 2. Steelman of Variant A

The strongest version of A: an acceptance claim is only as good as the checks that could have failed it, and the E2 study shows how checks fail silently. The package-id mapper matches on a 12-character prefix and puts 59 control-package flags on designSpec (`T:A1/analysis/final-table.py:15-18`); the judge's completion test is exit code plus `jq -e . judge.json` and never looks at `score.json` (`T:A1/tools/tmp-scripts/judge-one.sh:28-30`, [CODE-VERIFIED]); the reviewer launcher overwrites its expected model after a fallback (`T:A1/tools/run-reviewer.sh:76`, [CODE-VERIFIED]); a whole batch (j1) sat outside every audit. A says: do not rely on operator discipline for that class, make identity, completeness and conservation a deterministic, three-valued check (`pass`, `flag`, `unrecorded`) that any consumer, including a skill, can call through the only path the install rule allows (the `superclaude` CLI), and make the table builder refuse unaudited runs. Put the tested harness where CI collects it (`scripts/` plus `tests/`, `pyproject.toml:107-108` `testpaths = ["tests"]`), pre-register the rule by commit order, and gate on the metric that counts blocking, because the one pre-set rule passes arm C on the any-severity count (2 against 2x1) while 0 of 8 implement-blocking defects were caught by any arm (`T:A1/PILOT-REPORT.md:56-61`, [CODE-VERIFIED]). A "no evidence" outcome is honest; a wrong "pass" is costlier than a slow "lead".

What A genuinely gets right (and I verified): the harness defects it names are real; `scripts/` already holds tested eval code (`tests/cli/reflect/test_shadow_exit_script.py` is tracked, [CODE-VERIFIED] by `git ls-files tests`); the `.dev/` harness is at HEAD untracked and its `lib/` folders are ignored by `.gitignore:13`; and the any-severity gate is weak (PILOT-REPORT.md:61 itself says C qualifies "only marginally", and :71 says the single-reviewer arm "passed both defect-rich packages, the worst observed outcome for a gate whose job is to fail bad plans").
