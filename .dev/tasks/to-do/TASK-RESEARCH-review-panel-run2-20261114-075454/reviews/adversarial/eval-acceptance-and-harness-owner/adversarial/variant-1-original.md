## 1. The position

A unified Review Panel design is accepted for a use case only on three tiers of evidence, and the two harness layers have two named owners. Tier S (structural) is code that needs no ground truth: model identity, completeness against a manifest, and conservation of reviewer lines (`raw == kept + rejected-with-reason`, with a repaired term if slot C-06 adds a repair step). Tier Q (quality on a derivation set) is judged by a rule, an analysis script and a values file committed in a commit that precedes the first run commit, so `git log` and not file mtimes shows the order. Tier G (generalisation) is a hold-out package set that neither E1 nor E2 touched, plus seeded defects with a clean twin where no implement outcome exists (reflect UC-2, PR review, rf-qa). Anything weaker than S, Q and G for that use case is a lead, as E1's own `PLAN.md:184` says ("leads, not findings"). The metric of record for Tier Q is: ground-truth items found in a ledger row that is flagged blocking where the item is blocking in implement; plus wrong blockers (a blocking row with no ground-truth match); plus control found. The any-severity count stays in the report as a secondary number and gates nothing. Ownership is split by layer. The checks every consumer needs at run time (identity, completeness, conservation) belong to the kernel as `superclaude review verify-run`, with the counts it needs written into the ledger entry and the served model into the run record. The judge wrapper, the anonymiser, the ground-truth registry (hashes and quote checks), the table builder and the statistics belong to a tested script set under `scripts/` with `tests/`, whose paths are arguments. `.dev/` keeps run outputs and per-run data only.

## 7. Effect on future PR code review and rf-qa replacement

- No ground truth exists for either today: no ground-truth file is tracked at HEAD (E-7), the E2 ground truth is plan defects, and the E1 seeded set is plan or spec defects and was never run (R16:152, `S05:681`). Under this proposal acceptance for each of them needs its own Tier G set, seeded defects with a clean twin per plan or diff. - Until that set exists, a PR-review or rf-qa replacement claim has status "lead". That does not stop either module being built or shadow-run; it limits what an acceptance statement may say.
- Tier S applies to both at once through the CLI: identity, completeness against the dispatched reviewers, conservation of reviewer lines. A skill reaches it as `superclaude review verify-run`.
- Metric of record in their terms: items found in a blocking finding where the item would block (for PR review, would block a merge; for rf-qa, would fail the gate); wrong blockers (false blocking findings, which cost fix cycles); control found on the clean twin.

## 8. The strongest objection and my answer

**Objection.** The metric of record has no power on the data that exists. The pilot shows 0 of 8 real-blocking catches in every arm (E-1) and the replicated default panel shows 0.17 of 8 (`R08:97`). The collaboration design itself says its plan "cannot detect the central estimates of any slot" (`merged-requirements.md:980`, R16:101, [UNVERIFIED by me]). A gate on a quantity that is near zero in every arm cannot rank anything, so Tier Q would return "no evidence" for every candidate, while the any-severity count at least moves (1.83 of 14 for the default panel). A gate that never opens is not an acceptance test.

**Answer.** Power is a property of the data, not of the definition. The any-severity count does move, but E-4 shows why: 89 percent of its catches are three easy defects, so it moves with how often those three are hit and says nothing about whether a blocking defect is caught. The purpose of the gate is a blocking verdict, and the one rule that exists already passes a panel on the any-severity count while no arm finds an item that was blocking in implement (E-1). "No evidence" is the correct output when that is the state of the evidence; a wrong "pass" costs more than a slow "lead". The rule is required to state the minimum detectable effect and the comparison count up front (R16:135, row 4), so "no power at this n" is a reported result, not a failure to report. Tier G adds blocking-in-implement items through the hold-out and the seeded sets, which is where the power comes from; the any-severity count stays in every report as a secondary number so no information is lost. I do not claim the hold-out will reach the needed power; M-3 is the test for it, and a result of "zero in every arm" is a result against this metric as a gate.

**Other objections considered.**
- Kernel growth with maintainer tooling, and identity, tool-use and judge-completion checks that need records the product does not write (R16:255). Answer: a check reports `unrecorded` when its record is missing and never `pass`; the checks computable today (E-12, M-1) do not wait for the records; and the repository already ships a no-model advisory subcommand of this shape (`verify-citations`).
- The wrong-blocker count scores a true novel blocking defect as wrong (E-5). This is a real limit of the metric. The registry reports each unmatched blocking row with its text-free reference so that an owner can adjudicate it; adjudication is outside this slot and no number is changed without it.
- The other position keeps E1's structural exit gates and the E2 any-severity metric, with the harness under `.dev/` and no kernel `verify-run`. Its stated facts are true as far as I checked: the exit script is code in git, tested by 20 tests, and the README says harness code goes under `.dev/` (E-14). This proposal differs on whether Tier S alone, or the any-severity count, is enough for an acceptance statement, and on where the layers live; it does not dispute those facts.
