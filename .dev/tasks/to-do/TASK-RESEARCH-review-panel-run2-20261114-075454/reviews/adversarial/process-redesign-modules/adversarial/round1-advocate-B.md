2. The primary module, the spec review loop on v1, has `anchor`, not citations; its findings never pass through `verify-citations`. A admits this ("the module's own advisory check must validate it against the sheet", A section 6). So "adds only three things" (A section 2) understates the work for the module A itself calls primary-shaped.
3. A's per-reviewer assignment conflicts with a shipped loop rule. The loop runs reviewers "each in a fresh context with the same brief" (`document_review_loop_prompts.md:70`, [VERIFIED]). A's replica assignment (an item to 2 of 3 reviewers, A section 6) needs different briefs per reviewer. B can keep the same brief by binding the same recipes to every slot; A's sheet by design cannot. 3b. A's pre-pass reaches into the reflect brief, which is fenced: the brief has "exactly three sections" and additions go inside existing ones (`reviewer-spec.md:55-59`, [VERIFIED]). A does not say which section a sheet occupies. This is A's cost, not B's, because B excludes reflect from `recipes`.

And if M1 fails for every class, what remains is a loader and an entry point with no producer, which is the "adopt neither" option B declines to argue, so A's "degrades by construction" is not a fallback with value.

7. A's size and determinism burden is real: no extractor exists; every extractor must be byte-deterministic (directory order, locale, `git grep` order) and pinned by tests (A 4); the first two (C4, C8) are the only ones research/10 marks fully mechanical. ## 8. Invariants and edge cases the emerging consensus must protect

State variables and guards
1. Sidecar entry per card. `verify-citations` stops with an error when the sidecar has no entry for a card (`SKILL.md:345`, text read); `{}` is the entry for a card with none. Any new producer of `assigned` or `observed` must write an entry for every card, including cards of reviewers that returned nothing.
2. Sidecar key = card file stem (`cluster_cmd.py:146`), not `<slot_id>-<i>` (`panel.py:668`). A binding by slot must be translated to the stem the cards use (concession 6); a mismatch yields `assigned = None`, which makes every empty block invalid.
3. The empty-block guard is `not rows or not rows <= observed` (`findings_v2.py:292`). A module with no cards must keep producing `assigned = None` or an empty list so that today's behaviour (an empty block is invalid) is unchanged. The no-card run must stay byte-identical to HEAD: this needs a test for B (T-B1, corrected) and for A (M5).
4. Define what counts as `observed`. If an UNSURE row counts, a reviewer can pass the empty-block guard with all UNSURE; if it does not, a reviewer who honestly cannot decide is invalid. Recommended: OK and PROBLEM count toward `observed`; UNSURE counts but is reported as `rows_unsure` in telemetry (ids and counts only) so the rate is visible.
5. A bad link invalidates the whole block. `coverage_rows` outside the assigned slice is an error line (`findings_v2.py:174-176`) and any error makes the state `invalid` (`findings_v2.py:299-303`), which removes the reviewer from the C-02 quorum count (`block_ok`). Row ids must be short and copyable, and any consequence of a wrong link should be tested; a typo in one finding must not cost the reviewer's whole round without the consensus saying so.

Count divergence
6. `rows_total` must equal the sum over cards of `|assigned|` after de-duplication across reviewers. A replicated row (assigned to two reviewers) is legal in A; the recorded sidecars show a row id assigned more than once in 11 of 13 files ([UNVERIFIED], r10 Unit 10). The consensus must say whether that is intended and how `rows_total` counts it.
7. Distinct reviewer count. `_confidence` counts distinct `reviewer_id` values per round (`ledger.py:86-90`, [VERIFIED]). A promoted line (if ever built) must carry the reporting reviewer's own id; a separate pseudo-reviewer id would turn `single` into `overlap`.
8. Quorum interaction. Replica assignment is not a quorum (A 6, U-008); a reviewer whose block is invalid because of a row error is counted lost by C-03's `min(2, requested)` floor. Neither design may feed row counts into that floor.

Collection boundaries
9. Report ending. The first-review prompt says to end the report with the findings block (`document_review_loop_prompts.md:33`); `findings.py` treats an unclosed `findings-v1` fence as truncated. A rows block after the findings block needs an amended sentence and its own truncation rule; before the block it needs a placement rule that protects the findings block. Whichever is chosen, a truncated rows block must never invalidate a complete findings block.
10. Same brief. The spec loop gives every reviewer "the same brief" (`document_review_loop_prompts.md:70`). A per-reviewer assignment (A) or a per-slot `recipes` list that differs between slots (B) breaks that sentence unless it is amended; uniform binding keeps it.
11. Snapshot. Evidence a script or reviewer cites must be a snapshot path (`verify_cmd.py:46-48`); anything else is `check_skipped` or `unchecked`, never a basis for a consequence.
12. Quote limits. Findings-v2 quotes are 12 to 200 flattened characters (`findings_v2.py:79-80`); row quotes need an explicit rule so short literal patterns (C4, C8) are neither rejected nor silently accepted.
13. Reflect brief fence. The reflect reviewer brief has exactly three sections and additions go inside them (`reviewer-spec.md:55-59`); the reflect result adds no top-level key (`panel_lint.py:318`). Any new reflect-side item must live inside the existing `## Coverage slice` or `## Grounding hunks`, or not exist.

Interaction effects
14. Re-review resurrection. A flag lowered in round 1 is recomputed in round 2 from that round's members (`ledger.py:210-218`) and recipes apply to the first review only (`apply_to: ["first"]`). Any flag-changing consequence needs a persisted per-row record or must be stated as round-1-only. This alone is enough reason to leave `rowcheck: apply` unbuilt.
15. Union and fail-closed. Under `any(m["blocking"] ...)` (`ledger.py:187`) a single-reporter, non-CRITICAL finding is the only case demotion can turn from block to pass; that is also the case where C-03's fail-closed choice matters most.
16. Telemetry. Counters (`rows_total`, `rows_problem`, `rows_missing`, `rows_unsure`) hold ids and counts only; the existing guard is a convention checked for `context` values (`telemetry.py:238-251`), so a test must pin that no record serialises a quote, claim or `problem` text (T-B6). Whether `review-telemetry/1` accepts new keys without a schema bump is [UNVERIFIED].
17. Byte identity. `precheck.json` byte-identity and "no card changes" are pinned (`test_review_verify_citations.py:165, 176`); the new row-check output must be deterministic (sorted keys, stable order) and must not be required by the existing `reread_set` consumers.

Sufficiency (does the proposed design alone achieve the stated outcome?)
18. A alone: assigns items and attaches evidence, but cannot show an item was examined (weakness 1), has no check for the v1 engine (weakness 2), and has no producer unless an extractor passes M1. It does not alone achieve per-item accountability.
