## 1. Position

I argue for Variant A on its core claims and I move to a named hybrid on one point where the code shows A has a hole.

- Keep from A: the process layer is script-first for the classes a script can decide (C4 and C8 are the two research/10 Unit 7 marks mechanical), every post-run check is advisory, the core gains no demotion and no promotion, and no recipe asks a read-only reviewer to run a shell. Classes stay module data.
- Take from B: a separate record-only output file for item checks (B's `review-rowcheck/1` idea) so `review-precheck/1` stays byte-identical, B's code-level tests (golden brief, slot-key rejection, card-to-tool lint, telemetry text test), and B's per-item answer carrier as an optional, record-only block, because A has no way to record "item examined, no defect" (section 5, concession 1).
- Reject from B: demotion and promotion in the core, even behind a switch. The switch has no host in code, the demotion contradicts the adjudicated C-02 outcome, and the exactness risk is B's own number (section 4, weaknesses 1 to 4).

The hybrid in one phrase: script-built items and advisory-only checks (A), answered through an optional record-only row block (B's carrier without B's overlay).

## 2. Steelman of Variant B

The strongest version of B: nothing the process layer needs has to be built before the review, so there is no extractor to keep in step with each module's documents, no pre-pass to time-box, and no second source of false positives (B section 1; E2's own tie rule adopts the Recipe Ledger when both designs pass within 0.05, [UNVERIFIED], MR2:1095-1102 via research/10 Unit 5). The reviewer's per-row answer turns "observed" from a number the orchestrator declares into something computed from reviewer output, and the existing empty-block rule gives that a consequence: a closed empty block is complete only when every assigned row is observed (`findings_v2.py:291-298`, [VERIFIED]). A separate rowcheck file keeps `review-precheck/1` and its `reread_set` byte-identical (B U-010). Demotion and promotion are contained: off by default, never on CRITICAL, only the demoted reviewer's own flag, only for file-checkable quotes, nothing dropped. B ships code-level tests T-B1 to T-B7, and a card-to-tool lint (T-B5) that turns the read-only invariant into a failing test. B's first gate (a compliance spike) is honest about being a model run, and M-B3 is a real measurement of whether demotion ever removes a true blocker.

What B gets right and A does not match: a per-item reviewer answer, a concrete slot binding (`_SLOT_KEYS` at `panel.py:46` is closed, and B names the key it would add), test-level invariants, and a cheaper first commitment.

## 4. Weaknesses identified in Variant B

1. **Demotion is a second authority over `blocking`, and B concedes the reading.** B section 2 (table, C-02 row): "A reader of C-02 may still see it as a second authority over `blocking`; this proposal accepts that reading". C-02's adjudicated winner keeps typed `blocking` as the only authority and adds "no category predicate and no grader in the core" ([VERIFIED], C-02 ADJUDICATION-RESULT). The lost side of C-02 was "`blocking` is decided by a script predicate over typed fields" (undecidable-conflicts.md row C-02, Position B, [VERIFIED]). A script rule that lowers `blocking` when a quote check fails is that predicate with a different input. B's distinction ("a script rule over a failed quote check, not a category predicate") is a distinction of input, not of authority. Also, the C-02 CRITICAL floor keys on reviewer-typed severity (C-02 INV-016), so B's "CRITICAL is never demoted" protects only reviewers who typed CRITICAL; a true blocker typed MAJOR is exposed.
2. **The exactness risk is B's own number.** B section 8 cites E2's per-row figure 0.914 x 0.914 = 0.835 ([PLANNING], [UNVERIFIED], r10 Unit 10). By that figure 1 - 0.835 = 16.5 percent of correctly flagged two-quote rows fail an exact whitespace-normalised substring test. Recorded data shows a floor: 31 of 1,047 recorded citations were `quote-not-found` (3.0 percent) ([UNVERIFIED], research/10 Unit 10, jq not re-run by me). The code that would run the test is `_norm` plus `in` (`verify_cmd.py:28-29, 68-72`, [VERIFIED]): it fails on any smart quote, escape or markdown difference. The only containment left for a single-reporter, non-CRITICAL true blocker is the switch, and B's own text says "for that case the answer is the switch and M-B3, not an argument" (B section 8 (2)).
3. **Demotion by flag alone is not valid in the v2 engine.** `check_finding` requires, when `reflect_category` is set, `blocking == (severity != "MINOR")`: a MAJOR or CRITICAL finding must be blocking and a MINOR one must not (`findings_v2.py:161-162`, [VERIFIED]). An overlay that lowers only `blocking` leaves a line the kernel would reject if re-validated; a correct demotion would also have to rewrite severity, which B's overlay does not list (B section 3 item 6: "demotions (finding id, reason)"). B's way out is `rowcheck: off` for reflect, which leaves B's value in the v1 engine, where `observed` is not computed (B concedes this in section 5) and where no precheck exists (weakness 5).
4. **The switch has no host, and the brief renderer does not exist.** `merge_cmd.py` has two functions, `_read` and `command(ledger_path, doc, round_n, reports, resolution, out, cap)` (Grep, [VERIFIED]); `grep profile|rowcheck|degrade` over `src/superclaude/cli/review/*.py` finds 7 matches, all in `panel.py` (count only; I did not read them), and none in `ledger.py` or `merge_cmd.py`. B's "profile `rowcheck: off | advisory | apply`" is a layer that C-03 INV-003 records as unspecified ("which layer owns the profile ... is unspecified", C-03 ADJUDICATION-RESULT, [VERIFIED]). B core item 3 says "The brief renderer appends ... each card's `recipe_text`", and T-B1 asserts golden files for "the rendered brief of each" of the 8 templates. A Grep for `def .*brief|render_brief` over `src/superclaude` `*.py` returns only `ledger._brief_ids` and an unrelated `_check_brief` in the implement skill ([VERIFIED by absence]). The spec loop brief is prose in `document_review_loop_prompts.md` with `{{CANDIDATE}}` placeholders (lines 17, 32, [VERIFIED]). B describes a code component that does not exist as if it did, so T-B1 has nothing to hash, and B's "all optional, data-driven" core is really a seven-part build (cards, slot key, renderer, row parser, rowcheck, overlay, switch).
5. **B's primary target module has no precheck to extend.** B names the spec loop (v1) "the primary target" (B section 3, Modules) and extends the precheck with a rowcheck file. But `verify-citations` reads cards "with a findings-v2 block" (`verify_cmd.py:82`, [VERIFIED]) and an `input-snapshot.yaml` (`verify_cmd.py:89`), `cluster_cmd.py` imports `findings_v2` (line 25, [VERIFIED]), `input-snapshot` appears in 8 files, none under `rules/` and none in the loop prompt file, and `verify-citations|review cluster|coverage.json` has no match under `src/superclaude/rules` ([VERIFIED by absence]). So the loop prompt and rules carry no snapshot, sidecar or precheck step (I did not grep the spec-panel command files, so "the v1 loop has none anywhere" is [UNVERIFIED]; the absence in the loop prompt is verified). A shares this gap for its own spec-review module (A-003), but B stakes its primary target on it.
6. **B's CB-2 answer cites the wrong list.** B section 3 (Modules, CO-24): "a PROBLEM row without a finding is listed under follow-up candidates by the report builder (non-blocking rows are already listed, `ledger.py:468`)". `ledger.py:467-474` prints `## Other findings` from `ledger["rows"]` where `not r["blocking"]` ([VERIFIED]): those are findings already in the ledger, under a different heading. A PROBLEM row with no finding is not a ledger row, so the report builder would not list it. B needs a new consumer of the row block to deliver CB-2, which is what B says it avoids.
7. **Round-1 compliance is coupled to the quorum floor.** In the v2 engine an empty findings block is invalid unless every assigned row is observed (`findings_v2.py:291-298`, [VERIFIED]); B uses this on purpose (B section 3 item 4). B's table says a reviewer who skips the row block "does not count toward the C-02 quorum", but recipes apply to the first review only (B section 2), where C-02's `prior` quorum does not run; the reviewer's block validity there feeds C-03's `min(2, requested)` floor and its merge-time refusal (C-03 ADJUDICATION-RESULT, [VERIFIED]). A row-format failure therefore can refuse a round, which B's section 8 (3) describes as "a counted event, not a failed round, except through the empty-block rule". That exception is the main path in the v2 engine, and B's tasklist and workflow module goes through reflect UC-1 (v2).
8. **Row-block placement and the brief disagree.** B puts the row block "after the findings block" (B section 3 item 4). The loop brief says "end the report with the findings block" (`document_review_loop_prompts.md:33`, [VERIFIED]), and reflect step 4 says "The orchestrator never edits, remaps or normalizes a reviewer's findings itself" (`SKILL.md:343`, [VERIFIED]), which is the rule promotion (a synthesized finding) and demotion (a lowered flag) cut across even when they live in an overlay file. A reviewer reading card text appended by B's renderer and the unchanged brief gets two placement rules. B says the brief file is untouched; that is the cause of the conflict, not a defence.
9. **B's per-row answer is still a self-report.** B concedes `ran` is "recorded and unverified" until the C-08 transcript adapter exists (B section 5, INV-G). OK, UNSURE and a missing row are reviewer-typed; the computed `observed` proves the reviewer typed an id, not that it ran the step. On X-007 B improves completeness of the record, not proof of examination.

## 8. Invariants and edge cases the emerging consensus must protect

Each item states what must hold, why, and which variant (or both) it endangers.

**State variables**
- S1. Sidecar consistency: `assigned` and `observed` per `reviewer-<N>` must come from one writer with one rule. Recorded sidecars show free-form ids, a range token, duplicates and empty `observed` (research/10 Unit 10, [UNVERIFIED]). Test: a unit test that rejects duplicate ids within one reviewer and a range token. Endangers both.
- S2. `review-precheck/1` and `reread_set` stay byte-identical when no sheet or row block exists (`tests/review/test_review_verify_citations.py:165, :176`, [VERIFIED names]). Test: golden precheck with and without a sheet. Endangers A (flags added to `precheck.json`); B is safe if its second file is separate.
- S3. "No cards declared" equals the legacy run by hash (MR2 REQ-23, [UNVERIFIED as text]). Test: hash of the brief and of `coverage.json` with zero cards. Both.

**Guard conditions**
- G1. Minimum assignment. In the v2 engine a clean card is valid only if assigned rows are non-empty and all observed (`findings_v2.py:291-298`, [VERIFIED]). A sheet that assigns zero items to a reviewer, or a recipe set with zero steps, makes that reviewer's clean review invalid. The design must assign at least one row to every reviewer or the consensus must change the rule. Endangers A directly; B only if a slot has no recipe.
- G2. Who writes `observed`. If the orchestrator writes `observed` equal to `assigned` for every card, the empty-block rule is a rubber stamp. If the observed ids are parsed from a reviewer-written block (B's carrier), the rule has meaning. The consensus must name the writer. Endangers A.
- G3. Demotion can never be the only guard on a blocker. If any module is allowed to turn it on, the guards are: never on CRITICAL, only the demoted reviewer's own flag, only when `quote_plan` is checkable, and a rewrite of severity together with `blocking` when `reflect_category` is set (`findings_v2.py:161-162`). Endangers B.
- G4. Read-only reviewer tool set. A card that names a tool outside the slot's agent allowlist (`reflect-reviewer.md:5`) must fail a test (B's T-B5), and a recipe whose only form needs Bash must not be bound to that agent. Both.
- G5. Placement of the row block against the brief's "end the report with the findings block" (`document_review_loop_prompts.md:33`, [VERIFIED]) and the parser-neutral report ending (C-S11, decided).
