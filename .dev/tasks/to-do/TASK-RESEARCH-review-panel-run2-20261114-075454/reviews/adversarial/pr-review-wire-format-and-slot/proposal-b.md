## 1. The position in one paragraph

Panel findings stay in the findings-v2 line format from reviewer to `pr_submit`. The four facts the PR path needs and the line does not carry today (`in_diff`, `confidence`, `original_line`, `reviewer`) become optional keys of that line, validated against a vocabulary the PR module declares (the decided requirement that vocabularies are module inputs, synth-05 6.11 Option 1 / research/13 M1 to M3). `pr_submit` reads the line itself through one pure reader placed next to `finding_from_comment`, so there is no panel-side converter that decides what to keep. The panel is a third reviewer of the PR: a third value of `Finding.reviewer`, a third key of the Output Contract `reviewers` object, and a third pair in `merge_wait`, with its standing (`present` / `absent` / `incomplete`) computed from the panel's recorded completion states. `Finding`, `Severity`, the FSM, the fork-only checks and the "no `gh` / `git` in the core" rule stay untouched (INV-E); B changes where the PR facts are recorded, not the PR data class.

### 3.4 Severity: a sub-decision B states openly

The router re-grades every hint with category floors and ceilings (`severity_router.py:151-200`), and an unknown or absent hint becomes Medium (`:122-133`) [CODE-VERIFIED]. Under B the line carries the core's three-token `severity` and `blocking`. The mapping to the five-tier hint (CRITICAL to critical, MAJOR to high, MINOR to low) is lossy: Medium and Nit are unreachable from the hint and only reachable through category clamps. Medium is the tier that triggers `--fix` and the merge guard (`SKILL.md:305`, research/13 section 1.6), so a MAJOR mapped to High routes `--depth deep --fix`, the more expensive route. Two ways to close this, both inside B: (i) the PR profile declares an optional `severity_hint` key (the router's five tiers) beside the core `severity`, a fifth key beyond the position's four; or (ii) accept the lossy map. The lossy map is the same under position A (research/13 P4), so severity is not a differentiator; B recommends (i) only if the owner wants Medium reachable. Which tier is "blocking" for PR is an open owner question (research/12 Q1, [UNVERIFIED]); B leaves `blocking` as a recorded field that `pr_submit` does not route on.

### 3.5 The `confidence` key name

`confidence` is already used in the review package with other meanings: a per-finding calibration number in the cluster sidecar (`cluster.py:12-13`), the ledger row column "single"/"overlap" (`ledger.py:86-90, 192, 203`), and `self_confidence` 0 to 1 on the line itself (`findings_v2.py:178-182`) [CODE-VERIFIED]. pr_submit uses `confidence` as text where only `"low"` matters (`severity_router.py:174`). B keeps the PR key `confidence` (text) as declared by the PR profile and never copies it into ledger rows (C-01 defers ledger passthrough keys); the alternative inside B is to omit the key and let the reader map `self_confidence` below a threshold to `"low"`. B states both and does not decide the threshold: no source measures one.

## 8. The strongest objection and my answer

**Objection (the strongest).** B edits `reviewers.py` (five functions, B13), the Output Contract and three prose copies, and creates the first dependency between `pr_submit` and a kernel format, to host a reviewer that is not a GitHub reviewer: the panel has no login, no thread, no completion marker and no re-trigger comment. B2 shows that `finding_from_comment` already is the reader, so a separate adapter is a rename and the extra wire-format keys buy nothing a pure adapter with the same four fields could not produce. A separate pre-step leaves `reviewers.py`, `merge_wait`, the Output Contract and the 47 test files untouched, and keeps `Finding`, `Severity` and the FSM out of reach by construction.

**Answer.** Three parts.

1. B concedes B2: the reader is a rename. That is B's point, not a gap in it: if the conversion carries so little logic, a separate converter module has nothing to protect and only adds a place where fields (B1: `quote`, second citation, `blocking`, `reviewer` provenance) are dropped before the one component that could use them. The dependency B creates is on a text format that `pr_submit` parses itself, with no import of kernel code (B14), and the vocabulary parameters it needs in the core are the decided M2 requirement, not a B-specific change.
2. The slot cost (B13) is real and B states it in full. What it buys is a standing in the contract operators already read (B10) and reuse of the per-reviewer-name cycle bookkeeping (B9). The measurable question is whether panel standing in the Output Contract is worth five edited functions; M1 (cost per round) and the owner's answer to research/13 Q4 decide it, and no research file settles it.
3. B's evidence for the wire format (B1 to B8) and its evidence for the slot (B9, B10, B13) are separate sets; a reader can weigh them separately.
