## 1. The position

The core owns dispatch as a small closed set of launch adapters, chosen per resolved reviewer and per environment, instead of owning only a resolution that nothing launches. Two adapters are defined: `agent-class` (the orchestrator's Agent call with a class word `sonnet|opus|haiku|fable`, used with the read-only `reflect-reviewer` agent; this is today's E1 path and stays the default wherever the model a class word resolves to is acceptable) and `claude-p` (a child `claude -p --model <raw id>` process, used for gateway models that no class word can name; this is E2's path, rebuilt as product code). Every launch, under either adapter, ends in a transcript identity check that records the model that actually served the reviewer, compared with the id requested for that attempt, never with a fallback that overwrote it. The reflect profile keeps its 3-reviewer cap, its Fable exclusion and its `classes` rule, but its launch ceiling widens from "one of sonnet, opus, haiku" to "one of those class words, or the `claude-p` adapter when the process is mechanically restricted to a read-only tool set". The `claude-p` adapter is usable by a module that needs mechanically read-only reviewers (INV-G) only after a read-only probe passes on the target id (section 6, M-2); until then it is available to modules that do not need that property.

## 5. Effect on future PR code review and rf-qa replacement

- PR review: the only way to put a non-Claude reviewer in a PR panel is a launcher that takes a raw id (`--revagent` takes four class words, r13:87). Under A that launcher is in the product and reached through the CLI; `pr_submit` is untouched (INV-E); C-10's adapter to `Finding` is independent. A cost A accepts: each PR round spawns up to N `claude -p` children; without `--bare` each loads the host's hooks and policy files (w02:27, 77), with `--bare` it loses `--settings` hooks (w02:132). The cost of a local panel per PR round was never measured (C-10 row of `undecidable-conflicts.md`). A diff from an untrusted PR is the input where INV-G matters most, so for PR review A uses the `agent-class` adapter until M-2 passes for `claude-p`.
- rf-qa replacement: the `/task` lens agents run `bypassPermissions` with Write/Edit/Bash (r13:195, R1); the replacement needs mechanically read-only reviewers (INV-G). Under A the `agent-class` adapter delivers that today for Claude-served models, and the `claude-p` adapter delivers it for gateway models once M-2 passes. A panel that wants gateway diversity for rf-qa is blocked on M-2, not on a design change.

## 6. Test or measurement that would show A right or wrong

M-1, identity (reach and the check): launch one fixed brief to each of five gateway ids that no class word reaches (for example the tier-2b, tier-3 and tier-4 first models and one non-first slot) through the `claude-p` adapter, three attempts each, and read `message.model` from every transcript. Right if every attempt has an observed id, every mismatch is recorded as a mismatch (zero unrecorded swaps), and at least one id is served that the `agent-class` path cannot request. Wrong if mismatches cannot be told from a legitimate failover, or if the observed field is empty for gateway ids.

M-2, read-only (whether the HIGH invariant holds): launch a reviewer on a gateway id and on `sonnet` with the restricted tool set, with a brief that tells it to run a shell command and to write a file. Right if the transcript has no Bash/Edit/Write tool call and `git status` is unchanged. Wrong if either occurs, or if the flag is rejected for gateway ids. If wrong, A narrows to `agent-class` plus an unproven `claude-p`, which is close to Position B's end state plus an unused launcher.

M-3, no regression: resolve every packaged `reflect-*` template under `anthropic-only` before and after the change; the only permitted difference is the additive `adapter` key. Also run `tests/review/test_review_panel.py`, `test_review_panel_reflect_profile.py` and the shadow-exit parity unchanged.

M-4, cost (absent today, CO-10 in `s06:213`): same brief and same model through both adapters, wall time and tokens, three runs each. This does not decide A, but it is the number the position lacks.

## 7. Strongest objection and answer

Objection: the proposal puts a launcher in the core that depends on Claude Code behaviour the repo does not pin: `--tools`/`--restricted` (and their version gate), the transcript's `message.model` field, and gateway failover. A CLI update can silently turn a read-only reviewer into one that can write, and the core then reports a verified, independent panel. The class-word path has the same dependence on harness behaviour (the Agent enum, `resolvedModel`), but its read-only property sits in a file this repo owns, `reflect-reviewer.md`.

Answer: the objection is right about prevention and A does not claim otherwise. A's controls are (1) detection at the end of every launch: the launcher reads the transcript's tool names and observed model, and an attempt that shows a tool outside the allowlist or an identity that differs from the requested id is recorded as a violation and never counted as a verified independent reviewer; (2) a per-environment probe (M-2) that must pass before `read_only: unproven` is cleared, re-run at install; (3) the `agent-class` adapter stays the default for any module that must have prevention, so an untrusted-diff reviewer never depends on the process flags. What A does not offer is prevention under the `claude-p` adapter when the probe has not been run. On the second half, the class-word path's identity problem is the larger evidenced harm (point 4), and it has no check at all today (point 11), while the process path adds one.
