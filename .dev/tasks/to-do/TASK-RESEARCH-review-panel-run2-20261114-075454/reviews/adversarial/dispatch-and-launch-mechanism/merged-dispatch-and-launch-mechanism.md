## 1. The position

<!-- Source: Base (original, modified) — Change 1: the packaged `gateway.launch` class-word fill is replaced by "binding as data in an explicit environment" (r2B section 0 items 1-3; r2A N1, N3, N4, V1' items 1 and 5); Change 3: a launcher is "gated, not built now" -->
The shared core launches nothing. It resolves a panel and prints, per reviewer, the intended model and a `launch` value that is one of the Claude Code class words (`sonnet`, `opus`, `haiku`, `fable`); the orchestrator turns that value into the `model` argument of one Agent call to a read-only reviewer agent (`reflect-reviewer` and agents built on its pattern). Gateway models are reachable today in exactly two ways: as what a class word resolves to in the session environment (`ANTHROPIC_DEFAULT_{OPUS,SONNET,HAIKU}_MODEL` set to a tier alias or a raw model id before the session starts), and through the swarm HTTP transport that already exists in the reflect engine. A third way, an id-addressed `claude -p --model <raw id>` child, is gated and is not built now (section 2B).

The base proposal filled the packaged `gateway` environment's missing `launch` entries by a data edit (model id to class word). The debate withdrew that remedy: Advocate B withdrew it in Round 2 and Advocate A had rejected it, on grounds the evidence table records (E18, E19 and E21). A one-word-per-model map in the packaged file cannot be right for the packaged random-slot templates (over 400 run ids `reflect-pre` slot `t4` varies across three models), and under the documented default binding the word `haiku` is tier 2, which disagrees with every tier 4 model; any packaged tier edit changes `tiers_sha256` and makes earlier recorded shadow runs "not proven"; and `gateway` is the default environment when `$T3Model01` is set and no `--env` is given. In its place a binding of models to class words is stated as data in an explicit environment (section 2A, item S5), and the packaged `gateway.launch` stays `{}`. The sentence of the base that the `--env gateway` refusal comes from an empty data map and not from the ceiling stays true (E13) and both advocates confirmed it.

The reflect profile ceiling (`panel.py:72`, three class words, three reviewers) stays as it is, and no `claude -p --model <raw id>` launcher, identity wrapper or fallback ladder is added to the core now. Whether the model that ran is the model that was intended is answered after the fact from the transcript (`message.model` of the sidechain, with the Agent result `resolvedModel` as a collapse detector), and that capture is the work of slot C-08, not of a launcher. The position trades reach (any gateway model, any panel size) for the one property the research calls a HARD design point: reviewers that are read-only by construction, not by prompt.
