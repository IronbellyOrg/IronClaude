## 1. Position summary

Observation (served model, usage, refusals, non-reviewer agents) is a different kind of fact from stage state, and it needs a row for every agent and for refused actions that the manifest has no place for; so it belongs in a separate append-only per-run file written through one CLI, with the manifest limited to a lock and a revision check. Variant 2's route (closed `usage`/`model` on attempts plus `agents[]` on `published`/`failed`) is workable for a reviewer's final usage, but its `agents[]` and its two producers have no code path at HEAD (X-002, X-003, X-008), so it does not deliver the non-reviewer and refusal coverage the slot requires. A's genuine weak points are the unwritten refusal writer (X-004), the loop's missing location (X-010), the memory move against the edit fence (X-011) and its dependence on an unverified adapter.

## 2. Steelman of Variant 2

The strongest version of Variant 2: the repository already has both homes. The manifest hashes each attempt payload and discards it (`manifest.py:348-354` [RE-READ]), and `--payload` already reaches `record_attempt` (`manifest_cmd.py:172, 181-183` [RE-READ]), so keeping a closed subset is a one-dict change. `review-telemetry/1` already has `model.observed` and a five-counter cost group, and `append_record` is already an append-only per-run JSONL (`telemetry.py:49, 74-80, 287-307`). So the smallest change that meets "served model from the transcript, cost on one row per agent, serialised writes, no document text" is to fill existing fields, add two locks and close the key sets: no new schema id, no new CLI family, no `/2` bump, nothing added to the C-01 "shared now" list but a closed key set. All its SKILL edits stay inside `### 4.3a`, which the fence test allows (`test_shadow_skill_contract.py:52-75` [RE-READ]), and it replaces the orchestrator's self-report now (steps 3, 9, 10) with an aggregator recompute in `scripts/reflect_shadow_exit.py`, outside `cli/reflect`. ## 3. Strengths claimed for Variant 1

1. **Observation stays out of the state machine.** An attempt entry is exactly `{stage, reviewer_id, attempt_id, completion, payload_sha256}` (`manifest.py:348-354` [RE-READ]). The same identity with a different payload raises `Conflict` (`:355-368`), a further attempt after a `complete` one raises `Conflict` "would add a vote" (`:378-381`), and an attempt needs an open stage (`:371`). `_recount` derives `reviewers_complete` from the `collected` attempts (`:269-274`); that it feeds the shadow shortfall (`scripts/reflect_shadow_exit.py:244-245`) is [UNVERIFIED], taken from A's text. Putting data that can be re-read, late or superseded into that identity either re-specifies these rules or leaves the data out of the hash. A separate file means a wrong or late reading cannot change a stage decision.
2. **A row exists for every agent and for a refused action.** `PER_REVIEWER_STAGES = ("dispatched", "collected", "calibrated")` (`manifest.py:53`); `fail()` sets only `state` and `failure_reason` (`:389-397`); a stage record stores only `payload_sha256`, `outputs`, `deps`, `invocation` (`:317-326`). Debater, judge, validator, helper and refusal rows have no home in the manifest, and Variant 2's `agents[]` has none either (section 4, point 1).
3. **Rows survive a killed run.** Rows are appended while the run goes and `record ingest` can run at any time. Variant 2 states the opposite as its own residual (7.2.3: a run killed before `published`/`failed` leaves no `agents[]`).
4. **One producer for every path.** `export` derives the `reviewer_run` records and the contract `telemetry:` numbers for the Tier 2 path and the loop path alike. At HEAD nothing writes telemetry from either path: `append_record` has exactly one caller, `telemetry_cmd.py:67` [RE-READ via grep], and `SKILL.md` has 0 hits for `review telemetry` and `review merge` and 3 for `review manifest` [RE-READ].
5. **Value checks arrive with a version, not as a guess.** `append_record` and `load` share `validate_record` (`telemetry.py:289, 411`); `load` reports an invalid line and skips it (`:412-414`). A `/2` schema that carries the type checks, with `/1` still loadable, is a mechanism; checks "at append only" is not one without a second validator.
6. **Self-falsifying design.** M3 says A is wrong on its cost reason if reviewer-only tokens are within 10 percent of all-stages tokens in 12 of 15 runs; M2 runs today's unlocked `advance_cmd` as a control and concedes the manifest lock is hygiene if it never loses an attempt in 1000 trials; M4 lists the existing tests that must pass unmodified.
7. **More of the evidence is re-read.** Variant 1 tags 4 items fully UNVERIFIED; Variant 2 tags 8 rows fully UNVERIFIED and takes all real-run facts (29 manifests, E1 contracts, orchestrator share) from research files (S-002 [DIFF-ANALYSIS]). A also brings re-read precedents B lacks: E3 harness already fills `model.observed` (`harness.py:534-560`), E2's per-attempt `meta.json`, sprint stream-json usage readers, and the PR monitor's authoritative append-only log (U-004).
8. **INV-F and the fence are respected.** The adapter is reached only as `superclaude review record ...`; no stable contract name, `merge_method` value or `CONTRACT_VERSION` changes; nothing reads events to decide a verdict (INV-L).

## 4. Weaknesses identified in Variant 2

1. **X-002 confirmed: `agents[]` on `published`/`failed` has no code path.** `fail()` takes only a reason and sets `state` and `failure_reason` (`manifest.py:389-397`); `advance_cmd --stage failed` calls `mf.fail(manifest, reason or "unspecified")` and never passes `body` (`manifest_cmd.py:174-175`); the `--publish-from` branch calls `publish_files` with no payload (`manifest_cmd.py:184-199`; `publish_files` signature `manifest.py:476-482`); and a stage record keeps only `payload_sha256`, `outputs`, `deps`, `invocation` (`manifest.py:317-326`) with the digest `sha256_json(payload)` (`:292`) and a same-stage different digest raising `Conflict` (`:295-299`). Orchestrator usage grows on every read, so an `agents[]` that includes it either changes the digest (an identical replay of `manifest advance --stage published` stops being a no-op) or needs a new unhashed field. Variant 2's text names neither. This is the half of its design that carries every non-reviewer agent and the orchestrator.
2. **X-003 confirmed: the producer "after `merge_round`, before any refusal exit" cannot run on the refusal.** The no-valid-block refusal is raised inside `merge_round` (`ledger.py:150-157`) before the round is appended; `merge_cmd.py:109` calls `merge_round` and `:111-112` turns `LedgerError` into `ClickException`, so statements after line 109 are skipped. The per-reviewer `block_ok` is returned only at `ledger.py:295`, after that check. B-7's claim that a producer "closes that gap without touching the ledger" holds only if the producer is moved into the `except` branch and re-parses the blocks, which is not what the text says.
3. **X-007 confirmed: "checks at append, `load` reports a failing legacy line" has no mechanism.** `append_record` calls `validate_record` (`telemetry.py:289`) and `load` calls the same function (`:411`); on errors `load` records the first error in `counts["invalid"]` and `continue`s (`:412-414`), so the line never reaches `reviewer_runs`. Tightening the shared validator makes existing E3 harness lines invalid at load; leaving it alone means no append-time check. B needs a second validator or a schema version, and it rejects the version.
4. **X-008 confirmed: no component carries the Tier 2 `reviewer_run` producer.** `SKILL.md` has 0 hits for `review telemetry` and `review merge` and 3 for `review manifest` (grep at HEAD); `advance_cmd` writes no telemetry (`manifest_cmd.py:160-215`); `append_record` has one caller, the CLI (`telemetry_cmd.py:67`). B's section 2 table lists a producer only for `merge_cmd.py`, and B-8 itself says the reflect SKILL never calls `review merge`. So "at the published commit (Tier 2 path)" in its position paragraph has no module behind it. B's own table under-delivers on its own position (INV-H, cost, and identity for the main panel path all depend on it).
5. **C-002: B's capture timing loses exactly the rows A is about.** The orchestrator is a median 0.59 of output tokens (research figure, [UNVERIFIED]); B reads it once at commit and labels it "through publish", with the tail excluded and a killed run leaving nothing (7.2.2, 7.2.3). X-009: B's M1 requires per-run output tokens within 1 percent of the extractor's `out_tokens`, which is a run-level total including any post-publish tail; B's design can fail its own M1 by construction.
6. **C-007: B has no cross-run all-agents basis.** The all-agents figure comes from a new `manifest summary` that reads manifests, so a cross-run cost view needs a manifest crawl; B states this as "a stated cost". A derives both bases from one store at export.
7. **S-002: much of B's "what the code lacks" evidence is not re-derived** (B-13 to B-15, B-18 to B-21 and the 29-manifest scan). Its robustness argument for the attempt route (7.2.1, "all 29 manifests hold every reviewer's `collected` attempt") rests on B-18, tagged [UNVERIFIED]; for `calibrated` attempts there is no existing call site (SKILL step 5 says only "Advance `calibrated`", per diff-analysis X-005; not re-read in full by me) and no field evidence (X-005).
8. **X-001 residual:** B's answer is that it reads usage once. That is correct for a reviewer's final usage and wrong for the retry case: `superseded_by` is set on the earlier attempt (`manifest.py:382-383`) and the transcript has sidechains, not attempts. B does not say how a retried reviewer's usage is partitioned (A-007).
9. **Lock redundancy is not a differentiator.** B's 7.2.4 is right that a lock is needed under either position; the difference between the positions is where observation lives, which is the argument above.

## 5. Concessions

1. **X-004 (conceded).** A says an event row with `completion: refused` "closes" C-03 INV-001, but the refusal happens inside `review merge` (`ledger.py:150-157`) and A's own table says `merge_cmd.py` changes "none". The row therefore exists only if the orchestrator calls `record add` after a failed merge, which is the same call discipline A criticises. "Closed" is conditional. A fix that is consistent with A: `review merge` itself writes the refusal row from its `except LedgerError` branch (a write into the event store, not a read), which changes A's "none" for `merge_cmd.py`.
2. **X-010 (conceded).** A names no location, flag or caller for the spec-review loop. The loop prompt calls `review panel resolve`, `review merge` and `review ledger revise` and has no panel directory or publish step (`document_review_loop_prompts.md:70` [RE-READ]); `review merge --out` is a file (`merge_cmd.py:57-63`) while `manifest --out` is a directory (`manifest_cmd.py:138`). "Per run `<out>/panel/events.jsonl`" is therefore undefined for the loop, and `export` "at publish" has no publish there. B is right that the loop's run record, if any, rides on `merge`.
3. **X-011 (conceded).** A's memory writer moves a Wave 5 write that `### 6.3` still describes as an LLM `Write` (`SKILL.md:592-593` [RE-READ]). A step inside `### 4.3a` step 10 would satisfy the fence test, but then two writers are named unless `### 6.3` is edited, which `test_shadow_skill_contract.py:52-75` forbids (allowed: `3.1`, `4.3a`, `5.4`, `9.2`). A did not say which. For this change B's "leave the writer, freeze reads by instruction" is the safer position, and A's script writer is a later step if a lost update is ever observed.
4. **A telemetry append lock is missing from A (C-004).** A's `export` writes `reviewer_run` records through `append_record`, which is a plain `open(path, "a")` (`telemetry.py:305`) with no lock; A's table adds a lock to the events writer and the manifest only. B is right to lock it. Whether it is needed for correctness is unevidenced (A-009), but it is cheap.
5. **The lock precedent is fail-fast, and A does not choose.** The lock A cites uses `LOCK_EX | LOCK_NB` and raises `LockHeld` on contention, and needs the lock file to exist (`issue_watch/record.py:389-405` [RE-READ]). A says "exclusive flock" and expects 400 valid lines from 8 concurrent writers (M2), which a fail-fast lock would not give. A must specify a blocking lock with a timeout, and import `fcntl` lazily as the precedent does (neither `manifest.py` nor `telemetry.py` imports it today [RE-READ via grep]).
6. **The adapter is unverified (A-001 to A-003).** The entire identity half rests on item 17. Every cited reader works on headless output (E1 stream logs, E2 `claude -p` JSON, sprint stream-json); no interactive-session transcript path or format is shown, E2's reader looks only at main-thread messages, and the E1 logs are untracked so M1 runs only on this machine. A's null fallback keeps it honest but means the identity benefit may not materialise.
7. **The effort and the gain are unmeasured.** A is a new module pair, a schema id, a `/2` bump and a CLI family for a problem with zero recorded incident (29 manifests). The slot row itself calls it design from evidence. If M3 shows reviewer-only tokens within 10 percent of all-stages tokens in 12 of 15 runs, the cost half of A falls.
8. **A's objection 1a/1b is overstated for a reviewer's final usage (X-001).** If usage is read once when the attempt is recorded, B's route does not hit `Conflict`, and 29 of 29 manifests have every `collected` attempt (B-18, [UNVERIFIED]). A's argument is strong for retries and non-reviewer agents, not for the first reviewer attempt.
9. **The orchestrator-header replacement is deferred (C-006).** A leaves `model_observed:` (`SKILL.md:341`) and `identity_source` (`:348`) as hand-written "in a later change"; B replaces them inside `### 4.3a` now. A's "correct without that edit" holds for the record, not for the contract text the user reads.
10. **`ext{<module>}` is an unguarded leak path** until it is type-checked (A states this; the type check is not designed).
11. **X-006 / A-005:** a lock held only inside `save` or `load` leaves the lost update; A's stated span (around load-modify-save) is right but its `rev` is then redundant with the lock for a single process. It may be kept as a cross-host or crash guard, not as the main control.

## 6. Shared assumptions A-001 to A-009

- **A-001: QUALIFY.** It is a real dependency of both variants, but only the Claude Code transcript is evidenced, and only through headless logs; A degrades to `null` plus `requested-pinned`, so the design is safe if it fails and worthless for identity until M1 passes.
- **A-002: ACCEPT.** The unstated input is the transcript path and format; the cited readers are headless stream logs (`extract.py`, `run-reviewer.sh`, sprint monitor), the E1 logs are untracked, and no interactive-session path is shown. M1 must include one real interactive-session transcript before the adapter is relied on.
- **A-003: ACCEPT.** The join from a sidechain to `(reviewer_id, attempt_id)` is undefined in both variants; `extract.py` keys by tool-call id and takes the most common served id, which hides a two-id sidechain. A should define one row per sidechain, the served-id list when more than one appears, and `attempt_id` supplied by the caller.
- **A-004: QUALIFY.** The assumption is contradicted for B's `dispatched`/`calibrated` ordering (9 of 29 manifests, `manifest.py:371` refusal) and is weaker for A, whose rows append at any time and whose `ingest` can run after the fact, but A still needs the calls (X-004); so A is less order-sensitive, not independent of the orchestrator.
- **A-005: ACCEPT.** `fcntl` is POSIX-only and the precedent imports it lazily (`issue_watch/record.py:389`); neither `manifest.py` nor `telemetry.py` imports it today. The lock helper must import lazily and be blocking with a timeout, and a non-POSIX runner is unsupported.
- **A-006: QUALIFY.** `<out>/panel/events.jsonl` is reachable wherever a manifest directory exists, not for the spec-review loop (X-010); and B's producer inside `review merge` would write to `.dev/benchmarks/review-telemetry` relative to cwd unless an env var is set (`telemetry_cmd.py:12, 64`). A needs a stated loop location.
- **A-007: ACCEPT.** One row per agent is the right grain only if the partition is proved: A's M1(c) tests the total, not the per-attempt sum, and a retried reviewer (`superseded_by`, `manifest.py:383`) or helper child maps many sidechains to one attempt. A should add a per-attempt reconciliation test and a many-to-one rule.
- **A-008: ACCEPT.** The loop prompt itself handles "`superclaude` not installed" as a real case; A's "a consumer that never calls `record add` behaves as today" is not a design for the gap. A should make a missing or empty record visible (a `record_absent` flag at export).
- **A-009: QUALIFY.** A's events lock has its own reason (`seq` assignment); for the cross-run telemetry append no variant shows a race (`telemetry.py:305-306` is one `write` per record in append mode), so the lock is cheap hygiene and not an evidenced fix. A's `export` writes through `append_record`, so it should take the lock anyway.
