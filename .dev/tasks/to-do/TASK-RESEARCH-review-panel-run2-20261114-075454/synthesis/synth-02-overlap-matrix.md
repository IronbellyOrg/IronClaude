**Classification definitions (R01 section 4.1, applied to the row as a whole).**

| Class | Meaning |
|---|---|
| identical | the efforts carry the same mechanism or the same code (shared code counts) |
| superset | one effort does everything the other does and adds at least one named capability. "Strict" = no capability of the smaller one is missing from the larger one. |
| conflicting | the efforts do the same job in an incompatible way (different vocabulary, schema, rule or semantics), so both cannot be the shared default without a decision |
| unique-E1 / unique-E2 / unique-E3 | only that effort has the mechanism; no incompatibility with the others is implied |

**How one row gets one class.** The class in the Classification column is the primary, decision-relevant relation, chosen in this order: conflicting (any [CODE-VERIFIED] incompatibility between two mechanisms of the row, including E3s against E3i) before superset before identical before unique. Secondary relations are written in the Notes column and feed the lists in 2.9.5 and 2.9.6. A cell that has no mechanism for the capability is written ABSENT. R01 used a fifth cell label "absent"; it is kept here for the same reason (an absent cell cannot be identical, superset, conflicting or unique). A mechanism that does the neighbouring job (for example E3i's blind `finding-grader` against calibration) is named in the cell as "adjacent" and still counts as ABSENT for that row.

**Evidence tags (rule 7 of the assignment).** `[CODE-VERIFIED]` = confirmed at file:line, by a read-only command or by a probe in the research file named. `[CODE-CONTRADICTED]` = the research file shows the code differs from a claim; the cell states what the code shows. `[UNVERIFIED]` = taken from a scope slice and not re-derived by the research file; it is flagged in the cell, never used as the sole basis of a class, and listed in 2.9.8 for Open Questions. A dagger (†) in the Evidence tag column marks a row with at least one [UNVERIFIED] cell. All 16 rows carry it (mostly E3i cells and E2 study figures), so it does not discriminate between rows; the Evidence tag column names which cells are [CODE-VERIFIED]. The class of rows 12, 14 and 15 (unique-E1, unique-E1, unique-E2) rests in part on an [UNVERIFIED] statement about another effort (E2 has no calibrator; E2 has no memory; E2 ground truth and blind judge exist only in E2), and is flagged again in 2.9.8.

**Row count.** The assignment lists 16 capabilities. R01 grouped "ids, identity and hash" into one row; here "Ids" (row 2) and "Identity and hash" (row 3) are separate rows so that each of the 16 named capabilities has its own row. Row 2 and row 3 content comes from R01 section 4.3 row 2 and R04 section 4; no fact is added.
