## Design

### Position in one paragraph

<!-- Source: Base (original, modified) - merged framing, neutral claim, staged delivery, Change #15, #18 / Amendment A-14 -->
C13 decides what a review round after the first one is. The target model for rounds 2 and 3 is Option B's: only round 1 searches the whole candidate for defects. Rounds 2 and 3 answer one question per existing blocking row ("is it fixed, still open, or regressed, and here is the quote from the new text") and report new blocking defects only in the text the reviser changed; a defect noticed anywhere else is recorded as an outside row that never enters the plan but is counted (see W). Everything that decides the loop (row state, frozen fields, the round counter, the cap, clearing, the verdict) is computed by a script that is the only writer of the ledger. The experiment ledger already implements the document-lens core of this design in 2,668 lines with 77 test functions (`~/.claude/skills/sc-review-ledger/scripts/review_ledger.py`; byte-identical to the git-tracked copy under `.dev/experiments/346-validation/phase5/final-bundle/builds/ledger/repo-files/` by `cmp`; test file `tests/skills/test_review_ledger_script.py` in the same folder, 1,578 lines) [CODE-VERIFIED]. The merged proposal delivers it in stages: Stage 0 lands Variant A's round-bound, quorum and atomic-refusal fixes on the existing engine because every option needs them; Stage 1 adds the round-1 hand-off and two measurements; Stage 2 is a decision gate between "Option A plus fixes" and the verify-only port, and this proposal does not say which side wins; Stage 3 finishes the chosen side. The port is not "mostly a port": it carries the document-lens core, and the per-lens predicate, the click CLI, multi-path snapshots and the round-1 hand-off are new code (Cost). Nothing in this document claims, on measured evidence, that either round model converges faster or finds more real defects than the other; Evidence D says what was measured and where it stops.

### What B decides and what it leaves alone

<!-- Source: Base (original, modified) - last sentence, because A's re-find engine survives as the Stage-2 alternative, Change #18 / Amendment A-14, Disposition: modified, Decision basis: the advocates ended SPLIT at 58% on C-001 -->
B decides the round model: how rows are created, how they change, who may clear them, what a later round may report, and how the loop ends. It does not decide who judges blocking at round 1 (C05), how findings are clustered (C12, decided: one v2 clusterer with complete-link admission), the finding container (C01, decided: v2 container, v1 a strict subset) or bad-line policy (C15, decided: keep valid lines, mark the reviewer partial). B consumes those. Option C of C-13 is B plus an explicit round-1 merge; this proposal gets the same round-1 merge by reference to C05, C12 and C15. A reader who finds B and C indistinguishable is right about everything except one point: the port carries no A-style "re-find and cluster" mode as a fallback for rounds 2 and 3. Variant A's re-find engine is not discarded; it stays in this document as the Stage-2 alternative, "Option A plus fixes", specified in Cost.

### Data flow

<!-- Source: Base (original, modified) - round-1 rules, refusal classes, W term, Change #2, #3, #5, #10 / Amendment A-01, A-02, A-05, A-07 -->
```
ROUND 1 (the only find)
  panel resolve --kind first  ->  N reviewers, fresh context, same code-rendered brief (C10)
  each reviewer report  ->  findings block (v2 container, v1 lines accepted)
  review merge --round 1:
      keep valid lines; record every rejected line (id, reason, blocking flag)   [C15, D1]
      partial reviewers flagged; quorum rule and degraded table (Core item 3)   [D3, INV-007, INV-016]
      a missing or doubly occurring anchor: row kept, deferred, warning names the finding id   [C02]
      anchor -> citation; cluster (C12); decider hook (C05)
      rows[] = {grade, rule, wrong_outcome, anchor/citations, finding, label}
      a refusal changes nothing except refusals[] (Core item 3)
  ledger find   ->  profile predicate computes blocking; rows frozen; non-blocking rows stored deferred
  ledger close  ->  decision: PASS | REVISE | ESCALATE (cap 1 of 3 reached only by count)

REVISE (reviewer role, no panel)
  reviser edits the candidate from the Reviser brief
  ledger answer   <- fix map (applied | rejected, reason); applied rows -> fixed only if a hunk touches them

ROUND k = 2, 3 (verify-only)
  ledger begin --doc D   ->  snapshot r<k>, diff against r<k-1>, plan-r<k>.md; refuses past the cap (E-CAP)
  panel resolve --kind re-review  ->  ONE anchor reviewer (panel.py:600-605); a resolution with more than one reviewer is refused (Core item 10)

  ledger verify   ->  invalid plan answers refuse the whole input (E-SCHEMA, E-FROZEN, E-ILLEGAL, E-NOT-CHANGED,

                      invalid new rows are demoted to flagged deferred rows in the same atomic write as the valid answers
  ledger close   ->  decision from U, X, I, W (formula below)

AFTER THE LOOP (profiles with sweep: required)
  ledger sweep --prepare  ->  copy of accepted text; fresh context critiques it
  ledger sweep --input    ->  rows stored deferred with would_block / challenges; delivery outcome computed
  ledger verdict          ->  exit 0 PASS, 10 REVISE, 11 ESCALATE, 12 PENDING (until the sweep ran)
```

```
U = rows with blocking and scope == in and status in {open, fixed, reopened}
X = cannot-verify answers + unmappable anchors + failed revert preimages, this round
I = ledger hash valid and snapshots intact and every plan row answered
W = would-block outside rows found in rounds >= 2, on a lens with sweep: none   (never in U, never in the plan)
decision = ESCALATE if not I or X > 0 | ESCALATE (reason outside_would_block) if W > 0
           | PASS if U == 0 | REVISE if k < cap | ESCALATE
delivery outcome (after the sweep) = ESCALATE if decision == ESCALATE or any sweep row would block
             or challenges a verified row, else PASS
```

The brief for a round k reviewer changes in one clause. ## Correctness argument

<!-- Source: Base (original, modified) - restated as conditional on the register, Change #20 / Amendment A-09, Disposition: modified, Decision basis: INV-010 shows the unconditional claim is false for the consensus package alone -->
Correctness here means: the loop stops, it never reports PASS on a review that did not happen or on a row nobody checked, a row's blocking status cannot change by accident, and what the loop did not look at is recorded. Each property below names the evidence it rests on and holds on the recorded-round path only, given the closure rules of the Invariant register (INV-001 to INV-009); the register's status column says which of them are closed by a written rule and which are open.

**P1. No silent pass, and a stop that is computed.** PASS requires I (hash and snapshots intact, every plan row answered), X = 0, U = 0 and, on a lens with `sweep: none`, W = 0, all computed by the script (E-8, E-10). Invalid plan answers refuse the input and only `refusals[]` is written (`review_ledger.py:1790-1794`), so a round that did not produce a valid plan-answer set stays in `verify`; it cannot become PASS. Invalid new rows are demoted and flagged, not refused (Core item 4). The master ledger can PASS on one valid reviewer while another reviewer's block was invalid (D3, `ledger.py:150-157`, `:273-274`, E-2) and writes a verdict that is only a label at the cap (E-5); Stage 0 closes both. External support for refusing instead of defaulting: E-25.
<!-- Source: Base (original, modified) - refusal wording and W, Change #5, #10, #20 / Amendments A-02, A-05, A-07, Disposition: modified, Decision basis: reword P1 "invalid answers refuse the input; invalid new rows are demoted" -->

**P2. Identity and blocking are stable after round 1.** After `find`, no clustering step touches a row: its id and the thirteen frozen fields cannot change (E-8) except through the two named inputs of Core item 2, and only `status` moves, through the script's transition table (`SKILL.md:63-80`). Two defects of the re-find model cannot occur by construction: one reviewer's non-blocking re-report un-blocking a row (E-3), and a nearby new defect being matched to an old row by the three-line rule (E-4). A new defect in a changed hunk gets its own row with `caused_by` naming the rows that claimed the hunk (E-9); it is a fix-induced defect and is recorded as one. Accepted text cannot be re-attacked except through `reattack_of` with a located quote over changed text; a reopened row enters the next round's plan, so a reopen loop is bounded by the cap only.

**P3. Clearing needs evidence about the new text.** A row leaves the blocking set only if (a) a hunk touched its span, (b) the reviser's claim moved it to `fixed`, (c) the verifier answered `resolved` with a quote that occurs in the new snapshot, and (d) the anchor still maps (E-8), or a human defers or releases it. Silence is `E-INCOMPLETE`. This is the fix the synthesis itself proposes for D2: "clearing needs a positive answer in the verify-only protocol" (S4 D2 row, line 1357). The evidence rule still does not prove the verifier judged well (E-22): it proves the verifier was shown the touched text and had to quote it, and the quote is stored.
