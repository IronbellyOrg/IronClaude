## Suggested resolutions for the UNADDRESSED items (from the fault-finder; not debated)

- INV-001: have `defer` call the same `decide()` as `merge_round`, fed from ledger state (live blocking rows, `unverified`, `degraded`, cap); accept only a live blocking row; record `deferred_lids`. Tests: defer after an `unverified` FAIL stays FAIL; defer of a non-blocking or resolved row is refused.
- INV-002: allow one write on refusal (an additive `refusals: [{round, reason, report_sha256s}]` list); after two refusals for a round, `merge_round` records an ESCALATE round itself so `verdict` exits 11. Tests: rows byte-identical after a refusal; the third call yields ESCALATE.
- INV-003: only `status == "resolved"` can clear; `open` or `regressed` keeps the row out of `resolved` (and, if no finding line, records an inconsistency warning). Pin test: prior `open`, no finding line, row stays uncleared and the round is not PASS.
- INV-004: count priors only from reviewers with `block_ok`; collapse duplicate prior ids to the most blocking status and flag the block; across reviewers a row clears only if every answering valid reviewer said `resolved` and none re-reported it.
- INV-005: render `unverified` ids in a separate merged-report section and name them in the RE-REVIEW instruction; keep them out of `brief_ids`; use a distinct RE-REVIEW decision (no reviser step) or state that REVISE with an empty id list is accepted. Test: round 2 `unverified` FAIL then round 3 with prior lines plus evidence reaches PASS.
- INV-006: record `revised: {round, old_sha256, new_sha256}` on the round; refuse a second revise for the round and a merge whose doc hash differs from `revised.new_sha256`. Tests: revise twice leaves spans unchanged; merge without revise refused or flagged.
- INV-007: `panel_size = len(resolution.reviewers)`; refuse a report id not in it, a `review_kind` that does not match the round, or an empty list; record `panel_size`, `quorum`, `valid`, `denominator_source`; with more than one round-1 report and no `--resolution` mark the round `degraded`.
- INV-008: store and render `anchor_status` and `anchor_ambiguous`; an ambiguous row clears only via a prior line whose quote overlaps a touched occurrence; a spanless blocking row gets `unanchored: true` and the decision text says "needs a human defer or re-anchor".
- INV-009: parse `evidence` (flat string, 12 to 200) for `resolved` and require it there; the quote must `locate` in the new text AND overlap `map_span(row.span, ops)` widened by 3 lines or touch a changed hunk; deletion-only hunks check that the row's anchor no longer locates; missing evidence counts as no answer.
- INV-010: restate the claim as "no PASS and no clear without a positive, script-checked signal on the recorded-round path, given INV-001..009 closed"; list F4 to F6 as accepted residual risks with owners (C01 for F5, C05 hook for F4); add a path-closure test that enumerates every writer of `status` and `blocking` and asserts each is gated.
- INV-011: base sticky on `members` from valid blocks only (an invalid-block reviewer's blocking call opens the row as `provisional`); state the order (decider output is `current`, sticky applies after, un-block only via a named, logged `unblock` event).
- INV-012: define field classes (frozen: `lid`, claim and anchor origin, `fp`, `category`; mutable: `span`, `span2` via revise mapping, `status`); keep `last_seen: {round, claim, anchor}`; a 3-line re-find adds an `adjacent_refind` member instead of overwriting `span`.
- INV-013: one shared decision-to-exit-code table for `ledger.py` and `ledger_cmd.py`, with a test that every value `_decision` can return has a code; prefer a non-PASS through ESCALATE with a `reason` field unless the owner wants PENDING.
- INV-014: add an additive `min_writer` key; new code refuses to append to a ledger whose `min_writer` it does not know and writes it on every save; print the writing version in the merged report header.
- INV-015: `--cap` equal to the stored value is no conflict; refuse a merge after a recorded PASS or ESCALATE; warn when the reviewer's `review: N of cap` header differs from `--round`; boundary tests for caps 1, 2, 3.
- INV-016: define `degraded = valid < panel_size`, `quorate = valid >= quorum`; record `valid`, `panel_size`, `quorum`, `dropped_lines`; refuse a would-be PASS with `degraded` and `dropped_lines > 0` for any reviewer.
- INV-017: gate only on rows that were blocking when moved to `resolved_check` (store `blocking_at_fix`); move non-blocking `applied` rows straight to `resolved` with an event or refuse the line; keep only the unanswered rows in `unverified`.
- INV-019: save the ledger first, then write `--out` (or temp-and-rename); return the stored result for an identical replay (same report hashes).
