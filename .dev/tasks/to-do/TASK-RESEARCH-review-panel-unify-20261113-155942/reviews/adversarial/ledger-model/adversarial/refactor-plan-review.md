## 1. Findings

### PR-001 BLOCKER - Change 2 states the degraded-round rule two incompatible ways (checklist 3)
EVIDENCE: Change 2 "Anchors preserved" keeps A's rule "a degraded would-be PASS is refused with nothing recorded" and the Threshold table sets `degraded = valid < panel_size` (INV-016). The rationale of the same change says a would-be PASS is refused only "when any reviewer's block was invalid and a dropped line existed (`dropped_lines > 0`)". With `degraded = valid < panel_size`, a panel of 3 with 2 valid empty blocks and 1 missing reviewer is degraded, so the anchor refuses PASS, but the rationale records it. A's own tests 7 and 8 (missing reviewer counts as abstention, degraded would-be PASS refused) then fail against the INV-016 rule. In A, `degraded` meant `valid < quorum` (A "Core changes" 3).
FIX: Replace the Change 2 rule text with one table and tell the executor to delete the "Anchors preserved" clause about refusal:
- valid = 0: refuse (unchanged, `ledger.py:150-157`).
- valid < quorum (`below_quorum`): a would-be PASS is refused, nothing recorded; a FAIL is recorded with `degraded: true`.
- quorum <= valid < panel_size (`degraded` by INV-016): a would-be PASS is refused only if some non-valid reviewer had `dropped_lines > 0` or a rejected line with `blocking: true`; otherwise PASS is recorded with the `degraded:` header line.
- valid = panel_size: as today.
Record both booleans (`degraded`, `below_quorum`). Rewrite A tests 8 and 9 to match (k-1 versus k at quorum, and a second pair at panel_size minus 1 with and without a dropped line). Add that the `review_kind` and resolution-membership checks of INV-007 apply only when `--resolution` is given (the CLI round-trip test at `tests/review/test_review_cli.py:196` runs round 2 with one `--report` and no `--resolution`).

### PR-002 BLOCKER - Change 10 contradicts itself and the base's frozen `blocking` (checklist 3, 6)
EVIDENCE: Change 10 (b) makes a would-block outside row give ESCALATE with `reason: outside_would_block`; (c) says that, until the late-row rate is measured, outside rows that would block "count toward U". In the code, `u_count` is `r["blocking"] and r["scope"] == "in" and r["status"] in LIVE_STATUSES` (`RL:474-479`); `make_row` sets `blocking = predicate and scope == "in" and rnd != "sweep"` (`RL:889`), so an outside row is never `blocking`; it is stored `deferred` (`RL:1856-1881`) and an answer to a deferred row is `E-ILLEGAL` (`RL:1696-1698`); the plan at `RL:1654-1658` contains only live blocking in-scope rows. So an outside row cannot count toward U without redefining U, and if it did it would be a blocker nobody can answer or fix (REVISE with an empty fix list, the INV-005 pattern). (c) also contradicts (b): ESCALATE versus REVISE.
FIX: In Change 10 delete "count toward U" and write: "an outside row records `would_block = predicate(row)` (as sweep rows do, `RL:2253`); `decide` gets a fourth term W = number of would-block outside rows found in rounds >= 2 on a lens with `sweep: none`; W > 0 gives ESCALATE with `reason: outside_would_block` (no new exit code; INV-013 table). W never enters U, never enters the plan, and is listed in the merged report. D-1 (adopt the deferral policy) decides only whether W is ignored." Note in Risk Summary row 10 that W > 0 ends a loop at round 2 without a fix cycle (that is the visible cost).

### PR-004 BLOCKER - Change 8's "parented new row reopens a verified row" does not match the code and weakens the base's main guarantee without saying so (checklist 3)
EVIDENCE: `E-NOT-CHANGED` is raised for an answer to a verified row (`RL:1699-1705`), not for a new row, so "E-NOT-CHANGED becomes ... a parented new row is allowed" changes nothing the reopen needs. And "accepted text cannot be re-attacked" (`RL:1703`) is a stated guarantee of Strength 1/Core 5/P2 of the base; Change 8 reverses it for rows that carry a quote.
FIX: Rewrite Change 8's two paths as new, named inputs, not as a reading of `parent`: new-row field `reattack_of: <verified row id>` (needs `evidence` that locates and a changed hunk overlapping the quote, or the row is stored `deferred` and counted in W of PR-002) and `regrade_of: <non-blocking row id>`. State the changes to code: (a) validation at `RL:1769` accepts those ids, (b) the transition table gains `verified -> reopened` through this input only, (c) `E-FROZEN` lists `blocking` with these two named exceptions, (d) a reopened row enters the next round's plan (not the current one; the current round's `I` is unaffected). Say in P2 and in "Strengths to Preserve" that the guarantee "accepted text cannot be re-attacked" is now "cannot be re-attacked except through `reattack_of` with a located quote over changed text". Add the two paths to Risk Summary row 8 with impact "reopen loop is bounded by the cap only".
