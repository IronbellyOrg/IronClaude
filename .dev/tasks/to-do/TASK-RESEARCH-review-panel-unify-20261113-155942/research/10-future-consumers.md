## 1. PR review: data flow and the seam where a panel would enter

### 1.1 How a PR finding enters, changes and leaves today [E3-adjacent: master consumer]

1. **Sources (closed set of two).** `REVIEWERS = ("augment", "codex")` (`src/superclaude/pr_submit/reviewers.py:41`); `reviewer_identities` raises `ValueError` for any other name (`reviewers.py:47-60`). Augment roots come from `classifier.actionable_finding_comments` (`classifier.py:605`), Codex roots from `codex_finding_comments` (`reviewers.py:261-270`), which tags each root with `reviewer: "codex"`, `codex_priority`, and a `severity_hint` from the P0-P3 badge (`reviewers.py:234-243`, map `_CODEX_HINTS` at `:43`). A third source would need a new adapter here plus a `merge_wait` rewrite, because `merge_wait` takes exactly two positional pairs, `augment` and `codex` (`reviewers.py:395-424`).
2. **Normalize.** `finding_from_comment(raw)` builds a `Finding` (`severity_router.py:61-119`). It requires a nonempty `path` and `body` (`:69-71`) and a `line`/`original_line` that is a positive int or null (`:72-76`). It defaults `in_diff=True` (`:112`) and `reviewer="augment"` (`:118`), and extracts one `**Severity:**` line from the body when no hint is given (`:83-91`). `verification_status` starts as `"unverified"` (`models.py:188`).
3. **Grade.** `remap_severity(finding, *, deep=False)` (`severity_router.py:151-200`) runs: hint → clamp to `_CATEGORY_TABLE` (`:34-53`) → drop one tier if `confidence == "low"` (`:174-175`) → drop if `in_diff is False` (`:178-189`) → drop if `deep` (`:192-193`) → clamp again (`:197`).
4. **Dedup.** `dedup_groups` groups by exact `(path, line)`, falls back to `original_line`, and keeps every member (`reviewers.py:430-440`). There is no line-proximity window and no text-similarity clustering.
5. **Verify (S2b).** The FSM edge `(S2_CLASSIFY, "findings")` goes to `S2B_VERIFY` after the round-budget gate (`fsm.py:806-813`); `(S2B_VERIFY, "verified")` goes to `S3_DIAGNOSE` (`:823-824`); `(S2B_VERIFY, "unverified")` goes to `REPORT_ONLY` and consumes no round (`:825-826`). In `run_skill`, verification is an injected seam, `verify: Callable[[Finding], bool]` (`fsm.py:941`). Its default, `_default_verify`, only checks `verification_status != "unverified"` (`fsm.py:888-896`); production injects the `evidence-validator` spawn (docstring `fsm.py:892-895`; prose `refs/finding-verify.md:38-43`). The structural location check is `is_groundable`: path present and line a positive int (`fsm.py:364-372`).
6. **Route and dispatch (S3).** `route` sends Critical/High to `--depth deep --fix`, Medium to `--fix`, and Low/Nit to `report-only` (`severity_router.py:203-223`). `seed_troubleshoot` builds `{scope: "path:line", issue: body, type: category, route}` (`fsm.py:437-453`). `plan_dispatch` batches by file and truncates to the remaining round budget (`fsm.py:476-499`). The fix agent is `/sc:troubleshoot`, not a reviewer.
7. **Fallback source.** When Augment declines, the FSM enters `S5B_AUGGIE_FALLBACK` (`fsm.py:854-861`). `_run_fallback` invokes `/sc:auggie-review` at most once, then checks its findings through the same `config.verify` seam (`fsm.py:956-1022`). So `/sc:auggie-review` is already a pluggable internal reviewer source in this flow, but only as a once-per-PR fallback.

### 1.2 Where an internal panel would enter (question 1)

Both seams below exist in code and are [CODE-VERIFIED] by the citations in 1.1.

| Seam | What it is | What a panel would have to provide | Fit |
|---|---|---|---|
| **A. Extra reviewer source** (next to Augment and Codex) | The closed tuple at `reviewers.py:41` plus per-reviewer adapters (`reviewer_identities`, `retrigger_phrase`, `reviewer_activity`, `*_wait_outcome`, `merge_wait`) | Raw roots shaped like PR review comments (`path`, `line`, `body`, optional `severity_hint`, `category`, `confidence`, `in_diff`, `reviewer`) that `finding_from_comment` accepts (`severity_router.py:61-119`) | Every adapter assumes a GitHub bot that posts threads: identities, badges, re-trigger comments, silence timers. An in-session panel has no GitHub identity and no thread, so `thread_id`/`comment_id` would be null; `fsm.py:1064` already treats that case as "fallback_only" (reply, no resolve). The S5b fallback path (`fsm.py:956-1087`) is the closest existing model of an internal source: findings arrive as `Finding` objects and are then verified. |
| **B. Verification stage** (S2b) | `RunConfig.verify: Callable[[Finding], bool]` (`fsm.py:941`) | One boolean per finding (`verified` / `unverified`) | Narrow and already injectable. The verdict is per finding, never per reviewer or group (`refs/finding-verify.md:67-72`). A panel placed here would be a multi-model checker of external findings (the calibrator / evidence-gate role), not a finder. |

**Agreement and ledger confidence.** On the PR side, agreement shows up only as a dedup group (same `path`, `line`). Its members keep their own verdicts, and the group routes at the highest member tier (`refs/severity-routing.md:35-37`; grouping at `reviewers.py:430-440`). No pr-submit code maps group size to a confidence or a severity.

- The only agreement rule is step 5 of the auggie rubric: a finding found by both the Auggie main pass and the `auggie-reviewer` agent keeps its tier, and a single-source finding drops one tier (`severity-rubric.md:97-99`).
- `remap_severity` implements step 5 as an unconditional drop whenever `deep=True`, with no source count (`severity_router.py:191-193`).
- **No caller passes `deep=True`.** A Grep for `remap_severity(` and `deep=` over `src/` and `tests/` finds callers at `reviewers.py:301`, `fsm.py:447`, `sc-pr-submit-protocol/SKILL.md:126,151` and in `tests/pr_submit/test_severity_router.py` and `test_codex_reviews.py`, none with `deep=`. So agreement between sources never changes PR severity today.

In the shared review core [E3], `_confidence` returns `overlap` when two or more **distinct `reviewer_id`s** hit one row in the same round, else `single` (`src/superclaude/cli/review/ledger.py:86-90`) [CODE-VERIFIED]. The direct mapping is: a dedup group with members from two or more distinct `reviewer` values becomes `overlap`. The catch is that the two sides cluster on different keys (exact `path,line` versus text-anchor clustering), so the same pair of findings could be one row on one side and two rows on the other.

### 1.3 Edge cases in the PR intake [E3-adjacent: master consumer]

- **Live PR roots carry no `category`, `confidence` or `in_diff`.** The only root builders found set `path`, `line`, `original_line`, `body`, `reviewer` and `severity_hint` (`reviewers.py:236-243, 292-299`), and a Grep for `category|in_diff|confidence` in `src/superclaude/pr_submit/` finds no other producer. For Augment and Codex findings, remap steps 2-4 therefore do nothing (category `None` means no clamp; `in_diff` defaults to `True`). Severity equals the hint, or Medium when there is none (`severity_router.py:122-133`). The 5-step rubric only takes effect for findings that carry those fields, such as Auggie JSON. I read `classifier.py` only at the Grep hits `:447` and `:605`, so this is [UNVERIFIED] for any field the classifier adds to a root.
- `_default_apply_edits` counts only `in_diff` findings (`fsm.py:899-907`), so with the default seam an out-of-diff finding never yields an applied edit.
- `fix_key = sha256(path + line + body)` is the idempotency identity (`models.py:196-207`). A panel finding without stable `body` text would get a new identity on every run.

**Key Takeaways**
- PR review has two real seams. The first is an extra reviewer source, which means changing the closed `REVIEWERS` tuple and its GitHub-shaped adapters (`reviewers.py:41-78, 395-424`). The second is the S2b verify seam (`fsm.py:941`), which is the cheaper entry point. The S5b fallback (`fsm.py:956-1087`) is the existing template for an internal finder.
- PR grading does not use agreement between sources today: step 5 needs `deep=True`, and no caller passes it.
- Mapping PR dedup groups to ledger `overlap` needs a single clustering key. PR uses exact `path,line`; the review ledger uses text anchors and counts distinct `reviewer_id`s per round (`ledger.py:86-90`).
