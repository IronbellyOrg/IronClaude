# Implement Pipeline Hardening Closure Mode for sc:troubleshoot-protocol (RELEASE-SPEC v1.1.0)

## Task Overview

This task implements the **Pipeline Hardening Closure** mode for the `sc:troubleshoot-protocol` skill per RELEASE-SPEC v1.1.0. The mode is a new protocol stage (waves/gates **H0-H5** plus a cross-cutting **waiver / no-re-greening latch**) that triggers after Tier-1 diagnosis and before report closure, closing the **E1-E5 pipeline-escape class** — defects at runtime / generated-artifact / shared-contract / review-input boundaries where a review signs off from adjacent proof while the real boundary still fails. The work hardens the protocol so remediation is not "complete" until the invariant is proven at the same boundary where the escape can recur.

The deliverable set is: **6 new ref files** under `src/superclaude/skills/sc-troubleshoot-protocol/refs/`, **4 modified files** (SKILL.md, commands/troubleshoot.md, refs/report-template.md, refs/remediation-handoff.md), and a **net-new pytest suite** under `tests/troubleshoot/` (directory + `__init__.py` + EXACTLY 7 test modules — `test_hardening_h0.py`, `test_hardening_h1.py`, `test_hardening_h2.py`, `test_hardening_h3.py`, `test_hardening_h4.py`, `test_hardening_verdict.py`, `test_hardening_output_contract.py` — holding 13 unit + 5 integration tests + 6 documented E2E backtest scenarios in `e2e-backtest-scenarios.md`). All authoring follows the §4.6 7-group implementation order. After authoring, the task runs `make sync-dev`, `make verify-sync`, markdownlint on the new/modified `src/` markdown, and `uv run pytest tests/troubleshoot/ -v`, then a FINAL_ONLY lens-based QA gate (>=7 agents, standard intensity) and a POST reflect gate before marking Done.
