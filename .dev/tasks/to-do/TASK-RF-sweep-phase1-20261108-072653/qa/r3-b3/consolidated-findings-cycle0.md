### R3B3-F5 (MAJOR): the `call_failed` trigger ("`sources` row has `unscanned` set") cannot be evaluated by `classify` and also holds for an outage
- Sources: IC F3 (MAJOR, kept). Merged duplicates: AC A-1 (MAJOR), EQ E3 (MINOR).
- Evidence: `:501` keys the note on the `orca worker-list <run>` row having `unscanned` set. `:456` and `:467`: `classify_all` receives `orca_available`, `truncated` and `sources` (`name, coverage, age_seconds, unscanned`) and no per-call kind. `:250-251` and `:850`: after an unavailable result the remaining Orca sources are marked `unscanned: orca unavailable`. `:287` and `:378`: a budget cut is `call_failed` with `unscanned: time budget reached (90 s)`.
- Effect: read literally, the outage fixture also gets `origin unknown: worker list call failed`, and test 1 has two valid outputs.
- Smallest fix: write the trigger as "a `sources` row `orca worker-list <run>` has `unscanned` set while `orca_available` is True" (the outage note owns the unavailable case; a budget cut counts), add that qualifier to fixture 3, and say in fixture 1 that `sources` holds `orca worker-list R1` with `unscanned` `orca unavailable` and T carries exactly one `origin unknown:` note.

### R3B3-F6 (MAJOR): the SPEC reason "tab map unreadable" and the "tab map is read" condition have no rule
- Sources: IC F4 (MAJOR, kept). Merged duplicates: SF F1 (MAJOR), AC A-7 (MINOR), CR M4 (MINOR), CO F3 (MINOR), NM N3 (MINOR).
- Evidence: `merged-requirements.md:104` lists four reasons ("Orca unavailable, worker list truncated, worker list call failed or tab map unreadable") and makes True require "the tab map is read". `:501` carries three; a search of the design for "tab map unreadable" returns nothing. `:394` and `:401`: `read_tab_map` returns a bare tuple and never raises, so an unreadable `orca-tabs/` yields an empty tuple plus an unscanned source row. `:500`: under path A a transcript with no tab-map entry may be True.
- Effect: an unreadable tab map can let an unproved transcript reach True, then idle or Historical, with no `origin unknown:` note.
- Smallest fix: add a fourth trigger and note `origin unknown: tab map unreadable` (the `orca-tabs/` source row is `unscanned`; an empty readable folder is not this case) to `:501` and its note order, add one non-SPEC fixture, and mention it in the FR-010 row (`:771`). If the owner decides the SPEC sentence is only illustrative, record that as a deviation instead (an owner decision: the fix agent must not invent it).

### R3B3-F7 (MAJOR): a scoped Run whose `worker-list` is never attempted is not covered
- Sources: DA F2 (MAJOR, kept). Merged duplicate: CR M9 (MINOR).
- Evidence: `:501` triggers on a `worker-list` result that is `call_failed`; `:349` covers only rows already listed; budget defaults `total_s=90.0`, `per_call_s=10.0` (`:367`), `call_timeout()` returns None below 1 s (`:371`); `:287` covers a call that started and timed out, not one never started.

- Smallest fix: state in `:501` and `:595` that every Run in `ctx.runs` has a source row `orca worker-list <run>`, and that a Run not reached because of the budget carries `unscanned: time budget reached (90 s)` and counts as `call_failed` for this rule; add one fixture.
