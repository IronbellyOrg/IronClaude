## H. Key takeaways

- Two session roles plus the person: a person-opened coordinator and a worker session identified only by a preamble with Task ID and Dispatch ID. Subagents are not roles; they may not send lifecycle messages or call Orca.
- Authority is stated as contract text read by LLM sessions. IronClaude code enforces only `orca worktree create` without `--agent`, via a fail-open lexical PreToolUse hook registered in `hooks.json`, listed in the installer, and present in this machine's settings. Orca source adds partial machine-side controls (worker-start scope and the nested-worker depth cap, a narrow Run-binding refusal), which differ by Orca build (depth default 1 in the checkout, 2 in the installed files) and whose effective state on the running Orca is UNVERIFIED (section C.1).

- Current ownership wording (person-opened coordinator, "eligible session" owns the agent) exists only as an uncommitted working-tree change; HEAD and the installed copies still use the old "coordinator under another orchestrator" phrasing.
- Sub-orchestrator mode is deferred and not implemented: no command, skill, flag or contract role exists; #444 is open.

## I. Summary

Sections 1-3 of `WORKER-CONTRACT.md` define a worker run by one runtime fact, a dispatch preamble carrying Task and Dispatch IDs, and bind it to run one command at top level, send lifecycle messages only from that session, never fan out, never act outward, and never give a Ruling. The coordinator is a session the person opened (`WORKER-CONTRACT.md:69`, `HOW-WE-WORK.md:400`); `core/CLAUDE.md` adds that the creating session owns a worktree's agent and that a hook blocks worktree creation without `--agent`. Verification found the contract text and its owner-decision references (D1-D5) consistent with the sc-implement Ruling rules and with 31 converted commands and 8 never-as-worker commands, but almost all authority is instruction-level: the only executable IronClaude control is the lexical `--agent` check, nothing in IronClaude code detects a worker run or a coordinator, and Orca's own worker-start, depth-cap and Run-binding controls are build-dependent and unobserved on the running host. The clarified ownership wording is uncommitted and not installed (a managed package records the explicit request and its execution, not acceptance or rollout), and the term "orchestrator" in it has no definition in the contract, so the technical reference must label the sub-orchestrator layer as deferred.
