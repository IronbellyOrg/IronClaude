**`worktree`** (`cmd_worktree`, `:607-720`). Data flow:
1. `git rev-parse --path-format=absolute --git-common-dir` (`git_common_dir`, `:269-273`), then `main_checkout` (`:276-278`). Not in a git checkout gives `W-WORKTREE-CREATE-FAILED`.
2. `orca worktree list --repo path:<main> --limit 500 --json` (`list_rows`, `:296-332`). 3. `lookup` (`:355-393`) matches existing rows by four keys in fixed order: comment marker `sc:issue <repo>#<N>`, record path, basename `^issue-<N>(-|$)`, branch last segment. Archived and main rows are ignored (`:378-380`). Several live hits give `W-WORKTREE-AMBIGUOUS`; no live hit gives `W-WORKTREE-STALE`; exactly one goes to `finish(..., "reused", ...)`.
4. No match: `git fetch origin` (a failure is only a `W-ORIGIN-BASE-STALE` note, `:660-664`), `git rev-parse --verify <base>` (missing gives `W-ORIGIN-BASE-MISSING` and no create, `:654-659`), then the create at `:666-682`:
   `orca worktree create --repo path:<main> --name issue-<N> --base-branch <base> --no-parent --comment "sc:issue <repo>#<N>" --json`.
   **There is no `--agent` and no `--prompt` flag** [CODE-VERIFIED `:666-682`; docstring `:28-29` "no link flag, no agent flag"; test `test_fo18_exact_commands_and_no_forbidden_flag`, `tests/skills/test_issue_orca_worktree.py:837`].

## Summary

The two launchers are ordinary-session launchers: `orca_worktree.py` (claim flow, run by Bash from a skill) creates an agent-less Orca worktree (an accepted exception recorded by the owner on 2026-11-08), closes the plain first tab, writes a one-time pending record, and runs `orca agent launch` with a marked prompt after a read-only enforcement preflight; `launch.py` (watcher, run from `issue-watch once`) runs one fixed 12-element `orca agent launch ... /sc:issue --claim <n>` in a configured checkout after fork-origin and budget checks.
