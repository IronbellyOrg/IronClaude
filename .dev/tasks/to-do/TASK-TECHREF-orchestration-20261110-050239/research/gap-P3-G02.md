## Step 1. Command-word match, read from the code

### 1.1 `require-orca-worktree-agent.sh` (the PreToolUse hook, 359 lines)

- The command word is accepted by one test: `if (b == "orca" || b ~ /^\$/) { isorca[o] = 1; ... }` at `src/superclaude/hooks/scripts/require-orca-worktree-agent.sh:145`. [CODE-VERIFIED]
- `b` is `base(w)` (`:141`), and `base` (`:86`) is the text after the last `/` of the word, after the scanner has removed quotes and escapes. So `orca`, `/usr/local/bin/orca`, `"orca"` and `'orca'` all give `b == "orca"`. `orca-ide`, `orca-dev`, `orca.cmd`, `ccsession-orca` and `Orca`/`ORCA` (case-sensitive compare) do not. A word ending in `/` gives an empty `b`. [CODE-VERIFIED]
- Wrappers are skipped by basename: `iswrap` (`:82-85`) lists `env sudo nice nohup time exec timeout command coproc`; `endword` sets `wrap[o] = b` (`:142`) and then reads the next non-option word as the command word. So `env X=1 orca-ide ...`, `sudo orca-ide ...`, `command orca-ide ...` are decided on the word after the wrapper, which is still `orca-ide`, so they pass. Variable assignments before the command word are skipped (`:119`). [CODE-VERIFIED]
- A command word that starts with `$` (`$ORCA`, `${ORCA:-orca}`, `$(printf orca)`; a substitution is recorded as the text `$()` by `addc(o, "$()")` at `:178,183`) is treated as a possible orca (`:145`, comment `:48-51`). This is a conservative guess, not a name match: `$ORCA worktree create --name x` is blocked whatever `ORCA` holds. The hook never sees the variable's value. [CODE-VERIFIED]
- After the command word is accepted, `track` (`:94-98`) records the first two non-option words (`a1`, `a2`), `--agent`/`--agent=*` (`hasagent`) and `--help`/`-h` (`hashelp`); `fin` (`:99-103`) prints `orca` only when `a1 == "worktree"`, `a2 == "create"`, no agent flag and no help flag. For any other command word `isorca[o]` stays 0 and `fin` returns at once (`:100`). [CODE-VERIFIED]
- Symlinks and aliases: the scanner is purely lexical and never touches the file system. A link named `orca` pointing at anything is matched; a link named `o` pointing at the real `orca-ide` is not. [CODE-VERIFIED by reading; probe P21 below confirms the second case.]
- The hook's own header lists the known ceilings (`:39-61`): `bash -c`/`sh -c`/`eval`/`env -S`/`ssh` strings, `xargs orca`, `find -exec orca`, heredoc piped to a shell, a command word built from pieces, global options with a separate value before `worktree`, wrapper options not in the tables, tools other than Bash, no `jq`/`awk`, `claude --bare`, humans, and scripts that call Orca as a subprocess. **Alternate binary names are not on that list.** `orca-ide`, `orca-dev` and `orca.cmd` are never mentioned in the header, the block message (`:351-357`) or `tests/hooks/test_require_orca_worktree_agent.py` (grep of `tests/hooks` for `orca-ide|orca-dev|orca\.cmd` found no match). [CODE-VERIFIED, negative evidence: searched `src/superclaude/hooks/scripts/require-orca-worktree-agent.sh` and `tests/hooks/`]
- The block message itself also says `Supervised workers use \`orca orchestration worker-start\`` (`:356`), always in the bare-name form, whatever name the blocked command used. [CODE-VERIFIED]

### 1.2 `launch-level-guard.sh` (the launch-level guard, 747 lines)

- The guard has no command-position logic for Orca. The classifier block normalises the command into `T`/`W` (`:431-437`), splits `W` into segments on `newline ; & | ( )`, and for **every word in every segment** takes `b=${w##*/}` (`:450`) and runs `case $b in ... orca) ...` (`:455-479`). [CODE-VERIFIED]
- `orca)` is an exact-match arm (`:458`). `ccsession* | tmux | screen | xdotool | ydotool)` is the arm above it (`:457`); `ccsession*` is a prefix glob, so `ccsession-orca` and `ccsession-tag` are ESCAPE. `orca-ide`, `orca-dev`, `orca.cmd` match no arm, so they add no class. [CODE-VERIFIED]
- For an `orca` word the guard reads the next two non-option words (`:460-473`; `--version` counts as the first). Allowlist (no class): `status *`, `help *`, `--version *`, `worktree current|list|show`, `terminal list|show|read`, `orchestration check|inbox|run-current|task-list|worker-show` (`:475-476`). Everything else adds ESCAPE unless the last word of the segment is `--help`/`-h` (`:477`). So with the bare name, `worktree create` (any form, even with `--agent`), `agent launch`, `terminal send`, `orchestration worker-start` etc. are ESCAPE. [CODE-VERIFIED]
- ESCAPE is denied at every launch level: `ESCAPE:W | ESCAPE:WA | ESCAPE:F | ESCAPE:FS) ll_deny LL-ESCAPE` (`:737`), message text at `:86-89` names "claude, ccsession, orca, SendMessage, /sc:issue ..." (the word `orca` only). [CODE-VERIFIED]
- Because the arm is matched on any word, wrappers do not matter for the guard: `bash -c "orca ..."` (quotes are deleted at `:431`), `env`, `sudo`, `xargs`, `find -exec` all still expose an `orca` word. This is the opposite of the hook, which stops at the first command word. The same property over-blocks: `echo orca` has an `orca` word with no sub-command, so it falls to the `*)` arm and is ESCAPE (probe P22). [CODE-VERIFIED by reading; probe P22 confirms]
- `$ORCA worktree create`: `W` keeps `$` (`:435`), so the word is `$ORCA`, whose basename is `$ORCA`, not `orca`: the guard does **not** treat a `$`-led word as a possible orca (the hook does). [CODE-VERIFIED by reading; probe P18 confirms]
- Case: the lower-casing is applied to `G` only (`:433`); the arm tests `b` from `W`, which keeps case. `ORCA` and `Orca` do not match. [CODE-VERIFIED]
- Scope: the guard applies only to a session with a binding file `$HOME/.claude/state/launch-level/sessions/<session_id>` (`:20-23,257-273`); any other session exits 0 (`:394`). Registration: PreToolUse matcher `^(Bash|Skill|Agent|...)$` (`src/superclaude/hooks/hooks.json:116`). The hook is registered on matcher `Bash` with timeout 3 (`hooks.json:106-111`). [CODE-VERIFIED]

### 2.3 What the probes establish

1. **The hook** blocks a bare `worktree create` only when the command word's basename is exactly `orca`, or the word begins with `$`. P02 to P06, P08, P11 to P15, P17, P21 are the same bare create (or a worker-start) under another name and all return 0. [CODE-VERIFIED]
2. **The guard** (inside a bound session, at every level; levels W and FS gave identical results on all 29 rows) classifies ESCAPE only for a word whose basename is exactly `orca` (plus the `ccsession*`, `tmux`, `screen`, `xdotool`, `ydotool` arms). Every `orca-ide`/`orca-dev`/`orca.cmd` row returns 0, including `agent launch` (P28), `terminal send` (P24) and `orchestration worker-start` (P06). [CODE-VERIFIED]
3. The two scripts are **not symmetric**: the hook catches `$ORCA ...` (P18, P19) and the guard does not; the guard catches `bash -c "orca ..."` (P16), `xargs orca ...` (P23) and `echo orca` (P22) and the hook does not. [CODE-VERIFIED]
4. Neither script reads the name through to what the file really is. On this host `orca` (a dispatcher script) and `orca-ide` reach the same launcher (see Step 3.2), so a session that types `orca-ide` is doing exactly what the scripts were written to stop. [CODE-VERIFIED for the host files; the effect on behaviour is by reading, not by a live run]
5. Not probed and why: nested-backtick `\` form (unchanged from `research/03-guards.md` GAP-3); `jq`/`awk` missing branches (covered by existing tests); any run of a real Orca CLI (forbidden by the brief).
