#### F2.1 Where `sc-launch-v1-...` comes from: `ccsession --auto-name` (`:635-680`, dispatched `:694-700`)

- Called by `ccsession-orca:228` with the launch prompt as its argument. Output label = `<folder>[-<up to 4 words>]-<stamp>` (`:659-662`).
- `folder`: basename of `pwd -P`, non-alphanumerics become `-`, runs squeezed, cut to 20 characters (`:646-649`).
- `words`: first 400 bytes of the task text, every non-alphanumeric to a space, lowercased, first 4 words, each cut to 12 characters, joined by `-` (`:650-651`). The claim prompt `[sc-launch:v1:<32 hex>] Read ...` yields the words `sc`, `launch`, `v1`, and the first 12 hex digits of the nonce. The nonce is `secrets.token_hex(16)`, 32 hex digits (`orca_worktree.py:1091`), so the 12-character cut is why the regex allows `{1,12}`.
- `stamp`: `date +%m%d-%H%M%S` plus `-` plus `printf '%04x' $((RANDOM % 65536))` (`:657`); `CCSESSION_AUTO_NAME_STAMP` replaces it, read as text, cut to 24 characters, non-`[A-Za-z0-9-]` to `-` (`:654-656`; test hook).
- `prefix` is cut to 59 characters and a trailing `-` removed (`:660-661`). With a 20-character folder the prefix is at most 20+1+13+12 = 46 characters, so the stamp is never cut for the claim prompt.
- If the repo's name list already holds that label, `-2`, `-3`... is appended (up to 99) (`:671-676`); if the list directory cannot be created or written, `return 1` with no output (`:668-670`), and `ccsession-orca:228` falls back to an empty name (untagged launch).
- Final guard: `validate_label` must pass, else `session-<stamp>` (`:678`).
- Result: `<folder>-sc-launch-v1-<12 hex>-<MMDD>-<HHMMSS>-<4 hex>[-n]`. This is exactly what `SHIM_TITLE = sc-launch-v1-[0-9a-f]{1,12}-\d{4}-\d{6}-[0-9a-f]{4}\b` searches for (`orca_worktree.py:779`; it uses `.search`, so the folder prefix in front is fine) [CODE-VERIFIED by reading both sides; whether this exact string survives into Orca's `terminal show` title is F6].

#### F4.3 What happens when the check fails (advisory, not blocking)

- `cmd_launch` appends `("W-LAUNCH-NOT-CCSESSION", "the agent's screen showed no ccsession text")` when a handle exists but the check failed, or `"the launch result named no terminal"` when no handle was found (`:1377-1386`). The check is skipped entirely when there is no handle (`handle is None or ...`, `:1378`).
- Nothing in `cmd_launch` closes, stops or rewrites the agent. The only `orca terminal close` call in the file closes the empty first tab after a worktree create (`:601`, and `:35` in the docstring). So the agent keeps running.
- The `launch` entry is still written, so a re-run returns `already_launched` (`:1389`; pinned by `test_la4_launch_entry_is_written_even_when_the_shim_check_fails`, `tests/skills/test_issue_orca_worktree.py:1491-1509`).

## Key takeaways

1. The tab title the claim looks for is produced by ccsession, in two places that agree: `ccsession --auto-name` makes the label from the launch prompt's first four words (`sc`, `launch`, `v1`, the first 12 of the 32 nonce digits) plus a `MMDD-HHMMSS-xxxx` stamp (`ccsession:635-680`), and the label is shown as `<label> · Claude Code` both by an OSC title escape at launch (`ccsession:1875`) and by `orca terminal rename` from the SessionStart hook (`ccsession:537`, `session-name.sh:196-203`). `orca_worktree.py` then matches the label with `SHIM_TITLE` (`:779`). Feeds template 8.2 (integration points: the three `orca terminal` verbs, the `orca agent launch` argument, the three hook events and their 5 s timeouts) and 4.1 (flow F9).
