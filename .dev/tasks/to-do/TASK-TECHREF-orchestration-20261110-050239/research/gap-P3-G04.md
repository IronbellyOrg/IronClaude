## 7. Key takeaways

1. **One authored schema, no code behind it.** The worker contract's key list and four-value `worker_status` enum exist only as prose in `WORKER-CONTRACT.md:32-39`; five producer files repeat the field list in YAML, table or prose form (3.1); the other converted commands carry only a `Contract.` bullet that fixes `report_path`, the `artifacts` rule and the status mapping. No executable under `src/` writes, parses or routes on `worker_contract_version`, `worker_status` or `blocked_question` (4.4, two searches, zero non-markdown hits). [CODE-VERIFIED negative]
2. **Writer = the LLM that did the work; reader = the coordinator LLM.** The result channel is: command `## Unattended mode` section -> skill steps -> LLM writes `<report-dir>/return-contract.yaml` -> worker LLM maps `worker_status` to `worker_done --outcome` and passes the path (`:59, :39`) -> Orca carries `--report-path` without checking the file -> coordinator LLM opens and admits it (`:93, :237-246`). Steps 8-9 of the flow in section 2 are normative text; the coordinator-reads step has no code. The designed fallback for a missing or malformed file is `--outcome failed` and "any other `worker_status` value is treated as `failed`" (`:59`).
3. **Four layouts of the same contract file** (corrected in fix cycle 1; the first version said three). (a) Worker fields merged into the command's own contract (brainstorm/reflect with `--output`; impact/graph with `--output-dir`; also cli-portify, release-split, auggie-review); (b) a separate worker file that lists the command's own contract in `artifacts` (adversarial, workflow, and brainstorm/reflect with `--report-dir`); (c) a full contract, existing fields plus worker fields, written to `<report-dir>` (impact with `--report-dir`, `artifacts` = `impact.md` and the own contract; graph with `--report-dir`, `artifacts: []`); (d) a worker-only file (the rest). The contract names only (a) and (b), and only for brainstorm/reflect (`:35`).
4. **Package contract and worker contract are different files with different vocabularies.** `<pkg>/return-contract.yaml` (contract 1.1, `status: success | partial | failed`) is read by code (`archive_workspace.py:325-334`); `<report-dir>/return-contract.yaml` (`worker_status: succeeded | partial | failed [| blocked]`) is read by no code. Research/01:31 and research/06:118 describe the package contract of an archived plan; do not conflate them in the reference.
5. **The tests are static text pins.** WC-4's field list, enum, `artifacts` exclusion rule, the four-pair status mapping, the exact missing-directory error and the WC-5 outcome rule are pinned in `RULE_PHRASES`; 31 per-command sections are pinned for `return-contract.yaml`, the contract path, `--report-dir`, nested directories, selected gate sentences and the `paths git ignores are left out (WC-4)` clause. Nothing parses a produced contract.
6. **`/sc:implement` has no worker-contract producer** (converted in a later phase, "P4" in the test file) although contract text at `:33, :243, :250` speaks of an implement contract. Forward-looking text, not shipped behavior.

The worker result channel is a text protocol end to end. `WORKER-CONTRACT.md:32-39` defines the seven keys and the four-value `worker_status`, each command's `## Unattended mode` section (31 of 31) fixes where the file lands and what `report_path`, `artifacts` and the status mapping mean for that command, and the command's skill has the LLM write `<report-dir>/return-contract.yaml` on every outcome in one of four layouts. The worker LLM maps `worker_status` to `worker_done --outcome` and passes the path, Orca does not check the file, and the coordinator LLM opens it and admits or rejects the result; none of those steps is code, and two searches found no executable in `src/` that reads or writes the worker fields. The only code that touches nearby contracts is the reflect wrapper (which ignores unknown keys), the workflow-package archive check and the swarm and cli-portify pipelines, all for their own contracts. The tests are static pins of instruction text and parse no produced file, and `/sc:implement` has no producer although the contract text speaks of one.
