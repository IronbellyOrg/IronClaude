### 12.3 Anti-Patterns (Things to Avoid)

| Anti-Pattern | Why It's Wrong | Do This Instead |
|---|---|---|
| Recognising the Orca CLI by one literal name (`b == "orca"`, case `orca)`) | Both scripts miss `orca-ide`, `orca-dev`, `orca.cmd` and renamed links; on Linux `orca-ide` is the installed name, and on the research host `orca` and `orca-ide` run the same program. For the launch-level guard this is the recorded DEFECT (14.2 TD1); for the worktree gate it is a documented ceiling. [CODE-VERIFIED, probes re-run 2026-11-12, 15.2 step 5] | Match the set of names the product uses and state the remaining limit (obfuscated or built names) in the header and the design; follow the remediation plan. |
| Treating the `hooks.json` array order as an execution order | DOCUMENTED: matching hooks run in parallel, completion order is non-deterministic, and every matching hook runs to completion (https://code.claude.com/docs/en/hooks; hooks guide "Limitations"). | Make each hook independent; do not rely on one hook running first or on a sibling's `deny` stopping another. |
| Two hooks rewriting the same call's input | DOCUMENTED: rewrites are neither merged nor ordered (hooks guide, "Limitations"). Only `launch-job-identity.sh` rewrites Bash input here. | Keep one rewriting hook per tool; a new Bash hook returns decisions only. |
| Writing "fail-closed for governed sessions" without a qualifier | A hook stopped at its timeout lets the call go ahead (design row `docs/designs/sc-issue-launch-level-hook.md:216`, residual risk R2 `:440`; DOCUMENTED for `command` hooks without `onFailure`, web-01 Q1); identity loss and ungoverned sessions also allow. | Write "fail-closed on the script's own failure paths, except when the hook is stopped at its timeout, identity is lost, or the session is not governed". |
| Blocking with exit 1 | DOCUMENTED: a non-blocking error unless stdout is schema-valid JSON that decides. | Block with exit 2 and a stderr message. |
| Quoting the ownership wording as installed or merged | The new wording is an uncommitted edit set; HEAD, `origin/master` and the research host's installed copies carry the old "coordinator under another orchestrator" text (research/06 F5, F6). | Say "uncommitted at the time of writing" and re-read `git status` first. |
| Treating the Orca checkout as the installed or running build | Depth default is 1 in `dc57b3d6e` and 2 in the installed files; `worktree ps --agent-wait` exists only in the installed files; the running setting is UNVERIFIED. | Report both with provenance; never write "Orca refuses a worker's helper start" without scoping it. |
| Reading heartbeat age or `unverifiable` as an Orca stall verdict | Orca derives no verdict from `last_heartbeat_at` on the live surface; `unverifiable` means no fresh positive evidence; `finished_unverified` has no production writer (gap-P3-G01 S3, S4). | Apply the contract's S-table and ladder as IronClaude policy over raw evidence. |
| Using `worker-start --retry-of` in the coordinator flow | Orca's circuit-breaker refusal runs only on a `--retry-of` start, so WC-6's own flow is never guarded by it; only the coordinator's three-failed-starts comparison guards (research/02 section 2). | Create a new Task per retry (WC-6) and make the comparison. |
| Putting a `src/superclaude/` path, an Orca command name or a hand-written nested directory in an `## Unattended mode` section | The section checker fails on each (`tests/skills/test_worker_contract.py:869-886`); installed primitives run where `src/` does not exist. | Name installed paths (`~/.claude/...`) and use the contract's wording. |
| Editing `.claude/` mirrors or using `git add -f` on them | `.claude/` is gitignored sync output; doubling diffs breaks `make verify-sync`. | Edit `src/superclaude/`, `make sync-dev`, stage the `src/` side only. |
| Relabelling a shipped-but-unwired capability as a gap, future phase or question | Rule C8 (`BUILD-REQUEST.md:54`) needs a cited scope decision. | Record a DEFECT and link a remediation task (14.2). |
| Calling the sub-orchestrator layer shipped, or "orchestrator" a role | No command, skill, flag or contract role exists; `WORKER-CONTRACT.md` has no orchestrator role; #444 is OPEN. | Say "deferred"; keep the future-role question open. |

## 16. Glossary

| Term | Definition |
|---|---|
| Supervised orchestration | An Orca coordinator session, opened by a person, runs IronClaude `/sc:` commands as workers through `orca orchestration` Tasks and `worker-start`, under the rules of `WORKER-CONTRACT.md`. "Supervised" has no definition of its own in the contract; its operational meaning is dispatch through `worker-start` with a preamble (research/01 B.1). |
| Coordinator | The session that plans, creates Tasks, starts workers, reads reports and performs every outward action; "an Orca coordinator session the person opened" (`WORKER-CONTRACT.md:69`). Never a session Orca started as a worker (`HOW-WE-WORK.md:400`). Nothing in code detects the role. |
| Worker run / worker session | A top-level session that received an Orca preamble carrying a Task ID and a Dispatch ID; only it sends lifecycle messages (`WORKER-CONTRACT.md:11`). Identified by prompt text, not by code. |
| Ordinary session (contract sense) | Any session that is not a worker run, the person-opened coordinator included: the contract's complement of "worker run" (`WORKER-CONTRACT.md:11`). Not the guard's notion; see "Ungoverned session". |
| Non-worker session | Shorthand in this reference for a session that is not a worker run, for example the agents the claim script and the issue watcher launch. |
| Governed session | A session bound by the launch-level guard through the claim script's launch marker; every other session is ungoverned. A different identity system from "worker run" (research/01 B.1). |
| Ungoverned session (guard sense) | A session with no launch-marker binding in the guard's store; the guard allows all its calls, and also allows a call whose `session_id` is missing. The person-opened coordinator, a supervised worker and a watcher-started session are ungoverned. |
| Person-opened | The coordinator eligibility rule: a procedural fact, not a runtime property. |
| Eligible session | Undefined in the distributed guidance; only the negative reading (a supervised worker is not eligible) is stated (L16). |
| Orchestrator | Used once in the ownership paragraph (`core/CLAUDE.md:58`); no orchestrator role exists in the contract or code (L16). |
| Sub-orchestrator / subordinate mode | A proposed layer between the coordinator and workers. Deferred, not implemented, not shipped; #444 is OPEN. Not the same as Orca's federated own-Run preamble text (research/05 5.3). |
| Subagent | A command's Agent-tool fan-out inside a session. Not a role; may not send lifecycle messages or call Orca (WC-7). Hook payloads inside a subagent carry `agent_id` and `agent_type` (DOCUMENTED). |
| Task, Dispatch, Run | Orca records: a Task is a unit of work; a Dispatch is one attempt to run a Task by a worker; a Run groups Tasks under a coordinator. A retry is a new Task under WC-6. |
| Preamble | The text Orca types into a dispatched worker: identity lines, `worker_done`, `heartbeat`, `ask`, `check` commands and, when depth allows, a SUB-DISPATCH section. Built by `buildDispatchPreamble`; the contract defers to it for verb syntax and cadence (`WORKER-CONTRACT.md:7`). |

| Heartbeat | A periodic liveness message at the cadence the preamble sets (default 5 minutes, range 1-60, may be off); never a stall proof (WC-10). |
| `ask` / `check` / `--wait` / `--ack` | `ask` blocks until the coordinator replies (preamble timeout 600000 ms, resume by message ID); `check` pulls messages; `--wait --types ...` is the coordinator's blocking wait; `--ack` acknowledges a batch (an unacked batch replays). |
| Brief | The text of a Task spec: Guard line, Chain line, gate policy, local-commit line, report directory, worktree, outward actions, `Command:` lines (`WORKER-CONTRACT.md:283-327`). |
| Brief guard | The worker-side check of each `Command:` line before running it; four refusal cases with a `guard refused:` body. Instruction only; no executable (L10). |
| Never-as-worker list | `/sc:agent`, `/sc:git`, `/sc:help`, `/sc:issue`, `/sc:pm`, `/sc:spawn`, `/sc:swarm-wizard`, and `/sc:pr-submit` while decision D3 keeps it off workers (`WORKER-CONTRACT.md:23`). Advisory (L19). |
