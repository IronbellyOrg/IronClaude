## 8. API & Integration Points

> **Note:** Supervised orchestration has no HTTP API. "API" here means the Orca CLI verbs (and the RPC methods behind them) that IronClaude code calls or that its normative contract tells a coordinator or worker to call. IronClaude itself defines no Orca verb: no Python launcher calls `worker-start`, `dispatch`, `task-create` or any `orchestration` verb (`research/04-launchers.md` F1 and F2, grep of `src/superclaude` re-run in fix cycle 1: `worker-start` occurs only in four documentation or message files). #### 10.1b Launch-level guard messages and decision order

Classes are checked in this order and the first blocked class supplies the message: `BIG TAMPER MERGE GHWRITE PROTECTED ESCAPE MCP UNKNOWN SUBMIT REPO PUSH PUSHFORM COMMIT TURN IMPL SKILL` (`launch-level-guard.sh:722`, re-read). Message ids: `LL-BIG`, `LL-TAMPER`, `LL-MERGE`, `LL-GH-WRITE`, `LL-PROTECTED`, `LL-ESCAPE`, `LL-MCP`, `LL-UNKNOWN`, `LL-SUBMIT`, `LL-REPO`, `LL-PUSH`, `LL-PUSH-FORM`, `LL-COMMIT`, `LL-TURN`, `LL-IMPL`, `LL-SKILL`, plus `LL-BROKEN` and `LL-NOBIND` for internal failures; `LL-STATE` and `LL-TEXT` are notes appended to a block (`:724-747`, re-read). Levels: `W` worktree, `WA` worktree approved, `F` full, `FS` full-submit. **Approval.** The record `sessions/<sid>` holds the level word the claim script chose. An approval exists only at level `W`: when the prompt, trimmed and lower-cased, is exactly `approved`, `approved.` or `approved!`, or its first line starts with `/sc:implement`, `/sc:task` or `/task` as a whole word, the guard creates the file `sessions/<sid>.ok` (`launch-level-guard.sh:341-363`), and a `.ok` file beside a `W` record makes the level `WA` (`:270-272`). The approval lasts until a person deletes the session's files (`:364`); at `F` and `FS` no approval is read. Which classes block at which level is in the table below.
