# Implement Fix B Merged Refactor of `integration_contracts.py` (Mechanism-Signature + 3-Layer Coverage)

## Task Overview

This task implements the merged Fix B refactor of `src/superclaude/cli/roadmap/integration_contracts.py` as specified verbatim in the adversarial merged-output.md (confidence 0.88). The refactor closes a false-positive class in the anti-instinct gate where LLM-generated roadmaps trigger `uncovered_contracts` failures because the extractor over-captures bare "dispatch" mentions, dedup is per-evidence-line rather than per-mechanism, and coverage requires literal mechanism-term substrings that valid roadmaps may not contain. The fix unifies three patches into one coherent refactor by introducing a `mechanism_signature` field — a normalized `(mechanism_kind, identifier_set)` tuple — that routes both deduplication and coverage matching through the same semantic abstraction.

Four sub-changes land together in a single module edit plus a test class addition: (§2.1) add `mechanism_signature: tuple[str, frozenset[str]]` field to `IntegrationContract` with a default that preserves backward-compat for direct constructors; (§2.2) tighten `DISPATCH_PATTERNS[0]` to drop bare `DISPATCH`, add explicit `DISPATCH_TABLE` for reviewer clarity, and add a compound-noun arm (`class-priority|priority|named-theme|role-keyed|theme|severity-keyed|module-tier|subprocess|gRPC` + `[\s_-]?dispatch`); (§2.3) replace per-evidence-line dedup in `extract_integration_contracts` with signature-based dedup via a new `_signature_subsumed` helper, computing `idents = frozenset(_extract_identifiers(context))` from the 3-line context window; (§2.4) broaden the FR-MOD2.7 fallback into three layers — Layer 1 dispatch_family regex, Layer 2 existing literal-term + 3-line-window check (with `populate` added to `impl_verbs`), and Layer 3 NEW generic stem-fallback constrained by identifier-overlap against `contract.mechanism_signature[1]`. Test verification: 7 new pytest tests (t1-t7) in a new `TestHubDispatchRegression` class authored in `tests/roadmap/test_integration_contracts.py`, with 2 synthetic module-level fixtures (`TUIBBS_HUB_SPEC`, `TUIBBS_HUB_ROADMAP`) authored per Option A from research file 04-gap-fill.md §3. All 22 existing tests in `test_integration_contracts.py` plus the `TestSC001RegressionBlocks` class in `test_anti_instinct_integration.py` MUST remain green. A live re-run against `/config/workspace/TUIBBS-scp/.dev/releases/current/v1-MVP/epics.md` + `roadmap.md` (BEFORE the Fix A workaround is reverted) confirms the end-to-end behavioral target `uncovered_contracts == 0`. ### RQ-1: TUIBBS_HUB_SPEC fixture identifier-content shape — Option A (synthetic fixture) adopted

**Background.** Research file `04-gap-fill.md` §3 surfaced a CRITICAL engineering finding: applying `_extract_identifiers` to verbatim 3-line context windows around TUIBBS-scp epics.md hub-dispatch evidence lines (lines 200, 430, 1031) yields heterogeneous identifier sets — `{ADR, WAL, MCP, ACS, NFR, S10}` for IC-005, the empty set for IC-008, `{PresenceUpdates}` for IC-011. Because `_signature_subsumed` requires subset+overlap to dedup non-empty sets and `(mechanism, ∅)` falls back to exact-match dedup, verbatim TUIBBS-scp content yields 3 surviving hub-dispatch contracts (not 1 as merged-output.md §3 t1 asserts). The gate STILL passes via Layer 1 dispatch_family on roadmap.md:392 (`uncovered_count == 0`), but t1's `len(hub_contracts) == 1` assertion would fail.

**Decision: Option A (Fixture-Engineered).** Author `TUIBBS_HUB_SPEC` as a 30-40 line synthetic fixture that reuses TUIBBS-scp prose phrasing but adds at least one shared UPPER_SNAKE_CASE identifier (`FR-S10-02`) in every hub-dispatch context window so subsumption fires deterministically. The shared identifier set across all windows must have at least one element so subsumption fires regardless of asymmetric additions in any single window.
