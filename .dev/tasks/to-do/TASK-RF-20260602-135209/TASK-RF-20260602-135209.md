# Implement 8 Low-Complexity Serena Adoptions (FR-RV3-LOW.1–8) into sc-reflect-protocol

## Task Overview

This task implements the 8 low-complexity Serena feature adoptions (FR-RV3-LOW.1 through FR-RV3-LOW.8) specified in `.dev/releases/current/Reflect-V3-Serena/04-spec-low-complexity.md` into the `sc-reflect-protocol` skill. The work is **additive and fail-open**: it extends the SKILL.md frontmatter `allowed-tools`, the §4.0 Wave-0 calibration steps, the §6.1 mandatory evidence chain, the §6.3 memory-retention rule, the inline §9.1 return contract and §9.2 telemetry block, plus mirror edits in three `refs/*.md` files and the §10.2/§10.3 deviation taxonomy. It additionally scaffolds **6 new eval-workspace case directories** (input fixtures + `expected.yaml` + an `evals.json` assertion object per case) as first-class deliverables, and encodes **OQ runtime-probe precondition items** that gate the version-sensitive and corrected flows.

The change closes three concrete grounding-chain gaps: (1) the Wave 1A §6.1 chain cannot enumerate polymorphic/external surfaces (no `find_implementations`/`find_declaration`); (2) Wave 0 never reads Serena's own active context/modes/version (a calibration blind spot); (3) the §6.3 retention rule is specified-but-unimplemented (`write_memory` grows unbounded). Two adoptions CORRECT upstream-Serena drift and MUST be implemented in their corrected form, never as named: `check_onboarding_performed` was DELETED in Serena v1.5.0 (FR-6 derives the signal via `activate_project` message parse + `list_memories` proxy), and `find_referencing_code_snippets` was absorbed into `find_referencing_symbols(include_info=True)` (FR-3, gated on the OQ-1 runtime probe).

This is a **read-only-with-respect-to-source** change: sc:reflect does NOT mutate project source code, config, or tests. The only mutating Serena tools wired (`delete_memory`/`rename_memory`/`edit_memory`) operate on **Serena memory blobs**, not project source — those are in scope. Project-mutating symbolic-editing tools (`replace_symbol_body`, `insert_*_symbol`, `rename_symbol`, `replace_content`, etc.) are explicitly OUT of scope and belong to the Tier 3 remediation chain.
