# PRD pipeline: halt-on-hard-failure + typed missing-artifact guard (defense-in-depth)

## Task Overview

The `superclaude prd run` PRD pipeline currently dies with a raw Python traceback (`FileNotFoundError: .../scope-discovery-raw.md`) instead of halting gracefully whenever an upstream hard step failure occurs. Two coupled defects produce this. **(A) Halt-gate conflation:** when `scope-discovery` hard-ERRORs (its subprocess exits non-zero and therefore writes no artifact), the Stage-A loop does NOT halt, because the halt decision keys off the downstream *gate enforcement tier* (`scope-discovery` is `STANDARD`, not `STRICT`) rather than off whether the step actually crashed. **(B) Unguarded required-artifact read:** the next step, `research-notes`, builds its prompt by unconditionally reading the missing `scope-discovery-raw.md` inside `_build_prompt`, which runs *outside* any try/except, so the exception escapes `executor.run()` (try/finally, no except) and crashes the CLI.

This task applies the defense-in-depth fix as **two ordered atoms**. **Atom 1 (executor halt-on-hard-failure)** adds an `is_hard_failure` predicate to `PrdStepStatus` and changes the Stage-A halt condition to fire on any hard execution failure (ERROR/TIMEOUT/QA_FAIL_EXHAUSTED/HALT) regardless of gate tier, OR a STRICT-gate failure (preserving existing STRICT semantics). Atom 1 alone is sufficient to prevent the reported crash and is independently revertable. **Atom 2 (typed missing-artifact guard)** adds a `MissingArtifactError(FileNotFoundError)` plus two required-read helpers (`_read_required` for str sites, `_load_json_required` for dict sites) in `prompts.py`, converts the five REQUIRED Stage-A reads, and wraps the `_build_prompt` call site at `executor.py:672` in a `try/except MissingArtifactError` that returns a `HALT` step result with a clear reason. **Atom 2 depends on Atom 1** — the `HALT` it raises only breaks the Stage-A loop once Atom 1's `is_hard_failure` includes `HALT`. Therefore Atom 1's phase MUST complete before Atom 2's phase begins.

All source-of-truth edits go in `src/superclaude/cli/prd/`. Because the repo convention runs sync verification regardless of whether the edited code is package code, after the code edits the task runs `make sync-dev`, `make verify-sync`, and `make lint`, then the prd test suite via `uv run pytest`. All Python operations use UV.
