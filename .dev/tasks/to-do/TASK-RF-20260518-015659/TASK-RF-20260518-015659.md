# Sprint Runner Deterministic Fixes — C1 Watchdog Split + C2 Per-Task Output Collision + C3 Timeout Reconciliation + C4 phase_start JSONL

## Task Overview

This task lands four deterministic sprint-runner fixes — C1, C2, C3, C4 — that surfaced in the audit of `superclaude sprint run .dev/releases/current/task-builder-merge/tasklist-index.md` where six phases ran 74–153 minutes each while their underlying API time per phase was only 3–5 minutes. The four fixes target independent code surfaces: (C1) the watchdog at `executor.py:1365-1404` is split into a startup-stall guard and a mid-stall guard, and the `SprintConfig.stall_timeout` default is reconsidered alongside a new `startup_stall_timeout` field; (C2) the per-task output-file collision in `_run_task_subprocess` (`executor.py:1086-1115`), which writes every per-task subprocess to the same `phase-N-output.txt` truncating predecessors, is eliminated by introducing `SprintConfig.task_output_file(phase, task)` and `task_error_file(phase, task)` helpers in `models.py`; (C3) the divergent timeout formula at `executor.py:86` (`max_turns * 60`) is reconciled to the canonical `max_turns * 120 + 300` already used at `executor.py:1106` and `sprint/process.py:115`; (C4) the missing `phase_start` JSONL event in the per-task branch (`executor.py:1262-1300`) — where `logger.write_phase_start` is never called — is fixed by adding a single emit call so that live production sprints emit `phase_start` for every phase.

Each fix has unit + integration tests added in `tests/sprint/` and `tests/pipeline/`, an rf-qa task-integrity gate runs after each fix cluster, and a final rf-qa-qualitative gate runs before completion. The branch is `feat/hook-sync-and-matcher-fix`, which is currently dirty with hook-config work — this task does NOT touch `src/superclaude/hooks/`. C5 (`--no-session-persistence` removal) and C6 (axis-fan-out prompt injection) are deferred to follow-up tasks; they are documented in the Follow-Up Items section.

## Key Objectives

The following objectives MUST be achieved by this task:

1. **C1 — Watchdog split + stall_timeout default reconsideration:** Introduce a new `SprintConfig.startup_stall_timeout: int = 300` field (with `0 = disabled` sentinel) and split the watchdog branch at `executor.py:1365-1404` into a startup-stall guard (fires when `ms.events_received == 0` AND `ms.stall_seconds > config.startup_stall_timeout`) and a mid-stall guard (the existing branch, gated on `ms.events_received > 0`). `stall_timeout` keeps its current `0` default and is documented as the mid-stall knob. `stall_action` keeps its `"warn"` default; `"kill"` is documented as the production-recommended value (Open Question Q1).
2. **C2 — Per-task output-file collision elimination:** Add `task_output_file(phase, task)` and `task_error_file(phase, task)` helpers to `SprintConfig` in `models.py:469-476` alongside the existing `output_file()` / `error_file()`. Migrate `_run_task_subprocess` at `executor.py:1086-1115` (specifically lines 1101-1102 and 1112) to use the new helpers. Existing per-phase callers untouched. Path format: `phase-{N}-task-{task_id}-output.txt`.
3. **C3 — Timeout formula reconciliation:** Replace `self._config.max_turns * 60` at `executor.py:86` with `self._config.max_turns * 120 + 300` to match `executor.py:1106` and `sprint/process.py:115`. The remediation method shape is preserved (per Open Question Q3 recommendation); the method has zero production callers per Researcher 3 IP-7, so this is risk-free.
4. **C4 — phase_start JSONL emission in per-task branch:** Add `logger.write_phase_start(phase, started_at)` to the per-task branch at `executor.py:1262-1300`, immediately after `started_at = datetime.now(timezone.utc)` and before the `tui.update` call. The per-phase branch at `executor.py:1328` already calls this and is correct. This addition emits `phase_start` events for every phase regardless of per-task vs per-phase routing.
5. **Tests for every fix:** Unit + integration tests added per `TESTING_REQUIREMENTS` — C1 (`tests/sprint/test_config.py` + `tests/sprint/test_watchdog.py`), C2 (`tests/pipeline/test_process.py` + `tests/sprint/test_executor.py`), C3 (`tests/sprint/test_executor.py`), C4 (extend `tests/sprint/test_regression_gaps.py::TestSprintLoggerPhaseStart`). Existing subprocess-mock and real-subprocess patterns are reused verbatim.
6. **Validation green:** `make lint` ruff-clean, `uv run pytest tests/sprint/ tests/pipeline/ -v` passes, full `make test` passes before completion. No `make sync-dev` / `make verify-sync` because Python CLI source is not under `.claude/{skills,agents,commands}`.
7. **QA gates per phase:** rf-qa task-integrity verifies each fix cluster's outputs before the next is started (max 2 fix-cycle rounds per gate per Retry Monotonicity Protocol). rf-qa-qualitative runs once before final completion.
