# Remediate 2 Regressions + 2 Drift from sprint-recovery POST-reflect audit (c0d56f18)

## Task Overview

A deep `/sc:reflect --mode post` audit of commit `c0d56f18` (the sprint-recovery stranded-deliverables + stale-checkpoint fix, diff `b05e0fe1..HEAD`) independently reproduced four real defects using an executor-disjoint Tier-2 ensemble of three heterogeneous reviewers, with every blocking finding re-verified by the orchestrator via re-Read plus an executable proof-of-concept. The original task TASK-RF-20260608-150011 shipped green tests and a passing inline rf-qa gate, yet two of the defects directly contradict that task's own hard acceptance criteria. The defects survive precisely because the existing tests never exercise the vulnerable code paths.

This task remediates exactly four fixes in the sprint CLI and adds the regression tests that would have caught each defect. FIX-1 (Regression, HIGH) repairs the PRIMARY post-merge checkpoint re-run, whose subprocess argv omits the required `INDEX_PATH` positional so the command exits 2 and the failure is swallowed by `check=False` — meaning PRIMARY re-runs nothing and writes no fresh verdict. FIX-2 (Regression, MED) closes a never-auto-PASS hole where the gate substrings `STATUS: PASS` / `**RESULT**: PASS` can be injected verbatim from tasklist verification prose into a re-stamped UNKNOWN report, causing the gate reader to read it as PASS. FIX-3 (Drift, MED) removes an OR-clause in the deliverable landing-verify that can report a stranding as landed via a stale cwd-resolved declared path even when relocation never reached the canonical destination. FIX-4 (test hardening, MED) adds four missing checkpoint regression tests (BLOCKED-branch, body-only parse, idempotent re-fire, default-off-with-evidence). The original task is HALTed at its Step 8.3 POST-reflect gate and cannot be marked Done until a re-run reflect over this remediation shows 0 regressions.

The following objectives MUST be achieved by this task:

1. **FIX-1 — PRIMARY checkpoint re-run repaired:** Insert `str(config.index_path)` as the `INDEX_PATH` positional in the PRIMARY `rerun-tasks` subprocess argv so the nested command parses (exit 0) and writes a fresh verdict, and surface a warning on a non-zero return code so a failed PRIMARY re-run is never silent.
