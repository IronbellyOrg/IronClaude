# Implement sc:pr-submit PR Review Auto-Remediation Monitor (V1.0)

## Task Overview

This task implements the `sc:pr-submit` feature exactly as specified in the adversarial-merged spec at `/config/workspace/IronClaude/.dev/brainstorms/20260610-234750-pr-review-auto-remediation/merged-spec.md`. The feature automates a PR-review remediation loop: open a PR on the fork → arm an in-session Monitor that polls for the Augment Code GitHub App review → re-grade finding severity through the reused rubric → verify each finding grounds in real code (verify-before-remediate) → dispatch only verified findings to `/sc:troubleshoot` → validate → push → reply → resolve → terminate under a capped, monotonic round counter. The `--monitor {0,1,2,3}` ordinal is a capability ceiling on a SINGLE finite state machine, compared at exactly three gates plus one override, not four divergent code paths.

The implementation is delivered across six components on a hard dependency DAG (spec §3): a new hyphenated skill package `src/superclaude/skills/sc-pr-submit-protocol/` (SKILL.md + 8 refs + 2 bash scripts) that holds the LLM-facing markdown and bash glue; a new importable UNDERSCORED Python package `src/superclaude/pr_submit/` that holds the deterministic core (FSM, severity router, loop-guard, classifier, detection, run-log, recovery, models) the spec's test bodies import and call (`run_skill(...)`, `remap_severity(...)`, `poll_augment_review(...)`, `classify(...)`); a new command `src/superclaude/commands/pr-submit.md`; an edit to the existing hook `src/superclaude/hooks/scripts/offer-pr-review.sh`; a ~115-test suite under `tests/pr_submit/`; and a pyproject.toml pytest-marker registration. Detection of the Augment bot is an UNKNOWN BOUNDARY locked behind an R1 empirical probe — the build BLOCKS (HALTs for an operator) until `detection-contract.md.locked == true`, while all other (internal-pure) work proceeds on synthetic fixtures.

Quality goals (spec §1.2): deterministic termination (loop-guard off-by-one is a P0 defect), zero-regression at `--monitor 0`, autonomy-gate enforcement proven by behavioral tests, fail-safe defaults, NFR-6 core purity (zero `gh`/`git` tokens in fsm/severity_router/loop_guard), and full test coverage (every FR/NFR/AC/INV → a concrete test ID).
