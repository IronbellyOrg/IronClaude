# Fix PR #140 review comments: dedup --spec values + make R5 resume-path WARN fire from persisted SPECS

## Task Overview

This task applies two confirmed, evidence-validated correctness defects diagnosed by `/sc:troubleshoot` Tier 1 against the PR branch `feature/prd-input-spec` (PR #140). Both fixes touch the prd executor module, and three regression tests are added to the prd spec-flag test module.

**Fix 1 (low — review comment r3367342586):** `_bind_specs()` dedups spec parent directories but never the spec paths themselves, so two identical `--spec FILE` arguments produce two duplicate `SPECS` entries — violating the method's own idempotency docstring. The fix adds an order-preserving dedup of `spec_files` before the `SPECS` array is built.

**Fix 2 (medium — review comment r3367342583):** `--spec` is declared only on `prd run`; `prd resume` calls `resolve_config(...)` without `spec=`, so `config.spec_files` is always empty on resume while the bound `SPECS` persist durably in `parsed-request.json`. As a result the R5 scope-discovery degradation WARN gate (and its message) can never fire on the resume path, defeating R5's intent to surface "specs-present + scope-gate-failed regardless of how the run got there." The fix adds a `_bound_spec_paths()` helper that reads the persisted `SPECS` array when `config.spec_files` is empty, and routes both the gate condition and the WARN message through it.

The resolved design choice is to read the persisted `SPECS` (the durable source of truth), NOT to add `--spec` to the resume command. The executor module is canonical Python source (not a `.claude/` mirror), so no `make sync-dev` step applies.

## Key Objectives

The following objectives MUST be achieved by this task:

1. **Fix 1 — dedup spec paths:** `_bind_specs()` produces exactly one `SPECS` entry per unique spec path even when `--spec FILE` is passed more than once, with order preserved and `WHERE` idempotent.
2. **Fix 2 — resume-path WARN fires:** A new `_bound_spec_paths()` helper returns config spec paths when present, else the persisted `SPECS` paths from `parsed-request.json` (fail-closed to `[]` on missing/corrupt JSON); the R5 gate condition and WARN message both route through it so the WARN fires on `prd resume scope-discovery`.
3. **Regression tests added:** Three new tests in the prd spec-flag test module cover dedup, resume-path WARN from persisted SPECS, and `_bound_spec_paths()` fail-closed behavior — matching existing fixture/mock construction patterns.
4. **Validation green:** `make lint` (ruff check) and `uv run ruff format --check src/ tests/` are clean, the targeted spec-flag tests pass, and the full prd suite (`uv run pytest tests/cli/prd/ -v`) passes with no regressions.

```python
    def _bound_spec_paths(self) -> list[str]:
        """Authoritative spec paths for this run: from config, else from the
        persisted SPECS array in parsed-request.json. On `prd resume`, --spec is
        not re-passed, so config.spec_files is empty even though the original run
        bound SPECS; reading the persisted array makes R5 fire on any run path."""
        if self._config.spec_files:
            return list(self._config.spec_files)
        parsed_path = self._config.task_dir / "parsed-request.json"
        try:
            parsed = json.loads(parsed_path.read_text(encoding="utf-8"))
        except (OSError, json.JSONDecodeError):
            return []
        specs = parsed.get("SPECS") or []
        return [s["path"] for s in specs if isinstance(s, dict) and s.get("path")]
```
