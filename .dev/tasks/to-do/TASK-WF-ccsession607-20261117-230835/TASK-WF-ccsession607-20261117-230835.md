# Make the ccsession session list fast (issue 607): Stage 1 in bash, then Stage 2 with a python3 batch helper

Source: ./source.md
Goal: `ccsession --here`, `--here --all`, `--list` and `--ask` build the saved-session list with a number of process spawns that does not grow per saved name, with byte-identical output, exit codes (0, 1, 3, 130), row order and here/gone/other classification, and with no file written while listing.

## Constraints

- Two separate changes. Stage 1 (Phases 1 to 3) edits exactly two files: `src/superclaude/skills/ccsession-tag/ccsession` and `tests/unit/test_ccsession_tag.py`. Stage 2 (Phases 4 and 5) is a second change that adds `src/superclaude/skills/ccsession-tag/scan_sessions.py`, wires it into the same script, and extends the same test file. Stage 3 (stat and date strings in the helper) and everything listed as out of scope in the source stay out: no bound on the number of rows, no cache file, no row-by-row printing, no start-folder hook, no change to `session_place`'s git calls.
- Bash 3.2 compatible: no associative arrays, no `mapfile`, no `printf '%(...)T'`, no `${var,,}`, no `&>>`.
- The script runs under `set -e` (line 132): every new `read`, `ls` or command substitution that can fail ends in `|| true` or sits in an `if`.
- Listing writes no file (README: "Listing never writes any file"); only the first 256 KiB and last 1 MiB of a transcript are read; nothing touches transcript files; GNU `stat -c` is tried first; the date text stays `%Y-%m-%d %H:%M`; the existing functions `session_transcript`, `session_home`, `get_btime`, `get_mtime`, `format_epoch` stay defined, because the resume path (`session_transcript` and `session_home` at the resume block near line 2054) and the fallback use them.
- Per-row caches are built in the parent shell before the row loop: a `$(...)` runs in a subshell and discards variables set inside it.
- Edit only `src/superclaude/...` and `tests/...`; run `make sync-dev` and `make verify-sync` before committing; the synced dev mirrors that `make sync-dev` writes are never staged (only the `src/` side is).

## Phase 1: Stage 1, cheaper locale, dates and stat

## Task 1: Run grep and awk in the C locale inside session_home and session_branch

In `src/superclaude/skills/ccsession-tag/ccsession`, `session_home` (lines 1377 to 1399) and `session_branch` (lines 1401 to 1408) declare `local ... LC_ALL=C`, which does not reach child processes when `LC_ALL` was not already exported, so `grep` runs in the user's UTF-8 locale. Prefix `LC_ALL=C` on the `grep` and the `awk` of the pipeline in `session_home` (lines 1396 to 1397) and on the `grep` in `session_branch` (line 1405). Keep the `local ... LC_ALL=C` lines (they only affect bash's own matching).

Acceptance criteria:
- A `grep` shim first on PATH that records `$LC_ALL` sees `C` on every call made by `ccsession --here` and `--list`, with `LC_ALL` unset in the caller's environment; an `awk` shim sees `C` too.
- The callers keep working unchanged: `list_sessions` (the `--here`, `--here --all`, `--list` and `--ask` views through `show_saved`), the resume path that calls `session_home` near line 2055, and `session_place`, which calls `session_branch` near line 1455. All existing `_listed` tests in `tests/unit/test_ccsession_tag.py` pass unchanged.
- On the scale store built by `.dev/issues/607/scripts/make_scale_store.py` (477 names), `ccsession --here` is measurably faster than the saved 22.0 s baseline (the isolated effect was measured at about 6 to 7 s); the before and after timings and `uptime` lines go to `./artifacts/stage1-timing.md`.

## Task 2: Probe the date flavour once and format epochs without a subshell

Depends on: Task 1

In `src/superclaude/skills/ccsession-tag/ccsession`, `format_epoch` (lines 1533 to 1537) runs `date -r <epoch>` first, which on GNU date takes a file and always fails, then `date -d @<epoch>`; `list_sessions` calls it through `$(...)` twice per row (lines 1616 and 1617). Add a probe run once per `list_sessions` call in the parent shell (`date --version` succeeds: GNU; otherwise BSD, busybox or other) and a function that sets a named variable without a subshell (`printf -v` or plain assignment). On GNU it runs `date -d "@$epoch" '+%Y-%m-%d %H:%M'` first and falls back to `date -r` when that fails; elsewhere it keeps today's order (`date -r` first, then `date -d`). The text format must not change and `printf '%(...)T'` must not be used. Replace the two `$(format_epoch ...)` calls in `list_sessions` with the new function. `format_epoch` itself stays defined.

Acceptance criteria:
- `ccsession --here` output is byte-identical to before on the test fixtures; the date text for a GNU host, for a host whose `date --version` fails (BSD shim), and for a busybox-style `date` is unchanged.
- The number of `date` processes per row is at most 2 (one per timestamp) and none of them is the failing `date -r` call on a GNU host.
- `list_sessions` still builds the "started ... last ..." range, the same-day shortening and `format_duration` text as before (lines 1618 to 1627).

## Task 3: Read birth and change time with one stat per row

Depends on: Task 2

In `src/superclaude/skills/ccsession-tag/ccsession`, `list_sessions` calls `$(get_btime "$jsonl")` and `$(get_mtime "$jsonl")` (lines 1610 and 1611), two subshells and two `stat` processes per row. Add one function that runs `stat -c '%W %Y' "$jsonl"` once (GNU first; only when that fails the BSD form `stat -f '%B %m'`), splits the answer into the start and last variables with parameter expansion, and keeps the rules of `get_btime` (lines 1488 to 1512) and `get_mtime` (lines 1514 to 1531): a birth time that is empty, `0`, `?` or `-` leaves the start empty, a non-numeric change time leaves the last empty, and an empty start or last still gives the row text `(times unavailable)`. Call it from `list_sessions` instead of the two `$(...)` calls. `get_btime` and `get_mtime` stay defined.

Acceptance criteria:
- A `stat` shim that counts calls sees one call per row that has a transcript (not two), and none for a row whose transcript is missing.
- A fixture where `stat -c '%W'` prints `0` still lists `(times unavailable)` for that row, exactly as before.
- `ccsession --here`, `--here --all` and `--list` output on the existing fixtures is byte-identical to before.

## Phase 2: Stage 1, transcript index and per-row string work

## Task 4: Build the transcript index once and look uuids up with parameter expansion

Depends on: Task 3

In `src/superclaude/skills/ccsession-tag/ccsession`, `list_sessions` finds a transcript with `$(session_transcript "$uuid")` (line 1599), one `ls -t "$PROJECTS_DIR"/*/<uuid>.jsonl | head -n 1` pair per row whose own repo-keyed folder holds no copy (`session_transcript`, lines 1480 to 1483). Build the index once per `list_sessions` call in the parent shell (not inside a `$(...)` that is itself run per row, and lazily at the first row that needs it): `idx=$(ls -t "$PROJECTS_DIR"/*/*.jsonl 2>/dev/null) || true`. Look a uuid up by parameter expansion with no bash loop over the index per row (for example `pre=${idx%%"/$uuid.jsonl"*}` and keep the text after the last newline, then add the suffix back); the first match in `ls -t` order is the newest copy. Keep the rule "own repo-keyed folder first, newest copy otherwise" (lines 1595 to 1600). An empty index, or an `ls` that failed, falls back to the existing per-uuid `session_transcript` call. Do not touch the resume path's use of `session_transcript` (near line 2054).

Acceptance criteria:
- An `ls` shim that counts calls sees the index built at most once per `ccsession --here` or `--list` run, whatever the number of saved names, and the fallback only when the index is empty.
- With two copies of a transcript in two folders the newest copy (`ls -t` order) is used; with the transcript only in another folder it is found; with no transcript the row reads `(transcript missing)`; a uuid that is a prefix or suffix of another file name never matches the wrong file.
- Under `set -e`, a missing or unreadable `$PROJECTS_DIR` glob (no `*/*.jsonl`) does not stop the script and the output equals the output of the unchanged per-uuid path.
- `--here`, `--here --all` and `--list` output on the existing fixtures is byte-identical to before.

## Task 5: Replace basename, dirname and head with parameter expansion in the row loop

Depends on: Task 4

In `src/superclaude/skills/ccsession-tag/ccsession`, per row `list_sessions` runs `basename "$topic_file" .txt` (line 1593), `head -n 1 "$topic_file"` (line 1594) and `dirname "$ws_dir"` (line 1595), once per list `basename "$(dirname "$ws_dir")"` (line 1572), and `session_home` runs `basename "$(dirname "$1")"` (line 1384). Replace them with parameter expansion: `${x##*/}` and `${x%/*}` (and strip the `.txt` suffix with `${x%.txt}`), and for the uuid set `uuid=""` first and then `IFS= read -r uuid < "$topic_file" || true`, so a failed redirect (a file that cannot be read) does not leave the previous row's uuid. The results must equal what `basename` and `dirname` printed for the paths the script can see (a trailing slash, a `.txt` name, a name with no slash).

Acceptance criteria:
- Counting shims for `basename`, `dirname` and `head` first on PATH see zero calls per row: a store of 10 topic files and a store of 60 topic files give the same count for each of the three (the calls left are the per-list and per-run ones, not per-row ones).
- A topic file with mode 000 does not show the previous row's uuid: its row is `(transcript missing)` with an empty or its own short uuid exactly as the unchanged script prints it (compare against the pre-change output).
- Topic names with spaces and `%2F` escapes still list under the same names; the first-two-lines handling in `show_saved` (lines 1715 to 1731) is unchanged.

## Phase 4: Stage 2, the python3 batch helper

## Task 10: Write scan_sessions.py, the batch transcript index and start-folder scan

Depends on: Task 9

Create `src/superclaude/skills/ccsession-tag/scan_sessions.py` beside `retention.py` (precedent: the script calls a python3 helper from `$CCSESSION_DIR`, `retention_warning`, line 1675; `install.sh` line 40 and `src/superclaude/cli/install_skill.py` line 52 copy the whole skill folder, so no manifest edit). It takes the repo-keyed folder, a mode (worktree view or `--list` view), and the uuids of the topic files in the order bash passes them (arguments or a file named by an argument, never a file it writes), and prints one `\x1f`-separated record per uuid in input order: the transcript path and the session's start folder. Rules from the source: prefer the file in the repo-keyed folder, else the newest copy under `$PROJECTS_DIR/*/<uuid>.jsonl`; run the start-folder scan only for the worktree filter and never for `--list`; read bytes, the first 262144 and the last 1048576, head first and skip the tail when a store-matching folder is found; extract `"cwd":"..."` values with the same pattern as the script (`"cwd":"([^"\\]|\\.)*"`), apply the two unescapes in the order of the script (`\"` to `"`, then `\\` to `\`), not `json.loads`; match the folder by replacing every byte other than a letter or digit with `-` and comparing with the transcript's own folder name; first-cwd fallback and de-duplication as in `session_home` (lines 1383 to 1398); birth time stays with `stat -c '%W'` in bash. It writes no file and exits non-zero on any error.

Acceptance criteria:
- The helper opens transcript files read-only, reads only the head and tail slices, and writes nothing (checked by a test that lists files under HOME and TMPDIR before and after).
- On the scale store, a direct run of the helper over the 439 transcripts takes about one second (the source's prototype: 0.75 s warm), written with the command and `uptime` to `./artifacts/stage2-helper-timing.md`.
- For a cwd with invalid UTF-8 bytes, a non-ASCII cwd, and an escaped quote or backslash, the start folder equals what `session_home` prints for the same file (compared byte for byte in Task 12).
