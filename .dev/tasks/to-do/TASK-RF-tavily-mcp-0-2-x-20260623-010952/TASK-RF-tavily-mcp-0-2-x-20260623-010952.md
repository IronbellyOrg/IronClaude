# Tavily MCP Upgrade to Pinned tavily-mcp@0.2.20 Across 8 Integration Clusters

## Task Overview

This task implements the consolidated Tavily 0.2.x MCP upgrade across all 8 integration clusters (C1-C8) of the SuperClaude codebase, folding in the fixes surfaced by a pre-execution `/sc:reflect` Tier-2 audit (B1, H1-H4, M1-M5). The repo's Tavily integration is currently split across three conflicting version stances: `install_mcp.py` pins a stale `tavily-mcp@0.1.2`, `src/superclaude/mcp/configs/tavily.json` declares an unpinned remote transport, and `docs/user-guide/mcp-servers.md` uses `tavily-mcp@latest`. The user's B1 decision is to pin the exact version `tavily-mcp@0.2.20` (the current npm latest — reproducible, manual bumps, NOT a floating `@latest`).

The upgrade (a) reconciles to a single source of truth (`install_mcp.py` registry) and deletes the orphan `tavily.json`, (b) adopts the 0.2.x `tavily-map`/`tavily-crawl` tool surface in the deep-research engine ONLY, (c) registers the `mcp_server.tavily` eval capability + a capability-gated verification eval as the proof vehicle, (d) aligns all documentation, and (e) ships 7 CI-safe drift-guard test files. The implementation is dependency-ordered: C1 (install/config/version) must land first because every other cluster inherits the version pin and the `DEFAULT_PARAMETERS` baseline.

Seven cross-cluster invariants MUST be preserved across every item: **X1** version `0.2.20` everywhere in scope; **X2** single config source (`install_mcp.py`); **X3** `DEFAULT_PARAMETERS` root = `{"search_depth":"basic","max_results":10}` with the troubleshoot Tier-2 query intentionally overriding to `advanced` (documented per M4); **X4** eval capability token = `mcp_server.tavily` (NOT the stale `mcp.tavily`); **X5** `map`/`crawl` adopted in the research engine ONLY; **X6** docs POINT to canonical sources, never duplicate param tables; **X7** frontmatter↔prose parity for every `mcp__tavily__*` tool id.

3. **C7 — Eval verification vehicle:** Register `mcp_server.tavily` in BOTH `real.yaml` AND `capabilities.py` `_DEFAULT_CAPABILITY_SPECS` (MANDATORY per M2), add a capability-gated `tavily-search` verification eval that SKIPs without a key, and fix the stale `mcp.tavily` docstrings in `models.py` (X4).
