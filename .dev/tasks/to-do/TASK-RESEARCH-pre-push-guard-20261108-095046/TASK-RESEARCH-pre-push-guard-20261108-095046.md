# Technical research: git pre-push hook semantics for the L2 launch-level guard (issue #441)

## Task Overview

This task runs a structured technical investigation into git's pre-push hook as it bears on the L2 layer of the launch-level guard: a git pre-push hook that refuses a governed AI agent's push to `refs/heads/main` or `refs/heads/master`. The investigation answers six sub-questions: (a) the stdin record format `<local ref> <local oid> <remote ref> <remote oid>` for create, update, delete, force, `HEAD:main`, multiple refspecs, `--mirror`, `--all` and `--tags`, the behaviour on empty stdin, and the arguments `$1` (remote name) and `$2` (URL); (b) which push paths skip the hook (`--no-verify`, `-c core.hooksPath=/dev/null` or another directory, `git send-pack`, other tools); (c) where git looks up hooks from a linked worktree (common dir versus per-worktree, `git rev-parse --git-path hooks`, `core.hooksPath`, `extensions.worktreeConfig`); (d) the hook's process ancestry and environment when run from a linked worktree; (e) Linux no-replace atomic publication (`link(2)`, `O_EXCL`, `rename(2)`, `renameat2` `RENAME_NOREPLACE`) and git's executable-bit requirement; (f) the git version that introduced each behaviour, measured against the installed git 2.47.3 on Linux kernel 6.8.0-147-generic.

Evidence comes from three sources: the repository code (the L1 text guard, the job-identity selector, the L2 design section and the IR-7 W-L2-ABSENT status code), official documentation (git-scm.com, the git RelNotes, man7.org, git source), and experiments run against the real installed git inside a throwaway `mktemp -d` directory under /tmp with a local bare repository as the only remote. The final deliverable is `.dev/tasks/to-do/TASK-RESEARCH-pre-push-guard-20261108-095046/RESEARCH-REPORT-pre-push-guard.md`, a 10-section research report that feeds a `/sc:brainstorm` on issue #441. No source file is edited and nothing is posted anywhere.
