## 1. probes.py (src/superclaude/cli/sweep/probes.py, 1478 lines): the read side

Module docstring (probes.py:1-8): "the only module that starts a subprocess"; holds the two seams `_git` and `_orca`, the argv allowlists, the time budget, the disk/git readers and `collect`. The claim "Nothing here writes a file, takes a lock or uses the network" is [CODE-VERIFIED] by reading the whole file: every file open is a read (probes.py:609, 842, 889, 906; `read_bytes` at 770), and the only `subprocess.run` calls are at probes.py:274 (Orca) and probes.py:344 (git). The module does not itself prevent a child process from writing (git or Orca could), it only constrains which argv shapes are started.

### 1.2 `_orca` seam and result classification (probes.py:266-312)

- `subprocess.run([binary, *args], capture_output=True, timeout=timeout, check=False, stdin=DEVNULL)` (probes.py:274-280). Output is buffered; the 8 MiB `OUTPUT_LIMIT` (probes.py:85) is checked only after the child exits (probes.py:287). A `shortcut:` comment (probes.py:270-272) cites "owner ruling 2026-11-12, D-01": upgrade to Popen with a chunked read only if a call is seen to exceed the limit.
- Result kinds (`OrcaResult.kind`, probes.py:112-118): `ok | no_binding | unavailable | call_failed`.
  - `TimeoutExpired` -> `unavailable` "timeout after N s" (281-282); `FileNotFoundError` -> `unavailable` "binary not found" (283-284); other `OSError` -> `unavailable` (285-286).
  - Output over 8 MiB -> `call_failed` (287-290).
  - `runtime_unavailable` as JSON `error.code` or as the whole first stderr line -> `unavailable` (294-299).
  - Non-zero exit -> `call_failed` "orca call failed (exit N)" (300-303).
  - `run-current` replies in plain text: `_run_current_result` (254-263): empty -> call_failed; starts with "No Run is bound to this terminal." -> `no_binding`; exactly one distinct `run_[0-9a-f]{12}` id -> ok; anything else -> call_failed.
  - Every other verb must return a JSON dict with `ok: true` and a dict `result` (306-311), else call_failed "invalid response".
- `_call` (369-394) adds the budget: no timeout left -> `call_failed` with the budget reason (371-373); a list reply without the captured list key (`workers`, `tasks`, `worktrees`; `_LIST_KEY` 362-366) is "invalid response" (378-384); a timeout when the timeout had been cut below per_call becomes `call_failed` with the budget reason (385-390); a non-zero exit or invalid response on the very first Orca call of the sweep is promoted to `unavailable` (391-393).
- After any `unavailable`, `_OrcaState.available` is False (1108-1111, 1139-1140, 1288-1289, 1352-1353) and every later Orca read is skipped with an `unscanned ... orca unavailable` source row (1128-1129, 1146-1149, 1273-1275, 1355-1358).

### 1.3 Budgets (`Budget`, probes.py:124-208)

Defaults: `shows=50` (worker-show cap), `total_s=90.0` (whole sweep), `per_call_s=10.0` (probes.py:127-133). Byte limits (probes.py:85-89): OUTPUT_LIMIT 8 MiB; CONTRACT_LIMIT = LEDGER_LIMIT = 1 MiB; LEDGER_SPLIT 512 KiB; TRANSCRIPT_TAIL 256 KiB; WORKER_LIST_PAGE 100. The first four are annotated "proposed (DESIGN 17 open item 19)"; status of that open item is in section 6.
- `share_shows` (145-169): splits the show cap evenly across Runs, remainder to the first; then each Run's share is capped at what it needs and spare share is handed to Runs that still need more.
- `take_show` (171-183) returns False once the total or the Run's share is spent; `_show` then records an `unscanned` source row with `show_cap_reason()` (probes.py:1276-1280, 207-208).
- `call_timeout` (185-191): None when under 1 s of the total remains; otherwise `min(per_call_s, remaining)`, setting `_cut` when shortened. `spent()` (196-198) stops `_stable` re-reads.

### 1.4 The git calls (`ALLOWED_GIT`, probes.py:68-81; `_git`, probes.py:315-358)

Four fixed argv shapes, exact-match checked by `check_git_args` (probes.py:241-244, `tuple(args) in ALLOWED_GIT`):
1. index 0: `status --porcelain=v1 -z --branch --untracked-files=all --ignore-submodules=all` (69-76; submodules are ignored because a submodule's own config could start a program, issue 547, comment 65-67)
2. index 1: `config --show-origin --list -z` (`CONFIG_LIST`, 77, 81)
3. index 2: `ls-files -z` (`LS_FILES`, 78, 81)
4. index 3: `check-attr --stdin -z filter` (`CHECK_ATTR`, 79, 81)

The seam always prepends `git --no-optional-locks -C <cwd> -c core.fsmonitor=false` and sets `GIT_OPTIONAL_LOCKS=0` in the child env (probes.py:331-340); fsmonitor is forced off because a command named by repository configuration or the inherited environment would otherwise run during status (issue 547, probes.py:325-328).

"4 fixed calls per worktree" is a maximum. `_filter_blocks_status` (995-1018) runs `config` first; if no filter driver has a non-empty `clean` or `process` command (`_filter_drivers`, 970-992: later config entries override earlier, only keys `filter.<name>.clean|process` with a non-empty value count) it returns False and neither `ls-files` nor `check-attr` runs. If `ls-files` is empty it returns False. Otherwise `check-attr` is fed the NUL-separated tracked-file list on stdin (1008-1018) and the function returns True when any file's `filter` attribute value is one of those drivers. So per worktree there are 2 calls (config + status) up to 4. The filter check runs BEFORE status (probes.py:1038-1041): if it returns True the status call is not made and the source row is `unscanned: git filter could run a program` (`FILTER_REASON`, 967, 1039).

Failure mapping in `_read_worktree` (1021-1048): missing path -> `unscanned "worktree not readable"` (1027-1031); no timeout left -> unscanned with the budget reason (1032-1036); `GitCallFailed` -> "worktree not readable", or the budget reason when a timeout was budget-cut (1042-1046). `_git` raises `GitCallFailed` on timeout, OSError, output over 8 MiB, or non-zero exit (347-357). A failed worktree becomes `WorktreeState(status_read=False, uncommitted=None, unpushed=None, dev_tasks_unsaved=None, ...)` (923-934): a failure maps to unknown, never to clean. Malformed config or attribute output also raises `GitCallFailed` (probes.py:980-981, 1016-1017).

### 1.5 Disk reads (all reads; each checked with `_inside`, symlinks resolved, against a root)

- Packages (`_packages`, 655-710): scandir of `<worktree>/.dev/tasks/to-do` and `.../done` (661-662); a package folder whose real path escapes the worktree gives an `unscanned ... outside root` row (663-668, 686-692). The `.archiving` marker is detected with `_marker` (644-652, 698). For a to-do package, `progress.md` is read by `_ledger`; `_ledger_has_final` looks for a line starting with `FINAL:` (607-636); over 1 MiB only the last 512 KiB is searched (610-615); a missing ledger is `False`, "unfinished" (GQ-105, 630-634). Done-only packages get `final=None` (699-709).

- Transcript tails (`_transcript` 819-862, `_read_transcripts` 1445-1477): folder `~/.claude/projects/<project_key>`, key = worktree path with every non-alphanumeric character replaced by `-` (`_project_key`, 1075-1077, 1450-1453); only `*.jsonl`; last 256 KiB with the first partial line dropped (840-848); the last complete record's `timestamp` and `sessionId` and the first timestamp are extracted (786-816).
- ccsession tab map (`_tab_map`, 870-895): `<$XDG_STATE_HOME or ~/.local/state>/ccsession/orca-tabs/*` (871, 1369-1372); each file's first three non-blank lines are session id, folder, handle; the file name is the pane key (893-894). A missing folder is "readable and empty" (875-876).
- Orca version: `read_orca_version` reads `/opt/Orca/resources/app.asar.unpacked/out/package.json` (`ORCA_VERSION_FILE`, 83, 903-914), a fixed Linux path; elsewhere it yields None.
- Stability: `_stable` (590-604) compares (size, mtime_ns) before and after a read and re-reads once while the budget allows; a second change is `ReadFailed("conflict: inconsistent observation")`.
- Remote hosts: always `SourceCoverage("remote hosts", "unknown", None, None)` (probes.py:1381); no code reads remote hosts and `--include-remote` is forbidden in argv (62).

### Key Takeaways (probes.py)

- Binary is `orca-ide` or `$ORCA_CLI_COMMAND`; the env value is unvalidated; bare `orca` is never the default.
- Git: exact-match allowlist of 4 argv shapes, always `--no-optional-locks`, `-c core.fsmonitor=false`, `GIT_OPTIONAL_LOCKS=0`; the filter pre-check (config, ls-files, check-attr) refuses to run status when a filter driver with a command applies to a tracked path.
- Every failure maps to `unscanned` or None, never to a clean or empty value.
- Budgets: 50 shows, 90 s total, 10 s per call, 8 MiB output, 1 MiB contract/ledger, 256 KiB transcript tail.
- Disk reads are limited to `.dev/tasks/{to-do,done}`, `~/.claude/projects/<key>`, `$XDG_STATE_HOME/ccsession/orca-tabs` and Orca's `package.json`.

## 2. commands.py (src/superclaude/cli/sweep/commands.py, 289 lines): CLI, publish, exit codes

### 2.1 CLI surface
`sweep_group` (`@click.group("sweep")`, commands.py:214-216) with one command `run` (219-288). Options (220-241): `--run` (multiple; Run id; default the Run bound to this terminal), `--window` (default `6h`, `DEFAULT_WINDOW` 27; `<N>h` or `<N>d`, max 720h or 30d, regex `[1-9][0-9]{0,3}[hd]`, 43-52), `--root` (default found by walking up from cwd to the first folder holding `.git`, 55-84), `--output` (default `<root>/.dev/sweeps/`). Pipeline in `run` (246-277): parse window -> check root -> check run ids (regex `probes.RUN_ID_RE`, duplicates collapse, 87-92) -> `_check_output` -> `probes.Budget()` -> if no `--run`: `probes.bind_run(budget)` (264-266) -> `SweepContext` -> `probes.collect` -> `classify_all` -> `render` -> `_publish` -> `json.dumps(to_json(...))` printed with `click.echo` (277-278). The report is therefore published BEFORE the JSON is printed; if printing fails after publication the file remains.

### 2.2 `_check_output` (99-123)
Resolved output folder must be `<root>/.dev/sweeps` or below (`_within`, 108-112; the base is deliberately not resolved so a symlinked sweeps folder fails) and must not overlap (contain or be contained by) any input folder: `<root>/.dev/tasks`, `~/.claude/projects`, `<state>/ccsession/orca-tabs` (254-261, 113-122). Violations are `click.UsageError` (exit 2).

### 2.3 Publish atomicity: `_publish` (153-208), the only write
- Stem `YYYYMMDD-HHMMSS-sweep` from UTC now (155). `os.makedirs(output_dir, exist_ok=True)` (158). Re-checks the resolved dir is inside the `.dev/sweeps` base (161-164; `_sweeps_base` 129-134).
- Encodes to UTF-8 before creating any file (165-167). Writes to a hidden temp `.<stem>.<pid>.tmp` opened `O_WRONLY|O_CREAT|O_EXCL` mode 0o666 (168-170), `os.write` loop then `fsync` then close (146-150, 175-179).
- Commit point: `os.link(tmp, output_dir/name)` for `<stem>.md`, then `<stem>-2.md` ... `<stem>-99.md` (`MAX_SUFFIX = 99`, 29, 182-196); `os.link` fails with `FileExistsError` if the name exists, so it never overwrites (186-190). Name space exhaustion -> `_PublishError` (197-201). Then `os.unlink(tmp)` (202-207); a failure there leaves the complete report but yields no success JSON (204-207).
- Own temp files are removed on failure (`_drop_own_temp`, 137-143, extra stderr line `[sweep publish] left temp file ...` if unlink fails); a pre-existing temp file with that name is left alone (171-172).
- Observation: `os.link` needs a filesystem that supports hard links; a failure other than FileExistsError is `[sweep publish] cannot link report` (191-194).

### 2.4 Exit codes (documented in the docstring 6-8, implemented 279-288)
- 0: report published and one JSON object printed on stdout.
- 2: `click.UsageError` or `probes.BindingError` (no Run bound, or Orca unavailable while binding): message printed to stderr (279-281).
- 1: `_PublishError` (stderr lines, 282-285) or any other exception, printed `[sweep <stage>] <sanitized message>` where stage is one of args, bind, collect, classify, render, publish, output (286-288). An allowlist `ValueError` therefore exits 1.
Note: Orca being unavailable during `collect` does NOT fail the sweep: it yields exit 0 with `unscanned` rows; only a failed binding (no `--run`) exits 2.

### Key Takeaways (commands.py)
- The only write is one report file under `<root>/.dev/sweeps/`, via temp file + `os.link` (no overwrite, up to 99 same-second names), then unlink of the temp.
- JSON is printed after publication; stdout carries only the JSON object.
- Exit 0 published, 1 internal/publish error, 2 usage or binding error.
