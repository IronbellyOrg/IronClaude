# Apply Layered PRD Document-Capture Hotfix (Layers 1-3)

## Task Overview

The `superclaude prd run` pipeline has a confirmed defect (root cause confidence 0.95): document-producing steps fail their line-count gate on roughly 24 lines of NDJSON commentary instead of the agent's real document. The chain is: the prompt builders for document steps do NOT pin a canonical output path, so the agent invents a variant filename in a writable source/spec directory listed in its scope (wrong name AND wrong location); the executor recovery (`_resolve_step_content`) only rglobs the EXACT canonical filename under the task directory and its parent, misses the variant, and falls back to the short NDJSON commentary; the STRICT research-notes gate then HALTs the run on insufficient lines. A compounding contamination loop occurs because agents write into the writable WHERE source directory and later steps re-ingest those files as source.

This task implements the layered defense decided by the adversarial debate (convergence 0.86, status success) recorded in `merged-solution.md`. Layer 1 (primary, at-source) pins the canonical absolute output path in the four un-pinned document builders and adds a shared read-only mirror helper of the executor's artifact mapping. Layer 2 (backstop, defense-in-depth) hardens the executor recovery with a per-step pattern map, bounded WHERE search roots with realpath containment + symlink rejection, a pattern-aware search, and a deterministic tiebreak that ranks freshness above raw content size (INV-006). Layer 3 (guard) adds a cheap truncation-marker check in the gates module and a guard comment preserving the NDJSON-vs-disk content split (INV-010). The two Layer-3-adjacent architectural items — working-directory isolation and result-event capture — are EXPLICITLY OUT OF SCOPE per the design's deferral decision and MUST NOT be implemented here. The work is implemented in the prd CLI package (Python package source, NOT a synced skill/agent/command), so NO `make sync-dev` is needed and no `.claude/` path may ever be staged.

## Key Objectives

The following objectives MUST be achieved by this task:

1. **Layer 1 — Prompt path pinning:** Add the `_artifact_path_for_step` mirror helper and inject a `CRITICAL -- Output Location:` pin into each of the four un-pinned document builders (scope-discovery, research-notes, sufficiency-review, preparation) at their exact per-builder anchors, so agents write to the canonical task-directory path and never into a WHERE source/spec directory.

3. **Layer 3 — Guards:** Define `_check_no_truncation_marker` in the gates module (defined + unit-tested only, NOT wired into any gate's semantic_checks list) and add a guard comment preserving the NDJSON `output_text` vs disk `gate_content` split (INV-010).
