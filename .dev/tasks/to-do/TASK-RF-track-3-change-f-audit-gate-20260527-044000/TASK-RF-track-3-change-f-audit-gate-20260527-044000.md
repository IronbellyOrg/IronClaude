# Change F — Insert Tier 2 Calibration Completeness Gate Subsection into sc-troubleshoot-protocol Wave 3

## Task Overview

This task inserts a new `####`-level subsection — **"Tier 2 calibration completeness gate (hard precondition for report publishing)"** — into Wave 3 of the `sc-troubleshoot-protocol` SKILL.md at `src/superclaude/skills/sc-troubleshoot-protocol/SKILL.md`. The new subsection lands immediately after Step 4 (Distill candidate fixes, currently at L264) and before the `**Exit criteria**:` block (currently at L266), positioning the gate as the last action Wave 3 performs before exit.

The gate closes **Cause #1** (calibrator non-execution) from the cross-environment merged proposal. Empirical evidence from T4 runs showed that `tier2-*-calibration.md` artifacts were sometimes absent, allowing 0.95 / 0.85 self-reported confidences to pass through unguarded past the Wave 2 STOP gate. Per the proposal: **"No formula refinement closes this; only an audit gate does."** Change F is the most-load-bearing V2 contribution.

The gate verifies on-disk presence and parseability of every sibling calibration artifact. When any artifact is missing or malformed, the orchestrator MUST: (1) log `calibration: missing` to `audit.log`, (2) re-dispatch the `confidence-calibrator` Task once with a 2-minute wall-clock wait, (3) on retry failure, write the card into `REPORT.md` with confidence force-degraded to `min(self_reported, 0.65)` and a `calibration_status: failed_to_calibrate` annotation. **Self-reported confidence is NEVER passed through unmodified.**
