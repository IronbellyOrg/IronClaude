### 2.2 launch-job-identity.sh (582 lines: bash wrapper + embedded Python run by `uv run --no-project python -I`, :582) [CODE-VERIFIED]
- Purpose (:1-19): Linux same-user "job identity". Not a sandbox. Lets a git hook tell whether a process descends from a governed Bash tool call. Subcommands (main :541-572): `hook`/no args (PreToolUse Bash adapter), `execute SESSION TOOL_ID COMMAND`, `identify [PID]`, `prepare SESSION COMMAND [TOOL_USE_ID]` (prints single-use token), `run TOKEN`.
- State under `~/.claude/state/launch-level/`: `sessions/<sid>` (level), `requests/<token>` (single-use, flock + unlink on read :140-159), `jobs/<kernel-sid>.json` (supervisor record {pid,start,boot,kernel_sid,session_id} :231, :315-316). Dirs/files must be owned by euid with no group/other bits (`private()` :81-84), opened O_NOFOLLOW (:93, :112, :131).
- Mechanism: for a governed session's Bash call the hook returns `updatedInput` rewriting the command to `/bin/bash <script> execute <sid> <tool_use_id> <original>` (:491-498). `execute` publishes a request; `run` consumes it, forks a supervisor that `setsid()`s, sets PR_SET_CHILD_SUBREAPER (:311), writes `jobs/<sid>.json`, runs `bash -c <command>`, waits for the shell and all non-zombie members of the same kernel session (:338-356); signals forwarded via pidfd (:284-304); on exit SIGKILLs survivors, removes the job record only if none remain (:359-375).
- `identify` (:215-260): one JSON line: `ordinary` (no job record :229) / `ordinary`+`reason: released` (session level record gone :255) / `governed`+session_id / `unknown` with reason `stale|orphaned|foreign|unreadable` and `record` path (:257-260). Checks: pid==kernel sid, exact field set, start time and boot_id (:246), process uid==euid (:249), not zombie (:242).
- Fail modes: hook with no store dir -> exit 0 (:20-24). No `uv`: jq fallback verifies an exact top-level bound Bash session + owned record chain, else exit 0; if bound -> "UV is required" exit 2 (:25-54) = closed for governed, open for ordinary. In `hook()`: >1 MiB, unparseable, non-Bash tool, invalid sid, or no session record -> return 0 (:433-453); once a record exists any failure to wrap -> exit 2 "cannot be wrapped safely" (:500-502). A command naming the runner script followed by run|hook|execute is refused (:474-476).
- Declared limits: deliberate setsid/daemonize escapes selection (:7-8); Monitor and pipelines unsupported (:9); fresh bash per call so cd does not persist (:16-18); live auto-mode rewrite ordering unverified (:14-15, :497).
- Registered as PreToolUse matcher "Bash", AFTER the guard (hooks.json :125-134).

### 2.7 Bypass paths and fail-open / fail-closed summary
- OPEN (by design): an ordinary session (no `sessions/<sid>` record) is never blocked (guard :391, header :6-7); missing/invalid `session_id` is identity loss and allowed (:209-217, :386-391); hook killed at its 5 s timeout lets the call go ahead (design :216 "V8, R2", not testable here); `uv` absent AND `jq` absent in the identity hook = no rewrite (:25-30); identity hook ignores Monitor, other tools, >1 MiB input (:433-444); `setsid`/daemonised children escape job identity (identity :7-8, design LIM-2); a Monitor-run push reads `ordinary` to L2 (LIM-1).
- CLOSED for a bound session: any internal error, jq failure, bad tool field, NUL, >64 KB command (:392, :419, :145-163, :807-808); identity hook cannot wrap -> exit 2 (:500-502); L2 unknown actor + protected ref -> refuse (pre-push :201-208); L2 malformed stream from non-ordinary actor -> refuse (:192-195).
- Interaction: a `degraded` record (loose marker, no nonce) is level W + LL-STATE note in the guard (:268) but the identity hook's `governed()` rejects any word outside the 3 levels (identity :74, :183), so every Bash call of such a session is blocked by the identity hook (exit 2); pinned by `test_degraded_word_guard_worktree_with_state_note_identity_blocks_all` (test_launch_level_guard_with_identity.py:187) [CODE-VERIFIED reading; behaviour not run].
- Human release: person runs `rm sessions/<sid> sessions/<sid>.ok` (message :97; claim output `release` text, orca_worktree.py:1471). After release the session is ordinary to both guard and identity (`identify` returns `ordinary` + `reason: released`, identity :255).
- Static limits of the L1 text scan: no quoted-text awareness (LL-TEXT note :130-132); variables, globs, scripts, `bash ./push.sh` not caught (design R1, row 33; guard :771-772 `shortcut` comment); `pre-push` bypass spellings `--no-verify`, `core.hooksPath`, `hook.pre-push` are TAMPER only as text (:766-768).
