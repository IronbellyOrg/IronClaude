- How a check works: the coordinator computes the hash over the plan files it names and writes it in the plan reply (marker `plan=<hash>`); the worker recomputes over the same names and compares via `approval_line.check` (B3). `stage-status` recomputes it again when `--plan-dir` and `--plan-file` are given and treats an unreadable plan as changed (cli.py l.286-291).

## B7. `stage_predicates.py` (301 lines, confirmed by `cat -n`): stage predicates
Pure functions; no I/O. Docstring l.1-34 states the rules (quoted in short):
- Plan reply: "the latest comment by the host login that carries the hidden marker `<!-- sc:stage:plan id=<record-id> plan=<64 hex> -->`", unedited since posted, and the plan files must still hash to the marker value (`latest_plan_reply` l.118-127: max by `(created_at, id)` among host-login comments with a marker).
- Label channel (`_label_channel` l.145-189): label events for the approval label sorted by `(created_at, id)`; counts only a `labeled` event strictly after the plan reply's `created_at`; reasons `no-label`, `label-before-plan`, `label-removed` (a later `unlabeled` event; also sets the revoked flag), `actor-not-user` (actor type not `User`), `actor-not-allowed` (login not in the issue's assignees and id not in the approvers set), else accepted `ok`; carries `actor_is_host_login`.
- Comment channel (`_comment_channel` l.192-224, `_comment_failure` l.227-244): newest first; only comments whose whole body is `approved` or the long form (`approval_form` not None); author must be type `User` and assignee (by login) or approver (by id), else `author-not-allowed`; then reasons `comment-before-plan` (created at or before the reply), `edit-unknown` (no edit evidence row for the comment id: fails closed), `comment-edited` (`last_edited_at` set), `hash-mismatch` (long form whose hash or record id differs from the marker's); an accepted comment gives `ok`; none gives `no-comment`.
- `evaluate(...)` l.247-301: no plan reply gives state `no-plan-reply`; a reply with no edit evidence gives `plan-reply-invalid` with `plan_reason` `plan-reply-edit-unknown`; an edited reply gives `plan-reply-invalid` / `plan-reply-edited`; `changed = plan_hash_now is None or plan_hash_now != marker.plan_hash`; `approved = (label.accepted or comment.accepted) and not changed`; state order: `plan-changed`, `approved`, `revoked`, else `awaiting-approval`. Key `(issue, "plan", marker.plan_hash)`; `status_seen` = a `project_v2_item_status_changed` event after the reply (`STATUS_EVENT` l.44), "never required, never part of the key" (docstring l.26-27). `assignee_is_host_login = host_login in assignees`.
- Equal timestamps never count as "after" (docstring l.32-33; the code uses strict `>` at l.162 and `<=` at l.232).
- Why it did not reuse the watcher's predicates: docstring l.7-10 (`unchanged_since` skips host-login comments; `approval_of` orders against the trigger label, not a plan reply).
- States set: `no-plan-reply | plan-reply-invalid | plan-changed | awaiting-approval | approved | revoked` (l.82). `revoked` arises only when no channel is accepted and the label was removed after being applied: a comment approval stands when the label is removed (pinned by `test_a_comment_approval_stands_when_the_label_is_removed`, old test_stage_predicates.py l.392).
