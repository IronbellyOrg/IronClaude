# Add Pipeline Hardening Closure protocol mode (H0-H5) to /sc:troubleshoot and sc:troubleshoot-protocol

## Task Overview

This task hardens `/sc:troubleshoot` and `sc:troubleshoot-protocol` by adding a reusable **Pipeline Hardening Closure** protocol mode (waves/gates H0-H5) that forces evidence at the four boundaries where the canonical pipeline escapes E1-E5 recurred: the runtime entrypoint, the shared contract, the same-class sibling sweep, and the independent-review effective input. The escapes recurred because troubleshoot remediation accepted ADJACENT proof (helper/argv construction, PASS-report presence, edited-helper tests, single-repro fixes, generic-evaluator proof, reviewer presence) as if it covered the RUNTIME contract. The new mode catches future escapes by invariant rather than by issue-specific patch.

Concretely, this task EDITS 4 source-of-truth markdown files and CREATES 5 new ref files, all under `src/superclaude/`, then validates via `make sync-dev`, `make verify-sync`, and markdownlint. The hardening is mechanism-based and lands ENTIRELY in the command + `SKILL.md` + 5 refs. It does NOT touch any PRD/pipeline/reflect source code — the root-cause symbols named in the frozen escape evidence (`PrdExecutor._evaluate_gate`, `pipeline.gates.gate_passed`) are FROZEN EVIDENCE ONLY, never edit targets.

The driving spec (`troubleshoot-pipeline-hardening-spec.md`) is the fidelity source-of-truth. Every spec card (§7 H1/H4 cards), table (§6.2 output-contract fields, §7 H2 ledger), report block (§8), rejected-substitution list (§4), and command/skill change (§5.1/§5.2) MUST appear faithfully in the built output — byte-faithful where the spec gives literal templates.
