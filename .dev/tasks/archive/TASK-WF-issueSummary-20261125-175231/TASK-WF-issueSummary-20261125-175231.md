# Start every ccsession Claude process with the low-memory reap switch set (issue 765, Part 1)

Source: ./source.md
Goal: Every Claude Code process that `ccsession` starts (new, resumed, tagged, untagged, with or without a model, directly or through `ccsession-orca`) has `CLAUDE_CODE_DISABLE_BG_SHELL_PRESSURE_REAP=1` in its initial environment whatever the shell or `~/.claude/ccsession.env` held, the scope and override decision is recorded, the session-wide effect and its limits are documented, and a live coordinator launch shows the switch in the process environment and its message watch still receiving messages.

## Constraints

- Part 1 only. Part 2 of the old issue body (research, guard, sampler, browser stops, the eight plan problems) is dropped and is not planned, built or estimated here.
- The base branch is `origin/integration`, not `master`. The switch is absent from `src/` at integration commit `a6fec24480e8cc65abbb16b194625e2ea52238c7`; a Grep of the repo outside `.dev/` found no match.
- Implement in `src/superclaude/` and `tests/`. The `.claude/` mirror is generated by `make sync-dev` and its contents are never edited by hand and never staged.
- Launch-time environment only. No settings change (`src/superclaude/cli/user_settings_defaults.json` stays untouched), no installer change (`wire_ccsession` copies the launcher unchanged), no automatic watch restart, and the coordinator wait contract at `src/superclaude/core/WORKER-CONTRACT.md` lines 100-104 is preserved as written.
- No coordinator-only predicate exists in the launcher: `CCSESSION_ORIGIN` records who chose a name, not the coordinator role. Do not infer a role from a label or from `CCSESSION_ORIGIN`.
- A shell value or env-file value must never leave a ccsession launch without `=1`. An earlier suggestion to respect overrides is not owner approval to weaken this.
- Direct `ic` (`src/superclaude/scripts/ic` lines 128 and 130) and a bare `claude` start bypass ccsession. Do not widen this issue into launcher work for them, and do not claim universal coverage.
- Tests capture only the named non-secret switch, never a full environment dump, and stay isolated from the developer's own environment values.
- The live check reads only the exact switch from the process environment and never forces memory pressure on the shared host.
