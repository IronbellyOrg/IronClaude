# Implement the modular /sc:git, authorized between-task commits in /sc:implement, and submodule operations (issue 326)

Source: ./source.md
Goal: Deliver the design in ./source.md: a refactored `/sc:git` (command file, protocol skill, read-only `vcs` helper script) with defined submodule operations, and an opt-in `--commit-tasks` commit step in `/sc:implement` with crash recovery, protection of work outside the commit set and owner resolution, plus the routing, worker-contract, plugin-mirror, documentation and test changes around them. This plan repairs the 11 blocking findings of the review of the first plan (the `## Revision 1` section of ./source.md lists them as M-01 to M-11) and avoids the Medium findings M-12 to M-24 listed there.

## Constraints

- Requirement ids (FR-xxx, NFR-xxx, AC-xx, T-xx, D1-D11) and the decisions DD-1 to DD-11 are defined in ./source.md (the design) and, in full wording, in the merged requirements at .dev/brainstorms/20261126-115614-git-pm-workflows-skills/merged-requirements.md. A task that needs exact wording (a regex, a refusal text, a line form) reads the cited FR in that file. Where the design adds a decision (DD-n), the design wins, except in the recorded overrides below.
- Recorded overrides, each forced by an existing test or by the real ledger grammar, and each written into the code or text that carries it: DD-8 lists seven ledger line patterns and the ledger reader copies nine (`_HEADER` and `_ARCH` as well, Task 9); requirement T-16 and NFR-005 say the existing implement tests pass unchanged, and that holds except for the new entries of the halt-line allow-list in `tests/skills/test_implement_severity_static.py` that the archive-gate refusal of Task 32 needs and the classification rows of `tests/skills/test_worker_contract.py`; the two new `E-RESUME-NEEDED` reasons are listed in `refs/commit-step.md` only, so the pin in `tests/skills/test_task_workspace_lifecycle.py` stays unchanged.
- Decided scope: the narrowed scope of 2 November is confirmed; the local branch cleanup that PR 711 delivered (`scripts/worktree_cleanup.py`, `_remove_branch` at line 2636, and the `/sc:worktrees` command) is reused and stays unchanged; nothing in this work deletes a remote branch or any local branch.
- Out of scope: a relay through which every command calls `/sc:git`; push, pull, merge, rebase or PR creation in `/sc:git`; nested submodules; new project-management workflows; any change to the level table in `src/superclaude/core/HOW-WE-WORK.md`; any change to `src/superclaude/skills/sc-implement-protocol/scripts/archive_workspace.py` or to the task-ledger grammar.
- `/sc:git` never pushes, merges, fetches on its own or opens a PR. The one exception is `submodule update`, which may clone or fetch from the `.gitmodules` URL on the person's typed, disclosed line (FR-044, NFR-001). PRs stay with `/sc:pr-submit`.
- The `vcs` helper is read-only: it writes no ref, user index, work-tree file or config, and runs git only through one runner with an allow-list. Every repository write is a visible call the agent makes (FR-011, NFR-002).
- Installed primitives (files under `src/superclaude/commands`, `skills`, `agents`, `core`, `hooks`, `templates` and their `plugins/superclaude/` copies) never name a `src/superclaude/...` path: they use `~/.claude/...` with the project copy made by `make sync-dev` as the fallback (FR-009, NFR-010). Edit `src/superclaude/` first, run `make sync-dev`, and keep the `plugins/superclaude/` copies byte-identical: every task that changes a primitive file that has a plugin twin copies the twin and compares it (`cmp`) in the same task, and the last task only verifies. Never stage any file under the project agent-host folder `.claude/` other than its `settings.json`.
- Python runs through UV: `uv run pytest ...` and `uv run --no-project python <script>`. The helper uses the Python standard library only (Python 3.10 or later). New Python passes `uv run ruff check` and `uv run ruff format --check` (CI runs both over `src/` and `tests/`).
- The write-verb scan in `tests/skills/test_worker_contract.py` (`WRITE_VERB_RE` at line 1894, `_scan_write_verbs` at line 1927, `WRITE_VERB_CLASSIFICATION` keyed by file, verb and exact stripped line) covers every file under `src/superclaude/skills`, `commands` and `agents`, scripts included, and also fails on stale rows. New behavior and helper tests live under `tests/vcs/` (real temporary repositories); static text pins live under `tests/skills/` and `tests/commands/`; real-framework hook tests are marked `real_framework` (registered in `tests/vcs/conftest.py` through `pytest_configure`, because `--strict-markers` is on and `pyproject.toml` is not edited) and are skipped when `pre-commit` is not installed (DD-7).
