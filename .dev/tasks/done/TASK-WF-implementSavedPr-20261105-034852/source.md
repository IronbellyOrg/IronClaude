## Why

The fence-fix run (`.dev/tasks/done/TASK-WF-devGuideFenceFix-20261104-204854/`) showed two gaps in the `/sc:implement` rule that compares each saved reviewer prompt with the closed reviewer template:

1. The comparison is byte-exact outside the slots. A hand-filled prompt that dropped one blank line (between "Saved-probe re-check hit locations (may be empty): " and "Do not trust the implementer's report.") blocked the managed archive twice, although no review criterion was added, removed or reworded.
2. There is no recovery path. A saved prompt may never be overwritten, so once a prompt differs from the template, every later FINAL returns `issues`, and the managed archive gate just stops (`E-ARCHIVE-BLOCKED`) with nothing that starts a fix. The package could only archive by an ad-hoc user instruction (here: moving the two prompts to `artifacts/superseded-prompts/` and an `ARCHIVE: Ruling:` line, ledger `progress.md` lines 7-11 of that package). The re-review that preceded the move (a second `complete` line per task with no new `start`, prompts named `prompt-1-2.md` with no repair file) is also not described by the protocol.
3. The earlier package `.dev/tasks/done/TASK-WF-devGuideRefactor-20261104-135403/` holds nine saved prompts (`artifacts/retries/T1/` to `T9/`, each `prompt-1-1.md`) with the same missing blank line; its FINAL passed without noticing.

## What to change

Rule source: `src/superclaude/skills/sc-implement-protocol/refs/qa.md` ("## FINAL derived test"; "## Managed FINAL review (archive gate)"; the "Saved prompts and paperwork-only reviews" bullets under "## Subagent prompt (when not inline)"), `refs/ledger.md` (record forms, Resume), `refs/managed-workspace.md` (the "Completion: fresh FINAL, then archive" steps, "Ledger, artifacts, pins", and the Enforcement-map row for saved reviewer prompts). A. Whitespace tolerance, stated once. The saved-prompts bullet in "## FINAL derived test" is the single statement of the comparison rule. Line 1 of every saved prompt is the task's start sha; FINAL compares the lines after that header and outside the slots. A difference only in blank lines (their number or position) or in trailing whitespace is not a template difference and FINAL records it as a note (cited `noted`); any other difference (a changed, added, removed or reordered non-blank line) stays `issues` (managed) or `FINAL:` evidence (legacy), as today. The first bullet under "Saved prompts and paperwork-only reviews" currently restates the rule ("... and return `issues` (managed) or record it in `FINAL:` evidence (legacy) when they differ"); rewrite that sentence to point to the FINAL derived-test rule instead of restating it, so that after the change the phrase "when they differ" no longer appears in `refs/qa.md`. The Enforcement-map row in `refs/managed-workspace.md` says the same (blank-line and trailing-whitespace differences are a note).

B. Recovery path for a defective saved prompt.
- Trigger, managed. In `refs/managed-workspace.md`, step 6 of "Completion: fresh FINAL, then archive": when every `issues` item of the FINAL concerns a saved prompt (a template difference, a superseded prompt with no later passing saved prompt, or a missing README), the executor runs the recovery below in the same invocation and then repeats the archive gate from step 1 (a new FINAL). The recovery is idempotent: it finishes a half-done move, writes a missing README and runs a missing re-review. The step-6 sentence "do not reopen completed tasks unless the operator says" gains the exception "except the recovery's own re-review of a saved-prompt task", and the existing wording "`issues` → STOP `E-ARCHIVE-BLOCKED`" stays verbatim, with the stop applying only if the recovery cannot finish or the new FINAL still returns `issues`.
- Trigger, legacy. In a legacy run (advisory FINAL), when the FINAL records a saved-prompt template difference in its `FINAL:` evidence, the executor runs the same recovery before printing the final summary. A blocker found by the re-review is recorded in the `FINAL:` evidence and the summary and appends no `blocked` line, because the legacy FINAL never reopens a task.
- Re-review. The executor re-runs that task's review with a template-exact prompt saved as the next unused `j` of the same `k` (`prompt-<k>-<j>.md`), without reopening or reverting the task; it skips the re-review when a later saved prompt of the task already passes the comparison and only moves the defective one. The delta-diff, earlier-findings and re-check slots of that prompt are empty. The reviewed diff is `git diff <the task's start sha from its ledger start line> -- <the paths in the files= field of the task's latest complete line>` plus the full contents of untracked files among those paths; edits by later tasks to the same paths are in the diff and the reviewer judges only this task's acceptance criteria; when the start is not a tree (`nogit` or a HEAD fallback) the paths come from the Q0 tool trace as `refs/qa.md` already says. The reviewed tree is pinned as `r<k>-<j>` and that ref is deleted again when the `complete` line is appended.
- Ledger. A re-review with no blocking finding appends the task's `complete` line again with the same verdict fields as its latest `complete` line and no new `start` line, except that a re-review which writes new notes lines replaces the `notes@` token. A `compliant` task stays `compliant`; a task completed after a user-accepted gap repeats its non-compliant verdict fields unchanged so the accepted gap stays valid (`refs/ledger.md`, "Post-ruling complete line"). In a managed run a re-review with a confirmed blocker appends `blocked` and follows the existing Resume rows.
- Move. The defective prompt is then moved unchanged (never edited or deleted), with an ordinary file move (the "Helper, sole movement path" rule covers packages only), to `<pkg>/artifacts/superseded-prompts/T<id>-prompt-<k>-<j>.md` (managed) or `.dev/implement/<slug>/superseded-prompts/T<id>-prompt-<k>-<j>.md` (legacy), with a `README.md` there naming each moved file, its old path, the FINAL line that flagged it and the replacing prompt. This move is part of the protocol and needs no separate user approval.
- FINAL. Files under `superseded-prompts/` are history and are not compared. FINAL returns `issues` (managed) or records it in `FINAL:` evidence (legacy) when a superseded prompt's task has no later saved prompt (a higher `j` of the same `k`) in `<retries>/T<id>/` that passes the saved-prompt comparison of the FINAL derived test, or when the README is missing.
