# Implementation workflow: apply the three rulesets to the IronbellyGroup repos (issue 838, smallest version)

Source: ./source.md
Goal: Add `scripts/apply_org_rulesets.py`, a one-repo-per-run script with a dry run that prints what would change and an `--apply` step that saves the repo's before state to a file, with its offline tests and an operator page, so the owner can roll the three IronClaude rulesets out to the 17 repos by hand, one repo at a time. No step of this work makes a live call to GitHub. This plan replaces two plans for a full rollout framework that failed review; what was dropped is listed in section 5 of `./source.md`.

## Constraints

- No task calls GitHub or touches any IronbellyGroup repo. Every GitHub call in a test goes through `FakeRunner` of `tests/org_rulesets/conftest.py`; no test starts the real `gh`.
- `.github/rulesets/*.json`, the commands in `docs/developer-guide/branch-protection.md` and `tests/docs/test_branch_protection_rulesets.py` stay unchanged. The only edit to the guide is the one link line of Task 7. The existing test must keep passing.
- Python 3.10, standard library only; ruff rules `E,F,I,N,W,TID` at line length 88 as set in `pyproject.toml`.
- No real private repo name and no real org login is written in any tracked file. Tests use synthetic names such as `acme-one`. The script holds no org or repo name, except the upstream org name it refuses.
- Only these paths may change: `scripts/apply_org_rulesets.py`, `tests/org_rulesets/`, `docs/developer-guide/branch-protection-multi-repo.md`, `docs/developer-guide/branch-protection.md` (one link line) and `docs/developer-guide/documentation-index.md`. Nothing under `.claude/` or `.github/` changes.
- "source.md section 2.3" names a heading of `./source.md`.
- Test setup follows `tests/worktree_cleanup/conftest.py` (the session fixture `wc` at lines 26 to 37 loads the script once; `RecordingRunner` at lines 68 to 109 subclasses the real `Runner` and overrides `_execute`). `tests/org_rulesets/conftest.py` defines the session fixture `orr` (the script module) and every shared fixture exactly once; a test module never imports a fixture from another module, because CI lists fixtures with `pytest --fixtures` and a duplicate crashes it.
- Location rule: the repo root is `Path(__file__).resolve().parent.parent`, the rule files are read from `<root>/.github/rulesets/`, and no function reads the current working folder. The before-state file is written into the folder given with `--out`.
- Choices for the owner's review (all are made inside the scope cut and listed in the pull request): one repo per run; the push check excuses no direct push by a named person; the tag ruleset is applied with a printed warning and a manual check of release workflows; rollback is manual.
- Every task ends with the same checks: `uv run pytest tests/org_rulesets/` passes (plus `tests/docs/test_branch_protection_rulesets.py` from Task 6 on), `uv run ruff check scripts/apply_org_rulesets.py tests/org_rulesets` reports nothing and `uv run ruff format --check scripts/apply_org_rulesets.py tests/org_rulesets` reports nothing.

## Phase 1: Rendering and the command runner

## Task 1: Create the script with rendering, branch set and digest

Create `scripts/apply_org_rulesets.py` with a module docstring, the constants `EXIT_OK = 0`, `EXIT_USAGE = 64`, `EXIT_FAILED = 69` (the values at `scripts/worktree_cleanup.py` lines 96 to 98), `ROOT` and `RULES_DIR` (location rule), and the pure functions of source.md section 2.1: `render_branch(branch)`, `render_tags()`, `branch_set(default_branch, existing)`, `plan_bodies(branches)` (the tag body first, then `integration`, then `master`, then any other default branch) and `payload_digest(bodies)` (sha256 of the canonical JSON, sorted keys and fixed separators, of the bodies in that order). Also add `compare_bodies(rendered, remote)` as in section 2.4: it compares `name`, `target`, `enforcement`, `conditions`, `bypass_actors` as a set and `rules` as a set of type plus complete parameters, ignores only the server metadata keys named in one constant, and returns a list of difference descriptions, empty when equal.

Create `tests/org_rulesets/__init__.py`, `tests/org_rulesets/conftest.py` with the session fixture `orr` (loads the script with `importlib.util.spec_from_file_location("apply_org_rulesets", ROOT / "scripts" / "apply_org_rulesets.py")`, registered in `sys.modules`) and `tests/org_rulesets/test_render.py`.

Acceptance criteria:
- `render_branch("master")` and `render_branch("integration")` equal the parsed `protect-master.json` and `protect-integration.json`; `render_tags()` equals the parsed `protect-release-tags.json` and holds the rule types `deletion`, `non_fast_forward` and `update`.
- A branch name that is empty, contains `*` or `~`, or starts with `refs/` raises; no rendered body contains the text `~DEFAULT_BRANCH`.
- `branch_set` returns the expected set for three cases: default `master` only; default `main` with no `integration`; default `integration` with `master` present. It never repeats a name.
- `plan_bodies` returns the order tag, `integration`, `master`, other default branch.
- `payload_digest` is equal for equal input and differs when any body changes or the order changes.
- `compare_bodies` returns an empty list for identical bodies and for a remote body that adds only the ignored metadata keys, and a non-empty list naming the difference for an extra rule, an extra bypass actor, a changed `required_approving_review_count`, a changed `enforcement`, a changed ref and an unknown extra top-level key; rule and bypass-actor order do not matter.
- With the working folder changed to an empty temporary folder, `render_branch` and `render_tags` return the same bodies.
- The closing checks of the Constraints pass.

## Task 2: Add the allowlisted Runner and the shared FakeRunner

Depends on: Task 1

Add to `scripts/apply_org_rulesets.py` the types `Result(returncode, stdout, stderr)`, `CommandRecord(argv, stdin_name)` (it keeps the `name` of a posted body, not only a count), `RefusedCommand` and `Runner(read_only=False)`, modelled on `Runner` in `scripts/worktree_cleanup.py` (lines 246 to 586), as in source.md section 2.2. `Runner.run(argv, stdin=None)` does four things in order: `check_allowed` (a positive allowlist of the `gh api` shapes listed in section 2.2, all under `repos/<org>/<repo>`), the read-only check (refuses POST), appending a `CommandRecord`, and one call to `_execute(argv, stdin)`. `_execute` is the only method that starts a process; it passes the named constant `TIMEOUT_SECONDS` to `subprocess.run` and turns `subprocess.TimeoutExpired` into the one named result `TIMED_OUT` (a `Result` with return code 124), never a hang. Add `check_org(org)`, which refuses an empty value and the upstream org name `SuperClaude-Org` in any letter case.

Extend `tests/org_rulesets/conftest.py` with `FakeRunner(orr.Runner)` (built inside a session fixture `fake_runner_cls`) that overrides only `_execute`. Its answers are keyed by method and path; an answer may be a callable that receives argv and stdin, or a list served in order, so three POSTs to `rulesets` can return three ids. An answer with no canned reply gets return code 127. Create `tests/org_rulesets/test_runner.py`.

Acceptance criteria:
- A call outside the allowlist, an empty argv and a path with an option-like segment raise `RefusedCommand` when sent through `FakeRunner`, and the overridden `_execute` is never reached (a counter on the fake stays 0).
- A read-only runner refuses POST; a normal runner accepts POST only for `rulesets` under `repos/<org>/<repo>`.
- `check_org("SuperClaude-Org")`, `check_org("superclaude-org")` and `check_org("")` raise; `check_org("acme")` passes.
- Every accepted `gh api` call recorded by the fake is one of the allowed shapes and names `repos/<org>/<repo>` in full.
- A test replaces `subprocess.run` with a stub: a `subprocess.TimeoutExpired` gives the result `TIMED_OUT`, and the timeout argument passed equals `TIMEOUT_SECONDS`.
- The closing checks of the Constraints pass.

Create `tests/org_rulesets/test_checks.py` using `FakeRunner`.

Acceptance criteria:

## Task 4: Add the dry-run report and apply

Depends on: Task 1, Task 2, Task 3

Add `dry_run_report(...)` and `apply_repo(runner, org, repo, out_dir, confirm, now)` to `scripts/apply_org_rulesets.py` as in source.md sections 2.3 step 4 and 2.4. `dry_run_report` assembles and returns the printed lines from the results of Task 3: repo facts, the push-check result per branch with its evidence count, the existing state, the count of `v*` tags with a warning line that the tag ruleset blocks moving and deleting tags so release workflows must be checked by hand first, the rulesets that would be created in order (a same-name ruleset already present is listed as skipped), the digest from `payload_digest` and the exact apply command. `dry_run_report(runner, org, repo, now)` itself calls `read_repo`, `check_push` and `read_existing`. `apply_repo` carries no state from the dry run: it calls the same three functions again and recomputes the digest of all rendered bodies in order (a skipped same-name ruleset does not change the digest). It refuses, with the failed check named and no write call, unless `confirm` equals that digest, the push check is `pass`, no branch has classic protection, the repo has no refusal reason and `out_dir` is given. Then it writes `<repo>-before.json` into `out_dir` once (it must not exist; it holds the full body of every existing ruleset read by id and the protection state of each branch of the set, a 404 recorded as the string `"none"`, a 403 raises and writes nothing); then for each body in order, skipping a body whose name is already present, it POSTs the body (`name` is recorded in the `CommandRecord`), reads the ruleset back by id and compares it with `compare_bodies`; it stops at the first failure and returns what was written. A `TIMED_OUT` POST is followed by one list call before any other call, a matching same-name ruleset is adopted, and a POST is never repeated. It returns the ids by name and the one-line comment text for issue 838 (repo, date, ids by name); it never posts the comment and never makes a call that names the ruleset ids 28081842, 28081844 or 28081845. It also returns the manual rollback commands, one `gh api --method DELETE repos/<org>/<repo>/rulesets/<id>` per id it created.

Create `tests/org_rulesets/test_apply.py`.

Acceptance criteria:
- A dry run makes no POST call and its lines contain every item listed above.
- `apply_repo` with a wrong `confirm`, a push check of `blocked` or `incomplete`, classic protection, an archived repo or no `out_dir` makes no write call and no file, and names the failed check.
- The recorded call order is tag ruleset, then `integration`, then `master`, each read back before the next write; three POSTs get three different ids from the fake.
- `<repo>-before.json` holds complete bodies even when the list call returns summaries without `rules`; a second `apply_repo` for the same repo and folder refuses because the file exists, before any write.
- A read-back mismatch stops the run after the first ruleset and the returned result lists only what was written; a non-success POST does the same.
- A `TIMED_OUT` POST is followed by a list call and never by a second POST; a matching same-name ruleset found by that list is adopted.
- A same-name ruleset already present gets no POST and no PUT; the fake records no PUT and no DELETE in any test.
- The comment line and the rollback commands contain the created ids.
- The closing checks of the Constraints pass.

## Task 5: Add the command line and main

Depends on: Task 4

Add `parse_args` and `main(argv=None, env=None, runner=None, now=None)` to `scripts/apply_org_rulesets.py` and the `if __name__ == "__main__"` guard, in the shape of `main` in `scripts/merged_pr_log.py` (line 622), as in source.md section 2. Options: `--org` (required, no default, through `check_org`), `--repo` (required, exactly one), `--out`, `--apply` and `--confirm`. Without `--apply` it builds a read-only runner and prints the dry-run report; with `--apply` it builds a runner that may POST and calls `apply_repo`, then prints the ids, the comment line and one rollback DELETE command per created id (on a failure, what was written before the stop). A runner passed in (tests) is used as given. Exit codes: `EXIT_OK`; `EXIT_USAGE` (64) for usage errors (a missing `--org` or `--repo`, the upstream org name, a list of repos, `--confirm` without `--apply`, `--apply` without `--confirm`); `EXIT_FAILED` (69) for a refusal or a failed step, with the failed check named on stderr.

Create `tests/org_rulesets/test_cli.py`.

Acceptance criteria:
- A missing `--org`, an upstream org name in any letter case, a missing `--repo`, two `--repo` values, `--apply` without `--confirm` and `--confirm` without `--apply` exit with `EXIT_USAGE`.
- A refusal in `--apply` exits with `EXIT_FAILED` and the stderr text names the failed check.
- A successful fake `--apply` prints the comment line and one DELETE command per created id; a read-back failure prints the one written id and exits `EXIT_FAILED`.
- A dry run of a synthetic repo through `main` exits `EXIT_OK`, prints the digest, and records no POST.
- A full fake run of a dry run and then `--apply --confirm <printed digest>` records, across all calls, only the allowed shapes: repo-scoped `gh api` calls name `<org>/<repo>` in full, none contains `SuperClaude-Org` in any letter case, and none writes to the ruleset ids 28081842, 28081844 or 28081845.
- `main` run with the working folder changed to an empty temporary folder finds the rule files and gives the same digest.
- The closing checks of the Constraints pass.
