# Fix sprint-recovery stranded-deliverables + stale-checkpoint data-integrity defects

## Task Overview

The SuperClaude sprint recovery flow (`superclaude sprint rerun-tasks` merge-back plus the post-merge `superclaude sprint verify-checkpoints --recover` auto-invoke) carries two confirmed, silent data-integrity defects. Both were reproduced live on disk in `/config/workspace/TUIBBS-scp` (Phase 12 / T12.09, recurring across Phase 13 T13.02/T13.06/T13.17) and diagnosed to exact `file:line` anchors in the troubleshoot REPORT and the four research files under this task's `research/` directory.

**Defect 1 (stranded deliverables, false SUCCESS):** A rerun executes in an isolated sub-config with `release_dir=bundle` and a sub-index that pins `TASKLIST_ROOT` to the bundle directory, so rerun agents write declared deliverable trees (`artifacts/<D-ID>/`, `evidence/<TASK>/`) into the bundle root. `merge_recovery_bundle` only reconciles the three `results/phase-N-*` file families — it never copies the deliverable trees back to canonical and never checks that they landed. The `failures` list therefore stays empty and the merge reports `status: success, failures: []` while real deliverables remain stranded inside `results/rerun-*/`. The fix adds a new merge step that relocates the deliverable trees to the canonical TASKLIST_ROOT and fails loudly (appends to `failures`, downgrading status to PARTIAL) when a declared/produced tree fails to land.

**Defect 2 (stale checkpoint verdict, un-closeable phase):** After a successful task recovery, the gated end-of-phase checkpoint stays FAIL/BLOCKED because `recover_missing_checkpoints` only regenerates *missing* report files (it short-circuits and returns any existing file unchanged) and never re-evaluates an existing stale verdict. The fix adds a PRIMARY path that re-runs the runnable end-of-phase checkpoint task after a successful merge (producing a fresh real verdict that Fix 1 then lands canonically) plus a FALLBACK re-stamp path (`--reevaluate-stale`) that converts a stale FAIL/BLOCKED to `UNKNOWN`/Auto-Recovered (NEVER auto-PASS) when no runnable checkpoint task exists.

This task modifies four CLI Python files under `src/superclaude/cli/sprint/` and adds two regression tests under `tests/sprint/`. It is a code-modifying task: it runs the sprint unit-test suite, lint, and format; passes a final structural QA gate; and ends with an independent post-execution reflection gate before being marked Done.

## Key Objectives

The following objectives MUST be achieved by this task:

1. **Fix 1 — relocate + verify deliverables (recovery.py):** Add a new merge step to `merge_recovery_bundle` that copies the rerun's TASKLIST_ROOT deliverable trees (`artifacts/`, `evidence/`, and `checkpoints/` if present) from the bundle root to the canonical TASKLIST_ROOT (`source_index.parent`), preserving any clobbered canonical file as `.failed-<mtime>`, and appends a `deliverable-not-landed:<task>:<rel>` entry to `failures` (downgrading status to PARTIAL) for any declared/produced tree that does not land — so stranded deliverables can NEVER be silently reported as SUCCESS.
2. **Fix 1 caller wiring (rerun_tasks.py):** Thread the affected tasks' declared deliverables into `merge_recovery_bundle` via a new optional `expected_deliverables` parameter (default None preserves current behavior), computed at the merge call site from `_declared_deliverables(phase_obj.file, tid)` for each `tid` in `resolved`.
3. **Test A — Defect 1 regression (test_recovery.py):** Add a test that builds a bundle holding deliverable trees at the bundle root, runs the merge, and asserts the load-bearing coupling: EITHER the trees landed in canonical with content preserved AND status SUCCESS, OR status is PARTIAL with a non-empty `failures` audit entry — never the current "stranded but SUCCESS" outcome.
4. **Fix 2 — stale-checkpoint re-evaluation (checkpoints.py + commands.py + rerun_tasks.py):** Implement the PRIMARY post-merge checkpoint re-verify (re-run the runnable end-of-phase checkpoint task) and the FALLBACK `--reevaluate-stale` re-stamp path (stale FAIL/BLOCKED → `UNKNOWN`/Auto-Recovered, never auto-PASS), honoring the `UNKNOWN`-not-PASS hard constraint and pinning the regenerated/re-stamped report where `_check_checkpoint_pass` reads it.
5. **Test B — Defect 2 regression (test_checkpoints.py):** Add a test that seeds a stale `status: fail` checkpoint with fresh passing evidence and asserts the stale verdict is re-stamped (not left verbatim), PLUS a paired negative test asserting that tasks still failing ⇒ checkpoint FAIL preserved.
6. **Validation + gates:** All modified files pass `make lint` and `make format`; `uv run pytest tests/sprint/ -v` passes with the two new regression tests green; a final structural QA gate passes; and an independent POST `/sc:reflect` gate is surfaced before the task is marked Done.
