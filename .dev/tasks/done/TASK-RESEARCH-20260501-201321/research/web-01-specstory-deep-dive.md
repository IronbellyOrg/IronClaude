## Question 1 (cont.) — On-disk format & capture mechanics (HIGH)

**Source:** docs.specstory.com FAQs — reliability HIGH (official).

- **Output file format on disk: Markdown** (`.specstory/history/*.md`). The `docs/overview` page also confirms "conversations saved as Markdown."
- Capture mechanism is **per-tool, not generic**:
  - **Cursor** — reads the local Cursor SQLite database `state.vscdb` and converts to Markdown.
  - **Copilot (VSCode)** — reads local `chatSessions` JSON files.
  - **Claude Code** — `specstory run` wrapper launches Claude Code, then reads its JSONL transcripts at `~/.claude/projects/` and converts to Markdown in `.specstory/history/`.
  - (CLI providers for Codex / Cursor CLI / Droid / Gemini follow the same wrapper-and-translate pattern.)
- **Tool calls captured?** Inferable: because Claude Code's `~/.claude/projects/` JSONL contains tool-use blocks, the Markdown conversion can preserve them — but the docs do not state explicitly which fields the converter retains. The FAQ explicitly notes "formats differ by tool and can change," so fidelity is per-source.
- **Round-trip back into the editor: NOT SUPPORTED** today. SpecStory does not write to Cursor's `state.vscdb` or Copilot's chat storage — workaround offered is "reference the saved markdown file in your prompt." This is a major architectural fact: SpecStory is a one-way capture pipeline, not a two-way memory layer.

## Question 2 — Sync mechanics (HIGH where stated)

**Source:** docs.specstory.com (Cloud overview) + GitHub README + API docs.

- **Trigger:** opt-in only — sync runs when user runs `specstory sync` (backfill) or `specstory run` while logged in (live push); editor extensions expose equivalent commands. "Private by default, nothing syncs until you explicitly run it."
- **Direction:** push from local → cloud. (Pull / merge from cloud → local is not advertised; cloud is the authoritative searchable hub, local is the source of truth for capture.)
- **Conflict resolution:** **Not documented.** Given session files are immutable Markdown transcripts indexed per-project per-time, conflicts are unlikely by design.
- **Encryption:** **Not documented** in any page reached. Likely standard TLS for transport; at-rest encryption not explicitly claimed.
- **API endpoint base:** `https://cloud.specstory.com` (REST + GraphQL).

## Question 3 — Cloud schema & search interface (HIGH — semantic confirmed)

## Question 4 — Cloud API surface (HIGH)

**Source:** docs.specstory.com/api-reference/introduction.

- **Base URL:** `https://cloud.specstory.com`
- **Auth:** Bearer token from API keys at `/settings/api-keys` (no OAuth yet).
- **Protocols:** REST + GraphQL. Response formats: JSON and Markdown. ETag caching supported.
- **GraphQL endpoint:** `https://cloud.specstory.com/api/v1/graphql`
- **Rate limits:**
  - REST: **1000 req/hour/key**
  - GraphQL: **500 queries/hour/key**
  - Headers: `X-RateLimit-Limit`, `X-RateLimit-Remaining`, `X-RateLimit-Reset` (UTC epoch seconds)
- **REST endpoints (Projects):** `GET list-projects`, `PATCH update-project`, `DELETE delete-project` (note: no Create — projects appear to be auto-created by sync).
- **REST endpoints (Sessions):** `GET list-sessions`, `GET get-recent-sessions`, `GET get-session`, `HEAD check-session` (cheap existence check — useful for sync dedup), `DELETE delete-session`. **No POST for create** — write path is exclusively via the CLI / extension sync, not direct API upload.
- **GraphQL:** offered for richer querying with examples in docs.
- **SDKs:** Not yet released. **Coming soon: JavaScript/TypeScript, Python, Go.**
- **Webhooks:** **Not mentioned** — likely not available.
- **Errors:** Error Handling section exists at `/api-reference/errors`; specific schema not extracted.

## Question 5 — Agent Skills feature scope (HIGH)

**Source:** github.com/specstoryai/agent-skills — reliability HIGH (official OSS, Apache-2.0).

- **License:** Apache-2.0.
- **Distribution:** Skills CLI (`npx skills add ...`), git clone, submodule, or fork.
- **Cross-agent:** Works across Claude Code, Cursor, Codex, Gemini, Copilot.
- **Six published skills** (as of 2026-05-01):
  1. **specstory-guard** — pre-commit secret scan over `.specstory/history/` files.
  2. **specstory-link-trail** — collect/report URLs visited during AI sessions.
  3. **specstory-organize** — reorganize history files into year/month directory structure.
  4. **specstory-project-stats** — pull project metrics from SpecStory Cloud (uses Cloud API).
  5. **specstory-session-summary** — standup-style summaries of recent sessions.
  6. **specstory-yak** — detect "yak shaving" / goal-drift / rabbit-hole patterns in sessions.
- **How they consume history:** Read/parse local Markdown in `.specstory/history/` (5 of 6 skills) or call Cloud API (1 of 6 — `project-stats`).
- **No retrieval / RAG / memory-injection skill exists.** The skills are *post-hoc analysis* on captured history — they do not feed history back into a live prompt.
- **Implication:** "Agent Skills" is a side-channel summarization/hygiene layer, not the missing RAG primitive.

## Question 4 (cont.) — API auth & errors deep detail (HIGH)

**Source:** docs.specstory.com/api-reference/authentication & /errors.

- **Auth:** JWT Bearer (`Authorization: Bearer YOUR_API_KEY`). Headers also: `Content-Type: application/json`, `Accept: application/json`.
- **Key creation:** Cloud → Settings → API Keys → Generate.
- **Storage convention:** env var `SPECSTORY_API_KEY`; never commit.
- **Expiration:** No fixed lifetime documented; recommended **rotation every 90 days**.
- **Revocation:** Immediate; revoked keys produce 401.
- **Permission scopes:** No granular OAuth-style scopes — keys are user-scoped (403 = trying to access another user's resources).
- **GraphQL auth:** Same Bearer scheme on `/api/v1/graphql`.
- **Status codes returned:** 200, 304 (ETag match), 400, 401, 403, 404, 429, 500, 502, 503.
- **REST error shape:** `{ "success": false, "error": "<message>" }`.
- **GraphQL error extensions.code values:** `UNAUTHENTICATED`, `FORBIDDEN`, `NOT_FOUND`, `VALIDATION_ERROR`, `RATE_LIMITED`.
- **Retry guidance:** No retry on 4xx (except 429 honoring `X-RateLimit-Reset`); exp-backoff on 5xx, max 3 attempts.

## Key External Findings

- **Architecturally local-first**: `.specstory/history/*.md` is the canonical artifact, written by per-tool capture adapters that translate from Cursor SQLite / Copilot JSON / Claude Code JSONL into uniform Markdown. Cloud is a downstream searchable index, not a write-master.
- **One-way pipeline**: SpecStory does **not** write back into editor chat storage; "import history into editor" is explicitly unsupported. This is the core architectural reason it is *not yet* a RAG product.
- **OSS surface is the CLI + provider plugins (Apache-2.0)**; IDE extensions and the Cloud server are closed source. AIrgap is a separate OSS guardrail tool.
- **API**: REST + GraphQL on `cloud.specstory.com`, JWT Bearer auth, **read-mostly** (no POST to create sessions — write path is sync-only), 1000/hr REST + 500/hr GraphQL limits, ETag + Markdown-or-JSON responses. No SDK shipped (JS/Py/Go coming soon). No webhooks.
- **Cloud search is hybrid lexical + semantic** with project + time-range filters, organized as a "personal cross-repo knowledge hub."
- **Team product is pre-revenue / design-partner stage**: no public pricing, no published RBAC/audit-log, single-user workspaces today, team collaboration on roadmap. Teams page = Design Partner CTA.
- **RAG is roadmap-shaped but not concretely scoped**: "AI knowledge base" / "memory retrieval" appear in beta-site/landing language; no shipping retrieval-into-prompt feature today; no published timeline.
- **Agent Skills (6 skills, OSS Apache-2.0) are post-hoc analyses** of stored history (yak detection, summary, organize, link-trail, guard secret-scan, cloud project-stats). None retrieves history into a live prompt.
- **Capture fidelity is per-tool and "may change"** — a structural risk for downstream consumers expecting stable schema.
- **Free for individuals today** (extension + CLI + cloud); team tier monetization not yet executed.

## Recommendations from External Research

1. **Treat SpecStory as the *capture* baseline, not the *RAG* baseline.** Its core competency is multi-tool conversation capture into uniform Markdown — comparables on the capture axis are limited, but on RAG they are not. Benchmark RAG-roadmap claims against shipping memory-layer products (Mem0, Letta/MemGPT, Zep, Cursor Memory, Cline Memory, Continue.dev memory, etc.).
2. **The local-first Markdown corpus is reusable.** Any custom architecture can adopt SpecStory as the *capture layer* (its hardest engineering problem — per-tool adapters) and bolt its own RAG/memory/team layer on top using either the Cloud REST/GraphQL API or by reading `.specstory/history/*.md` directly. This significantly de-risks build-vs-buy.
3. **Watch for the SpecStory team-tier release** — it will define their RBAC/audit/workspace model. If the team release lands cheap and feature-rich, build-on-top becomes attractive; if it lands expensive or shallow, in-house team aggregation has a clear lane.
4. **The "MCP integration" mention on the cloud landing is the likely RAG delivery vector.** When SpecStory ships an MCP server exposing the cloud's hybrid-search, that becomes their RAG product — comparables analysis should explicitly track shipping memory-MCP servers (e.g., Mem0 MCP, Zep MCP) as the head-to-head set.
5. **Capture fidelity is a structural risk.** "Formats differ by tool and can change" means any architecture depending on tool-call-level fidelity should not assume SpecStory preserves it. If tool-call traces are required for the broader system, plan a parallel capture path (e.g., Claude Code transcript JSONL ingest direct from `~/.claude/projects/`, bypassing SpecStory's lossy Markdown).
6. **API ergonomics are reasonable but not write-friendly.** No POST-create for sessions means external systems cannot inject synthetic conversations into the SpecStory cloud — they must run through `specstory run` / `specstory sync`. Plan integrations accordingly.
7. **Pricing opacity is a procurement risk.** A team rollout can't be costed today without a design-partner conversation with SpecStory directly. Time-box that intake before anchoring architecture decisions on it.
