Read-only operating-system contract verification:
1. POSIX Issue 8 wait/waitpid:
https://pubs.opengroup.org/onlinepubs/9799919799/functions/wait.html
The functions only return status on an immediate child process. A process-group selector still selects only child processes in that group. ECHILD covers a target that is not a child of the calling process.
2. Apple BSD waitpid manual:
https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man2/waitpid.2.html
Waitable processes must be the caller's children; nonchild requests yield ECHILD. If a parent terminates without waiting, its remaining children are assigned parent PID 1. This archived Apple manual is corroborating platform documentation, not a test run on current macOS.
3. Linux waitpid:
https://man7.org/linux/man-pages/man2/waitpid.2.html
Orphaned descendants are adopted by init or the nearest registered subreaper; the adopting parent can wait for them. Sending a signal to a process group is not collection of exit status.
4. Linux PR_SET_CHILD_SUBREAPER:
https://man7.org/linux/man-pages/man2/PR_SET_CHILD_SUBREAPER.2const.html
Setting the calling process's subreaper state makes it eligible to adopt orphaned descendants and wait for them. The API is Linux-specific (since Linux 3.4), not POSIX/macOS portable. No such state was changed in the developer process or a test helper during this pass.

Why no portable narrow fix is offered:
A surviving wrapper without adoption privileges still cannot wait for nonchild grandchildren after their immediate parent exits. Repeated waitpid calls, negative process-group selectors, polling and killpg cannot convert those nonchildren into waitable children. Keeping a top-level wrapper alive also cannot prevent arbitrary upstream descendants from exiting, reparenting or creating new sessions. A stronger Linux-specific helper would require a separately designed adopter; it does not provide a macOS/std-library solution. Changing host-wide process behavior or introducing OS-specific supervision/containment would exceed the permitted minimum implementation and the explicit fix-pass constraints.

Requested regression boundary:
Executing the requested orphan scenario without a controlled adopter would make final zombie collection depend on external PID1. Claiming that a wait failed with ECHILD or that a process is a zombie as proof it was reaped would be false. Installing a test-only adopter would change the relevant ownership conditions and would not establish a portable product guarantee. Accordingly no weakened, mocked-signalling or external-PID1-dependent passing regression was added.
