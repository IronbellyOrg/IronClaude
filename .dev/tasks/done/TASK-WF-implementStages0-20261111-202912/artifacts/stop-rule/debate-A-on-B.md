## 1. Where B is better than A and should be adopted (3)

**B-1. Detect safety event 3 at the run boundary, not at grading.**
B has the operator mechanically re-read every certified `file:line` citation after each run (`B:62`, item 3). I deferred event 3 to the blinded grader after the last block (A: S-1.1, S-1.4), which means a panel that certifies unsupported citations would run all 12 blocks, spending up to the full C-5 upper bound of 2,616k (`pd:131`), before anyone sees a failure that T-5 says is fatal regardless of savings (`src:530`). The re-read is mechanical, needs no grader judgment, and the operator already knows arm identity, so blinding (`src:532`) is not touched; B also keeps graders blind explicitly (`B:91`). Adopt B's detector; keep my halt scope for arms C and D.

**B-2. Treat T-4 as descriptive at pilot size.**
B points out that with 12 runs per arm the p95 is effectively the largest run (0.95 x 12 = 11.4, so the 12th ranked value; `B:27`, `B:78`). I missed this, and it matters more under my own I-2: I count a killed run as above T-4 (A: S-3.1), so a single kill in 12 arm-C runs would "fail" H-C in the pilot. The pilot does not decide H-B (`src:536`) and should not decide H-C on one run either; the H-C verdict belongs to the confirmatory run, and Stage 3 entry needs H-C passed (`src:411`) on that run. Adopt B's sentence at `pd:146` (`B:105`, edit 7) together with my killed-run counting.

**B-3. A fixed stop record with precedence and a list of contents.**
My proposal ends with one sentence on what a stop report contains (A: last line of the replacement text). B gives a numbered record written before any other action (`B:80-89`): rule id, threshold id and observed value, run id and position, spend per unit and per arm, detector output, in-flight runs, which of d_AB, d_BC and d0 remain estimable, co-firing rules, and the owner's answer. The current section says only "report to the owner" (`pd:187-188`), which is the defect both of us named; B's record is what makes a stop auditable and lets the owner re-plan the confirmatory request (`pd:197`). Adopt it in place of my last sentence. Also adopt B's explicit precondition that the owner sees the Stage 0 exit state (FAIL on conversion, `pd:171`, `pd:226`) before run 1 (`B:45`); my S-2.1 approvals omitted it.

## 2. B's three strongest weaknesses

**W-1 (blocking). B's information checkpoints pause the pilot on the outcomes it is meant to measure.**
(a) The plan-6 noise check pauses when d0 >= 0.8 x d_BC (`B:73`). For H-B, which is a non-inferiority test of panel against legacy (`src:528`), d_BC close to d0 is exactly what parity predicts: two engines that behave alike disagree about as much as one engine disagrees with itself. B's checkpoint therefore fires on the good outcome and puts a stop decision in front of the owner on it. The source states T-6 as a reading of the pilot's estimate (`src:538`), not an interim check, and B's own note concedes that with 3 repeats the value is "rough" (`B:73`). (b) The plan-4 headroom check pauses when arm-A recall is above 0.85 (`B:71`). The arithmetic is right (T2 cannot beat T1 by T-1 if T1 exceeds 0.85), but that outcome is a valid H-A result, not an uninformative pilot: the source says to record that "the T2 spend does not buy recall on plans" and hand the owner the O-8 choice (`src:527`, `pd:32`). At 20 defects the estimate is also too noisy to act on (own arithmetic: SE of a proportion near 0.85 at n = 20 is sqrt(0.85 x 0.15 / 20) = 0.080). Both checkpoints are interim futility looks that `src:536` (the pilot estimates, it does not decide) does not support, and both need interim grading, which is the blinding exposure B then has to police with a third checkpoint (`B:72`). The only part worth keeping is the floor case (arm-A recall 0: seeding broken), and that is better done as a dry run on one seeded plan before run 1, not mid-pilot.

**W-2 (blocking). S-4's run-validity rule conflicts with the pilot design and rests on invented numbers.**
(a) S-4 counts a null convergence score as an invalid run (`B:56`). The pilot design says the opposite: "a null score in an arm-B or arm-C run is still recorded as a T2 outcome" (`pd:173`), and 8 of the recorded legacy T2 runs carry one (`pd:173`), so S-4 would pause on legacy baseline behaviour, the same failure B correctly criticises in rule 1 (`B:21`). S-4 also counts MALFORMED as invalid, which arm B produces today (B's own scope note, `B:61`). (b) "2 or more of the first 4 runs of any one arm" (`B:56`) is a placeholder B admits is a round number (`B:114`); each arm runs once per plan, so "the first 4 runs" exist only at plan 4 and the rule cannot fire again "at the end of a plan" after that. (c) The retrieval watch at 1.5 x (R-2 + R-3 + R-4) (`B:63`) is another unsourced multiplier (`B:114`). (d) Consistency edit 6 says the 72-run reading moves the ceiling "from 2.62M to about 5.0M" and then computes 7,236k in the same sentence (`B:104`); 5.0M is C-4 alone (72 x 70k = 5,040k, `pd:134`), not the pilot total. The document's reading rules forbid new numbers without a stated derivation (`pd:9`, `pd:11`).

**W-3 (blocking). The safety scoping has no consistent principle and leans on a citation that does not hold.**
(a) B's reason for logging MALFORMED in arm B is that it is legacy baseline (`B:61`), but S-1 STOPs on item 1 (forbidden model or executor-class collision) in any arm, arm B included (`B:53`), with no argument that the legacy rotation cannot collide. If baseline behaviour should not end the pilot, item 1 in arm B should be logged like item 2; if it should, item 2 should too. (b) S-2 scopes items 2 and 3 to "an arm that is not legacy" (`B:54`), which leaves arm A (T1, an unchanged legacy path) inside the halt scope for MALFORMED and certified citations, so a T1 baseline event pauses the panel arms. (c) B's evidence for legacy MALFORMED is `SKILL.md:666` via `src:519` (`B:10`, `B:21`, `B:61`). Line 666 of the current `SKILL.md` is about agents deliberately not introduced, and a search for "2-of-3", "reviewer-shortfall" and "fewer than 3" finds no such rule. The conclusion survives on other evidence (4 recorded illegal `merge_method` values, `pd:173`, which `SKILL.md:837` defines as MALFORMED), but B cites the unverified line three times. Smaller: `B:112` cites `src:411` for the default `/sc:workflow` budget being unset, but `src:411` is the Stage 3 row; the default-call description is at `src:142`. And B's ceiling rule (at least C-5's upper bound, `B:63`) is a floor with no maximum, after B's own D-2(a) argued that a worst-case ceiling "fires after the money is gone" (`B:24`); the projection warning (`B:65`) is the actual brake, and it is a PAUSE, not a STOP.

Partly answered B open point: B asks whether the `shadow` form of arm C runs both engines and so costs more than 35k-70k (`B:111`). `src:410` says shadow writes the panel resolution next to the legacy rotation and keeps the legacy debate authoritative, which reads as one set of reviewers plus a resolution file, not two runs. That lowers the cost worry but raises a different one outside the stop rule: a shadow-form arm C would measure legacy behaviour, not panel-fed T2.

## 3. What I would drop from my own proposal

1. **The one-rerun allowance (A: S-3.2).** It is an invented number (I said so in A's open item 8), and B's simpler treatment, no retry, record and score, avoids it (`B:64`). A crashed or contract-less run becomes a recorded failed run whose seeded defects score as not found in that arm. That is conservative against the arm that fails more, which is the safe direction for a non-inferiority question (`src:528`), and it removes a cost path from the ceiling.
2. **Deferring safety event 3 to the grader (A: S-1.1 and S-1.4).** Replaced by B's run-boundary re-read (B-1 above). S-1.4 shrinks to "an event 3 the re-read missed and the grader finds still fails T-5".
3. **The 89% illustration in my D-1.** It assumes the 4 illegal `merge_method` values all fall within the 34 recorded merged verdicts and that the recorded rate carries over to seeded plans; neither is established (`pd:170`, `pd:173`). The defect stands on the qualitative evidence (legacy produces MALFORMED today, `pd:173` with `SKILL.md:837`); the number adds false precision and should go.
4. **The closing one-line stop report in my replacement text.** Superseded by B's stop record (B-3 above).

What I keep against B: block run order with repeats early and the spend check only between blocks (both proposals converge here, `B:47`; I keep blocks 1-6 for the repeats so d0 exists earlier than B's plans 2-12 spread, though B's spread is also acceptable); no interim recall, precision or T-6 look (W-1); S-1 scope by code path, with arms A and B logged for items 1-3 and halted only for items 4 and 5 (W-3 a and b); the stated retrieval ceiling from a whole-pilot R-6 row instead of B's 1.5x watch (W-2 c); and the per-SD-3-reading ceiling values, with B's projection warning added as a PAUSE before the block-start forecast check.
