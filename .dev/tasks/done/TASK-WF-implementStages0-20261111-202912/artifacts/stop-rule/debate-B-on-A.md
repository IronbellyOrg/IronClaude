## 1. Where A is better than B and should be adopted

**1.1. Plan-block run order (A:44, A:10) beats my run order.**
My rule cancels in-flight runs on S-1 and spaces the 6 repeats after plans 2, 4, 6, 8, 10, 12 (B, "Run order"), so a stop can leave a plan with arm B but not arm C, and at plan 6 only 3 repeats exist, which I admitted is rough. d is defined per defect, paired across arms on the same plans (`pd:75`, `src:536`), so a half-run plan produces no pair. A runs one block per plan, starts a block only after the previous one finished, and puts one repeat in each of blocks 1-6, so every stop leaves complete pairs and d0 is estimable from block 6 (A:44). This is the more useful property for an owner whose aim is the estimate (`pd:71`). Adopt A's S-0.

**1.2. A handles runs that end without a result (A:63-67); mine does not.**
I covered only a run aborted at the kill line (B, note 4). I missed crashes, timeouts and no-contract runs. A names the real failure modes: unbounded rerun loops until the ceiling fires, and silent gaps that bias H-B toward the panel when arm C fails more often (A:27). That is a gap in `pd:189` that I did not list. Adopt S-3, with the corrections in 2.2.

**1.3. A forbids interim recall and fixes grading after the last block (A:71), and its evidence for the legacy-MALFORMED defect is verifiable. Mine is partly wrong.**
(a) My checkpoints (B, table "Checkpoints") compute arm A recall at plan 4 and d0 against d_BC at plan 6. That is interim, per-arm scoring by the operator, which breaks the blinding the source requires (`src:532`) and invites exactly the look that the source says is underpowered (60 defects: about 79% power at d = 0.10, 54% at d = 0.20, `src:536`; 69% and 45% with clustering, `pd:99`). A's S-4 is the correct hygiene. (b) I cited `SKILL.md:666` for "2-of-3 run is MALFORMED" by copying `src:519`. I checked now: `SKILL.md:660-668` is about merge-judge selection and agents not introduced, so that citation is wrong or stale; I had not verified it. A's evidence is better: `pd:173` (4 recorded T2 runs with an illegal merge_method) plus `SKILL.md:837` (such a value is MALFORMED), and its 18-run illustration (A:21). My D-1(a) conclusion stands on that evidence, not on mine. Adopt A's evidence and its S-4 "never a stop" list. A's second ceiling for retrieval (A:57-58) is also better than my 1.5x watch (see section 3).

## 2. Three strongest weaknesses of A

**2.1. Event 3 is detected only after the last block, so the rule leaves the costliest single event undetected for the whole pilot (A:48, A:51).**
A defers "an unsupported citation certified" (T-5 item 3, `pd:38`, `src:530`) to the blinded grader after block 12. If arm C certifies unsupported citations on plan 1 (format-compliance and grounding are real risks, `src:513`, `src:511`), the pilot spends the whole C-5 range (1.30M-2.62M, `pd:131`) before the fact is known, and A:51 admits "no runs remain to stop". The stop rule exists to protect the owner from wasted spend (the task's own framing), and this is one of the five safety events. The check does not need a blinded grader: re-reading each certified `file:line` is mechanical (the evidence-validator pattern, which the skill already uses). A's choice protects blinding, but at the cost of making one of five events un-stoppable. Fix: the operator runs a mechanical citation re-read after each block and writes only a pass/fail count, with no recall scoring.

**2.2. S-3.2 and S-3.1 invent a rerun allowance, reclassify a missing contract, and score kills against the arm that is killed more often (A:65-66, A:95, A:100).**
(a) "One rerun" is an invented number by A's own admission (A:100). A rerun of a crashed run also breaks the blind plan-block symmetry (the arm that crashes more is run twice) and its tokens count toward the ceiling (A:60), so arm cost is no longer comparable for H-C (T-3, `pd:19`). (b) A treats a run with no contract as "a failed run, not a MALFORMED contract" (A:66, A:95), but a missing or unparseable contract is exactly how a T-5 item 2 event would appear; the reclassification can turn a safety event into an ordinary failure and the owner's confirmation is left open. (c) Scoring "no report" as "not found" (A:65) plus killing at 65k penalizes the arm with the higher token band: the T2 band tops out at 70k while the kill is 65k (`cost-profile.yaml:55,69-70`; `src:479`), so legacy and panel T2 runs in the 65-70k part of their band are killed, and the arm that spends more is scored lower on recall for cost reasons. That mixes H-C into H-B. A noted censoring for H-C but not this effect on recall. (My own note 4 shares (c); A is not worse than me here, but it did not resolve it.)

**2.3. S-2's ceiling is the worst-case estimate, so it will not bind, and grading is outside every ceiling (A:57-61, A:71).**
(a) S-2.1 sets the claude ceiling at "the upper bound of row C-5" (2,616k) and S-2.3 tests spend plus the block's band tops (8k + 70k + 70k, plus 70k for arm D blocks) against it. With every run at or under its band top, spend plus remaining band tops never exceeds the sum of band tops, so the test cannot fire unless runs already exceed the profile band, which is the same defect A (and I) flag elsewhere: it fires after the money is gone. A's forecast is conservative but not informative; it has no projection from observed per-arm cost. (b) Grading by blinded graders happens after the last block (A:71) and appears in no C row (`pd:127-132`) or S-2 ceiling, so the owner can approve a "ceiling" that leaves grading unbudgeted and discover it after the pilot has finished. (c) A halts the whole pilot on any event in arm C or D (A:49), including events 1 and 2, which loses arm A and B data (the d_AB and d0 data) on the first MALFORMED of arm C. Format non-compliance by panel reviewers is rated Medium probability (`src:513`), so over 12 blocks this halt is likely; the pilot would end with only partial pairs, and the section protects the owner from "uninformative results" poorly. A reads T-5 as a panel-only criterion without a source (A:93 admits it).
(d) Also missing from A: no pre-run harness validity check and no pause for an uninformative pilot (A:71 forbids interim looks entirely), so a seeding fault (defects not findable, or T1 recall at ceiling) runs to the end at 1.3M-2.6M. A mechanical, zero-token check before block 1 (each scripted defect is present in the plan file; the blinded input contains no arm marker) would cover it without any recall scoring.
