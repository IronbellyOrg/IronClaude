# Per-field source table: the five fields whose producer changes

The panel replaces the producer of five contract fields. The panel contract lint (`src/superclaude/cli/reflect/panel_lint.py`, assertion L7) requires each to equal the legacy value on a matched fixture; for `reviewer_cards` the comparison is over the sorted list of file basenames, because recorded paths are absolute and differ by run directory and machine.

Environment for the "expected" column: `anthropic-only` with `@reflect-pre`, no executor exclusion: the reviewers resolve to sonnet, haiku, opus (`tests/review/test_review_reflect_templates.py`).

| Field | Legacy source and rule | Panel source and rule | Expected on anthropic-only |
|---|---|---|---|
| `t2_model_class_diversity` | `SKILL.md` section 4 Wave 0 step 0.5 table (lines 237-239): the number of distinct models the resolved aliases name. 3 or more: `full`; 2 or 1: `degraded`. | The number of distinct classes among the resolved reviewers, taken from the tier file's `classes` map (`review panel resolve` output, `reviewers[*].model`). 3 or more distinct classes: `full`; fewer: `degraded`. The vocabulary stays `full` or `degraded`; the headless helper's `insufficient` (`_diversity.py:15`) is a separate mismatch and is not used. | `full` (opus, sonnet, haiku: three distinct classes) |
| `t2_vendor_diversity` | `SKILL.md` Wave 0 step 0.6 (line 259): the vendor of each resolved alias; 2 or more vendors: `multi`; one: `single` (warn only). | The vendor family of each resolved model id, by the same coarse rule as `_diversity.py:_vendor_from_model_id` (`claude` is Anthropic, `gpt` is OpenAI, `glm` is Zhipu, and so on). 2 or more vendors: `multi`; one: `single`. | `single` (all three are Anthropic) |
| `t2_effective_diversity` | `SKILL.md` line 792 and `refs/ops-integration.md:97-109`: derived from the two axes above. Only the names and the model-only example are written down; the four-way derivation below is the reading of those two texts. | The same derivation over the panel's two values: class `full` and vendor `multi`: `full`; class `full` and vendor `single`: `model-only`; class `degraded` and vendor `multi`: `vendor-only`; both degraded: `none`. | `model-only` (class `full`, vendor `single`) |
| `calibrator_diversity` | `SKILL.md` section 11.3 (lines 1176-1188): the calibrator class is picked from `{opus, sonnet, haiku, qwen, kimi, deepseek}` minus the reviewer classes. Non-empty remainder: `full`; empty (no unused class is available): `degraded`. | The same rule, with "available" meaning classes the environment can run. The panel changes who the reviewers are, so the reviewer-class set is the resolved panel's. | `degraded` (the reviewers use opus, sonnet and haiku, and qwen, kimi and deepseek are not available in anthropic-only) |
| `reviewer_cards` | The paths of the reviewer card files the run wrote under `<out>/reviewer-cards/` (`reviewer-<n>-card.yaml`), in reviewer order, absolute. | The same list, from the panel's resolution order (fixed anchor first, then slot order). The lint compares sorted basenames, so only the card names and their count must match; the count must also meet EV-1 (`reviewers_resolved` from `panel/manifest.json`, minimum 2). | Three cards: `reviewer-1-card.yaml`, `reviewer-2-card.yaml`, `reviewer-3-card.yaml` |

## Notes

- The recorded legacy fixture (`tests/cli/reflect/fixtures/panel_lint_legacy/`, from run `pre-design-20261104164711`) carries `t2_vendor_diversity: multi`, `t2_effective_diversity: full`, `t2_model_class_diversity: full`, `calibrator_diversity: degraded`. That run used non-Anthropic aliases, so its vendor and effective values differ from the anthropic-only expectation above. The lint compares a panel run with a matched legacy run of the same environment, not with this table; the table states what an anthropic-only pair must show.
- Unverified: the four-way derivation of `t2_effective_diversity` is read from the two texts cited above, not from a formula in code (`grep model-only` finds no code).
