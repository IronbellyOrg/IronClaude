# Differential Backtest/Eval Harness for sc:troubleshoot Pipeline Hardening Closure (E1-E5 OLD=MISS vs NEW=CATCH)

## Task Overview

This task builds an executable differential backtest/eval harness for the `sc:troubleshoot` Pipeline Hardening Closure mode (waves H0-H5). The harness replays the five canonical pipeline escapes E1-E5 against their PRE-FIX PARENT commits and asserts a per-escape differential: the **un-hardened (pre-fix) protocol MISSES** each escape while the **new H0-H5 gate CATCHES** it. It emits a machine-readable catch-rate report that populates the `backtest_status` field (`not_run`|`partial`|`complete`) per RELEASE-SPEC NFR-1.

The harness lives ENTIRELY under `tests/troubleshoot/backtest/` and is built on its OWN branch + git worktree (`feat/troubleshoot-hardening-evals` off `origin/master`), kept SEPARATE from the parallel implementation work (`feat/troubleshoot-pipeline-hardening`, whose impl worktree is at `/config/workspace/IronClaude/.dev/worktrees/troubleshoot-hardening`).

**Why this exists:** RELEASE-SPEC NFR-1 "100% would-have-caught" is explicitly deferred to milestone M5 / out-of-scope in the implementation tasklist, so the new gates' efficacy is only PREDICTED, not proven. This executable differential eval closes that false-assurance gap by mechanically demonstrating the un-hardened protocol MISSES each escape, and by emitting a machine-readable catch-rate report that drives `backtest_status` — keeping production-facing pipeline-health signoff `advisory` until the corpus is proven `complete`.

**The two halves (designed asymmetry):**
- **OLD=MISS half — runs GREEN NOW.** Asserted by IN-PROCESS replay of the REAL product callables AT the pre-fix parent checkout (these are real, importable callables at the parent tree). These callables exist today; no impl dependency.
- **NEW=CATCH half — SKIP-GUARDED until impl lands.** The new H-gate logic is PURE MARKDOWN (refs/*.md under the skill dir, produced by the parallel impl branch). There is NO importable Python H-gate. NEW=CATCH is therefore a documentation-presence PROXY guarded by `pytest.mark.skipif` keyed on impl-ref file existence. The proxy's limitation is recorded in the report wording so it is not oversold.

## Key Objectives

The following objectives MUST be achieved by this task:

1. **Git-replay helper (mirror-shape):** A subprocess-seam git-worktree replay helper under `tests/troubleshoot/backtest/` mirroring the `src/superclaude/cli/sprint/process.py` `import subprocess as _subprocess` seam, with a `checkout_worktree` context manager (try/finally `remove --force` + `prune`) and the authoritative per-escape PRE-FIX PARENT sha table stored DIRECTLY (NO `^` suffix, per G1).
2. **ReplayExecutor seam (mirror the LifecycleExecutor Protocol):** A `ReplayExecutor` Protocol seam (spawn→observe), mirroring `src/superclaude/cli/eval/runner.py::LifecycleExecutor`, so the harness invokes in-process callables (not a literal PTY) and is unit-testable via subprocess-mocking.
3. **Catch-rate report model + JSON Schema (mirror run_report.py):** A frozen `CatchRateReport` + `EscapeResult` dataclass pair with field-order tuples, `to_dict()` SoT, a `__post_init__` invariant guard deriving/validating `backtest_status ∈ {not_run|partial|complete}`, a pure `render_*_json` calling the invariant before write, and a draft-2020-12 JSON Schema validated by `jsonschema.Draft202012Validator` in a fidelity test.
4. **Per-escape differential runners (one per escape, E1-E5):** Individual parametrized OLD=MISS assertions (in-process replay of the real pre-fix callable) + skip-guarded NEW=CATCH documentation-presence proxies, mapped 1:1 to RELEASE-SPEC §8.3.
5. **pytest wiring + skip-guards:** A self-contained `tests/troubleshoot/backtest/` package (own `__init__.py` + `conftest.py`), the CI shallow-clone module-level `skipif` (G2), the no-leaked-worktree post-condition (G3), and a green `uv run pytest tests/troubleshoot/backtest/` run (passes-or-correctly-skips) plus `ruff check` + `ruff format --check`.
6. **Machine-readable catch-rate report driving `backtest_status`:** Aggregate the 5 per-escape results into a `CatchRateReport`, derive `backtest_status` (all 5 CATCH → complete; 1-4 → partial + list missing IDs; none/not-run → not_run), and assert the SEPARATION invariant (signoff stays advisory until complete).
