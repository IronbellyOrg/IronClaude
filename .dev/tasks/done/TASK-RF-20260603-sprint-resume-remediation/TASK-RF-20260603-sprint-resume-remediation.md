# Corrective Remediation — v4.3.5 Sprint Auto-Resume UC-2 Reflection Audit (CG-4, F-3, F-2, F-4)

## Task Overview

A `/sc:reflect --mode post` UC-2 audit of the v4.3.5 sprint auto-resume feature found that the feature passed all 9 in-band gates and 31/31 task items but is only `partial` against its driving spec. Promotion is BLOCKED (strict-gate conditions 4 and 8 fail: drift==1, regression==1, needs_human_decision==true). This task is the documented Tier-3 remediation path. It must be executable by `/task` with no external context — every checklist item embeds its own source references.

The remediation has four actionable items, executed in priority order across phases:

1. **CG-4 (spec self-contradiction, HUMAN DECISION):** design §7 enacts `passed=True` with partial work merely reported, while design §4(c) and FR-2.4 require `passed` to include `(partial work quarantined OR accepted)`. Both cite FR-2.4 as authority — a genuine self-contradiction the implementation already had to resolve toward §7. Phase 1 surfaces the contradiction, presents the recommended ruling (YES, conditional on F-2) plus the conservative alternative (NO/tighten the gate), and records the operator decision. It MUST NOT silently pick a side and ship a gate change.
2. **F-3 (HIGH, regression-class):** the drift assessor's fall-through branch returns confidence 0.9 / `cosmetic_only=True` whenever the current task-ID set equals the recorded set — even after a Tier-0 hash MISS already proved file content changed. Same-ID prose/checkpoint/deliverable edits to a completed task silently resume, violating AC-5. Fixed with the PRINCIPLED whitespace-normalized-hash approach (NOT the minimal branch flip, which regresses AC-4).
3. **F-2 (MED-HIGH, drift):** `_detect_partial()` computes partial-work paths but on the default report-only path they are dropped — never reaching the `BoundaryReport` or any print surface. Fixed with Option A (add `BoundaryReport.partial_paths`, populated unconditionally), the literal design §4(b) "report suspect paths in BoundaryReport (always)" contract, then printed in the resume-decision printer.
4. **F-4 (MED, coverage gap):** on a PHASE hard crash the planner emits `boundary_tasks == []`, so the integrity gate's last-completed validation is vacuously True — the prior phase's tail is never double-validated, under-delivering AC-3 (:141-143). Fixed with a multi-file co-dependency: a `BoundaryTask` phase field, a planner emit of a `last_completed` prior-tail boundary task, and an integrity validation that resolves the transcript under the correct phase.

Each code fix lands with its missing coverage-gap test (CG-2→F-3, CG-1→F-2, CG-3→F-4), written RED before the fix and GREEN after. Each code-fix phase ends with an rf-qa task-integrity gate.
