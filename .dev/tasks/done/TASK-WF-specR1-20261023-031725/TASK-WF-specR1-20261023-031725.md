Source: ./source.md
Goal: pull-sync-framework.yml opens a pull request from `sync/framework` instead of pushing to master and fails closed if it cannot check for an open one; boundary-guard.yml describes itself as advisory and diffs with three dots; the Codecov step uses the inputs its v4 documentation names, with a token; .github/workflows/README.md and the publish paragraph of scripts/README.md describe the workflows that actually exist. Every acceptance check below fails on a wrong edit and passes a correct one.

## Constraints

- Allowed edits: .github/workflows/pull-sync-framework.yml, .github/workflows/boundary-guard.yml, the `Upload coverage to Codecov` step of .github/workflows/test.yml, .github/workflows/README.md, and the publish-pypi paragraph of scripts/README.md (lines 7-12 on base a88f100b: the sentence naming `.github/workflows/publish-pypi.yml` and the bullet list that completes it). Nothing under src/, tests/, Makefile, pyproject.toml or .claude/ changes.
- Evidence goes under ./artifacts/ in this package. Proof logs contain the exact commands run and their full output.
- Every Python or pytest command runs through `uv run`.
- No scope check may use an unscoped `git diff --stat` or a `master...HEAD` range. Scope is checked against the Task 1 baseline only.
- Placeholder definitions used by every task: `<t1-head>` is the single line in ./artifacts/t1-head.txt, written as `$(cat ./artifacts/t1-head.txt)` in commands. The Codecov file-input name is the value on the single line beginning `Decision:` in ./artifacts/t2-codecov-v4.md. A task fails if a command it runs still contains an angle-bracket placeholder.
- Checks are anchored on text, never on fixed line numbers, and scoped to one line or one block (header comment block, the job-level `name:` value read with PyYAML, the `::warning` line, the summary item 3 block). No file-wide search for the word "required": the "Required reviewer checks" heading legitimately contains it and must stay.
- Necessary deviation from the scope rule (source "Quality rules"): the reflect and implement pipelines that execute this plan write their own records under `.dev/reflect/`, `.dev/troubleshoot/` and `.dev/workflow/` during execution. Task 9 lists new paths under exactly those three roots separately as tooling output and does not fail on them; every other new or changed path outside `.github/workflows/`, `scripts/README.md` and this package fails.
- The boundary guard stays advisory. Turning it into a real merge gate (required label, CODEOWNERS, branch protection) is a repository-settings decision and is not part of this plan.
- The workflow token is not changed: no personal access token or GitHub App token is introduced.
- Accepted leftovers, not edited: .dev/specs/pr-submit-ci-monitor.md still mentions quick-check.yml (a historical spec); scripts/README.md lines outside the publish-pypi paragraph still assume a publish workflow (Task 9 lists them for the user).
- Known consequences of Fix 1 (source "Fix 1"): docs/.framework-sync-commit is committed on `sync/framework`, so until that pull request merges master keeps the old value and every 6-hourly run re-syncs and force-replaces the branch; an open pull request from `sync/framework` is reused, not duplicated; commits pushed to `sync/framework` by hand are lost at the next run.
- Prerequisites this plan cannot create: the repository setting "Allow GitHub Actions to create and approve pull requests" (checked in Task 3); a `CODECOV_TOKEN` repository secret (Task 7). Fix 1 and Fix 3 stay unverified until runs on GitHub after merge.
- Task order: tasks run in number order. A task whose work needs more than one earlier task names the latest one in its `Depends on:` line and lists the others in its body.
