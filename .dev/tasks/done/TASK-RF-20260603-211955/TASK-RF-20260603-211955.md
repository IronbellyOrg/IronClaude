# Broaden per-task error_max_turns recovery to accept tail completion-verdict evidence

## Task Overview

The SuperClaude/IronClaude sprint harness already recovers a per-task `error_max_turns` overrun when the task wrote a structured completion envelope (`"subtype":"success"` or `task_complete`) before overrunning the turn budget — this is the merged PR #121 machinery (`TaskStatus.PASS_RECOVERED`, the gated `_task_completed_before_overrun` helper, and the `.is_success` aggregation). However, TUIBBS V1 MVP sprint Phase 7 / task T07.05 exposed a detection gap: T07.05 completed and wrote its deliverable (complete and green on disk), then overran the 100-turn budget, but emitted ZERO `subtype:"success"` / `task_complete` envelopes. The merged `_task_completed_before_overrun` therefore keeps it `FAIL_TERMINAL`, causing the whole phase to log a phase-level `error` (exit 1) despite a complete deliverable.

This task closes that gap by adding a SECOND, tail-scoped class of completion evidence to `_task_completed_before_overrun`: a strong completion verdict (e.g. `VERDICT: PASS`) appearing in the last N=15 pre-terminal lines of the task NDJSON. The change is deliberately tail-scoped and conservative so it cannot fire on a casual mid-stream "PASS" — preserving the completed-after-overrun vs overran-mid-work distinction the gate exists to protect. The classifier already maps the helper's `True` to `PASS_RECOVERED`, so ONLY the helper (plus a new module-level pattern) needs extending; no classifier change is required. The change ships as a PR from a `fix/` branch to IronClaude `master`.

## Key Objectives

The following objectives MUST be achieved by this task:

1. **Add tail-completion pattern:** Add a conservative, tail-scoped module-level regex `_TASK_TAIL_COMPLETION_PATTERN` (and window constant `_TASK_TAIL_COMPLETION_WINDOW = 15`) to `executor.py` next to the existing `_TASK_SUCCESS_ENVELOPE_PATTERN`, leaving the existing envelope pattern intact.
2. **Extend the helper:** Add a second OR-branch in `_task_completed_before_overrun` that scans the last N=15 pre-terminal lines for the tail-completion verdict, returning `True` on a match — built ON the merged PR #121 machinery, NOT duplicating it.
3. **Document the two classes:** Extend the `_task_completed_before_overrun` docstring to document the two completion-evidence classes and why the verdict scan is tail-scoped.
4. **Prove correctness with strong tests:** Add mirrored unit tests (positive tail-verdict recovery, anti-false-positive tail-scoping, and a direct-helper unit test) using STRONG assertions, mirroring the existing Phase 6 tests.
5. **Prove zero regression and pass all gates:** Demonstrate via a `git stash` baseline-vs-post-change diff that there are 0 NEW failures and the new tests pass; `make lint` exits 0; `make verify-sync` shows no NEW drift; then ship a PR from a `fix/` branch to IronClaude `master`.
