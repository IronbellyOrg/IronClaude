# Fix PR #120 Medium Findings (M1 leak, M2 unbounded watchdog, M3 corrupt-handoff crash, M4 scheduler tests)

## Task Overview

This task remediates the four Medium-severity findings raised by the auggie-powered code review of PR #120 (Sprint CLI per-task execution wire-up). All four are failure-path robustness defects plus one real test-coverage gap, each small and surgical:

- **M1 (resource leak):** When an exception (e.g. `KeyboardInterrupt`) interrupts the per-task subprocess wait, the subprocess file handles opened by `start()` leak because the only happy-path `_close_handles()` caller — `proc.wait()` inside the stall watchdog — is never reached. The fix wraps `start()` + the poll in `try/except BaseException: proc.terminate(); raise` so cleanup runs on the exception path while the exception still propagates.
- **M2 (unbounded wait / liveness):** In the default `warn` stall mode, the per-task stall watchdog's poll loop has its only `break` inside the `kill`-mode branch. A child that never produces output and never exits causes the loop to spin forever. The fix adds an absolute wall-clock ceiling derived from the proc's own timeout budget so the loop falls through to the already-bounded `proc.wait()`.
- **M3 (corrupt-state crash on resume):** The handoff read parses JSON with no guard, so a truncated/garbled handoff file raises and aborts resume. The fix wraps the parse in `try/except (json.JSONDecodeError, ValueError): return None`; both call sites already treat `None` as "re-run the task", so a corrupt record degrades safely to a re-run.
- **M4 (test-coverage gap):** The sprint scheduler has zero dedicated tests. The fix adds a new `tests/sprint/test_scheduler.py` covering wave ordering (diamond, linear, independent), cycle detection, self-edge drop, unknown/cross-set dep filtering, dependency de-dup/union, and the tri-state `is_task_satisfied` oracle.

Each source fix (M1/M2/M3) is accompanied by a regression-proving unit test that would FAIL against the current (unfixed) code and PASS after the fix. All test items use only registered pytest markers (the suite runs with `--strict-markers`; an unregistered marker is a hard error).

## Key Objectives

The following objectives MUST be achieved by this task:

1. **M3 corrupt-handoff guard + test:** Make `FileHandoffStore.read` return `None` on a corrupt/unparseable handoff file, with a unit test proving the degrade-to-`None` behavior across truncated, empty, and garbage inputs.
2. **M1 handle-leak guard + test:** Wrap the per-task subprocess wait so an exception triggers cleanup (`proc.terminate()`) and re-raises, with a unit test proving cleanup fires and the exception propagates.
3. **M2 watchdog ceiling + test:** Add an absolute wall-clock ceiling to the warn-mode poll loop so it is bounded, with a unit test proving the loop terminates and reaches the bounded `proc.wait()` (plus a companion kill-mode-unchanged assertion).
4. **M4 scheduler test suite:** Create `tests/sprint/test_scheduler.py` exercising wave ordering, cycle detection, self-edge drop, unknown-dep filtering, dep de-dup/union, and `is_task_satisfied`, all asserting exact expected outputs traced from the real scheduler.
5. **Green verification gate:** Full sprint test suite passes (`uv run pytest tests/sprint/ -q`), `uv run ruff format --check src/ tests/` is clean, and `make lint` is clean, verified by a final QA gate before the task is marked Done.
