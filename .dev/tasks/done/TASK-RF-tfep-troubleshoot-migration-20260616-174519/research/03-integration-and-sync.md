## 4. The adapter contract (change 2) — exact field reconciliation

What the **task-protocol TFEP consumer** reads (`sc-task-protocol/SKILL.md`):
- Invocation (L212): `--tier {light|standard}`, `--intent triage`, `--caller task-unified`, `--context {context_path}` (a `context.yaml` written at L203), `--output {output_dir}`, `--depth quick`.
- Consumes `{output_dir}/return-contract.yaml` (L216) with fields: `test_is_wrong` (L219), `status` ∈ success|partial|failed (L220–222), `recommended_escalation` (L221), `tasklist_insertion_path` (L225).

What the **troubleshoot skill** currently provides (`sc-troubleshoot-protocol/SKILL.md` Output Contract, L37–72):
- Flags it accepts (L115): `--type`, `--depth`, `--fix`, `--no-escalate`, `--models`, `--output-dir`, `--no-mcp`, `--no-diagnosability-audit`, `--diagnosability-handoff`, `--reset-diagnosability-rounds`. **No `--caller`, `--tier`, `--intent`, `--context`.**
- Returns a **dict** (not a `return-contract.yaml` file). Fields: `status` (success|partial|failed — matches!), `tier_reached`, `report_path`, `audit_log_path`, `confidence`, `escalation_reason`, `test_is_wrong` (matches!), `test_file_path`, `behavior_is_documented`, `task_file_path`, `remediation_offered`, `remediation_accepted`, etc.

**Gaps the adapter (change 2) must close** (each is a concrete tasklist item):
1. **Dispatch translation**: task-protocol's `--tier light|standard --intent triage --depth quick` → troubleshoot's `--depth quick|standard|deep` (+ no `--fix` in triage). `--caller`/`--intent`/`--context` have no troubleshoot equivalent — decide: add pass-through flags to troubleshoot, OR have the adapter drop them and pass `--output-dir {output_dir}` + the context file via the issue description.
2. **Return-contract emission**: troubleshoot returns a dict, task-protocol reads a `return-contract.yaml` FILE at `{output_dir}/return-contract.yaml`. Adapter must either (a) make troubleshoot write that file, or (b) rewrite task-protocol Step 4 to read troubleshoot's dict/`REPORT.md` instead.
3. **Field-name mapping**: `tasklist_insertion_path` (consumer) — troubleshoot has NO such field today (closest is `task_file_path`, Tier-3-only, and `diagnosability_tasklist_path`). `recommended_escalation` (consumer) — troubleshoot has `escalation_reason`/`tier_reached`, not an escalation-recommendation enum. These are the fields the new `## TFEP Consumer` report block (§2) should surface: `remediation_target`, `tasklist_insertion_recommendation`, `safe_to_auto_insert`.
4. **Escalation budget (change 8)**: task-protocol L258–259 hardcodes forensic token bands (`~5-8K`, `~15-20K`). Troubleshoot's own budgets are per-wave (≤3k Tier 1; full table L559–567 shows a 3–9k Claude-token band for Tier-1-only). The migrated budget block must restate budgets against troubleshoot tiers, not forensic tiers.
5. **Incident reporting (change 7)**: task-protocol L237–253 `tfep-incident-report.md` references "Forensic artifacts" / "forensic artifacts" and pulls `rca-verdict.md` / `solution-verdict.md` (forensic-pipeline filenames). Troubleshoot produces `REPORT.md` + hypothesis cards + `audit.log` instead — the incident-report template fields must be re-sourced from troubleshoot's artifacts.
