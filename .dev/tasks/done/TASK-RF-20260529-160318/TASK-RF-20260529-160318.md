# Implement Wave 1.6 Diagnosability Audit into sc-troubleshoot-protocol

## Task Overview

A grounded brainstorm completed 2026-05-29 produced `merged-output.md` — an adversarially-debated (3-variant pipeline, convergence 0.78 against threshold 0.75) design spec absorbing 7 additives from a real-world session-replay field study. The current `sc-troubleshoot-protocol` never asks "is the system under-instrumented for this symptom?" before fanning out hypothesis agents, leading to wasted token-rounds against blind code for intermittent / race / performance / production-only failures. Wave 1.6 is the structural fix — it audits log-call density and log-config reachability against the failing component, computes a sufficiency verdict, and (when verdict is insufficient + non-trivial) hard-stops the pipeline with an invocation-site-only instrumentation tasklist instead of hypothesizing harder against blind code.

This task implements that spec into the live skill as v1.0 (additive — no re-numbering of existing waves).
