    fix(sprint): migrate .sprint-exitcode writes to non-tracked transient state_dir (FU-001)
    
    Migrates the sprint runner's .sprint-exitcode sentinel write/read pair
    from config.release_dir (tracked archive path) to a new transient
    config.state_dir (default .dev/sprint-state/<tasklist-id>/, override via
    SPRINT_STATE_DIR env var or --state-dir CLI flag).
    
    Changes:
    - Add state_dir: Path field to SprintConfig with empty-Path sentinel
      default + __post_init__ derivation (models.py)
    - Thread state_dir kwarg through load_sprint_config() (config.py)
    - Add --state-dir Click option + SPRINT_STATE_DIR env-var resolution +
      re-derivation when --release-dir is overridden (commands.py)
    - Migrate writer (executor.py, _write_exit_sentinel helper) and reader
      (tmux.py) to config.state_dir
    - Update tests/sprint/test_tmux.py fixture
    - Patch cross-skill external reader bootstrap_scan.sh:90,126 to check
      new state_dir first with read-only fallback to legacy in-release path
    - Remove 40 tracked 1-byte .sprint-exitcode sentinels (redundant with
      execution-log.jsonl exit_code field in sibling directories)
    - Add tests/sprint/test_state_dir_isolation.py regression coverage (4 cases)
    
    Resolves the follow-up flagged in TASK-RF-20260518-181333 Phase 3 PR
    body. The temporary anchored '/.sprint-exitcode' .gitignore line added
    in that PR can be replaced with '.dev/sprint-state/' in a sibling
    cleanup once this lands.
