# FU-001 — Migrate sprint .sprint-exitcode writes to non-tracked transient state_dir + remove 40 tracked sentinels

## Task Overview

The sprint runner currently writes a `.sprint-exitcode` sentinel file inside `config.release_dir` — a tracked archive path under `.dev/releases/**/` — so the outer tmux caller can read the inner sprint's exit code after `tmux attach-session` detaches. Because `release_dir` resolves to a tracked directory, every sprint run produces a transient file inside the release archive. Forty (40) 1-byte sentinels have accumulated under `.dev/releases/**/` from historical runs and currently sit in `git ls-files`. Phase 3 of TASK-RF-20260518-181333 added an anchored repo-root `.gitignore` line (`/.sprint-exitcode`) as a workaround; this task delivers the root fix.

This task introduces a transient `state_dir` field on `SprintConfig` (default `.dev/sprint-state/<tasklist-id>/`, override via `SPRINT_STATE_DIR` env var and `--state-dir` CLI flag), migrates the writer at `executor.py:1754` and the reader at `tmux.py:166` to use it, removes all 40 tracked sentinels via `git rm`, patches the cross-skill external reader at `bootstrap_scan.sh:90,126` to check the new state_dir AND keep a read-only fallback to the legacy archive locations during migration, updates `tests/sprint/test_tmux.py:100` (the writer-side fixture), and adds a regression test that asserts `git ls-files | grep -c '\.sprint-exitcode$'` returns 0 post-migration plus asserts the new state_dir is the actual writer destination.

## Key Objectives

The following objectives MUST be achieved by this task:

1. **State-dir field**: Add a `state_dir: Path` field to `SprintConfig` with empty-Path sentinel default and `__post_init__` derivation to `.dev/sprint-state/<release_dir.name | index_path.parent.name | index_path.stem>/` so all ~30 existing test fixtures continue to pass unchanged.
2. **CLI plumbing**: Add `--state-dir` Click option and `SPRINT_STATE_DIR` env-var resolution in `cli/sprint/commands.py::run`, threading an optional `state_dir=` kwarg through `load_sprint_config()` so `__post_init__` sees the explicit value.
3. **Writer/reader migration**: Update `executor.py:1754` (writer) and `tmux.py:166` (reader) to use `config.state_dir / ".sprint-exitcode"` with `mkdir(parents=True, exist_ok=True)` ahead of the write. Update the test fixture at `tests/sprint/test_tmux.py:100` to write to the new path.
4. **Tracked-file purge**: Remove all 40 tracked `.sprint-exitcode` files via `git rm` (full delete, not `--cached`) per the research disposition; content is redundant with `execution-log.jsonl` `exit_code` field in the same directories.
5. **Cross-skill external reader**: Patch `src/superclaude/skills/sc-crash-recovery/scripts/bootstrap_scan.sh:90,126` to check the new `state_dir` first AND keep a read-only fallback to the legacy `release_dir` location during the migration window (so crash recovery continues to surface stalled-sprint state from historical release directories that may still hold sentinels written by older sprint binaries in-flight). Sync the change to `.claude/skills/...` via `make sync-dev`.
6. **Regression coverage**: Add `tests/sprint/test_state_dir_isolation.py` with at minimum: (a) `test_writer_uses_state_dir_not_release_dir` (asserts sentinel ends up in `state_dir`, not `release_dir`); (b) `test_no_tracked_sprint_exitcode_files` (asserts `git ls-files | grep -c '\.sprint-exitcode$' == 0`); (c) `test_state_dir_default_derives_from_release_dir`; (d) `test_state_dir_override_via_env_var` (using `monkeypatch.setenv`).
7. **Open Question resolutions documented**: Record the three Open Questions from the BUILD_REQUEST (release-dir override re-derivation, env-var routing, cross-skill scope) with chosen dispositions in the Task Log.
