## 2. §6.1.1 consumer-side safety envelope — eight mandatory controls

The §6.1.1 preface states: "`execute_shell_command` runs **non-mutating verification only** (tests/linters/type-checkers/build). Serena executes the command via `subprocess.Popen(command, shell=True)` with **no upstream allowlist or sandbox** (Serena Security Audit #380), so the entire safety envelope is **consumer-side**. A first-token allowlist is *necessary but not sufficient* — under `shell=True` an allowlisted first verb still permits a chained mutation (e.g. `pytest ; rm -rf src`). The envelope therefore validates the **whole command structure**, not just the first token. All eight controls are mandatory:" (`/config/workspace/IronClaude/.claude/worktrees/ReflectGateWiring/src/superclaude/skills/sc-reflect-protocol/SKILL.md:491-491`).

Verbatim controls:

- **(a) Template construction, not prose assembly.** The command MUST be built from a fixed allowlisted-verb template with arguments supplied as a vetted token list. The command string is NEVER assembled from raw spec/tasklist prose (untrusted by definition). (`/config/workspace/IronClaude/.claude/worktrees/ReflectGateWiring/src/superclaude/skills/sc-reflect-protocol/SKILL.md:493-493`)
- **(b) Verb allowlist.** The first token MUST be in `{pytest, ruff, mypy, make, uv, npm, tsc, cargo}`; otherwise the command is rejected with `verify_blocked: true` + `verify_blocked_reason: "verb '<v>' not in allowlist"` and is **not** invoked. (`/config/workspace/IronClaude/.claude/worktrees/ReflectGateWiring/src/superclaude/skills/sc-reflect-protocol/SKILL.md:494-494`)
- **(c) Structural metacharacter rejection (the load-bearing C1 control).** Reject outright with `verify_blocked: true` + `verify_blocked_reason: "metachar-denied"` any command containing a shell control character — semicolon `;`, pipe `|`, ampersand `&`, dollar `$`, backtick `` ` ``, redirect `>` / `<`, newline, or parentheses `(` `)`. This validates the whole command structure; a denylist of mutation *verbs* alone is insufficient against `shell=True` composition. Such a command is **never** passed to `execute_shell_command`. (`/config/workspace/IronClaude/.claude/worktrees/ReflectGateWiring/src/superclaude/skills/sc-reflect-protocol/SKILL.md:495-495`)
- **(d) Per-call timeout.** Wrap every command as `timeout <N> <cmd>` with default **120s, max 600s** (Serena's tool-level timeout is unverified, so the wrap is consumer-side). A timeout kills the command, records `exit_code: 124` + `verify_timeout_hit: true`, classifies it Grounding Gap, and the run continues. (`/config/workspace/IronClaude/.claude/worktrees/ReflectGateWiring/src/superclaude/skills/sc-reflect-protocol/SKILL.md:496-496`)
- **(e) Output cap.** Pass `max_answer_chars=51200` (50 KB, tighter than the 200 KB Serena default) plus a defensive tail-truncate of captured stdout/stderr. (`/config/workspace/IronClaude/.claude/worktrees/ReflectGateWiring/src/superclaude/skills/sc-reflect-protocol/SKILL.md:497-497`)
- **(f) `cwd` scoping.** Scope `cwd` to the affected subtree (blast-radius reduction). (`/config/workspace/IronClaude/.claude/worktrees/ReflectGateWiring/src/superclaude/skills/sc-reflect-protocol/SKILL.md:498-498`)
- **(g) Per-invocation audit artifact (M-ARC1).** Each invocation is appended to `<output>/verify-logs/invocations.yaml` as an array entry `{cmd, exit_code, duration_ms, stdout_path, stderr_path, blocked_reason, deviation_class}`. The step-5.5 audit row references this artifact via its `evidence_ref` field — the per-invocation data is **NEVER inlined** into the fixed 5-field per-step audit row. (`/config/workspace/IronClaude/.claude/worktrees/ReflectGateWiring/src/superclaude/skills/sc-reflect-protocol/SKILL.md:499-499`)
- **(h) `--no-verify`.** Disables the verification triangle globally (`verification_skip_reason: --no-verify`). (`/config/workspace/IronClaude/.claude/worktrees/ReflectGateWiring/src/superclaude/skills/sc-reflect-protocol/SKILL.md:500-500`)

Additional no-mutation gate: independently of (b)/(c), mutation-denylisted commands such as `git commit`/`git push`, `pip install`, `rm`, or redirects outside `<output>/` are rejected as `verify_blocked_reason: "mutation-denied"` and never invoked (`/config/workspace/IronClaude/.claude/worktrees/ReflectGateWiring/src/superclaude/skills/sc-reflect-protocol/SKILL.md:502-502`).

### Option A — command-prefix `env -u SUPERCLAUDE_REFLECT_WRAPPER_ACTIVE <cmd>`

- As a raw user-visible command prefix, this conflicts with current control (b) because the first token would be `env`, not one of `{pytest, ruff, mypy, make, uv, npm, tsc, cargo}` (`/config/workspace/IronClaude/.claude/worktrees/ReflectGateWiring/src/superclaude/skills/sc-reflect-protocol/SKILL.md:494-494`).
- If placed before the timeout wrapper, it also obscures control (d)'s required `timeout <N> <cmd>` shape; if placed after `timeout`, the actual executed command starts with `timeout`, while control (b) still needs to be explicit that allowlist validation applies to the base verification command, not fixed wrappers (`/config/workspace/IronClaude/.claude/worktrees/ReflectGateWiring/src/superclaude/skills/sc-reflect-protocol/SKILL.md:494-496`).
- It can compose safely if and only if the skill adds an explicit fixed-wrapper rule: validate a base command whose first token is allowlisted, reject metacharacters on that base command, then execute the fixed non-user-controlled wrapper `timeout <N> env -u SUPERCLAUDE_REFLECT_WRAPPER_ACTIVE <base-cmd>`. This wrapper uses no denied shell metacharacter, and `env -u` is not accepted as a user-supplied verb.

### Option B — strip via `subprocess.Popen(..., env=...)` / Python env dict

- This would be the cleanest implementation if a Python wrapper constructed step-5.5 verification subprocesses, because environment mutation would be outside the shell command string and would not disturb the verb allowlist or structural-metacharacter checks.
- Verified blocker: `src/superclaude/cli/reflect/` has Python subprocesses for git resolution, tmux launch, and ClaudeProcess audit/apply orchestration, but no Python implementation of the §6.1 step 5.5 `execute_shell_command` verification runner. The reflect skill itself says step 5.5 is `mcp__serena__execute_shell_command` (`/config/workspace/IronClaude/.claude/worktrees/ReflectGateWiring/src/superclaude/skills/sc-reflect-protocol/SKILL.md:466-467`), and the CLI runner only launches ClaudeProcess audit/apply subprocesses with the marker intentionally set (`/config/workspace/IronClaude/.claude/worktrees/ReflectGateWiring/src/superclaude/cli/reflect/runner.py:405-449`).
- Therefore a Python env-dict fix in `src/superclaude/cli/reflect/` would either target the wrong process (audit/apply child, where the marker must remain intact) or require adding a new verification runner that does not currently exist.

### Option C — add a §6.1.1 consumer-side control for wrapper-marker scrubbing

- This is the cleanest current fix surface because §6.1.1 is already the consumer-side envelope for Serena's unsandboxed `subprocess.Popen(command, shell=True)` execution (`/config/workspace/IronClaude/.claude/worktrees/ReflectGateWiring/src/superclaude/skills/sc-reflect-protocol/SKILL.md:491-491`).

Also amend control (b) at line 494 to say the allowlist applies to the base verification command before fixed consumer-side wrappers, and/or have (i) define that validation order.

The base command still must satisfy (a), (b), (c), and the no-mutation gate before any wrapper is added; `env` must not be added to the verb allowlist as a user-selectable command.
- Audit impact: keep (g) intact by recording the final executed command in `<output>/verify-logs/invocations.yaml`; adding a boolean such as `marker_stripped: true` would be useful, but if the schema must remain minimal, the fixed wrapper in the recorded `cmd` is enough to evidence the strip under current (g) (`/config/workspace/IronClaude/.claude/worktrees/ReflectGateWiring/src/superclaude/skills/sc-reflect-protocol/SKILL.md:499-499`).

## Summary

The likely fix surface is §6.1.1 of `src/superclaude/skills/sc-reflect-protocol/SKILL.md`, not `src/superclaude/cli/reflect/`. The reflect CLI correctly keeps `SUPERCLAUDE_REFLECT_WRAPPER_ACTIVE=1` in audit/apply children for nested-gate suppression; the leakage problem is that the skill's Serena `execute_shell_command` verification grandchild inherits that marker and can trip `superclaude reflect run` tests. Add a consumer-side control (i) after the existing eight controls, with a small control-(b) validation-order clarification, requiring the marker to be stripped only for step-5.5 verification commands via a fixed protocol-authored wrapper such as `timeout <N> env -u SUPERCLAUDE_REFLECT_WRAPPER_ACTIVE <base verification command>` after the base command passes template, verb, structural, timeout, cwd, audit, and no-mutation checks.
