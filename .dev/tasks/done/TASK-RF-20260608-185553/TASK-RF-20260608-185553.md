# Implement `superclaude reflect run` — thin fail-closed CLI wrapper for the POST reflect gate

## Task Overview

This task implements `superclaude reflect run`, a new Click sub-command package under `src/superclaude/cli/reflect/`. The wrapper turns the manual POST reflection HALT gate (today the task-builder tasklists emit `reflect_post: PENDING` and stop for a human to run `/sc:reflect --mode post` in a fresh session) into an unattended gate. It does this by launching reflect as a **top-level `claude --print` subprocess** through the existing `ClaudeProcess` primitive. A top-level subprocess is NOT an Agent-tool subagent, so it escapes the Agent-tool nesting limit and reflect's Tier-2 ensemble (heterogeneous-model reviewers + adversarial merge) actually fans out — the entire reason the naive "executor spawns a subagent" automation is structurally broken.

The wrapper is an **invocation + contract-consumption shell**, NOT a reimplementation of reflect (FR-2, NFR-1). It builds a single `/sc:reflect …` slash invocation, launches it, parses exactly `<output>/return-contract.yaml`, derives a 4-state verdict `{pass, halted, degraded, blocked}` from the contract fields per the spec §6 table, writes a structured `reflect_post:` block back into the tasklist frontmatter atomically and race-safely, and exits on a **fail-closed** exit-code contract (`pass`→0, `halted`→10, `degraded`→11, `blocked`→2). Because the wrapper is a completion-gate consumer, it must NEVER accept a silently degraded Tier-2 audit: it fail-closed HALTs whenever it cannot prove a full, non-degraded Tier-2 audit (FR-8, FR-11, NFR-4, §11 invariant probe).

The task additionally adds the opt-in `POST_REFLECT_MODE: wrapper|halt` (default `halt`) signal to the task-builder skill (`src/superclaude/skills/task-builder/SKILL.md`) so generated tasklists can shell out (Bash, never Agent/Task — NFR-7) to `superclaude reflect run` instead of HALTing for a human. When unset/`halt` the emitted tasklist is byte-identical to today (NFR-3 reversibility).

These were surfaced during research; each item that depends on one references it by index in its Context. Proceed with the stated recommended default but FLAG the decision in the Task Log — do NOT silently bake a guess that ships a wrong base.

1. **Base branch for `git merge-base` (LOAD-BEARING).** FR-3's `<BASE>` falls back to `git merge-base HEAD <integration>`, but `<integration>` is unencoded in code; the project trunk is `master` (origin/HEAD→master) while an `integration` branch also exists — hardcoding `integration` would compute the WRONG base. **Recommended default (applied in Phase 2 Step 2.2):** make the base branch a config parameter defaulting to `master` (`_DEFAULT_BASE_BRANCH = "master"`). Flag the decision.
2. **`--executor-model` source seam (IMPORTANT).** FR-3 derives `--executor-model` from "frontmatter/`EXECUTOR_MODEL_CLASS` env", but the SKILL frontmatter template lacks an `executor_model_class:` field. **Recommended default (applied in Phase 2 Step 2.2):** read `EXECUTOR_MODEL_CLASS` env first, fall back to a frontmatter field if present, else omit the flag (reflect tolerates absence). Flag the decision.
3. **`--remediate` flag (IMPORTANT).** The manual POST-gate `/sc:reflect` command includes `--remediate`, but the spec §8 wrapper prompt OMITS it (the wrapper is audit-only by default, FR-9). **Recommended default (applied in Phase 3 Step 3.5):** do NOT pass `--remediate` in the default audit-only path; document that the wrapper audits but does not auto-remediate. Flag the decision.
4. **chdir / cwd (MINOR).** `ClaudeProcess` has no `cwd` param; the child inherits the parent's cwd. FR-10 requires cwd = project root so `--diff` resolves. **Recommended default (noted in Phase 3 Step 3.5 runner / Phase 5 wrapper-arm):** the runner documents it MUST be invoked from the repo root (the tasklist's own worktree); no chdir is performed.
5. **`deviations` serialization shape (MINOR).** Spec §6 shows `deviations: { ... }` inline-flow, but `_IndentDumper` with `default_flow_style=False` emits block style (yamllint-clean, round-trips). **Recommended default (applied in Phase 3 Step 3.2):** use block style. Flag the decision in the write-back item.
6. **`max_turns` ceiling for the child reflect (LOAD-BEARING — surfaced by the `/sc:reflect --mode pre` audit, gap G1).** `ClaudeProcess` defaults `max_turns=100` (`src/superclaude/cli/pipeline/process.py:43`), and a Tier-2 POST reflect (heterogeneous reviewers + adversarial merge + evidence-validator + promotion gate) can exceed 100 top-level turns in one `claude -p` session → truncated/partial contract → wrapper routes `blocked`/`degraded` → the gate HALTs. The failure is fail-closed (safe) but would make the COMMON PATH HALT for exactly the medium/complex tasklists the wrapper exists to automate, negating the "zero human intervention in the common path" success criterion. **Recommended default (applied in Phase 2 Step 2.2 / Phase 3 Step 3.5):** set a config-layer constant `_DEFAULT_MAX_TURNS = 250` and pass `max_turns=config.max_turns` explicitly to `ClaudeProcess`; do NOT add a user-facing `--max-turns` CLI flag in v1 (keeps the spec §9 option set exact for the PG-gate "§9 exactly" invariant; a `--max-turns` override is deferred). Flag the chosen 250 default in the Task Log; revisit if real T2 runs approach the ceiling.
7. **`--resume` behavior (IMPORTANT — surfaced by the pre-execution audit, gap G2).** Spec §7/§9 specify `--resume` as "skips a still-clean HEAD", but the original plan declared the flag (models/config/CLI) without implementing its behavior — a declared-but-inert flag. **Recommended default (applied in Phase 3 Step 3.5):** implement the skip-on-clean-HEAD short-circuit in `ReflectRunner.run` (read the existing `reflect_post` block; if `reflect_post.head == config.head` and the prior `verdict == "pass"`, skip the launch and exit 0 with reason `resume-clean-head`), rather than dropping the flag from scope.
