# PR4 — Repair tests/audit/ fixtures + xfail genuinely-broken cases

## Task Overview

This is PR4 of a 5-PR CI rot cleanup release. Prior PRs (PR1 dev-deps, PR2 lint/format hygiene, PR3 ruff/mypy noise) have reduced extraneous CI failures. PR4 targets the `tests/audit/` failure cluster surfaced by PR #35's Python 3.10 run (job `76365604444`) — a set of tests whose fixtures no longer match the current scanner regex requirements. The work consists of: (a) running `uv run pytest tests/audit/ -v` to produce a complete failure inventory, (b) classifying every failure as `fixture-short` / `scanner-wrong` / `env-dependent` / `flaky`, (c) applying the user-chosen default from the /sc:brainstorm Q3 decision — fix the fixture to match scanner reality wherever possible — and (d) marking genuinely-broken cases with `@pytest.mark.xfail(strict=True, reason="...")` pointing to a single umbrella follow-up GitHub issue. The PR delivers AC3 (pytest tests/audit/ -v reports 0 failed/0 errors with xfail/xpass acceptable) and AC6 (an in-line PR review comment on the credential_scanner fixture diff demonstrating per-test triage). The worked example (mandatory for AC6) is the `tests/audit/test_credential_scanner.py` `FIXTURE_CONTENT` constant where `api_key = "FAKEAPIKEY"` (10 chars, double-quoted) must become `api_key = FAKEAPIKEY_1234567890ABC` (24 chars, UNQUOTED) so it matches the `[A-Za-z0-9_\-]{20,}` pattern at `src/superclaude/cli/audit/credential_scanner.py:28`. (The surrounding quotes must be REMOVED because the regex's trailing character class `[A-Za-z0-9_\-]` does not include the `"` character — a quoted value can never satisfy the {20,} quantifier regardless of inner length.) NFR4 escalation gate: if the discovery phase shows more than 20 distinct failing tests, halt in-PR work and escalate to `/sc:task --compliance strict` for sub-PR splitting; ≤20 proceeds in-PR.

## Key Objectives

The following objectives MUST be achieved by this task:

1. **Complete failure inventory:** Run `uv run pytest tests/audit/ -v` on the PR4 branch (after PR1+PR2+PR3 are merged into the working base) and produce a machine-readable classification table covering EVERY failing test with columns `test_path`, `assertion_summary`, `classification` (fixture-short / scanner-wrong / env-dependent / flaky), and `recommended-action` (fix-fixture / xfail / triage-further).
2. **Worked-example fixture fix (AC6 anchor):** Edit `tests/audit/test_credential_scanner.py` `FIXTURE_CONTENT` (lines 17-26) so the `api_key` value satisfies the `[A-Za-z0-9_\-]{20,}` pattern at `src/superclaude/cli/audit/credential_scanner.py:28` — specifically change `api_key = "FAKEAPIKEY"` to `api_key = FAKEAPIKEY_1234567890ABC` (REMOVE the surrounding double quotes AND lengthen to 24 chars; the quotes must go because the regex character class `[A-Za-z0-9_\-]` does not include `"`) — and verify the assertion `result.real_secret_count >= 3` now passes.
3. **Per-failure fix execution:** For every other failing test in the inventory, apply the classification's recommended action — fixture-short → lengthen/repair the fixture value; scanner-wrong → mark with `@pytest.mark.xfail(strict=True, reason="<umbrella-issue-link>: scanner pattern mismatch")` and add to the umbrella issue bullet list; env-dependent → either pin the fixture or xfail with the same umbrella issue; flaky → xfail with same umbrella issue.
4. **Umbrella follow-up issue:** Open a single GitHub issue listing all xfail'd tests as bullets (each with a link to the scanner code and a recommended scanner-side fix), then use that issue's URL as the `reason=` value in every `@pytest.mark.xfail(strict=True, reason="...")` decorator added in this PR.
5. **Local verification (AC3):** Run `uv run pytest tests/audit/ -v` and confirm 0 failed / 0 errors (xfail and xpass results are acceptable per AC3).
6. **Regression sweep (NFR2 transitivity):** Run `uv run pytest -v --ignore=tests/audit` and confirm the rest of the suite still passes (no fixture edit accidentally affected tests outside `tests/audit/`).
7. **Sync verification:** Run `make verify-sync` and confirm clean (no drift between `src/superclaude/` and `.claude/`).
8. **PR delivery with AC6 in-line comment:** Open PR titled `fix(tests): repair tests/audit/ fixtures + xfail genuinely-broken cases` on branch `fix/ci-rot-pr4-test-fixture-repair` and add the required in-line review comment on the credential_scanner fixture diff explaining the 10→24 character change and the `{20,}` pattern constraint.
