# Observer phase 3: question text, dispatch link and the Decision Desk

Source: ./source.md
Goal: With the question-to-session gate passed, the observer shows each coordinator question's real text instead of the subject "Question", links a selected question to the one worker session that sent it, and says "affected scope unknown" for any question it cannot link.

## Constraints

- Read-only. No write path into Orca. The allow-listed argv set and the forbidden verb set in `src/superclaude/cli/observe/adapter.py` (`QUESTION_TEMPLATE`, `FORBIDDEN_PREFIXES`, `assert_allowed`) do not change, and the argv log still shows only `worker-list` and the one `check --all --types question` call.
- The raw message `body`, the raw `payload` and `to_handle` are never kept on any object. Only the sanitized question text, the dispatch id and a link state are kept from the payload.
- Question text is screen-only. The JSON snapshot (`src/superclaude/cli/observe/export.py` `snapshot_dict`) and `src/superclaude/cli/observe/snapshot.schema.json` do not change, and the text record written by `e` and `--once` carries no question text, only ids and the link state. Whether question text may be exported is an owner decision that is still open; this plan builds the default (screen only).
- The link is dispatch level, as the owner confirmed on 2026-11-17 in `.dev/issues/409/bmad/spec-orca-observer/release-gates.md` (section QUESTION-LINK): message, to `dispatchId`, to the worker-list row, to that row's `resource.worktreeId`. The worktree id is shown as evidence about the one linked session and is never used to list or count other sessions as affected (acceptance check AC-7 in `.dev/issues/409/bmad/spec-orca-observer/acceptance-tests.md`).
- Unknown is never rendered as zero, false or blank. A payload that is not valid JSON, is not an object, has no valid `dispatchId`, or comes from a sender that is not `dispatch:<id>` with the same id reads as unlinked, never as an error.
- With the link switch off the observer behaves exactly as it does today: `tests/observe/golden_release1_surface.json`, the existing question golden tests and the link-off questions screen captured in Task 4 stay byte-identical, including the keys line.
- The honesty labels of a question line (age, bracketed state, `reason unknown`) are never clipped. Only the question text is shortened, with a visible mark.
- Out of scope: showing the payload `options`, using `taskId`, a worktree-wide affected set, any write-back, remote hosts, and the two-column Decision Desk layout of the design prototype (this plan builds one stacked block, like the R2 questions panel).
- Run tests with `uv run pytest tests/observe -q` and lint with `uv run ruff check src/superclaude/cli/observe tests/observe` and `uv run ruff format --check src/superclaude/cli/observe tests/observe`. Before any push, rebase the branch onto `origin/master`.
