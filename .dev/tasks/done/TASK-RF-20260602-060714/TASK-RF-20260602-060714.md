## Task Overview

This task remediates the 5 validated code-review findings (R1 through R5) that survived a parallel auggie-reviewer re-validation of the augment-bot reviews on PR #112 and PR #111 (IronbellyOrg/IronClaude). The findings span five surfaces of the roadmap pipeline and supporting tooling. **R5** (milestone-prefixed `M{n}-D{nn}` ID handling) is the single finding that could be a genuine defect rather than polish, so it leads the task as an **investigation + decision gate**: an executor first REPRODUCES the proven word-boundary false-positive (`\bD-?\d+\b` extracts `D01` from `M1-D01`) by building an `M{n}-D{nn}` spec+roadmap fixture and running the structural/fidelity checks, then writes a DECISION ARTIFACT that handles BOTH branches — (a) confirmed-not-needed → document evidence and recommend closing PR #111 as superseded, or (b) reproduce confirms the FP → re-introduce MD support SOURCED FROM `contracts.ID_PATTERNS` (never inlined — arch_lint Rule 2 forbids it), porting PR #111's 3 oracle unit tests and threading `md_ids` in lockstep across the registry, sidecar, and schema layers. The R5 implementation subtree is executed ONLY under decision path (b). **R1** is a comment-only docstring fix. **R2** is a resume-aware reset of a module-level sidecar-path global that must NOT fail-shut MERGE on a legitimate `--resume`. **R4** distinguishes grep exit-1 (ok) from exit-2 (fatal) in a POSIX skill script. **R3** is an optional, droppable defensive hardening of arch_lint Rule 2 against docstring literals.
