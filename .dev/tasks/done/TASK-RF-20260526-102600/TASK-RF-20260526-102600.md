# PR #86 PR A: Identifier Canonicalization Fix (F1 + F3 + F5)

## Task Overview

This task implements **PR A** from the pr86-integration-contracts adversarial merge (`/config/workspace/IronClaude/.dev/troubleshoot/pr86-integration-contracts-20260526100600/adversarial/merged-output.md`). PR #86 (`fix/integration-contracts-mechanism-signature`, head sha `67ab0af5`) introduced a `mechanism_signature` refactor that created an identifier-handling subsystem without naming its canonicalization invariants. Three of the five review findings share a single root cause: **F1** (hyphenated requirement IDs like `FR-S10-02` are dropped because `\b` word boundary splits on `-`), **F3** (Layer 3 identifier overlap is case-sensitive while Layer 2 normalizes case), and **F5** (test fixture comment misrepresents `_extract_identifiers` behavior). The Round 2.5 fault-finder surfaced a HIGH-severity gap requiring the **INV-002 amendment**: helper canonicalization alone is insufficient for F3 — Layer 3 MUST also call `window_text.upper()` (the original consensus's "OR" is actually "AND").

The fix is bundled into 7 enumerable steps: (1) add 4 behavior-pin tests in a new `TestExtractIdentifiersInvariants` class that go RED on PR sha `67ab0af5` and GREEN after the helper lands; (2) introduce the `_canonicalize_identifiers(text) -> frozenset[str]` helper with a 3-invariant docstring; (3) switch the construction-site call at PR-line 196 to use the new helper; (4) mandate `window_text.upper()` at PR-line 355 (INV-002); (5) update the `test_t1` filter from `c.spec_evidence` substring to `c.mechanism_signature[1]` membership so it actually asserts canonicalization fired; (6) rewrite the F5 fixture comment at PR-lines 129-131; (7) run a grep audit for other case-sensitive ident comparisons and document findings in the PR description. PR B (F2 empty-idents policy) and PR C (F4 subsumption symmetry) are RFC-first follow-ups and are explicitly OUT OF SCOPE for this task.
