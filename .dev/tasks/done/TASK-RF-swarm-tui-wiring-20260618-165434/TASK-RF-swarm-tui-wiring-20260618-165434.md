# Wire --tui flag into `superclaude swarm run` (Approach A)

## Task Overview

The swarm Rich Live dashboard at `src/superclaude/cli/swarm/tui.py` — the `TUI` class (start/update/stop/render), the `should_enable_tui()` gate, and `_project_workers()` — is fully built and unit-tested, but it is UNREACHABLE. `run_cmd` in `src/superclaude/cli/swarm/commands.py` has no `--tui` option, never imports the TUI module, and makes a single blocking `dispatch_wave1(...)` call with no observer seam. There is no way for an operator to see the live dashboard during a swarm run.

This task wires `--tui` into `swarm run` per **Approach A: threaded dispatch + main-thread file-tailing poller**, fresh-run path ONLY. In `run_cmd`, the existing blocking `dispatch_wave1(...)` call (plus its post-dispatch normalize/reduce continuation) is moved onto a NON-DAEMON background thread. The main thread gates on `should_enable_tui(tui, sys.stdout)` AND `state_output_dir is not None`; when both hold it constructs `TUI`, calls `start()`, then runs a 2/s poll loop that reads `.swarm-state.json` via `read_state()` and tails `execution-log.jsonl` via a new module-level `_tail_events(path, offset)` helper (byte-offset, exactly-once, partial-trailing-line tolerant), parsing each complete line with `from_json(EventRecord, line)` and feeding the result list to `tui.update(state, events)`. After the loop, the main thread joins the worker thread, calls `tui.stop()` in a `finally`, and re-raises any captured worker `BaseException` AFTER `stop()`. When the gate is closed (no `--tui`, non-TTY, or `state_output_dir is None`) the EXISTING fully-synchronous `dispatch_wave1(...)` path runs byte-identically with no thread, no tail loop, and no Rich import side effects.

Approach A makes "exactly one thread touches the Console" a STRUCTURAL property: the workers' only output channel is the filesystem (the `Logger`), and only the main thread reads that file and writes the Console. This is the crash-safety invariant (FR-1) that prevents the Rich Live cross-thread render crash class observed in #181/#182/#184. The non-daemon worker thread + explicit `join()` (FR-5) guarantees `execution-log.jsonl` is never truncated at interpreter shutdown. `dispatch_wave1` (dispatch.py) and `ParallelExecutor` (execution/parallel.py) signatures stay FROZEN (C3/AC-004/NFR-001).

This is a tightly-scoped CODE-implementation task. Verification rigor comes from (a) the full swarm pytest suite plus new FR-driven tests, (b) ruff lint + format-check, and (c) the POST reflect gate (an executor-disjoint heterogeneous audit). It deliberately waives multi-agent rf-qa lens gates per the QA_GATE_REQUIREMENTS: NONE decision (mirroring precedent TASK-RF-pr167-verdict-regex-20260613).
