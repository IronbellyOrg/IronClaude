## What this adds

`/sc:closeout <PR>` and the `sc-closeout-protocol` skill, for a pull request that has merged on the `origin` repository. It settles three things and prints one fixed-shape result block:

- **The issue.** A script reads the pull request state first and goes on only for a merged pull request. The skill then judges whether the issue is done by reading the issue's own criteria against what the pull request and its linked pull requests delivered. A done issue is closed once, with a note that says why and who merged. An issue that is not done stays open with one marked note of what remains, and the unmet criteria go back to the caller in the result. A case it still cannot tell is escalated with one question. The words `Fixes`, `Closes` and `Refs` decide nothing.
- **The work report entry**, settled through the orchestrator's report command, or escalated when that command is absent.
- **The worker's Orca task**, set to completed, or escalated when Orca or its Run is not there.

Every item ends with a stated final status or an escalation that says why. "Completed" means merged; the word "deployed" is never written. The command is for a person or the orchestrator, never a worker (it is on the never-as-worker list in four places).

Contents: the command, the skill (`SKILL.md`, three refs, four templates), two scripts (`branch-landed.sh`, `settle.sh`) with a names deny list, the routing row in `HOW-WE-WORK.md` and its plugin copy, the user guide entry, the CHANGELOG entry, the never-as-worker pin, the write-verb audit rows, and the tests. The design spec `docs/designs/sc-closeout.md` (owner approved) rides in this pull request.
