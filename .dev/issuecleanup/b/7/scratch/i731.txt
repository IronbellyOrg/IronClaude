#731 [OPEN] [BACKLOG] Reusable release planning pipeline: BMAD for planning, IronClaude for implementation
## What was tried

First design pass on 2026-11-22 and 2026-11-23, on the dashboard roadmap of issue #727. Nothing of the pipeline is built yet; the final form is to be formulated after the first release has gone through it.

- Two planning agents (one for BMAD, one for IronClaude) debated the pipeline for three rounds and signed a consensus with no open topics. Plan: BMAD does the upfront planning and collaboration (epics and user stories as the release plan), then hands each feature to IronClaude as a folder with one file per story; IronClaude reviews the spec, plans with `/sc:workflow`, executes with `/sc:implement`, and only the coordinator writes progress back. 15 epic drafts and 73 feature sub-issue drafts were written and not filed.
- Owner decisions of 2026-11-23: O1 (coordinator writes its own briefs for now), O2 (track the BMAD output in git), O4, O5 (build an unattended mode for `/sc:implement`), O6 and O7 approved; O3 (plan approval before implement) not answered yet. Branch model: each dashboard release is an integration branch, each user story a sub-branch of it, the release branch merges to the default branch, then the next release.
- Known gaps: `/sc:implement` has no unattended mode (O5 work item); BMAD's epics step needs a person; several BMAD and `gh` behaviours are UNVERIFIED and are trial items in the proposal.

## Done when

A reusable release planning and execution pipeline exists as a written spec plus the agents, skills, templates and commands it names, built from what actually happened in the first release: what worked, what the owner approved, what was iterated on or changed. `PIPELINE-RECORD.md` has an entry for every decision and every completed phase of that release (date, phase, what happened, who decided, evidence, status). The owner has reviewed the spec in chat. Preferably it has been tried on a second release.
