## Feature Summary

Add a standing rule that whenever an agent asks the user a decision or question, it assumes the user is coming in blind: the agent presents the context, implications and risks very concisely, and links an existing file with more information (never creates a file just to link it).

## Problem Statement

The Pragmatic output style already requires decision requests to be one question at a time, each option self-sufficient, and followed by answer lines (src/superclaude/output-styles/pragmatic.md:54-56, :43). But nothing tells the agent to assume the user has none of the session's accumulated context at the moment they read the question. In practice, questions can arrive that rely on context the user never saw, and there is no rule requiring a concise context/implications/risks preamble plus a link to an existing file with the details, nor a prohibition on creating a file merely to have something to link.

## User Story

As a user, I want every question or decision request an agent sends me to include enough concise context, implications and risks that I can answer it without having followed the session, with a link to an existing file for the full detail, so that I can decide correctly and quickly.

## Proposed Solution

Extend the decision-request guidance in the Pragmatic output style (src/superclaude/output-styles/pragmatic.md, "Decision requests" section, lines 52-57) with a rule that the agent always assumes the user is coming in blind: present the decision's context, implications and risks in a very concise, verbally efficient form (one or two lines each), and link an existing file that has more information. The agent must link an already-existing file; it must not create a file just to have something to link. If no existing file holds the detail, say so rather than creating one. Optionally mirror a one-line pointer in the relevant core rule (src/superclaude/core/RULES.md "Verification Before Recommendation" area, lines 54-66) only if needed for non-Pragmatic contexts; otherwise keep the change confined to pragmatic.md.

## Acceptance Criteria

- [ ] A decision request in the Pragmatic output style's rules carries one-line context, one-line implications, and one-line (or similar very concise) risk, readable by someone who has not followed the session.
- [ ] The decision request links an existing file with more information (for example an on-disk artifact or report path).
- [ ] The rule explicitly forbids creating a file for the purpose of linking it; if no existing file has the detail, the agent says so instead of creating one.
- [ ] The one-question-at-a-time, self-sufficient-option and answer-lines rules (pragmatic.md:43, :54-56) still hold unchanged.
- [ ] `make verify-sync` still passes (the `.claude/` mirror stays in sync with `src/`).

## Out of Scope

- Any change to the AskUserQuestion tooling or UI.
- Any change to worker/orchestrator internal communication rules (src/superclaude/core/WORKER-CONTRACT.md), which govern agent-to-agent messages, not user-facing questions.
- Generating or curating the "more information" files themselves; only existing files may be linked.
