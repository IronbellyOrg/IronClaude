# Pull Request

## Summary

Per-user ccsession tiers for Coder workspaces. `CCSESSION_ACCESS` in the central workspace env file (`defaults.sh`) sets, per Coder username, the tier ccsession starts on and the tiers it offers: space-separated `<username>=<start tier>[:<tier>,<tier>,...]` entries, where no tier list means every tier. The owner comes from `CODER_WORKSPACE_OWNER_NAME` (set by the Coder agent). A user who is not listed, or an unknown owner, keeps today's behaviour: `CCSESSION_DEFAULT_TIER` with every tier.

The Coder side, a separate <private-repo> PR after this merges, ships the first entry (`clay=tier1`), forwards the owner name to Orca terminals, and moves the IronClaude pin to this merge.

## Changes

- `models.py`:
  - reads `CCSESSION_ACCESS` and the owner, and resolves the start tier and allowed tiers;
  - applies them to `--help`, `--tier`, `--model`, `--models-status` and the shim's `/model` list and routing;
  - a broken or repeated entry for the current user stops the launch with the reason. A piece of the value that isn't a `name=...` entry, a `${...}` value, or the name on any other line of the file stops every launch that has an owner name. This fails closed rather than opening every tier.
- Env file reader: drops a trailing ` # comment`, splits lines at newlines only, and keeps the file when a byte isn't UTF-8, as bash does.
- `local-gateway-alias-proxy.py`: serves and routes only the owner's tiers. Each owner name gets its own shim.
- `ccsession`: header comment only.
- `tests/unit/test_ccsession_tiers.py`: new tests for parsing, refusals, the shim list and routing, and the reader changes.
- README, MODEL-TIERS.md, CHANGELOG.

The limit is advisory, and documented as such: the owner can undo it from their own environment or call a model directly with their gateway key. Only a gateway key limited to those models enforces it.
