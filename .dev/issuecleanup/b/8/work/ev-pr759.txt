Fixes #751. run_sweep only called first_run when it generated a missing config, so a config left enabled: false after a failed first run (for example worktree_invalid) was skipped as not_enabled forever. It now retries first_run for a disabled config whose first-run report says first-run: failed (config step every sweep, later steps after one hour; never on a dry run, on a config generated in the same sweep, or when the report is missing or says passed). Tests: 9 for failed_step and 7 retry tests (six fail against the old dispatch.py); tests/issue_watch passes (3030) and ruff is clean; the full repository suite was not run locally. Known limits: a crash between generating the config and its first run, or an unwritable report, still leaves no failed report, so those cases are not retried; the not_enabled skip text does not mention the one-hour delay. 🤖 Generated with [Claude Code](https://claude.com/claude-code)
