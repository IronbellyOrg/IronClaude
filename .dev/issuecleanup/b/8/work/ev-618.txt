#618 Make IronClaude's ruff version follow the Coder image pin instead of its own [OPEN ] closed=-
Owner request (2026-11-17): IronClaude should stop pinning its own ruff version. If a pin is needed, IronClaude's pin should simply point to the Coder image's pin.

## What was tried
- **The failure that exposed this.**
  - On 2026-11-17, a `/sc:pr-submit --monitor 3` run on PR #614 halted at validation gate VG-4 (`uv run ruff format --check src/ tests/`).
  - The check reported 12 files that "would be reformatted". The PR changed no Python code. All 12 files are Markdown, and each is byte-identical to `origin/master` (e3e9d636a).
- **The root cause, verified.**
  - IronClaude pins `ruff==0.15.20` in the `dev` extra. The worktree's `.venv` had no dev extra installed, so ruff was missing there.
  - `uv run ruff` then fell back to the Coder image's system copy at `/usr/local/bin/ruff`, which is version 0.17.3.
  - Ruff 0.17.3 also formats the Python code blocks inside Markdown files. It checked 1970 files, where 0.15.20 checks 1392.
  - With the pinned version (`uvx ruff@0.15.20 format --check src/ tests/`), the check passes: "1392 files already formatted". CI installs the dev extra, so it gets 0.15.20 and passes.
- **Two pins that disagree.**
  - IronClaude pins 0.15.20 in three places.
  - The Coder workspace image pins 0.17.3 (Coder CHANGELOG entry for #364; contract test `test-77-ruff-requests-baked.sh`; Renovate keeps it current).
  - Any session that runs `uv run ruff` without the dev extra gets Coder's version, so the local result and CI disagree.
- **No change has been made yet.** The owner halted the PR #614 run.
