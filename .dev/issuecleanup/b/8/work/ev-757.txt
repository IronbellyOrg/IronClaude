#757 [FEATURE] Run the coordinator sweep outside the session and wake it only on change [OPEN ] closed=-
## Feature Summary

A scheduled task that runs outside the coordinator session, with no model in the loop, performs the coordinator's periodic read-only checks, compares them with the last recorded state, and wakes or pings the coordinator session only when something actually changed or a decision is outstanding for the first time.

## Problem Statement

The standing coordinator session keeps a recurring cron prompt that fires every 10 minutes; each firing runs the session's sweep and report pass even when nothing changed, printing "Nothing has changed, and nothing new needs you..." into the channel every tick. This fills the channel with noise and spends model tokens on every tick for zero information. WC-16 makes the coordinator run the sweep itself at most once every 5 minutes on every wake or wait timeout (src/superclaude/core/WORKER-CONTRACT.md:290) and states "Phase 1 adds this duty, not a scheduler", so today there is no scheduler outside the session to suppress the empty ticks.

## User Story

As the project owner, I want the periodic checks to run in a model-free scheduled task that wakes the coordinator session only when there is something to act on, so that the channel stays quiet and tokens are not spent on unchanged ticks.

## Proposed Solution

The goal: move the read-only observation duty (the collection and classification that `superclaude sweep run` already performs read-only, src/superclaude/cli/sweep/commands.py:242-288) into a scheduled task outside the coordinator session. That task compares each run's result with the last persisted state and, only on a real change or a first-time outstanding decision, wakes the coordinator session through an existing wake channel (Orca messages, `orca terminal send` as used at src/superclaude/core/WORKER-CONTRACT.md:136, or a cross-session SendMessage). Constraints:

- The scheduled task must remain read-only in effect apart from its own state file and report output (the sweep package already keeps exactly one writing function, `_publish`, src/superclaude/cli/sweep/commands.py:153-208).
- WC-16's rules stay authoritative: only Orca's stall proofs make a worker stalled; the sweep recommends nothing (src/superclaude/core/WORKER-CONTRACT.md:290).
- The coordinator's wait (`orca orchestration check --wait ... --timeout-ms 300000`, src/superclaude/core/WORKER-CONTRACT.md:102) and its re-arm behaviour must stay compatible with being woken by the outside task.
- The cron entry pattern already exists in the issue watcher (`src/superclaude/cli/issue_watch/dispatch.py`, one cron entry running a sweep with absolute paths) and can be the model for a cron-driven coordinator wake path.

The concrete design (scheduler choice, state comparison format, wake channel, and the WC-16 wording change) is to be produced by a `/sc:brainstorm --depth deep` session; this issue does not fix it.

## Acceptance Criteria

- [ ] With no changes between two consecutive scheduled checks, the coordinator session produces no per-tick report output (no "Nothing has changed..." message) and no model tokens are spent on the tick.
- [ ] When a real change occurs (worker result, new message, first-time outstanding decision), the outside task wakes the coordinator session and the coordinator handles it under the existing WC-6/WC-16 rules.
- [ ] The scheduled task itself performs only read-only checks apart from its own state and report files.
- [ ] WC-16 and "Liveness supervision" in src/superclaude/core/WORKER-CONTRACT.md are updated to describe the new division of duty.

## Out of Scope

- Changing what the sweep classifies or probes (the sweep package's read model stays as is).
