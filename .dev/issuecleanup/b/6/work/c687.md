## Feature Summary

A script that removes git worktrees of our own repos that hold finished, merged work, and nothing else. Before it removes a worktree that holds untracked or ignored workflow files under `.dev/`, it saves them to a private evidence repo (`<private-repo>`) and checks the copy against GitHub; if that fails the worktree stays. It removes a worktree only when its own pull request is merged, nothing was added after it, the issue it was for is closed, nothing but its own Orca terminals is using it (they are closed first), and it has been idle 7 days. It runs by hand through a thin command (`/sc:worktrees`) and once a day at 2:00 AM Central (08:00 UTC) through an opt-in Orca automation in each Coder workspace that starts no agent. Adapted from Jay Wedgeworth's lane retire, lane prune and disk janitor (Apache-2.0). The full spec is in this issue, below.

## Problem Statement

Nothing removes merged worktrees and nobody decides when. On 2026-11-20 git knew 53 worktrees of our repos besides the main checkouts (49.4 GB) and Orca listed only 26 of them. A dry run of the rules finds 13 removable (3.1 GB), 4 of which need their workflow files saved first. The workflow files (`.dev/issues/<n>/` reports, PR monitor output, logs) are untracked or git-ignored, never reach a pull request, and are deleted with the worktree. Sixteen workspaces were removed by hand that day after saving; two of them belonged to issues still open (#354, #419), which is why the issue check is a rule. Numbers and sources: spec section 2.

## User Story

As a person who works in Coder workspaces, I want merged worktrees removed safely every day and their workflow files kept somewhere I can mine later, so that disk and the sidebar are not eaten by finished work, no unfinished work is ever lost, and the source repos do not fill with thousands of run files.

## Proposed Solution

One script, `scripts/worktree_cleanup.py`, with four verbs (`list`, `archive`, `retire`, `prune`; dry run by default, `--apply` to remove) and a thin command `/sc:worktrees`. A removal is: save the `.dev` files (verified against GitHub), close the worktree's Orca terminals and check again, clear exactly the saved files with `git clean`, then `orca worktree rm` (worktrees Orca lists) or `git worktree remove` (the rest) without `--force`, then `git branch -d`. Facts come from git, GitHub and Orca, never from an agent's word. A worktree is removed only when all eight rules of spec section 6 hold. The design, the alternatives rejected and Clay's decisions are in the Design section; the full spec follows it.

Rulings from Clay, not to be re-asked:

1. Home is IronClaude. The removal code is plain scripts with no model call, so this is a script run by a scheduled Orca automation that starts no agent, plus a thin command so a person can run it. It is not a skill.
2. The schedule is opt-in: not set up for everyone who installs IronClaude.
3. Remove only worktrees whose pull request is merged and that hold nothing new or changed that was not in the pull request. (Changed on 2026-11-20 by the save step: workflow files under `.dev/` that are saved and verified in the evidence repo no longer count. Spec section 7.
