# #678 Launch-level guard: a bare 'claude <prompt>' command runs a turn outside the limits (442 OB-H1 item 8) [OPEN]
## What was tried
Observation OB-H1 item 8 of issue 442 (live run, Claude Code 2.1.327, 2026-11-18). A session ran this Bash command: `timeout 60 claude "reply with the single word ob-item8" < /dev/null`. The launch-level guard (`src/superclaude/hooks/scripts/launch-level-guard.sh`, lines 445-460) marks `claude` as an escape only when the same command also holds one of these flag words: `-p`, `--print`, `--continue`, `--resume`, `--bare`, `--settings`, `--dangerously-skip-permissions`, `--fork-session`, `--session-id`, `--permission-mode`. A bare `claude "<prompt>"` carries none of them, so the guard lets it through. Result: a new Claude session started, got its own session id, and ran a turn (a Stop event was logged for the new id). In a real governed launch that nested session has no launch marker, so the guard would treat it as an ordinary session and apply none of the launch-level limits.
