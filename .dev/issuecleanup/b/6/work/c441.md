# #441 [FEATURE] Build the L2 pre-push layer of the launch-level guard, then make a missing L2 a refusal [CLOSED COMPLETED] closed 2026-11-10T11:24:58Z
## What was tried
PR #432 (merged 2026-11-08) built the first layer (L1) of the launch-level guard for claim-launched agents, a hook that reads the text of each Bash command. It built no second layer (L2, a pre-push check). The PR body says so: "The L2 pre-push layer is not built (`artifacts/l2-disposition.md`)".

The design says a missing L2 layer should make the launch refuse (rule IR-7). The PR did not do that: a refusal would switch off every governed claim and make the live observations impossible, so the launch only prints the warning `W-L2-ABSENT` and continues. The owner accepted "warn now, refuse later". Turning it into a refusal later is one line (`artifacts/ir7-consequence.md`).

Why L2 matters: the L1 guard is text only. The Codex security review of PR #432 found that `cd ~/.claude/. && mv state state.old` removed the guard's state folder in two steps; the fix added dot segments and doubled slashes as tamper. The author's reply on that thread states the limit: "variable and quoting tricks still pass; the pre-push layer (L2) is the real answer and is not built in this PR" (review comment 4503735032). `artifacts/final-check.md` lists more known limits, for example a curl write passes when a word named `gh` sits in the same command, and an `orca send` can pass when the command ends in `-h`.
