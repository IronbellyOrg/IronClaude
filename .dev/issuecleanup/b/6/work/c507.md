## Feature Summary

Make `--unattended` and exactly one report directory the positive default on each eligible worker `Command:` line, with an explicit coordinator preflight against the command copies the worker will see. This is a coordinator-side documentation and test-pin change, not a change to command behaviour or a worker-side repair mechanism.

## Problem Statement

The coordinator instructions describe `--unattended` as a restriction rather than a dispatch default. The section 5 brief template omits the flag, its slot rules retain obsolete P0 instructions, and the routing guide says only to use the flag where supported. The two-copy decision already exists in the contract, but only as prose, not as a numbered step before creating a Task.

The guard refusal strings say what is wrong without saying how the coordinator repairs it. Static tests pin several obsolete phrases, and the developer guide still says that no command accepts the flag at P0 and that the unattended-command set is empty. These instructions need to agree without broadening what workers are allowed to do.

## User Story

As an Orca coordinator, I want each worker step to have an explicit unattended command line and a known report directory, checked against the worker's command copies before Task creation, so that workers do not start with missing flags or stale-copy mismatches and any refusal tells me what to repair.

## Proposed Solution

1. **Make the default positive and per step.** Rewrite section 5 of `src/superclaude/core/WORKER-CONTRACT.md`, including the `Command:` template and slot rules, and the Orca-coordination bullet in `src/superclaude/core/HOW-WE-WORK.md`. Keep the plugin routing-guide copy byte-identical. Put a standalone `--unattended` and exactly one report directory on every eligible worker `Command:` line unless the two-copy check fails; do not treat unattended mode as a session-wide setting. A failed check stops that dispatch for coordinator repair, rather than silently starting a person-mode worker. Preserve the never-as-worker exclusions.
2. **State the initial default set and its limits.** List the 16 phase 1 commands as the default worker set: adversarial, brainstorm, cleanup-audit, graph, impact, index-repo, init-lite, workflow, analyze, build, business-panel, design, document, explain, index and test. Phase 2 commands are not promoted into that default set merely because their files contain the section; require a phase 2 live check first. Keep their documented support distinct from default-set admission. Starting each command through its Skill call is mandatory; reading its command file is not a substitute. A person-in-the-loop run is not a worker.
3. **Add a numbered coordinator preflight.** Before the first `task-create` for a command, apply the guard's test to every existing command-file copy the worker will see: the target worktree's project `.claude/commands/sc/<name>.md` and `~/.claude/commands/sc/<name>.md`, not the coordinator's own project copy. Set the flag only when all existing copies have `## Unattended mode`; disagreement or absent support requires repair before dispatch. Repeat the decision for each command in a chain.
