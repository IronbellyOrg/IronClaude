# PR #711 feat(worktrees): remove finished git worktrees with /sc:worktrees and scripts/worktree_cleanup.py (issue 687) [MERGED] merged 2026-11-22T10:08:02Z 6b17a7449f9400a9acc4140d6ce48dec93a9de8e
## Summary

Refs IronbellyOrg/IronClaude#687. Adds `scripts/worktree_cleanup.py` (Python standard library only) and a thin `/sc:worktrees` command with four verbs: `list`, `archive`, `retire` and `prune`.

A worktree is removed only when all eight rules hold: it is a linked worktree of one of our repos, its own pull request is merged, nothing was added after that pull request, every issue it relates to is closed, nothing unsaved is in it, nothing but its own Orca terminals is using it, it has been idle for 7 days, and it is not pinned. `list`, `retire` and `prune` are dry runs unless `--apply` is typed. `archive` is the one verb that writes without it: it saves the untracked and ignored `.dev/` files to `<private-repo>`, checks the copy against GitHub and removes nothing. A fact the script cannot read keeps the worktree and exits 69.

## What changed

- `scripts/worktree_cleanup.py`: one runner with a positive allowlist of exact argument shapes (no `--force` on a removal, no `git branch -D`, no `rm`, no `git worktree prune`, no remote branch delete, and the only push is to the evidence clone); the eight rules; the archive step with a names-only secret check; the removal pipeline (save, close Orca terminals, check again, clear exactly the saved files, remove, `git branch -d`, read back); the four verbs with a per-repo lock, output files and exit codes 0, 64 and 69.
- `src/superclaude/commands/worktrees.md`: the command, for a person only (on the never-as-worker list).
- Registrations: routing guide row (and its plugin copy), worker contract and developer guide, user guide, CHANGELOG, NOTICE and `scripts/worktree_cleanup_PROVENANCE.md` (rules adapted from Jay Wedgeworth's AI-Fleet-Coordinator under Apache-2.0).
- `scripts/worktree_cleanup_orca_automation.md`: a definition of a daily Orca automation, written and not switched on. No automation was created or run.
- Tests: `tests/worktree_cleanup/` and `tests/commands/test_worktrees_command.py`. They use throwaway repositories, a local bare repository standing in for the evidence repo, and fake gh, git and orca replies only.
- The `.dev/tasks/done/` package holds the plan, the ledger and the evidence of the build.

## Safety

No test and no run of the build removed, moved or cleared any real worktree. The only run against the real workspace was a dry run (`list` and `prune` without `--apply`): 566 recorded commands, none a removal, terminal close, archive or push; the worktree lists of every repo were identical before and after (`.dev/tasks/done/TASK-WF-specWorktreeClea-20261120-173546/artifacts/dry-run-report.md`).
