### Summary

The issue watcher runs first-run setup only when it generates a missing config. If that first check fails (for example `worktree_invalid` because the Coordinator worktree did not exist yet), the config stays `enabled: false` and later sweeps skip it as `not_enabled`, so the trigger label, state and lock need manual commands. The fix is to retry unfinished setup on a later sweep through the existing first-run path, without re-enabling projects someone disabled on purpose and without writes in a dispatcher dry run.
