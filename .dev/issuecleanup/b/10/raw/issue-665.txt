## Findings from the review of PR 681 (spec landing)

PR 681 lands the owner-approved design `docs/designs/orchestrator.md` unchanged. The Augment and Codex reviews raised six findings about its text. The owner approved the text byte for byte, so none was fixed in that docs-only pull request. They are recorded here for the follow-up of the design.

1. [Codex P2, line 565](https://github.com/IronbellyOrg/IronClaude/pull/681#discussion_r4636029171): the wave 4 worktree helper takes its source checkout from the current directory, so it must be run from the issue's repo checkout and not from the orchestrator repo.
2. [Codex P2, line 708](https://github.com/IronbellyOrg/IronClaude/pull/681#discussion_r4636029179): a `done` or `skipped` issue that is reopened or reassigned cannot be retaken, because `--take` creates the state file exclusively and only three `escalated` endings are archived.

[Augment high, line 350](https://github.com/IronbellyOrg/IronClaude/pull/681#discussion_r4636047200): the sample poll precheck runs `superclaude issue-watch once` without `--dry-run`, while the shadow phase is meant to be a dry run (section 4.8 adds the flag), so the sample can be mistaken for the shadow command.

[Augment medium, line 702](https://github.com/IronbellyOrg/IronClaude/pull/681#discussion_r4636047226): a plan request acknowledged as skipped for `held_backlog` has no plan record, so the in-flight count treats it as in flight and a lasting backlog label can hold a slot and trigger extra orchestrators.

## Follow-ups from the review of PR 684 (the report skill moved into IronClaude)

These findings are about code moved unchanged from the IronFlow repository (or were left out of PR 684 on purpose). None was fixed in that pull request.

1. **Local report server (security).** `page.py` `ensure_server` runs `python -m http.server --directory .dev/coordinator` on 127.0.0.1:8765. It serves the whole state folder with a directory listing and accepts any Host header, so a page in the operator's browser that uses DNS rebinding could read run files and transcript excerpts. Fix: serve only `report.html`, reject any Host other than 127.0.0.1:8765, and turn the listing off.
2. **Item titles are not quoted as data.** An instruction-shaped title (a renamed issue or task) reaches the report session as raw Markdown. Fix: quote the title on its own line; this changes the item template, the heading rule in `check.py` and the parsing in `page.py`.
3. **A ClickUp task whose only GitHub link is in a comment loses that link** once the comment leaves the collection window, so the task gets its own card again.
4. **Replies inside a ClickUp comment thread** are collected but not printed in `activity.md`, so the report session never sees a reply that asks the owner something.
5. **Removed in PR 684 because the spec does not ask for it:** the carry-forward of ClickUp tasks and sessions across a claim (each review round found a deeper case in it). If the owner wants it back it needs its own design.

## Findings from the review of PR 686 (PR A, the poll core): required before the poll is switched on

PR 686 ships the poll with `enabled: false`. Codex raised these seven findings; none is a bug that blocks merging disabled code, but each must be resolved before switch-on (the shadow run will also show whether they matter).

1. `cycle.py` `_ack_step`: an acknowledgment of the first wake is not read after a resend replaces the entry's `wake_id` (one `wake_id` per entry in the schema-2 store); the entry can end abandoned although the orchestrator took the wake. Fix: read acknowledgments of earlier unarchived wake files, or change the schema.
2. `github.py` org-wide search bound (100 rows) counts unlisted repos, so someone who can assign the account in an unlisted repo could stop the poll (availability). Fix: query listed repos only (changes discovery and the call budget).
3. `github.py` timeline read is one page of 100: the newest events of a long issue can be missed. Fix: bounded pagination (a new allowed argv form).
4. `cycle.py` day-cap reservations of plan requests that routing then declines can crowd out a ready assignment in the same cycle (cycle order).
5. `cycle.py` a failing resume of a dead orchestrator keeps no attempt count and retries every cycle (restart state in the store or registry).
6. `cycle.py` `last_poll_at` advances although information items beyond the 50-item limit (or a failed information-only delivery) were not delivered (needs a cursor that cannot pass undelivered items).
7. (fixed in the PR) registry probes fell back to a 1 s call with no allowance.
