### C10. Worker check-in template and the hourly status pass (655 section 2, 3, 4, 8, 10; rows S03-F21, S04-F37, S02-F32, S08-F7, S10-F25)
  - What to build: The coordinator skill carries one check-in template used at each `--hourly` pass, id-only for GitHub data and written under the four typing rules.
  - Also in this item:
    - S04-F37: The coordinator sends each running worker an hourly status request from one template and reads the worker's answer from fixed fields.
    - S02-F32: `/sc:coordinator --hourly` runs a status check per running worker (Orca state, optional check-in, issue re-read) at a configurable interval, default hourly, Monday to Friday, and stops for a worker once its `worker_done` arrives.
    - S08-F7: Define the `/sc:coordinator --hourly` pass as a once-an-hour check of each running worker, Monday to Friday, with a configurable interval, that ends for a worker when its `worker_done` arrives.
    - S10-F25: For each running worker the coordinator runs one status check an hour (interval configurable), reading Orca state and the issue, Monday to Friday around the clock, and stops the check for a worker when that worker sends `worker_done`.
  - Done when: a test fills the template and the filled text contains no GitHub-sourced free text and is refused by `refuse(argv)` if the target terminal has unsent typing or output under 60 seconds old.

    - also: a fake clock test shows one check per running worker per interval on weekdays, none on Saturday or Sunday, and no check after `worker_done`.
