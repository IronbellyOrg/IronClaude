@ironbelly thank you for the roadmap. One thought from how we expect to work with many coordinators at once. For one person to handle 20 or more pull requests a day, there needs to be one place to ask "where does this stand?" and to send a message to any coordinator. Jumping between coordinator sessions will not scale. The review item "routing to the correct coordinator" looks like the key part either way.

We would like to offer one idea for how that place could work. Much of our own work already happens through agents rather than screens, so the single place could be a small set of contact agents (two or three), each following several coordinators, that can answer "where does this stand?" and pass a message on. The dashboard would stay as one view of the same data. We know the earlier research found that one agent for everything does not keep up with 5 projects of 10 to 15 worktrees each. A few agents, each with a bounded set of coordinators and all reading the same code-generated feed, might avoid that flood. Would it be worth trying both ways on a small scale? The same question applies to the "orchestrator of orchestrators" line in plan item 3 of #409 and to the cross-host view in #604.

Happy to help write it up.
