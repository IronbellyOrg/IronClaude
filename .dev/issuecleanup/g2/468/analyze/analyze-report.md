## Architecture and metrics
The contract describes a loop that no program runs. It is text that a coordinator session is told to follow, and tests pin that the phrases exist; nothing in code executes the loop (`docs/architecture/SUPERVISED-ORCHESTRATION-TECHNICAL-REFERENCE.md:961`: "A coordinator program: N/A, not built; the loop is a person-directed LLM session by design").

The loop has two parts:

1. A blocking wait. `src/superclaude/core/WORKER-CONTRACT.md:102` gives the command `orca orchestration check --wait --types status,dispatch,worker_done,merge_ready,escalation,handoff,decision_gate,question,heartbeat --timeout-ms 300000`. Line 104 states that `--types` only decides when the wait wakes, and that the returned delivery is the whole queue batch. Line 109 says a heartbeat only updates the worker's heartbeat record and is never proof a worker has stalled.
2. A sweep. `src/superclaude/core/WORKER-CONTRACT.md:111` says that after every wake or timeout, at most once every 5 minutes, the coordinator runs one worker listing, one prompt-wait listing and one file check per worker.

The cadence the issue wants halved is not set here. `src/superclaude/core/WORKER-CONTRACT.md:7` says the dispatch preamble, issued per dispatch by the running Orca version, is the authority for heartbeat cadence, and that the contract never copies it. The technical reference records the Orca default as 5 minutes (range 1 to 60, off when null) and marks the running value UNVERIFIED (`docs/architecture/SUPERVISED-ORCHESTRATION-TECHNICAL-REFERENCE.md:1742`), and states that changing the cadence is an Orca setting, not IronClaude code (`:961`). Line 1746 states that nothing in code enforces any of the contract's own cadences.

The initial literal search missed partial question-retention code: `src/superclaude/cli/observe/questions.py:3-11,81-137` implements an in-memory store without any closure evidence source, `src/superclaude/cli/observe/collector.py:214-245` merges question reads into dashboard state, and `tests/observe/test_questions.py:40-78` covers retention, failed reads and disappearing source rows (read, not executed). The only match for the notification wording "orchestration message" is the launch-level guard (`src/superclaude/hooks/scripts/launch-level-guard.sh:497`), which classifies `orchestration check` as a read verb; it does not produce notifications.

3. Assess reuse of the existing question store, collector integration and retention tests before proposing another store. Design the missing actual-user-answer closure evidence, durability and automatic presentation separately; retention alone does not satisfy the issue.
