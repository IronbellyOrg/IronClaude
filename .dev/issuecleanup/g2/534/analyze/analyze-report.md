## Architecture and prioritized findings
1. **P2, open: bounded reads still prevent complete large-Run visibility.** `probes.py:129` defaults to 50 detailed worker reads; `:171-183` refuses the next read; `:1150-1161` makes one worker-list request and records a full page or `hasMore` as truncated, without following a cursor. `:1265-1280` records skipped detailed reads. The exact current behavior is deliberately pinned by `tests/sweep/test_probes_allowlist.py:1137-1152` (60 listed rows, 50 detailed reads, 10 skipped). PR #579 did not implement issue #590. Impact: a coordinator cannot interpret missing activity as no activity, especially after restart. If the owner confirms paging after measurement and reconciliation of the conflicting records below, that approach needs coordinated budget, paging allowlist, coverage and fixture/test changes, not a new subsystem; the final implementation choice is UNVERIFIED.
2. **P2, open: invalid YAML becomes a fieldless record marked read.** `probes.py:722-734` converts parser errors into `{}`, `:737-760` builds a record with no worker status, and `:1426-1429` marks that record as read. Thus a malformed blocked contract can lose its blocked signal while appearing covered. `tests/sweep/test_probes_allowlist.py:1968-1994` explicitly expects fieldless invalid YAML. This is an input-quality visibility gap, not a claim that malformed YAML should be accepted. A parse diagnostic is the minimal change.
3. **P3, not a defect to reopen: accepted output buffering and chat-summary limits.** `probes.py:270-289,342-352` buffers subprocess output then checks the limit, matching the owner's recorded acceptance, not the original streaming design. Owner ruling files cited in the issue accept both this and the chat reply's lack of outage text. Keep these as limitations unless the owner changes the decision.
4. **Partly resolved: worker-state interpretation.** `classify.py:251-268` now recognizes a live worker with outcome `in_progress` and an explicitly null wait signal; the captured end-to-end regression is `tests/sweep/test_cli_contract.py:1133-1160`. Non-null wait behavior is implemented at `classify.py:226-236` but the real non-null shape remains UNVERIFIED in `tests/sweep/fixtures/SOURCES.md:25,42`. Do not describe that path as absent code or as live-validated.
5. **P3, documentation reconciliation remains.** `docs/designs/orchestrator-mode.md:1002-1016` still lists uncaptured paging, unverified wait data, rollback/fallback checks and proposed size-limit rationale. The wording mismatch about coordinator wakes is also still present. These require scoped triage, not blanket reopening of owner-accepted deviations.
