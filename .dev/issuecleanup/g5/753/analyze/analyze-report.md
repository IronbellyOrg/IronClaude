## Findings
1. **High: role membership is captured at setup, not refreshed from GitHub during approval.** `/home/coder/workspaces/worktrees/IronClaude/Issuecleanup/src/superclaude/cli/issue_watch/generate.py:211-214` returns before discovery if configuration or an orphan approvers file already exists. Lines 233-245 merge fixed ids and a maintainer lookup, then remove the launch account. `/home/coder/workspaces/worktrees/IronClaude/Issuecleanup/src/superclaude/cli/issue_watch/cycle.py:718` reloads the file each cycle, not GitHub roles. `/home/coder/workspaces/worktrees/IronClaude/Issuecleanup/src/superclaude/cli/issue_watch/predicates.py:253-261` only tests supplied membership and exclusions. Therefore a new maintainer absent from that file is rejected, and a demoted user still listed can pass this membership check if the other approval requirements pass. Existing configuration protection is intentional and should not be replaced with blind file overwrites.
2. **High: generated membership prevents the launch account from approving even if it is an administrator.** The discard at `/home/coder/workspaces/worktrees/IronClaude/Issuecleanup/src/superclaude/cli/issue_watch/generate.py:243-245` is unconditional. `/home/coder/workspaces/worktrees/IronClaude/Issuecleanup/tests/issue_watch/test_generate.py:173-195` explicitly expects exclusion and an empty-result skip. By contrast, the approval predicate's exclusion is explicit and configurable, not inherently tied to the launch account. Merely deleting the discard fixes neither freshness nor demotion.
3. **Retain the current validation boundaries.** `/home/coder/workspaces/worktrees/IronClaude/Issuecleanup/src/superclaude/cli/issue_watch/cycle.py:323-386` checks file type, ownership, writability, inode stability and id syntax. `/home/coder/workspaces/worktrees/IronClaude/Issuecleanup/src/superclaude/cli/issue_watch/cycle.py:940-950` and `:1076-1083` pass the same cycle membership and explicit exclusions into both approval checks. A role resolver belongs at the read/coordinator boundary, not as a network side effect inside the pure predicate; keep event ordering, human-actor checks and exclusions.
4. **Read completeness is part of the fix.** `/home/coder/workspaces/worktrees/IronClaude/Issuecleanup/src/superclaude/cli/issue_watch/generate.py:117-126` requests at most 100 collaborators without pagination, and `:172-179` reads only ids. Do not reuse that helper unchanged as proof of complete current admin/maintain membership. Actual GitHub filter semantics and live role assignments are UNVERIFIED in this read-only issue/PR review.

## Recommendations
Implement a current-role read per cycle (or equivalent freshness guarantee) before membership can authorize work, accept maintain/admin including the launch account, and retain explicit exclusions. Do not union stale generated ids back into current role-derived authority. Prefer skipping approval with an audited reason on a failed, incomplete or malformed role read rather than treating old data as current, so revocation cannot silently fail. Keep shared deadline/rate limits and both approval checks aligned. Add promotion, demotion, launch-admin, exclusion, read-failure and multi-page tests; replace generator tests that enforce the old unconditional exclusion.
