## Specific security checklist

For each item below, search the snapshot and report findings:

1. **Path traversal** — every function that joins user input to a base path: does it call `Path.resolve()` then check `is_relative_to(base)`? Or does it just `joinpath`?
2. **Symlink traversal** — when walking a scratch tree, are symlinks followed? Do walkers reject symlinks pointing outside scratch_root?
3. **TOCTOU** — gap between "validate path is inside scratch_root" and "open path" — does an attacker who controls the filesystem in between get to substitute a symlink?
4. **Command injection** — every `subprocess` call: is `shell=False`? Are all args literals or from typed sources?
5. **Deserialization** — every `yaml.load` / `pickle.load` / `json.load` of untrusted input: is `safe_load` used? Is the source trusted?
6. **AC12 allowlist tautology** — commit dce3c3cb claims to fix a tautological allowlist check in isolation.py. Read the current allowlist logic and verify:
   - Default-deny is the posture (unknown paths rejected, not allowed).
   - The allowlist is not `if path in allowlist or True:` or similar.
   - The fix introduced a meaningful constraint, not just renamed a variable.
7. **Secrets in logs** — any `logger.info(...)` / `print(...)` that might emit env vars, API keys, paths containing tokens?
8. **Insecure tempfile** — any `tempfile.mktemp()` (deprecated, race-condition vulnerable) instead of `mkstemp` / `TemporaryDirectory`?
9. **PTY input echo** — does `pty_driver.py` log raw user input that might contain secrets typed into the eval?
10. **YAML/JSON DoS** — billion-laughs / deeply-nested input to `loader.py` — is there a depth limit?
