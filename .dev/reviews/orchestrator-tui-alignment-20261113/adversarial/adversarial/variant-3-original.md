### What IronClaude must supply or wait for

1. **A decision on option A versus B or C** (Q1). Until it is made, #477 has no stable requirement set; the watcher (#450) must not wait on #477 and does not.
2. **An identity and ownership envelope for the sweep output**, if the observer is to see several workspaces: workspace id, owner, `gh` login, host name, and a per-row Run id and worktree path. JSON v1 has none of them (`report.py:619-695`). #409 draft item 1 already asks whether to add fields to v1 (additive) or move to v2. PR #539 is open and the schema is golden-tested, so this is a Phase 1 follow-up or a Phase 2 item, not something #477 can assume.
3. **Remote collection.** `--include-remote` is forbidden in Phase 1 (`orchestrator-mode.md:539`); remote hosts stay `unknown`. A later phase must define how a sweep from another workspace is obtained read-only.
4. **The trust-grant format** (#339 questions 1 and 2 to `/tech-research`, macaroon versus Biscuit to an adversarial debate). #477 should adopt it, not invent one.
5. **A written listener contract**, only if B or C is revisited: what the listener may be asked (one validated issue number, as in D3), the permission class of the session it starts, and the live-test evidence the watcher already requires (FU-1).
6. **Phase 2 and #444** (sub-orchestrator mode): how a session is marked as an orchestrator. Until then "the project's orchestrator" cannot be an address (F7).
7. **A correction to the #409 draft diagram** (F17), or an explicit label that the listener path is option B or C and not what is built.
